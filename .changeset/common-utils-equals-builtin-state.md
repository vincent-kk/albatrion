`equals` and `stableEquals` return different results for some built-in values. `equals` used to report any two `ArrayBuffer`s, `DataView`s or boxed `Number`, `String` or `Boolean` values as equal whatever their contents; it now reports them unequal when their bytes or primitive values differ, and when those match it still compares their own enumerable properties, so `new Number(1)` with `extra: 1` and with `extra: 2` stay unequal. `equals` also reports errors with a different `name` or `message` as unequal. `stableEquals` already compared buffer and `DataView` bytes and boxed strings; it now also reports boxed `Number` and `Boolean` values with different primitive values as unequal, and compares the own properties of `ArrayBuffer`s with matching bytes, while `DataView`s with the same bytes stay equal whatever their own properties. If your code relied on these values comparing equal, compare them explicitly before calling `equals`. Plain objects and arrays are compared exactly as before, and the packaged agent guide now states the comparison rules of both functions.
