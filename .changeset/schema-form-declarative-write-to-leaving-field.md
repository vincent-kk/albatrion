When a `controls.injectTo` or `controls.derived` write names a value for a field that is already leaving when the write is applied (for example a caller gate change and the source write in the same `node.batch()`), the named value is now kept for the field, as it is when the field became inactive in an earlier update. The field's exit policy runs first: a value the write names replaces the result of `unsetOnInactive` or `inactiveValue`, and an omitted sibling keeps what that policy left. A whole write to the leaving field itself replaces that field’s retained value. Before, the field kept its previous value and the written value was lost. This holds however the write names the field: through its parent object, by the field's own path (`{ '../y': value }`), or by a path below an object that becomes inactive in the same update. It also applies to the fields of a virtual group, including a group inside such an object, and to a field that a lower-ranked rule of the same update makes inactive. Among overlapping winners in the same round, the higher-ranked rule decides the overlapping value. An accepted write in a later round can replace that value. A rule that closes the gate in the same round as the write is not such a case: the write lands on the still-active field and its exit policy then applies to that value. This also preserves a value written through a whole parent object, array, or virtual group when the default exit policy retains the field. When a later rule of the same update makes the field active again, its exit is cancelled: no exit policy runs and the named value is written to the field; a field the write does not name keeps its value. If the revived field leaves again and finishes the update inactive, the second exit runs its policy before retaining the declarative value. If the second exit is also cancelled, the declarative value remains live. A `controls.injectTo` or `controls.derived` value for a field that is already inactive now also wins over a value the caller wrote to that field in the same update or `node.batch()`, as it does when the two writes are separate updates; before, the caller value was kept.

When an earlier rule omits an active field and a later rule names it before it leaves, `inactiveValues` now retains the later value under the default exit policy. This also covers newly grown array positions that never become active and already-inactive fields named through a parent or virtual group. If the last whole write instead omits an active field, its exit policy uses the source from the start of the update. An already-inactive field omitted by a parent write keeps its retained value. If a parent becomes active again and a later whole write names one of its inactive fields, that field retains the later value.
