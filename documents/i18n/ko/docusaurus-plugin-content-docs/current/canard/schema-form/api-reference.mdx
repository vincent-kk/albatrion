# API 참조

소비자 API는 `@canard/schema-form`에서 import하십시오. callback에서 추론되는 record 형이 이름 있는 패키지 export는 아닐 수 있으므로 내부 형 이름을 추측해 import하지 마십시오.

## Form props {#form}

| Prop                                                        | 용도                                                                       |
| ----------------------------------------------------------- | -------------------------------------------------------------------------- |
| `jsonSchema`                                                | root load에 사용하는 필수 스키마입니다.                                    |
| `defaultValue`                                              | root load에서 읽는 초기 값이며 controlled value prop은 없습니다.           |
| `onChange`                                                  | 동기 출력 callback입니다.                                                  |
| `onSubmit`                                                  | 수락한 제출의 값 callback이며 promise를 반환할 수 있습니다.                |
| `onValidate`                                                | 원시 오류 목록 변경이며 같은 검증 결과는 생략합니다.                       |
| `onStateChange`                                             | 전체 트리 interaction aggregate 변경입니다.                                |
| `onError`                                                   | 발생 채널이며 오류 참조를 확인하십시오.                                    |
| `onDiagnosticsChange`                                       | 준비 후 root 진단 변경이며 초기 진단은 handle.node에 있습니다.             |
| `readOnly / disabled`                                       | 폼 전체 입력 잠금이며 기본값은 false입니다.                                |
| `unsetOnInactive`                                           | 기본 이탈 제거 정책이며 노드 controls가 우선합니다.                        |
| `disableAutomaticWrites`                                    | 명령형 쓰기는 허용하면서 자동 쓰기를 억제합니다.                           |
| `errors`                                                    | 외부 오류이며 배열 참조 변경과 reset에 다시 적용합니다.                    |
| `errorVisibility / validationMode`                          | 검증 페이지의 표시·실행 정책입니다.                                        |
| `validatorFactory`                                          | 완전한 검증기 객체이며 검증 페이지를 참조하십시오.                         |
| `FieldRenderer`                                             | 필드 그룹 렌더러입니다.                                                    |
| `FormLabelRenderer / FormInputRenderer / FormErrorRenderer` | 조합 렌더러입니다.                                                         |
| `formatError`                                               | 필수 노드 인자를 받아 오류를 ReactNode로 바꾸는 formatter입니다.           |
| `fieldInputDefinitions / fieldInputMap`                     | 순서 있는 검사와 경로 재정의이며 입력 선택을 참조하십시오.                 |
| `virtualization`                                            | 입력 마운트 지연이며 기본값은 꺼짐입니다.                                  |
| `context`                                                   | provider context 위에 병합하는 live form context입니다.                    |
| `children`                                                  | 레이아웃 또는 node·jsonSchema·defaultValue·value·errors를 받는 함수입니다. |
| `ref`                                                       | 현재 root를 다루는 FormHandle입니다.                                       |

각 prop의 조건은 [렌더링](./core-concepts#rendering), [입력 선택](./schema-reference#input-resolution), [검증](./validation), [오류 보고](./error-reference#occurrences)에 있습니다.

## root load와 설정 수명 {#configuration-lifetime}

`jsonSchema`·`defaultValue`만 바꾸면 현재 트리와 편집 값을 유지합니다. `reset()`은 최신 committed props를 읽고 첨부 파일을 지우며 기본값을 로드합니다. 함수 children은 현재 트리의 schema를 받으므로 reset 전에도 새 schema prop과 옛 node가 짝지어지지 않습니다. reset은 대체 값 대신 automatic-write override flag만 받습니다.

`rebuild()`는 schema 객체의 cached analysis를 무효화하고 reset의 load 옵션으로 이 Form의 root를 교체합니다. 같은 schema 객체를 쓰는 다른 Form은 기존 트리를 유지합니다. 교체 후에는 현재 handle에서 노드를 다시 조회하십시오.

`validatorFactory` 참조를 교체하면 Form 트리를 다시 만들므로 설정이 같으면 안정된 객체를 사용하십시오. context·입력 잠금은 live 변경을 지원하며 renderer·입력 설정에는 [live 렌더링 규칙](./core-concepts#rendering)이 적용됩니다.

잘못된 입력 map을 유효한 map으로 교체하면 재마운트 없이 복구합니다. live map 변경이 실패하면 기존 트리와 마지막 유효 map을 보존합니다. [입력 map 오류](./error-reference#occurrences)를 참조하십시오.

`validationMode`, `unsetOnInactive`, `disableAutomaticWrites`는 commit에서 기존 트리에 적용됩니다. 값·상호작용·노드 정체성을 유지하며 두 쓰기 기본값은 다음 엔진 진입부터 적용하고 소급 쓰기를 하지 않습니다. 모드 전환의 취소·오류·재활성화 조건은 [검증 모드](./validation#modes)를 참조하십시오. Form commit 전에 자식 layout에서 시작한 호출은 마지막 committed 설정을 사용합니다.

## FormHandle {#form-handle}

| 멤버                                              | 용도                                                                                                                                                                                                       |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `node`                                            | 현재 root이며 마운트 전에는 undefined입니다.                                                                                                                                                               |
| `getValue() / setValue(valueOrUpdater, options?)` | 출력 읽기·root 쓰기입니다.                                                                                                                                                                                 |
| `findNode(path) / findNodes(path)`                | 일치하는 live 노드 하나 또는 전부이며 없으면 각각 null 또는 []를 반환합니다.                                                                                                                               |
| `getState() / setState(flags) / clearState()`     | aggregate flag 읽기·전체 트리 patch·clear입니다.                                                                                                                                                           |
| `getErrors() / validate()`                        | 원시 오류·새 판정 promise입니다.                                                                                                                                                                           |
| `focus(path?) / select(path?)`                    | 중첩 가상화 게이트를 열어 정확한 대상 입력 container의 DOM 순서상 첫 input·textarea·select·button에 focus를 요청합니다. 텍스트 선택은 button·select를 건너뛰고 첫 input·textarea에 요청하며, 해당 요소에 select 메서드가 있으면 호출합니다. |
| `refresh(path?) / remount(path?)`                 | committed 입력 값 재읽기·렌더 subtree 재마운트입니다.                                                                                                                                                      |
| `reset(option?) / rebuild(option?)`               | 위에서 설명한 root load 연산입니다.                                                                                                                                                                        |
| `revealErrors()` / `resetErrorVisibility()`       | 표시 override이며 검증 페이지를 참조하십시오.                                                                                                                                                              |
| `getAttachedFilesMap()`                           | Map&lt;string, File[]&gt;이며 파일 예제를 참조하십시오.                                                                                                                                                    |
| `submit()`                                        | promise를 반환하는 명령형 제출이며 handler에 pending·subscribe도 있습니다. 거부와 오류 공개는 [native·명령형 제출](./error-reference#submission)을 참조하십시오.                                           |

일치 노드가 없는 focus·select·refresh·remount는 아무 작업도 하지 않습니다. 마운트 전에 `findNode`는 null, `findNodes`·`getErrors`는 빈 배열, `validate()`는 빈 배열을 resolve하고 `getState()`는 빈 객체를 반환합니다. 이런 빈 query 결과는 검증 판정을 뜻하지 않습니다.

## 쓰기 옵션과 subtree walk {#write-options}

`SetValueOption.Overwrite`(기본값) 또는 `Merge`를 사용하고 필요하면 `DisableAutomaticWrites`·`EnableAutomaticWrites`로 덮어쓰십시오. Overwrite·Merge 또는 충돌하는 자동 쓰기 flag를 함께 지정하지 마십시오. object·array 결과는 [값 규칙](./schema-reference#value-states)에 있습니다.

`node.batch(fn)`은 동기 쓰기를 묶습니다. `visitSubtree(visitor)`는 자기 노드, 자손을 preorder·형제 순서로 방문하며 false 반환은 그 노드의 자손을 건너뜁니다. visitor는 필수 FieldNode를 받습니다. live walk는 현재 형상, detached walk는 고정된 subtree를 방문합니다. 중복 도달 노드는 한 번만 방문하고 walk 중 생긴 노드는 놓칠 수 있습니다.

값 쓰기는 끝에서 한 번 정착하므로 중간 값 읽기는 직전 commit을 봅니다. state·external-error 변경은 즉시 적용하고 이벤트만 기다리며 외부 batch가 있으면 모두 그 끝까지 미룹니다. 그런 외부 batch 밖에서는 Form reset·`resetSubtree()`의 load는 즉시 정착합니다. 읽기 전용 walk는 쓰기가 발생할 때까지 write 경계를 열지 않고 listener 안에서도 사용할 수 있습니다.

visitor 실패는 이미 수행한 쓰기를 적용한 뒤 전파합니다. listener 안의 값 쓰기 walk에서는 실패가 직접 caller 대신 listener 채널로 보고될 수 있습니다. handle에는 visitSubtree가 없으므로 `handle.node`를 사용하십시오.

## Form 조합과 사용자 입력 {#composition}

`Form.Field`는 그룹을, `Form.Label`, `Form.Input`, `Form.Error`는 개별 슬롯을 렌더링합니다. `Form.Render`의 함수 children은 `node`, `value`, `Input`, `errorVisible`, `errorMessage` 등을 가진 `FieldRendererProps`를 받습니다. 모두 Form 조상이 필요합니다. `Form.Input`, `Form.Render`의 path도 상대·wildcard를 포함한 [확장 query 규칙](#paths)을 사용합니다.

입력 쓰기의 interaction 동작이 필요하면 사용자 렌더러에서 제공된 `Input`을 사용하십시오. 직접 `node.setValue()`는 프로그램 쓰기이므로 Edited를 표시하지 않습니다. 추가 입력 props는 선택한 입력 컴포넌트로 전달하며 native element에 자동 적용하지 않습니다. 내장 string 입력의 autoComplete 같은 native 속성은 `inputProps`에 둡니다.

`FieldInputProps`는 `jsonSchema`, `node`, `type`, `schemaType`, `misfit`, `name`, `path`, `nullable`, `required`, `readOnly`, `disabled`, 원시 `errors`, `errorVisible`, `watchValues`, `defaultValue`, `value`, `onChange`, `onFileAttach`, `ChildFields`, `context`, presentation props를 제공합니다. 빈 입력은 undefined를, null은 의도적으로 선택할 때만 발행합니다. 계산된 입력 잠금과 [접근 가능한 이름](./schema-reference#accessibility)을 지키십시오.

FieldInputProps와 FieldRendererProps의 node prop은 모두 필수입니다.

`ChildFields`는 key·path·field metadata가 있는 컴포넌트이며 형은 `FieldInputProps['ChildFields'][number]`로 얻습니다. `ChildFieldProps`에는 `FieldRenderer` 등 자식별 재정의가 있습니다. FieldInput에 내장 `FieldRenderer` prop을 제공하지는 않으므로 Form·Form.Field·자식 컴포넌트에서 렌더러를 선택하십시오.

## 플러그인과 FormProvider {#plugins}

`SchemaFormPlugin`은 renderer 컴포넌트, `fieldInputDefinitions`, `validator`, `formatError`를 받습니다. 뒤의 등록은 제공한 renderer·validator·formatter를 대체하고 입력 정의를 앞에 붙입니다. `registerPlugin(null)`은 플러그인 상태를 내장 기본값으로 초기화합니다. 등록은 이후 마운트에서 캡처하는 설정에 적용됩니다.

`FormProvider`는 subtree에 renderer 기본값·입력 정의·formatError·errorVisibility·validationMode·validatorFactory·context를 공유합니다. 명시적인 Form props가 우선하고 Form context는 provider context 위에 병합합니다. 공개 이름 `FormProvider`를 사용하십시오. `plugin` prop은 없으므로 renderer 슬롯·`fieldInputDefinitions`·`formatError`를 명시적으로 전달하고 검증기는 `validatorFactory={plugin.validator}`로 연결하십시오. 검증기 요구사항은 [검증기 객체 계약](./validation#validator-contract)에 있습니다.

## 노드 값·state·배열 연산 {#nodes}

identity·tree는 `type`, `strategy`, `schemaType`, `jsonSchema`, `path`, `name`, `escapedName`, `depth`, `rootNode`, `parentNode`, `children`으로 읽습니다. terminal children은 null입니다. `value`는 해석된 로컬 값, `outputValue`는 방출 JSON, `source`, `extras`, `inactiveValues`는 retained 입력을 나타냅니다. `isRequired`, `nullable`, `isActive`, `isVisible`, `isPresent`, `isReadOnly`, `isDisabled`, `isMisfit`, `misfits`, `watchValues`, `context`, `diagnostics`는 현재 노드 상태입니다. `isPresent`는 disabled와 무관하게 active이면서 visible임을 뜻합니다.

root의 parentNode는 null입니다. `find()`의 일치 노드가 없으면 null, `findNodes()`는 []를 반환합니다.

`FieldNodeState.Edited`는 사용자 입력을 기록하며 프로그램·자동 쓰기에는 설정하지 않습니다. 기본 입력 blur는 다음 animation frame에 Touched를 기록하고 사용자 입력은 flag를 명시적으로 쓸 수 있습니다. `isEdited`, `isTouched`는 해당 flag입니다. `node.state`·`setState`는 사용자 flag도 받고 Form reset·clearState는 사용자 flag도 지웁니다. `globalState`는 true 또는 부재인 aggregate flag를 방출합니다. 일괄 변경에는 subtree state·error 메서드를 사용하십시오.

array 노드의 `push(value?)`, `insert(index, value?)`는 길이를, `pop()`·`remove(index)`는 제거한 값을, `update(index, value)`는 갱신한 값을, `clear()`는 void를 반환합니다. insert는 0부터 length까지 정수 index를 받고 잘못된 index에서는 원래 길이를 반환합니다. minItems·maxItems는 강제하지 않습니다. batch에서는 앞선 mark를 반영해 호출 위치에서 계산하고 전체 배열 정착 때 항목 identity를 위치로 이어갑니다. 배열 연산 전에 `isArrayNode`로 확인하십시오.

공개 guard는 unknown을 받는 isFieldNode와 FieldNode·null·undefined를 받는 isArrayNode·isBooleanNode·isBranchNode·isNumberNode·isObjectNode·isStringNode·isTerminalNode·isUnionNode·isVirtualNode입니다. 이 아홉 kind·strategy guard는 null·undefined에 false를 반환합니다.

## load baseline과 divergence {#divergence}

`isDivergent`는 같은 경로에서 현재 방출 출력과 마지막 성공 root load의 최종 출력을 비교합니다. 첫 load 전·detach 후에는 false이며 배열 위치와 키 순서도 비교합니다.

쓰기 때 divergence 비교를 추가하지 않습니다. root load는 다음 load까지 baseline 출력 참조 하나를 유지하므로 그동안 바뀐 output 조각이 남습니다. getter는 O(depth)로 경로를 읽고 두 값·결과를 Object.is로 cache하므로 NaN을 포함해 값이 그대로이면 깊은 비교를 반복하지 않습니다. 노드 memo는 해당 경로의 두 값과 결과만 가집니다.

root의 UpdateValue·UpdateState·RequestRefresh와 노드의 UpdatePath를 관찰하고 root·node가 바뀌면 다시 연결하십시오. 두 load 경로 모두 출력이 같은 reset에도 RequestRefresh를 전달합니다.

## detached·inactive 노드 수명 {#detached-nodes}

detached 노드는 마지막 committed 읽기와 고정 subtree를 유지하고 구독 전달을 멈추며 setValue·배열 연산으로 현재·retained·미래 instance를 바꿀 수 없습니다. detached array의 push·insert는 고정 길이, 나머지 배열 메서드는 undefined를 반환하며 개발 경고 외에는 값을 바꾸지 않습니다.

inactive JSON을 갱신하려면 live root·host를 통해 쓰십시오. 재진입은 해당 overlay를 소비하는 새 노드를 만듭니다. 활성 노드가 없으면 `find`는 null이므로 재진입 후 경로를 다시 조회하고 오래된 구독을 교체하십시오.

## onInactive와 이탈 정리 {#inactive-listeners}

`node.onInactive(resolver)`는 이 instance의 정상 retained gate 이탈에 동기 resolver를 등록하고 unsubscribe를 반환합니다. unmount·dispose·배열 삭제·재진입에 소비되는 옛 instance에서는 실행하지 않으므로 새 instance에 다시 등록하십시오.

listener는 등록 순서로 실행하고 마지막 non-undefined 결과를 사용하며 defined listener 결과가 `controls.inactiveValue`보다 우선합니다. listener가 throw하면 노드 override 전체를 취소하고 retained 원본을 유지하되 이탈은 commit하고 `ExpressionThrew`를 보고합니다.

resolver 안의 값 쓰기·배열 verb·batch·resetSubtree는 무시하고 개발에서 `WriteInInactiveResolver`로 경고합니다. state·external-error·request·validation 명령은 유지합니다. 쓰기 메서드 대신 retained 값을 반환하십시오. component cleanup의 값 쓰기는 같은 resolver 서명의 `controls.inactiveValue` 또는 onInactive로 옮기십시오. [이탈 coverage 규칙](./schema-reference#inactive-values)도 적용됩니다.

## 숨김 Form과 callback 수명 {#hidden-lifecycle}

첫 layout 준비 뒤의 current load는 숨김 중에도 callback을 전달하고 다시 표시할 때 replay하지 않습니다. 준비되지 않은 load는 construction record만 buffer하고 일반 callback은 버리며 retired load의 이후 record도 버립니다. root 교체 reset은 handle binding 전환 전에 mount record, buffered build record 순으로 전달하며 각 handler 실패를 격리합니다.

React에서는 이 binding이 hidden·unmounted를 확실히 구분할 수 없어 retained handle·node가 unmount 뒤에도 callback을 전달할 수 있으므로 소비자 구독을 정리하십시오. 숨김 동안 일반 callback은 마지막 연결 commit, onError는 최신 handler를 사용합니다. field layout-effect 쓰기와 render warning은 다시 표시할 때 도착합니다.

React가 숨겨진 폼을 다시 표시하면 입력은 현재 노드 값을 보여줍니다. 숨겨진 동안 기록한 값과 숨겨질 때 끝나지 않은 IME 조합도 여기에 포함됩니다.
폼이 숨겨진 동안에는 React가 ref를 분리하므로 `formRef.current`는 null입니다. 숨김 중에 값을 쓰려면 폼이 표시되어 마운트된 뒤 보관한 `FormHandle`이나 노드 참조를 사용하십시오.

## JSONPointer query와 표현식 {#paths}

| token         | Form query 의미                                                       |
| ------------- | --------------------------------------------------------------------- |
| `#`           | 절대 root                                                             |
| 빈 문자열     | 현재 origin                                                           |
| `/` 또는 `#/` | root의 빈 이름 자식                                                   |
| `.` / `..`    | 현재·부모 노드                                                        |
| `*`           | wildcard이며 find는 첫 match, findNodes는 전부 반환                   |
| `@`           | context 표현식 token이며 query 노드가 아니므로 find=null·findNodes=[] |

controls의 `@.prop`와 optional chaining은 live form context를 읽습니다. 분기 표현식의 `./`는 host 자식, 일반 노드 표현식의 `../`는 부모를 통한 형제 경로입니다. 표현식 origin을 기준으로 깊이를 계산하십시오.

segment 자체가 `*`, `..`, `.`, `@`이면 연산자로 먼저 해석합니다. literal 이름은 `%2A`, `%2E%2E`, `%2E`, `%40`으로 escape합니다. 그 밖의 percent 문자는 그대로 두고 다른 segment는 `~1`, `~0`만 decode합니다. 맨 앞의 `#`만 fragment prefix이며 내부 `#`는 일반 이름입니다. literal property 이름 `%2A`, `%2E`, `%2E%2E`, `%40` 자체는 round-trip할 수 없어 ReservedPropertyName으로 거부합니다.

canonical node·inactive-value·오류 경로는 이 percent literal 표기를 사용합니다. 첨부 키에는 [파일 전송 예제](./examples/media-registration#files)의 규칙을 적용하십시오. 검증기·`$ref`의 RFC6901 pointer에는 폼 연산자를 적용하지 않으며 표준 URI fragment는 모든 segment를 percent-decode합니다. `JSONPointer`는 라이브러리 상수를 제공하며 일반 JSON 값 reader는 아닙니다.

## 이벤트와 훅 {#events-hooks}

이벤트는 최외곽 public 쓰기가 끝날 때 노드별 bit를 병합하여 동기 전달하며 다음 microtask까지 기다리지 않습니다. `FieldNodeEventType`은 Initialized, UpdatePath, UpdateValue, UpdateState, UpdateGlobalState, UpdateError, UpdateGlobalError, UpdateChildren, UpdateControlledProperties, Focused, Blurred, RequestFocus, RequestSelect, RequestRefresh, RequestRemount, UpdateJsonSchema, UpdateDiagnostics입니다. 각각 초기화, 경로·값·interaction·오류·자식·controls, 입력 동작, schema 참조, root 진단을 나타냅니다.

`node.request`에는 `FieldNodeRequestType.Focus`, `Select`, `Refresh`, `Remount` 중 하나를 전달하십시오. 한 번의 호출은 한 동작이며 bit mask를 결합하지 않습니다. `subscribe`는 cleanup, `revision(mask?)`는 전달 revision을 반환합니다.

| 훅                                                                           | 소비자 계약                                                                                                                                                                                                                                                     |
| ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `useFormSubmit(ref)`                                                         | submit·boolean 또는 undefined인 pending을 반환하며 binding 전 submit은 문제없이 resolve합니다. 이벤트 handler에서 rejection을 처리하십시오.                                                                                                                     |
| `useFieldNodeTracker(node: Node \| null \| undefined, mask?)`                | 선택한 revision에 다시 렌더링하며 기본은 전체입니다. null·undefined이면 구독하지 않고 클라이언트·서버에서 0을 반환합니다. snapshot이 동시 render→commit 변경을 잡습니다.                                                                                        |
| `useFieldNodeSubscribe(node: Node \| null \| undefined, listener, options?)` | 자동 렌더링 없는 구독이며 null·undefined이면 listener·onSubscribe를 모두 호출하지 않습니다. state mirror는 `options.onSubscribe(node: Node)`로 attach 시 현재 상태를 읽으십시오. 이 인자는 추론된 노드 subtype의 필수 값이며 이전 이벤트는 replay하지 않습니다. |
| `useChildFieldMap(ChildFields)`                                              | 직접 자식 이름별 컴포넌트이며 없는 이름은 아무것도 렌더링하지 않습니다.                                                                                                                                                                                         |
| `useChildFieldErrors(node, disabled?)`                                       | FieldNode가 필수입니다. 원시 child errorMatrix, formattedErrors·formattedError, childErrorVisibleList·errorVisible, 표시를 반영한 errorMessage입니다. disabled는 자식 오류 읽기와 표시 flag를 비웁니다.                                                         |

노드 입력이 바뀌면 두 관찰 훅은 이전 구독을 해제하고 새 노드가 있을 때 다시 연결합니다. unmount에서도 구독을 해제합니다.

ref 할당은 소비자를 다시 렌더하지 않습니다. `formRef.current?.node`를 전달한 두 훅은 다음 렌더가 실제 노드를 넘길 때 연결되므로 React state 갱신으로 렌더를 일으켜야 하며 callback ref도 마찬가지입니다. `rebuild()`, 바뀐 schema를 읽는 `reset()`, validatorFactory 변경에 따른 root 교체는 소비자를 다시 렌더하지 않고 FormHandle.node를 바꿉니다. 소비자가 다시 렌더할 때까지 훅은 이전 root를 관찰합니다.

가능하면 중복 이벤트 mirror 대신 useFieldNodeTracker와 render 중 live getter 읽기를 사용하십시오.

## 가상화 {#virtualization}

`virtualization: true` 또는 옵션 객체로 켭니다. 노드 트리는 항상 완전하며 값·검증·제출에 참여합니다. 화면 밖 입력 DOM은 placeholder로 지연할 수 있고 한 번 공개하면 다시 지연하지 않습니다.

옵션은 Form key 교체 없이 마운트 후 반영됩니다. 끄면 대기 placeholder를 모두 공개하고 관찰·backfill을 멈춥니다. 다시 켜거나 threshold·eagerCount를 바꾸면 미공개·새 노드만 지연합니다. rootMargin·backfill 변경은 대기 placeholder를 다시 관찰하고 estimateHeight·Placeholder는 표현만 갱신합니다. 같은 원시값·콜백 참조는 재관찰하지 않습니다. 값·노드 상태·오류는 유지합니다. 무관한 변경은 진행 중 포커스를 보존하고 gate 공개는 공개 커밋 후 요청을 끝냅니다. FormProvider는 virtualization을 제공하지 않습니다.

| 옵션           | 기본값                      | 의미                                                                                  |
| -------------- | --------------------------- | ------------------------------------------------------------------------------------- |
| threshold      | 30                          | branch의 gate를 켤 최소 렌더 자식 수                                                  |
| eagerCount     | 20                          | gate branch마다 즉시 마운트할 선두 자식 수                                            |
| rootMargin     | '100%'                      | px·% 단위의 viewport 공개 여백                                                        |
| backfill       | VirtualizationBackfill.Idle | Idle은 순차 공개, None은 표시 또는 placeholder 노드에 전달되는 focus·select 명령 대기 |
| estimateHeight | 40                          | px 숫자 또는 `(node: FieldNode) => number`이며 노드 인자는 필수                       |
| Placeholder    | 없음                        | 필수 FieldNode·height를 받는 컴포넌트                                                 |

placeholder는 추정 높이와 `data-path`, `data-deferred`, aria-hidden을 사용합니다. 지연 입력은 공개 전까지 페이지 검색·화면 읽기·autofill에 사용할 수 없으며 backfill 완료 시간을 보장하지 않습니다. `focus(path)`와 native 무효 제출의 포커스는 중첩 게이트와 가상 그룹을 지나는 대상 렌더 경로를 한 공개 커밋에 엽니다. 포커스를 받을 입력이 이미 마운트되어 있으면 다른 조상 위치를 열지 않고 기존 요청 동작을 유지하며, 마운트된 중복 위치는 모두 요청을 받아 마지막 위치가 포커스됩니다. 같은 대상의 다른 자리표시자는 자기 구독으로 공개될 수 있습니다.

새 포커스 요청, reset, 확인된 폼 언마운트 또는 게이트 소멸은 대기 중인 공개 포커스 예약을 취소합니다. 요청 뒤 다른 요소로 초점이 이동하거나 초점을 가진 요소에서 벗어나면 행동을 막으며, 페이지 본문으로 빠지는 blur, 다른 곳에 갔다 돌아오는 이동과 공개된 하위 트리의 자동 포커스도 포함합니다. 공개 과정에서 시작 요소를 제거하는 것 자체는 초점 이동으로 보지 않습니다. StrictMode의 effect 재실행은 Mount를 반복하지 않고 요청을 보존합니다.

terminal 내부, 생략된 레이아웃, 숨겨진 Activity와 공개 커밋에서 Suspense로 마운트되지 않은 입력에는 도달할 수 없습니다. 숨김·disabled·inert 요소는 포커스를 무시할 수 있습니다. 주변 자리표시자 높이 변경에 따른 스크롤 이동은 보정하지 않습니다. 이미 마운트된 대상이나 막는 게이트가 없는 대상에 보낸 요청이 지연되면 나중에 마운트된 위치에도 도달하며 새 요청으로 취소할 수 없습니다. native 무효 제출은 [후보 선택 규칙](./error-reference#submission)을 유지합니다.

SSR은 모든 입력을 렌더링하고 hydration은 이를 그대로 유지합니다. hydration 뒤 추가한 branch·children에 gate를 적용하며 준비된 자식은 나중에 탭·아코디언에서 처음 표시해도 준비 시의 gate 결정을 유지합니다. IntersectionObserver가 없으면 브라우저는 eager 렌더링하고 서버는 경고하지 않습니다.

hydration 자체는 사용자 branch 입력의 Suspense에 추가 갱신을 보내지 않습니다. React 18에서 hydration 완료 전 후속 갱신은 해당 경계를 client 렌더링으로 바꿀 수 있습니다. [가상화 예제](./examples/virtualized-form)와 실제 branch 레이아웃을 검증하십시오.

## TypeScript 추론 {#typescript}

`as const`로 schema literal을 보존하십시오. type이 string으로 넓어지면 추론이 any로 퇴화할 수 있습니다. inactive controls·omitEmpty가 키를 제거할 수 있으므로 `InferValueType`은 required와 무관하게 객체 키를 optional로 만듭니다. `additionalProperties: false`가 아니면 열린 객체입니다. 추론 값을 검증이 끝난 업무 데이터라고 가정하지 마십시오.

명시적인 배열 스키마는 [`@winglet/json-schema`의 튜플 추론 계약](../../winglet/json-schema/index.mdx#tuple-inference)을 따르며, 유한한 리터럴 `prefixItems`의 optional 위치와 `items`의 rest 규칙을 적용합니다. `Form`과 `FormHandle`의 기본 `Value` 타입에 이 추론 튜플이 적용됩니다. 이는 `any[]`보다 좁으므로 자유로운 위치나 초과 항목에 의존하는 코드에는 컴파일 오류가 날 수 있습니다.

정확한 소비자 형상은 `Form<Schema, Value>`, `FormHandle<Schema, Value>` 양쪽의 두 번째 generic으로 지정하십시오. 특히 구체적 defaultValue가 handle과 다르게 required 키를 추론할 때 필요합니다. `InferFieldNode`는 정적 근거가 있으면 노드 형을 추론하며 동적 reference·gate에서는 전체 노드 union이 남을 수 있습니다.
