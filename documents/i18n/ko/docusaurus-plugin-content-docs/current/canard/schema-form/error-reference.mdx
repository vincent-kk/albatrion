# 오류 참조



## 오류 guard와 코드 비교 {#guards}

형제 오류 클래스 네 가지에는 `isJSONSchemaError`, `isSchemaFormError`, `isUnhandledError`, `isValidationError`를 사용하십시오. 각 guard는 자기 클래스의 instanceof를 검사하므로 사용자 코드·플러그인의 native 오류가 자동으로 일치하지 않습니다. 패키지는 네 constructor 대신 이 guard를 내보냅니다.

group-qualified `error.code`·record.code를 `FormErrorCode`, `FormWarningCode` 멤버와 비교하면 컴파일러가 이름을 검사합니다. `ValidationIssue`는 판정 항목이며 이 예외 클래스와 다릅니다. native 어댑터 bind·pointer 실패는 [AJV 설정](./validation#ajv-configuration), [guard compile](./validation#guard-compilation)을 참조하십시오.

## onError 발생과 origin {#occurrences}

`onError`는 발생 채널이며 현재 이슈 목록이나 해결 통지가 아닙니다. callback은 level·group-qualified code·message·origin과 선택적인 path·schemaPath·details·error·componentStack을 받습니다. `FormErrorRecord`는 root의 이름 있는 export가 아니므로 `FormProps['onError']`에서 매개변수 형을 추론하십시오. onError observer 안에서 같은 Form에 다시 쓰지 마십시오.

| origin | 연산 |
| --- | --- |
| load | 생성·mount·reset·rebuild·검증기 교체의 load chain |
| write | 값·state·배열·context·외부 오류 쓰기와 통지 listener |
| validate | 전체 schema compile·판정·결과 전달과 listener |
| submit | degraded 제출 거부 또는 native submit에서 처음 잡은 실패 |
| render | renderer 경계와 render warning |

이미 열린 chain은 중첩 쓰기·reset에도 바깥 origin을 유지하며 트리 생성 발생은 항상 load입니다. 외부 errors의 최초 적용은 load, 이후 prop 교체는 write이며 submit 안에서 이미 보고한 검증 실패는 validate를 유지합니다. 일부 개발 console 경고에는 onError record가 없어 두 채널이 같지 않을 수 있습니다.

## rejection·listener·host 실패 {#host-failures}

validate·submit caller는 aggregate rejection 하나를 받고 onError는 개별 발생을 받을 수 있으며 record에 aggregate rejection 자체를 넣지는 않습니다. 검증 결과 listener 실패는 명시적 validate 중에도 caller 없는 통로이므로 promise가 resolve해도 host에 오류를 보고할 수 있습니다.

caller 없는 실패 전달은 정상적이고 비어 있지 않은 MultipleErrors bundle만 원소 순서·깊이 우선으로 펼칩니다. 배열은 1부터 2^32−1까지의 안정된 정수 길이와 own index가 필요하고 각 순회는 원소 1,000,000개의 검사 budget을 공유합니다. malformed·읽기 불가·순환·재방문·길이 변경·budget 초과 bundle은 같은 identity의 불투명 leaf이므로 host가 bundle 자체를 받을 수 있습니다.

engine 검증 wave·자동 OnChange·load flush는 handler-first, native submit·load slot은 original-first 실패 순서를 유지합니다. React·render 경계는 원래 thrown 값을 기록합니다. capture는 정상적으로 이미 보고된 bundle만 억제하고 읽기 불가 metadata는 원래 값을 담은 고정 fallback 메시지 record 하나로 보고합니다. host 실패와 onError를 연결할 때 각각을 별개 원인으로 세지 않도록 이 조건을 고려하십시오.

## 제출 실패와 native Enter {#submission}

스키마 검증에 실패한 제출은 `FormErrorCode.SchemaValidationFailed`, degraded 진단 상태의 제출은 `FormErrorCode.SubmitWhileDegraded`로 거부합니다. 수락한 제출은 캡처한 방출 값을 onSubmit에 전달하고 promise를 기다립니다. 이벤트 handler에서는 명령형 submit rejection을 처리하십시오. 표시 정책은 [검증](./validation#visibility)에 있습니다.

Enter 제출은 native form 알고리즘을 따릅니다. text-like 필드가 여러 개이면 submit 버튼을 포함하십시오. blocking text 입력 하나와 checkbox 조합은 버튼 없이 제출할 수 있지만 이를 여러 text 입력에 일반화하지 마십시오. form 밖 버튼에는 명시적 handle 호출 또는 native form 연결이 필요합니다.
