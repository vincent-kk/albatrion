# 0.x 이전 안내



## 이전 순서와 무시되는 키 {#migration-order}

현재 API를 사용하려면 schema 설정, component·type import, node state·validation issue 처리 순서로 이전하십시오. 폼 엔진은 formType·computed 같은 옛 최상위 설정 키의 별칭이나 경고를 제공하지 않으므로 현재 그룹으로 직접 옮겨야 합니다. 별도로 구성한 검증기는 자기 정책에 따라 알 수 없는 schema keyword를 거부할 수 있습니다.

이 문서를 변환 체크리스트로 사용하고 두 표기를 함께 남기는 대신 연결된 현재 계약을 참조하십시오.

허용 옵션은 [설정 그룹](./schema-reference#authoring-groups)을 따릅니다. 입력 설정은 presentation.FieldInputProps로 옮기고 oneOf가 폼 분기를 자동으로 하나만 고른다고 가정하지 말고 [분기 선택](./schema-reference#composition)을 확인하십시오.

검증 결과는 [원시 issue 데이터](./validation#issues-messages), thrown 예외는 [오류 guard](./error-reference#guards)를 사용하십시오.

## 변환 후 동작 확인 {#behavior-checks}

- [닫힌 options·열린 presentation](./schema-reference#authoring-groups)을 확인하여 옛 플러그인 설정의 UnknownGroupKey를 피하십시오.
- [enum 빈 값과 checkbox·radio 이름](./schema-reference#accessibility)에 맞게 DOM 검사를 바꾸십시오.
- virtual 입력은 [현재 test hint](./schema-reference#input-resolution)로 매칭하십시오.
- 완전한 [검증기 객체](./validation#validator-contract)를 제공하십시오.
- 현재 Edited·EditedTouched 상수를 사용하십시오. 기본 정책·표시 조건·Form showError prop·handle 동작은 [오류 표시](./validation#visibility)를 참조하십시오.
- injectTo context에서 `parentJSONSchema`, `rootJSONSchema`를 사용하십시오.
- onError callback의 추론 record에서 surface·aggregate 대신 `origin`을 읽고 [발생 계약](./error-reference#occurrences)을 따르십시오.
- component cleanup 쓰기는 [inactive-value resolution](./api-reference#inactive-listeners)으로 바꾸고 reset·재진입 후 노드를 다시 조회하십시오.
