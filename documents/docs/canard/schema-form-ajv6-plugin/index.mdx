<PackageHeader name="@canard/schema-form-ajv6-plugin" />

AJV 6.x validator plugin for `@canard/schema-form`.
The default instance validates JSON Schema Draft-07.
Draft-06 schemas need the Draft-06 meta-schema on a bound instance; Draft-04 schemas also need the Draft-04 meta-schema and a `schemaId` setting.
For new projects, prefer `@canard/schema-form-ajv8-plugin`.

:::tip Official Documentation
- [AJV 6 Documentation](https://ajv.js.org/v6/)
- [JSON Schema Draft-07](https://json-schema.org/draft-07/json-schema-release-notes)
:::

## Installation

```bash
yarn add @canard/schema-form @canard/schema-form-ajv6-plugin
# ajv@^6 is bundled as a direct dependency
```

## Quick Setup

```ts
import { registerPlugin } from '@canard/schema-form';
import { plugin } from '@canard/schema-form-ajv6-plugin';

registerPlugin(plugin);
```

## Default Configuration

```ts
// Internal defaults applied when no custom AJV instance is bound
{
  allErrors: true,      // collect all errors, not just the first
  nullable: true,       // allow null values
  verbose: true,        // include additional error context
  format: false,        // format validation disabled for performance
  multipleOfPrecision: 9, // accept decimal multiples such as 19.99 for multipleOf: 0.01
}
```

## Custom AJV Instance

```ts
import Ajv from 'ajv';
import { plugin } from '@canard/schema-form-ajv6-plugin';

const ajv = new Ajv({ allErrors: true, nullable: true });

// Bind once, before registerPlugin and the first compile; rebinding later is not supported
plugin.validator.bind(ajv);
```

## Instance requirements

- `bind`, `createValidator` and `createValidatorFactory` throw `ValidatorBindRefusedError` (`group: 'UNHANDLED_ERROR'`, `code: 'UNHANDLED_ERROR.VALIDATOR_BIND_REFUSED'`) for an instance with `coerceTypes`, `useDefaults` or `removeAdditional` enabled; enabling one later makes the next validation or guard compile throw. Use a separate AJV instance for code that should modify data.
- The plugin compiles each form root on a private compiler and never adds the root's `$id` to your instance. Register with `addSchema` any schema that application code looks up or another root references, and declare `$async: true` on it when it needs asynchronous validation.
- A custom AJV subclass must not register schemas or meta-schemas in its constructor; register them after constructing the instance.

## Using `createValidatorFactory` Directly

```ts
import Ajv from 'ajv';
import { createValidatorFactory } from '@canard/schema-form-ajv6-plugin';

const ajv = new Ajv({ allErrors: true });
const validate = createValidatorFactory(ajv)(myJSONSchema);

const errors = await validate(formData); // null | ValidationIssue[]
```

## Per-Form Validator with `createValidator`

`createValidator(ajv, options?)` returns a complete validator object for a Form's `validatorFactory`, independent of `plugin.validator`. Create it once outside render; a new object makes the Form rebuild its tree.

```tsx
import { Form } from '@canard/schema-form';
import { createValidator } from '@canard/schema-form-ajv6-plugin';
import Ajv from 'ajv';

const validator = createValidator(new Ajv({ allErrors: true }));
const schema = { type: 'object', properties: { name: { type: 'string' } } } as const;

export const NameForm = () => <Form jsonSchema={schema} validatorFactory={validator} />;
```

## Custom AJV instance and custom keywords

Give a Form your own AJV instance with `createValidator(ajv)`. Create the instance and the validator once at module scope, because a new validator object makes the Form rebuild its tree.

```tsx
import { Form, type JSONSchema } from '@canard/schema-form';
import { createValidator } from '@canard/schema-form-ajv6-plugin';
import Ajv from 'ajv';

const ajv = new Ajv();
ajv.addKeyword('isEven', {
  validate: (schema: boolean, data: unknown) =>
    typeof data === 'number' && (data % 2 === 0) === schema,
});
const validator = createValidator(ajv);

const schema = {
  type: 'object',
  properties: { n: { type: 'number' } },
  if: { type: 'object', properties: { n: { isEven: true } }, required: ['n'] },
  then: { properties: { evenField: { type: 'string' } } },
  else: { properties: { oddField: { type: 'string' } } },
} satisfies JSONSchema;

export const EvenOddForm = () => (
  <Form jsonSchema={schema} defaultValue={{ n: 2 }} validatorFactory={validator} />
);
```

To use the instance for every Form instead, bind it to the plugin and register the plugin:

```ts
import { registerPlugin } from '@canard/schema-form';
import { plugin } from '@canard/schema-form-ajv6-plugin';

plugin.validator.bind(ajv);
registerPlugin(plugin);
```

The plugin validates and evaluates `if` conditions on private copies of the instance. Keywords and formats you add to the instance before the next compile apply to both, including a format added after `createValidator(ajv)` but before the Form mounts. In the form above, `evenField` exists while `n` is 2, and `oddField` replaces it when `n` becomes 3.

### Choosing a `oneOf` or `anyOf` branch

A branch is chosen in one of three ways:

1. `controls.active` on the branch.
2. `controls.discriminator` on the object, with `const` or `enum` tags in each branch.
3. An `if` on the branch with `else: false`. The validator decides the `if`, so a custom keyword can choose the branch:

```ts
const schema = {
  type: 'object',
  properties: { n: { type: 'number' } },
  oneOf: [
    {
      if: { type: 'object', properties: { n: { isEven: true } }, required: ['n'] },
      then: { properties: { evenField: { type: 'string' } } },
      else: false,
    },
    {
      if: { type: 'object', properties: { n: { isEven: false } }, required: ['n'] },
      then: { properties: { oddField: { type: 'string' } } },
      else: false,
    },
  ],
} satisfies JSONSchema;
```

A branch with none of the three is always part of the form. A keyword written directly in such a branch takes part in validation but does not choose the branch: when each branch only carries `n: { isEven: … }` beside its own field, both `evenField` and `oddField` stay in the form. See [composition and conditional gates](../schema-form/schema-reference.mdx#composition) for `controls.active` and the discriminator.

### Limits

- A condition AJV cannot compile fails its guard, for example on an instance with `strictKeywords: true` that lacks a keyword the condition uses. Neither `then` nor `else` applies, `onError` receives one `GUARD_FAILED` record (`FormErrorCode.GuardFailed`), and every later write that evaluates the condition again keeps its value but throws that error. A production build also raises the error, uncaught, when the Form mounts. Add every keyword before the Form compiles; without `strictKeywords`, AJV 6 ignores unknown keywords.
- Guards are synchronous: a condition that uses an asynchronous keyword (`async: true`) fails to compile (`async keyword in sync schema`).
- A guard receives only the value of the object that holds the `if`; a keyword that reads parent or root data, and `$data`, see only that value.
- The plugin refuses an instance with `coerceTypes`, `useDefaults` or `removeAdditional` enabled. It does not refuse a keyword declared with `modifying: true`; keeping such a keyword from changing the form's values is your responsibility.

## AJV 6.x Notes

- The plugin compiles whole validation with AJV's `jsonPointers: true`, so the issue `dataPath` and the `dataPath` of its `source` AJV error are JSON Pointers (`/foo/bar`); a `required` issue appends the missing property to the issue `dataPath`.
- `nullable: true` enables the `nullable` keyword: `{ type: 'string', nullable: true }` accepts `null` like `{ type: ['string', 'null'] }`.
- AJV 6 does not support Draft 2019-09 or Draft 2020-12. See the [validator comparison](#) for details.
