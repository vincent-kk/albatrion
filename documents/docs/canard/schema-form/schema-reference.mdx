# Schema Reference



## Authoring groups {#authoring-groups}

Keep standard JSON Schema constraints at their standard locations. Put renderer payload in `presentation`, reactive policies in `controls`, and engine options in `options`. `controls` is a closed executable namespace: unknown node, child, and fragment control keys fail with `FormErrorCode.UnknownGroupKey` so typos cannot silently change visibility, value clearing, or derivation, and future control names remain reserved. `options` and `presentation` are open: unknown option keys produce no error or warning and remain available through the node schema to a FieldInput or plugin. A non-plain-object `options` value, including an array of choices, supplies no engine options. Custom option keys read as `any`, while reserved keys retain their declared types and completion. TypeScript completion helps prevent misspelled option names; a future reserved option name may collide with a custom key, so adding one is a contract change.

At blueprint load, a defined reserved value must have the shallow type below; `undefined` means absent, and `FieldInput: null` also means absent. A mismatch throws `FormErrorCode.InvalidControlShape` at `<schemaPath>/<group>/<key>` with details `{ group, key, expected }`. Existing controls container, fields, discriminator, virtual declaration, and terminal compatibility checks still apply. Nested payload contents are not checked. FieldInput functions and object components are not invoked or inspected for React identity.

| Group | Reserved keys | Accepted values |
| --- | --- | --- |
| `controls` | `active`, `visible`, `readOnly`, `disabled`, `unsetValue`, `resetInteraction`, `unsetOnInactive` | boolean or expression string |
| `controls` | `derived` | expression string |
| `controls` | `watch` | string or array of strings at runtime; the public type uses an array |
| `controls` | `default`, `inactiveValue` | any value; literal/resolver semantics remain unchanged |
| `controls` | `fields`, `injectTo`, `discriminator` | fields-entry array, function, nonempty string respectively; existing scope and shape rules apply |
| `options` | `terminal`, `omitEmpty`, `omitTrailing`, `trim` | boolean |
| `options` | `propertyOrder` | array of strings; `*` is a literal property name, not a wildcard |
| `options` | `virtual` | virtual-group declarations with the existing fields checks |
| `presentation` | `inputType` | string |
| `presentation` | `controlled` | boolean |
| `presentation` | `FieldInput` | function or non-null object; null means absent |
| `presentation` | `FieldInputProps`, `FieldRendererProps`, `errorMessages` | non-null, non-array object; no nested-value checks |

The same control value checks apply inside fields entries and fragments, within their allowed key lists. Options and presentation extension keys do not acquire library semantics merely by being present. Checks happen during cached blueprint analysis, not on user input; fixed-key checks have constant cost and string-array checks visit their elements.

| Group | Consumer use |
| --- | --- |
| `presentation` | `inputType`, `controlled`, `FieldInput`, `FieldInputProps`, `FieldRendererProps`, `errorMessages`; custom renderer payload is allowed |
| `options` | Reserved engine options use the types above; custom keys are allowed |
| `controls` | The controls listed below; input-specific settings do not belong here |

`options.trim` trims the stored string on blur, not on every keystroke. `omitTrailing` removes trailing `undefined` entries from normalized array output without deleting their raw child nodes. `omitEmpty` defaults to true; `trim` and `omitTrailing` default to false. See the [array output example](./examples/array-output-filters).

`options.propertyOrder` orders emitted object keys, not fields on screen: listed keys first, then remaining declared keys, then arriving additional keys. It creates no absent values, and integer-like keys still follow JavaScript's key ordering.

Declare virtual groups on an object as `options.virtual: { groupName: { fields: ['first', 'last'] } }`, using existing sibling property names. Do not author a schema with `type: 'virtual'`.

## Terminal strategy invariants {#terminal-strategy}

The strategy choice described in [node types](./core-concepts#node-types) must remain valid across gates. Opposite `options.terminal` settings on fixed-strategy scalar, union, or virtual nodes produce `TerminalOptionUnsupported`. A gate that could change one node between branch and terminal produces `TerminalStrategyMismatch`.

Among static ungated declarations, later `options.terminal` values win; a `$ref` target is treated after the referencing declaration. An ungated `oneOf`/`anyOf` branch's terminal option does not choose the host's strategy.

## Nullable, empty, and misfit values {#value-states}

`nullable: true` is a supported spelling for adding `'null'` to `type`; that spelling alone does not warn. Explicit `null`, `undefined`, and empty containers are different states. `null`, `false`, and `0` are values; `undefined` clears a field, and an empty string also clears it under default `omitEmpty`. `null` is not removed by `omitEmpty` or array output filters.

For a nullable object or array holding null:

- Assigning a container to the node or writing a value to an active descendant promotes it to a container. `insert(0, value)` promotes a null array like a push into an empty array; other indices do not.
- Defaults, derived values, branch restoration, and automatic `injectTo` alone do not promote it. Child inputs can remain visible without materializing a parent object.
- Clearing a descendant or merging an empty object retains null and remembers the clearing for later promotion.
- After loading null or a wrong-kind value, promotion leaves existing children empty; only newly created children receive defaults. Data discarded by assigning null does not return automatically.

Writing null to a non-nullable object preserves the wrong-kind value as a misfit; it does not repair it to `{}`. `setValue(undefined)` clears child values and array entries without restoring child defaults.

Arrays are replaced even with `SetValueOption.Merge`. A parent Overwrite that omits an array clears it, while a parent Merge that omits it retains it. See [write options](./api-reference#write-options).

## Controls and declaration layers {#controls}

A node has the following 14 control keys. `controls.fields[].controls` and fragment controls accept only the first ten keys in the list below, ending with `inactiveValue`; they cannot nest `fields`, `injectTo`, `discriminator`, or `watch`.

| Key | Meaning |
| --- | --- |
| `active` | Existence gate; false removes the field from shape and output. |
| `visible` | Visibility gate; false hides the input while retaining values and errors. |
| `readOnly` | Read-only lock. |
| `disabled` | Disabled lock, independent of presence. |
| `default` | Literal for a newly appearing node without a value; never compiled as an expression. |
| `derived` | Expression that overwrites on dependency change; undefined writes nothing. |
| `unsetValue` | Clears on false-to-true, and when true at load/new entry; staying true on a continuously live node does not clear repeatedly. |
| `resetInteraction` | Clears Edited and Touched on false-to-true, and on load/entry while true. |
| `unsetOnInactive` | Drops retained data on exit; node policy overrides the Form default. |
| `inactiveValue` | Literal or synchronous retained-value resolver; strings are literal. |
| `fields` | Array of &#123; targets: string[], controls &#125;; addresses direct children by name. |
| `injectTo` | Function that writes other paths from a changed source. |
| `discriminator` | Nonempty property name for object/nullable-object union selection. |
| `watch` | Array of dependency paths passed as watchValues in order. |

Standard `readOnly` and controls `readOnly`/`disabled` layers combine by OR for the target node's local input lock; `visible` layers combine by AND. The default branch-object input does not forward its local lock to child inputs; declaring that lock produces `LockOnNonTerminalObject`. Apply locks to direct children with `controls.fields`, or use Form `readOnly`/`disabled` for the whole form. Default precedence is node `controls.default`, parent `fields`, fragment `controls.default`, then standard `default`.

String expressions use form paths and context; see [path expressions](./api-reference#paths). This requires the [CSP capability](./quick-start#transpilation-csp).

## Retaining values on gate exit {#inactive-values}

An `inactiveValue` resolver receives the previous committed value, `dataPath`, `schemaPath`, current/parent/root schemas and values, and form context. Returning `undefined` preserves the original retained source. It runs only for a normal retained gate exit with automatic writes enabled, not load, reset, failure, budget overflow, a throwing gate, or an instance that only entered transiently during that settlement.

Caller JSON wins when the write causing exit explicitly covers that path; neither `onInactive` nor the resolver runs there. A whole ancestor write covers omitted descendants, while Merge covers supplied keys only. Multi-write batch merges are shallow. Explicit coverage is the union of all caller writes; later partial/empty merges or automatic writes do not erase earlier whole coverage.

After an array move, a resolver reads the preceding committed value and address but retains its result at the current address. Policy precedence is node, parent fields, then fragment; descendant results overwrite their own paths in an ancestor result. Retained results preserve undeclared keys and wrong-kind values under the usual inactive-JSON rules, and reentry consumes the overlay.

`unsetOnInactive: true` skips the resolver; declaring literal true together with `inactiveValue` in the same layer warns with `InactiveValueWithUnsetOnInactive`. For imperative exit listeners and cleanup migration, see [onInactive](./api-reference#inactive-listeners).

## Composition and conditional gates {#composition}

`oneOf` and `anyOf` branches participate according to `controls.active` or a host discriminator. Without gates all branches participate in form shape; the validator separately checks matching. Multiple gated `oneOf` branches can be active and warn with `MultipleGatedBranchesActive`. An `allOf` fragment with `controls.active` also participates conditionally.

The parent's type determines the node kind. A branch's different type does not replace it and still reaches the validator. Incompatible shared property kinds in static/ungated declarations produce `SharedNodeKindConflict`; gated declarations are not compared that way. Terminal objects skip child-kind comparisons and unreachable warnings, but retain discriminator mismatch, null-branch warnings, and static enum intersection errors.

`if` synchronously tests the host value and selects `then` or `else`. Without a validator both remain off. A guard compile/evaluation failure also turns both off and records `GuardFailed`; it is not a false verdict. A missing or non-object host is tested as `{}`: include `required` in a condition that requires a value. A host that cannot admit object warns with `IfOnNonObjectHost`; move the condition to an object host.

For nullable `oneOf`, include one null branch and explicitly declare `type: 'object'` on object branches so null can match exactly one branch. The null branch is validator-only: fields and active controls in it do not create form shape. The value decides nullness while gates decide the displayed object branch. The form does not warn merely because a nullable `oneOf` rejects null, so check that schema yourself; `anyOf` has no exactly-one condition.

## Discriminator selection and limits {#discriminator}

Declare `controls.discriminator` as a nonempty string on an object or nullable-object host. Malformed keys fail with `InvalidControlShape` before host checks; TypeScript rejects other host kinds. Each declaration selects only its own union, so declarations on one node can use different discriminator keys.

| Condition | Result |
| --- | --- |
| No `oneOf`/`anyOf` array | Ignored, reason `union` |
| Known non-object host | Ignored without reading the tag, reason `host` |
| No branch gives the key a `const`/`enum` tag | `DiscriminatorMismatch`, reason `missing` |
| Only some branches have tags | Untagged branches keep their own active controls without a discriminator gate |
| Overlapping `oneOf` tags | Mismatch, reason `overlap` |
| Repeated `anyOf` tags | All matching branches participate |
| No host tag type, incompatible branch tag kinds | Mismatch, reason `kind` |
| Host tag type is a union admitting the tag kinds | Allowed |
| Branch tag kind lies outside host type | Unreachable warning, reason `kind`; no tag promotion |
| Empty `const`/`enum` tag intersection | Unreachable warning, reason `empty`; always-off gate |

Comparison uses `===` and combines with the branch's `controls.active` using AND. A reachable branch-only tag property is promoted to an always-mounted child. An empty tag intersection still counts as a tag, and unreachable declarations do not augment an existing host child.

An untyped union host reads the tag but does not infer its own type from a gated branch. An ignored discriminator creates no gate, does not itself deactivate branchless paths, and performs no extra host-enum exclusion check.

Diagnostics include `propertyName` and `reason`, not tag values. Ignored warnings report once per declaration at `controls/discriminator`; unreachable warnings point to the branch schema location.

## Derived values and injection {#injection}

`controls.derived` maintains a target from its dependencies. `controls.injectTo` copies a changed source to other paths without preventing later edits at the targets. It is a function, returning a path/value map, an ordered array of `[path, value]` entries, or null to skip. Relative and absolute target paths can be mixed.

The handler receives the source value separately; its context contains `dataPath`, `schemaPath`, `jsonSchema`, `parentValue`, `parentJSONSchema`, `rootValue`, `rootJSONSchema`, and form `context`. A nonconvergent injection cycle stops after 25 derive rounds: caller writes remain, that settlement's automatic writes roll back, and a derive-degraded diagnostic and exception remain. A throwing handler skips that round's rule, leaves expression-degraded diagnostics, and reports `ExpressionThrew` to the caller.

## Input resolution {#input-resolution}

Schema selection uses `presentation.FieldInput`, then Form `fieldInputMap`, Form definitions, FormProvider definitions, and plugin definitions (including built-in fallbacks). A direct `FieldInput` on a composition component overrides that slot. Within definitions the first match wins. An inputType is a component-selection hint, not an HTML input type.

### Path matching {#input-map-keys}

`fieldInputMap` maps a node path to its input component. A key is a regular expression only when it starts with `^`; apart from the single-segment `*` wildcard, other keys are compared as text.

```tsx
<Form
  jsonSchema={schema}
  fieldInputMap={{
    '/settings/theme/color': ColorInput,
    '^/settings/': SettingsInput,
  }}
/>
```

| Key | Meaning |
| --- | --- |
| Starts with `^` | The node paths the expression finds a match in (`RegExp.test`). The leading `^` anchors the start; add `$` to anchor the end. |
| Starts with `/` or `#/`, has a segment exactly `*`, and does not end with `/` | Same segment count; each `*` consumes one segment, including array indexes and object keys. Every other segment is text. |
| Otherwise | Exact text. Absolute pointers are canonicalized once; relative text is compared as written and matches no node. |

Write names as they appear in a path in every kind of key: `/` as `~1`, `~` as `~0`, and a name exactly `*` as `%2A`. Thus `'/a~1b'` selects the property `a/b`, and `'^/a~1b$'` is its pattern equivalent. A noncanonical tilde such as `/a~b` is normalized to `/a~0b` in pointer keys; patterns see the escaped path without normalization.

A key that can match starts with `/`, `#/` or `^`, or is the root (`''` or `'#'`); `'/'` is an empty-name child, not the root. Use the field's data path, including a validation error's data path, rather than its schema location: `#/properties/contact` does not address `/contact` (it would address a data property named `properties` containing `contact`). Another library's `contact.email` or `items[0].name` notation is text no node path equals.

`'/user/(name|email)'` and `'/items/**/name'` select only properties literally named that way. `**` is not recursive. A wildcard key such as `'/files/*/images/(thumb|full)'` compares `(thumb|full)` literally; `'/items/*/'` is outside wildcard grammar and matches no node. These keys neither throw nor warn.

Inside a `^` key every character is regular-expression syntax: `'^/items/*/name$'` matches `/items/name`, not `/items/0/name`; one nonempty segment is `[^/]+`. In a JavaScript string write a backslash twice (`'^/users/\\d+$'`), and group alternatives (`'^/(billing|shipping)/email$'`). Patterns see no fragment `#`; `'^#/a'` matches nothing and `'^$'` selects the root.

| Intended selection | Key | Matches | Does not match |
| --- | --- | --- | --- |
| That node | `'/settings'` | `/settings` | `/settings/theme`, `/settingsBackup` |
| Direct children | `'/settings/*'` | `/settings/theme` | `/settings`, `/settings/theme/color` |
| Every descendant | `'^/settings/'` | `/settings/theme`, `/settings/theme/color` | `/settings`, `/settingsBackup` |
| The node and every descendant | Two keys with the same input: `'/settings'`, `'^/settings/'` | `/settings`, `/settings/theme/color` | `/settingsBackup` |
| A name at any depth | `'^.*/note$'` | `/note`, `/settings/theme/note` | `/notebook`, `/note/child` |

Do not substitute `'^/settings'` (also `/settingsBackup`), `'/settings/'` (an empty-name child), or `'/settings/**'` (a literal `**` child) for a descendant pattern. A descendant pattern includes object and array nodes along the path: their input must render `ChildFields` or their descendants disappear; see the [custom input contract](./api-reference#hybrid-parent-inputs). To select only leaf fields, use a `fieldInputDefinitions` entry with a `test` function that checks the hint's type and path.

The first matching key in `Object.keys` order wins regardless of kind; an exact key does not outrank an earlier pattern. Put exact keys before `*` keys before `^` keys. When extending a shared map, put local exceptions first and spread the shared map last.

An unmatched key is ignored without diagnostics, whether caused by a typo, a renamed property, or a node not rendered yet (an empty array or inactive branch). If the input changes stored values through units, masks or normalization, cover its key with a test. Only an uncompilable `^` pattern produces `FormTypeInputMap`: the entire replacement map is rejected and the tree keeps its last committed valid map, including unchanged inputs; on first load there is no valid map and the form displays its load fallback. Replace the map reference with a valid one to recover; see [configuration failures](./error-reference#occurrences) and the [migration table](./migration-from-0x#input-map-keys).

`FieldInputTestObject` accepts a single value or list for `type`, `schemaType`, `path`, `format`, and `inputType`, plus boolean `required` and `nullable`. Omitted conditions do not restrict matching. A virtual node has `type: 'virtual'` and `schemaType: undefined`; do not match `schemaType: 'virtual'`.

Use `presentation.FieldInputProps` for input-specific settings because it is forwarded to the input. Custom settings such as `lazy`, `protocols`, or `minRows` in `options` are accepted, but an input must explicitly read them from the node schema. A direct schema `inputType` or `FieldInput` is not a substitute for the presentation group.

### Skipping remounts for a controlled input {#controlled}

A value an input did not write itself (`setValue` at any scope, reset, `refresh(path)`, `derived`, `injectTo`, `unsetValue`, array operations) remounts that input and hands it a new `defaultValue`. An input that draws from `value` on every render does not need the remount: declare `controlled: true` on its `FieldInputDefinition`, or per field in `presentation.controlled`, and it keeps its DOM, focus and local state while the new value arrives through `value`.

| `controlled` | A value the input did not write |
| --- | --- |
| omitted or `false` | remount with a new `defaultValue` |
| `true` | new `value`, no remount |

This is an optimization for fields recalculated often and for widgets that are expensive to mount. Declare it only for a component that keeps no copy of the value: a copied draft would survive a reset. An inline `presentation.FieldInput`, a `fieldInputMap` component, and a `FieldInput` passed to `Form.Input`, `Form.Field` or `Form.Render` can only be declared in the schema. `false` on either side wins, so a schema can switch a controlled definition back for one field. A direct input write preserves the emitting input; a parent override follows the [hybrid parent contract](./api-reference#hybrid-parent-inputs). `remount(path)` replaces an input whatever it declares. The UI plugins declare their checkbox, switch and stepper inputs that draw from `value`.

## Custom-input accessibility {#accessibility}

Use `id={path}` on a single custom input so its label can target it. Group inputs reference `label:${path}` with `aria-labelledby`. Built-in checkbox/radio choices use `${path}-${index}` and matching `htmlFor` inside a named `role="group"` container. Update DOM selectors accordingly.

At a root, array item, or unlabeled composition where `label:${path}` is absent, the custom renderer must supply an accessible group name. `Form.Label` derives its id and htmlFor from the supplied path, so use the actual absolute input path for that association.

The built-in enum select represents undefined as a selected, disabled empty option first in the list; an out-of-enum value gets its own disabled option. It does not silently choose the first enum item.

## Official UI plugin input selection {#ui-selection}

The following patterns apply to antd-mobile, antd5, antd6, and MUI. Here `inputType` means `presentation.inputType`. These are matching conditions, subject to the first-match order in [input resolution](#input-resolution).

| Condition | Input |
| --- | --- |
| Boolean + inputType `switch` | Boolean switch |
| String-item array with items.enum + inputType `checkbox` | Checkbox group |
| String with exactly two enum entries + inputType `switch` | String switch |
| String / number / integer enum + inputType `radio` or `radiogroup` | Radio group |
| Array not matched earlier | Add/remove array input |
| String + (`format: 'textarea'` or `presentation.inputType: 'textarea'`) | Multiline input |
| Remaining string | Text input; format `password` uses password display |
| Remaining number / integer schemaType | Number input |
| Remaining boolean | Checkbox |

Antd5, antd6, and MUI also select a URI input for string `format: 'uri'` or inputType `uri`; month/date/time inputs for string format `month`/`date`/`time`; a number/integer slider for inputType `slider`; and a Select for string enums. Antd5/6 select multiple Select for string-item arrays with `items.enum`, and range inputs for string-item arrays with format `month-range`/`date-range`/`time-range` or inputType `monthRange`/`dateRange`/`timeRange`.

Antd-mobile's slider uses numeric format `slider`. Its general array definition precedes its numeric-array slider test, so numeric arrays do not automatically become range sliders. Supply a suitable custom `presentation.FieldInput` or an earlier form definition for range UI; no standalone mobile slider component is exported by the plugin entry point.

## Shared input settings and labels {#ui-settings}

Pass input props using [presentation.FieldInputProps](#input-resolution).

| Input | Antd-mobile, antd5, antd6 | MUI |
| --- | --- | --- |
| Boolean switch | Checked/unchecked labels through `alias: { checked, unchecked }` or `context.checkboxLabels` (context wins) | `label`, `hideLabel`, `size`; no separate checked/unchecked text |
| Checkbox group | Enum-value labels through `alias` or `context.checkboxLabels` | Enum-value `alias` labels |
| String switch | Enum-value labels through `alias` or `context.switchLabels` | Reads schema-level `switchLabels` tuple and `switchSize`; these are current input-specific exceptions |
| Radio group | Enum-value labels through `alias` or `context.radioLabels` | `alias`, with schema `radioLabels` entries taking precedence |
| Array | Add/remove buttons hidden when readOnly | Add/remove buttons hidden when readOnly |
| Textarea | `minRows`, `maxRows` | `minRows`, `maxRows` |
| Number | Schema `minimum`, `maximum`, `multipleOf` supply min/max/step | Same schema values; integer fallback step 1, other numbers allow any step |
| Boolean checkbox | Undefined can display indeterminate | Undefined can display indeterminate |

For mobile Boolean Switch, the context label object specifically uses `context.checkboxLabels.checked` and `.unchecked`. Do not reuse an unrelated label shape.

## URI, date, and slider contracts {#date-uri-slider}

| Setting | Antd5 / antd6 | MUI |
| --- | --- | --- |
| URI protocols | `FieldInputProps.protocols`; default `http`, `https`, `ftp`, `mailto`, `tel` | Same prop; default `http`, `https`; also handles single-colon protocols such as `mailto`, `tel` |
| Month | `FieldInputProps.minimum` / `maximum`; `YYYY-MM` | `YYYY-MM`; month range limits are not connected |
| Date | `FieldInputProps.minimum` / `maximum`; `YYYY-MM-DD` | Schema-level `minimum` / `maximum` become minDate/maxDate; `YYYY-MM-DD` |
| Month / date ranges | `FieldInputProps.minimum` / `maximum`; arrays of corresponding month/date strings | No corresponding range definitions |
| Time | dayjs format `HH:mm:00Z` | `HH:mm:ss` |
| Time range | `FieldInputProps.minimum` / `maximum`; array of `HH:mm:00Z` values | No corresponding range definition |
| Slider | `lazy: false` publishes each movement; omitted lazy publishes on release | `lazy` defaults false; true publishes on release; `showMarks` controls marks and value labels display automatically |
| Number formatting | `FieldInputProps.formatter` / `parser` | Use a custom input for a different formatting contract |

In this table `FieldInputProps.*` always means `presentation.FieldInputProps.*`. The Antd time format's `Z` is a timezone offset token. Its time input does not expose the range input's minimum/maximum props.

Mobile sliders accept `range`, `marks`, and `lazy` in that same prop group. `lazy: false` publishes on movement; omission publishes on release. Numeric-array selection still has the [first-match restriction](#ui-selection).

UI bounds guide interaction; schema validation remains responsible for accepting or rejecting the final value.
