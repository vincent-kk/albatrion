# Migration from 0.x

## Migration order and silent keys {#migration-order}

To use the current API, migrate schema configuration first, component/type imports next, and node state / validation issue handling last. The form engine does not alias or warn for old top-level configuration keys such as formType or computed: move them explicitly into their current groups. A separately configured validator can still reject unknown schema keywords under its own policy.

Use this guide as a conversion checklist, then consult the linked current contracts rather than retaining both spellings.

## Behavior checks after conversion {#behavior-checks}

- Check [open options and presentation, and closed controls](./schema-reference#authoring-groups); move plugin input settings to presentation.FieldInputProps so they reach the input, and check reserved value types in all three groups.
- Update DOM tests for [enum empty values and checkbox/radio naming](./schema-reference#accessibility).
- Match virtual inputs using the [current test hint](./schema-reference#input-resolution).
- Supply a complete [validator object](./validation#validator-contract).
- Use the string ErrorVisibility enum and its AfterEdit / AfterEditAndTouch policies. Check [error visibility](./validation#visibility) for the default policy, display conditions, and Form errorVisibility prop/handle behavior.
- Use `parentJSONSchema` and `rootJSONSchema` in injectTo context.
- Read `origin` on the inferred onError callback record, using the [occurrence contract](./error-reference#occurrences).
- Replace component cleanup writes with [inactive-value resolution](./api-reference#inactive-listeners); reacquire nodes after reset/reentry.

| Before                                          | After                                                                                  |
| ----------------------------------------------- | -------------------------------------------------------------------------------------- |
| `ShowError.Always / Never`                      | `ErrorVisibility.Always / Never`                                                       |
| `ShowError.Dirty / Touched / DirtyTouched`    | `ErrorVisibility.AfterEdit / AfterTouch / AfterEditAndTouch`                           |
| `ShowError.Dirty \| ShowError.Touched`         | `ErrorVisibility.AfterEditOrTouch`                                                     |
| `showError={true}` / `showError={false}`        | `errorVisibility={ErrorVisibility.Always}` / `errorVisibility={ErrorVisibility.Never}` |
| `handle.showError()` / `handle.showError(true)` | `handle.revealErrors()`                                                                |
| `handle.showError(false)`                       | `handle.resetErrorVisibility()`                                                        |
| `useChildNodeErrors().showError / .showErrors` | `useChildFieldErrors().errorVisible / .childErrorVisibleList`                                               |

The 0.x spellings have no compatibility aliases. `ErrorVisibility` is a string enum, not a bit mask: replace combinations with the named policy rather than combining enum values. Search application wrappers, persisted settings, custom renderers and tests as well as direct Form calls.

## Submission and issue handling {#submission}

Test native Enter and a submit button separately from `handle.submit()` / `useFormSubmit`. An invalid native schema verdict reveals errors and focuses the first eligible invalid field without calling `onSubmit`, `onError`, or the host error sink. `ErrorVisibility.Never` suppresses both reveal and focus; form-wide readOnly/disabled suppress focus only. Imperative submission still rejects, and does not reveal automatically: catch the rejection and explicitly call `revealErrors()` when that is your UX. Compilation failures, degraded forms and application callback failures are distinct from an invalid verdict; preserve the [submission failure handling](./error-reference#submission).

A terminal object/array root receives issues for paths inside its whole value. Do not duplicate those issues onto synthetic children or interpret an empty child tree as successful validation. Use `getErrors()` / `validate()` for the verdict and `node.errors` for routed field feedback.

## Settings after mount {#live-settings}

Remove `onChange` and `onFileAttach` from `Form.Input`, `Form.Render` and `Form.Field`; relay callbacks belong on Child or renderer Input. Remove child/layout `value` and `defaultValue` overrides; initialize with Form.defaultValue and write subsequent values through the parent callback or handle. Move `presentation.FieldInputProps.required` to `presentation.required`; required in either props bag is ignored. For renderer and input `required`, follow [the display override contract](./api-reference#composition).

Remove Form key changes used only to apply configuration, after checking the lifetime below. Replace configuration objects, arrays and callbacks immutably; mutating an existing reference is not a supported update signal. Explicit Form settings take precedence over FormProvider defaults. FormProvider has no `fieldInputMap`, `virtualization`, `readOnly`, `disabled`, `unsetOnInactive`, or `disableAutomaticWrites` prop.

| Setting                                                                  | Migration check                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `jsonSchema`, `defaultValue`                                             | Changing props preserves edits until `reset()` reads the latest committed inputs. `rebuild()` replaces the root and rereads defaults. Neither method accepts replacement form data; use `setValue` for a value write.                                        |
| `validatorFactory` on Form or FormProvider                               | Swapping after mount is unsupported: a changed selected reference re-initializes through reset, discarding edits and applying committed schema/default changes. Do not create the object per render; see the [full reset effects and stable setup](./api-reference#configuration-lifetime). |
| `validationMode` on Form or FormProvider                                 | Changes apply to the existing tree. `None` cancels pending work and clears validator issues while preserving external issues; switching to OnChange schedules current-value validation. Check the [mode transition rules](./validation#modes).               |
| `unsetOnInactive`, `disableAutomaticWrites`                              | Changes affect the next engine entry, without replaying earlier transitions or refilling values. An open write chain keeps its existing settings. Child layout-effect calls before settings commit use the preceding committed settings.                     |
| `errorVisibility` on Form or FormProvider                                | The committed policy updates live. Replace `showError` and boolean/mask settings with the named enum; check node overrides and `revealErrors()` / `resetErrorVisibility()`.                                                                                  |
| Renderer slots and `formatError` on Form or FormProvider                 | A changed renderer recreates the UI subtree it owns. A formatter update changes messages and can recover a failed formatter boundary; a healthy input need not remount.                                                                                      |
| `fieldInputDefinitions` on Form or FormProvider, `fieldInputMap` on Form | Selection updates live, retaining node values, state and external issues. A changed selected component remounts that input; a changed parent input also recreates descendant DOM and uncommitted drafts. Stable selections and ancestors preserve input DOM. |
| `context`, Form `readOnly` / `disabled`                                  | Context and input locks apply live. Context uses a content snapshot, so equal-content Date/Map/class objects do not force an update. Input locks do not prohibit imperative node writes.                                                                     |
| Form callbacks, `errors`, `children`, `ref`                              | Use current committed callbacks and layout; replace the errors array to reapply external issues. Reacquire the current handle/node after root replacement. For hidden forms, follow the callback lifetime below.                                             |
| Form `virtualization`                                                    | All options update live, subject to the one-way reveal and hydration limits below.                                                                                                                                                                           |

`Form.Field`, `Form.Input`, and `Form.Render` have their own mount-fixed component/children overrides. For those overrides, use live context, hooks inside the component, or a deliberate new key; the Form-wide live settings do not change this [composition contract](./schema-reference#input-resolution).

An uncompilable explicit pattern such as `^/invalid[` reports `FormErrorCode.FormTypeInputMap` with `origin: 'load'` once after commit, including StrictMode. An initial failure keeps the load fallback; a failed live replacement keeps the tree and last valid map. Replace the map with a valid reference to recover. An input component throwing during render remains a render failure; do not classify it by the thrown code alone.

## Input-map keys {#input-map-keys}

This is a breaking change from 0.16: keys without a leading `^` no longer have a regular-expression fallback. Except for the existing one-segment `*` wildcard, they compare as text. There is no development warning, including for a plain key that relied on capturing descendants; that dependency cannot be detected automatically.

| Intent or 0.16 key | Write now | Matches | Does not match |
| --- | --- | --- | --- |
| `'/contact'` meant one node | `'/contact'` | `/contact` | `/contact/first`, `/contacts`, `/a/contact/b` |
| Direct children only | `'/contact/*'` | `/contact/first` | `/contact`, `/contact/a/b` |
| Every descendant, excluding the node | `'^/contact/'` | `/contact/first`, `/contact/a/b` | `/contact`, `/contacts` |
| The node and every descendant | Two keys with the same input: `'/contact'`, `'^/contact/'` | `/contact`, `/contact/a/b` | `/contacts` |
| Bounded pattern alternative | `'^/contact(?:/\|$)'` | `/contact`, `/contact/first` | `/contacts` |
| Mistake: `'^/contact'` as a subtree boundary | Use the bounded forms above | `^/contact` also matches `/contacts` | It does not match `/a/contact` |
| `'/user/(name\|email)'` as a pattern | `'^/user/(name\|email)$'` deliberately narrows the old substring match | `/user/name`, `/user/email` | `/a/user/name`, `/user/email/child` |
| `'#/users/\\d+/profile'` as a pattern | `'^/users/\\d+/profile$'` (drop `#`) | `/users/12/profile` | `/users/a/profile`, `/users/12/profile/more` |
| `'/name'` matched in the middle | `'/*/name'` for one depth, or `'^.*/name$'` for any depth | `/user/name` | `/user/name/child` |
| `'contact.email'`, `'items.0.name'` relied on `.` matching `/` | `'/contact/email'`, `'/items/*/name'` | `/contact/email`, `/items/0/name` | `/contact/email/child`, `/items/0/deep/name` |
| `'#email'` lost `#` and matched the substring `email` | The old key now matches nothing; use `'/email'` for that node or `'^.*/email$'` for that name at any depth | `/email`; the pattern also matches `/contact/email` | `/emailBackup`, `/email/child` |
| `'email'` relied on substring matching | `'^.*/email$'`, or a definition with a `test` function | `/email`, `/contact/email` | `/emailBackup`, `/email/child` |
| `'/name$'` relied on a suffix pattern | `'^.*/name$'` | `/name`, `/user/name` | `/username`, `/name/child` |
| `'/items/**/name'`, `'/price['` produced compile errors | Keep them only for those literal names; they no longer throw | `/items/**/name`, `/price[` | `/items/0/name`, `/price` |
| `{ '/contact': A, '/contact/first': B }` gave A to both | Keep the map to give B to the child | A at `/contact`, B at `/contact/first` | A no longer captures `/contact/first` |
| Existing `^` patterns and recognized `*` wildcards | Keep them | `'^/contact$'` → `/contact`; `'/items/*/name'` → `/items/0/name` | Those keys exclude `/contact/child` and `/items/0/deep/name` respectively |

For example, migrate `'/user/(name|email)': Input` to `'^/user/(name|email)$': Input` when only those two paths are intended. Adding `^` alone preserves an open end but removes middle-of-path matches. Preserving the entire old substring behavior would require a prefix such as `^[\s\S]*` (double the backslashes in a JavaScript string); prefer the bounded recipes above instead. Patterns match escaped data paths, not fragment-prefixed paths. See [path matching](./schema-reference#input-map-keys) for order, branch inputs and silent nonmatches.

## Observation, hidden forms, and inferred values {#observation-types}

- Pass `null` or `undefined` directly to `useFieldNodeTracker` and `useFieldNodeSubscribe` when a node is absent. The tracker returns 0 without subscribing; the subscription hook calls neither listener nor `onSubscribe`. Both release the old subscription when their node argument changes. Kind/strategy guards return false for either absent value. Required callback nodes, such as `onSubscribe`, `visitSubtree`, formatter and placeholder nodes, remain required.
- Ref assignment alone does not rerender the observer. A hook reading `formRef.current?.node` needs a consumer rerender after binding or root replacement; otherwise it stays on the old node. Prefer Form's function children when the observer belongs to the form.
- A shown form resynchronizes inputs to current node values after being hidden, including an unfinished IME draft. React detaches the ref while hidden: use a handle/node retained after visible mount to write. Callbacks from a prepared current load can continue while hidden and are not replayed on showing; clean up subscriptions. See [hidden lifecycle](./api-reference#hidden-lifecycle).
- Literal finite `prefixItems` gives optional-position tuples in `InferValueType`, Form and FormHandle; unrestricted indexes and extra elements can become type errors. Preserve literals with `as const`, inspect the `items` rest rule, and use the same explicit value generic on Form and FormHandle when your application needs an exact shape. Object keys remain optional and inferred values are not proof of validation. See [TypeScript inference](./api-reference#typescript).

## Virtualization and exact focus {#virtualization}

Virtualization defers input DOM, not the node tree or submission data. Turning it off reveals waiting fields and stops observation/backfill. Re-enabling it, changing `threshold` or `eagerCount`, or recreating child lists never re-hides an already revealed node. `rootMargin` and `backfill` reconfigure waiting placeholders; `estimateHeight` and `Placeholder` change their presentation. Preserve callback references to avoid needless reconfiguration.

Replace ancestor-focus workarounds with `handle.focus(path)` / `select(path)`: a pending target behind nested gates or virtual groups is revealed along its render path and focused at its exact input. A newer request, reset/root replacement, confirmed unmount or disappearing gate cancels a reveal reservation. User focus movement, including away-and-back or blur to the body, suppresses its action. An unrelated option update preserves the request; an option update revealing its gate delivers it at that commit.

Test your actual custom layout: omitted inputs, terminal interiors, hidden Activity and inputs suspended during reveal cannot be reached. Hidden/disabled/inert controls may refuse focus; native invalid-submit does not try a second candidate. Mounted duplicate positions retain ordinary request behavior, and ordinary node commands have a different cancellation lifetime from reveal reservations. Placeholder height changes do not receive scroll correction. Deferred DOM is unavailable to page search, accessibility tools and autofill until revealed; idle backfill promises no completion deadline.

SSR renders all fields; hydration preserves them, with gating only for later-added branches/children. Without IntersectionObserver rendering is eager. See [virtualization](./api-reference#virtualization) for focus selection, duplicate positions and React 18 hydration limits.

## AJV migration {#ajv}

AJV6, AJV7 and every AJV8 dialect entry refuse `bind(instance)` immediately when `coerceTypes`, `useDefaults`, or `removeAdditional` is enabled. Turn these options off before binding. The failure has `group: 'UNHANDLED_ERROR'` and `code: 'UNHANDLED_ERROR.VALIDATOR_BIND_REFUSED'` (`FormErrorCode.ValidatorBindRefused`); it is a native plugin error, so the core `isUnhandledError` guard does not recognize it. A refused instance does not replace the active binding.

Move coercion to an explicit application input conversion, establish defaults through schema/defaultValue and the form's load rules, and remove unwanted keys in an explicit application transformation. Test the resulting submitted value; do not depend on validation to mutate the form. In particular, enabling `removeAdditional` is not a substitute for rejecting extra keys with JSON Schema.

AJV8's built-in instances set `allowUnionTypes: true`. This removes the strictTypes log for multiple non-null types without changing which values satisfy the union and without enabling coercion. A consumer-bound instance retains its own strict options; configure it deliberately. AJV7 defaults to `strict: false`; AJV6 does not have AJV8's strictTypes union warning. Keep [validator configuration and dialect support](./validation#ajv-configuration) separate from input selection.

## UI plugin union inputs {#plugin-unions}

Upgrade the UI plugin with the core. With core 0.16.1 and UI plugins 0.16.0, a multiple-non-null declaration such as `type: ['string', 'number']` fails schema loading; a nullable single kind is not that case. The current engine creates a terminal `UnionNode`. None of the four official UI plugins automatically selects its single-kind input for that union, so the core draft input handles it unless you provide an earlier union definition or a path/inline override.

| UI plugin                                | Union migration                                                                                                                                                          | Preserved selection to check                                                                  |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| `@canard/schema-form-antd5-plugin`       | Replace a rejected multi-kind schema or custom workaround with an explicit union input when Ant Design styling/type selection is required; otherwise use the core draft. | Nullable strings still select Ant Design Input; integers select InputNumber.                  |
| `@canard/schema-form-antd6-plugin`       | Use the same union decision explicitly; Ant Design 6 inputs do not become a multi-kind editor merely by upgrading.                                                       | Nullable strings still select Ant Design Input; integers select InputNumber.                  |
| `@canard/schema-form-antd-mobile-plugin` | Provide a custom union editor when mobile input/choice UI is required; the core draft is the automatic fallback.                                                         | Nullable strings still select mobile Input; integers select Stepper.                          |
| `@canard/schema-form-mui-plugin`         | Provide a custom union editor when Material UI presentation is required; the core draft is the automatic fallback.                                                       | Nullable strings and integers still select TextField with text and number input respectively. |

Migrate custom definitions with the [input selection contract](./schema-reference#input-resolution): `Hint` becomes `FieldInputHint`; integer hints and input props have `type: 'number'`, `schemaType: 'integer'`. A `type: 'number'` test includes integers; use `schemaType: 'integer'` for integer-only matching. Multiple non-null kinds use `type: 'union'` and a schemaType array, with `nullable` separate. `FieldInputProps` supplies `misfit` for rejected interpretation; do not silently repair that value. Object-test keys are closed: unsupported keys are ignored with a development warning, so move custom matching to a predicate rather than relying on an unknown key to reject a definition. `type: 'integer'` is not a supported node-kind test.

## Remaining application behavior audit {#application-audit}

Use application tests to decide whether each item applies; renaming imports alone does not cover the release line.

- Check null, undefined, empty strings and containers, nullable-parent promotion and array replacement against [value states](./schema-reference#value-states). `minItems` is a constraint, not a promise to create submitted entries. Empty inputs publish undefined; explicit null is intentional. `omitTrailing` filters output without deleting raw nodes, and `propertyOrder` orders output keys, not screen fields.
- Replace timing assumptions: `onChange` and node notifications settle synchronously at the outer write boundary. Test batches and callbacks that write again, and use [event revisions and subscription catch-up](./api-reference#events-hooks) instead of waiting for an assumed microtask.
- Audit conditional composition: ungated oneOf/anyOf branches all participate in shape; validation is separate. Use controls or a discriminator for branch selection, provide a validator for if, and test shared-property conflicts, nullable branches and terminal strategy. See [composition](./schema-reference#composition) and [discriminators](./schema-reference#discriminator).
- Distinguish Edited/Touched from `isDivergent` and the current load baseline. Reacquire nodes on reentry/root replacement; detached nodes do not write into the live form. Replace cleanup-time writes with the [inactive resolver contract](./api-reference#inactive-listeners).
- Use resolved custom-input locks and the [accessible naming contract](./schema-reference#accessibility). A branch object's local lock does not automatically lock all children: use `controls.fields` or a form-wide lock. Test enum empty options and radio/checkbox selectors.
- Keep schemas and configuration immutable, clean up subscriptions, handle degraded diagnostics and execution failures separately from raw validation issues, and verify [CSP requirements](./quick-start#transpilation-csp) before deploying expression-based controls.

## Renderer parts and input error feedback {#renderer-parts}

These are breaking changes. Apply the names to Form props, FormProvider props and plugin members, and import the new dedicated prop types from @canard/schema-form. Old registration keys are silently ignored at runtime. TypeScript rejects old keys in object literals and JSX props; a plugin object typed elsewhere, such as one from an older plugin package, still compiles and its old keys are ignored. A successful render is not evidence that an old key applied. registerPlugin failure messages list the plugin’s slots by the new names.

| Previous name | Current name / contract |
| --- | --- |
| `FormLabelRenderer` | `LabelRenderer` / `LabelRendererProps` |
| `FormInputRenderer` | `InputRenderer` / `InputRendererProps` (frame) |
| `FormErrorRenderer` | `ErrorMessageRenderer` / `ErrorMessageRendererProps` |
| `Form.Error` / `FormErrorProps` | `Form.ErrorMessage` / `FormErrorMessageProps` |

Form.Label and Form.ErrorMessage do not add an outer label/span. A renderer returning bare text must now own its label and apply htmlFor/id. The following snippets show the previous and current registration. Keep the component reference stable.

```tsx
// Before
const LegacyLabel = ({ name }: FieldRendererProps) => <>{name}</>;
registerPlugin({ FormLabelRenderer: LegacyLabel });
```

```tsx
// After
const Label = ({ htmlFor, id, children }: LabelRendererProps) => (
  <label htmlFor={htmlFor} id={id}>{children}</label>
);
registerPlugin({ LabelRenderer: Label });
```

Replace the previous standalone slot:

```tsx
// Before
<Form.Error path="/name" />
```

```tsx
// After
<Form.ErrorMessage path="/name" />
```

Real inputs no longer receive errors/errorVisible props or re-render just for error changes when no deferred Refresh is pending. Import useFieldErrors to opt into feedback. This excerpt changes only the feedback; retain your input control and its onChange.

```tsx
// Before
const Input = ({ errors, errorVisible }: FieldInputProps) => (
  <span>{errorVisible && errors[0]?.message}</span>
);
```

```tsx
// After
const Input = ({ node }: FieldInputProps) => {
  const { errorMessage } = useFieldErrors(node);
  return <span>{errorMessage}</span>;
};
```

Search all custom inputs, destructuring, member reads and prop payloads for `errors` and `errorVisible` (for example, `rg "errors|errorVisible" src`). Their @deprecated optional-never keys catch member access such as errors.map and passing values, but a bare `if (errorVisible)` can still compile and read undefined. Typecheck alone cannot finish this migration. For hook limits and ownership, read [useFieldErrors](./api-reference#field-errors).

The default group renders no empty em when a message is absent. A selector such as `[data-path="/branch"] em` can therefore match a descendant’s message; check that the message element’s closest data-path is the desired field. The default group removes the non-required label’s trailing space and marks its existing required asterisk aria-hidden; a default standalone Form.Label now shows the same asterisk. Form.Label accepts children for explicit copy. These markup excerpts omit other attributes and input markup. Group label/error markup without a message:

```html
<!-- Before -->
<label for="/name">name </label><em></em>
<!-- After -->
<label for="/name">name</label>
```

For a required standalone default label, the data-path div moves from inside the label to outside it; selectors such as `label > div` must change. Other attributes are omitted:

```html
<!-- Before -->
<label for="/name"><div data-path="/name">name</div></label>
<!-- After -->
<div data-path="/name"><label for="/name">name <span aria-hidden="true">*</span></label></div>
```

Replace a pass-through input renderer with a deliberate frame, or omit it. Follow [the children and unwrapped lifetime contract](./api-reference#input-frames); changing the ancestor path restarts the input with the current node value and loses focus/composition. The [bound part defaults](./api-reference#renderer-parts) replace hand-drawn labels and errors.
