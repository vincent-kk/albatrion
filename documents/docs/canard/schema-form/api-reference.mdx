# API Reference

Import consumer APIs from `@canard/schema-form`. Types inferred from callbacks can describe records that are not named package exports; do not import an implementation-only type by guessing its name.

## Form props {#form}

| Prop                                                        | Use                                                                                |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `jsonSchema`                                                | Required schema used on root load.                                                 |
| `defaultValue`                                              | Initial value read at root load; no controlled value prop.                         |
| `onChange`                                                  | Synchronous output callback.                                                       |
| `onSubmit`                                                  | Value callback after accepted submission; may return a promise.                    |
| `onValidate`                                                | Raw error-list changes; equal validation results are skipped.                      |
| `onStateChange`                                             | Whole-tree interaction aggregate changes.                                          |
| `onError`                                                   | Occurrence channel; see the error reference.                                       |
| `onDiagnosticsChange`                                       | Root diagnostic changes after preparation; initial diagnostics are on handle.node. |
| `readOnly / disabled`                                       | Form-wide input locks, default false.                                              |
| `unsetOnInactive`                                           | Default exit-removal policy, overridden by node controls.                          |
| `disableAutomaticWrites`                                    | Suppress automatic writes while allowing imperative writes.                        |
| `errors`                                                    | External issues, reapplied on array-reference changes and reset.                   |
| `errorVisibility / validationMode`                          | Policies described in Validation.                                                  |
| `validatorFactory`                                          | Complete validator object; see Validation.                                         |
| `FieldRenderer`                                             | Group renderer for fields.                                                         |
| `FormLabelRenderer / FormInputRenderer / FormErrorRenderer` | Composition renderers.                                                             |
| `formatError`                                               | Error-to-ReactNode formatter with a required node argument.                        |
| `fieldInputDefinitions / fieldInputMap`                     | Ordered tests and path overrides; see input resolution.                            |
| `virtualization`                                            | Deferred input mounting, off by default.                                           |
| `context`                                                   | Live form context merged over provider context.                                    |
| `children`                                                  | Layout or function receiving node, jsonSchema, defaultValue, value, errors.        |
| `ref`                                                       | FormHandle for the current root.                                                   |

See [rendering](./core-concepts#rendering), [input resolution](./schema-reference#input-resolution), [validation](./validation), and [error reporting](./error-reference#occurrences) for the conditions behind these props.

## Root loads and configuration lifetime {#configuration-lifetime}

Changing `jsonSchema` or `defaultValue` alone preserves the current tree and edits. `reset()` reads the latest committed props, clears attached files, and reloads defaults. Function children receive the schema of their current tree, so before reset they do not pair the newer schema prop with the old node. Reset accepts only an automatic-write override flag, not a replacement value.

`rebuild()` invalidates that schema object's cached analysis and replaces this Form's root using reset's load options. Another Form using the same schema object keeps its existing tree. Reacquire nodes from the current handle after replacement.

Changing the `validatorFactory` reference rebuilds the Form tree, so use a stable object for an unchanged configuration. Context and input locks can change live; renderer/input configuration follows the [live rendering rules](./core-concepts#rendering).

Replace an invalid input map with a valid map to recover without remounting. A failed live map change preserves the existing tree and last valid map; see [input-map errors](./error-reference#occurrences).

`validationMode`, `unsetOnInactive`, and `disableAutomaticWrites` apply to the existing tree at commit, preserving values, interaction and node identity. Write defaults affect the next engine entry without retroactive writes. See [validation modes](./validation#modes) for cancellation, errors and reactivation. Calls from child layout effects before the Form settings commit use the last committed settings.

## FormHandle {#form-handle}

| Member                                            | Use                                                                                                                                                                                                                                                        |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `node`                                            | Current root, undefined before mount.                                                                                                                                                                                                                      |
| `getValue() / setValue(valueOrUpdater, options?)` | Read output / write the root.                                                                                                                                                                                                                              |
| `findNode(path) / findNodes(path)`                | First or all matching live nodes; no match returns null or [], respectively.                                                                                                                                                                               |
| `getState() / setState(flags) / clearState()`     | Read aggregate flags / patch or clear the whole tree.                                                                                                                                                                                                      |
| `getErrors() / validate()`                        | Raw issues / a promise for a fresh verdict.                                                                                                                                                                                                                |
| `focus(path?) / select(path?)`                    | Focus the exact input through nested virtualization gates, using the first input, textarea, select, or button in its input container in DOM order; request text selection on the first input or textarea, skipping buttons and selects. Selection calls the element's select method when available. |
| `refresh(path?) / remount(path?)`                 | Re-read committed input values / remount a rendered subtree.                                                                                                                                                                                               |
| `reset(option?) / rebuild(option?)`               | Root load operations described above.                                                                                                                                                                                                                      |
| `revealErrors()` / `resetErrorVisibility()`       | Display override; see Validation.                                                                                                                                                                                                                          |
| `getAttachedFilesMap()`                           | Map&lt;string, File[]&gt;; see the file example.                                                                                                                                                                                                           |
| `submit()`                                        | Promise-returning imperative submission; handler also exposes pending and subscribe. See [native and imperative submission](./error-reference#submission) for rejection and reveal behavior.                                                               |

Focus/select/refresh/remount with no matching node do nothing. Before mount, `findNode` returns null, `findNodes`/`getErrors` return empty arrays, `validate()` resolves an empty array, and `getState()` returns an empty object. These empty query results do not establish a validation verdict.

## Write options and subtree walks {#write-options}

Use `SetValueOption.Overwrite` (default) or `Merge`, with an optional `DisableAutomaticWrites` or `EnableAutomaticWrites` override. Do not combine Overwrite and Merge or conflicting automatic-write flags. [Value rules](./schema-reference#value-states) explain object/array consequences.

`node.batch(fn)` groups synchronous writes. `visitSubtree(visitor)` visits self, then descendants in preorder/sibling order; returning false skips that node's descendants. The visitor receives a required FieldNode. A live walk visits current shape; a detached walk visits the frozen subtree. A node reachable twice is visited once, and new nodes created during the walk may be missed.

Value writes settle once at the end, so intermediate value reads see the preceding commit. State/external-error changes apply immediately but their events wait; an enclosing batch postpones everything to its end. A Form reset or `resetSubtree()` still settles its load immediately outside that enclosing batch. A read-only walk opens no write boundary until a write occurs and can run inside listeners.

A visitor failure applies writes already made and then propagates. When a value-writing walk runs inside a listener, its failure may be reported through the listener channel instead of returning to the direct caller. The handle has no visitSubtree method; use `handle.node`.

## Form composition and custom inputs {#composition}

`Form.Field` renders a group; `Form.Label`, `Form.Input`, and `Form.Error` render individual slots. `Form.Render` takes function children receiving `FieldRendererProps`, including `node`, `value`, `Input`, `errorVisible`, and `errorMessage`. These components require a Form ancestor. `Form.Input` and `Form.Render` paths use the [extended query rules](#paths), including relative and wildcard paths.

Use the supplied `Input` in a custom renderer when you need input-write interaction behavior. A direct `node.setValue()` is programmatic and does not mark Edited. Extra input props are forwarded to the selected input, not automatically to its native element: the built-in string input uses `inputProps` for native attributes such as autoComplete.

`FieldInputProps` supplies `jsonSchema`, `node`, `type`, `schemaType`, `misfit`, `name`, `path`, `nullable`, `required`, `readOnly`, `disabled`, raw `errors`, `errorVisible`, `watchValues`, `defaultValue`, `value`, `onChange`, `onFileAttach`, `ChildFields`, `context`, and presentation props. Empty input publishes undefined; null is published only deliberately. Honor resolved input locks and [accessible naming](./schema-reference#accessibility).

The node prop is required in both FieldInputProps and FieldRendererProps.

`ChildFields` contains components with key/path/field metadata; use `FieldInputProps['ChildFields'][number]` when you need their type. `ChildFieldProps` allows per-child overrides including `FieldRenderer`. A FieldInput does not receive a built-in `FieldRenderer` prop; choose the renderer on Form, Form.Field, or child components instead.

## Plugins and FormProvider {#plugins}

`SchemaFormPlugin` accepts renderer components, `fieldInputDefinitions`, `validator`, and `formatError`. Later registrations replace supplied renderer/validator/formatter fields and prepend input definitions. `registerPlugin(null)` resets plugin state to the built-in defaults. Registration affects configuration captured by subsequent mounts.

`FormProvider` shares renderer defaults, input definitions, formatError, errorVisibility, validationMode, validatorFactory, and context within a subtree. Explicit Form props take precedence; Form context overlays provider context. Use the public name `FormProvider`. It has no `plugin` prop: pass renderer slots, `fieldInputDefinitions`, and `formatError` explicitly, and connect the plugin's validator with `validatorFactory={plugin.validator}`. For validator requirements see the [validator object contract](./validation#validator-contract).

## Node values, state, and array operations {#nodes}

Read node identity/tree through `type`, `strategy`, `schemaType`, `jsonSchema`, `path`, `name`, `escapedName`, `depth`, `rootNode`, `parentNode`, and `children`. Terminals have null children. `value` is the interpreted/local value; `outputValue` is emitted JSON; `source`, `extras`, and `inactiveValues` describe retained input. `isRequired`, `nullable`, `isActive`, `isVisible`, `isPresent`, `isReadOnly`, `isDisabled`, `isMisfit`, `misfits`, `watchValues`, `context`, and `diagnostics` describe the current node. `isPresent` means active and visible, independent of disabled state.

The root's parentNode is null. A missing `find()` result is null; `findNodes()` returns [] when nothing matches.

`FieldNodeState.Edited` records user input, not programmatic/automatic writes. Default input blur records Touched in the next animation frame; custom inputs can write flags explicitly. `isEdited` and `isTouched` read those flags. `node.state`/`setState` also accept user flags; Form reset and clearState remove user flags as well. `globalState` publishes true-or-absent aggregate flags. Use subtree state/error methods for bulk changes.

Array nodes provide `push(value?)` and `insert(index, value?)` returning length; `pop()` / `remove(index)` returning the removed value, `update(index, value)` returning the updated value; and `clear()` returning void. Insert accepts integer indices from zero through length; invalid indices return the unchanged length. These operations do not enforce minItems/maxItems. In a batch they compute on prior marks at the call site; whole-array settlement carries item identity by position. Use `isArrayNode` before array operations.

Public guards include isFieldNode (unknown input) and isArrayNode, isBooleanNode, isBranchNode, isNumberNode, isObjectNode, isStringNode, isTerminalNode, isUnionNode, and isVirtualNode (FieldNode, null, or undefined input). These nine kind and strategy guards return false for null and undefined.

## Divergence from the load baseline {#divergence}

`isDivergent` compares current emitted output with the final output of the last successful root load at the same path. It is false before first load and after detach. Array positions and key order matter.

Writes do not perform extra divergence comparisons. A root load keeps one baseline output reference until the next load, retaining changed output fragments for that period. A getter reads its path in O(depth) and caches the two values/result with Object.is; unchanged values, including NaN, avoid repeated deep comparison. Each node memo holds only those two path values and the result.

Observe root UpdateValue/UpdateState/RequestRefresh and the node's UpdatePath, rebinding when root/node changes. Both load paths deliver RequestRefresh even for a reset with equal output.

## Detached and inactive node lifetime {#detached-nodes}

A detached node retains its last committed reads and frozen subtree, stops delivering subscriptions, and cannot change current, retained, or future instances through setValue or array operations. Detached array push/insert return frozen length; other array methods return undefined with no mutation, apart from a development warning.

To update retained inactive JSON, write through the live root/host. Reentry creates a new node that consumes that overlay. `find` returns null while no active node exists, so look up the path again after reentry and replace stale subscriptions.

## onInactive and exit cleanup {#inactive-listeners}

`node.onInactive(resolver)` registers one synchronous resolver for this instance's normal retained gate exit and returns unsubscribe. It does not run for unmount/dispose, array deletion, or the old instance consumed at reentry; register again on the new instance.

Listeners run in registration order, using the last non-undefined result; a defined listener result beats `controls.inactiveValue`. A throwing listener cancels the entire node override, keeps the original retained source, commits the exit, and reports `ExpressionThrew`.

Inside a resolver, value writes, array verbs, batch, and resetSubtree are ignored with development `WriteInInactiveResolver`; state, external-error, request, and validation commands remain available. Return the retained value rather than calling those write methods. Replace component-cleanup value writes with `controls.inactiveValue` or onInactive using the same resolver signature. The [exit coverage rules](./schema-reference#inactive-values) still apply.

## Hidden Forms and callback lifetime {#hidden-lifecycle}

After first layout preparation, a current load delivers callbacks while hidden and does not replay them on showing. A never-prepared load buffers construction records only and drops ordinary callbacks; retired loads drop later records. During a root-replacing reset, mount records then buffered build records are delivered before handle binding switches, with each handler failure isolated.

React does not let this binding distinguish hidden from unmounted reliably: retained handles/nodes can still deliver callbacks after unmount, so clean up consumer subscriptions. While hidden, ordinary callbacks use the last connected commit and onError stays latest. Field layout-effect writes and render warnings arrive on showing.

When React shows a hidden form again, its inputs show the current node values, including writes made while it was hidden and an IME composition left unfinished when it was hidden.
While the form is hidden, React detaches its ref, so `formRef.current` is null. Write through a `FormHandle` or node reference retained after the visible form has mounted instead.

## JSONPointer queries and expressions {#paths}

| Token        | Form query meaning                                                                       |
| ------------ | ---------------------------------------------------------------------------------------- |
| `#`          | Absolute root                                                                            |
| Empty string | Current origin                                                                           |
| `/` or `#/`  | Root's empty-name child                                                                  |
| `.` / `..`   | Current / parent node                                                                    |
| `*`          | Wildcard; find gives the first match and findNodes gives all                             |
| `@`          | Context expression token, not a queryable node; find returns null / findNodes returns [] |

In controls, `@.prop` and optional chaining read the live form context. A branch expression's `./` addresses host children; an ordinary node expression uses `../` to reach siblings through its parent. Calculate depth from the expression's origin.

Segments exactly `*`, `..`, `.`, or `@` are operators first. Escape literal names as `%2A`, `%2E%2E`, `%2E`, `%40`. Other percent text remains literal; other segments decode only `~1` and `~0`. A leading `#` alone is the fragment prefix; internal `#` is an ordinary name. The literal property names `%2A`, `%2E`, `%2E%2E`, `%40` themselves cannot round-trip and are rejected with ReservedPropertyName.

Canonical node, inactive-value, and error paths use those percent literal forms. Apply the attachment-key rule in the [file submission example](./examples/media-registration#files). Validator and `$ref` RFC6901 pointers have no form operators, and standard URI fragments percent-decode every segment. `JSONPointer` exports the library's constants; it is not a general JSON value reader.

## Events and hooks {#events-hooks}

Events deliver synchronously when the outermost public write ends, merging bits per node; they do not wait for the next microtask. `FieldNodeEventType` includes Initialized, UpdatePath, UpdateValue, UpdateState, UpdateGlobalState, UpdateError, UpdateGlobalError, UpdateChildren, UpdateControlledProperties, Focused, Blurred, RequestFocus, RequestSelect, RequestRefresh, RequestRemount, UpdateJsonSchema, and UpdateDiagnostics. These represent initialization, paths/values/interaction/errors/children/controls, input actions, schema references, and root diagnostics respectively.

`node.request` accepts one of `FieldNodeRequestType.Focus`, `Select`, `Refresh`, or `Remount` per call; do not combine these as a bit mask. `subscribe` returns cleanup and `revision(mask?)` reads the delivery revision.

| Hook                                                                         | Consumer contract                                                                                                                                                                                                                                         |
| ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `useFormSubmit(ref)`                                                         | Returns submit and boolean-or-undefined pending; before binding submit resolves harmlessly. Catch rejection from event handlers.                                                                                                                          |
| `useFieldNodeTracker(node: Node \| null \| undefined, mask?)`                | Re-renders on selected delivery revisions, all by default; null or undefined creates no subscription and returns 0 on client and server. Its snapshot catches concurrent render→commit changes.                                                           |
| `useFieldNodeSubscribe(node: Node \| null \| undefined, listener, options?)` | Raw subscription, no automatic render. Null or undefined calls neither listener nor onSubscribe. Use `options.onSubscribe(node: Node)` with a required, inferred node subtype to catch up a mirrored state after attach; earlier events are not replayed. |
| `useChildFieldMap(ChildFields)`                                              | Components keyed by direct child name; missing names render nothing.                                                                                                                                                                                      |
| `useChildFieldErrors(node, disabled?)`                                       | Requires a FieldNode. Raw child errorMatrix, formattedErrors/formattedError, childErrorVisibleList/errorVisible, and gated errorMessage. Disabled empties child error reads and show flags.                                                               |

When the node input changes, both observation hooks release the previous subscription and attach to the new node if present; unmount releases the subscription.

Assigning a ref does not re-render its consumer. With `formRef.current?.node`, these hooks attach only when a later render supplies the node; trigger that render with a React state update, including when using a callback ref. Root replacement through `rebuild()`, `reset()` with a changed schema, or a validatorFactory change updates FormHandle.node without re-rendering the consumer. The hooks keep observing the old root until the consumer renders again.

Read live node getters during render with useFieldNodeTracker instead of maintaining a redundant event mirror when possible.

## Virtualization {#virtualization}

Opt in with `virtualization: true` or an options object. The complete node tree still supplies values, validation, and submission. Offscreen input DOM can defer to placeholders; once revealed it is not deferred again.

| Option         | Default                     | Meaning                                                                                                             |
| -------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| threshold      | 30                          | Minimum rendered child count before gating a branch                                                                 |
| eagerCount     | 20                          | Leading children mounted immediately per gated branch                                                               |
| rootMargin     | '100%'                      | Viewport reveal margin, using px/% units                                                                            |
| backfill       | VirtualizationBackfill.Idle | Idle reveals progressively; None waits for visibility or a focus/select command delivered to the placeholder's node |
| estimateHeight | 40                          | Number or `(node: FieldNode) => number`, in px; the node argument is required                                       |
| Placeholder    | none                        | Component receiving a required FieldNode and height                                                                 |

Placeholders use `data-path`, `data-deferred`, and aria-hidden with an estimated height. Deferred inputs are unavailable to page search, screen readers, and autofill until revealed; backfill has no fixed completion-time promise. `focus(path)` and native invalid-submit focus open the target's render path through nested gates and virtual groups in one reveal commit. A mounted focusable input keeps ordinary request behavior without opening another ancestor position; mounted duplicates receive the request and the last position takes focus. Another placeholder for the same target can still reveal through its own subscription.

A newer focus request, reset, confirmed form unmount, or disappearing gate cancels a pending reveal-focus reservation. Focus moving to another element or leaving the focused element after the request suppresses its action, including a blur to the page body, moving away and back, or autofocus inside the revealed subtree. Removing the starting element during reveal does not itself count as focus movement. StrictMode effect replay preserves the request without repeating Mount.

Terminal interiors, omitted layouts, hidden Activity and inputs suspended during the reveal commit cannot be reached. Hidden, disabled or inert elements may ignore focus. Scrolling is not corrected when nearby placeholder heights change. A request sent to an already mounted target or one with no blocking gate can be delivered later to newly mounted positions and cannot be cancelled by a newer request. Native invalid submissions keep their [candidate selection](./error-reference#submission).

SSR renders all inputs and hydration preserves them. Gating applies to branches/children added after hydration; prepared children retain their gate decision even when a tab or accordion first displays them later. Without IntersectionObserver browsers render eagerly, while servers do not warn.

Hydration itself sends no extra update into a custom branch input's Suspense. On React 18, a subsequent update before hydration completes can still switch that boundary to client rendering. See the [virtualized example](./examples/virtualized-form) and test your actual branch layout.

## TypeScript inference {#typescript}

Use `as const` to preserve schema literals; a widened type string can degrade inference to any. `InferValueType` makes all object keys optional regardless of required, because inactive controls and omitEmpty can remove them. Objects remain open unless `additionalProperties: false`. Do not treat inferred values as guaranteed validated business data.

Explicit array schemas follow the [`@winglet/json-schema` tuple inference contract](../../winglet/json-schema/index.mdx#tuple-inference), including optional positions for finite literal `prefixItems` and the `items` rest rules. These tuples are the default `Value` type for `Form` and `FormHandle`. This narrows `any[]`, so code relying on unrestricted positions or extra items can encounter compile errors.

Use the second generic on both `Form<Schema, Value>` and `FormHandle<Schema, Value>` for an exact consumer shape, especially when a concrete defaultValue would otherwise infer required keys differently from the handle. `InferFieldNode` infers a node type where static evidence allows it; dynamic references/gates can retain the full node union.
