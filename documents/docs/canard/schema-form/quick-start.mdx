# Quick Start



## Installation and plugin choice {#installation}

```bash
yarn add @canard/schema-form
# Optional validator and UI integration:
yarn add @canard/schema-form-ajv8-plugin @canard/schema-form-antd6-plugin
```

The core includes fallback renderers and inputs, so a UI plugin is optional. Without a selected validator, validation requests have no verdict and produce a warning; `if` gates require a synchronous validator guard. Select a published validator plugin or pass a complete `validatorFactory` object. See [validation](./validation#validator-contract).

Use `@canard/schema-form-antd5-plugin` for Ant Design 5, `@canard/schema-form-antd6-plugin` for Ant Design 6, `@canard/schema-form-antd-mobile-plugin` for Ant Design Mobile, or `@canard/schema-form-mui-plugin` for MUI. The package name is `schema-form-mui-plugin`. Replace `@canard/schema-form-antd-plugin` with `@canard/schema-form-antd5-plugin`.

## Declared environment requirements {#compatibility}

The core's peer ranges are `react >=18 <20` and `react-dom >=18 <20`. The core and the plugins below declare no `engines` field and no browser minimum versions. Their syntax target is not a promise that a particular Node.js or browser version supplies every runtime API or UI dependency.

| Package | Declared peers and direct UI / validator dependencies |
| --- | --- |
| AJV 6 / 7 / 8 plugins | Direct dependency `ajv ^6.0.0` / `^7.0.0` / `^8.0.0`; no core peer declaration |
| antd-mobile | React / React DOM `>=18 <20`, dayjs `>=1`; direct `antd-mobile ^5.0.0`, dayjs `^1.0.0` |
| antd5 | React / React DOM `>=18 <20`, antd `>=5.10.0`, dayjs `>=1`; direct antd `^5.10.0`, icons `^5.0.0` |
| antd6 | React / React DOM `>=18 <20`, antd `>=6.0.0`, dayjs `>=1`; direct antd `^6.0.0`, icons `^6.0.0` |
| MUI | React / React DOM `>=18 <20`, Material / icons `>=7.0.0`, X date pickers `>=8.0.0`, Emotion react / styled `>=11.0.0`, dayjs `>=1` |

The MUI plugin depends on MUI 7, MUI X 8, Emotion 11, and dayjs 1 ranges. Keep the UI library and its plugin aligned. For Ant Design CSS-variable defaults and theme configuration, follow [Ant Design's v6 migration documentation](https://ant.design/docs/react/migration-v6/); this guide does not assign that dependency's defaults.

## Transpilation and CSP {#transpilation-csp}

For targets that cannot parse the distributed ES2020 syntax, include the core and the external `@winglet` packages you actually consume in transpilation: `@winglet/common-utils`, `@winglet/json`, `@winglet/json-schema`, and `@winglet/react-utils`. Apply the same check to the UI plugin bundles. Transpilation alone does not supply missing APIs; AJV adapters use `WeakRef` and `FinalizationRegistry`.

String controls expressions compile with `new Function`. A CSP that prohibits dynamic function compilation cannot run those expressions unchanged. Check this policy before adopting expression-based controls.

## Register before rendering {#registration}

```tsx
import { Form, registerPlugin } from '@canard/schema-form';
import { plugin as validatorPlugin } from '@canard/schema-form-ajv8-plugin';
import { plugin as uiPlugin } from '@canard/schema-form-antd6-plugin';

registerPlugin(validatorPlugin);
registerPlugin(uiPlugin);

const schema = {
  type: 'object',
  properties: { text: { type: 'string' } },
} as const;

export function BasicForm() {
  return <Form jsonSchema={schema} onChange={console.log} />;
}
```

### Registration rules {#registration-rules}

Register plugins globally before mounting forms so their captured configuration is ready. There is no fixed UI-before-validator order: plugins supplying disjoint slots are independent. When slots overlap, registration order matters:

- Renderers, `validator`, and `formatError`: the last newly registered plugin supplying that slot replaces its previous value; omitted slots stay unchanged.
- `fieldInputDefinitions`: the new list is prepended, preserving order within it; the first matching definition wins. Earlier definitions remain as fallbacks.
- Registrations are deduplicated by a content hash that includes function identity. Registering identical content again does nothing, even after another plugin overrides it; a new object with the same content and function references is also a duplicate. Only a hash not registered since the last reset is applied.
- `registerPlugin(null)` restores defaults and clears the registered hashes, allowing the same plugins to be applied again.

Use [FormProvider](./api-reference#plugins) for subtree defaults.
