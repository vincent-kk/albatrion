React utility library providing custom hooks, higher-order components (HOCs),
a Portal system, and helper functions.
Supports React 16.14–19, with full TypeScript types and tree-shakeable sub-path exports.

## Installation

```bash
yarn add @winglet/react-utils
# peer deps: react >=16.14 <20, react-dom >=16.14 <20
```

## Key Exports

### Hooks (`/hook`)

| Hook | Description |
|---|---|
| `useConstant(value)` | Retains the supplied value, including a function value |
| `useHandle(fn)` | Stable callback that always calls the latest function |
| `useMemorize(input, dependencies)` | Enhanced memoization with intuitive API |
| `useSnapshot(value)` | Returns a stable snapshot of a value |
| `useDebounce(callback, dependencies, ms)` | Schedules a callback; returns `{ isIdle, cancel }` |
| `useWindowSize()` | Tracks browser window dimensions |
| `useEffectUntil(effect, condition)` | Runs effect until condition is true |
| `useOnMount(fn)` | Runs callback once on mount |
| `useOnUnmount(fn)` | Runs callback once on unmount |

### HOCs (`/hoc`)

- `withErrorBoundary(Component, fallback)` — wraps with error boundary
- `withErrorBoundaryForwardRef(Component, fallback)` — with ref forwarding
- `withUploader(Component)` — file upload handling

### Portal (`/portal`)

- `Portal` — renders children at a designated anchor in the DOM
- `Portal.Anchor` — declares where portal content mounts
- `Portal.with(Component)` — HOC providing portal context

## Usage Examples

```tsx
import { useLazyConstant, useHandle, useWindowSize } from '@winglet/react-utils/hook';

class ExpensiveManager {}

function MyComponent({ onSave }: { onSave: () => void }) {
  const manager = useLazyConstant(() => new ExpensiveManager());
  const handleSave = useHandle(onSave); // stable ref
  const { width, height } = useWindowSize();

  return <button onClick={handleSave} data-ready={!!manager}>{width}x{height}</button>;
}
```

```tsx
import { withErrorBoundary } from '@winglet/react-utils/hoc';
import { Portal } from '@winglet/react-utils/portal';

const Widget = () => <p>Widget</p>;
const Modal = () => <p>Modal</p>;

const SafeWidget = withErrorBoundary(Widget, <p>Something went wrong.</p>);

const App = Portal.with(() => (
  <>
    <Portal.Anchor />
    <Portal><Modal /></Portal>
  </>
));
```

## Claude Code Integration

`@winglet/react-utils` ships coding-agent assets — the `react-utils-skill` expert skill and its knowledge base covering hooks, HOC patterns, the portal system, and utility helpers — under `docs/agents/`. They are published alongside the package so AI assistants can reason about React-specific utilities with package-specific context.

Inject those assets with `@slats/agents-assets-sync` (bin: `inject-agents-settings`). `--agent` decides where they land — `claude`, `codex`, or the vendor-neutral `agents`:

```bash
# Into ~/.claude (user-level)
npx -p @slats/agents-assets-sync inject-agents-settings --package=@winglet/react-utils --agent=claude --scope=user

# Into the project root: nearest ancestor with .git, workspace manifest or lockfile; else the nearest agent directory
npx -p @slats/agents-assets-sync inject-agents-settings --package=@winglet/react-utils --agent=claude --scope=project

# The same assets into Codex locations (skills into .agents/, rules into AGENTS.md)
npx -p @slats/agents-assets-sync inject-agents-settings --package=@winglet/react-utils --agent=codex --scope=project

# Preview / overwrite flags
npx -p @slats/agents-assets-sync inject-agents-settings --package=@winglet/react-utils --agent=claude --scope=user --dry-run
npx -p @slats/agents-assets-sync inject-agents-settings --package=@winglet/react-utils --agent=claude --scope=user --force
```

The CLI resolves `@winglet/react-utils/package.json` via `createRequire`, reads its `agents.assetPath` (`docs/agents`), and applies hash-based diff into the selected agent's asset locations (skip unchanged, warn on divergence, require `--force` to overwrite).
