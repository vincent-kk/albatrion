# 버그 바운티 이후 속도 재측정

`1.0.0-beta`의 바운티 수정 커밋 `d78e45c6b`를 기준 커밋 `1c77ced57`과 비교하는 측정 자료입니다. 대상 행과 판정 규칙은 [SPEED-TARGETS.md](../SPEED-TARGETS.md)가 정하고, 측정 도구는 [benchmarks/compare](../../benchmarks/compare/README.md)를 그대로 씁니다. 이 디렉터리에는 이번 측정에만 해당하는 것만 둡니다.

| 경로                          | 내용                                                                                                                                                               |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ROWS-P1.md`, `ROWS-P2-*.md`  | 행별 고정 입력, 측정 구간, 입력 종류의 근거입니다.                                                                                                                 |
| `issues/`                     | Vincent의 결정이 필요해 건너뛴 항목과, 바운티 수정의 필연적 비용으로 밝혀진 초과 행의 기록입니다. 항목마다 파일 하나이며 내용, 측정 근거, 선택지, 권고를 적습니다. |
| `RESULTS-P<n>.md`, `results/` | 우선순위별 결과 표와 실행별 원자료입니다.                                                                                                                          |
| `RESULTS-FINAL.md`             | 개선을 모두 병합한 뒤 110행 전체를 다시 잰 최종 값과 판정입니다.                                                                                                   |
| `rows/`                       | 위 명세를 옮긴 행 파일입니다. 파일 이름은 `p<우선순위>-<순번>-<행 이름>.mjs`입니다.                                                                                |

## 실행

두 트리는 각 커밋을 `git archive`로 풀어 따로 설치하고 빌드한 사본이며, 루트의 `.speed-ref`에 커밋을 적어 둡니다.

```sh
node benchmarks/compare/run.mjs --a ../albatrion-speed/beta --b ../albatrion-speed/head \
  --rows bug-bounty/speed/rows --only p1- --out <새 출력 디렉터리>
```

## 이번 측정의 결정

- **antd-mobile 행**은 기준 트리의 플러그인 `antd-mobile`을 후보와 같은 5.43.0으로 맞춘 변형 트리를 `--a`로 주고 따로 실행합니다. 두 커밋의 잠금 파일에서 실제 버전이 다른 외부 라이브러리는 이것 하나이고(기준 5.40.0), 비교 대상은 라이브러리가 아니라 이 저장소의 코드이기 때문입니다.
- **`@canard/schema-form`은 Node 조건의 공개 진입점**(`dist/index.node.mjs`)으로 측정됩니다. 행이 패키지 이름으로 가져오므로 두 트리 모두 같은 조건을 따릅니다.
- **입력 종류는 초과 행만 확인합니다.** 행 파일의 `inputKind`는 명세의 예상값이고, 1.03을 넘은 행에 한해 호출 횟수를 세어 확정합니다.
- **수정 비용 판정은 도구가 내리지 않습니다.** 도구는 `pass`, `over`, `void`만 기록합니다. 초과 행이 수정 비용인지는 [수정 비용 승인 조건](../SPEED-TARGETS.md#2-측정-규칙) 세 가지를 측정으로 보인 뒤 표에 따로 적습니다. AJV 6 `default/boundFirstIdResourceInvalid` 행의 승인 상한은 min과 p10 모두 1.46입니다.
- **허용 폭은 연산 한 번의 기준 시간으로 정합니다.** 1밀리초 이상이면 1.05 미만, 1마이크로초 이상 1밀리초 미만이면 1.35 미만, 1마이크로초 미만이면 수 배 미만(작업 기준선 3배)입니다. 규모가 작을수록 수치가 흔들리므로 작은 규모에서는 비율보다 알고리즘적·논리적 비효율을 봅니다. 화면 플러그인과 `@slats/agents-assets-sync`는 1.5까지 수용합니다. `RESULTS-P1.md`와 `RESULTS-P2.md`의 판정은 이 기준 이전의 값(1.03 / 1.10 / 1.35)으로 매겨졌습니다.
- **경계에 걸린 행**(같은 트리끼리 잰 잡음 폭 안에서 1.03에 닿는 행)은 `--rounds`를 늘려 다시 잰 뒤 판정합니다.
