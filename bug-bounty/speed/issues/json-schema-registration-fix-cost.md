# `json-schema` 세 행의 남은 비용은 등록 키 정규화와 실패 색인, 필수 오류 생성입니다

- **종류** — 수정 비용입니다. 줄일 수 있는 부분은 줄였고, 남은 차이는 진단 빌드로 귀속했습니다. 수용 여부는 Vincent의 확인 대상입니다.
- **행과 경과** — 우선순위 2의 세 행이며 모두 마이크로초 규모라 기준은 1.35입니다. 24라운드, 최솟값 / 10번째 백분위입니다.

  | 행                                        | 기준 시간 | 개선 전         | 개선 후         | 대조군        |
  | ----------------------------------------- | --------- | --------------- | --------------- | ------------- |
  | `schema-known-noncanonical` (평범한 입력) | 4.2µs     | 4.704 / 4.653   | 1.972 / 1.987   | 0.986 / 0.997 |
  | `schema-first-embedded`                   | 1.1µs     | 13.922 / 13.908 | 11.794 / 11.627 | 1.001 / 0.999 |
  | `schema-key-collision`                    | 3.7µs     | 2.383 / 2.358   | 2.380 / 2.354   | 1.003 / 1.003 |

- **남은 차이의 귀속** — 진단 빌드를 6라운드로 재고 버렸습니다(대조군 유효).
  - `schema-known-noncanonical`: 알려진 주소의 등록 확인을 빼면 0.478 / 0.478입니다. 남은 비용은 비정규 등록 키 20개를 정규화하는 작업(키당 약 300나노초)입니다. 빼면 테스트 18개가 실패합니다(등록된 문서가 다른 문서에 내장된 주소와 충돌할 때의 거부, 참조 순서와 무관한 결과, 반복 조회에서의 같은 실패 등).
  - `schema-key-collision`: 같은 진단에서 0.473 / 0.488입니다. 후보 시간의 70%가 계약상 던져야 하는 `DuplicateIdentifier` 오류 객체의 생성입니다.
  - `schema-first-embedded`: 실패 시 색인을 빼면 3.797 / 3.818이고 테스트 14개가 실패합니다(계약 R1-JSC-1, R1-JSC-A1, R3-JSC-1). 키 정규화까지 빼면 0.947 / 0.947이고 26개가 실패합니다(R1-JSC-4의 철자 변형 조회 포함).
- **판단** — 수정 비용의 세 조건을 충족합니다. 정규화는 호출마다 등록 키당 한 번, 색인은 첫 실패 때 한 번, 오류 생성은 충돌마다 한 번 수행됩니다.
- **더 줄이는 방법** — 호출자의 `resources` 객체별로 정규화된 키를 리졸버 사이에 공유하는 캐시가 있습니다. 리졸버 사이에 걸친 상태를 새로 두는 구조 변경이라 시도하지 않았고, 승인 대상입니다.
- **결정** — Vincent이 수정 비용으로 수용했습니다. 리졸버 사이의 캐시는 넣지 않습니다.
