# `useRestProperties`의 남은 비용은 바운티 수정에 필요한 작업입니다

- **종류** — 수정 비용입니다. 줄일 수 있는 부분은 줄였고, 남은 차이는 측정으로 귀속을 확인했습니다. 수용 여부는 Vincent의 확인 대상입니다.
- **행** — 우선순위 1의 `rest-changed`와 `rest-equal`입니다. 재렌더 한 번에 `useRestProperties`를 2,000번 부르는 행이며, 호출 한 번의 기준 시간은 약 100나노초이고 허용 폭은 1.35입니다.
- **경과** — 후보 커밋 `d78e45c6b`에서 `rest-changed` 1.651 / 1.708, `rest-equal` 2.050 / 2.037이었습니다. 개선 커밋 하나(커밋 단계 게시를 훅에서 직접 등록) 뒤에는 `rest-changed` 1.494 / 1.585, `rest-equal` 2.048 / 1.976입니다(24라운드, 대조군 0.992 / 0.997과 1.015 / 0.992).
- **남은 차이의 귀속** — 진단 빌드 두 개를 24라운드로 재고 버렸습니다.
  - 비교 결과를 기준 커밋처럼 렌더 중에 기록하면(`useMemo`와 커밋 단계 게시 없음) `rest-equal`이 1.669 / 1.650이 됩니다(대조군 1.008 / 1.014). 이때 "버려진 전환 렌더 뒤에도 이전 객체를 유지한다"는 테스트(`snapshotCommit.round4.test.tsx:117`)가 실패합니다. 폐기된 렌더가 비교 기준을 덮어쓰기 때문입니다.
  - 심볼 키 비교까지 빼면 `rest-changed` 1.118 / 1.092(대조군 0.983 / 0.986), `rest-equal` 1.202 / 1.198(대조군 0.999 / 0.994)로 둘 다 허용 폭 안에 들어옵니다. 이때 심볼 키 테스트 여섯 개(계약 R6-RU-1)가 추가로 실패합니다.
- **판단** — 수정 비용의 세 조건을 충족합니다. 두 행의 입력은 커밋 격리 경로를 지나고 `rest-equal`은 심볼 비교까지 지납니다. 남은 작업은 그 두 수정에 필요한 작업이고 호출마다 한 번씩만 수행됩니다. 귀속은 진단 빌드 측정으로 보였습니다.
- **효과가 없어 버린 시도** — ref 초깃값의 지연 생성(1.636 / 1.661, 2.054 / 2.014)과 심볼 비교의 색인 반복(`rest-equal` 2.028 / 2.022)입니다.
- **결정** — Vincent이 수정 비용으로 수용했습니다.
