# `schema-form` 우선순위 2의 남은 초과는 수정된 동작 자체입니다

- **종류** — 수정 비용입니다. 이 묶음에서 병합한 코드 변경은 없습니다. 남은 차이는 진단 빌드와 대조 행으로 귀속했습니다. 수용 여부는 Vincent의 확인 대상입니다.
- **시도했으나 넣지 않은 것** — 가상 그룹의 분기 여부를 호스트 참조에 메모하는 변경을 쟀습니다(24라운드): `p2e-17` 2.197 → 0.383 / 0.381, `p2e-16` 1.312 → 0.720 / 0.713. 독립 검증에서 탈락해 버렸습니다. `getValue()`와 `node.value`가 엔진 내부 객체를 그대로 돌려주므로, 소비자가 그 객체를 제자리에서 고치면 참조는 같고 내용만 달라져 메모가 낡은 답을 냅니다(53개 시퀀스 중 3개, 관찰 20건 차이). 두 행은 읽기 한 번이 34나노초와 95나노초라서 메모 없이도 나노초 규모 기준(3배) 안입니다(2.20배, 1.31배). Vincent이 "돌려받은 값을 제자리에서 고치는 것은 지원하지 않는다"고 정하면 이 메모를 다시 넣을 수 있습니다. 부모 객체 노드는 기준 커밋에서도 같은 경우에 낡은 답을 냅니다.
- **남은 행과 귀속** — 진단 빌드는 6라운드로 재고 버렸습니다(`results/schema-form-p2-diagnostic-a`, `-b`, `-c`).

- **범위 안이라 손대지 않은 행** — `p2e-18` 비활성 가상 게터는 2.93배이지만 읽기 한 번이 3.3나노초라서 나노초 규모 기준(3배) 안입니다. 메모로 줄이려면 공개 선언에 닿는 레코드 칸이 하나 더 필요합니다.
- **플러그인 행** — `antd5` 외부 배열 쓰기(`p2c-03`)는 7.7배로 목표 1.5를 넘습니다. 프로파일상 `schema-form` 쓰기 비용은 같고(158 대 149), 차이는 위의 다시 마운트로 `antd`의 `Checkbox.Group`이 다시 마운트되며 도는 `@ant-design/cssinjs` 삽입 효과입니다(커밋 효과 4,466 대 19.5). `antd5` 가지 오류(`p2c-02`)는 1.79 / 1.91이며 분석하지 않았습니다.
- **판단** — 다섯 묶음 모두 기준 커밋이 하지 않던 올바른 동작을 지금은 한다는 것이 원인입니다. 낭비가 아닙니다.
- **작업자가 적은 재설계 안** — `FieldProxy`와 `FieldInputBridge`가 같은 식별자를 렌더마다 두 번 계산하므로 한 번 계산해 내려 주면 서버 렌더의 약 1%가 줄어듭니다. 구조 변경이고 이득이 작아 하지 않았습니다.
