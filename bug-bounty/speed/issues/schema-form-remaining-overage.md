# `schema-form` 세 행에 4~7%의 초과가 남습니다

- **종류** — 줄이지 못한 초과입니다. 일부는 수정 비용으로 귀속했고, 나머지는 한 곳에서 줄일 수 있는 원인을 찾지 못했습니다. Vincent의 결정이 필요합니다.
- **행과 현재 값** — 개선 가지 `perf/schema-form-speed-2`(커밋 세 개) 기준, 24라운드, 최솟값 / 10번째 백분위입니다. 세 행 모두 수십 마이크로초라서 기준은 1.03입니다.

  | 행                               | 개선 전       | 개선 후       | 기준 `react-utils`를 넣었을 때 (12라운드) |
  | -------------------------------- | ------------- | ------------- | ----------------------------------------- |
  | 서버 렌더 마운트 (`mount-plain`) | 1.085 / 1.109 | 1.049 / 1.044 | 1.005 / 1.016                             |
  | 배열 전체 자체 쓰기              | 1.084 / 1.087 | 1.048 / 1.049 | 1.034 / 1.043                             |
  | 컨텍스트 갱신                    | 1.067 / 1.071 | 1.071 / 1.069 | 1.056 / 1.050                             |

- **귀속된 부분** — 작업 트리의 `@winglet/react-utils` 빌드만 기준 커밋의 것으로 바꾼 진단에서 서버 렌더 마운트는 기준 안으로 들어옵니다. 바뀐 작업은 커밋된 값만 읽게 하는 훅 수정(계약 R3-RU-2, R5-RU-2)이며, 없으면 `committedReference.round3.test.tsx:165`("callbacks match the visible committed render") 등이 실패합니다. 따라서 서버 렌더 마운트의 남은 차이는 `react-utils` 수정 비용입니다.
- **귀속되지 않은 부분** — 배열 전체 자체 쓰기의 약 3~4%와 컨텍스트 갱신의 약 5~6%는 `schema-form` 안에 남습니다. 프로파일에서는 쓰기 경로의 여러 함수(`computeStableNode`, `updateOutput`, `markCommitDeliveries`)와 React의 메모 비교, 커밋 작업에 몇 밀리초씩 흩어져 있고, 효과 기준(기준 시간의 2%)을 넘길 단일 변경을 찾지 못했습니다. 프로파일을 따른 시도가 두 번 연속 효과가 없어 멈췄습니다.
- **선택지** — (1) 현재 값을 받아들입니다. (2) 쓰기 경로와 컨텍스트 정착 경로의 구조를 바꾸는 작업을 따로 엽니다. 구조 변경이라 승인이 필요합니다.
- **권고** — (1)입니다. 남은 차이가 여러 수정에 흩어진 작은 비용의 합이라 구조 변경의 위험에 비해 얻는 것이 작습니다.
- **결정** — Vincent이 현재 값을 수용했습니다. 배열 전체 자체 쓰기와 컨텍스트 갱신 두 행만 수정 비용과 비효율을 한 번 더 분리해 보고, 그 결과를 이 문서에 덧붙입니다.
- **두 행의 추가 분리** — 연산 한 번 동안의 훅 호출, 요소 생성, DOM 쓰기를 기준 트리와 개선 트리에서 세어 비교했습니다(200회 평균).
  - 두 행 모두 요소 생성 횟수(9와 46)와 DOM 쓰기가 양쪽에서 같습니다. 렌더나 커밋이 한 차례 더 도는 종류의 비효율은 없습니다.
  - 늘어난 호출은 `useInsertionEffect`뿐이고(배열 전체 자체 쓰기 +4, 컨텍스트 갱신 +14), 전부 `@winglet/react-utils`의 `useCommittedReference`에서 나옵니다. 커밋된 값만 읽게 하는 수정이며, `react-utils`를 기준 빌드로 바꾼 진단에서 0.6~1.9%로 측정된 몫입니다.
  - 배열 전체 자체 쓰기는 React를 뺀 엔진 행(`p2e-12`, 같은 쓰기)이 1.042 / 1.046이고, 그 추가 시간 약 1.4마이크로초가 이 행 기준 시간의 약 2.6%입니다. 따라서 이 행의 5% 중 약 4%가 `react-utils` 몫과 엔진 쓰기 경로로 설명됩니다. 엔진 쓰기 경로의 1.4마이크로초가 어느 수정의 작업인지는 `p2e-12`의 귀속에서 가립니다.
  - 컨텍스트 갱신은 5~6% 중 `react-utils` 몫 1.5~1.9%를 뺀 3.5~4%가 호출 횟수가 같은 `schema-form` 함수들 안의 작업으로 남습니다. 추가 패스가 아니라는 것까지 확인했고, 수정별 귀속은 하지 않았습니다.
