# `json-schema` 첫 조회 실패의 남은 비용은 바운티 수정에 필요한 작업입니다

- **종류** — 수정 비용입니다. 줄일 수 있는 부분은 줄였고, 남은 차이는 측정으로 귀속을 확인했습니다. 수용 여부는 Vincent의 확인 대상입니다.
- **행** — 우선순위 1의 `schema-first-miss`입니다. 등록 문서 20개가 있는 리졸버에서 어느 등록에도 없는 주소를 처음 조회하는 호출 한 번이며, 기준 커밋 `1c77ced57`에서는 약 1.07마이크로초입니다.
- **경과** — 후보 커밋 `d78e45c6b`는 기준의 146.9배였습니다. 개선 가지 `perf/json-schema-speed`의 커밋 다섯 개(불필요한 URL 파싱 제거) 뒤에는 9.76배입니다(24라운드, 최솟값 9.761 / 10번째 백분위 9.756, 대조군 0.988 / 0.984).
- **남은 차이의 귀속** — 진단 빌드 두 개를 재고 버렸습니다(각 6라운드).
  - 조회 실패 때 등록 문서 20개를 색인하는 작업만 건너뛰면 4.70배가 됩니다(대조군 1.000 / 1.008). 이때 테스트 14개가 실패합니다. 등록 문서에 내장된 식별자 해석, 중복 식별자 거부, 실패 후 재시도 등으로, 계약 R1-JSC-1, R1-JSC-A1, R3-JSC-1에 해당합니다.
  - 등록 키 정규화까지 건너뛰면 0.95배가 됩니다(대조군 1.016 / 1.013). 이때 테스트 24개가 실패합니다. 추가로 실패하는 것은 표기가 다른 같은 주소의 등록 처리로, 계약 R1-JSC-4에 해당합니다.
- **한 번만 수행되는지** — 같은 리졸버에서 두 번째 조회 실패를 재는 임시 행의 비율은 1.21 / 1.21입니다. 색인과 정규화는 리졸버마다 첫 실패에서 한 번만 일어납니다.
- **판단** — 수정 비용의 세 조건을 충족합니다. 입력이 수정 경로(첫 실패 시 등록 문서 확인)에 닿고, 남은 작업은 그 수정에 필요한 작업이며 한 번만 수행되고, 그 귀속을 진단 빌드 측정으로 보였습니다.
- **같은 리졸버를 쓰는 우선순위 2 행** — 개선 뒤 `schema-known-noncanonical` 4.74배(개선 전 32.8배), `schema-first-embedded` 14.3배, `schema-key-collision` 2.39배입니다. 이 행들은 수정 경로 입력이며 같은 색인과 정규화 비용을 냅니다.
- **근거 자료** — 작업자의 측정 기록은 개선 PR 본문에 옮겨 적습니다. 진단 빌드는 커밋하지 않았습니다.
- **결정** — Vincent이 수정 비용으로 수용했습니다.
