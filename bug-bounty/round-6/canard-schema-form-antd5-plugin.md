## 1. Switching an editable slider to read-only displays a rounded value instead of its stored decimal.

- Severity: low. A review-mode transition displays `2` for the valid stored value `2.4`; the stored value remains intact.
- Affected public API: `FieldInputSliderDefinition`, public `Form.readOnly`, and a number schema with `minimum: 0`, `maximum: 10`, no `multipleOf`, and stored value `2.4`.
- Contract violated: `packages/canard/schema-form-antd5-plugin/src/DETAIL.md:17` preserves valid ungridded read-only values. The same final read-only state must display the same value after a transition and a direct mount; `../round-5/FIXES.md:199`, `:408`, and `:508` record the decimal-preservation decision.
- Root cause: `packages/canard/schema-form-antd5-plugin/src/fieldInputs/utils/slider/useSliderControl.ts:24-27` chooses the editable snapped draft or read-only stored value only during state initialization. Changing `readOnly` locks the widget without recomputing its draft from the stored decimal.
- Relation to earlier rounds: same class as the read-only decimal follow-up in `../round-5/FIXES.md:199`, with a lifecycle transition rather than a direct mount. Each plugin owns its copied implementation and records its own item.
- Reopens an earlier fix: the [round 5 slider follow-up](../round-5/FIXES.md) at line 199, `2182e4c4d` and `16f3ba679`.
- Regression of an earlier fix: yes, case (b) of `16f3ba679`, confirmed by executing its unchanged archived plugin source and its parent in `r6-regression-check/lifecycle.test.tsx`. The parent transition displays `2.4`, while the commit transition displays `2`; direct read-only mounts display `2.4` and stored values remain `{ level: 2.4 }` at both revisions.
- Watch list: yes; sliders, labels, and control identifiers across the core and four interface plugins.
- Reproduction: `r6-ui-sliders/lifecycle.test.tsx`, “read-only transition shows the same valid decimal as a read-only mount”, gives `aria-valuenow="2"` after `readOnly=false` becomes `true`, versus `"2.4"` on a direct read-only mount; both must be `"2.4"`. `getValue()` remains `{ level: 2.4 }`. Run `yarn workspace @canard/schema-form-antd5-plugin test --run src/__bounty__/r6-ui-sliders/lifecycle.test.tsx`. Editable or disabled normalization remains the permitted behavior of `../round-5/FIXES.md:537`; only the final read-only display is reported.
- Confidence: high for the current lifecycle difference; public interface with the installed component library, with historical attribution confirmed by archived-source execution.

## 2. Slider tooltips display integer coordinates instead of schema values for exponent steps.

- Severity: low. Small-step sliders give incorrect visible numeric feedback while storing the correct value.
- Affected public API: `FieldInputSliderDefinition` with `multipleOf: 1e-7`, `minimum: 0`, and `maximum: 1e-6`.
- Contract violated: `packages/canard/schema-form-antd5-plugin/src/fieldInputs/utils/slider/getSliderBounds.ts:6-14` defines the schema-to-library mapping; feedback must express the schema value. `../round-5/FIXES.md:408` and `:508` preserve decimal values, and `packages/canard/schema-form-mui-plugin/src/fieldInputs/FieldInputSlider.tsx:139` maps its displayed value back correctly.
- Root cause: `packages/canard/schema-form-antd5-plugin/src/fieldInputs/utils/slider/getSliderBounds.ts:101-106` converts tiny steps to integer coordinates, while `packages/canard/schema-form-antd5-plugin/src/fieldInputs/FieldInputSlider.tsx:104-108` supplies the transformed value and bounds without a tooltip formatter that converts them back. The repaired thumb accessibility value uses schema units, so the tooltip disagrees with it.
- Relation to earlier rounds: same class as [round 5 item 4](../round-5/canard-schema-form-antd5-plugin.md), on the display surface of the exact-grid conversion rather than stored-value selection. The sibling implementation owns its own corresponding item.
- Reopens an earlier fix: [round 5 item 4](../round-5/canard-schema-form-antd5-plugin.md), `cafc784f1`, recorded at `../round-5/FIXES.md:138-140` and `:148-149`.
- Regression of an earlier fix: yes, case (b) of `cafc784f1`, confirmed by executing its unchanged archived plugin source and its parent in `r6-regression-check/tooltip.test.tsx`. For the same stored endpoint `0.000001`, the parent tooltip displays `0.000001` and the commit tooltip displays `10`; both thumb accessibility values remain `0.000001`. The midpoint is supplementary current-defect evidence, not a historical comparison.
- Watch list: yes; sliders, labels, and control identifiers across the core and four interface plugins.
- Reproduction: `r6-ui-sliders/tooltip.test.tsx`, “the tooltip displays schema value 5e-7 rather than its integer coordinate” and the `0.000001` row, display `5` and `10`, expected `5e-7` and `0.000001`. The thumb's `aria-valuenow` remains correct. “control: the pre-conversion library props show the endpoint in schema units” passes. Run `yarn workspace @canard/schema-form-antd5-plugin test --run src/__bounty__/r6-ui-sliders/tooltip.test.tsx`; the probe supplies a no-operation ResizeObserver because jsdom does not implement layout observation.
- Confidence: high for the current defect; public interface and real Ant Design tooltip elements, with historical attribution confirmed by archived-source execution.
