## 1. Five controls display a custom label but announce the schema key instead.

- Severity: medium. Speech-input and assistive-technology users cannot identify ordinary controls by their visible label.
- Affected public API: `plugin`, `presentation.FieldInputProps.label`, and the enum select, slider, boolean switch, string switch, and text input definitions.
- Contract violated: Web Content Accessibility Guidelines 2.1 and 2.2 Success Criterion 2.5.3, Label in Name, requires the accessible name to contain the visible label. The label prop is accepted at `packages/canard/schema-form-mui-plugin/src/fieldInputs/FieldInputStringEnum.tsx:26` and `packages/canard/schema-form-mui-plugin/src/fieldInputs/FieldInputSlider.tsx:35`.
- Root cause: `packages/canard/schema-form-mui-plugin/src/components/FieldRenderer.tsx:90-92` emits a hidden title containing only `name`. The references at `packages/canard/schema-form-mui-plugin/src/fieldInputs/FieldInputStringEnum.tsx:111-118`, `packages/canard/schema-form-mui-plugin/src/fieldInputs/FieldInputSlider.tsx:150` and `:160`, `packages/canard/schema-form-mui-plugin/src/fieldInputs/FieldInputBooleanSwitch.tsx:86`, `packages/canard/schema-form-mui-plugin/src/fieldInputs/FieldInputStringSwitch.tsx:105`, and `packages/canard/schema-form-mui-plugin/src/fieldInputs/FieldInputString.tsx:101` override the controls' visible native labels through `aria-labelledby`.
- Relation to earlier rounds: same class as [round 5 item 2](../round-5/canard-schema-form-mui-plugin.md), with the visible-label mismatch on the repaired title association.
- Reopens an earlier fix: [round 5 items 2 and 4](../round-5/canard-schema-form-mui-plugin.md), `0ce02213a`.
- Regression of an earlier fix: yes, case (b) of `0ce02213a` (`../round-5/FIXES.md:157-159`), confirmed by executing its unchanged archived plugin source and its parent in `r6-regression-check/visibleLabel.test.tsx`. All five parent names contain `Volume setting` (the string switch also contains `off on`), while all five commit names are `internalKey`.
- Watch list: yes; sliders, labels, and control identifiers across the core and four interface plugins.
- Reproduction: `r6-ui-sliders/visibleLabel.test.tsx`, the enum, slider, boolean switch, string switch, and text rows of “accessible name contains the visible custom label”, each displays `Volume setting` but computes `internalKey`; the expected name contains `Volume setting`. No external `Form.Label` is present, so the recorded duplicated-title limit does not explain the failure. Run `yarn workspace @canard/schema-form-mui-plugin test --run src/__bounty__/r6-ui-sliders/visibleLabel.test.tsx`.
- Confidence: high for the current defect; public interface with the real Material UI document tree and accessible-name calculation, with historical attribution confirmed by archived-source execution.

## 2. Switching an editable slider to read-only displays a rounded value instead of its stored decimal.

- Severity: low. A review-mode transition displays `2` for the valid stored value `2.4`; the stored value remains intact.
- Affected public API: `FieldInputSliderDefinition`, public `Form.readOnly`, and a number schema with `minimum: 0`, `maximum: 10`, no `multipleOf`, and stored value `2.4`.
- Contract violated: `packages/canard/schema-form-mui-plugin/src/DETAIL.md:43` preserves valid ungridded read-only values. The same final read-only state must display the same value after a transition and a direct mount; `../round-5/FIXES.md:199`, `:408`, and `:508` record the decimal-preservation decision.
- Root cause: `packages/canard/schema-form-mui-plugin/src/fieldInputs/utils/slider/useSliderControl.ts:24-27` chooses the editable snapped draft or read-only stored value only during state initialization. Changing `readOnly` locks the widget without recomputing its draft from the stored decimal.
- Relation to earlier rounds: same class as the read-only decimal follow-up in `../round-5/FIXES.md:199`, with a lifecycle transition rather than a direct mount. Each plugin owns its copied implementation and records its own item.
- Reopens an earlier fix: the [round 5 slider follow-up](../round-5/FIXES.md) at line 199, `2182e4c4d` and `16f3ba679`.
- Regression of an earlier fix: yes, case (b) of `16f3ba679`, confirmed by executing its unchanged archived plugin source and its parent in `r6-regression-check/lifecycle.test.tsx`. The parent transition displays `2.4`, while the commit transition displays `2`; direct read-only mounts display `2.4` and stored values remain `{ level: 2.4 }` at both revisions.
- Watch list: yes; sliders, labels, and control identifiers across the core and four interface plugins.
- Reproduction: `r6-ui-sliders/lifecycle.test.tsx`, “read-only transition shows the same valid decimal as a read-only mount”, gives `aria-valuenow="2"` after `readOnly=false` becomes `true`, versus `"2.4"` on a direct read-only mount; both must be `"2.4"`. `getValue()` remains `{ level: 2.4 }`. Run `yarn workspace @canard/schema-form-mui-plugin test --run src/__bounty__/r6-ui-sliders/lifecycle.test.tsx`. Editable or disabled normalization remains the permitted behavior of `../round-5/FIXES.md:537`; only the final read-only display is reported.
- Confidence: high for the current lifecycle difference; public interface with the installed component library, with historical attribution confirmed by archived-source execution.

## Hypotheses checked and not bugs

- Combined inclusive and exclusive decimal bounds, negative bounds, exponent steps with two exclusive endpoints, and narrow inclusive ranges select valid Home and End values in immediate and lazy mode.
- A navigation key released while read-only does not publish its pending value. Direct read-only decimal mounts preserve the valid decimal; the reported failure requires a transition.
- Current identifier and external-write ports, focused slider constraints, custom layout names, and accessible-definition checks pass. The retained earlier failures above do not establish a new defect.
