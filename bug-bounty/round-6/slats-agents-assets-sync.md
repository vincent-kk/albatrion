## 1. A forced update replaces a skipped skill's contents through another destination hard-linked to the same inode.

- Severity: medium. An uncommon but plausible dotfiles/template-sharing arrangement makes the skipped skill receive another skill's contents while all output modes report success. The probe is deterministic and requires no concurrent writer.
- Affected public API: `runCli` with `--package`, `--agent=claude`, `--scope=project` and `--force --yes`, including plain and JSON output; the internal terminal execution path has the same result.
- Contract violated: `packages/slats/agents-assets-sync/src/core/injectDocs/DETAIL.md:11` requires incompatible source hashes resolving to one physical destination to fail merging without writes; `:13` requires existing hard-link identity to survive in-place writes. `packages/slats/agents-assets-sync/src/DETAIL.md:18` defines equal destination bytes as a skip, and `:112` defines forced-update settlement. Planning must therefore detect shared inodes before incompatible writes; breaking the links would violate the identity contract.
- Root cause: `packages/slats/agents-assets-sync/src/core/injectDocs/utils/session/prepareUnits/utils/resolveCanonicalPath.ts:15` uses `realpath` as ownership identity. Distinct hard-link names remain distinct, so `packages/slats/agents-assets-sync/src/core/injectDocs/utils/session/mergePlans.ts:20` misses the collision. `packages/slats/agents-assets-sync/src/core/injectDocs/utils/replaceDocument.ts:55` deliberately writes in place for `nlink > 1`, changing both names, including the skipped destination.
- Relation to earlier rounds: [round 4 asset-sync item 5](../round-4/slats-agents-assets-sync.md) concerns run-wide conflicting destinations; [round 5 asset-sync item 4](../round-5/slats-agents-assets-sync.md) concerns hard-link identity. This input adds the missing hard-link dimension to collision planning.
- Reopens an earlier fix: [round 5 asset-sync items 1, 2, 3 and 7](../round-5/slats-agents-assets-sync.md), commit `7e56b4e1a`, which introduces `resolveCanonicalPath`; the conflict map also includes [round 4 asset-sync item 5](../round-4/slats-agents-assets-sync.md), commit `e429b0dfa`.
- Regression of an earlier fix: no. No retained probe or specification row establishes this conflicting-hard-link input as fixed. Source inspection before `e308b7712` shows that `applyAction` uses `copyFile` on the existing destination and also writes the shared inode while conflicts still use path strings; no archived runtime comparison is claimed.
- Watch list: yes, the planning stage, where ownership identity must match the writer's storage identity.
- Reproduction: `r6-agents-assets-sync/hardLinkPlans.test.ts`, "plain: a force run refuses incompatible sources that address one hard-linked inode", and the corresponding `json:` and `ink:` rows. Sources contain `# a\n` and `# b\n`; both destinations initially hard-link the inode containing `# a\n`. The plan skips `a` and updates `b`. Actual in every mode is `{ code: 0, a: '# b\n', b: '# b\n', linked: true }`, expected `{ code: 1, a: '# a\n', b: '# a\n', linked: true }` with refusal before writes. JSON lists `a` as skipped and `b` as updated without failures. The independent-file control passes.
- Confidence: high; public source API in plain/JSON modes and an internal terminal fixture for Ink. The wrong bytes and false success are reproduced directly.
