# Validator Parity Scenarios contract

## Requirements

폼이 검증기 플러그인에 거는 기대와 적용 조건을 공유합니다. 지원 범위의 적합성을 같은 기대로 비교하되 판정이 미정인 관찰은 동등성 약속으로 바꾸지 않습니다. 데이터·실행의 공통 경계는 [패키지 계약](../../DETAIL.md)을 따릅니다.

## API Contracts

검증기 전용 하위 경로는 일반 폼 장면과 분리합니다. 행 목록 대조는 모든 플러그인이 같은 규칙을 쓰는 순수 함수이므로 이 부류가 소유합니다. 사본 만들기·결과 읽기·수명 단계 실행은 AJV 인스턴스 형에 묶이므로 각 플러그인이 소유합니다.

- 수명 단계는 자체 형의 닫힌 어휘를 따릅니다. 어휘 확장은 플러그인마다 다른 수명 실행을 함께 검토하여 한 플러그인의 성공을 공통 지원으로 오인하지 않게 합니다.
- 적용 여부는 진입점·방언·필요 기능을 모두 만족해야 합니다. 프로필의 custom은 첫 사용 전에 한 번 bind한 소비자 인스턴스이며, 이미 등록된 루트를 재바인딩하는 계약이 아닙니다.

불리언 가드 기대값은 플러그인과 인스턴스를 공유하지 않는 별도 AJV 전체 검증의 `if` 판정과 대조합니다. 같은 가드를 다시 부른 결과를 기대값으로 쓰면 양쪽에 같은 결함이 있어도 통과하므로 독립 판정을 유지합니다.

엔진 쪽 동작인 비객체 호스트의 `{}` 평가(SETTLE-021)는 플러그인 계약이 아니므로 이 목록으로 보장하지 않습니다. 서로 다른 층의 성공 조건을 섞으면 플러그인에 없는 정규화를 기대하게 됩니다.

## Acceptance Criteria

### validator-scenario-data — 순수 공유 기술

- 시나리오 모듈은 자체 형만 가져오고 schema-form, AJV, 테스트 러너를 가져오지 않는다.
- 각 시나리오의 `id`는 목록 안에서 유일하고, 플러그인 시험의 행 제목과 관찰 표의 열쇠로 쓰인다.

### validator-scenario-bundles — 적합성과 관찰의 분리

- 불리언 기대값은 지원 조건 안에서만 독립 AJV 전체 검증과 대조합니다. 미지원이라는 이유로 임의의 참·거짓 기대를 만들어 플러그인 간 일치를 강제하지 않습니다.
- 컴파일 단계의 거부가 보장되는 형태는 지원 밖이어도 적합성입니다. 사슬 밖 앵커·자원 루트가 아닌 재귀 앵커·묶이지 않은 동적 이름의 거부를 관찰로 낮추지 않습니다(VALIDATE-047). 소비자는 `compileGuard` 호출만 감싸 거부를 확인하며 가드 호출의 실패로 대신하지 않습니다.
- 판정이 미정인 관찰에는 기대값을 두지 않습니다. L16은 플러그인 문서의 한계를 확인하는 관찰이며 원본 회귀 시험이나 공통 판정의 보장으로 취급하지 않습니다.

리터럴 행 목록은 실행 없이 사례 수를 세기 위한 소비자 계약입니다. 카탈로그의 적용 조건을 펼친 목록과 순서까지 대조하여 누락된 조합이나 중복 실행을 방치하지 않습니다.

### validator-scenario-size — 파일 상한

- 각 플러그인의 parity 시험 파일은 관찰 행을 포함해 펼친 행(시나리오 × 진입점 × 프로필 × 경로)이 32건 이하이다. 가드 묶음은 draft-07 진입점 파일과 동적 어휘 진입점 파일로 나뉜다.
