# Composite Scenarios

## Purpose

기능 카탈로그의 복합 사례 CX-01부터 CX-24까지의 공유 장면과 소비자 꼬리 단계를 소유합니다.
여러 기능이 한 폼에서 겹치는 동작, 분기 전환과 배열 동사·주입·검증·재설정이 같은 정착 안에서 엇갈리는 타이밍을 다룹니다.

## Conventions

- 장면 모듈은 데이터 전용으로 두며, 실행은 어댑터와 소비자가 소유합니다(TEST-010).
- 사례 이름은 `composite.cxNN-` 접두사로 번호 순서를 따르고, 모든 최상위 단계에 기대값을 둡니다.
- 장면 형식에 없는 소비자 동작(Merge 쓰기, 검증 보류, 속성 단계, 제출, 상태 확인)은 꼬리 단계(`CompositeTailStep`)로 적고, 소비자가 런타임에 대응시킵니다.
- 꼬리가 공유 단계의 끝 상태에서 이어지지 않으면 `tailStart`를 두고, 소비자는 그 값으로 다시 적재합니다.

## Boundaries

이 부류는 복합 장면의 입력, 관찰 가능한 기대값, 꼬리 단계의 뜻을 소유합니다.
소비자는 엔진 실행·렌더링·검증기·브라우저 입력(IME, 파일, 네이티브 숫자 입력)과 단언 런타임을 소유합니다.

## Always do

- 기대값은 원장 항목으로 근거를 대고, 장면 설명에 그 항목을 적습니다.
- 단일 기능이 아니라 둘 이상의 기능이 겹치는 순서와 타이밍을 단언합니다.
- 결함이나 미결 질문은 `composite.finding-` 장면으로 따로 두고, 원장 계약을 기대값으로 적습니다.

## Ask first

- 사례를 더하거나 번호를 바꾸기 전에 확인합니다.
- 꼬리 단계(`CompositeTailStep`)에 새 동작을 더하기 전에 확인합니다.

## Never do

- 엔진의 형과 열거형을 포함해 폼 엔진이나 테스트 러너를 장면 데이터에 가져오지 않습니다.
- 지금 엔진의 결함 동작을 기대값으로 고정하지 않습니다.
