# Validation State Feature Scenarios

## Purpose

기능 카탈로그의 검증·상태·오류(G5) 그룹이 새로 쓰는 공유 장면과 사례 상수를 소유합니다.
검증 모드, 외부 오류, 오류 표시 정책, 오류 문구, 상호작용 상태, 제출, 오류 귀속을 다룹니다.

검증 상태 장면은 판정·오류 보유·화면 표시를 구별합니다.
숨은 메시지를 오류가 없는 상태로 오인하지 않게 합니다.

잘못된 외부 오류 값도 소비자가 그대로 전달합니다.
형 변환이 JavaScript 호출자의 입력 경계를 대신 검증하지 않게 합니다.

## Conventions

- 장면 모듈은 데이터 전용으로 두며, 실행은 어댑터가 소유합니다(TEST-010).
- 장면 이름은 `validation-state.` 접두사로 식별하고 모든 최상위 단계에 기대값을 둡니다.
- 장면 형식에 없는 Form 속성과 소비자 전용 상호작용은 사례 상수로 두고, 엔진 열거형 대신 이름으로 적어 소비자가 바꿉니다.

## Boundaries

이 부류는 새 장면의 입력과 관찰 가능한 기대값을 소유합니다.
소비자는 엔진 실행·렌더링·검증기 등록·단언 런타임을 소유합니다.

## Always do

- 사례 상수의 기대값은 현재 소유 계약의 안정 ID로 식별하고 장면 설명에 남깁니다.
- 오류 기대값은 keyword 목록으로 적고, 개수와 순서를 함께 고정합니다.

## Ask first

- 부류의 책임을 검증·상태·오류 밖으로 넓히기 전에 확인합니다.
- 장면 형식(`FormScenario`)에 새 단계나 기대 키를 더하기 전에 확인합니다.

## Never do

- 엔진의 형과 열거형을 포함해 폼 엔진이나 테스트 러너를 장면 데이터에 가져오지 않습니다.
- 지금 엔진의 결함 동작을 기대값으로 고정하지 않습니다(결함이나 미결 질문이면 발견 장면으로 따로 둡니다).
