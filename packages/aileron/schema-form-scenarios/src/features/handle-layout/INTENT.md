# Handle Layout Feature Scenarios

## Purpose

기능 카탈로그의 핸들·레이아웃·합성 API(G7) 그룹이 새로 쓰는 공유 장면과 사례 상수를 소유합니다.
핸들의 값·오류 왕복과 명령, 경로별 레이아웃, Provider 계층, prop 교체와 reset 로드를 다룹니다.

핸들 장면은 prop 교체와 reset의 계기를 구별합니다.
prop 변경 자체가 로드인 것처럼 시험을 단순화하지 않습니다.

포커스와 선택은 실행 환경의 관찰 범위를 명시합니다.
jsdom 선택 범위의 성공을 실제 브라우저 포커스 검증으로 확대하지 않습니다.

## Conventions

- 장면 모듈은 데이터 전용으로 두며, 실행은 어댑터가 소유합니다(TEST-010).
- 장면 이름은 `handle-layout.` 접두사로 식별하고 모든 최상위 단계에 기대값을 둡니다.
- 장면 형식에 없는 Form 속성과 소비자 전용 상호작용은 사례 상수로 두고, 엔진 열거형 대신 이름으로 적어 소비자가 바꿉니다.

## Boundaries

이 부류는 새 장면의 입력과 관찰 가능한 기대값을 소유합니다.
소비자는 엔진 실행·렌더링·검증기 등록·단언 런타임을 소유합니다.

## Always do

- 사례 상수의 기대값은 현재 소유 계약의 안정 ID로 식별하고 장면 설명에 남깁니다.
- settle·fill 부류에 같은 동작의 장면이 있으면 소비자가 거기서 가져오고 여기로 복사하지 않습니다.
- 레이아웃·Provider·prop 교체는 경로와 기대값만 적고, 소비자가 컴포넌트와 렌더 순서를 만듭니다.

## Ask first

- 부류의 책임을 핸들·레이아웃·합성 API 밖으로 넓히기 전에 확인합니다.
- 장면 형식(`FormScenario`)에 새 단계나 기대 키를 더하기 전에 확인합니다.

## Never do

- 엔진의 형과 열거형을 포함해 폼 엔진이나 테스트 러너를 장면 데이터에 가져오지 않습니다.
- 지금 엔진의 결함 동작을 기대값으로 고정하지 않습니다(결함이나 미결 질문이면 발견 장면으로 따로 둡니다).
