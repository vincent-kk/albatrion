# Plugins Feature Scenarios

## Purpose

기능 카탈로그의 플러그인과 격리(G8) 그룹이 새로 쓰는 공유 장면과 사례 상수를 소유합니다.
검증기의 출처와 우선순위, 렌더러 교체, 주입 입력의 오류 경계 격리를 다룹니다.

검증기 없음 사례는 전역 등록 전의 환경을 전제로 합니다.
이미 등록된 플러그인을 둔 스토리로 미등록 동작을 검증하지 않습니다.

격리 사례의 던지는 입력과 렌더러는 소비자가 만듭니다.
데이터 모듈의 평가 자체가 오류나 전역 등록을 일으키지 않게 합니다.

## Conventions

- 장면 모듈은 데이터 전용으로 두며, 실행은 어댑터가 소유합니다(TEST-010).
- 장면 이름은 `plugins.` 접두사로 식별하고 모든 최상위 단계에 기대값을 둡니다.
- 장면 형식에 없는 Form 속성과 소비자 전용 상호작용은 사례 상수로 두고, 엔진 열거형 대신 이름으로 적어 소비자가 바꿉니다.

## Boundaries

이 부류는 새 장면의 입력과 관찰 가능한 기대값을 소유합니다.
소비자는 엔진 실행·렌더링·검증기 등록·단언 런타임을 소유합니다.

## Always do

- 사례 상수의 기대값은 현재 소유 계약의 안정 ID로 식별하고 장면 설명에 남깁니다.
- 검증기·렌더러·던지는 입력은 소비자가 만들고, 장면은 그 출처와 기대값만 적습니다.
- 렌더러 표식은 `<출처>-<자리>` 문자열로 적고, 소비자 렌더러가 같은 표식을 그립니다.

## Ask first

- 부류의 책임을 플러그인과 격리 밖으로 넓히기 전에 확인합니다.
- 장면 형식(`FormScenario`)에 새 단계나 기대 키를 더하기 전에 확인합니다.

## Never do

- 엔진의 형과 열거형을 포함해 폼 엔진이나 테스트 러너를 장면 데이터에 가져오지 않습니다.
- 지금 엔진의 결함 동작을 기대값으로 고정하지 않습니다(결함이나 미결 질문이면 발견 장면으로 따로 둡니다).
