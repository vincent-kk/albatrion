# app

## Requirements

같은 트리(문서 또는 하나의 shadow root) 안에서 이름·form 소유자가 같은 라디오는 선택된 하나만 Tab 정차점으로 취급합니다. 브라우저의 라디오 그룹은 트리마다 따로이므로, 트리를 넘어 묶으면 shadow 안의 라디오에 닿지 못합니다. 선택 전 그룹은 이동 방향에 맞는 첫 또는 마지막 후보를 경계로 사용하며 이름 없는 라디오는 독립적입니다. DOM 후보를 기준으로 그룹을 비교하므로 일반 컨트롤의 기존 순서를 유지하고 그룹 비교 비용은 후보 수의 제곱 이내입니다.

살아 있는 노드와 구독, 고유 id 및 쌓임 순서는 static 인터페이스가 연결한 전역 저장소가 소유합니다. id 배열은 등록과 제거 때만 새 참조가 됩니다.

## API Contracts

Provider 밖에서도 쓰는 저장소 구독 훅과 기본 경로 훅은 이 경계가 소유합니다. Context 소비 훅을 되가져오지 않으며 노드 연산은 core/node만 참조하여 handle → app의 역방향 순환을 막습니다. 기본 경로 함수 객체는 단일 선언을 공유하고 현재 pathname 읽기·생존 노드가 있을 때의 폴링 시점은 유지합니다.

- 동일한 구조 버전의 모듈 사본은 globalThis의 Symbol.for('@lerx/promise-modal') 객체 하나를 사용합니다. 앵커·큐·핸들러·계수·소유권·세대·대기자·스타일 범위·키보드·격리·스크롤·포커스 자원을 함께 보관하므로 다른 사본의 요청도 현재 소유자가 처리합니다.
- 구조 버전이 다르면 기존 객체를 덮어쓰거나 공유하지 않고 사본 내부 상태를 사용합니다. 개발 모드에서는 호환되지 않는 버전을 경고하고 운영에서는 경고하지 않습니다.
- ModalManager는 소유자당 document keydown 처리기 하나로 Esc와 Tab을 처리하고, Escape 직전 상태를 기록하는 capture 단계 리스너를 함께 등록·해제합니다. 처리기는 React 루트 리스너 뒤에 실행되므로 모달 안의 컨트롤이 기본 동작 방지 없이 이미 모달을 확정했을 수 있습니다. 그래서 탐색은 capture 단계에서 기록한 목록을 쓰고, 그 목록의 노드가 같은 이벤트 중 확정됐으면 그 확정을 이번 입력의 닫기로 보고 더 닫지 않습니다. 기록이 없으면 현재 목록을 씁니다. Esc는 기본 방지·IME 이벤트와 분리된 앵커를 무시합니다. 살아 있고 보이는 미확정 노드를 쌓임 순서 위에서 아래로 살피며 유효 closeOnEscape가 true인 첫 노드만 취소 값으로 닫고 기본 동작을 방지합니다. Escape를 받지 않는 nondimmed 노드는 페이지의 키보드 정책을 소유하지 않으므로 건너뜁니다. Escape를 받지 않는 dimmed 노드에서는 탐색을 멈추고 기본 동작을 방지하지 않아 아래 모달을 보호합니다.
- 포커스 대상은 등록 시 보관하고 확정 시 환경 복원 뒤 되돌립니다. 다른 열린 모달의 포커스는 유지하며 대상이 inert이거나 연결이 끊겼으면 남은 최상위 dimmed 모달로 이동합니다. 남은 dimmed 모달이 없으면 연결이 끊긴 대상은 무시합니다. 등록 시 포커스 대상이 없었으면 포커스를 옮기지 않습니다. 페이지가 아직 inert인데 포커스가 닫힌 모달이나 body에 남으면 스크린 리더 사용자가 위치를 잃기 때문입니다.
- Tab 가두기는 전체 visible 미확정 최상위 노드가 dimmed이고 trapFocus가 true일 때만 수행합니다. 최상위가 토스트이면 기본 Tab 순서를 유지하며 기존 dimmed 모달의 inert는 유지합니다.
- 포커스가 이동 방향의 후보 목록에 없으면(tabindex가 음수인 제목, 방향 목록이 대표하지 않는 선택 전 그룹의 다른 라디오) DOM 순서에서 그 방향에 후보가 남아 있는지로 경계를 판단합니다. 남은 후보가 없으면 기본 이동이 모달을 벗어나므로 반대쪽 끝으로 감쌉니다. 위치 비교는 같은 트리 안에서만 정확하므로 shadow root 안에서 목록에 없는 요소에 포커스가 있으면 판단이 브라우저와 다를 수 있습니다.
- 최초·복귀 포커스 이동은 dimmed 참여 목록의 최상위만 대상으로 하고 이미 처리한 최상위 아래로 내려가지 않습니다. 노드 publish는 환경만 재평가하고 전경의 layout effect가 DOM 반영 뒤 한 번 이동합니다. 내부에서 사용자가 옮긴 포커스는 재렌더에도 유지합니다.
- alive && visible && dimmed && !settled인 노드만 포커스 이동·가두기와 페이지 격리에 참여합니다. trapFocus와 lockScroll은 기본 true이며 dimmed false는 전역 환경을 바꾸지 않습니다.
- 탭 순서는 양수 tabindex 오름차순 뒤 0 요소의 DOM 순서이며 같은 순위의 비교 결과는 0으로 정합니다.
- 열린 shadow root 안의 후보는 호스트 위치에 트리 순서로 이어 붙이고, 가두기는 shadow root를 따라 내려간 실제 포커스 요소로 경계를 판단합니다. 그렇지 않으면 shadow 안의 컨트롤을 건너뛰어 웹 컴포넌트에 Tab으로 닿지 못합니다. 닫힌 shadow root는 읽을 수 없어 제외하며, 슬롯에 들어간 light DOM 자식은 슬롯 위치가 아니라 호스트 자식 위치로 계산합니다. 어떤 슬롯에도 들어가지 않은 호스트의 light DOM 자식과 그 자손은 렌더되지 않으므로 제외합니다. 남겨 두면 마지막 실제 컨트롤에서 누른 Tab을 가두지 못해 포커스가 모달을 벗어납니다. 호스트가 없는 프레임은 전체 요소를 한 번 훑는 비용만 더하고 기존 선택자 결과를 그대로 씁니다.
- 한 번의 Tab 후보 탐색에서는 공유 조상의 CSS 표시 여부를 재사용하여 스타일 계산을 반복하지 않습니다. 다음 탐색은 다시 읽으므로 모달이 열린 뒤의 표시 변경도 반영하며, 닫힌 details의 summary 포함 여부는 후보마다 따로 판단합니다.
- CSS visibility는 후보 자신의 계산값으로 판단하여 숨겨진 조상 아래 명시적으로 보이는 자손도 브라우저의 Tab 순서에 포함합니다. display none·hidden·inert와 닫힌 details는 조상 전체에서 검사하여 실제로 렌더되거나 상호작용할 수 없는 자손을 제외합니다.
- 닫힌 details에서는 첫 번째 직계 summary와 그 내부 컨트롤만 자손 Tab 후보로 인정합니다. 중첩된 닫힌 details도 각각 확인해 숨겨진 컨트롤이 포커스 순환의 끝점이 되지 않게 합니다.
- 전경 래퍼는 setFrameElement로 등록합니다. 첫 탭 가능 요소 또는 래퍼로 포커스를 이동하며 autoFocus가 잡은 내부 포커스는 유지합니다.
- 첫 대상이 생길 때 앵커에서 body까지 각 조상 경로의 형제를 inert로 만들고 기존 속성은 보존합니다. 이후 추가 요소는 격리하지 않으며 root 이동과 재초기화는 현재 저장소를 재평가합니다. 앵커를 다른 root로 옮기면 브라우저가 그 안의 포커스를 잃으므로, 옮기기 전 앵커 안에 있던 포커스 요소를 열린 shadow root 안의 실제 포커스 요소까지 따라 내려가 기록하고, 격리 갱신 뒤 다시 포커스합니다. 호스트만 기록하면 shadow 안의 입력 위치를 잃습니다. 새 root가 이전 격리로 inert인 동안 포커스하면 브라우저가 거부하므로 순서가 중요합니다.
- 스크롤 잠금은 body의 overflow와 padding-right를 복원 가능하게 보관하고 0보다 크고 100보다 작은 스크롤바 너비만 보정합니다. 해제와 reset은 키보드·격리·스크롤·포커스 자원을 정리합니다.

- 유효 root는 마지막 root prop 변경 또는 initialize 호출로 정합니다. null인 소유자는 앵커를 떼되 포털과 노드를 유지하며 신규 요청을 큐에 둡니다. 요소로 복귀하면 같은 앵커를 붙이고 큐를 처리합니다.
- 처음부터 null인 주체는 앵커나 소유권을 만들지 않습니다. null이 된 대기자는 대기 목록을 떠나며 소유권은 현재 소유자의 cleanup 때만 이전합니다.
- 소유자 하나만 앵커와 포털을 사용하고 나머지 초기화 주체는 대기합니다. 소유자 해제 시 첫 대기자가 이어받으며 대기자 정리는 자신만 제거합니다.
- 대기자가 없으면 해제 시점의 세대 번호를 검사하는 마이크로태스크가 살아 있는 노드를 파괴합니다. 재초기화와 StrictMode는 이전 정리를 무효화하며 마운트 전 큐는 보존합니다.
- 스타일 관리자는 적용 시 지연 생성하고 해제 시 버립니다. reset은 DOM 앵커, 저장소 구독, 큐, 핸들러, 소유권, 계수를 모두 초기화합니다.
- reset은 테스트 격리 전용이므로 미확정 Promise를 완료하지 않고 요청을 버립니다. 결과를 확정하면 소비자 콜백이 테스트 경계를 넘어 실행되므로 이 초기화에서는 확정하지 않습니다. 실제 Provider 해제는 detach가 맡으며, 대기자나 같은 커밋의 재초기화가 없으면 열린 요청을 취소 값으로 완료합니다. ModalManager와 reset은 소비자 공개 API가 아닙니다.
- 소유권 이전은 이전 소유자의 요청 핸들러를 먼저 폐기합니다. 대기 요청은 새 소유자의 핸들러 설치 뒤 그 소유자의 경로·옵션으로 생성하여 숨겨진 모달과 미완료 Promise를 막습니다. 같은 이유로 표시 중인 살아 있는 노드도 새 소유자의 경로에서 표시를 판단합니다. 같은 소유자의 root 복귀는 현재 핸들러를 유지합니다.
- 큐 항목의 처리 오류는 해당 handleReject로 전달하며 다른 항목은 계속 처리합니다.

## Acceptance Criteria

### app-contract — 관찰 가능한 동작

- 등록·파괴·순서 변경은 구독자에게 반영되고 소유권 이전과 실제 해제는 서로 다른 결과를 유지합니다.

### shared-platform-state — 모듈 사본 간 일관성

- 같은 버전은 스타일 클래스·노드·큐·소유권과 전역 효과를 공유하고 다른 버전은 격리합니다.
