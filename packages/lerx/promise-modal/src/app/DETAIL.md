# app

## Requirements

살아 있는 노드와 구독, 고유 id 및 쌓임 순서는 static 저장소가 소유합니다. id 배열은 등록과 제거 때만 새 참조가 됩니다.

## API Contracts

- 소유자 하나만 앵커와 포털을 사용하고 나머지 초기화 주체는 대기합니다. 소유자 해제 시 첫 대기자가 이어받으며 대기자 정리는 자신만 제거합니다.
- 대기자가 없으면 해제 시점의 세대 번호를 검사하는 마이크로태스크가 살아 있는 노드를 파괴합니다. 재초기화와 StrictMode는 이전 정리를 무효화하며 마운트 전 큐는 보존합니다.
- 스타일 관리자는 적용 시 지연 생성하고 해제 시 버립니다. reset은 DOM 앵커, 저장소 구독, 큐, 핸들러, 소유권, 계수를 모두 초기화합니다.
- 큐 항목의 처리 오류는 해당 handleReject로 전달하며 다른 항목은 계속 처리합니다.

## Acceptance Criteria

### app-contract — 관찰 가능한 동작

- 등록·파괴·순서 변경은 구독자에게 반영되고 소유권 이전과 실제 해제는 서로 다른 결과를 유지합니다.
