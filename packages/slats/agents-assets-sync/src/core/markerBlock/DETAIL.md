# markerBlock Specification

## Requirements

- 이 경계는 문자열 변환만 소유하며 파일시스템을 읽거나 쓰지 않습니다. 대상 문서의 블록 밖 바이트는 보존합니다. 대상은 UTF-8 텍스트 또는 바이트와 일대일 대응하는 Latin-1 표현입니다.
- 규칙 원본의 정규형은 맨 앞 UTF-8 BOM 바이트 EF BB BF 하나(텍스트 입력에서는 U+FEFF 하나)를 제거하고 CRLF와 단독 CR 줄바꿈을 LF로 바꾼 바이트열입니다. 그 밖의 바이트는 UTF-8로 재해석하지 않으므로 Win-1252와 CP949도 보존합니다. 검증·블록 쓰기·설치 본문 비교용 해시는 이 정규형 하나를 사용합니다. 매니페스트의 files와 일반 파일 복사의 해시는 원본 바이트 그대로이며, ruleBodyHashes는 규칙별 정규형의 해시를 별도로 보유합니다. 대상 문서의 BOM과 외부 줄바꿈은 바꾸지 않습니다.

## API Contracts

### 어휘 문법

- 마커는 대소문자를 구분하는 정확한 한 행 `<!-- AGENTS-ASSETS-SYNC:START:<id> -->` 또는 `<!-- AGENTS-ASSETS-SYNC:END:<id> -->`입니다. 앞 들여쓰기와 뒤 공백은 허용하지 않습니다. ID는 비어 있지 않으며 첫 콜론 앞을 패키지 이름, 뒤를 상대 경로로 읽습니다. 콜론 없는 ID는 패키지 이름 전체와 빈 상대 경로로 읽는 기존 직접 API를 유지합니다.
- 일반 문맥에서 행의 선행 공백을 뺀 시작이 정확한 예약 접두사 `<!-- AGENTS-ASSETS-SYNC`인데 마커 문법과 일치하지 않으면 해당 행에서 거부합니다. 이 검사가 일반 HTML 주석 검사보다 먼저입니다. 소문자 등 다른 접두사는 이 도구의 마커가 아니며 일반 HTML 주석 문법을 따릅니다.
- 행 구분은 CommonMark처럼 LF·CRLF·단독 CR이며 원래 구분자의 바이트 수를 위치에 반영합니다. 원본은 이 세 줄바꿈을 같은 LF 정규형으로 읽지만 대상 문서의 기존 구분자는 보존합니다. 문서 첫 BOM만 분류에서 제외하되 위치는 원본 오프셋을 유지합니다. EOF 직전 개행은 필수가 아닙니다.
- fence는 backtick 또는 tilde 3개 이상이며 들여쓰기 0~3칸에서 열립니다. backtick 정보 문자열에는 backtick이 없어야 합니다. 같은 문자로 길이가 같거나 더 길고 뒤에 공백만 있는 행이 닫습니다. fence 내부의 마커는 예시 본문이며 소유 블록을 열거나 닫지 않습니다. EOF에 열린 fence가 있으면 시작 행에서 거부합니다.
- 목록 상태는 일반 문맥의 `-`, `+`, `*`, 숫자 뒤 `.` 또는 `)`와 공백으로 시작한 행이 보유하며 내용의 시작 열을 기억합니다. 빈 행 뒤의 비어 있지 않은 행이 그 열보다 왼쪽이면 목록 상태를 끝냅니다. 목록 내용 열 이상의 들여쓴 fence, 목록·blockquote 접두사 뒤 fence, 탭 또는 4칸 이상 들여쓴 fence는 해당 행에서 지원하지 않는 문맥으로 거부합니다. 이 보수적인 목록 문법 밖의 경계를 추측하지 않습니다.
- HTML 주석은 fence 밖 행의 0~3칸 뒤 `<!--`에서 시작하고 첫 `-->`까지 이어집니다. 같은 행에서 닫히면 다음 행은 일반 문맥입니다. 닫힌 뒤 같은 행의 또 다른 열린 주석도 추적합니다. 한 행의 backtick 코드 안에 있는 구분자와 `foo <!--`처럼 행 처음이 아닌 주석 예시는 일반 본문이며 주석 상태를 열지 않습니다. 주석 안의 마커는 첫 `-->`까지 본문입니다. 따라서 마커 행 자체의 `-->`도 주석을 닫습니다. EOF의 열린 주석은 시작 행에서 거부합니다.

### 소유 상태와 사건

- 어휘 상태와 별도로 열린 블록 없음 또는 열린 ID·시작 행·본문 시작 위치를 보관합니다. 일반 문맥의 START는 열린 블록이 없을 때 엽니다. 열린 블록 안의 START, 열린 블록 없는 END, 다른 ID의 END는 해당 행에서 거부합니다. EOF의 열린 블록은 START 행에서 거부합니다. 마커가 닫힌 fence·주석 안에만 있으면 소유 경계가 아니므로 실제 열린 블록을 대신 닫지 않습니다.
- 완전히 닫힌 순차 중복은 해석 가능한 목록입니다. parseBlocks는 모든 사본을 문서 순서로 반환하며 findBlockBody는 첫 사본의 본문을 반환합니다. removeBlock은 첫 사본 하나를 제거하는 기존 계약을 유지합니다. 같은 ID의 upsertBlock은 첫 위치를 새 본문으로 바꾸고 나머지 사본을 제거합니다.
- 실행 계획은 같은 ID의 모든 사본이 원본 정규형과 일치하면 쓰지 않습니다. 하나라도 다르면 force가 없을 때는 쓰지 않고 강제 적용 필요를 보고하며, force가 있으면 upsertBlock으로 하나로 정리합니다. 정리 후 다음 실행은 바이트를 바꾸지 않습니다.
- 본문은 START의 행 구분자 직후부터 END 행 시작 직전까지입니다. writer는 원본이 개행으로 끝나지 않으면 LF 하나를 보충합니다. 빈 원본은 본문 LF 하나로 읽힙니다. 모든 원본의 비교는 writer가 보충한 후행 LF 하나를 제외하는 읽기도 허용합니다. 설치된 본문의 CRLF만 LF로 바뀐 표현도 같은 정규형으로 비교하여 체크아웃의 줄바꿈 변환을 내용 변경으로 판단하지 않습니다. 원본이 이미 LF로 끝날 때 빈 줄을 더한 본문과 완전히 빈 본문은 writer의 출력이 아니므로 일치하지 않습니다. parse(write(blocks))의 참조 모델은 이 후행 개행 표현을 명시적으로 포함합니다.
- parseBlocks·findBlockBody·removeBlock·upsertBlock은 같은 전체 파싱으로 존재와 부재를 판단합니다. 결과는 완전한 블록 목록 또는 파일명·행·이유를 가진 거부이며 부분 목록은 성공이 아닙니다. upsertBlock은 원본 정규형과 완성된 문서도 검증합니다. 거부된 파일은 force와 관계없이 바이트가 그대로입니다.

## Acceptance Criteria

### AC-MB-MODEL — 상태 모델과 생성 입력이 일치합니다

- 고정 사례는 앞 라운드의 fence·주석·중복·비UTF-8·BOM·CRLF 입력과 이번 삭제되거나 손상된 경계를 포함합니다.
- 생성 입력은 BOM 세 표현, LF·CRLF·혼합·마지막 개행 없음, UTF-8·Win-1252·CP949 바이트, 두 fence 문자와 길이·들여쓰기·목록·blockquote·미닫힘, 한 행·여러 행·미닫힌 주석·inline backtick·START/END 감싸기를 조합합니다.
- 블록 0·1·여럿, 빈 본문, 같은·다른 순차 중복, nested·unmatched·interleaved, 뒤 공백·대소문자·손상 접두사를 조합합니다. 참조 모델과 실구현의 목록 또는 거부를 비교하고 적용 후 재적용, 정리 후 멱등성 및 거부 파일의 불변을 확인합니다. 실패는 재현 seed를 출력합니다.
