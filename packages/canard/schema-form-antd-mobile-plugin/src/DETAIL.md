# UI 입력 연결 계약

## Requirements

입력은 폼이 전달한 저장 값과 상태를 표시하며 라이브러리의 로컬 draft를 폼 값으로 오해하지 않습니다.

## API Contracts

숫자 Stepper의 빈 값은 allowEmpty를 지원하는 antd-mobile 5.2.0 이상에서 제공합니다. null을 렌더하지 못하는 이전 버전은 지원 범위 밖입니다.

### 입력의 접근성 이름

모든 조작 요소의 접근성 이름은 그 요소를 식별하는 보이는 텍스트 레이블을 포함합니다. 사용자 레이블 렌더러가 표시한 레이블을 우선하며, 입력이 동시에 별도 레이블을 표시하면 렌더러 레이블, 입력 레이블 순서로 공백을 두고 합칩니다. 이름 후보는 공백을 정규화하고 텍스트나 렌더링할 자식이 없는 문자열·배열·Fragment를 건너뛰며 같은 텍스트는 한 번만 읽습니다. 스키마 title은 별도 레이블이 없을 때 보이는 기본 레이블입니다. 의미 있는 레이블이 없으면 options의 `aria-label`, 스키마 title, 코어가 제공한 필드 이름 순으로 기존 제목 주소의 숨은 텍스트 또는 조작 요소의 `aria-label`에 이름을 제공합니다. 이름 없는 루트 배열과 객체는 제목 참조 없이 그룹을 표시할 수 있습니다. 필수 표시와 보조 상태는 이름에 포함하지 않습니다. 의미 있는 레이블은 문서에 연결되어 있고 자신이나 폼 안의 조상에 `hidden` 또는 `aria-hidden="true"`가 없으며, 같은 속성으로 숨긴 자손을 제외한 텍스트가 남는 레이블입니다. 장식 전용 레이블은 대체 이름을 사용합니다. 소비자 CSS의 display, visibility, 클래스만으로 숨긴 레이블은 접근성 이름을 계속 공급합니다. 플러그인은 계산된 스타일을 조회하지 않으므로 대체 이름을 사용하려면 hidden 속성을 지정하거나 레이블을 렌더링하지 않습니다. 소비자가 소유한 ARIA 속성은 유지하며, 플러그인은 비어 있는 속성이나 자신의 마지막 생성값만 갱신하고 정리합니다.

조작 요소의 접근성 이름은 현재 문서에 있는 레이블 소스로 결정합니다. 조작 요소, 기본 레이블, 외부 레이블의 마운트·제거·재마운트 순서와 사용자 레이블 렌더러의 교체에 관계없이 현재 소스를 사용하며, 레이블의 텍스트가 바뀌면 이름도 바뀝니다. 주 조작 요소는 같은 주소의 DOM이 교체되어도 현재 이름을 사용합니다. 명시적 Form.Input과 폼 그룹 모두 의미 있는 제목이 아직 없거나 제거되거나 비동기 경계에서 대기하는 동안 대체 이름을 사용하며, 의미 있는 제목이 나타나면 그 텍스트가 우선합니다. 제목 없는 루트 컨테이너에는 대체 이름을 만들지 않습니다. 코어 이름이 비어 있는 단일 조작 요소에는 Field를 사용합니다.

텍스트·비밀번호·텍스트 영역·숫자·단일 체크박스·스위치, 단일·다중 enum의 combobox 및 Stepper의 숫자 편집 input에 필드 이름을 연결합니다. 슬라이더와 범위 피커는 각 조작 지점에 공통 필드 이름을 연결합니다. 라디오 및 체크박스 선택 그룹, 배열과 객체는 그룹에 필드 이름을 연결합니다. 선택지 이름에는 표시 alias, 텍스트 버튼 이름에는 보이는 버튼 문구를 포함하며 아이콘 전용 버튼에는 기능 이름을 사용합니다. 배열 항목에는 해당 필드의 이름을 적용합니다. URI 주소 입력에는 필드 이름, 프로토콜에는 프로토콜 선택기의 이름을 사용합니다. 피커의 세부 부분과 열기 버튼, 비밀번호 가시성 버튼, 숫자 증감 버튼과 배열 이동·추가·제거 버튼에는 해당 요소의 레이블을 사용하며 필드의 이름 있는 그룹 또는 설명으로 소속을 표시합니다.

코어의 `inputId`는 주 조작 요소에 두고, 추가 조작 요소와 입력 자체 레이블에는 `getInputId(key)`가 발급한 서로 다른 id를 둡니다. bound Label과 Form.Label이 소유하는 제목의 id는 `labelId`입니다. 레이블의 `for`는 연결 대상 주 조작 요소의 id를 가리키며, 복합 그룹에는 제목을 참조하는 `aria-labelledby`를 사용합니다. `aria-labelledby`의 각 id는 실제 이름을 제공하는 요소 한 개를 가리킵니다. 외부 레이블과 내부 레이블이 같은 제목을 표시하는 선택 그룹은 하나만 접근성 트리에 노출합니다. 같은 규칙은 플러그인 기본 renderer, Form.Label과 Form.Input, bound Label을 사용하는 renderer, hideLabel에서도 적용합니다. 모바일 라이브러리가 내부 조작 요소로 ARIA 속성을 전달하지 않는 경우에는 hydration에서 현재 네이티브 요소에 이름을 연결합니다. 서버 HTML에서는 이 연결을 기다리는 동안 라이브러리가 제공하는 연결을 사용합니다.

### 슬라이더의 경계·격자·저장

포함·배타 경계가 함께 있으면 더 엄격한 경계가 이기며 한쪽에 둘 다 없을 때만 기본 0 또는 100을 사용합니다. multipleOf가 있으면 표기법에 관계없이 0부터 정확한 십진 배수 격자를 계산하며 정수 타입은 그 격자와 정수의 교집합을 사용합니다. 첫 허용 값과 마지막 허용 값이 트랙 경계이므로 step으로 닿지 않는 상한은 선택 범위에 포함되지 않습니다.

multipleOf 없는 number는 작성한 하한을 기준으로 기본 step 1을 적용하고 포함된 하한과 상한을 선택할 수 있게 합니다. 배타 하한은 첫 step부터 선택하고 배타 상한에 닿는 step은 제외합니다. 범위가 기본 간격보다 좁으면 허용되는 포함 상한을 유지합니다. multipleOf 없는 integer는 경계 안의 정수를 선택합니다. 선택할 값이 없는 격자는 잠그고 저장하지 않습니다.

매 렌더에서 값 표시는 현재 저장 값과 현재 모드에서 정합니다. multipleOf 없는 number의 읽기 전용 모드에서는 선택 범위 안의 저장 값을 보존하며, 그 외에는 포함 상한을 포함한 허용 정지점 중 저장 값과 가장 가까운 점을 표시하며 동률은 큰 점을 선택합니다. 범위 밖이면 가까운 끝점을 표시합니다. 활성 조작 중에는 현재 draft를 표시합니다. 잠금 전환과 외부 저장 값 교체는 미확정 draft와 대기 중인 확정을 폐기합니다. 잠금 해제 뒤 취소한 조작의 키 해제나 포인터 완료는 값을 쓰지 않습니다. 어느 모드에서 시작했는지와 무관하게 읽기 전용, disabled, 편집 가능 사이를 전환한 결과는 현재 저장 값과 새 모드로 다시 계산합니다. readOnly와 disabled가 함께 설정되면 읽기 전용 표시 규칙을 적용하고 조작은 잠급니다.

엄지의 `aria-valuenow`와 표시되는 툴팁은 같은 표시 값을 스키마 단위로 제공합니다. 값이 있으면 별도 `aria-valuetext` 없이 그 수를 읽습니다. 초기 값이 없거나 외부 reset으로 다시 미설정이 되면 새 조작 전까지 `aria-valuenow`를 생략하고 `aria-valuetext`에 `Not set`을 제공하며 툴팁과 값 레이블을 숨깁니다. 이때 엄지는 키보드 초점에서만 보입니다. 눈금은 유효한 정지점의 시각 표시이고 내부 좌표로 환산해도 사용자 레이블을 유지합니다.

잠금과 렌더는 저장 값을 바꾸지 않습니다. 유효한 조작을 하면 lazy가 false일 때 이동마다, 생략하거나 true면 키보드 또는 포인터 확정에서 값이 저장됩니다. Home과 End는 현재 엄지에서 선택 가능한 첫 값과 마지막 값을 선택합니다. 위와 PageUp은 방향과 무관하게 증가하며 아래와 PageDown은 감소합니다. 가로 화살표는 LTR에서 Right, RTL에서 Left가 증가합니다. 기본 격자에서 화살표는 한 step, PageUp·PageDown과 Shift+화살표는 열 step을 이동합니다. 미설정의 탐색 기준은 첫 정지점입니다. 격자 밖에서 증가 키는 floor 인덱스에 이동량을 더하고 감소 키는 ceil 인덱스에서 이동량을 뺀 뒤 경계 안으로 제한합니다. 포인터는 라이브러리가 위치에 맞춰 선택한 정지점을 스키마 단위로 변환하여 표시하고 저장합니다. 읽기 전용·disabled·빈 격자에서는 키와 포인터가 값을 바꾸지 않습니다.

Number.MAX_SAFE_INTEGER에 이르는 트랙에서 포인터 정밀도는 라이브러리의 부동소수점 좌표 범위까지입니다.

이 연결은 기존 표시 설정을 유지하기 위해 라이브러리의 popover를 노출하지 않습니다. 라이브러리는 왼쪽 좌표로 포인터 값을 계산하며 방향 설정이 없으므로 가로 방향은 LTR입니다. 기본 lazy에서는 이동 뒤 Shift를 먼저 놓아도 확정됩니다.

유효한 눈금이 하나 이상이면 포인터는 가장 가까운 눈금으로 이동하고 동률이면 큰 눈금을 선택합니다. 화살표와 Page 키는 같은 선택 집합에서 이동 방향의 다음 눈금을 사용합니다. Shift는 눈금 이동을 바꾸지 않습니다. 유효한 눈금이 없으면 라이브러리가 포인터 위치를 기본 step으로 반올림한 값을 경계 안으로 제한합니다. 기본 step에 맞지 않는 포함 상한은 라이브러리의 일반 포인터 후보에 별도로 들어가지 않습니다. multipleOf 없는 number에서 스키마 경계 안의 눈금은 기본 격자 밖에서도 유효하며 표시 값을 이미 그 눈금에 두었으면 유지합니다. 그 외에는 눈금이 integer와 multipleOf 격자에도 맞아야 합니다. 기본 격자가 비면 유효한 눈금 레이블을 보이지만 조작은 잠급니다.

숫자 배열 슬라이더는 items의 숫자 타입·경계·multipleOf를 양끝에 적용하며 경계나 multipleOf가 items에 없으면 같은 배열 설정을 사용합니다. 두 엄지는 서로를 넘지 않으므로 Home·End는 상대 엄지가 제한하는 구간에서 가장 바깥 정지점 또는 유효 눈금을 선택합니다. 편집 가능한 각 엄지는 Tab과 코어의 focus 대상입니다. 네이티브 식별자와 엄지 제목 연결은 hydration에서 완료되므로 서버 HTML에는 README의 서버 렌더링 한계가 적용됩니다.

## Acceptance Criteria

### control-names — 레이아웃과 무관한 입력 이름

- 입력 정의에서 파생한 표는 각 정의의 primary·range-end·auxiliary 분류를 요구합니다.
- 네 레이아웃에서 이름·소속·고유 id·참조 대상을 검사하며 새 정의가 미분류이면 실패합니다.

### slider-values — 모든 조작의 유효 값

일반 로컬 실행과 pre-release는 전체 교차 범위를 실행합니다. PR은 224개 스키마 조합과 타입·step·양끝 경계·다섯 시작 상태·모든 조작 분류의 쌍을 유지하며, 두 lazy 모드는 선택한 각 입력에서 같은 단언으로 비교합니다.

- 독립 십진 참조 모델에서 경계 조합·multipleOf·타입·시작 값·키와 pointer·lazy를 교차하여 저장 값과 schema 유효성을 비교합니다.
- 미설정 표시·렌더 시 값 보존·commit 시점 및 기존 소수 경계 동작을 유지합니다.
