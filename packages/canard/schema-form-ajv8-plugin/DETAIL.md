# AJV8 패키지 소유 계약

## Requirements

발행 manifest의 방언 경계와 공통 검증 구획을 함께 소유합니다. 방언은 각자의 bind·configure 선택과 등록 자원을 유지하며, 공통 구현을 쓴다는 이유로 프로필이나 스키마 수명을 합치지 않습니다.

## API Contracts

플러그인이 생성하는 기본 인스턴스는 `multipleOfPrecision: 9`를 사용합니다. 배수의 몫과 가장 가까운 정수의 차이를 `1e-9`까지 허용하여 몫의 절댓값이 `1e6` 이하인 정확한 소수 배수가 이진 나눗셈 오차로 거부되지 않게 합니다. 이 범위 밖의 정확한 배수는 보장하지 않으며 정수 몫에 `1e-9` 이내로 가까운 비배수도 허용할 수 있습니다. 소비자가 제공하는 인스턴스의 정밀도 설정은 바꾸지 않습니다.

등록 해제는 각 등록이 실제로 추가한 레지스트리 항목만 제거합니다. 애플리케이션이 먼저 등록했거나 이후 같은 주소에 다시 등록한 항목은 유지하며, 해제 시 현재 값이 기록된 소유 값과 같은지 확인합니다. 등록 키의 별칭이 애플리케이션의 캐시를 재사용한 경우 그 캐시도 제거하지 않습니다.

`compileGuard`의 조각 접두사 없는 포인터는 RFC 6901 JSON Pointer입니다. `%`는 이름의 문자이며 폼 경로 이스케이프로 디코딩하지 않습니다. 루트 참조에 붙이는 URI 조각에서만 `%25`로 이스케이프하여 다른 이름의 스키마를 평가하지 않습니다.

기본 인스턴스는 모든 strict 검사를 끄며, 소비자가 bind한 인스턴스의 strict 옵션은 유지합니다. 가드의 독립 컴파일과 열린 튜플도 기본 strict 경고를 내지 않습니다.

공개 검증 의미는 [플러그인 계약](../schema-form/src/app/plugin/DETAIL.md)을 따릅니다. 공통 validator는 세 방언이 재사용하는 조상의 내부 구획입니다. 외부에서는 발행된 방언 주소를 쓰고 자식 구현은 저장소의 위로 열린 참조 원칙에 따라 공통 구획의 구체 파일을 읽습니다.

루트 package manifest가 실제 공개 주소를 열거하므로 별도의 대표 index나 module-entry-point 면제를 추가하지 않습니다. 이 소유권은 구현을 옮기거나 모듈 초기화 순서를 바꾸지 않습니다.

소비자가 bind한 인스턴스에 나중에 추가·교체·제거한 format과 keyword는 이후 컴파일에 반영합니다. 스키마 캐시는 루트별로 격리하지만 규칙 레지스트리는 살아 있는 원본을 참조하므로 풀 회전이나 첫 가드의 컴파일 순서가 이후 검증 의미를 바꾸지 않습니다. 이미 생성한 검증 함수는 재컴파일하지 않습니다.

복제된 컴파일러에서 외부 스키마가 없으면 원래 인스턴스에서 조회하고 그 스키마만 컴파일러에 등록한 뒤 재시도합니다. 애플리케이션의 늦은 스키마 등록은 이후 컴파일에 반영하며 이미 복제하거나 컴파일한 스키마를 교체하지 않습니다. 일반 컴파일은 레지스트리를 다시 순회하지 않습니다.

가드의 동적 앵커 표는 선언된 이름만 자체 키로 보유합니다. Object.prototype의 이름과 같은 앵커도 일반 이름처럼 바인딩하고, 선언이 없는 이름은 상속 여부와 관계없이 거부합니다.

## Acceptance Criteria

### dialect-ownership — 방언과 공통 구현의 소유자를 구별합니다

- 방언별 초기화·설정·등록의 실행 의미와 공개 이름을 유지합니다.
- 공통 validator 구획에는 이 패키지의 소유권이 적용됩니다.

### public-contract — 공개 진입점을 유지합니다

- manifest의 공개 주소와 타입·런타임 진입점 대상은 바뀌지 않습니다.
- 기존 검증·가드·수명 시험을 같은 단언으로 실행합니다.

## Last Updated

공개 방언 주소·공통 구현의 소유권 또는 설정과 등록 수명의 경계가 바뀔 때 갱신합니다.
