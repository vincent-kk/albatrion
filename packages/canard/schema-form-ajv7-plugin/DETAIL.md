# AJV7 검증 연결 계약

## Requirements

선택한 AJV 방언이 스키마, 참조, 형식, 키워드 및 수치 판정을 결정합니다. 플러그인은 그 판정을 폼의 결과, 위치, 등록 주소와 수명 계약에 연결합니다. 값 변경 옵션은 입력의 소유권을 지키기 위해 바인딩과 독립 팩터리 생성 시 거부합니다. 바인딩 뒤에 옵션을 활성화하면 다음 검증 또는 가드 컴파일이 새 프로필을 수용할 때 같은 오류로 거부합니다.

## API Contracts

전체 검증 결과는 성공 시 `null`이고 실패 시 호출별 순서를 유지하는 `ValidationIssue[]`입니다. 네이티브 검증 오류 표지가 있는 AJV 오류를 issue로 변환합니다. 다른 실행 예외는 같은 값으로 전달합니다. 검증 메타데이터는 AJV가 컴파일한 스키마를 따릅니다.

오류의 데이터 위치는 JSON Pointer입니다. 실제 자식에 놓인 false 스키마만 부모 위치와 거부된 키로 바꾸며, 현재 값에 적용된 false는 해당 위치에 남깁니다. 단일 키 `not.required`는 native 주소가 가리키는 확인 가능한 스키마에서만 키를 얻습니다. `propertyNames`의 내부 오류에도 AJV가 제공한 원래 키를 전달합니다.

명시적 `createValidatorFactory(instance, key)`는 현재 앱에서 키가 선택하는 스키마를 사적으로 컴파일하며 앱의 컴파일 캐시에는 쓰지 않습니다. 사용자 지정 생성자는 사적 컴파일러를 만들 때 초기 스키마를 등록하지 않아야 합니다. 앱에 값을 바꾸는 옵션이 켜져 있으면 키를 컴파일할 때 거부합니다. 각 검증기는 스키마 경로에서 찾은 거부 키를 유지합니다. 비동기 키워드나 포맷을 쓰는 전체 검증은 이름 있는 루트를 포함해 플러그인 소유의 루트 사본에서 비동기 모드를 활성화합니다. 별도로 등록하는 비동기 참조 자원은 앱이 `$async: true`를 선언합니다.

동기 가드는 동일한 엔진 루트 사본의 표준 JSON Pointer를 받습니다. 루트 포인터 가드의 동적 앵커 표는 사슬 자원이 선언한 이름을 자체 항목으로 보존합니다. 이 이름이 객체 프로토타입 멤버와 겹쳐도 같은 규칙을 적용합니다. 루트와 무관한 조건은 직접 컴파일할 수 있고 그 밖의 조건은 원래 루트 문맥에서 AJV로 컴파일합니다. 가드는 전체 검증의 선행 호출을 요구하지 않습니다. AJV가 선택한 조건을 비동기로 컴파일하면 가드를 만들 수 없습니다.

애플리케이션은 인스턴스의 메타 스키마, 포맷, 키워드 및 별도 참조 자원을 구성합니다. 새 컴파일에는 그 시점의 native 등록과 설정을 사용하며 `addSchema`로 등록한 참조 문서의 내용 변경도 반영합니다. 앱 등록 키와 스키마 ID가 서로 다른 대상을 가리키면 각각의 연결을 유지합니다. 앱에서 제거한 내장 ID는 새 컴파일에서 참조할 수 없습니다. 반환된 검증 함수와 가드는 컴파일 시점의 판정을 유지합니다. 동일한 루트 사본을 `compile`, `compileGuard`, `release`에 전달합니다. 폼의 등록은 사적 native 컴파일러가 소유하며 앱에 노출되지 않습니다. 앱에서 조회하거나 다른 루트에서 참조할 주소는 앱이 등록합니다. 사용자 정의 키워드가 같은 어댑터에서 다른 폼을 컴파일할 때에도 진행 중인 폼의 주소는 참조 범위에 들어가지 않습니다.

기본 검증기는 AJV의 `multipleOfPrecision: 9`를 사용해 문서화한 유한 범위에서 십진 배수를 허용합니다. 기본 메타 스키마 검사는 제수 0을 거부합니다. `multipleOf: 0`인 동기 숫자 가드는 `false`를 반환합니다. 앱이 제공한 AJV 인스턴스의 옵션은 유지합니다.

## Acceptance Criteria

### native-validation — 호출별 결과와 주소

- 호출이 겹쳐도 각 검증이 자기 issue 순서와 위치를 유지합니다.
- 실행 예외는 같은 객체로 거부하며 비동기 성공값의 truthiness는 검증 결과를 바꾸지 않습니다.
- 직접 자식과 값 수준 false, 인코딩된 `not.required`, `propertyNames`를 구별합니다.

### native-guards — 동기 조건의 원래 문맥

- 포인터의 리터럴 퍼센트와 URI 조각 입력은 같은 authored 위치를 가리킵니다.
- 먼저 가드를 컴파일해도 원래 문맥에서 같은 native 동기 조건을 사용합니다.
