# 네이티브 검증 연결 계약

## Requirements

주입한 인스턴스의 검증 의미를 보존하며 폼의 루트 수명은 애플리케이션의 스키마 등록 수명과 구별합니다.

## API Contracts

키워드가 던지거나 거부한 값은 컴파일에 사용하는 AJV 인스턴스의 생성자가 제공하는 ValidationError의 인스턴스일 때만 검증 issue로 변환합니다. errors라는 속성이나 AJV 표지 속성은 클래스의 정체성을 대신하지 않습니다. 다른 오류와 오류가 아닌 값은 같은 값으로 호출자에게 전달하여 실행 실패를 검증 실패로 숨기지 않습니다. 별도 설치된 같은 AJV 버전의 인스턴스를 주입해도 그 생성자의 ValidationError를 사용하므로 설치 사본에 따라 의미가 바뀌지 않습니다.

### 루트 소유권 상태 모델

애플리케이션 AJV의 레지스트리·캐시·코드 scope·errors는 애플리케이션만 변경합니다. 폼 연산은 애플리케이션의 getSchema·compile·validate·addSchema·removeSchema·validateSchema를 호출하지 않습니다. 폼의 $id는 private 컴파일러에만 존재하므로 애플리케이션 getSchema로 폼 루트를 조회할 수 없고 애플리케이션 removeSchema는 이미 반환한 폼 함수를 제거하지 않습니다.

| 상태 | 소유자와 수명 | 보장 |
| --- | --- | --- |
| 애플리케이션 상태 | 애플리케이션 인스턴스 | 스키마 환경은 빌려 컴파일하지 않고 raw schema만 읽습니다. |
| 인스턴스 원장 | 버전이 구분된 realm 공유 WeakMap | 동일 애플리케이션 객체에 한해 등록 번호·finalizer·살아 있는 id 참조·64루트 풀을 공유합니다. 어댑터별 설정·루트 캐시는 합치지 않습니다. |
| 메타 검증 커널 | 인스턴스 원장의 현재 프로필 | 요청한 메타 raw schema만 컴파일하며 폼 root를 컴파일·등록하지 않습니다. 메타 코드 캐시는 폼 풀의 회전과 분리하며 프로필·수입 변경 또는 메타 문서 64개에서 회전합니다. |

| 대기 등록 | 어댑터의 weak key와 원장 | 원본과 분리한 스냅숏만 보유하며 검증·가드 컴파일러를 지연 생성합니다. |
| 검증 완료 등록 | 해당 어댑터·애플리케이션·루트 identity | 성공한 검증 함수를 캐시합니다. 원본 루트는 weak key와 finalizer target으로만 참조합니다. |
| 폐기된 컴파일러 | 기존 반환 함수 | 새 컴파일에는 쓰지 않으며 기존 함수만 스냅숏 의미로 유지합니다. |
| 해제 등록 | 소유 자원 없음 | 명시적 해제는 동기적이고 반복해도 무해합니다. |

| --- | --- |
| createValidator·최초 bind | 변경 옵션을 거부한 뒤 선택과 weak 상태만 준비합니다. 거부된 bind는 기존 선택을 유지합니다. |
| compile(root), 첫 성공 | 현재 프로필과 자원 충돌을 검사한 private 컴파일러에 detached 스냅숏을 전달하고 성공한 함수를 캐시합니다. |

| 후속 compileGuard | 이전 반환 가드는 스냅숏으로 유지하며 새 네이티브 컴파일은 현재 프로필을 봅니다. 직접·문맥 가드 모두 변경이 감지된 컴파일러를 재사용하지 않습니다. |
| public createValidatorFactory | private 컴파일러와 detached 입력을 사용합니다. 네이티브 비동기 반환 계약과 오류 정규화는 유지하며 애플리케이션 주소가 필요한 인자는 레지스트리에서만 읽습니다. |
| release(root) | 이 등록의 private 자원과 예약만 제거합니다. 이미 반환한 함수와 다른 루트·애플리케이션 등록은 유지합니다. |
| 새 루트 등록 | 죽은 weak 참조를 가지치기합니다. 컴파일러당 최대 64개의 등록 시도를 허용한 뒤 회전하며 캐시 적중은 한도를 소비하지 않습니다. 살아 있는 폼끼리 주소가 겹치면 private 컴파일러를 분리합니다. |
| 루트·어댑터 수거 | 원장의 finalizer가 등록을 정리합니다. 수거가 늦거나 finalizer가 없어도 충돌 격리 때문에 재방문 성공 여부가 GC에 의존하지 않습니다. |

bind는 첫 컴파일 전에 한 번 호출합니다. 컴파일 후 재바인딩은 지원하지 않습니다. 관찰 가능한 기존 동작은 새 바인딩이 기본 플러그인의 weak 루트 선택을 초기화하며 이전 반환 함수는 기존 private 프로필에서 실행을 계속한다는 것입니다. createValidator로 만든 독립 어댑터는 영향을 받지 않습니다.

### I1 — 애플리케이션 관찰 동등성

폼 연산을 끼운 애플리케이션과 애플리케이션 연산만 실행한 쌍둥이 인스턴스는 자기 호출의 반환·예외 종류와 메시지·ajv.errors, 레지스트리 키와 순서·캐시·fragment·코드 scope 크기가 같습니다. private 컴파일러 입력과 error 변환 closure, 직접 가드, scope와 cache에는 호출자 root나 그 자식 객체를 넣지 않습니다. JSON 스냅숏만 저장하고 원본을 강하게 도달하는 경로가 없음을 루트·어댑터의 실제 수거로 확인합니다.

AJV가 호출 때마다 초기화하는 keyword validate·validateSchema 함수의 errors는 임시 scratch 상태로 이 불변식에서 제외합니다. 같은 keyword metaSchema를 private 쪽에서 재컴파일하지 않습니다. 이미 등록된 validateSchema 함수를 그대로 사용하므로 그 metaSchema가 참조한 애플리케이션 문서가 이후 제거돼도 등록된 keyword의 의미를 보존합니다. RULES와 formats는 native 컴파일이 구조를 변경하지 않는 부분만 공유하며 함수 errors와 사용자 callback의 외부 closure 부수효과는 격리하지 않습니다.

### I2 — 현재 프로필·별칭·충돌

폼 스키마의 메타 검사는 원장 소유 메타 검증 커널에서 실행합니다. 이 커널은 폼 스키마를 검증 데이터로만 받으므로 폼 코드를 누적하거나 caller root를 보유하지 않으며, 같은 프로필의 메타 검증 함수를 폼 풀 회전 때마다 다시 만들지 않습니다.

private 생성자에는 schemas·keywords·formats·cache bootstrap 옵션을 전달하지 않습니다. 기본 meta 자동 등록도 끄며 애플리케이션의 현재 옵션에서 defaultMeta와 요청한 메타 주소를 구하고, 메타 raw schema와 메타 별칭을 private 환경에 동기화합니다. 제거된 초기 schemas를 되살리지 않으며 객체형 meta와 http://json-schema.org/schema 별칭 및 늦은 addMetaSchema도 같은 경로로 처리합니다. 사용자 cache와 AJV6 serialize 정책은 애플리케이션 안에서만 유지하며 private 캐시는 별도 identity 기반으로 소유합니다.

컴파일러는 사용한 옵션의 키·값, 사용한 규칙 정의와 format의 이름·값, 메타 주소, 수입 자원과 모든 중간 별칭·최종 문서의 레지스트리 값을 기록합니다. 다음 실제 컴파일 전에 Object.is 기반으로 이 기록을 현재 애플리케이션 상태와 비교합니다. 관찰 대상의 추가·제거·교체가 감지되면 그 컴파일러와 전이 refs·생성 코드·embedded 및 anchor 별칭을 통째로 폐기하고 새 컴파일러로 시작합니다. 가드와 아직 컴파일되지 않은 등록도 폐기된 컴파일러에서 새 환경으로 이동합니다. 기존 반환 함수는 그대로 둡니다.

검사 비용은 관찰한 옵션 P, 규칙 K, format F, 메타 주소 S, 수입·별칭 R에 대해 O(P+K+F+S+R)이며 전체 애플리케이션 데이터 스키마 M을 순회하지 않습니다. 외부 수입이 없고 detached 새 root가 네이티브 캐시를 재사용하지 않는 경로는 살아 있는 프로필을 읽는 경로로 유지하여 불필요한 규칙·데이터 스키마 재구축을 하지 않습니다. 같은 객체의 캐시 적중은 O(1)입니다. 비용은 adapter 생성·최초 컴파일·재컴파일·검증의 속도 행으로 입증합니다.

레지스트리 조회는 own key만 사용하고 문자열 별칭의 모든 중간 키와 최종 문서를 추적합니다. compound 문서는 raw schema로만 수입합니다. 애플리케이션이 embedded 주소만 제거한 경우도 별칭 기록의 변화로 감지합니다. 순환 별칭은 방문 주소로 종료하며 해석할 수 없는 참조 오류를 반환합니다. 순환 $ref는 네이티브 AJV가 지원하는 재귀 스키마 의미를 유지합니다.

참조는 컴파일 시점에 애플리케이션이 해당 키나 id로 해석하는 raw 문서에 연결합니다. 등록 키 A가 자체 id I인 이전 문서를 유지하고 I가 새 문서로 교체되면, A만 참조하는 루트와 I만 참조하는 루트는 각각의 문서를 사용합니다. 서로 다른 문서가 같은 정규화 id를 요구하면 풀을 분리합니다. 한 루트가 두 문서를 함께 요구하는 경우는 지원하지 않으며 해당 id와 두 참조 키를 명시한 오류로 거부합니다. 키별 네이티브 환경을 재구성하여 이 한계를 우회하지 않습니다.

주소는 해당 네이티브 AJV의 URI resolver로 부모 자원에 대해 상대 id를 해석하고 끝의 # 또는 #/를 제거한 값입니다. root·embedded id, 지원 방언의 $anchor·$dynamicAnchor와 레지스트리의 임의 등록 키·별칭을 모두 대조합니다. 애플리케이션 root뿐 아니라 embedded 주소나 anchor가 폼 root 주소와 겹쳐도 같은 충돌 규칙을 적용합니다.

현재 애플리케이션 레지스트리나 별칭에 폼 root 주소가 있으면 내용과 관계없이 중복 id 오류로 거부합니다. 폼 embedded 자원의 주소는 같은 raw 내용일 때만 허용하고 다르면 모호한 참조 오류로 거부합니다. 제거된 주소는 충돌하지 않습니다.

### I3 — 한정된 자원과 수거 독립성

폼 연산이 애플리케이션에 추가하는 등록·캐시·생성 코드는 0개입니다. 풀과 finalizer는 어댑터보다 오래 사는 인스턴스 원장이 소유하며 원장은 루트나 어댑터를 강하게 보유하지 않습니다. 등록은 detached snapshot·컴파일러·함수만 보유합니다. 명시적 해제와 풀 회전은 GC를 기다리지 않으며 죽은 weak 목록은 후속 등록에서 정리합니다. 코어의 어댑터별 recent 8개 정책과 어댑터별 옵션은 유지합니다.

### 지원 범위와 명시적 거부

- 공개 타입의 root는 JSON schema 객체입니다. boolean root는 compile·compileGuard·factory에서 명확한 TypeError로 거부합니다. 객체 root 안에서 포인터가 선택하는 boolean 조건은 계속 지원합니다.
- bind와 createValidator, createValidatorFactory는 coerceTypes·useDefaults·removeAdditional가 켜진 인스턴스를 거부합니다. bind 이후 이 옵션을 켜도 다음 실제 컴파일에서 같은 거부로 처리합니다. 안전한 상태에서 이미 반환한 함수는 스냅숏입니다.
- loadSchema는 호출하지 않습니다. 공개 컴파일은 동기적인 스키마 해석과 비동기 값 검증을 제공하며 외부 문서는 먼저 애플리케이션에 등록해야 합니다. 빠진 문서는 참조 오류로 거부합니다.
- 생성자는 옵션 객체 하나로 private 인스턴스를 만들 수 있어야 합니다. 비표준 필수 인자를 요구하거나 격리 옵션을 무시하는 하위 클래스는 원인을 담은 명확한 격리 컴파일러 생성 오류로 거부합니다. 다른 기본 생성자로 조용히 대체하지 않습니다.
- AJV6 serialize:false와 addUsedSchema:false는 애플리케이션 레지스트리의 실제 현재 상태를 기준으로 읽습니다. 존재하지 않는 등록을 schema 내용만으로 추정하지 않습니다. private identity 캐시와 등록 정책은 애플리케이션 cache·serializer를 호출하거나 변경하지 않습니다.
- 작성 root·등록한 raw schema 및 keyword·format 정의와 옵션 안의 중첩 객체를 제자리에서 바꾸는 것은 지원하지 않습니다. 공개 add/remove 또는 값·객체 교체로 변경해야 합니다. 이미 반환한 validator·guard와 같은 root 객체의 캐시 함수는 스냅숏입니다.
- FinalizationRegistry가 없으면 자동 해제를 보장하지 않습니다. WeakRef도 없으면 명시적 release만 수명 관리로 보장합니다. 이 호스트에서도 살아 있는 주소의 충돌 격리와 64루트 풀 한도는 유지합니다.

## Acceptance Criteria

### keyword-exception-identity — 실행 오류와 검증 실패를 구별합니다

- 동기·비동기 키워드와 공개 진입점에서 네이티브 ValidationError만 issue로 변환합니다.
- errors 배열·배열이 아닌 errors·표지를 가진 일반 객체는 같은 값으로 거부합니다.
- 다른 설치 사본의 AJV 인스턴스도 자기 네이티브 오류를 인식합니다.

### ownership-observation — 애플리케이션 관찰 동등성과 현재 상태

- I1은 애플리케이션 연산만 받는 쌍둥이 인스턴스와 비교합니다. I2는 폼이 사용하는 각 참조를 쌍둥이의 현재 레지스트리에서 컴파일 없이 해석한 뒤 필요한 raw 문서만 독립 검증기에 넣어 비교합니다. 전체 raw 문서를 다시 등록하거나 쌍둥이의 오래된 A.validate 캐시를 oracle로 쓰지 않습니다. 별칭 키를 유지한 id 교체 뒤 키·id·양쪽 참조를 모두 생성하며 양쪽이 한 루트에서 충돌하는 명시적 한계도 비교합니다.
- 수천 개의 seed 시퀀스는 세 root id·두 embedded id·상대 주소·anchor·내용 동등/변경, application add/compile/validate/get/remove와 규칙·format·meta 변경, 여러 어댑터·사본, 첫/반복/실패 후 compile, 선행·후속 가드, 반복 release와 64루트 회전을 교차합니다.
- 버전·방언과 allErrors·strict·validateFormats·bootstrap schemas 및 AJV6 경로·legacy id·serialize·addUsedSchema 옵션을 교차하며 GC 전후와 기능이 없는 호스트의 명시적 한계를 고정합니다.
- root와 직접 가드·반환 함수의 weak collection을 검사하며 모든 실패에 seed·연산 위치를 남깁니다. 1–5라운드 고정 입력을 포함합니다.
