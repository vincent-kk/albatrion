# types

## Purpose

공유 작성 스키마·값·입력·렌더러·오류 형과 공개 Roll 표현의 경계를 소유합니다.

## Conventions

- 내부 형은 본명을 유지하고 공개 표시용 Rolled 형은 재귀 고리 밖에서 감쌉니다. 공개 이름은 패키지 진입점에서 부여하여 순환 별칭을 피합니다.
- 형제 프랙탈의 형은 진입점의 type import로 가져와 런타임 순환을 만들지 않습니다.

## Boundaries

### Always do

- 라벨·오류·입력 틀의 공개 부품 props는 그룹 렌더러 props와 구별하여 요청하지 않은 오류 정보를 주입하지 않습니다.

- 공개 형 변경은 Roll 표현과 패키지 선언 시험을 함께 확인합니다.
- 작성 스키마 추론과 입력용 추론을 구분하여 virtual·union 내부 표현을 작성자에게 강요하지 않습니다.
- 노드 참조 부재와 값의 undefined·null을 구분하여 입력 구현에 불필요한 부재 검사를 퍼뜨리지 않습니다.

### Ask first

- 공개 형의 이름·모양·nullable 추론을 바꾸는 경우.
- 새 스키마 범주나 런타임 값을 추가하는 경우.

### Never do

- 형제 프랙탈의 내부 파일을 직접 가져오지 않습니다.
- 입력 구현이나 검증 실행 로직을 형 경계에 두지 않습니다.
- 정적으로 알 수 없는 실행 결과를 추론의 보증으로 내세우지 않습니다.
