# settle 계약

## Requirements

- S2의 커밋 방문자는 변경·진입·상태·경로·감시·대기 사건 후보를 합친 집합의 각 노드에서 종류 불일치와 Refresh, 전역 상태 증감, 배달 차이, 비트별 개정을 한 번 처리합니다. 이탈 하위 트리의 정리는 별도 생명주기 작업입니다. 전역 증감은 기존 이탈→진입→변경→상태→로드 순서의 키 삽입 순서를 보존하여 합산하고 배달 전에 공표합니다. `UpdateGlobalState`는 최외곽 진입 끝에 한 번이며 진단·커밋 번호와 사건 이름은 유지합니다(SETTLE-006, EVENT-007·024·062, 43C-01, 65C-03).


- 기능 통과는 청사진의 기능 정적 색인과 이번 재계산(변경·상태 dirty) 목록의 교집합만 방문합니다. 기능 선언이 없으면 방문은 0입니다. 이후 단계가 새 기능 통과를 더할 때에도 정적 색인을 두며, 전체 범위 방문이 필요하면 정적으로 범위를 알 수 없는 이유를 이 DETAIL에 명시합니다. 방문 순서가 관측 결과에 드는 통과는 SETTLE-006 순서를 유지합니다(65C-02, SETTLE-017).

- 의존 방향은 `blueprint < record < {behaviors, navigation} < validation < settle/derive < settle < dispatch < SchemaNode`입니다. settle의 라운드 실행기와 커밋은 derive 진입점만 소비하고, derive는 settle의 쓰기·전이·커밋 및 `settle/type.ts`를 가져오지 않습니다(NODE-016·045, LANDING-083·084). 살아 있는 노드의 계산은 `node.behavior`를 호출하고 형상 밖 값의 정적 해석과 빈 값 판정은 behaviors 진입점을 소비합니다. `SchemaNode`·`dispatch`는 import하지 않고 `validation` 진입점의 동기 가드 읽기만 소비합니다(VALIDATE-015·044, NODE-016, NODE-006, WRITE-082·098, VALUE-034).
- 정착의 내부 organ을 외부 소비자가 직접 가져오지 않으므로 경계 예외는 없습니다(NODE-016).
- 한 진입은 동기적으로 표시 → 계산(호스트 바퀴) → 파생(쓰기가 나오면 표시로) → 전이(쓰기가 나오면 표시로) → 커밋합니다. 전이가 재계산을 부른 뒤에도 파생을 다시 판정하며, 적용 쓰기가 있는 파생 라운드는 한 정착 전체에서 전이 뒤에도 이어 세고 상한은 25입니다(SETTLE-002–006·017, EVENT-020, LANDING-063).

## API Contracts

- 정착·자식 선택·제어 선언·배달의 배열 순회는 인덱스 `for`/`while`, 순서 집합과 맵은 `for...of`를 사용합니다. 게이트는 첫 거절에서 멈추며 선언/깊이/배달 순서와 같은 값의 참조는 유지합니다. 동일 자료의 filter→map과 flat 중간 배열을 제거해 O(N) 시간의 상수를 줄이고 임시 O(N) 메모리를 절감합니다. 정적 shape 검증은 완전 일치 확인 뒤 계산을 시작하므로 두 루프를 유지합니다(87라운드 원칙 3).

- 최초 루트 load에서 입력·기존 커밋·게이트·식·controls·가상 노드·배열·컨테이너 기본값이 없고 모든 잎 기본값이 스칼라인 정적 객체 트리는 형상 계산 중 출력 조립을 후위 목록에 보류합니다. 전이의 기존 깊이별 기본값 쓰기를 마친 뒤 그 목록을 한 번 조립합니다. 기본값 쓰기 순서·생김 순서·최종 값·오류·커밋은 그대로이며 생성이 끝나기 전에 전부 확정됩니다. 조건 밖 입력은 일반 계산을 사용합니다. 시간은 중복 compute/assemble·재계산 등록 O(N+D)를 줄이고, 최초 로드 동안 O(N) 후위 참조 목록 및 청사진당 boolean 약한 메모를 더합니다(86C-02 v, GOAL-071, SETTLE-006·017).

- 게이트 없는 청사진의 선언 선택은 불변 선언 배열을 공유하며 커밋마다 발생 경로별 색인을 복제하지 않습니다. 현재 계산의 선택이 우선이고, 게이트가 있는 트리는 기존 커밋 경로 색인과 이탈 선택을 유지합니다. 제어 읽기는 선언 배열 identity별 ID 메모를 사용합니다. 정적 커밋의 O(발생 수 × 경로 깊이) 색인 작업·메모리를 제거하고 O(사용된 선언 수)의 약한 캐시를 둡니다(86C-02 ii, NODE-006, SETTLE-017).

- 정적 자식 선택은 빈 pending exit·latent 저장소를 조회하기 위한 경로 직렬화를 하지 않습니다. 이미 같은 선언 ID 참조를 선택했으면 재등록하지 않으며 모든 노드 생성·생김 기록·원본 분배는 유지합니다. 속도는 빈 조회와 문자열 생성 횟수만큼 개선하며 새 영구 메모리는 없습니다(86C-02 i, NODE-006, GOAL-011).
- 커밋 배달은 automatic 작업 색인·순서 집합·소멸 방문 집합을 같은 형태로 생성합니다. automatic 색인은 중간 map 배열 없이 한 루프로 채웁니다. 빈 커밋은 조건부 방식보다 Set 최대 세 개와 빈 배열 한 개를 더 사용하지만 per-node optional 분기와 순서 집합의 두 형태를 없앱니다. 모든 영향 노드의 revision과 payload, 방문 순서는 유지합니다. 조건부 할당과 공유 빈 집합은 재측정에서 속도 이득을 입증하지 못해 채택하지 않습니다(87라운드, EVENT-001·007·024, SETTLE-006).

- dirty 경로는 일반 add/delete 색인으로 시작하고 게이트 없는 등록 경계에서 최초 descendant 순서를 유지한 직접 에지 색인으로 전환합니다. 이후 추가 시 아직 dirty가 아닌 조상까지만 닫고 직접 부모–자식 에지 하나씩 색인합니다. 실제 노드의 계산 완료가 자식 우선으로 소비하므로 생성 O(N), 잎 갱신 O(D), 색인 메모리 O(dirty 노드)이며 내부에서 만든 모든 조상을 다시 모든 접두에 색인하지 않습니다. 존재하지 않는 감시 경로가 남아 조상이 먼저 소비될 수 있어 등록의 조상 복구 루프는 유지합니다. 게이트가 있는 계산과 일반 DirtyPathSet 사용은 임의 add/delete 뒤 첫 살아 있는 descendant 순서를 보존하는 기존 색인을 씁니다(SETTLE-017·047, 82C-01).
- 전이 채움은 명시 raw와 기본값 부재를 먼저 제외하고 실제 기본값 후보에만 하위 원본 부재를 확인합니다. 내부 기본값 없는 N노드 트리의 채움 후보 탐색은 O(N), 추가 영구 메모리는 없으며 기존 부모 우선 채움과 잠복/자손 원본 보호는 유지합니다. 여러 층에 실제 branch 기본값이 있는 입력의 source 확인 비용은 별도입니다(SETTLE-004·005, 82C-01).

- 형상 불변 객체의 부분 합성도 배열과 같은 `hint.incremental` 계약으로 전체 동등 비교를 생략합니다. 행은 바뀐 자식의 값·키 존재를 검증하고 키 집합이 바뀐 경우 힌트를 켜지 않습니다. 정착은 재계산 자식만 `sameValue`로 비교하여 같은 내용의 새 하위 참조가 와도 부모의 기존 참조를 되살립니다. 비용은 힌트 객체 하나와 재계산 목록·실제 바뀐 하위 내용이며 직전 local 얕은 사본 밖 형제 전수 검사를 추가하지 않습니다(SETTLE-042·043, 65C-04, 82C-01).

- 비순환 청사진은 첫 확인 O(V+E)의 DFS 결과를 약한 캐시에 보관하여 각 생성의 재귀 조상 탐색을 O(1)로 생략합니다. 임시 DFS 메모리는 O(V), 보유 메모리는 청사진당 boolean 하나이며 순환 청사진은 기존 배열 에지 경계와 원본 판정을 유지합니다. 재계산 조상 확장은 호출당 방문 집합으로 중복을 차단하여 유일 경로·조상 수만큼만 확장하고 O(유일 경로 수)의 임시 메모리를 씁니다. 경로 문자열 해석과 dirty descendant 색인의 O(총 경로 segment 수) 비용은 별도입니다(SETTLE-017, BLUEPRINT-030, 82C-01).

- 역의존 owner와 호스트 게이트의 반복 중복 확인은 삽입 순서를 유지하는 Set으로 처리합니다. 등록·수집 시간은 선언/게이트 수에 선형이며 추가 메모리는 유일 owner/게이트 수에 비례합니다. 게이트의 평가 순서·횟수·고정 출발점은 바꾸지 않습니다(SETTLE-017·020·044·050, 82C-01).
- 전이 채움은 라운드 시작의 생김 집합을 깊이별 bucket으로 고정하여 부모 우선·같은 깊이 삽입 순서를 유지합니다. 정렬 대신 O(N+D) 시간·임시 메모리를 쓰며 라운드 중 생긴 노드는 다음 라운드에서 방문합니다(SETTLE-004·005, 82C-01).

- 커밋에서 변경된 객체 호스트의 유효 `required` 목록을 직접 자식의 필수 표시에 반영합니다. 필수 여부가 바뀐 자식은 값 변경 없이 `UpdateComputedProperties`를 받아 입력 선택과 DOM 표시를 갱신합니다. 형상을 고르는 데 `required`를 쓰지는 않습니다(LANDING-027·132, FRAGMENT-026). 검사는 변경된 호스트의 직접 자식에 한정되며 별도 영구 색인을 만들지 않습니다.

- 재생성 인계의 폐기는 옛 트리 전체에 폐기 표시를 하고 리스너·구독을 해제하며, 각 노드의 Refresh 번호와 상호작용 초기화 번호를 통지 없이 동기로 올립니다. 부모·자식·루트 참조는 끊지 않고 옛 참조의 읽기는 폐기 직전 마지막 커밋을 반환합니다. 입력 출처 표식이 있는 늦은 쓰기는 조용히 버리고 표식 없는 쓰기만 `DISPOSED_NODE_WRITE`로 던집니다. 검증기 등록 참조 수는 폐기가 아니라 옛 트리의 이펙트 정리에서 내립니다. 폐기 비용은 옛 트리의 노드·구독 수에 비례하며 일반 잎 쓰기에 전체 순회를 더하지 않습니다(WRITE-046·086, REACT-010·024, 69C-02).
- 폼 수준 reset 로드는 명령형 외부 오류와 검증 결과를 비웁니다. 바인딩이 소유한 `errors` 속성의 경로 키 재적용은 같은 reset 진입이 돌아오기 전에 끝나며, 트리 유지와 재생성 모두 같은 계약입니다(WRITE-045, 69C-03).

- 값·방출·유효 스키마·자식 형상·활성/제어 상태가 결정되는 자리, 경로 재부여 및 상호작용 초기화에서 해당 사건 종류의 첫 기준과 변경 비트를 레코드에 적습니다. 커밋은 기록된 종류만 비교하며 참조가 원래대로 돌아온 변화는 배달/개정에서 제외합니다. 배달 전 여러 커밋의 `previous` 연결과 커밋별 개정은 기존처럼 보존합니다. 기준 칸은 커밋에서 비우므로 변경 없는 노드의 11필드 스냅숏을 만들거나 갱신하지 않습니다(EVENT-007·024, SETTLE-006, VALUE-002, 65C-03).
- 감시의 영향 경로는 현장 기록과 기존 생김·소멸·`pathChanges` 사실에서 얻고, 조상 경로 중복 제거 뒤 정적 감시 색인의 affected 조회를 사용합니다. 감시 대상에서 마지막 값 비교와 경로 색인 갱신은 유지합니다. 이는 감시 없는 노드의 읽기를 다시 늘리지 않습니다(65C-02·03).


- `interpretSchemaNodeInput(template, input)`는 행의 정적 해석만 적용한 원본 트리를 돌려줍니다. dispatch는 배치 동사의 반환 슬롯에 이 함수를 사용하며 채움·파생·투영·생성은 하지 않습니다. 바뀐 하위 값이 있을 때만 그 조상 그릇을 복사하고 순환 입력은 재방문하지 않습니다. 비용은 반환 슬롯의 입력 트리 크기에 비례하며 첫 객체 템플릿에서 O(선언 자식 수)의 이름 색인을 약한 참조 캐시에 만들고 재사용합니다(EVENT-061, 62C-01).

- 진입점은 `writeSchemaNode<Self>(node: SchemaNodeRecord<Self>, input: unknown, kind: SchemaNodeWriteKind, option: SetValueOption): void`, `loadSchemaNodeAtMount<Self>(root: SchemaNodeRecord<Self>, value: unknown, option: SetValueOption): void`, `resetSchemaNodeForm<Self>(root: SchemaNodeRecord<Self>, value: unknown, option: SetValueOption): void`, `resetSchemaNodeSubtree<Self>(node: SchemaNodeRecord<Self>, option: SetValueOption): void`, `readSchemaNodeDefaultValue<Self>(node: SchemaNodeRecord<Self>): unknown`과 정착용 맥락 변경 함수를 이름으로 내보냅니다. `readSchemaNodeInactiveValues`·`readSchemaNodeTypeMismatch`·`readSchemaNodeTypeMismatches`·`readSchemaNodeWatchValues`도 노드 겉면에 이름으로 제공하여 각 게터가 내부 organ 없이 한 문장으로 위임하게 합니다. 각 읽기 함수는 살아 있는 참조에서는 런타임 값을, 떼어진 참조에서는 마지막 커밋의 동결 값을 읽는 해당 멤버의 계약을 따릅니다. `SchemaNode.setValue`·`resetSubtree`·바인딩 전용 `setContext`의 조율은 `dispatch` 진입을 경유하고, 그 진입이 이곳의 동기 정착 함수를 부릅니다(NODE-010·044, LANDING-064·084, WRITE-085, CONTROLS-032·080, SURFACE-055, 26C-01, 28C-03·07·08).
- 진입점은 `arrangeSchemaNodeItems(node, operation)`도 이름으로 내보냅니다. 배치 밖 배열 진입은 dispatch의 사슬 안에서 이 함수를 호출하여 행 계획을 적용하고 표시 → 계산 → 파생 → 전이 → 커밋을 동기적으로 한 번 돌립니다. 배치 안 동사는 정착을 호출하지 않고 표시된 원본 배열에 순수 계획을 적용하며 배치 끝 통째 쓰기 하나로 정착합니다. 커밋은 재인덱싱 경로 사실의 노드와 자손을 배달 후보에 넣어 `UpdatePath`의 `{ previous, current }`를 표시합니다(NODE-010·014, SURFACE-005, 33C-01, 35C-02, 36C-01, 62C-01, 실행 ADR D1·D4).
- `SchemaNodeWriteKind`는 `'input' | 'callerPartial' | 'callerReplace' | 'load' | 'automatic'`입니다. 마지막 종류는 채움·입력 마침 등 예약 층 쓰기이며, 기본 `setValue(V)`는 로드가 아닌 `callerReplace`입니다(VALUE-032, WRITE-096). 표시 단계가 종류·옵션·원래 쓰인 값을 기록하고, 정적 `schemaType`·`nullable`로 먼저 한 번 해석하며 쓴 노드와 역의존 조상을 재계산 목록에 넣습니다(WRITE-056·098, SETTLE-002·017).
- `setValue(V, Merge)`는 `callerPartial`이며 받은 키마다 살아 있는 자식 또는 형상 밖 자손의 종류별 잠복 원본에 부분 쓰기를 합니다. 형상 밖 호스트의 잘못된 종류 `raw`는 자손 잠복 잎에 방출 가능한 값을 쓴 호출자 부분 쓰기에서만 비우고, 살아 있는 호스트의 `raw`는 자식 방출이 실제 생길 때만 비웁니다. 빈 객체로 승격하거나 형제의 기본값을 채우지 않습니다(WRITE-013·079·090, VALUE-002·034·036, 26C-10, 26C-14).
- 통째 교체·로드에서 V에 없는 선언 자식은 없음으로 정하고(WRITE-091), 선언 밖 키는 `extras`에 보관합니다(WRITE-090).
- 배열 branch 호스트는 배열 입력을 길이만큼 자리별 아이템에 분배하고 청사진 없는 꼬리 값은 자리 순서의 `extras`에 보관합니다. `null`·수·평범한 객체 등 배열이 아닌 입력은 호스트 `raw`에 남습니다. 아이템 이름은 위치 문자열이고 통째 쓰기는 정착 안에서 이름을 바꾸지 않은 채 위치 i의 기존 노드와 키를 이어 쓰며, 새 꼬리만 만들고 남는 꼬리는 소멸시킵니다. 로드는 형상의 모든 아이템을 생김으로, 로드 아닌 통째 쓰기는 새 꼬리 아이템만 생김으로 판정해 없음인 자손에 채움을 적용합니다(NODE-021·051·052, VALUE-002, WRITE-007·090, LANDING-164·202).
- 가상 노드에 대한 호출자 쓰기는 참조 노드로 부채질합니다. `undefined`는 참조 노드마다 같은 쓰기 종류로 `undefined`를 쓰고, `fields` 수와 길이가 같은 배열은 원소를 순서대로 해당 참조 노드에 같은 종류로 씁니다(각 원소는 그 노드의 `interpret`를 거침). `null`·배열이 아닌 값·길이가 다른 배열은 호출자 오류로 정착 전에 `INVALID_VIRTUAL_NODE_VALUES` 코드의 `SchemaFormError`를 즉시 던지며 `path`와 `details`(기대 길이, 받은 값)를 담습니다. `onError` 보고는 진입 배선 단계가 더합니다(35C-01). 쓰기 종류는 호출자가 정한 그대로 참조 노드에 갑니다: `Merge`는 참조 노드마다 부분 쓰기, 옵션 없음·`Overwrite`는 참조 노드마다 통째 쓰기이며 어느 쪽도 기존 노드를 다시 채우지 않습니다(WRITE-090, 45C-01). 가상 노드 자신은 표시만 받고 값은 참조 노드에 삽니다. 자동 쓰기의 모양 분류(`writeShape`)는 그대로입니다(NODE-034, ERROR-195, 18C-21, 42C-02).
- 가상 노드의 `structure`는 `fields` 이름마다 실제 형제 노드를 가리키고, 자식 선택은 가상 노드 아래에 노드를 만들지 않습니다. 참조 노드의 값이 한 커밋에서 바뀌면 어느 길로 쓰였든 그 노드를 참조하는 가상 노드를 같은 정착의 재조립 대상에 넣습니다(NODE-034·054, 42C-02).
- 공개 옵션 `SetValueOption`은 `Overwrite`, `Merge`, `DisableAutomaticWrites`, `EnableAutomaticWrites`의 비트마스크입니다. 기본은 `Overwrite`; 억제는 호출 옵션이 Form 속성보다 우선하고 두 억제 비트가 함께 있으면 `DisableAutomaticWrites`가 이깁니다. 한 배치에 서로 다르면 억제가 이깁니다. 억제는 호출이 일으킨 채움·`derived`·`injectTo`·`unsetValue`·나감 비움을 막지만 받은 값과 투영은 막지 않고, 그 호출에서 소비한 에지를 뒤로 미루지 않습니다. 뒤이은 포커스 아웃 `trim`은 호출 비트가 아니라 Form 속성만 억제합니다. `resetInteraction`은 자동 쓰기가 아니어서 억제된 로드에서도 판정합니다(WRITE-015·097·100, SETTLE-028·048, CONTROLS-029, EVENT-012, 28C-04).
- 기존 `SetValueOption`의 `Overwrite`·`Merge` 비트 값은 레거시 소비자를 위해 유지하고 같은 enum에 억제용 새 비트 둘을 더합니다. 새 정착은 기존 비트 중 자기 계약에 든 네 선택만 해석합니다(WRITE-015, LANDING-159).
- 계산은 루트에서 한 번 내려가며 재계산 자식을 먼저 마칩니다. 각 호스트 바퀴는 `게이트 없는 조각 ∪ 상속 overlay`에서 시작하고 노드 게이트는 꺼진 채 시작합니다. 직전 커밋의 활성 집합은 평가 순서의 힌트에도 쓰지 않으며 청사진 전순서대로 모든 게이트를 매번 평가하고 가우스-자이델로 즉시 반영합니다. 상한은 `게이트 가진 조각 수 + 노드 게이트 수 + 1`입니다. 여러 조건(`if`·판별·active)을 가진 조각도 한 번만 세고 조각의 active를 노드 게이트로 다시 세지 않습니다. `controls.active`가 있는 `children` 항목은 대상 수와 무관하게 항목당 노드 게이트 하나로 셉니다. 분석별·호스트별 셈은 쓰기 사이에 재사용합니다(SETTLE-003·018·041·044·050, GOAL-050).
- 게이트를 가진 호스트의 자식 목록·출력은 완료한 자식 선택을 모아 게이트의 투영 값 읽기 직전 또는 자식 선택 끝에 한 번 갱신합니다. 하위 게이트가 미갱신 조상을 읽으면 자식을 바꾸기 전에 갱신해 같은 바퀴의 관측값(같은 바퀴에 들어온 사촌은 보이고 계산 중인 자식은 섞이지 않음)을 지킵니다(51C-01, NODE-026, SETTLE-017·045, 18C-15).
- 정착 도중 노드 객체의 읽기는 직전 커밋을 돌려주고, 바퀴 중간 상태는 관측 계약이 아닙니다. 게이트와 식의 입력만 정착 자신의 읽기 길로 같은 바퀴에 들어온 자식을 봅니다(VALUE-013, EVENT-061, 51C-01, 57C-01).
- 계산 끝에는 이번 최종 형상에서 노드 자신·부모의 `controls.children` 항목·직접 선언한 조각의 `controls`를 같은 층 해석으로 모읍니다. 표준 `readOnly`와 로컬 잠금(`readOnly`·`disabled`)은 OR, 로컬 표시(`visible`)는 AND로 결합하고 순서와 무관하게 레코드의 세 계산 필드에 씁니다. 상태 키 식이 던지면 그 선언은 없는 것으로 보며 커밋은 `degraded`·`cause: 'expression'`입니다. Form 속성의 전체 잠금은 렌더 계층에서 결합하고 코어 쓰기를 막지 않습니다(SETTLE-003, CONTROLS-042·045·046·073·082·083, ERROR-122·132).
- 게이트 없는 객체 호스트의 정적 자식 선택은 청사진 호스트별로 메모합니다. 선언 종류·순서·유효 스키마가 같은 완성된 발생은 같은 자식 참조와 선언 ID를 재사용하고 더러운 자식의 계산은 그대로 수행합니다. 처음 생성, 미완성 재귀 확장, 충돌, 가상 자식과 배열 호스트는 기존 선택 경로를 유지합니다. 약한 캐시의 비용은 정적 호스트의 선언 수와 살아 있는 발생 수에 비례하며 노드의 고정 필드를 늘리지 않습니다(NODE-006, SETTLE-003, 65C-01, I11 step 1).
- 청사진의 유한 선언에서 표준 `readOnly`와 `visible`·`readOnly`·`disabled` 제어(조각과 부모 `children` 항목 포함)가 하나도 없으면 상태 키 공표를 생략합니다. 이 판정만 청사진별 약한 캐시에 보관하며 노드별 기능 색인을 만들지 않습니다. 키가 선언된 청사진은 기존 후보·층 해석·실패 순서로 계산하고, 선언 없는 노드는 생성자의 `visible: true`, `readOnly: false`, `disabled: false`를 유지합니다(CONTROLS-045, NODE-006, 65C-01, I11 step 1).
- 게이트 입력은 투영 값과 `extras`이며 `@`와 식·`injectTo`의 `ctx.context`는 트리 런타임의 맥락 객체를 읽습니다. 투영에서 빠진 선언 자식은 원본·분배 입력을 읽지 않아 `undefined`이고, 선언 밖 경로 키만 `extras`에서 읽습니다(CONTROLS-080, 28C-03). 판별 게이트는 `./<propertyName>` 값이 `values`에 드는지 판정하고 분기 `controls.active`와 AND합니다. 노드·조각의 active는 `BlueprintExpression.evaluate`로 실제 평가합니다. `if`는 `validation` 진입점의 동기 가드로 평가하고 검증기가 없으면 조각을 끕니다. 가드 실패·던짐·boolean 아닌 값은 게이트 거짓과 `GUARD_FAILED` 기록이며, 식 실패는 `cause: 'expression'`입니다(VALIDATE-015·044·047, ERROR-041·133, TEST-069 (나), 26C-04).
- `BlueprintGate.evaluationReads`는 청사진의 정적 읽기 자리입니다. 정착은 노드 발생을 만들 때 실제 선언 호스트와 읽기 자리의 최저 공통 조상 L을 한 번 계산해 settle 소유 메모에 두며 바퀴마다 다시 계산하지 않습니다. 게이트를 L의 전순서에서 선언한 조각의 바로 뒤(그 조각의 노드 게이트 뒤)에 평가하고 옮긴 게이트끼리는 문서 순서를 지킵니다. 값이 바뀌면 L부터 선언 호스트까지 바퀴 안에서 재계산하며 그 비용은 호스트 바퀴 예산에 포함합니다. 두 번째 하강은 없습니다(SETTLE-045, 26C-04·07).
- 배열 아이템의 선언 경로에 있는 `*` 마디는 실제 색인 마디와 맞추고, 평가의 기준점은 해당 노드의 실제 경로입니다. 역의존 조회는 템플릿 소유자 경로를 변화한 아이템의 실제 색인으로 묶고 다른 아이템을 읽는 절대 경로는 배열 호스트 하위 트리 변화에 기대게 합니다. 게이트 등록과 자리 L, 파생 규칙의 원천·대상, 상태 키 층, 나감 정책 열쇠 및 `@` 맥락 소유자도 같은 실제 경로로 묶으며 청사진 템플릿과 식 컴파일 결과는 공유합니다(CONTROLS-080, SETTLE-017·045, BLUEPRINT-030, 35C-08, 실행 ADR D6).
- 활성 선언을 `mergeEffectiveSchema`로 합쳐 `EffectiveSchema { schema, typeConflict }`를 소비합니다. `selectNodeSchema`·`selectChildren`·`primeHost`의 런타임 병합은 청사진 결과가 보유한 `isAtomic`·`isTerminal`과 같은 함수 identity를 전달합니다. 게이트로 켜진 선언의 `options`·`presentation`도 같은 원자 판정을 받고, 판정을 주지 않은 core 호스트에는 렌더 계층의 암묵 판정이 없습니다(REACT-003, 69C-04). `typeConflict`가 참인 경우와, 정적 선언 없는 이름에서 fold가 다른 게이트 선언이 동시에 켜진 경우 모두 `SHARED_NODE_CONFLICT`이며 `cause: 'sharedConflict'`입니다. 충돌 중에도 형·nullable은 정적 선언의 값이고, 첫 전순서 종류만 형상에 둡니다(BLUEPRINT-041·044, 26C-05).
- 같은 이름의 다른 종류 선언은 같은 종류의 자식만 지우고 이어받습니다. 부모 원본의 한 경로에 어느 종류든 살아 있으면 그 값은 살아 있는 노드의 원본이므로 비활성 다른 종류 선언의 잠복 원본을 새로 만들지 않습니다. 다른 경로의 입력 쓰기나 게이트 전환처럼 그 경로를 덮지 않는 쓰기에서는 떠난 종류의 `(path, kind)` 잠복 원본을 보관하고 재진입 때 복원합니다. 통째 교체·로드는 루트든 하위 노드든 쓰기 범위 안의 모든 종류별 잠복 원본을 종류와 무관하게 지우며 V에 든 경로의 값만 그 경로의 새 원본입니다. 범위 밖의 잠복 원본은 그대로 남깁니다. V에 없는 경로는 잠복 원본까지 없고, 이후 다른 종류가 입력 게이트 전환으로 생길 때 이전 값은 돌아오지 않습니다. 형상 밖 경로를 덮는 쓰기는 청사진 전순서의 첫 종류에 값을 분배하고 같은 경로의 다른 종류 잠복 원본을 지웁니다. 경로를 덮지 않는 부분 쓰기는 다른 종류 잠복 원본을 보관합니다(26C-13, 26C-14, WRITE-085·094, NODE-043, WRITE-087, VALUE-006, 18C-64).
- 전이는 직전 커밋에 없던 최종 형상 노드의 없음인 값에 노드 자신의 `controls.default` > 부모 `controls.children` 항목의 `default` > 직접 선언한 조각의 `controls.default` > 유효 스키마의 표준 `default` 순으로 채웁니다. 같은 층은 전순서의 나중 선언이 이기고, 생긴 노드의 `unsetValue`가 참이면 채우지 않습니다(CONTROLS-073·077, FRAGMENT-050, SETTLE-004·005).
- 객체 호스트의 없음 판정은 자신의 `raw`·`extras`, 살아 있는 자손과 모든 종류의 잠복 자손을 함께 봅니다(WRITE-082, VALUE-037, 26C-14). 로드가 아닌 쓰기에서 비객체 원본을 든 객체 조상 아래의 자식은 새로 생겨도 채우지 않으며, 로드 아래에서는 편집용 채움을 유지합니다(WRITE-079·096). 이미 있던 노드는 새 조각만으로 채우지 않습니다(SETTLE-005, FRAGMENT-050).
- 나감 정책 `unsetOnInactive`는 노드 자신 > 부모 `controls.children` 항목 > 직접 선언한 조각의 `controls` > Form 속성 순으로 정하고 같은 층에 유지가 하나라도 있으면 유지합니다. 걸리는 선언과 식 값은 노드가 형상에 있던 직전 커밋에서 읽으며 형상 밖에서 새로 평가하지 않습니다. 던진 식의 선언은 유지로 세고 그 식을 평가한 정착은 `degraded`·`cause: 'expression'`이며 사슬 끝에 `EXPRESSION_THREW`를 던집니다(WRITE-031·032·038, CONTROLS-024·040, ERROR-122·125·126·132, 28C-05).

- 들어오는 자식의 입력은 이번 정착에서 호스트가 분배한 해당 키 값, 자기 `(경로, 종류)` 잠복 원본, 없음 순으로 정합니다. 부분 쓰기가 잠복 원본 위에 겹치면 먼저 그 노드 상태를 복원합니다. 호스트가 이전에 받은 객체의 키 값은 들어오는 자식의 입력이 아니다(VALUE-002·004·025, SETTLE-005, 26C-13).
- 형상 밖 객체 값은 선언의 전순서 첫 종류를 따라 노드별 잠복 원본으로 분배하고, 같은 경로의 다른 종류 잠복 원본은 지웁니다. 호스트 잠복 원본은 자신의 비객체 `raw`와 선언 밖 `extras`만 함께 보관하며 빈 호스트는 항목이 없습니다(26C-13, 26C-14, SETTLE-029, VALUE-002). 열거는 종류가 아닌 경로마다 한 항목입니다. 같은 경로에 서로 다른 종류의 잠복 키가 있으면 전순서상 가장 앞선 종류의 값만 열거합니다. 살아 있는 경로는 그 경로의 잠복 항목만 숨기고 형상 밖 자손은 계속 열거합니다. 경로가 형상을 떠나면 다시 열거합니다. 처음부터 비활성인 branch의 로드 값도 펼쳐 열거하고 재진입 때 복원합니다. 변경 없는 항목·배열은 참조를 재사용하며, 잠복 값과 형상 가시성이 그대로인 정착은 열거를 건너뜁니다(26C-13, NODE-043, WRITE-087, VALUE-029, VALUE-006, 18C-64, SETTLE-029·047).
- 최종 형상에서 나가거나 소멸한 노드와 그 당시 형상에 있던 모든 자손은 함께 떼어집니다. 정착 중 임시 나감은 분리를 보류하며 재진입하면 이미 만든 동일 노드를 붙입니다. 최종 형상 확정 뒤 `typeMismatch`·`typeMismatches`·`inactiveValues`·`defaultValue`와 로컬 `visible`·`readOnly`·`disabled`를 마지막 커밋 값으로 보존하고 `active`를 거짓으로 바꾸며 게이트 등록을 해제합니다. `diagnostics`는 살아 있는 트리에서 계속 읽습니다. 떼어진 참조의 쓰기는 정착·통지 없이 자신과 하위 선언의 노드별 잠복 원본을 고칩니다. 자기 종류를 쓰고 같은 경로의 다른 종류 잠복 원본을 지웁니다(26C-10·14, NODE-044, 28C-02, 35C-09). 단, 같은 `(path, kind)`가 현재 형상에 살아 있으면 옛 참조의 `setValue`·`Merge`·`resetSubtree`는 오류 없이 아무 효과도 내지 않고 잠복 원본도 만들지 않습니다. 그 경로가 다시 형상에서 나가면 옛 참조들은 같은 잠복 원본을 다시 쓸 수 있습니다. 살아 있는 경로 확인은 기존 경로 색인을 우선 사용하며 일반 살아 있는 쓰기에 할당을 더하지 않습니다. 전체 교체는 그 경로의 기존 잠복 자손을 지운 뒤 새 값을 노드별로 분배하고, `Merge`는 받은 키마다 자손 잠복 원본에 부분 쓰기를 하며 비객체 값은 해당 위치를 통째로 교체합니다(WRITE-079·087, NODE-043·044, SETTLE-010, ERROR-131, SURFACE-007, 26C-08·10·12·14).
- 비활성 배열 호스트의 잠복 원본은 아이템별 항목이 아니라 배열 전체를 호스트 자신의 얼린 `raw` 하나로 보관하며 `inactiveValues`에는 호스트 경로 항목 하나만 냅니다. 그 배열은 나가기 직전의 원본 트리입니다: 잎·터미널 아이템은 자기 `raw`, 배열 아이템은 자리 수 N 그대로의 배열(각 자리는 그 자리의 원본 트리, 원본이 없는 자리만 `undefined`, N = 0이면 `[]`)이고 배열 전체를 `undefined`로 접지 않습니다. 객체 아이템은 원본 트리가 `undefined`가 아닌 키만 모은 객체와 `extras`이며 그런 키가 없으면 `undefined`입니다(`{}`가 아님). 청사진 없는 자리는 그 `extras` 값입니다. 방출용 빈자리 채움(`{}`·`[]`·`null`)은 데이터가 아니라 얼리지 않습니다. 호스트 경로 아래에 이미 있던 `(path, kind)` 잠복 항목은 각 자리의 원본 트리에 접어 넣고 따로 두지 않습니다. 다시 활성화되면 그 원본 트리를 생김 입력으로 새 키의 아이템을 만들고 원본이 `undefined`인 곳에만 쓰기 종류에 맞는 채움을 적용합니다(SETTLE-029, VALUE-002·029, NODE-044, WRITE-007, 26C-13, 35C-10, 38C-02, 47C-01).
- 살아 있는 아이템이 없는 자리의 `update(i, v)`가 호스트를 다시 쓸 때도 같은 원본 트리 읽기를 쓰므로 다른 아이템의 자리 수·키·스냅숏 자리가 그대로 남습니다(35C-06, WRITE-007, NODE-051, 47C-01).
- 잘못된 종류의 `raw`를 든 호스트(객체 호스트의 비객체, 배열 호스트의 비배열)는 그 `raw`를 받은 그대로 방출합니다. 배열 호스트는 그때 아이템이 없습니다(기존 아이템은 소멸). 루트도 같아서 잘못된 종류의 `raw`를 든 루트는 그 `raw`를 방출하고, 방출이 없을 때만 루트 종류의 빈 그릇(`{}`·`[]`)을 냅니다(VALUE-033·034, WRITE-013, 38C-01, 39C-01).
- `TYPE_MISMATCH` 기록은 `{ level: 'warning', code, path, expected: { schemaType, nullable, effective }, received, reason, candidates?, source }`이며 꺼짐→켜짐·재생김·로드·게이트 좁힘에서 한 번 보냅니다. 켜진 채 다른 어긋난 값이 와도 반복하지 않습니다. 채움으로 들어온 원본의 `source`는 로드 도중에도 `'fill'`이고 직접 로드된 원본은 `'load'`입니다. 게이트만 경고등을 켜면 `'gate'`, 직접 쓴 원본은 입력 종류를 유지합니다. 로드 범위의 노드는 원본이 같아도 Refresh를 받습니다. 그 범위 밖을 포함한 비로드 쓰기는 원본이 실제 바뀐 노드 중 입력 출처로 쓴 자신만 제외하여 Refresh 대상을 모으고, `setValue(getValue())`의 대상은 비어 있습니다(VALUE-037, EVENT-039·071, SETTLE-049, 26C-03, 72C-01).
- 로드는 마운트·폼 reset·`resetSubtree`뿐입니다. 루트 `loadSnapshot`은 로드한 경로 P를 `setIn(snapshot, P, V)`로 갱신하고 `defaultValue`는 `getIn(snapshot, node.path)`입니다. `resetSubtree`에서 P의 값이 `sameValue`로 같으면 스냅숏 참조를 유지합니다. 폼 수준 로드는 에지·생김 기준과 진단을 비우며, `resetSubtree`는 하위 트리만 새 수명으로 보아 채움·비움 범위를 제한합니다. 일반 쓰기는 `setValue(V)`도 직전 커밋을 기준으로 삼습니다(WRITE-085·090, SETTLE-048·049, ERROR-204).
- 맥락 변경은 로드가 아니며 `SchemaNode/`의 바인딩 전용 `setContext`가 settle 진입 함수를 부릅니다. 맥락 객체가 `sameValue`로 같으면 참조와 커밋을 그대로 두고, 다르면 런타임 칸을 바꾼 뒤 `@` 소유자와 조상만 재계산 목록에 넣어 한 정착을 돕니다. `@`를 읽는 게이트·상태 키는 다시 판정하고 `derived`·`unsetValue`·`resetInteraction`에는 직전 커밋 기준의 에지를 내며 원천 방출 값이 그대로인 `injectTo`에는 내지 않습니다. 통로는 옵션을 받지 않아 Form 속성 `disableAutomaticWrites`가 자동 쓰기의 기본값입니다(CONTROLS-080, SURFACE-055, WRITE-015, SETTLE-043·048, NODE-010, 28C-03·08).
- 로드의 상호작용 상태는 쓰기 전에 비우되 경고등 경로 비움과 스냅숏 교체는 계산 뒤·커밋 직전에 합니다. 떼어지는 노드는 직전 커밋 값을 갈무리합니다(26C-10). 로드 커밋에서 해당 범위의 경고등을 다시 계산하며 `resetSubtree`는 형제의 상태·경고등·진단을 바꾸지 않습니다(WRITE-085, VALUE-030, EVENT-072).
- 로드 범위 밖에서 나간 노드는 로드가 아닌 정착과 같은 나감 규칙(정책·억제·원본 B)으로 자기 잠복 원본을 갈무리합니다. `resetSubtree()`의 로드 규칙은 그 하위 트리에만 적용되므로 범위 밖 원본은 형상을 떠나도 남습니다(EVENT-072, NODE-044, VALUE-006).
- 잎 입력은 재계산 목록·자동 쓰기 로그만 순회합니다. 로드와 전체 교체 쓰기만 쓰기가 닿은 하위 트리를 한 번 순회할 수 있습니다. 나감·채움에 꼭 필요한 하위 선언 순회는 해당 범위로 제한합니다. 게이트 없는 평면 객체의 초기 로드에서 선언·입력·활성 자식의 총 처리량은 자식 수에 비례하며 자식마다 전체 선언이나 이미 모은 키를 다시 검색하지 않습니다(SETTLE-017·047, GOAL-050).
- 한 트리의 `SettlementScratch<Self>`는 런타임의 선택적 슬롯에서 지연 생성하고, 비점유 때만 다음 쓰기에 재사용합니다. 작업 컨테이너는 분배 입력과 잘못된 종류의 호스트 후보를 별도로 보관합니다. 중첩 쓰기는 별도 컨테이너를 쓰며, 성공·throw 모두 `finally`에서 노드 참조와 작업 항목을 비운 뒤 점유를 해제합니다. 객체 호스트 입력 쓰기는 전체 교체처럼 살아 있는 자식과 형상 밖 선언에 분배합니다. 일반 입력 쓰기마다 새 작업 컨테이너를 만들지 않습니다(SETTLE-047, NODE-045).
- 모든 정착 오류는 종류와 무관하게 발생 순서의 실패 목록에 보존합니다. 게이트·공유 충돌·예산·주입 대상·쓰기 모양·파생·상태 키·상호작용 초기화·나감 정책의 오류가 모두 포함됩니다. 같은 게이트와 호스트, 같은 충돌 위치나 규칙 발생의 재계산은 한 정착에서 한 실패로 세며 다음 쓰기에서는 다시 수집합니다. 각 실패를 열린 디스패치 사슬의 오류와 기록 발생에 한 번씩 넘기고 커밋 뒤 다시 던지지 않습니다. 사슬 밖 직접 호출은 하나를 그대로, 여럿을 `MULTIPLE_ERRORS`의 `details.errors`로 발생 순서대로 묶어 던집니다. 진단 `cause`는 첫 실패의 원인이며 예산 초과가 뒤따라도 바꾸지 않습니다. 예산 초과 여부는 별도로 유지하여 계산 뒤 진행을 막고 원본 B를 복원하되 앞의 실패들을 버리지 않습니다. 개발 모드 `mountingGuardPass`는 게이트 실패 없이 가드의 `sink` 기록만 남기며, 가드 기록은 폼당 가드 하나에 한 번이라는 기존 규칙을 유지합니다(TEST-069, ERROR-004·005·034·041·070, 58C-01).
- 파생 판정은 개발 모드(`process.env.NODE_ENV !== 'production'`)에서만 규칙별 기록 항목을 만들고 실행기는 진입 API·옵션 비트·라운드별 결과·예산 초과의 마지막 라운드를 모읍니다. 커밋은 그 정착의 기록 하나로 런타임 칸을 바꾸며 프로덕션에는 항목도 칸도 만들지 않고 콘솔·`onError`로 보내지 않습니다(ERROR-030·159, NODE-045, 28C-01).

- 전이 중 잠복 원본의 변경은 건드린 키의 직전 존재 여부와 값만 기록하고 메타데이터는 유지합니다. 잠복 맵이 바뀌면 자손 접두 메모를 무효화합니다. 원본 B를 만들 때 노드 자동 쓰기 로그 뒤에 이 기록을 되돌리고, 최종 형상에서 사라진 중간 채움을 회수한 뒤 형상을 다시 계산합니다. 종료한 선언의 잠복 자손은 해당 청사진 하위 경로만 방문합니다(SETTLE-005·011·047, WRITE-034).

## Acceptance Criteria

### settle-disposal — 재생성 트리의 폐기

- 인계된 옛 트리는 통지 없이 두 번호가 동기로 오르고 리스너가 해제됩니다. 참조 연결과 마지막 커밋 읽기를 유지하며, 입력 출처 표식이 있는 늦은 쓰기만 조용히 버리고 나머지는 `DISPOSED_NODE_WRITE`로 거부합니다(WRITE-046·086, 69C-02).

### settle-form-reset-errors — 폼 로드의 오류 초기화

- 같은 트리와 재생성 트리의 reset 모두 명령형 외부 오류·검증 결과를 비우고, 호출이 돌아오기 전에 바인딩이 경로 키 `errors`를 재적용합니다(WRITE-045, 69C-03).

### settle-runtime-predicates — 런타임 병합의 판정 정체성

- 게이트 선언의 React 요소와 ref 모양은 청사진에 전달한 원자 판정대로 병합되고, 판정 없는 core 호스트의 병합 계약은 유지됩니다(REACT-003, 69C-04).

### settle-array-integration — 배열 소멸과 기록 저장소

- 오류 맵을 제거하기 전에 마지막 합쳐진 오류 읽기를 떼어진 노드의 약한 참조 읽기 묶음으로 보존합니다. 비용은 소멸 노드당 배열 참조 하나이며, 배열 합치기는 기존 오류 읽기 메모를 재사용합니다(NODE-044, 35C-09).

- 소멸 아이템과 자손은 전역 상태 셈·배달/감시·오류/대상 대기 저장소에서 제거됩니다. 경고 구조 키는 현재 경로를 따르고 기록 객체는 당시 경로를 유지합니다. 값·계산 상태 변화가 없는 경로 사실도 아이템과 자손의 배달 후보가 됩니다. 같은 없는 대상을 겨눈 배열 아이템마다 출처 경로를 담은 오류를 하나씩 발생 순서대로 묶습니다(35C-02·09, 43C-01, 58C-01, 59C-01).

### settle-failure-identity — 오류 발생 식별자

- 실패 중복 키는 한 정착의 발생 식별자이며, 대상 경로가 원천과 다른 파생 실패는 종류·원천 경로·대상 경로·규칙 스키마 경로를 함께 구별합니다. 같은 규칙을 공유하는 서로 다른 원천이 같은 대상에서 실패해도 별개 오류로 보존합니다(ERROR-004, 58C-01).
- 자동 쓰기의 `INJECT_TARGET_MISSING`·`INVALID_VIRTUAL_NODE_VALUES`는 오류 생성 시 `details.sourcePath`에 `controls.injectTo` 선언 노드의 데이터 경로를 넣고 `details.path`는 대상 경로로 유지합니다. 쓰기 모양 오류의 기대 길이·받은 값도 유지하며, 사슬 끝 기록은 같은 상세 참조를 전달합니다. 호출자 경로의 쓰기 모양 오류에는 원천 경로를 더하지 않습니다(ERROR-017·195, 59C-01).

### settle-gates — 평가와 위치

- 판별·노드/조각 active는 실제로 평가하고 `if`는 검증기 계약의 동기 가드로 판정합니다. 시험 전용 술어 대역 없이 L로 옮긴 게이트의 사촌·루트 읽기와 순환은 고정 출발점에서 같은 형상을 냅니다(VALIDATE-015·044, TEST-069 (나), SETTLE-045, 26C-04).

### settle-budget — 원본 B와 진단

- 호스트·파생·전이 초과 및 재귀 무한 확장은 원본 B·`degraded`·해당 `exceededBudget`을 커밋한 뒤 오류를 던지고, 폼 수준 로드 전에는 진단이 유지됩니다. 파생은 적용 라운드 25를 한 정착에서 누적하고 초과하면 `exceededBudget: 'derive'`·`iterations: 25`입니다. 자기 노드의 존재를 부정하는 게이트가 한 호스트 계산에서 진동하면 전이 중이라도 `hostWheel` 초과이며, 채움·비움이 서로 다른 게이트를 전이 상한보다 많은 라운드에 걸쳐 뒤집을 때만 `transition` 초과입니다. 같은 최종 형상에 이르는 로드는 입력 키 유무와 관계없이 같은 진단 상태입니다(SETTLE-003·005·011·017·022·029, EVENT-020, ERROR-070·132·190·204, TEST-069, 26C-11). 식이나 가드가 던져도 정착은 자리마다 정의된 값으로 끝까지 가며 파생·채움·나감 비움을 이어 갑니다. 나감 비움을 빼는 것은 던져 거짓이 된 게이트로 나간 노드와 함께 나가는 하위 트리뿐이고, 자동 쓰기 전체를 빼는 것은 예산 초과뿐입니다(ERROR-121·122·125·126, SETTLE-011, WRITE-033, 29C-02).

### settle-derive — 파생 단계의 실행

- 파생은 계산 뒤·전이 앞에 돌고 쓰기가 나오면 표시로 돌아가며, 로드는 기준을 비워 발화하고 같은 값의 일반 쓰기는 발화하지 않습니다. 태어난 노드의 규칙은 원천 방출 값이 `undefined`여도 발화하고 채움 뒤 새 에지로 다시 발화합니다. `DisableAutomaticWrites`는 그 호출의 파생 쓰기를 막고 값 동등은 `sameValue` 하나로 판정합니다(SETTLE-004·005·043·046·048, WRITE-015·028·029, 18C-50, 29C-01).

### settle-state-keys — 상태 키의 결합

- `publishStateKeys`는 상태 dirty 목록에서 청사진이 로컬 상태 키를 선언한 노드와 조각·부모 children 층의 직접 자식 대상을 골라 계산합니다. 역의존/형상 변경 호스트의 자식 확장도 색인된 대상에 한정합니다. 결합 결과는 방문 순서와 무관하나 실패 수집 순서는 기존 후보 순서를 유지합니다. 게이트가 꺼져도 정적 대상은 남으므로 잠금·표시가 기본값으로 돌아갑니다. 선언이 없는 청사진은 후보·식 방문이 0입니다(CONTROLS-045·073·082·083, 65C-02).

- 잠금은 네 자리 가운데 하나라도 참이면 참, 표시는 모두 참이어야 참이고 선언 순서와 무관합니다. 잎 입력은 역의존 소유자·형상 변경 호스트에서만 자식으로 넓혀 계산하며, 떼어진 노드는 마지막 커밋의 상태 키를 유지합니다(CONTROLS-073·082·083, SETTLE-017, GOAL-011, NODE-044, 28C-02·07).

### settle-virtual — 가상 노드의 쓰기와 참조

- 호출자의 가상 노드 쓰기는 참조 노드로 나뉘고 틀린 모양은 즉시 던지며, 가상 노드의 자식은 실제 형제 노드이고 참조 노드가 바뀐 정착에서 가상 노드의 튜플이 다시 조립됩니다(NODE-034·054, ERROR-195, 42C-01·02).

### settle-context — 맥락 변경의 정착

- 같은 맥락 객체 또는 깊이 같은 새 객체는 정착도 참조 교체도 하지 않고, 바뀐 `@` 맥락은 소유자와 조상을 재계산하되 `injectTo`를 발화시키지 않습니다(CONTROLS-080, SURFACE-055, SETTLE-043·048, 28C-03·08).

### settle-write — 쓰기 범위

- 두 단계 해석·로드 스냅숏·`resetSubtree`·옵션 억제·Refresh 대상을 쓰기 종류와 범위에 맞게 확정하고 잎 입력은 트리 전체를 걷지 않습니다(WRITE-015·085·098·099, EVENT-071, SETTLE-047).

### settle-array — 배열 형상과 구조 정착

- 배열 아이템 에지는 재귀 조상 탐색을 끊습니다. 빈 아이템도 참조된 객체 필드와 빈 자식 배열을 만들며, 빈 배열에서는 아이템을 만들지 않습니다. 배열 에지 안쪽의 객체 프로퍼티 전용 순환 보호는 유지합니다(BLUEPRINT-030, 18C-01, LANDING-128).
- 통째 쓰기는 자리의 노드·키를 잇고 새 꼬리만 만들거나 남은 꼬리를 소멸시키며, 로드와 비로드의 생김·채움을 구분합니다. 구조 동사는 행 계획으로 경로 열쇠 저장소와 게이트 등록을 재배치하고 스냅숏 자리를 맞춘 뒤 한 번 정착하며, 원본 B는 자동 쓰기의 구조 로그를 역순으로 되돌리고 키 계수를 유지합니다. 아이템 선언은 실제 경로에 묶이고 비활성 배열 호스트의 잠복 원본은 전체 배열 하나입니다(NODE-051·052, WRITE-036·085·090·095·099, CONTROLS-080, 35C-02·05·08·09·10).

### settle-delivery — 변경 범위의 배달 표시

- 하위 트리 로드에서 발화한 주입 등 비로드 쓰기로 범위 밖 노드의 원본이 바뀌면 그 노드에도 `RequestRefresh`를 한 번 표시합니다. 범위 밖의 원본이 그대로인 노드는 표시하지 않으며, 로드 범위의 모든 노드는 값이 같아도 표시합니다. 비로드 쓰기에서는 입력 출처로 쓴 자신만 제외합니다(EVENT-039·071, SETTLE-049, 18C-94, 72C-01). 추가 비용은 변경 원본 경로의 범위 판정에 비례하며 기존 Refresh 대상 집합을 재사용하고 전체 트리 순회를 추가하지 않습니다.
- `markCommitDeliveries`의 후보별 감시 값 읽기는 배달 후보와 청사진 감시 선언 색인의 교집합에 한정합니다. 의존 경로·맥락·형상으로 추가된 기존 감시 역색인 후보도 포함하며, 비활성 감시 선언의 이전 값은 빈 값과 비교하여 배달합니다. 감시가 없는 후보는 공용 빈 값을 쓰고 감시 메모/역색인을 방문하지 않습니다. 감시 비교 자체는 순서와 무관하지만 사건 표시·개정과 배달 후보의 순서는 유지합니다(EVENT-007·024·064, SETTLE-006, 65C-02).
- 배달의 변경 판단(값·방출·감시 값 튜플의 원소)은 참조 동일성에 `NaN`을 `NaN`과 같게 보는 SameValueZero입니다(SETTLE-043, 66C-01). 그래서 `NaN`을 든 잎은 다시 계산되거나 계산 플래그 변경으로 후보가 되어도 `UpdateValue`를 받지 않고, `NaN`을 든 감시 튜플은 그대로이면 `UpdateComputedProperties`를 받지 않습니다. 깊은 비교는 되살림에서 한 번, 배달은 참조: 내용 비교(`sameValue`)는 커밋의 참조 되살림(SETTLE-043 (나))과 원본·입력 비교에만 쓰고, 배달·`onChange`·검증 요청·감시 간선은 참조로 비교합니다(67C-01).
- `commitGlobalState`는 정적 범위를 줄이지 않습니다. 모든 종류의 노드가 스키마 선언과 무관하게 `setState`·`setSubtreeState`로 임의 상호작용 상태 키를 받을 수 있고, 로드/초기화 및 형상 진입·이탈에서 참→거짓과 이전 참 노드의 제거도 셈해야 합니다. 따라서 현재 참 플래그나 `controls.resetInteraction` 선언은 EVENT-062의 정적 상한이 아니며, 가능한 정적 범위는 전체 노드입니다. 키별 증감 합산은 순서와 무관하나 전역 상태 확정→배달 표시 및 최외곽 진입당 `UpdateGlobalState` 한 번의 SETTLE-006·43C-01 순서는 유지합니다(65C-02).

- 소멸한 아이템과 자손의 직전 상호작용 상태를 전역 셈에서 빼고, 구조 연산의 새 아이템은 생김 집합으로 더합니다. 소멸 노드의 레코드 배달 기준·감시 역색인·대기 사건·검증/외부 오류 및 대상 집합은 노드 identity로 지웁니다. 재인덱싱은 identity 저장소를 유지하고 경고 데이터 경로 키를 옮기며 소멸 경로의 경고는 버립니다. 사슬에 이미 발생한 오류와 기록은 당시 경로를 유지하여 발생 순서를 보존합니다. 정리는 소멸 하위 트리의 노드 수에 비례하고 일반 잎 쓰기에는 저장소 전체 순회를 더하지 않습니다(35C-02·09, 43C-01, 58C-01).

- 관련 없는 한 잎 쓰기와 맥락 참조가 그대로인 커밋은 해당하지 않는 감시 노드의 감시 값을 다시 읽지 않습니다. `@` 감시는 마지막 배달에서 본 맥락 참조와 현재 참조가 다른 커밋에서만 후보가 되며, 의존 경로·맥락·형상 변경은 해당 감시 값과 `UpdateComputedProperties` 비트를 유지합니다(EVENT-064, CONTROLS-019, 28C-07, 44C-01).

- I9 경로 저장소는 생성 시점부터 명시적인 PathKeyedMap·PathKeyedSet 형이며 native Map·Set의 열거와 instanceof 동작을 유지합니다. 인스턴스 메서드 패치·약한 등록·첫 쓰기의 adoption 순회는 없습니다. exact·조상·숫자 자리 radix 색인은 set·add·delete·clear와 명시적 replaceEntries 일괄 이동에서 갱신합니다. 소멸·이동은 영향 prefix만 조회하고 규칙 원천·대상을 모두 색인합니다. 일괄 이동 동안 빈 prefix를 보류하여 살아남는 마디와 숫자 radix를 재사용하며 경로와 숫자 판정을 prefix별로 보관합니다. 메모리는 경로 깊이 D의 항목 K개에 O(KD) 키 참조와 유일한 prefix 문자열·부모 연결·숫자 radix 마디를 더합니다. 값은 복제하지 않습니다. 생성은 빈 색인 O(1), 새로운 키의 쓰기·삭제는 O(D) 색인 연산과 문자열 처리이며 기존 키 값 갱신은 O(1)입니다(SETTLE-017·047, GOAL-011, 49C-01).
- 배열 소멸은 직전 스냅숏 경로를, 이동은 previous·current 경로를 배달 감시 역색인에 넣습니다. 변경 자손의 조상을 생략해도 역색인 조회가 조상 감시를 포함하므로 배달을 잃지 않습니다. 조건 의존의 나감은 기존 전체 감시 갱신을 유지합니다. 관련 없는 watcher 수 W에 비례하는 배열 구조 배달 비용을 추가하지 않습니다(NODE-026, EVENT-064, 44C-01).
