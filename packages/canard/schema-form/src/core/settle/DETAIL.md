# settle 계약

## Requirements

- 의존 방향은 `blueprint < record < {behaviors, navigation} < validation < settle/derive < settle < dispatch < SchemaNode`입니다. settle의 라운드 실행기와 커밋은 derive 진입점만 소비하고, derive는 settle의 쓰기·전이·커밋 및 `settle/type.ts`를 가져오지 않습니다(NODE-016·045, LANDING-083·084). 살아 있는 노드의 계산은 `node.behavior`를 호출하고 형상 밖 값의 정적 해석과 빈 값 판정은 behaviors 진입점을 소비합니다. `SchemaNode`·`dispatch`는 import하지 않고 `validation` 진입점의 동기 가드 읽기만 소비합니다(VALIDATE-015·044, NODE-016, NODE-006, WRITE-082·098, VALUE-034).
- 정착의 내부 organ을 외부 소비자가 직접 가져오지 않으므로 경계 예외는 없습니다(NODE-016).
- 한 진입은 동기적으로 표시 → 계산(호스트 바퀴) → 파생(쓰기가 나오면 표시로) → 전이(쓰기가 나오면 표시로) → 커밋합니다. 전이가 재계산을 부른 뒤에도 파생을 다시 판정하며, 적용 쓰기가 있는 파생 라운드는 한 정착 전체에서 전이 뒤에도 이어 세고 상한은 25입니다(SETTLE-002–006·017, EVENT-020, LANDING-063).

## API Contracts

- 진입점은 `writeSchemaNode<Self>(node: SchemaNodeRecord<Self>, input: unknown, kind: SchemaNodeWriteKind, option: SetValueOption): void`, `loadSchemaNodeAtMount<Self>(root: SchemaNodeRecord<Self>, value: unknown, option: SetValueOption): void`, `resetSchemaNodeForm<Self>(root: SchemaNodeRecord<Self>, value: unknown, option: SetValueOption): void`, `resetSchemaNodeSubtree<Self>(node: SchemaNodeRecord<Self>, option: SetValueOption): void`, `readSchemaNodeDefaultValue<Self>(node: SchemaNodeRecord<Self>): unknown`과 정착용 맥락 변경 함수를 이름으로 내보냅니다. `readSchemaNodeInactiveValues`·`readSchemaNodeTypeMismatch`·`readSchemaNodeTypeMismatches`·`readSchemaNodeWatchValues`도 노드 겉면에 이름으로 제공하여 각 게터가 내부 organ 없이 한 문장으로 위임하게 합니다. 각 읽기 함수는 살아 있는 참조에서는 런타임 값을, 떼어진 참조에서는 마지막 커밋의 동결 값을 읽는 해당 멤버의 계약을 따릅니다. `SchemaNode.setValue`·`resetSubtree`·바인딩 전용 `setContext`의 조율은 `dispatch` 진입을 경유하고, 그 진입이 이곳의 동기 정착 함수를 부릅니다(NODE-010·044, LANDING-064·084, WRITE-085, CONTROLS-032·080, SURFACE-055, 26C-01, 28C-03·07·08).
- `SchemaNodeWriteKind`는 `'input' | 'callerPartial' | 'callerReplace' | 'load' | 'automatic'`입니다. 마지막 종류는 채움·입력 마침 등 예약 층 쓰기이며, 기본 `setValue(V)`는 로드가 아닌 `callerReplace`입니다(VALUE-032, WRITE-096). 표시 단계가 종류·옵션·원래 쓰인 값을 기록하고, 정적 `schemaType`·`nullable`로 먼저 한 번 해석하며 쓴 노드와 역의존 조상을 재계산 목록에 넣습니다(WRITE-056·098, SETTLE-002·017).
- `setValue(V, Merge)`는 `callerPartial`이며 받은 키마다 살아 있는 자식 또는 형상 밖 자손의 종류별 잠복 원본에 부분 쓰기를 합니다. 형상 밖 호스트의 잘못된 종류 `raw`는 자손 잠복 잎에 방출 가능한 값을 쓴 호출자 부분 쓰기에서만 비우고, 살아 있는 호스트의 `raw`는 자식 방출이 실제 생길 때만 비웁니다. 빈 객체로 승격하거나 형제의 기본값을 채우지 않습니다(WRITE-013·079·090, VALUE-002·034·036, 26C-10, 26C-14).
- 통째 교체·로드에서 V에 없는 선언 자식은 없음으로 정하고(WRITE-091), 선언 밖 키는 `extras`에 보관합니다(WRITE-090).
- 공개 옵션 `SetValueOption`은 `Overwrite`, `Merge`, `DisableAutomaticWrites`, `EnableAutomaticWrites`의 비트마스크입니다. 기본은 `Overwrite`; 억제는 호출 옵션이 Form 속성보다 우선하고 두 억제 비트가 함께 있으면 `DisableAutomaticWrites`가 이깁니다. 한 배치에 서로 다르면 억제가 이깁니다. 억제는 호출이 일으킨 채움·`derived`·`injectTo`·`unsetValue`·나감 비움을 막지만 받은 값과 투영은 막지 않고, 그 호출에서 소비한 에지를 뒤로 미루지 않습니다. 뒤이은 포커스 아웃 `trim`은 호출 비트가 아니라 Form 속성만 억제합니다. `resetInteraction`은 자동 쓰기가 아니어서 억제된 로드에서도 판정합니다(WRITE-015·097·100, SETTLE-028·048, CONTROLS-029, EVENT-012, 28C-04).
- 기존 `SetValueOption`의 `Overwrite`·`Merge` 비트 값은 레거시 소비자를 위해 유지하고 같은 enum에 억제용 새 비트 둘을 더합니다. 새 정착은 기존 비트 중 자기 계약에 든 네 선택만 해석합니다(WRITE-015, LANDING-159).
- 계산은 루트에서 한 번 내려가며 재계산 자식을 먼저 마칩니다. 각 호스트 바퀴는 `게이트 없는 조각 ∪ 상속 overlay`에서 시작하고 노드 게이트는 꺼진 채 시작합니다. 직전 커밋의 활성 집합은 평가 순서의 힌트에도 쓰지 않으며 청사진 전순서대로 모든 게이트를 매번 평가하고 가우스-자이델로 즉시 반영합니다. 상한은 `게이트 가진 조각 수 + 노드 게이트 수 + 1`입니다. 여러 조건(`if`·판별·active)을 가진 조각도 한 번만 세고 조각의 active를 노드 게이트로 다시 세지 않습니다. `controls.active`가 있는 `children` 항목은 대상 수와 무관하게 항목당 노드 게이트 하나로 셉니다. 분석별·호스트별 셈은 쓰기 사이에 재사용합니다(SETTLE-003·018·041·044·050, GOAL-050).
- 계산 끝에는 이번 최종 형상에서 노드 자신·부모의 `controls.children` 항목·직접 선언한 조각의 `controls`를 같은 층 해석으로 모읍니다. 표준 `readOnly`와 로컬 잠금(`readOnly`·`disabled`)은 OR, 로컬 표시(`visible`)는 AND로 결합하고 순서와 무관하게 레코드의 세 계산 필드에 씁니다. 상태 키 식이 던지면 그 선언은 없는 것으로 보며 커밋은 `degraded`·`cause: 'expression'`입니다. Form 속성의 전체 잠금은 렌더 계층에서 결합하고 코어 쓰기를 막지 않습니다(SETTLE-003, CONTROLS-042·045·046·073·082·083, ERROR-122·132).
- 게이트 입력은 투영 값과 `extras`이며 `@`와 식·`injectTo`의 `ctx.context`는 트리 런타임의 맥락 객체를 읽습니다. 투영에서 빠진 선언 자식은 원본·분배 입력을 읽지 않아 `undefined`이고, 선언 밖 경로 키만 `extras`에서 읽습니다(CONTROLS-080, 28C-03). 판별 게이트는 `./<propertyName>` 값이 `values`에 드는지 판정하고 분기 `controls.active`와 AND합니다. 노드·조각의 active는 `BlueprintExpression.evaluate`로 실제 평가합니다. `if`는 `validation` 진입점의 동기 가드로 평가하고 검증기가 없으면 조각을 끕니다. 가드 실패·던짐·boolean 아닌 값은 게이트 거짓과 `GUARD_FAILED` 기록이며, 식 실패는 `cause: 'expression'`입니다(VALIDATE-015·044·047, ERROR-041·133, TEST-069 (나), 26C-04).
- `BlueprintGate.evaluationReads`는 청사진의 정적 읽기 자리입니다. 정착은 노드 발생을 만들 때 실제 선언 호스트와 읽기 자리의 최저 공통 조상 L을 한 번 계산해 settle 소유 메모에 두며 바퀴마다 다시 계산하지 않습니다. 게이트를 L의 전순서에서 선언한 조각의 바로 뒤(그 조각의 노드 게이트 뒤)에 평가하고 옮긴 게이트끼리는 문서 순서를 지킵니다. 값이 바뀌면 L부터 선언 호스트까지 바퀴 안에서 재계산하며 그 비용은 호스트 바퀴 예산에 포함합니다. 두 번째 하강은 없습니다(SETTLE-045, 26C-04·07).
- 활성 선언을 `mergeEffectiveSchema`로 합쳐 `EffectiveSchema { schema, typeConflict }`를 소비합니다. `typeConflict`가 참인 경우와, 정적 선언 없는 이름에서 fold가 다른 게이트 선언이 동시에 켜진 경우 모두 `SHARED_NODE_CONFLICT`이며 `cause: 'sharedConflict'`입니다. 충돌 중에도 형·nullable은 정적 선언의 값이고, 첫 전순서 종류만 형상에 둡니다(BLUEPRINT-041·044, 26C-05).
- 같은 이름의 다른 종류 선언은 같은 종류의 자식만 지우고 이어받습니다. 부모 원본의 한 경로에 어느 종류든 살아 있으면 그 값은 살아 있는 노드의 원본이므로 비활성 다른 종류 선언의 잠복 원본을 새로 만들지 않습니다. 다른 경로의 입력 쓰기나 게이트 전환처럼 그 경로를 덮지 않는 쓰기에서는 떠난 종류의 `(path, kind)` 잠복 원본을 보관하고 재진입 때 복원합니다. 통째 교체·로드는 루트든 하위 노드든 쓰기 범위 안의 모든 종류별 잠복 원본을 종류와 무관하게 지우며 V에 든 경로의 값만 그 경로의 새 원본입니다. 범위 밖의 잠복 원본은 그대로 남깁니다. V에 없는 경로는 잠복 원본까지 없고, 이후 다른 종류가 입력 게이트 전환으로 생길 때 이전 값은 돌아오지 않습니다. 형상 밖 경로를 덮는 쓰기는 청사진 전순서의 첫 종류에 값을 분배하고 같은 경로의 다른 종류 잠복 원본을 지웁니다. 경로를 덮지 않는 부분 쓰기는 다른 종류 잠복 원본을 보관합니다(26C-13, 26C-14, WRITE-085·094, NODE-043, WRITE-087, VALUE-006, 18C-64).
- 전이는 직전 커밋에 없던 최종 형상 노드의 없음인 값에 노드 자신의 `controls.default` > 부모 `controls.children` 항목의 `default` > 직접 선언한 조각의 `controls.default` > 유효 스키마의 표준 `default` 순으로 채웁니다. 같은 층은 전순서의 나중 선언이 이기고, 생긴 노드의 `unsetValue`가 참이면 채우지 않습니다(CONTROLS-073·077, FRAGMENT-050, SETTLE-004·005).
- 객체 호스트의 없음 판정은 자신의 `raw`·`extras`, 살아 있는 자손과 모든 종류의 잠복 자손을 함께 봅니다(WRITE-082, VALUE-037, 26C-14). 로드가 아닌 쓰기에서 비객체 원본을 든 객체 조상 아래의 자식은 새로 생겨도 채우지 않으며, 로드 아래에서는 편집용 채움을 유지합니다(WRITE-079·096). 이미 있던 노드는 새 조각만으로 채우지 않습니다(SETTLE-005, FRAGMENT-050).
- 나감 정책 `unsetOnInactive`는 노드 자신 > 부모 `controls.children` 항목 > 직접 선언한 조각의 `controls` > Form 속성 순으로 정하고 같은 층에 유지가 하나라도 있으면 유지합니다. 걸리는 선언과 식 값은 노드가 형상에 있던 직전 커밋에서 읽으며 형상 밖에서 새로 평가하지 않습니다. 던진 식의 선언은 유지로 세고 그 식을 평가한 정착은 `degraded`·`cause: 'expression'`이며 사슬 끝에 `EXPRESSION_THREW`를 던집니다(WRITE-031·032·038, CONTROLS-024·040, ERROR-122·125·126·132, 28C-05).
- 노드는 직전 커밋 형상에 있고 최종 형상에 없을 때만 나가며, 중간 이탈 뒤 재진입하면 같은 노드를 유지합니다. 나가는 객체·분기의 정책은 함께 나가는 하위 트리와 잠복 자손으로 내려가고 자손의 명시 선언이 가까운 순서로 이깁니다. 노드가 남아도 선언한 조각이 꺼지는 선언의 나감을 사슬에 세며 이때 `extras`는 건드리지 않습니다. 최종 나감의 비움은 정책대로 `raw`와 `extras`를 함께 지우되 억제·원본 B 정착에서는 적용하지 않습니다(SETTLE-005·011, WRITE-015·032–035, LANDING-092).
- 최종 형상에서 사라진 중간 채움은 자손의 자동 쓰기와 잠복 원본 변경까지 회수합니다. 채움이나 좁혀진 유효 목록으로 원래 입력을 재해석한 쓰기가 게이트를 바꿀 때만 다음 전이 라운드를 세고, 각 노드는 한 정착에서 채움을 최대 한 번 받으며 같은 게이트의 재반전은 새 라운드를 만들지 않습니다. 호스트 바퀴 초과는 전이 중에도 즉시 독립된 예산 초과로 처리하며 전이 상한은 `게이트 가진 조각 수 + 노드 게이트 수 + 1`입니다(SETTLE-003·005·011·017·022·029·041, WRITE-098·099, 26C-11).
- 상한 초과 시 Source-B 되돌림 기록은 채움·`derived`·`injectTo`·`unsetValue`의 지움·나감 비움의 이전 `raw`·`extras`·분배 값을 보관합니다. 파생 쓰기를 먼저 되돌리고 중간 채움을 철회하며 채움 노드를 `writtenInputs`에서도 제거하여 원본 B에는 쓰기 경계의 정적 해석만 남깁니다. 그 원본으로 형상을 한 번 더 계산하며 또 초과하면 마지막 활성 집합을 고정합니다. 객체 자식의 생김·빠짐은 형상 재계산으로 판정하고, 배열 구조의 생성·폐기 로그는 PR-5에서 더합니다(SETTLE-011, WRITE-099, TEST-069).
- `diagnostics`는 `{ status: 'stable' | 'degraded', cause?: 'budget' | 'expression' | 'injectTarget' | 'writeShape' | 'sharedConflict', exceededBudget?: 'hostWheel' | 'derive' | 'transition' | 'recursion', iterations?: number, commit?: number }`입니다. 파생 상한 25를 넘기면 `degraded`·`cause: 'budget'`·`exceededBudget: 'derive'`·`iterations: 25`로 원본 B를 커밋합니다. 모든 칸은 `commit`의 커밋을 설명하며 최초 손상 커밋을 유지하고 폼 수준 로드에서만 `stable`로 초기화합니다(ERROR-070·130–133·190·195·204, SETTLE-011·013·017, 26C-02).
- 재귀 발생에서 같은 청사진 템플릿이 자신의 `raw`·`extras`·분배 입력·잠복 자손·살아 있는 자손 어디에도 원본이 없는 조상과 다시 만나 계속 확장하려 하면 더 만들지 않고 `recursion`으로 기록합니다. 명시 원본의 유한 깊이는 이 판정으로 잘리지 않습니다(TEST-067 (c′), ERROR-190).
- 정착 오류는 기존 `src/errors/`의 `SchemaFormError`와 그곳의 이름 붙은 코드 표 상수를 씁니다. `BUDGET_EXCEEDED`·`RECURSIVE_SHAPE_DIVERGED`·`EXPRESSION_THREW`·`GUARD_FAILED`·`SHARED_NODE_CONFLICT`·`INJECT_TARGET_MISSING`·`INVALID_VIRTUAL_NODE_VALUES`의 분류를 이곳에서 적용하지만 목록을 다시 소유하지 않습니다. 동적 `injectTo` 대상이 없으면 후보에서 빼고 `cause: 'injectTarget'`, 가상 노드 자동 쓰기 모양이 틀리면 `cause: 'writeShape'`로 커밋한 뒤 사슬 끝에 던집니다. 버린 트리의 노드 쓰기에만 남는 `DISPOSED_NODE_WRITE`도 같은 오류 클래스와 표의 코드를 쓰며 단순히 형상을 떠난 참조의 쓰기는 오류가 아닙니다(NODE-044, CONTROLS-079, ERROR-070·122·132·164·195·198).
- 기존 경고 이름공간 `SCHEMA_FORM_WARNING`의 `TYPE_MISMATCH`·`NON_JSON_WHOLE_VALUE`는 `helpers/warning/warningCode.ts`에 이름 붙인 문자열 상수로 둡니다. 기존 경고와 같은 접두를 재사용하고 개발 모드의 통째 값 검사만 후자 코드를 냅니다(VALUE-037, ERROR-070·133).
- 커밋은 `record.markSchemaNodeEvent`로 값·경로·자식 형상·유효 스키마 `UpdateJsonSchema`·계산 상태·상호작용 상태·Refresh 대상·루트 진단을 배달 표에 합치고, 집합 전체의 해당 `revisionLedger` 비트를 한 번에 올립니다. `dispatch`는 그 표를 재계산하지 않고 배달합니다. 커밋 번호와 Refresh 대상·잠복 원본 열거 메모·정합 경고등도 확정합니다(EVENT-004·006·007·043·064·066·071, SETTLE-007). 루트의 잠복 원본은 `(절대 path, kind)`로, `typeMismatchPaths`는 현재 형상의 경로로 보관합니다. `inactiveValues`는 경로마다 형상 밖 잎·터미널 및 잘못된 종류의 `raw`를 든 호스트 중 전순서상 첫 원본을 골라 얼린 `{ path, value }` 항목을 청사진 문서 전순서로 열거합니다. 커밋은 잠복 집합·원본이 바뀐 경로의 조상 배열만 다시 만들고 변경 없는 배열·항목 참조는 재사용하며 빈 배열 하나를 공유합니다. `typeMismatch`는 현재 유효 목록과 원본의 함수이고, `typeMismatches`는 커밋 번호로 메모한 하위 경로 목록입니다(VALUE-029·030·037, WRITE-087, SURFACE-061).
- 커밋은 `record.markSchemaNodeEvent`로 값·경로·자식 형상·유효 스키마 `UpdateJsonSchema`·계산 상태·상호작용 상태·Refresh 대상·루트 진단을 배달 표에 합치고, 집합 전체의 해당 `revisionLedger` 비트를 한 번에 올립니다. `dispatch`는 그 표를 재계산하지 않고 배달합니다. 최종 형상에 든 노드의 참인 `interactionState` 키는 더하고 떠난 노드의 키는 빼며, 살아 있는 노드의 정착 중 상태 변경도 이전 커밋 값과 비교해 셈에 반영합니다. 순변화에서 0↔1 경계가 생겼을 때만 루트의 `UpdateGlobalState`를 정착 밖 사건 대기열에 합칩니다(EVENT-062, 43C-01). 커밋 번호와 Refresh 대상·잠복 원본 열거 메모·정합 경고등도 확정합니다(EVENT-004·006·007·043·064·066·071, SETTLE-007). 루트의 잠복 원본은 `(절대 path, kind)`로, `typeMismatchPaths`는 현재 형상의 경로로 보관합니다. `inactiveValues`는 경로마다 형상 밖 잎·터미널 및 잘못된 종류의 `raw`를 든 호스트 중 전순서상 첫 원본을 골라 얼린 `{ path, value }` 항목을 청사진 문서 전순서로 열거합니다. 커밋은 잠복 집합·원본이 바뀐 경로의 조상 배열만 다시 만들고 변경 없는 배열·항목 참조는 재사용하며 빈 배열 하나를 공유합니다. `typeMismatch`는 현재 유효 목록과 원본의 함수이고, `typeMismatches`는 커밋 번호로 메모한 하위 경로 목록입니다(VALUE-029·030·037, WRITE-087, SURFACE-061).
- 배달 표시는 자동 쓰기 노드를 커밋당 한 번 색인하고, 유효 `controls.watch`는 해석된 경로→살아 있는 감시 노드의 역색인으로 관리합니다. 변경된 방출 경로와 상태 변경 경로가 감시 경로의 조상 또는 자손이면 감시 값을 다시 읽고, `@` 감시는 마지막 배달에서 본 맥락 참조와 현재 참조가 다른 커밋에서만 후보에 넣습니다. 형상 진입 노드는 경로로 조회하고 형상 이탈, 노드 경로 변경, 배열 자식 참조 변경에서는 모든 감시 노드를 다시 읽습니다. 역색인 메모리는 O(감시 에지), 일반 커밋 조회는 O(변경 경로 수 × 깊이 + 일치 감시 노드 수)이며 형상 이탈 시에는 O(전체 감시 노드 수)입니다(EVENT-064, CONTROLS-019, 28C-07, 44C-01).
- 들어오는 자식의 입력은 이번 정착에서 호스트가 분배한 해당 키 값, 자기 `(경로, 종류)` 잠복 원본, 없음 순으로 정합니다. 부분 쓰기가 잠복 원본 위에 겹치면 먼저 그 노드 상태를 복원합니다. 호스트가 이전에 받은 객체의 키 값은 들어오는 자식의 입력이 아니다(VALUE-002·004·025, SETTLE-005, 26C-13).
- 형상 밖 객체 값은 선언의 전순서 첫 종류를 따라 노드별 잠복 원본으로 분배하고, 같은 경로의 다른 종류 잠복 원본은 지웁니다. 호스트 잠복 원본은 자신의 비객체 `raw`와 선언 밖 `extras`만 함께 보관하며 빈 호스트는 항목이 없습니다(26C-13, 26C-14, SETTLE-029, VALUE-002). 열거는 종류가 아닌 경로마다 한 항목입니다. 같은 경로에 서로 다른 종류의 잠복 키가 있으면 전순서상 가장 앞선 종류의 값만 열거합니다. 살아 있는 경로는 그 경로의 잠복 항목만 숨기고 형상 밖 자손은 계속 열거합니다. 경로가 형상을 떠나면 다시 열거합니다. 처음부터 비활성인 branch의 로드 값도 펼쳐 열거하고 재진입 때 복원합니다. 변경 없는 항목·배열은 참조를 재사용하며, 잠복 값과 형상 가시성이 그대로인 정착은 열거를 건너뜁니다(26C-13, NODE-043, WRITE-087, VALUE-029, VALUE-006, 18C-64, SETTLE-029·047).
- 최종 형상에서 나간 노드와 그 당시 형상에 있던 모든 자손은 함께 떼어집니다. 정착 중 임시 나감은 분리를 보류하며 재진입하면 이미 만든 동일 노드를 붙입니다. 최종 형상 확정 뒤 `typeMismatch`·`typeMismatches`·`inactiveValues`·`defaultValue`와 로컬 `visible`·`readOnly`·`disabled`를 마지막 커밋 값으로 보존하고 `active`를 거짓으로 바꾸며 게이트 등록을 해제합니다. `diagnostics`는 살아 있는 트리에서 계속 읽습니다. 떼어진 참조의 쓰기는 정착·통지 없이 자신과 하위 선언의 노드별 잠복 원본을 고칩니다. 자기 종류를 쓰고 같은 경로의 다른 종류 잠복 원본을 지웁니다(26C-10·14, NODE-044, 28C-02). 단, 같은 `(path, kind)`가 현재 형상에 살아 있으면 옛 참조의 `setValue`·`Merge`·`resetSubtree`는 오류 없이 아무 효과도 내지 않고 잠복 원본도 만들지 않습니다. 그 경로가 다시 형상에서 나가면 옛 참조들은 같은 잠복 원본을 다시 쓸 수 있습니다. 살아 있는 경로 확인은 기존 경로 색인을 우선 사용하며 일반 살아 있는 쓰기에 할당을 더하지 않습니다. 전체 교체는 그 경로의 기존 잠복 자손을 지운 뒤 새 값을 노드별로 분배하고, `Merge`는 받은 키마다 자손 잠복 원본에 부분 쓰기를 하며 비객체 값은 해당 위치를 통째로 교체합니다(WRITE-079·087, NODE-043·044, SETTLE-010, ERROR-131, SURFACE-007, 26C-08·10·12·14).
- `TYPE_MISMATCH` 기록은 `{ level: 'warning', code, path, expected: { schemaType, nullable, effective }, received, reason, candidates?, source }`이며 꺼짐→켜짐·재생김·로드·게이트 좁힘에서 한 번 보냅니다. 켜진 채 다른 어긋난 값이 와도 반복하지 않습니다. 채움으로 들어온 원본의 `source`는 로드 도중에도 `'fill'`이고 직접 로드된 원본은 `'load'`입니다. 게이트만 경고등을 켜면 `'gate'`, 직접 쓴 원본은 입력 종류를 유지합니다. Refresh 대상은 로드가 아닌 쓰기에서 원본이 실제 바뀐 노드 중 입력 자신을 뺀 집합이고 `setValue(getValue())`의 대상은 비어 있습니다(VALUE-037, EVENT-071, 26C-03).
- 로드는 마운트·폼 reset·`resetSubtree`뿐입니다. 루트 `loadSnapshot`은 로드한 경로 P를 `setIn(snapshot, P, V)`로 갱신하고 `defaultValue`는 `getIn(snapshot, node.path)`입니다. `resetSubtree`에서 P의 값이 `sameValue`로 같으면 스냅숏 참조를 유지합니다. 폼 수준 로드는 에지·생김 기준과 진단을 비우며, `resetSubtree`는 하위 트리만 새 수명으로 보아 채움·비움 범위를 제한합니다. 일반 쓰기는 `setValue(V)`도 직전 커밋을 기준으로 삼습니다(WRITE-085·090, SETTLE-048·049, ERROR-204).
- 맥락 변경은 로드가 아니며 `SchemaNode/`의 바인딩 전용 `setContext`가 settle 진입 함수를 부릅니다. 맥락 객체가 `sameValue`로 같으면 참조와 커밋을 그대로 두고, 다르면 런타임 칸을 바꾼 뒤 `@` 소유자와 조상만 재계산 목록에 넣어 한 정착을 돕니다. `@`를 읽는 게이트·상태 키는 다시 판정하고 `derived`·`unsetValue`·`resetInteraction`에는 직전 커밋 기준의 에지를 내며 원천 방출 값이 그대로인 `injectTo`에는 내지 않습니다. 통로는 옵션을 받지 않아 Form 속성 `disableAutomaticWrites`가 자동 쓰기의 기본값입니다(CONTROLS-080, SURFACE-055, WRITE-015, SETTLE-043·048, NODE-010, 28C-03·08).
- 로드의 상호작용 상태는 쓰기 전에 비우되 경고등 경로 비움과 스냅숏 교체는 계산 뒤·커밋 직전에 합니다. 떼어지는 노드는 직전 커밋 값을 갈무리합니다(26C-10). 로드 커밋에서 해당 범위의 경고등을 다시 계산하며 `resetSubtree`는 형제의 상태·경고등·진단을 바꾸지 않습니다(WRITE-085, VALUE-030, EVENT-072).
- 로드 범위 밖에서 나간 노드는 로드가 아닌 정착과 같은 나감 규칙(정책·억제·원본 B)으로 자기 잠복 원본을 갈무리합니다. `resetSubtree()`의 로드 규칙은 그 하위 트리에만 적용되므로 범위 밖 원본은 형상을 떠나도 남습니다(EVENT-072, NODE-044, VALUE-006).
- 잎 입력은 재계산 목록·자동 쓰기 로그만 순회합니다. 로드와 전체 교체 쓰기만 쓰기가 닿은 하위 트리를 한 번 순회할 수 있습니다. 나감·채움에 꼭 필요한 하위 선언 순회는 해당 범위로 제한합니다. 게이트 없는 평면 객체의 초기 로드에서 선언·입력·활성 자식의 총 처리량은 자식 수에 비례하며 자식마다 전체 선언이나 이미 모은 키를 다시 검색하지 않습니다(SETTLE-017·047, GOAL-050).
- 한 트리의 `SettlementScratch<Self>`는 런타임의 선택적 슬롯에서 지연 생성하고, 비점유 때만 다음 쓰기에 재사용합니다. 작업 컨테이너는 분배 입력과 잘못된 종류의 호스트 후보를 별도로 보관합니다. 중첩 쓰기는 별도 컨테이너를 쓰며, 성공·throw 모두 `finally`에서 노드 참조와 작업 항목을 비운 뒤 점유를 해제합니다. 객체 호스트 입력 쓰기는 전체 교체처럼 살아 있는 자식과 형상 밖 선언에 분배합니다. 일반 입력 쓰기마다 새 작업 컨테이너를 만들지 않습니다(SETTLE-047, NODE-045).
- 정착 오류와 공유 충돌은 모든 환경에서 진단을 기록한 커밋 뒤 드러냅니다. 게이트의 `GUARD_FAILED`·`EXPRESSION_THREW`는 한 정착에서 첫 실패 발생 순서대로 모두 수집하며 첫 실패 슬롯은 진단 판정에 유지합니다. 같은 위치·호스트의 게이트를 형상 계산 중 다시 평가하는 것은 그 정착의 실패 하나로 세고, 다음 쓰기에서는 다시 수집합니다. 열린 디스패치 사슬에는 평가 자리에서 각 게이트 오류와 기록 발생을 기존 사슬 수집기로 넘기며, 커밋 뒤 같은 오류를 다시 던지지 않습니다. 사슬 밖의 직접 정착 호출은 하나를 그대로, 여럿을 `MULTIPLE_ERRORS`의 `details.errors`로 묶어 던집니다. 개발 모드 `mountingGuardPass`에서는 게이트 실패를 수집하거나 던지지 않고 가드의 `sink` 기록만 남깁니다. 예산 초과는 자동 쓰기를 뺀 원본 B를, 식·가드의 던짐은 자리마다 정의된 값으로 마친 정착 결과를 커밋합니다(TEST-069, ERROR-004·005·041·070, 55C-01).
- 파생 판정은 개발 모드(`process.env.NODE_ENV !== 'production'`)에서만 규칙별 기록 항목을 만들고 실행기는 진입 API·옵션 비트·라운드별 결과·예산 초과의 마지막 라운드를 모읍니다. 커밋은 그 정착의 기록 하나로 런타임 칸을 바꾸며 프로덕션에는 항목도 칸도 만들지 않고 콘솔·`onError`로 보내지 않습니다(ERROR-030·159, NODE-045, 28C-01).

- 전이 중 잠복 원본의 변경은 건드린 키의 직전 존재 여부와 값만 기록하고 메타데이터는 유지합니다. 잠복 맵이 바뀌면 자손 접두 메모를 무효화합니다. 원본 B를 만들 때 노드 자동 쓰기 로그 뒤에 이 기록을 되돌리고, 최종 형상에서 사라진 중간 채움을 회수한 뒤 형상을 다시 계산합니다. 종료한 선언의 잠복 자손은 해당 청사진 하위 경로만 방문합니다(SETTLE-005·011·047, WRITE-034).

## Acceptance Criteria

### settle-gates — 평가와 위치

- 판별·노드/조각 active는 실제로 평가하고 `if`는 검증기 계약의 동기 가드로 판정합니다. 시험 전용 술어 대역 없이 L로 옮긴 게이트의 사촌·루트 읽기와 순환은 고정 출발점에서 같은 형상을 냅니다(VALIDATE-015·044, TEST-069 (나), SETTLE-045, 26C-04).

### settle-budget — 원본 B와 진단

- 호스트·파생·전이 초과 및 재귀 무한 확장은 원본 B·`degraded`·해당 `exceededBudget`을 커밋한 뒤 오류를 던지고, 폼 수준 로드 전에는 진단이 유지됩니다. 파생은 적용 라운드 25를 한 정착에서 누적하고 초과하면 `exceededBudget: 'derive'`·`iterations: 25`입니다. 자기 노드의 존재를 부정하는 게이트가 한 호스트 계산에서 진동하면 전이 중이라도 `hostWheel` 초과이며, 채움·비움이 서로 다른 게이트를 전이 상한보다 많은 라운드에 걸쳐 뒤집을 때만 `transition` 초과입니다. 같은 최종 형상에 이르는 로드는 입력 키 유무와 관계없이 같은 진단 상태입니다(SETTLE-003·005·011·017·022·029, EVENT-020, ERROR-070·132·190·204, TEST-069, 26C-11). 식이나 가드가 던져도 정착은 자리마다 정의된 값으로 끝까지 가며 파생·채움·나감 비움을 이어 갑니다. 나감 비움을 빼는 것은 던져 거짓이 된 게이트로 나간 노드와 함께 나가는 하위 트리뿐이고, 자동 쓰기 전체를 빼는 것은 예산 초과뿐입니다(ERROR-121·122·125·126, SETTLE-011, WRITE-033, 29C-02).

### settle-derive — 파생 단계의 실행

- 파생은 계산 뒤·전이 앞에 돌고 쓰기가 나오면 표시로 돌아가며, 로드는 기준을 비워 발화하고 같은 값의 일반 쓰기는 발화하지 않습니다. 태어난 노드의 규칙은 원천 방출 값이 `undefined`여도 발화하고 채움 뒤 새 에지로 다시 발화합니다. `DisableAutomaticWrites`는 그 호출의 파생 쓰기를 막고 값 동등은 `sameValue` 하나로 판정합니다(SETTLE-004·005·043·046·048, WRITE-015·028·029, 18C-50, 29C-01).

### settle-state-keys — 상태 키의 결합

- 잠금은 네 자리 가운데 하나라도 참이면 참, 표시는 모두 참이어야 참이고 선언 순서와 무관합니다. 잎 입력은 역의존 소유자·형상 변경 호스트에서만 자식으로 넓혀 계산하며, 떼어진 노드는 마지막 커밋의 상태 키를 유지합니다(CONTROLS-073·082·083, SETTLE-017, GOAL-011, NODE-044, 28C-02·07).

### settle-context — 맥락 변경의 정착

- 같은 맥락 객체 또는 깊이 같은 새 객체는 정착도 참조 교체도 하지 않고, 바뀐 `@` 맥락은 소유자와 조상을 재계산하되 `injectTo`를 발화시키지 않습니다(CONTROLS-080, SURFACE-055, SETTLE-043·048, 28C-03·08).

### settle-write — 쓰기 범위

- 두 단계 해석·로드 스냅숏·`resetSubtree`·옵션 억제·Refresh 대상을 쓰기 종류와 범위에 맞게 확정하고 잎 입력은 트리 전체를 걷지 않습니다(WRITE-015·085·098·099, EVENT-071, SETTLE-047).

### settle-delivery — 변경 범위의 배달 표시

- 관련 없는 한 잎 쓰기와 맥락 참조가 그대로인 커밋은 해당하지 않는 감시 노드의 감시 값을 다시 읽지 않습니다. `@` 감시는 마지막 배달에서 본 맥락 참조와 현재 참조가 다른 커밋에서만 후보가 되며, 의존 경로·맥락·형상 변경은 해당 감시 값과 `UpdateComputedProperties` 비트를 유지합니다(EVENT-064, CONTROLS-019, 28C-07, 44C-01).
