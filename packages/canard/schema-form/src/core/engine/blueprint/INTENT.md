# Blueprint

## Purpose

작성 스키마를 변경하지 않고 렌더러와 무관한 유한 선언 그래프와 정적 증거를 준비합니다.

## Conventions

- 스키마의 형상 언어, 선언의 공유와 적용 문맥, 분석과 실행의 경계를 소유합니다.
- 이름은 PropertyDeclaration·SchemaFragment처럼 풀어 써 다른 계층의 개념과 혼동하지 않습니다.
- 렌더러 판단은 predicate로 주입받으며 React를 가져오지 않습니다.
- branchless·기능·수렴 증거는 서로 독립적으로 판정하며 비활성 선언을 포함합니다.

## Boundaries

### Always do

- 연언 overlay와 선언 전용 분기를 구별해 검증기보다 좁은 힌트를 만들지 않게 합니다.
- 정적 실패는 작성 위치와 함께 생성 단계에서 보고합니다.
- 값과 게이트 결과를 저장하지 않는 정적 증거만 폼 사이에 재사용합니다.
- 불확실한 증명은 일반 경로로 돌리고 재귀 참조의 분석을 유한하게 유지합니다.

### Ask first

- 허용 스키마 언어·공유 정체성·정적 실패 범위·증거의 의미를 바꿀 때
- 분석에 값 평가·런타임 노드 할당·렌더러 의존을 도입할 때

### Never do

- 호출자의 스키마나 빌린 값을 변경하지 않습니다.
- 명시적 discriminator 없이 const·enum으로 분기를 선택하지 않습니다.
- 분석 중에 검증기 가드나 작성 식을 평가하지 않습니다.
- 정적 증거를 살아 있는 폼 상태로 대체하지 않습니다.
