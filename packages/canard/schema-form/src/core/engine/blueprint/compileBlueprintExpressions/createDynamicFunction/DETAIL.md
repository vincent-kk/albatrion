# Expression compiler contract

## Requirements

식은 JavaScript 코드이며 샌드박스가 아닙니다. 전역 이름의 허용·차단 목록을 두지 않지만 계약상 입력은 경로 토큰과 @입니다. 시간·난수·외부 가변 상태를 읽는 식과 신뢰할 수 없는 스키마 코드는 지원하지 않습니다. 이 경계를 숨기면 정착의 결정성과 분석의 신뢰 범위를 보장할 수 없습니다.

## API Contracts

경로 치환은 substituteDependencyPaths가 소유하고 형제 인식기도 같은 함수를 사용합니다. 별도의 정규식이나 의존 번호 체계를 쓰면 정적 증거와 실제 함수의 입력이 달라집니다. 함수 타입은 이 컴파일러 내부 계약이며 공개 함수 표면을 불필요하게 넓히지 않습니다.

호출자는 같은 pathManager와 원문에 substituteDependencyPaths를 적용한 결과를 선택적으로 전달할 수 있습니다. 이 경우 이미 등록된 의존과 치환 문자열을 사용하여 중복 치환을 피하며 원문은 오류 정보에 그대로 남깁니다.

## Acceptance Criteria

### CONTROLS-080 — 실행하지 않고 함수를 준비합니다

JavaScript 식 하나 또는 { … }로 감싼 return 문장 몸통을 의존 배열을 받는 함수로 컴파일합니다. 경로를 먼저 등록·치환하고 trim과 후행 세미콜론 정리를 적용하며, derived는 값으로, 상태·에지 식은 반환값을 !!로 바꿉니다. 문장 몸통의 return도 같은 강제 변환을 따릅니다. 함수 생성은 작성 식의 실행이 아니며 컴파일 중 폼 상태를 읽지 않습니다. 전체 언어를 동등식 인식기의 제한된 문법으로 축소하지 않습니다.

### create-dynamic-function-contract — 빈 식과 실패를 구별합니다

문자열이 아니거나 치환 뒤 비어 있으면 함수가 없습니다. 문법 오류는 CREATE_DYNAMIC_FUNCTION이며 원문·생성 본문·원인을 보존합니다. 부모가 작성 schemaPath를 덧붙일 수 있어야 하며, 실패를 빈 함수로 대체해 정상 분석처럼 보이게 하지 않습니다. 반복 경로는 같은 의존 번호를 쓰고 함수 생성 비용은 컴파일 단계에만 둡니다.
