# Non-executing equality contract

## Requirements

전체 식이 한 의존 참조와 원시 리터럴의 엄격 비교 또는 그 비교들의 논리합임을 실행 없이 증명합니다. 단순 문자열 검색으로 ===를 찾으면 호출·우선순위·연쇄 비교를 놓쳐 실제 함수와 다른 선택 표를 만들 수 있으므로, 전체 토큰과 구문 트리를 확인합니다.

## API Contracts

컴파일러와 같은 경로 치환을 새 경로 관리자에 적용하고, 얻은 의존이 정확히 하나이며 컴파일 결과와 원소별로 같을 때만 증거를 반환합니다. 리터럴 순서와 중복을 유지합니다. 인식 실패는 undefined이며 유효한 식을 거부하거나 바꾸는 대신 일반 평가로 돌아갑니다. 호스트 표 구성과 실제 게이트 결과 재사용은 [settle](../../../settle/DETAIL.md)이 소유합니다.

컴파일 소유자는 같은 원문·의존 등록부에서 얻은 치환 결과를 전달하여 중복 치환을 생략할 수 있습니다. 이 경로도 의존이 정확히 하나일 때만 전체 토큰·구문 증명을 수행합니다. 일반 호출의 독립 의존 대조는 유지합니다.

## Acceptance Criteria

### equality-evidence — 전체 식의 비실행 증거

컴파일 호출자는 의존이 하나인 식의 순수 평가기를 준비할 수 있으며 active에만 선택 표 증거를 붙입니다. 인식기 자체는 Function·eval·작성 함수·컴파일된 함수·toString을 호출하지 않습니다. 리터럴과 의존 읽기 외의 효과가 없음을 증명하기 위한 경계입니다.

치환된 참조는 정확히 dependencies[0]만 허용합니다. 기본항은 참조·리터럴·괄호식, ===는 ||보다 강하게 결합하며, 트리의 모든 논리합 잎이 참조 한쪽과 리터럴 한쪽의 ===여야 합니다. 참조·리터럴·비교·논리합을 감싸는 괄호와 비교 양쪽의 순서 바꿈은 허용합니다. 연쇄 비교, 비교 없는 논리합 항, 다른 의존 번호, 프로퍼티·색인 접근·호출·배열·블록·임의 식별자·includes는 인식하지 않습니다. 불완전한 접두 부분만 인식하지 않으며 괄호는 반복형 파서로 처리합니다.

### equality-literals — JavaScript와 같은 리터럴 값

허용 값은 string·유한 number·boolean·null입니다. 문자열 이스케이프는 `\\ \' \" \b \f \n \r \t \v`, 뒤에 숫자가 없는 `\0`, `\xHH`, `\uHHHH`, U+10FFFF 이하의 `\u{H…}`만 해석합니다. 줄 이음·옛 8진·`\8`·`\9`·식별 이스케이프·날 줄바꿈·U+2028·U+2029는 거절합니다. 일반 JavaScript가 받아도 인식기의 증명 범위를 넓혀 추측하지 않습니다.

수는 십진 정수·소수·지수(`.5`·`5.` 포함), 0x·0o·0b 및 앞의 단항 음수 하나만 해석합니다. 여러 자리 앞의 0·숫자 구분자·BigInt·비유한 값은 인식하지 않고 undefined·NaN·Infinity도 식별자이므로 거절합니다. Number 변환을 허용한 숫자 문법 안에서만 사용하여 JavaScript 리터럴과 의미를 일치시킵니다.

### equality-map-equivalence — 표 키와 엄격 비교의 동등성

이 리터럴 집합에는 NaN과 객체가 없으므로 Map의 SameValueZero 조회와 v === literal의 참인 경우가 같습니다. -0과 0은 같은 키이고 NaN인 입력이나 객체 입력은 어느 키와도 맞지 않습니다. NaN·객체를 증거에 추가하려면 이 논증부터 다시 성립해야 합니다. 인식하지 못한 꼴과 판별 descriptor를 이 식 인식기로 억지로 변환하지 않으며, 그 실행 경로의 자격은 settle이 결정합니다.

전체 스캔과 임시 토큰·트리는 식 길이에 비례하며 최종 리터럴 목록만 청사진에 남습니다. 런타임 값이나 게이트 판정은 보유하지 않습니다.
