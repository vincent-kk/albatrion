# Dependency path registry contract

## Requirements

의존 번호는 치환된 함수 본문의 주소이므로 최초 등록 순서와 정규화 규칙은 컴파일·인식·조회에서 일치해야 합니다. 등록부는 컴파일 호출마다 독립적으로 소유하여 다른 식이 번호를 바꾸지 못하게 합니다.

## API Contracts

등록과 조회는 같은 stripFragment의 절대 루트 보존 모드를 사용합니다. 반환 경로 배열은 관측을 위한 빌린 참조이며 소비자가 변경하지 않습니다. 폼 상태를 기준으로 경로를 해석하지 않습니다.

## Acceptance Criteria

### CONTROLS-080 — 루트와 빈 이름의 구별

단독 #는 절대 루트로 보존하고 다른 선두 fragment 표시만 제거합니다. /·#/는 빈 이름 자식으로 정규화되므로 #와 같은 의존 번호로 합치지 않습니다. 두 주소를 같게 취급하면 컴파일된 식이 다른 값을 읽습니다.

### get-path-manager-contract — 번호의 지역성과 안정성

정규화 뒤 같은 경로는 같은 번호이고 서로 다른 경로는 최초 순서를 유지합니다. 미등록 경로는 -1이며 새 등록부는 비어 있습니다. 작은 지역 목록에서 배열 중복 조회를 사용하며, 전역 공유 인덱스나 실행 값 메모를 만들지 않습니다.
