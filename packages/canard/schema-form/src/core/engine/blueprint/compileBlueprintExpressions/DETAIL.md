# compileBlueprintExpressions contract

## Requirements

모든 선언의 식·watch를 정적으로 수집하되 작성 코드를 분석 중 실행하지 않습니다. 비활성 선언을 빼면 게이트가 켜진 뒤 필요한 재계산을 놓치므로 현재 활성 집합에 의존하지 않습니다.

## API Contracts

문자열의 컴파일은 [createDynamicFunction](createDynamicFunction/DETAIL.md), 의존 순서와 fragment 정규화는 [getPathManager](getPathManager/DETAIL.md), 제한된 동등식 증거는 [recognizeEqualityExpression](recognizeEqualityExpression/DETAIL.md)이 각각 소유합니다. 실제 방출 값·맥락 읽기와 발생별 상대 경로 결합은 [settle](../../settle/DETAIL.md)에 둡니다.

## Acceptance Criteria

### BLUEPRINT-022 — 의존 선언과 선택된 watch를 구별합니다

식의 경로와 모든 선언의 watch는 정적 의존의 합집합입니다. 입력에 전달할 watchValues의 목록은 활성 유효 스키마의 watch가 정하므로 정적 합집합으로 대체하지 않습니다. 의존 사전은 프로토타입 이름과 충돌하지 않고 최초 등록 순서를 유지합니다. 컴파일 실패에는 해당 controls 키의 작성 위치와 원인을 보존합니다.

### CONTROLS-043 — 식의 기준점은 선언 호스트입니다

node 식은 그 노드, 조각과 fields 항목 식은 그 선언을 담은 호스트를 기준으로 합니다. 조각은 다른 작성 위치일 뿐 자식 네임스페이스가 아닙니다. 자식 식을 부모 fields 항목으로 옮길 때 ../x를 ./x로 바꾸어야 합니다. 참조 템플릿과 아이템은 컴파일 결과를 재사용하되 실제 발생의 호스트에 상대 경로를 결합하여 첫 방문의 절대 경로를 물려받지 않습니다.

### CONTROLS-080 — 경로 언어와 값 읽기의 경계

./p·../p·/p·#/p·#와 @를 경로 토큰으로 수집합니다. 루트와 빈 이름의 정규화는 getPathManager의 CONTROLS-080을 따릅니다. @는 맥락이며 @/p는 경로가 아니고 @.x·@['x']는 JavaScript 접근입니다. [n]은 경로 이름의 일부이며 배열 색인은 /n으로 적습니다. 독립 wildcard 연산자 조각은 식과 watch에서 거부하며, 별표를 포함한 보통 이름이나 인코딩한 리터럴 예약 이름과 구별합니다. 배열 전체를 읽고 JavaScript로 조사하는 식은 사용할 수 있습니다.

의존은 노드 존재를 증명하지 않습니다. extras·터미널 값 내부도 경로로 읽을 수 있으므로 청사진에 노드가 없다는 이유로 컴파일 오류를 만들지 않습니다. 방출에서 빠진 값·원시값 아래·없는 경로의 실제 읽기와 맥락 변경 에지는 settle이 소유합니다.

### complete-reads — 완전 읽기는 제한된 정적 증거입니다

리터럴·경로·연산자만으로 전체 읽기를 열거할 수 있는 식에만 증거를 줍니다. 호출·대입·동적 접근·주변 이름·문장 블록은 일반 실행 경로로 남깁니다. active와 파생이 있는 청사진에 같은 비실행 검사를 사용하며, 비열거·읽기 전용 completeReads를 생성 때 고정합니다. 모드 초기화로 이 사실을 지우거나 조회 때 재분석하지 않습니다. 정적 스캔은 식 길이에 비례하고 값·실행 결과를 보유하지 않습니다.

### equality-evidence — 증거 부재는 식 오류가 아닙니다

의존 경로가 하나이며 전체 엄격 동등식·논리합으로 증명된 식은 리터럴 목록을 순서대로 비교하는 순수 평가기를 사용하여 동적 Function 생성을 피합니다. 선택 표용 equality metadata는 active에만 붙입니다. 의존 치환 결과를 인식기와 컴파일러에 공유하므로 순서와 리터럴 의미가 같습니다. 목록과 평가기만 청사진 수명 동안 보유하고 살아 있는 값은 보유하지 않습니다.

증거를 얻지 못한 식은 분석 중 기존 컴파일러를 실행합니다. 오류의 시점·코드·작성 경로를 첫 활성화까지 미루지 않으며 completeReads의 별도 증명 조건도 바꾸지 않습니다. 최적화 자격을 식 언어의 허용 범위로 잘못 확대하지 않습니다.

### expressions — 컴파일과 연결의 보존

동일 선언의 중복 컴파일을 피하고 호스트·작성 위치·제어 키·상대 의존을 보존합니다. default·inactiveValue·injectTo를 문자열 식으로 컴파일하지 않으며, watch·식 경로의 독립 wildcard는 작성 위치를 가진 의존 오류입니다.

### expression-regexp-state — 정규식은 입력 메모가 아닙니다

공유 전역 정규식은 문자열 치환·matchAll의 해당 호출 규약으로 사용합니다. 이는 임의 exec 호출이나 중첩 실행에도 lastIndex가 독립적이라는 보장이 아닙니다. 경로 추출을 새 호출 방식으로 확장할 때 상태 공유를 다시 확인하여 앞선 분석의 위치가 다음 선언의 의존을 빠뜨리지 않게 합니다. 정규식 객체를 캐시 초기화 대상으로 취급하지 않습니다.
