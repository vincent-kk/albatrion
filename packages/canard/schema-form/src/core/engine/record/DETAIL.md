# record 계약

## Requirements

노드 인스턴스 자체가 레코드이며 트리 전체 자료는 공유 런타임에 둡니다. 입력 원본과 노드의 수명을 한 모델에서 관리하여 별도 값 모델과의 동기화 누락을 막습니다.

## API Contracts

레코드·행·런타임은 자기 형 `Self`로 부모·자식·생성 결과를 연결하며 공개 클래스에 역의존하지 않습니다. 실제 칸과 호출형은 [레코드 선언](types/record.ts)과 [행 선언](types/behavior.ts)이 정본입니다.

종류별 계산은 [behaviors](../behaviors/DETAIL.md), 원본의 선택·복원·커밋은 [settle](../settle/DETAIL.md), 사건 배달과 진입은 [write](../write/DETAIL.md), 공개 수명은 [surface](../../surface/DETAIL.md)가 소유합니다. 이 모듈은 그 구현을 실행하지 않습니다.

### record-validation-settings — 실행 설정 수명

검증 epoch는 모드 전환으로 폐기되는 비동기 실행 수명이며 load stamp와 다릅니다. activation stamp는 이번 활성화 뒤 전체 요청의 기준이므로 과거 load의 요청으로 대체하지 않습니다. 지연 설정 적용 콜백은 트리당 하나로 마지막 설정을 보유하며 record는 이를 실행하거나 상위 모듈을 import하지 않습니다. 새 자료는 모두 선택적 runtime 칸이며 노드 고정 칸을 추가하지 않습니다.

## Acceptance Criteria

### VALUE-001 — 원본과 노드의 수명을 일치시킵니다

노드 트리가 값 상태의 유일한 소유자입니다. 루트 JSON 모델을 두고 노드를 뷰로 만들거나, 중앙 셀 테이블에 손잡이를 붙이거나, 계층마다 사본을 동기화하는 모델을 두지 않습니다. 원본과 노드의 두 수명 기준을 만들고 사본 갱신·역류 방지 장치를 다시 요구하기 때문입니다. 호스트가 보유하는 비활성 원본도 이 소유권 안에 있습니다.

### VALUE-002 — 상태와 계산·작업 기록을 구별합니다

형상과 값 계산의 입력 상태는 `source`와 `extras`입니다. 상호작용 플래그, 계산한 `local`·`emit`·유효 스키마, 변경 기준과 리비전은 각각의 수명을 가진 자료이며 별도의 값 원본으로 사용하지 않습니다. 수동 분기 선택 상태도 두지 않습니다. 계산 메모나 배달 기록을 다음 형상의 입력으로 삼으면 동일한 원본에서도 호출 순서에 따라 결과가 달라집니다.

`extras`는 청사진 어디에도 선언되지 않은 입력을 순서와 함께 보존합니다. 객체는 입력의 own-key 순서를, 배열은 아이템 청사진이 없는 자리의 순서를 유지합니다. 꺼진 선언의 원본을 미선언 값으로 합치면 선언의 재진입과 미선언 값의 보존 정책을 구별할 수 없습니다.

### VALUE-004 — 계산 결과가 입력 원본을 대체하지 않습니다

터미널은 전체 값을 원본으로 보유하고, 객체·배열 branch의 맞는 종류 입력은 자식 원본과 `extras`에 분배합니다. branch도 맞지 않는 종류의 입력은 `source`에 보존합니다. 이를 자식 합성값으로 덮으면 잘못된 입력을 몰래 고쳐 검증과 불일치 표시가 그 입력을 관찰하지 못합니다. 종류별 해석과 투영의 판단은 behaviors가 소유합니다.

### NODE-004 — 공통 배치와 트리 자료의 비용을 분리합니다

모든 종류에 공통 생성 배치를 적용하고 노드 바깥에 별도의 레코드 객체를 만들지 않습니다. 트리 전체 기능은 공유 런타임에, 드문 기능은 필요한 수명에서만 생기는 선택적 자료에 둡니다. 루트 전용 자료나 기능별 관리 객체를 모든 노드에 배치하면 사용하지 않는 노드도 할당·힙 비용을 부담합니다. 런타임 칸을 추가할 때는 선언과 함께 소유 수명·할당 조건·보유 비용을 먼저 정합니다.

### NODE-006 — 행은 계산과 제안만 제공합니다

행 계약은 원본 쓰기·되돌림·자식 생성과 확정·통지를 행 안에서 실행하지 않도록 나눕니다. 자식 선언과 배열 조작은 호출자가 실행할 제안이며 생성 구현은 트리의 `nodeFactory`로 주입합니다. 행이 실행 순서까지 소유하면 종류마다 정착과 배달 규칙이 갈라집니다. 공유 함수와 행 배치의 구현 규칙은 behaviors가 소유합니다.

### NODE-008 — 레코드 연산이 정착 진입을 만들지 않습니다

이름·주소 갱신은 [공용 경로 조립기](../../../helpers/jsonPointer/DETAIL.md)를 사용합니다. 별도의 이스케이프 규칙을 만들면 예약 이름과 빈 이름의 주소가 탐색과 달라집니다. 상호작용 패치는 같은 키·값이면 기존 참조를 보존하고 떼어진 레코드를 바꾸지 않습니다. 불필요한 참조 교체와 옛 수명의 변경을 막으며, 통지와 검증은 호출자가 담당합니다.

### NODE-018 — 배치의 이점과 남는 비용을 구별합니다

공통 배치와 공유 행은 노드별 전략 객체·관리자·클로저를 피하기 위한 선택입니다. 행의 간접 호출과 종류 getter의 접근 비용은 남습니다. 같은 필드 순서만으로 모든 실행 엔진의 숨은 클래스나 인라인 캐시 성능을 보장하지 않으며, 특정 바이트 추정치를 메모리 상한으로 삼지 않습니다. 선택적 필드·보유 원본·트리 자료까지 포함한 비용을 검토해야 객체 하나의 크기만으로 최적화를 판단하지 않습니다.

### NODE-045 — 형 의존도 실행 의존과 같은 방향을 지킵니다

런타임은 소비자가 요구하는 구조적 계약과 주입된 콜백을 선언하며 선택된 검증 구현은 불투명하게 보유합니다. `settle`·`write`·`validation`·surface·앱·플러그인을 타입으로도 가져오지 않습니다. 청사진 선언과 도메인 없는 예약 수명 형은 사용할 수 있습니다. 구현 형을 가져오면 레코드를 소비하는 계층으로 역의존하여 타입만으로도 순환이 생깁니다.

### NODE-043 — 현재 형상과 보유 원본을 분리합니다

`structure`와 `children`은 해당 참조가 보는 형상이며 비활성 후보 전체를 담는 저장소가 아닙니다. 같은 이름의 후보를 구별하는 청사진 바인딩은 원본 보유에 사용하고 현재 자식 조회와 섞지 않습니다. 후보를 현재 형상에 노출하면 비활성 원본을 살아 있는 노드로 오인합니다. 탐색의 판정은 [navigation](../navigation/DETAIL.md)이 소유합니다.

### NODE-065 — 호스트 보유가 왕복 횟수에 따라 자라지 않습니다

보유 슬롯과 overlay는 호스트의 선택적 원본 자료이며 별도의 트리 단위 잠복 저장소를 두지 않습니다. 바인딩은 이름과 청사진 발생을 구별합니다. 호스트당 보유는 실제 방문한 엔트리 수 이하이며 재귀 템플릿 전체를 미리 실체화하지 않습니다. 보유 공간은 실제 원본 서브트리와 overlay에 비례합니다.

새 호스트가 비활성 자식 인스턴스를 그대로 공유하지 않습니다. 자식의 `parent`가 옛 호스트와 그 슬롯을 계속 붙잡아 반복 왕복만으로 보유 사슬이 자라기 때문입니다. 복제·overlay 적용·소비한 슬롯의 제거는 settle이 수행합니다. 슬롯은 후보 원본이며 옛 형상을 정답으로 재사용하거나 옛 공개 참조를 변경하는 통로가 아닙니다.

### SURFACE-065 — 가변 메모의 수명을 키의 소유 트리에 묶습니다

노드·런타임 키의 다시 계산 가능한 가변 메모는 런타임에 지연 생성하는 트리 소유 WeakMap에 둡니다. 노드별 고정 칸을 늘리거나 전역 저장소가 폼 수명을 붙잡지 않도록 하며, 전체 폼 reset·폐기에서 비우고 부분 reset에서는 트리 전체 저장소를 비우지 않습니다. 보유 원본처럼 다시 계산할 수 없는 상태를 이 초기화에 섞지 않습니다.

생성 때만 얻는 증거는 청사진 사실이고 정적 사실과 정착 수명이 섞인 자료는 분리합니다. 상수·단조 식별자·플러그인 구성은 이 메모 계약으로 초기화하지 않습니다. 구현 형의 역의존을 피하는 런타임 키 등록소는 해당 구현 소유자에 둘 수 있습니다. 파생 저장소의 구성은 [engine](../DETAIL.md), 소비자 키 캐시는 [app/cache](../../../app/cache/DETAIL.md), 검증 자원 장부는 [validation](../validation/DETAIL.md)의 계약을 따릅니다.

### NODE-067 — 출력 차이 읽기의 보유 비용을 드러냅니다

트리는 마지막 루트 로드 출력 참조를 `loadBaseline` 박스로 보유합니다. 박스 없음과 출력 `undefined`를 구별해야 아직 기준이 없는 경우를 판정할 수 있습니다. 출력 전체를 복사하지 않지만 이후 출력에서 교체된 부분도 다음 기준 교체까지 보유할 수 있습니다.

노드의 차이 메모는 마지막으로 읽은 자기 경로의 현재값·기준값·결과와 주소의 segment 배열만 보유합니다. 주소 메모의 추가 공간은 경로 깊이에 비례하며 주소가 바뀐 뒤 첫 읽기에서 교체합니다. 이 메모를 노드 수명에 두어 반복 읽기의 경로 재해석을 피합니다. 생성 배치에는 빈 메모 칸만 두며 쓰기·detach에서 비교하지 않습니다. 기준 교체와 동등성 판정은 settle, 공개 상태 어휘는 surface가 소유합니다.

### VALUE-003 — 진단의 수명이 값 상태와 독립입니다

`diagnostics`는 트리당 작업 기록입니다. 저하 기록은 폼 수준 로드로 초기화할 때까지 보유하여 나중의 정상 쓰기가 앞선 실패를 숨기지 않게 합니다. 노드별 값 상태나 상호작용 초기화와 함께 지우지 않습니다. 실패의 분류와 저하 커밋은 settle, 제출 거부는 [hooks](../../../hooks/DETAIL.md)가 소유합니다.

### record-delivery — 커밋 기준과 배달 기준을 섞지 않습니다

첫 변경 기준은 커밋까지, 대기 사건의 `previous`는 배달까지 유지합니다. 둘을 합치면 한 커밋의 A→B→A와 배달 전 여러 커밋을 구별하지 못합니다. 대기 사건은 배달 전에만 갱신하고 전달한 묶음은 뒤의 표시가 바꾸지 않습니다. 리비전 원장도 이전 읽기를 변경하지 않는 불변 값이며 공유 빈 원장을 출발점으로 사용합니다.

불변 전이의 공유는 payload를 생략할 수 있는 미관측 최외곽 커밋에만 적용하고 전이 메모는 커밋 종료·실패에서 버립니다. 공유 빈 원장을 뿌리로 과거 전이가 계속 붙잡히는 일을 막습니다. 관측·기존 대기·중첩 진입의 배달 의미와 자격 판정은 write와 settle이 소유합니다.

전역 상호작용 집계는 참인 노드 수와 공개 boolean 객체를 구별합니다. 수가 바뀌어도 0 경계를 넘지 않으면 공개 객체와 사건을 유지합니다. 내부 계수 변경만으로 소비자에게 상태가 달라졌다고 알리지 않기 위한 선택이며, 보유 비용은 상태 키 수에 비례하는 트리 자료입니다.

### record-work-lifetimes — 선택적 작업 자료가 소유 수명을 넘지 않습니다

정착 scratch는 트리에서 비운 컨테이너를 재사용하며 중첩 정착은 사용 중인 컨테이너와 분리합니다. 원본 재분배 표시는 해당 정착에서만 존재하고 노드나 로드 스냅숏에 남지 않습니다. 재사용이 이전 호출의 입력을 다음 호출에 유입시키지 않아야 합니다.

표시 자격의 변경 전 기록과 비활성 콜백 등록은 필요한 인스턴스·런타임에만 할당합니다. 표시 기록은 검증 실행 제어와 별도 수명을 가지며 [validation](../validation/DETAIL.md)이 해제합니다. 비활성 콜백은 옛 인스턴스의 등록이 새 공개 수명으로 넘어가지 않게 합니다. 검증 예약과 동기 나감 실행의 규칙은 각각 [validationScheduling](../validationScheduling/DETAIL.md)과 settle이 소유합니다.

경고 경로 역색인과 떼어진 참조의 읽기 묶음은 해당 자료가 생기는 트리에만 할당합니다. 경고 역색인의 키 참조는 경고 수와 경로 깊이의 곱에 비례하며, 이 비용으로 가지 정리 때 모든 경고를 훑는 일을 피합니다. 떼어진 읽기 묶음은 노드 키 WeakMap으로 보유하여 옛 참조가 사라진 뒤까지 그 읽기를 붙잡지 않습니다. 두 기능을 위해 모든 노드의 고정 칸을 늘리지 않습니다.

### record-layout — 생성 배치의 정본은 선언과 구현입니다

논리 필드와 생성자 대입의 순서를 함께 유지합니다. 선택적 기능을 위해 모든 생성자에 객체·배열·함수 할당을 추가하지 않습니다. 노드마다 같은 기본 배치를 유지하려는 목적이며 실제 필드 목록은 코드가 정본입니다.

### record-boundary — 최소 선언의 비용을 변경 전에 확인합니다

새 행·런타임 칸의 소비 형·수명·할당 조건은 NODE-045와 NODE-004의 기준을 따릅니다. 수출·필드 목록을 문서에 복제하여 코드와 다른 계약을 만들지 않습니다.

### record-retained-slots — 슬롯은 공개 수명의 재사용 통로가 아닙니다

슬롯은 원본을 보유하며 상호작용·오류·구독의 수명을 재사용하지 않습니다. 외부에서 옛 참조를 보관하지 않는 한, 동일한 엔트리 집합을 왕복한 횟수만으로 도달 가능한 원본 노드가 증가하지 않아야 합니다. 공개 참조의 읽기·구독·쓰기 계약은 surface가 소유합니다.

## Boundary Exemptions

### `types/` — 형 칸 유지

- **Consumers**: `entry-point`
- **Direct import**: `not allowed`
- **Reason**: 레코드가 소유하는 구조적 계약이므로 형 칸에 두고 외부 소비자에게는 진입점의 명명 수출로 제공합니다. 구현 계층의 형을 끌어와 순환을 만들지 않습니다.

### `utils/` — 레코드 불변식의 공유 보조

- **Consumers**: `entry-point`
- **Direct import**: `not allowed`
- **Reason**: 상태 패치와 변경 기준 기록은 여러 실행 계층이 사용하지만 레코드의 참조·기록 수명 불변식을 구현하므로 이 모듈에 둡니다. 외부 소비자는 진입점을 사용합니다.
