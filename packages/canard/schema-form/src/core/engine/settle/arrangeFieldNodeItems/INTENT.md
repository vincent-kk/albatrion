# arrangeFieldNodeItems — 배열 구조 적용 경계

## Purpose

순수 배열 계획을 살아 있는 아이템·원본 슬롯·경로 저장소·로드 스냅숏에 적용하고 한 정착의 구조 결과를 확정합니다.

## Conventions

- 통째 쓰기의 정체성은 위치를 따르며 구조 이동의 생존과 원본 파괴를 구별합니다.
- 행은 계획, 이 모듈은 적용, 부모 settle은 공통 계산·전이·커밋을 소유합니다.
- 꼬리 최적화도 이전 children·값·스냅숏의 불변성과 배달 기준을 보존합니다.

## Boundaries

### Always do

- 생존 자리의 모든 종류 원본과 overlay를 충돌 없이 함께 옮깁니다.
- 소멸한 참조의 마지막 읽기를 보존하고 쓰기는 무효로 둡니다.
- 정적 증명이 깨지면 같은 정착에서 일반 경로로 이어갑니다.

### Ask first

- 위치 정체성·itemKey·소멸 순서·스냅숏 원천 또는 정적 자격을 바꾸려는 경우.
- remove·insert의 꼬리 재매김 비용이나 불변 사본의 허용 범위를 바꾸려는 경우.

### Never do

- 데이터의 안정 키를 추측하여 통째 쓰기의 아이템을 재정렬하지 않습니다.
- 살아남아 이동한 원본을 옛 주소의 소멸 정리로 다시 지우지 않습니다.
- 행의 순수 계획·배치 사슬을 재구현하거나 증명 실패 뒤 구조 동사를 두 번 적용하지 않습니다.
