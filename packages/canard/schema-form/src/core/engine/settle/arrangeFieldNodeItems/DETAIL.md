# arrangeFieldNodeItems 계약

## Requirements

이 모듈은 배열 행의 순수 구조 계획을 현재 아이템과 경로 저장소에 적용합니다. 행의 계획·동사 경계는 [arrayBehavior](../../behaviors/arrayBehavior/DETAIL.md), 배치와 호출 사슬은 [write](../../write/DETAIL.md), 정착의 원본 B·나감 정책·참조 수명은 [settle](../DETAIL.md)가 소유합니다. 계획을 적용한 뒤에도 그 정착 순서와 관측을 유지합니다.

## API Contracts

구조 이동과 원본 파괴를 구별합니다. 살아남는 아이템은 위치별 청사진에 맞춰 재사용하거나 새 발생으로 재생성하고, 실제로 삭제한 자리의 모든 종류 원본은 버립니다. 옛 주소의 소멸 정리가 그 주소로 이동한 생존 원본을 다시 지우지 않게 이동을 충돌 없이 함께 적용합니다.

## Acceptance Criteria

### NODE-051 — 배열 정체성은 데이터 키가 아닌 위치를 따릅니다

배열을 통째로 쓰는 로드·입력·Merge·자동 쓰기는 기존 위치의 노드·itemKey를 잇고 긴 입력의 새 꼬리만 만들며 짧은 입력의 남은 꼬리를 소멸시킵니다. 상태·오류·참조는 데이터의 내용이 아니라 그 위치에 남습니다. 생김과 Refresh는 정체성 유지와 별개로 쓰기 종류를 따릅니다. 안정적인 데이터 키를 추정하여 배열을 재정렬하는 장치는 두지 않습니다.

구조 remove·insert는 편집 위치 뒤의 생존 아이템을 이동합니다. 같은 목적지 청사진이면 노드와 키를 유지하며 이름·경로를 바꾸고, 청사진이 다르면 새 발생을 만듭니다. 삭제·재생성의 옛 참조는 마지막 커밋 읽기를 유지하고 쓰기는 무효입니다. 키 발급 계수는 소멸·자동 쓰기 복원 때문에 뒤로 돌리지 않아 이미 외부에 보인 키를 재사용하지 않습니다.

### NODE-052 — 튜플의 목적지 청사진이 해석을 정합니다

각 자리는 자기 prefixItems 또는 나머지 items 청사진을 사용합니다. 청사진 없는 자리는 extras로 보존하며 막거나 버리지 않습니다. 이동으로 값이 노드와 extras 사이를 건너갈 수 있으며 newly declared 키와 더 이상 선언되지 않은 키도 목적지에서 분배합니다. 유효 제약과 배열 길이의 적합성은 검증기의 책임이므로 minItems를 채우거나 maxItems 초과 삽입을 막지 않습니다.

후보를 가진 자리의 생존 이동은 루트 깊이부터 모든 종류의 보유 원본과 overlay를 운반합니다. 목적지에 청사진이 없는 꼬리라도 원본 이동은 값 삭제가 아닙니다. 새 발생은 정확한 주소·종류 토큰으로 보유한 자신의 원본이 있을 때만 그것을 합성 입력보다 우선하고, 없으면 일반 입력 해석을 사용합니다. 후보 없는 그래프에 이 보유 탐색을 추가하지 않습니다.

### NODE-053 — 선언된 아이템은 생성 시 실체화합니다

청사진이 있는 아이템은 생성 때 노드를 만듭니다. 조회나 렌더 시점까지 실체화를 늦추면 find·검증 라우팅·채움·에지·리비전·구독에 관측 차이가 생길 수 있으므로, 같은 의미가 별도로 증명되지 않은 지연 노드 모델로 바꾸지 않습니다. UI 가상화는 이 원본·노드 수명을 바꾸는 근거가 아닙니다.

### NODE-065 — 생존 슬롯 이전과 재생성 비용의 한계

호스트의 슬롯·overlay는 생존 아이템과 함께 직접 이전하며 떼어진 원본 발생의 path·읽기를 수정하지 않습니다. 후보가 비활성이어도 이동 목적지의 원본·선언·규칙·분류를 소멸 정리에서 보호합니다. 원본 이동 기록은 해당 호출에서만 보유하고 다음 정착으로 캐시하지 않습니다.

같은 청사진의 이전은 영향 아이템에 비례하며 보유 발생의 복제·전체 합성을 하지 않습니다. 서로 다른 튜플 청사진 사이의 중첩 보유 자손은 재생성 깊이마다 복제·합성이 반복될 수 있어 최악 O(영향 서브트리 × 재생성 깊이)입니다. 실제 삭제·clear·shortening은 보유 원본도 파괴합니다. 일반 gate exit의 보존과 지움 배열의 keep 압축은 부모 settle의 VALUE-040을 따릅니다.

### WRITE-085 — 되돌림 입력은 구조 이동과 함께 이동합니다

구조 연산은 loadSnapshot의 같은 배열도 이동하여 생존 아이템이 자기 reset 원천을 유지하게 합니다. push·insert의 새 자리는 호출자가 준 생성 값 v를, 인자 부재는 undefined를 넣습니다. default로 채워진 결과를 스냅숏에 덮어쓰지 않습니다. update·입력·일반 Merge는 생존 자리의 스냅숏 값을 바꾸지 않습니다.

children·출력·스냅숏은 이전 배달 기준과 호출자 입력을 바꾸지 않도록 새 배열로 공표합니다. 스냅숏은 아이템 수에 맞는 밀도 있는 자리 배열이며 짧거나 성긴 입력의 빈 자리는 undefined로 채웁니다. 비용은 O(배열 길이)의 불변 사본과 경로 위 조상 복사이며, 꼬리 최적화도 이 비용을 없앴다고 약속하지 않습니다.

### WRITE-095 — 비구조 길이 변경도 되돌림 자리를 맞춥니다

비로드 통째 쓰기·입력·Merge로 아이템 수가 바뀌면 남은 자리의 스냅숏 값은 유지하고 없어진 꼬리는 자르며 새 꼬리에는 undefined를 넣습니다. 일반 쓰기가 스냅숏의 값을 바꾸지 않는다는 부모 계약은 이 자리 정렬을 금지하지 않습니다. 새 아이템에 현재 편집 값을 초기값으로 저장하면 resetSubtree가 호출자가 싣지 않은 값을 복원하게 됩니다. 로드는 자신의 입력을 새 스냅숏으로 삼습니다.

### WRITE-088 — 구조 생성은 로드가 아닙니다

push·insert가 만든 노드는 생김으로서 없음인 자손만 채움을 받습니다. 기존 접두를 새 수명으로 취급하지 않습니다. 생성 값이 명시한 원본을 default로 덮지 않으며 채움·억제·두 단계 해석은 부모의 SETTLE-005·WRITE-098을 따릅니다.

### array-position-cost — 꼬리 연산과 재매김 비용

push·pop은 새 꼬리나 제거 꼬리 하나의 구조 작업이 목표이고, remove·insert는 자리 i 이후 길이 T에 비례하는 이름·경로 재매김을 허용합니다. 재매김의 T 비용은 위치 정체성의 비용이며 안정 데이터 키 모델로 바꾸어 없애지 않습니다. children·출력·스냅숏의 전체 길이 N 사본은 별도의 불변 비용입니다.

정적 자격은 기본 branch 배열 행, 활성·첫 배달 완료·미분리·batch/visit 밖, 청사진 전체의 정적 capability, 해당 호스트의 보유 원본 부재, 전체 misfit 부재, 통째 source 부재, 호환 children·local·현재 방출 및 omitTrailing 꺼짐을 요구합니다. 튜플 밖의 비가상·단일 정적 아이템 등 동사별 자리 증명도 필요하며, append만 템플릿 없는 extras 전용 배열을 별도로 허용합니다. 하나라도 증명하지 못하면 일반 계획을 적용합니다. 여러 fold 후보나 동적 읽기가 있는 그래프에 이 자격을 강제로 넓히지 않습니다.

빠른 append·pop은 접두 계획·접두 자격 순회 없이 꼬리만 적용하고, 가운데 splice는 꼬리 T만 확인·이동·재공표합니다. children·스냅숏·출력 사본과 splice 뒤 스냅숏 정렬은 N에 비례하며 새 아이템의 생성·채움 및 소멸 자손 정리는 그 크기에 비례합니다. 기본값 채움이 추가 합성을 부르면 출력 사본이 한 번 더 생길 수 있습니다. remove·insert가 O(T)라는 말로 전체 호출이 N과 무관하다고 약속하지 않습니다.

적용 증명은 정착 문맥의 arrayAppend·arrayPop·arraySplice에만 두며 선택·합성·정렬이 각자 확인합니다. 깨지면 같은 문맥에서 일반 작업으로 이어가고 동사를 다시 적용하지 않습니다. 정적 이동은 위치를 읽는 식·게이트가 없으므로 이름만 바뀐 꼬리를 재계산하지 않지만, 일반 이동은 새 위치의 읽기를 다시 평가합니다.

### settle-array-prefix — 일반 계획의 접두 보존

일반 append·remove-last도 같은 위치의 원본 슬롯과 같은 살아 있는 청사진·노드라는 접두 증명이 있을 때만 꼬리 적용을 사용합니다. 접두 source를 재합성하지 않되 자격 확인과 공표 배열 복사의 O(P), 게이트가 있는 접두 하위 트리의 등록 해제·재등록 비용은 남습니다. 비접두 이동·재생성은 일반 전체 계획입니다.

### settle-array-clear — clear는 소멸이며 gate exit가 아닙니다

clear는 아이템과 그 보유 원본을 소멸시키고 inactiveValue나 unsetOnInactive의 gate exit로 대신하지 않습니다. 비활성 후보와 보류 나감도 소멸 발생의 identity로 정리합니다. 오류 저장소를 지우기 전에 마지막 합쳐진 읽기를 보존하고, 소멸 노드·자손의 대기 배달·리비전·감시·검증/외부 오류 대상을 정리합니다. 해당 노드에는 배달하지 않고 호스트와 조상의 변경을 커밋합니다.

새 길이가 0이면 경로 저장소를 아이템마다 재키하지 않고 호스트 접두로 정리합니다. 경로 저장소 정리는 실제 삭제 항목과 깊이에 비례하지만 분리할 아이템·자손 방문은 남으므로 clear 전체가 O(1)은 아닙니다. 원본 트리도 실제 extras·통째 source·살아 있는 노드 없는 반환/재생성에 필요할 때만 읽습니다.
