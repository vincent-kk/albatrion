# settle — 동기 정착 경계

## Purpose

명시적인 쓰기에서 현재 형상과 방출을 확정하고, 원본 보존·자동 전이·실패 시 커밋의 일관성을 소유합니다.

## Conventions

- 계산·투영은 원본 쓰기와 구별하며 종류별 해석은 behaviors의 계약을 소비합니다.
- 자동 규칙의 에지·승자는 derive, 배달 사슬은 write, 최초 마운트와 배열 계획 적용은 각 자식의 계약을 따릅니다.
- 정적 준비물은 불변 청사진의 증명이며 직전 동적 형상은 다음 형상의 출발점이 아닙니다.

## Boundaries

### Always do

- 같은 원본의 결과가 평가 이력에 의존하지 않도록 고정 출발점과 작성 순서를 지킵니다.
- 예산 초과에도 명시 입력을 남기는 원본 B를 커밋하고 실패를 외부 관측 경계로 전달합니다.
- 로드의 새 수명과 일반 전체 교체 쓰기의 직전 커밋 기준을 구별합니다.
- 떼어진 참조의 쓰기는 무효로 두고 비활성 값은 살아 있는 호스트의 경로 쓰기로만 바꿉니다.

### Ask first

- 고정 출발점·평가 순서·예산·참조 수명·나감 보존 정책을 바꾸려는 경우.
- 일반 경로와 다른 관측을 허용하거나 영향 범위 밖 순회를 추가하려는 경우.

### Never do

- 이전 활성 집합이나 평가 순서로 다른 고정점을 고르는 최적화를 하지 않습니다.
- 값·스키마·리비전이 확정되기 전에 리스너나 동기 보고기를 호출하지 않습니다.
- leaf 입력마다 전체 트리나 비활성 원본 전체를 순회하지 않습니다.
- 종류별 행 구현·surface 클래스·React 바인딩을 이 모듈로 가져오지 않습니다.
