# settle — 동기 정착 경계

## Purpose

쓰기 한 번의 진입을 표시, 계산, 전이, 커밋 순으로 처리해 현재 형상과 방출 값을 확정한다.

## Conventions

- 원본을 바꾸는 단계와 계산 단계를 구별하고, 상태는 `raw`와 `undeclaredValues` 둘만 둔다. 형상 밖의 정적 해석과 빈 값 판정은 behaviors 진입점을 소비한다(VALUE-002, WRITE-082·098, NODE-016, SETTLE-002–006).
- 청사진은 선언과 식을 제공하고, 이 모듈이 게이트를 평가한다(26C-04).
- PR-2의 예산은 호스트 바퀴와 전이 라운드이다(TEST-069).
- 표시된 배열 결과에 대해서는 채우기, 파생, 투영, 형상 생성을 적용하지 않고 정적 입력 해석을 제공한다(EVENT-061, 62C-01).

## Boundaries

### Always do

- 원본 B를 되돌림 기록으로 만들고, 예산을 초과한 뒤에도 진단이 설명하는 커밋을 확정한다(SETTLE-011, ERROR-130).
- 로드와 일반 쓰기의 생김과 에지 기준을 구별한다(SETTLE-048·049).

### Ask first

- 호스트 바퀴의 시작점, 전순서, 예산 식을 바꾸려는 경우.

### Never do

- 클래스에 정착 알고리즘을 넣지 않고, 종류별 행 구현을 직접 가져오지도 않는다(NODE-004·016).
- 잎 입력이 들어올 때마다 전체 트리를 순회하지 않고, 레거시 엔진도 가져오지 않는다(SETTLE-047, LANDING-159).
