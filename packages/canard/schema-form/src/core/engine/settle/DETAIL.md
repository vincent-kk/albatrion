# settle 계약

## Requirements

부분 로드 쓰기는 경로 문법을 한 번만 준비해 현재 값 비교와 조상 재구성에 함께 사용합니다. own 확인은 모든 이름에 유지하므로 일반 이름의 상속 속성도 읽지 않으며 값·조회 결과를 추가로 캐시하지 않습니다.

조건 경로가 노드 없는 extras 값으로 진입하면 남은 조각은 그 값의 own 속성만 읽습니다. 마지막 노드의 structure·extras로 돌아가면 상위 동명 필드를 잘못 읽으므로 노드 경계의 flush와 값 내부 순회를 구별합니다. 경로 깊이에 비례한 읽기 비용과 추가 보유량 없음은 유지합니다.

로드 스냅숏 경로는 own 속성만 읽고 예약 멤버도 own 데이터로 기록합니다. 배열 슬롯 정렬도 같은 규칙을 사용하여 기본값 조회·부분 reset이 상속 속성이나 프로토타입을 값으로 취급하지 않게 합니다. 경로 깊이에 비례한 확인과 기존 얕은 사본 비용을 유지합니다.

정착은 명시적 쓰기를 받은 원본에서 형상과 방출을 동기적으로 확정하는 경계입니다. 계산 도중의 형상은 작업 상태이며, 사건은 확정 결과를 전달합니다. 같은 원본에서도 직전 화면에 따라 다른 고정점을 고르는 최적화는 허용하지 않습니다.

원본의 저장 책임은 [record](../record/DETAIL.md), 종류별 순수 해석·합성·투영은 [behaviors](../behaviors/DETAIL.md), 자동 규칙의 승자·에지는 [derive](../derive/DETAIL.md)가 소유합니다. 이 모듈은 그 결과를 적용하는 순서와 범위, 원본 보존 및 실패 시 커밋을 소유합니다. 사건의 배달과 진입 사슬은 [write](../write/DETAIL.md), 검증 판정과 예약은 각각 [validation](../validation/DETAIL.md)과 [validationScheduling](../validationScheduling/DETAIL.md)의 계약을 따릅니다.

## API Contracts

공유 게이트 호스트 뷰는 정착 문맥의 데이터 계약으로 소유합니다. 타입 계층이 뷰를 읽는 구현에 의존하지 않아 문맥과 읽기 함수 사이의 순환을 막습니다.

일반 쓰기·로드·배열 구조 연산·맥락 변경은 동일한 정착 의미를 사용합니다. 최초 마운트의 자격과 관측 경계는 [loadFieldNodeAtMount](loadFieldNodeAtMount/DETAIL.md), 배열 계획 적용·정체성·스냅숏 이동은 [arrangeFieldNodeItems](arrangeFieldNodeItems/DETAIL.md)에 둡니다. 자식의 빠른 경로를 사용하는 부모도 일반 계산과 같은 최종 값·형상·오류·리비전·배달을 보장합니다.

경로 문법은 jsonPointer의 정본을 사용합니다. 재사용하는 것은 주소의 문법이며, 현재 인스턴스·선택·값·원본의 조회 결과는 매번 현재 형상에서 구합니다. 주소만 같은 다른 수명의 발생이 이전 결과를 물려받으면 재키·재진입 뒤 다른 아이템의 값을 읽게 됩니다.

## Acceptance Criteria

### SETTLE-001 — 단계 순서와 외부 관측의 경계

표시 → 계산 → 파생 → 전이 → 커밋의 순서를 유지합니다. 파생·전이 쓰기는 표시와 계산으로 돌아오며, 계산 자체와 커밋은 원본을 수리하지 않습니다. 배치는 여러 표시 뒤 한 정착을 확정하므로 중간 값을 배달하는 통로를 추가하지 않습니다. 상태·스키마·값이 서로 다른 시점의 결과로 관측되는 실패를 막는 경계입니다.

정착 중 동기 보고기나 콘솔을 호출하지 않습니다. 청사진 생성 오류와 실행을 중단하는 예외를 제외한 기록은 커밋 뒤 사슬 또는 마운트 준비 경계로 넘겨, 보고기가 미완성 트리를 읽지 않게 합니다.

### SETTLE-044 — 고정 출발점과 이력 없는 형상

호스트는 게이트 없는 선언과 상속 overlay에서 출발하고 동적 게이트는 꺼진 상태에서 작성 순서로 다시 고릅니다. 직전 활성 집합은 생김·나감 비교와 인스턴스 재사용에만 쓰며 출발점이나 평가 순서의 힌트로 쓰지 않습니다. C가 켜 준 A·B가 서로를 지탱할 때 C를 끈 뒤에도 A·B가 남는 이력 의존을 막습니다. 불투명 가드의 의존을 추측하여 이 조건을 완화하지 않습니다.

원본으로 지탱되는 조각과 default만으로 자기 게이트를 켜려는 조각은 다릅니다. default는 이미 생긴 노드의 채움 사건이므로 아직 없는 노드를 미리 채워 게이트를 통과시키지 않습니다. 고정점이 여러 개이면 작성 순서가 결과를 정하고, 고정점이 없는 순환은 예산으로 드러나는 지원 한계입니다. 마지막 활성 집합을 정상 고정점으로 약속하지 않습니다.

### SETTLE-019 — 작성 순서가 결정성을 만듭니다

게이트의 전순서는 본체 properties, allOf 항목, if/then/else, oneOf·anyOf 분기의 키워드 순위와 배열 위치로 정하며 JSON 객체의 키 삽입 순서로 정하지 않습니다. 감싸는 조각이 켜진 범위만 방문하고, 노드 게이트는 선언 조각 뒤에, fields 항목 게이트는 그 조각의 노드 게이트 뒤에 항목 순서로 둡니다. 순서 변경은 여러 고정점의 선택을 바꿀 수 있는 계약 변경입니다.

### SETTLE-020 — 앞선 판정은 같은 바퀴의 뒤 판정에 보입니다

참이면 켜고 거짓이면 끄며, 한 바퀴 안의 변화는 뒤 게이트의 입력에 즉시 반영합니다. 라운드 최초의 입력 객체 하나로 모든 가드를 평가하지 않습니다. 전수 평가와 같은 판정을 얻는다는 조건 아래에서만 입력 메모·표 조회·확인 바퀴 생략을 사용합니다. 변경 경로만으로 일부 게이트를 빼는 역색인은 고정 출발점에서 필요한 재진입을 누락하므로 사용하지 않습니다.

### SETTLE-021 — 게이트는 방출 관점의 현재 값을 읽습니다

게이트·상태 식·watch는 투영된 현재 방출 트리를 읽으며 extras도 보지만 원본과 비활성 원본은 보지 않습니다. 조상 투영이 뺀 값은 undefined이고, 노드가 없는 extras나 통째 값의 내부도 값 수준으로 읽습니다. 호스트 자신의 원본이 객체가 아닌 경우 자체 가드 입력은 빈 객체입니다. 원본의 빈 문자열과 검증기가 보는 없음이 서로 다른 참여 판정을 만드는 일을 막습니다. 조건 판정은 검증기의 책임이며 읽기 분석을 별도의 검증기로 사용하지 않습니다.

### SETTLE-045 — 다른 하위 트리를 읽는 게이트의 평가 자리

호스트 밖을 읽는 active 게이트는 선언 호스트와 모든 읽기를 덮는 가장 낮은 공통 조상 L의 바퀴에서 평가합니다. L에서 선언 호스트로 이어지는 자식의 선언 조각과 노드 게이트 뒤에 놓고, 여러 이동 게이트는 문서 순서를 지킵니다. @는 노드 주소가 아니므로 L 계산에 넣지 않습니다. 상속 overlay나 이동 게이트가 바뀌면 같은 바퀴 안에서 영향 경로를 다시 계산하며 그 일도 호스트 예산에 포함합니다.

비로드 쓰기에서 사전 공표가 local·emit을 바꾸었지만 라운드 끝 합성이 이를 다시 보고하지 않는 경우에도, 이미 평가한 이동 게이트의 실제 읽기가 달라지면 재예약합니다. 아직 평가하지 않은 게이트를 전부 재예약하거나 로드에 같은 보정을 적용하지 않습니다. 사촌의 새 출력 누락과 불필요한 추가 바퀴·로드 예산 초과를 함께 막습니다.

### SETTLE-022 — 예산은 작성된 결정 수를 셉니다

호스트 바퀴 상한은 그 호스트가 평가하는 게이트 가진 조각 수 + 노드 게이트 수 + 1이고, 전이 상한은 청사진 전체의 같은 결정 수 + 1입니다. if/then/else는 한 결정이며 fields의 active는 대상 수가 아니라 항목마다 하나입니다. 조각 자체 active를 조각 수와 별도로 중복 계산하지 않습니다.

파생은 실제 적용 쓰기를 낸 라운드를 한 정착에서 25까지 누적하고 전이 뒤에도 이어 셉니다. 전이는 쓰기를 내어 다음 계산을 부르는 라운드를 세며 파생과 별도입니다. 두 상한을 곱하지 않습니다. 전이 중 호스트가 먼저 진동하면 채움을 더 기다리지 않고 hostWheel 초과로 처리합니다. iterations는 초과한 예산의 상한을 나타내므로 최적화의 빈 확인 횟수로 바꾸지 않습니다.

### SETTLE-011 — 원본 B를 커밋하고 실패를 보존합니다

예산을 넘으면 이번 정착의 채움·파생·주입·unset·나감 비움·유효 목록 재해석 등 자동 변경을 되돌리고, 쓰기 경계의 정적 해석을 마친 명시적 입력을 남깁니다. 원본 B는 전체 트리 사본 대신 원본·extras·배열 구조·슬롯 변경의 되돌림 기록으로 만들며, 기록 수명은 정착 하나입니다. 리스너의 다음 정착까지 한 되돌림 범위로 묶지 않습니다.

B로 형상을 다시 계산하고 그 계산도 상한에 닿으면 마지막 바퀴의 형상을 커밋합니다. 이미 받은 입력을 거부하거나 직전 화면으로 되돌리지 않으면서 종료를 보장하는 선택입니다. 예산은 해당 고리를 끊으며 스키마 순환이나 후속 쓰기 자체를 금지하지 않습니다.

모든 정착 실패를 발생 순서로 보존하고 같은 발생의 반복 평가만 중복 제거합니다. 최초 cause를 뒤의 예산 오류로 덮지 않으며, 예산 초과 표시는 별도로 보존합니다. 가드·식 실패만으로 무관한 파생·채움·나감 정책을 모두 취소하지 않습니다. 다만 던진 게이트 때문에 나간 값은 비우지 않습니다. 커밋 뒤 실패를 전달하고 degraded는 폼 수준 로드까지 유지합니다. 제출의 거부는 [제출 바인딩](../../../hooks/DETAIL.md)이 소유하며, 검증 오류 목록이나 getValue 차단으로 대신하지 않습니다.

### SETTLE-006 — 확정과 리비전은 리스너보다 앞섭니다

커밋은 배달 집합 전체의 해당 비트 리비전·페이로드·커밋 번호를 리스너 실행 전에 확정합니다. 유효 스키마 변경도 값 변경과 독립적으로 배달 대상입니다. resetInteraction은 최종 트리의 에지로 상호작용 상태를 초기화하며 원본은 쓰지 않습니다. 값이 같아 돌아온 변화는 참조 복원 뒤 배달에서 제외하여 일시 계산을 새 입력으로 알리지 않습니다.

전역 상호작용 상태는 형상 진입·이탈·변경·상태·로드의 기존 순서로 키 증감을 합산한 뒤 공표합니다. 임의 노드가 공개 상태 명령으로 키를 받을 수 있어 현재 참 키나 resetInteraction 선언만으로 대상 범위를 줄이지 않습니다. 구독자가 없어 payload를 생략할 때도 비트별 리비전은 동일해야 늦은 구독이 변경을 놓치지 않습니다.

### SETTLE-017 — 비용은 영향 범위와 실제 보유량에 붙습니다

잎 쓰기의 값·형상 재계산 탐색은 재계산 목록·자동 쓰기 기록·영향 의존 폐포만 방문합니다. 로드와 전체 교체 쓰기만 대상 하위 트리를 순회하며, 생김 채움·나감과 선언 밖 보유 원본 정리는 해당 수명 범위에서 필요한 순회만 허용합니다. 기능 통과는 청사진의 정적 기능 색인과 이번 작업 집합의 교집합을 사용하고, 전체 순회를 추가할 때에는 정적으로 범위를 정할 수 없는 이유를 이 계약에 둡니다.

misfit 경로 집합이 바뀌면 잎 하나의 변경이어도 전체 misfit 경로를 정렬하고 각 조상 목록을 다시 구성합니다. 이 목록 작업은 재계산의 영향 범위에 한정되지 않으며, 정렬 시간과 경로를 조상별로 펼치는 시간·메모리 비용은 폼 전체 misfit 경로 수와 경로 깊이에 의존합니다. 목록 재구성은 경로 집합이 바뀌지 않고 기존 메모가 유효할 때만 생략합니다.

상위 컨테이너의 불변 얕은 사본은 남습니다. 변경 노드 수가 작아도 넓은 부모 객체·배열의 조립 비용까지 상수라고 약속하지 않습니다. 정착 문맥은 호출마다 독립적이고 scratch만 비점유 때 재사용하며 정상·예외 종료 모두 노드 참조와 작업 항목을 비웁니다. 중첩 쓰기는 점유 중인 scratch를 공유하지 않습니다.

### SETTLE-042 — 객체 키 순서와 참조 복원

객체 local·emit은 첫 선언의 청사진 전순서에 따른 키 뒤에 extras의 ECMAScript own-key 순서를 둡니다. 같은 이름의 다른 후보가 선택되어도 첫 이름의 선언 위치를 잃지 않습니다. 정수 이름의 언어 차원 순서는 그대로입니다. 키 집합이 같을 때만 패치하고 바뀌면 다시 만들어, delete/reinsert 때문에 출력 순서가 이력에 의존하지 않게 합니다.

내용이 같아진 출력은 조립 단계에서 직전 커밋 참조로 되살립니다. 커밋에서 뒤늦게 자식만 되살리면 부모가 다른 참조를 품게 됩니다. 공통 동등성 정의는 [engine의 계약](../DETAIL.md)을 따릅니다. 재계산 자식 참조가 실제 바뀌면 깊은 되살림 비교를 생략할 수 있으며, 같은 정착에서 자식 인스턴스가 교체되어 같은 내용의 새 참조를 내는 경우에는 부모 배달이 추가될 수 있다는 한계가 있습니다.

### WRITE-090 — 로드와 전체 교체 쓰기는 다른 수명입니다

마운트·폼 reset·resetSubtree만 로드입니다. 일반 setValue와 입력 Overwrite는 누락 원본까지 지우는 전체 교체이지만 직전 커밋의 생김·에지 기준을 유지합니다. 따라서 setValue(undefined)는 기존 자리를 비우며 다시 채우지 않고, 새로 들어온 노드만 채움을 받습니다. 같은 출력을 다시 쓰는 행위를 로드로 추측하면 사용자가 지운 값이 되살아납니다.

로드는 해당 범위의 노드를 새로 생긴 것으로 보며 자동 규칙의 기준도 비웁니다. resetSubtree는 그 범위만 새 수명으로 취급하므로 범위 밖 원천 injectTo를 재발화시키거나 형제의 상태·misfit·진단을 초기화하지 않습니다. 범위 안 원천이 밖 대상을 쓰는 주입은 허용합니다. 로드 범위 밖의 나감은 일반 보존 정책을 유지합니다. 에지와 승자 세부는 [derive](../derive/DETAIL.md)에 둡니다.

### SETTLE-005 — 채움은 생김에 한 번 적용합니다

공유 노드에 새 선언이 켜지거나 visible만 바뀌는 일은 생김이 아닙니다. 새 노드의 없음에만 node controls.default > fields 층 > fragment 층 > 유효 스키마 default를 적용하고, 같은 층은 작성 순서의 뒤 선언을 고릅니다. 생긴 노드의 unset 후보가 우선하면 채우지 않습니다. 최종 형상에 없는 중간 채움은 철회하지만 이미 적용된 일반 파생 쓰기를 조각 퇴장만으로 철회하지 않습니다.

부모 기본값의 명시 키를 먼저 분배하고 남은 없음인 자손만 채워 자식 default가 명시 입력을 덮지 않게 합니다. 빈 branch 객체는 원본·extras·자손 원본이 모두 없으면 기본값을 받을 수 있지만 통째 값을 보관하는 terminal의 빈 객체는 이미 값입니다. 명시적으로 분배된 배열은 빈 배열도 자신의 default로 늘리지 않습니다. 타입별 빈 값이나 minItems만을 근거로 입력을 만들지 않습니다.

잘못된 종류의 원본을 가진 object·array 조상 아래에서는 로드와 일반 쓰기 모두 자손 채움을 막습니다. null을 빈 그릇으로 바꾸거나, 방출되지 않는 기본값을 조용히 누적하지 않기 위한 조건입니다. 호출자 값이 이끄는 유한 재귀는 허용하지만 원본 없는 동일 청사진의 기본값 확장은 상대 게이트 읽기 범위를 고려한 재귀 예산으로 끊습니다.

### WRITE-013 — 자동 쓰기는 조상의 잘못된 종류를 수리하지 않습니다

명시적인 자식 입력·호출자 쓰기가 투영된 자식 방출을 만들면 잘못된 종류의 조상 source를 해제할 수 있습니다. 같은 값을 다시 쓴 경우도 쓰기의 의도를 보존합니다. 자동 주입·채움은 그 조상 원본을 객체로 바꾸지 않습니다. null을 쓴 호출자의 의도를 파생 규칙이 뒤집지 않게 하며, 종류를 값 변화 여부로 추측하지 않는 이유입니다. 호출자 입력과 default 객체는 불변으로 다룹니다.

### WRITE-098 — 쓰인 원래 입력만 최종 유효 목록으로 다시 해석합니다

쓰기 경계에서는 정적 schemaType·nullable로 해석하고, 전이에서는 이번 진입에서 쓰인 노드의 유효 목록이 좁아졌을 때 원래 받은 입력을 다시 해석합니다. 처음 변환한 값이나 직전 유효 목록을 쓰면 이전 분기에 따라 결과가 달라집니다. 쓰이지 않은 노드는 게이트만 바뀌어도 소급 변환하지 않고 misfit만 다시 판정합니다.

재해석은 전이 쓰기이며 원본과 게이트를 바꾸면 다음 라운드로 이어집니다. 예산 실패의 B에는 정적 경계 해석만 남깁니다. 순수 변환 표와 멱등성은 [behaviors](../behaviors/DETAIL.md)가 소유합니다. 유효 목록 밖 원본을 빈 값으로 수리하거나 입력을 거부하지 않습니다.

### WRITE-079 — 교체 범위는 명시한 쓰기에서 정합니다

Merge는 branch 객체와 평범한 객체 입력이 만나는 자리에서만 키를 합치고, 배열·null·undefined·원시 값·terminal 대상은 그 자리를 통째로 교체합니다. 입력이 명시한 undefined는 없음이며 extras에도 같은 규칙을 적용합니다. 비활성 선언도 받은 범위에 따라 분배하되 아직 없는 노드를 만들거나 그 규칙을 실행하지 않습니다.

여러 출처 배치는 각 원래 쓰기의 교체 범위만 지우며 합성한 루트 값 전체를 교체 범위로 보지 않습니다. 그렇지 않으면 무관한 형제의 보유 원본이 사라집니다. 구조 동사와 통째 쓰기의 동등성도 이동 후보의 보유 원본이 새 선택에 영향을 주지 않는 조건에서만 성립합니다.

### VALUE-031 — 비활성 원본의 수명과 왕복의 한계

형상에서 빠짐과 값 삭제를 구별합니다. 기본은 원본 보존이고, 원본을 지우는 길은 선언한 나감 정책, 로드·전체 교체의 누락 범위, 명시적인 없음 쓰기, 배열 자리의 실제 소멸입니다. 제출 뒤 자동 파기는 두지 않습니다. core는 제출을 소유하지 않으며, 제출 성공만으로 값을 지우면 호출자가 보존 의도를 통제할 수 없습니다.

비활성 값은 살아 있는 루트·호스트의 경로 JSON 쓰기로 바꾸고 슬롯 overlay에 남깁니다. 떼어진 참조의 쓰기는 현재 값·원본·overlay·커밋에 효과가 없습니다. 공개 참조 수명은 [surface](../../surface/DETAIL.md)의 계약을 따릅니다. 비활성 노드의 재계산 엔진이나 cleanup 유예 쓰기 창을 만들지 않습니다.

저장한 출력의 새 로드가 편집 트리의 원본·형상·정합 상태까지 복제한다고 약속하지 않습니다. 차이는 비활성 값 제외, 투영과 배열 빈자리 채움, 형 정규화·유효 목록 재해석, 로드 자동 쓰기, 선언 키·extras 순서에서 생깁니다. 투영 자체의 정의는 [behaviors](../behaviors/DETAIL.md)에 두며, 다음 조건은 정착의 왕복 한계입니다.

| 조건 | 편집 트리와 출력으로 새로 로드한 트리의 차이 | 유지 이유 |

### WRITE-094 — 출력의 재입력은 원본 복제가 아닙니다

setValue(getValue())의 멱등은 방출·채움·에지에 관한 것입니다. 첫 호출은 잠복 원본과 투영으로 빠진 원본을 지울 수 있고 다음 같은 호출부터 그 변화도 없습니다. 보존 원본까지 유지하려고 출력에서 원본을 역추정하지 않습니다. 호출자가 현재 출력만 남기려면 자동 쓰기를 억제한 전체 교체를 사용합니다.

### WRITE-021 — 투영은 편집 이력과 무관합니다

손대지 않은 값만 omitEmpty·omitTrailing을 건너뛰는 옵션을 두지 않습니다. 방출은 현재 상태의 투영이어야 같은 값의 출력이 편집 여부에 따라 달라지지 않습니다. 첫 편집 전까지 입력을 그대로 방출하는 별도 경로도 기본값·미선언 키·투영이 첫 입력에서 갑자기 바뀌게 하므로 두지 않습니다. 자동 쓰기 억제는 선언된 쓰기를 막는 것이며 투영을 끄는 선택이 아닙니다.

### WRITE-031 — 나감 정책은 마지막 살아 있던 선언을 읽습니다

unsetOnInactive는 node > fields > fragment > Form의 세부 우선순위이며 같은 층의 선언 가운데 하나라도 keep이면 보존합니다. 되돌릴 수 없는 삭제에는 같은 층의 동의가 필요합니다. 선언과 식 값은 마지막 살아 있던 커밋의 것이며 나감을 일으킨 새 입력으로 정책을 다시 평가하지 않습니다.

함께 나가는 가장 가까운 조상의 명시 정책을 상속하되 자손 자신의 명시 keep이 이깁니다. 살아 남는 조상의 정책은 상속하지 않습니다. 공유 노드가 남아도 선언만 나가면 그 선언 범위의 정책을 적용하고, 이때 extras는 지우지 않습니다. 이미 비활성인 자손도 함께 나가는 조상의 정책 대상이지만 자신의 보존 선언은 유지합니다. 실제 아이템 소멸과 로드 범위의 교체는 gate exit가 아닙니다.

### NODE-065 — 슬롯은 후보 원본을 보유하며 직전 형상이 아닙니다

호스트는 나간 발생을 선언 엔트리별 슬롯에 보유하고, 비활성 JSON 쓰기는 그 발생을 고치지 않는 overlay에 둡니다. 같은 주소의 종류는 union fold까지 포함한 토큰과 청사진 발생으로 구별합니다. 재진입은 source·extras·선언 밖 값·자손 슬롯을 새 그래프로 복제하여 부모·주소·등록을 다시 결합하고 슬롯과 overlay를 소비합니다. 상호작용·오류·배달 이력은 복제하지 않으며 배열 itemKey는 새로 발급합니다. 옛 공개 객체의 재사용은 옛 구독과 UI identity를 새 수명에 연결하므로 허용하지 않습니다.

슬롯은 방문한 엔트리에만 생기며 재귀 템플릿의 선언 가능성 전체를 실체화하지 않습니다. 원본 보유량은 방문 엔트리·실제 값 깊이·overlay·읽은 목록에 비례하고 전역 이력 journal을 두지 않습니다. 삽입은 엔트리당 평균 O(1)이지만 분리와 등록 해제는 이탈 서브트리, 재진입 복제는 실제 보유 서브트리 크기에 비례합니다. 나감 전체가 O(1)이라는 약속은 하지 않습니다.

비활성 자손을 새 부모로 복제하지 않고 공유하면 그 자손의 parent 연결이 옛 호스트들을 계속 붙잡아 보유량이 전환 이력에 비례합니다. 따라서 중첩 슬롯도 재귀 복제하며 수명마다 새 공개 손잡이만 덧씌우는 방식으로 대체하지 않습니다.

### VALUE-037 — 정합 경고와 검증 실패를 구별합니다

misfit은 현재 원본과 유효 형의 계산 결과이며 검증 통과 여부가 아닙니다. 원본·유효 스키마가 바뀐 노드에서 다시 판정하고, 꺼짐에서 켜질 때 경고합니다. 계속 켜진 채 다른 잘못된 값이 와도 반복하지 않으며 재진입·로드 범위 초기화·게이트 좁힘으로 새로 켜지면 다시 알립니다. 값이 그대로여도 유효 스키마 변경이 이 관측을 전달하므로 입력 수정과 형상 제약 변경을 구별할 수 있습니다.

통째 객체·배열 내부의 JSON 부정합 점검은 개발 모드에서 원본 참조가 바뀐 커밋에만 수행하고 경고 중복 수명은 폼 수준 로드입니다. 프로덕션에서 그 내부를 정규화하거나 점검한다고 약속하지 않습니다. 통째 값의 해석 한계는 behaviors, 경고의 공개 코드·기록 형은 errors가 소유하며 실행 실패를 입력 오류로 대신하지 않습니다.

### WRITE-087 — 비활성 읽기는 필요할 때 공표합니다

inactiveValues는 호스트의 첫 읽기에서만 원본·overlay를 합성하고 문서 순서로 정렬한 동결 목록을 만듭니다. 같은 주소에서는 첫 종류만 공표하며 살아 있는 경로 자체는 숨기되 그 아래 비활성 자손은 계속 열거합니다. 변하지 않은 항목·목록 참조는 재사용하지만 재진입·재이탈한 항목의 과거 객체를 되살리지 않습니다. 커밋마다 전역 비활성 목록을 복사하면 읽지 않는 쓰기도 보유량 전체의 비용을 치르게 됩니다.

떼어진 호스트는 자신이 보유한 자손 슬롯으로 마지막 커밋 목록을 읽습니다. 첫 읽기는 열거 원본 수와 정렬 비용, 변화 없는 반복 읽기는 O(1)이며 복제·materialize를 쓰기 비용에서 숨기지 않습니다.

### VALUE-040 — 지움 배열은 keep 원본만 압축 보존합니다

지움과 함께 나가는 배열은 명시 keep 원본을 가진 아이템만 원래 순서로 압축하며 후보 소유 범위와 무관하게 중첩 배열·이미 비활성인 keep에도 적용합니다. 빈 배열 자체의 명시 keep도 원본으로 셉니다. inactiveValues와 재진입은 압축 색인을 사용하고, 조건이 아직 거짓인 keep은 그 자리의 슬롯에 남깁니다. 후보별 종류를 첫 후보에 합성해 원본을 잃지 않습니다.

keep 선언 부재가 청사진으로 증명되면 아이템별 정책 계산을 생략합니다. 실제 압축 보존은 나간 최상위 보유 서브트리의 사적 복제를 필요로 하므로 시간·공간은 그 크기에 비례합니다. 복원 시 공유 분배 기록의 자리 이름 조회가 배열 순회이므로 생존 n개인 압축 배열의 복원에는 O(n²) 한계가 있습니다. 버린 보유 서브트리는 정리하고 모든 옛 참조의 쓰기는 무효입니다.

### VALUE-043 — 나감 값 해석은 동기이며 명시 입력이 우선합니다

inactiveValue와 onInactive는 정상 보존 gate exit에서 직전 커밋의 방출 값·context를 읽습니다. 스키마는 이번 계산에서 보존한 원래 스키마를 사용합니다. 문자열 노드에서 식과 리터럴을 구별할 수 없어 inactiveValue를 식 문자열로 컴파일하지 않으며 의존 추적도 하지 않습니다. 여러 콜백은 등록 순서로 호출하고 마지막 non-undefined 결과를 채택하며, 모두 undefined일 때 선언 값을 사용합니다. 하나라도 던지면 그 노드 override 전체를 취소하고 실패를 기록합니다.

load/reset 범위·소멸·clear 나감·들어오기만 한 발생·던진 게이트의 나감·자동 쓰기 억제·예산 복원에는 적용하지 않습니다. 다른 위치의 일반 실패만으로 정상 보존 나감까지 일괄 취소하지 않습니다. 원본 보유 뒤 결과 overlay는 조상 다음 자손 순서로 적용하며, 뒤 바퀴의 지움 조상 아래 자손 결과를 되살리지 않습니다.

호출자 JSON이 그 위치를 명시하면 resolver보다 우선합니다. 조상 whole은 생략 자손까지 덮고 Merge는 실제 키만 덮으며 배치에서는 그 범위들의 합집합입니다. 뒤의 빈 Merge나 자동 쓰기는 앞선 명시 whole을 취소하지 않습니다. 배열 이동과 겹치면 값·dataPath·parentValue는 옛 커밋 주소에서 읽고 결과는 현재 보존 주소에 씁니다.

resolver 안의 쓰기는 중첩 정착을 열지 않고 무시합니다. React cleanup 시점은 매크로태스크와 대응하지 않으므로 타이머로 떼어진 쓰기를 잠시 허용하는 대안을 사용하지 않습니다. 콜백 등록은 인스턴스 수명이므로 새 인스턴스에는 다시 등록합니다.

### WRITE-085 — 되돌림 입력과 출력 기준을 구별합니다

로드 스냅숏은 호출자가 실은 입력이며 defaultValue·resetSubtree의 원천입니다. 경로 로드는 그 위치 위의 조상만 복사하고 같은 값이면 참조를 유지합니다. 일반 쓰기는 스냅숏의 값을 바꾸지 않습니다. 배열 구조·길이 정렬의 예외와 비용은 [배열 소유 계약](arrangeFieldNodeItems/DETAIL.md)의 WRITE-085·WRITE-095에 둡니다.

### VALUE-044 — 차이는 마지막 루트 로드 출력의 같은 위치와 비교합니다

loadBaseline은 마지막 루트 로드 커밋의 최종 root.emit 참조이며 undefined 출력도 미설정과 구별합니다. 자식 reset과 일반 쓰기는 기준을 옮기지 않습니다. isDivergent는 현재·기준 출력의 같은 경로를 비교하므로 배열 이동 뒤에는 아이템을 따라가는 defaultValue로 reset해도 true일 수 있습니다. Edited는 입력 이력이고 Divergent는 출력 차이이므로 서로 대신하지 않습니다.

커밋 전에 중단한 로드는 기준을 유지하고 커밋 뒤 보고되는 실패는 degraded 출력을 기준으로 삼습니다. 첫 루트 로드 전과 detach 뒤에는 false입니다. 읽기는 두 경로의 깊이와 바뀐 값의 비교 비용이며 Object.is로 입력 값들을 메모해 반복 비교를 생략합니다. 쓰기에 기준 비교를 더하지 않는 대신 기준은 로드 뒤 교체된 출력 부분을 보유합니다. 경로 메모도 이동 시 다시 결합하며 일시 정착 값으로 한 읽기가 다음 커밋의 답을 고정하지 않게 합니다.

### CONTROLS-082 — 로컬 잠금과 표시는 서로 다른 결합입니다

잠금 readOnly·disabled는 OR, active·visible은 AND로 결합합니다. 한 선언의 false가 다른 선언의 잠금을 풀거나 true가 다른 선언의 숨김을 되살리지 않게 합니다. 표준 readOnly도 주석 덮어쓰기가 아닌 잠금입니다. 조상 상태를 자손에 상속하지 않으며 fragment·fields는 명시 대상에만 적용합니다. Form 전체 잠금의 집행은 렌더 계층이 소유하고 core의 프로그램 쓰기·자동 쓰기를 거부하는 근거로 사용하지 않습니다.

active는 형상과 방출에서 제외하지만 visible은 표시만 가리고 원본·방출을 유지합니다. 켜진 fragment 제어는 그 조각이 직접 선언한 호스트의 직계 자식에만 적용하며, 더 깊은 자손이나 다른 선언이 유지하는 공유 노드를 암묵적으로 지우지 않습니다. 상태 제한을 일반 주석의 뒤 선언 우선 덮어쓰기와 혼용하지 않습니다.

### BLUEPRINT-056 — 메모는 순수 판정의 입력에 귀속됩니다

active·if·discriminator는 발생별 reads와 evaluate 계약을 공유합니다. 같은 입력을 Object.is로 확인할 때만 성공 boolean을 재사용하고 던진 평가·실패한 guard 준비는 메모하지 않습니다. 동적 context callback은 매번 실행합니다. if·discriminator의 전체 입력 view는 투영 객체와 extras identity가 이어지는 동안만 공유하고 앞선 공표로 바뀌면 뒤 게이트부터 다시 만듭니다.

if의 읽기를 좁히는 허용 범위는 객체 type·properties·required·dependentRequired와 allOf·anyOf·oneOf·not 조합이며, 속성 값 제약은 type·const·enum·수 범위·multipleOf·문자열 길이·pattern과 그 논리 조합입니다. ref·patternProperties·additionalProperties·propertyNames·unevaluated 계열·중첩 조건·미지 키워드는 전체 호스트 읽기로 후퇴합니다. 분석은 guard를 실행하지 않으며 guard에는 항상 현재 전체 view를 전달합니다. 읽기 증거는 메모·일관성·표의 자격일 뿐 판정을 대신하지 않습니다.

### SETTLE-052 — 정적 준비물과 이전 동적 형상을 구별합니다

항상 활성인 정적 자식의 schema·ID·소유·주소 증인과 baseline은 호스트 수명에 한 번 준비할 수 있습니다. 이는 상태에 의존하지 않는 불변식이며 동적 엔트리는 매 정착 고정 baseline에서 다시 선택합니다. 직전 동적 목록은 재사용·나감 비교에만 씁니다. 커밋된 structure·children·값을 제자리에서 고치지 않고, 사적 동적 view의 선택이 끝난 뒤 일반 자체 속성 형상만 공표합니다. 예외 때는 직전 확정 structure로 복원합니다.

load·reset·rebuild·재진입·입력 분배·배열 이동·주소/청사진 변경·overlay·relocation·실패에서는 준비물을 버리거나 일반 경로로 후퇴합니다. 보유량은 준비된 호스트의 정적 폭 S와 게이트 G에 비례합니다. 구성원이 같다는 증거가 있으면 전체 복사를 생략하지만 실제 구성원이 바뀌면 O(S+K) 공표 비용은 남습니다. required 목록 identity가 같아도 새 진입 자식은 계산하고, 목록이 바뀌면 기존 자식도 다시 계산합니다.

### SETTLE-051 — 세대 표식은 보수적인 전체 폼 증명이 필요합니다

정적 첫 로드 capability가 있는 폼의 독립 callerReplace·input 전체 쓰기만 경로 장부 대신 세대 표식을 사용합니다. 게이트·식·파생·watch·가상·재귀, load·automatic·partial·batch·visit, 보유 원본·미확정 슬롯 변경·misfit이 있으면 일반 경로입니다. 자격은 현재 폼 전체 단위이며 하위 트리만 보고 완화하지 않습니다.

### settle-gate-table-selection — 세 모드의 같은 관측과 선택 상한

호스트 표는 직접 선택 계획과 불변 baseline 단말 읽기가 증명된 경우에만 만듭니다. 고유 이름·단일 선언·잎·가상 아님·호스트 안 게이트 등 기본 자격을 유지하고, 제한된 불변 discriminator 키의 다중 선언만 별도 증명으로 허용합니다. 여러 oneOf·anyOf 또는 조건이 있는 다중 allOf가 대상이며 단독 if는 일반 선택입니다. 표·부적격 null 결정은 청사진 호스트의 파생 수명에 묶고 live 값·노드·판정을 정적 표에 보유하지 않습니다.

리터럴 표는 비실행 인식기가 식 전체의 동등 비교를 증명한 결과와 유한 원시 discriminator 태그만 사용합니다. 식의 일부 문자열 일치나 실행 샘플로 자격을 추정하지 않습니다. 인식기의 문법·허용 리터럴과 표 키 비교의 동등성 조건은 [청사진 인식기](../blueprint/compileBlueprintExpressions/recognizeEqualityExpression/DETAIL.md#equality-map-equivalence--표-키와-엄격-비교의-동등성)가 소유합니다.

라운드 자격은 준비된 객체 호스트 계획, 표 모드, 호스트부터 루트까지 source 부재, 감시 단말 경로의 dirty 부재를 모두 요구합니다. 못 증명하면 일반 평가입니다. 루트는 첫 선언 자리, 비루트는 첫 해당 단계 자리에서 읽어 그 라운드 안에서만 공유합니다. 일반 술어 묶음은 연속한 단계 구간일 때만 표로 적용하고 던지면 뒤 단계는 원래 자리 평가로 돌아가 재시도와 오류 순서를 보존합니다.

방문 집합은 baseline·표 밖 단계·켜진 칸에 직전 자식·현재 구조·정확한 대기 나감·분배 입력의 정리 단계를 더한 오름차순입니다. 미방문 단계는 꺼져 있고 원래 실행도 아무 효과가 없는 경우뿐입니다. 같은 selectEntryStep 본문을 공유하는 이유는 진입·되살림·스키마·즉시 계산의 의미가 표 경로와 갈라지지 않게 하기 위해서입니다. 루트 선언 표도 자격을 별도로 증명하고 활성 목록·다중 활성 경고를 보존합니다.

마운트는 분기와 식이 있는 청사진의 계획을 load 전에 한 번 준비합니다. 다른 일반 load는 이미 준비된 계획만 사용하며 미준비 계획 구성은 첫 비적재 선택까지 미룹니다. 이는 첫 쓰기의 O(엔트리·게이트·리터럴) 준비 비용을 마운트에 두는 선택이며 숨은 생성자 효과로 만들지 않습니다. load는 사전 공표와 확인 바퀴를 유지합니다. 표 적용의 선택 비용은 활성·정리 단계와 표 밖 게이트에 비례하지만 표 준비·실제 guard·불투명 전체 입력·공표 사본 비용까지 상수라고 약속하지 않습니다.
