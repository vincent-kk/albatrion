# validation — 검증 판정과 표시의 경계

## Purpose

작성자가 정한 검증의 의미를 폼의 편집·렌더링 방식과 독립적으로 유지합니다. 검증기에 건네는 사본과 가드의 수명, 판정의 최신성, 오류의 배정과 표시 자격을 소유합니다.

## Boundaries

폼의 모양을 정하는 일과 입력이 유효한지 판정하는 일은 다릅니다. 가드의 답은 정착에 제공하고, 검증 결과의 사건 배달은 요청자가 맡습니다. 화면의 마운트 여부가 판정이나 표시 이력의 수명을 대신하지 않습니다.

### Always do

- 작성 스키마의 의미와 방출 값에 대한 판정을 보존합니다. 표시할 노드를 찾지 못한 오류도 판정에서 잃지 않습니다.
- 검증기와 작성 루트가 공유하는 자원 수명, 각 폼이 소유하는 요청과 실패 보고의 수명을 구별합니다.
- 결과를 배정하기 전에 요청과 커밋의 최신성을 확인합니다. 다른 입력에 대한 답으로 편집 중인 오류를 덮지 않습니다.

### Ask first

- 검증기와 작성 루트의 공유 기준이나 자원의 해제 조건을 바꾸기 전에 합의합니다.
- 판정의 배달 시점, 오류 표시의 대기 조건, 실패를 관찰하는 통로를 바꾸기 전에 합의합니다.

### Never do

- 화면에 맞춘 유효 스키마로 작성 스키마를 대체하거나, 검증 통과를 위해 값을 고치지 않습니다.
- 검증기를 전역 등록소에서 선택하거나, 쓰기·정착·React 계층을 가져와 결과를 직접 배달하지 않습니다.
- 전체 컴파일을 가드 읽기의 선행 조건으로 만들거나 비동기 가드로 정착을 지연하지 않습니다.
