# write — 루트 진입 사슬과 배달 경계

## Purpose

공개 쓰기와 정착 밖 사건을 루트별로 조율합니다. 정착된 값을 동기로 관측하게 하고, 사슬 안의 실패가 남은 통지와 검증 요청을 끊지 않게 합니다. 액션 저장소가 아니라 진입·배달 경계입니다.

## Conventions

- 정착은 상태를 확정하고 이 모듈은 확정된 배달 집합을 소비합니다. 사건 구독으로 엔진 내부 전이를 구동하지 않습니다.
- 입력 출처는 공개 쓰기 옵션과 별도로 전달합니다. 타이핑한 입력을 다시 마운트하지 않기 위한 구분입니다.

## Boundaries

### Always do

- Keep live settings and validation-epoch reads on the binding-only channel; never widen the package surface.
- 파동의 사건과 리스너 목록을 고정하고, 리스너별 실패를 격리하여 남은 배달을 마칩니다.
- 검증 요청을 `onChange`보다 먼저 내고, 오류 기록 전달과 최종 throw는 사슬 끝에 둡니다. 중첩 쓰기의 최신 요청과 커밋을 잃지 않아야 합니다.
- 루트를 인계하면 예산과 수집기를 이어받고 활성 루트에서 종료합니다. 옛 런타임에 열린 사슬을 남기지 않습니다.
- 오류 분류·공개 코드·기록 형은 [errors 계약](../../../errors/DETAIL.md)을 사용합니다.

### Ask first

- 진입 단위, 동기 통지, 되먹임·중첩 상한, 검증 요청과 콜백 순서를 바꿀 때.
- 입력·로드 바인딩 전용 채널을 공개하거나 떼어진 참조의 쓰기 권한을 늘릴 때.

### Never do

- 전체 트리를 다시 비교해 배달 집합을 만들거나 검증 결과 라우팅을 구현하지 않습니다.
- 렌더 수명·플러그인 선택·노드 겉면을 이 모듈로 가져오지 않습니다.
- 오류 관찰자의 반환값으로 원래 실패의 전달을 취소하거나 같은 폼의 쓰기를 재진입시키지 않습니다.
