# objectBehavior — 객체의 두 전략

## Purpose

객체 branch의 자식 합성과 terminal의 통째 값 투영을 한 종류의 계약으로 소유합니다.

## Boundaries

### Always do

- 비객체 원본과 자식 계산을 구별합니다. 자식이 있다는 이유로 명시된 부모 값을 빈 객체로 바꾸지 않습니다.
- 키 순서와 같은 결과의 참조를 지킵니다. 최적화의 증명이 없으면 일반 합성으로 돌아갑니다.

### Ask first

- 전략 경계, 비객체 원본 방출 또는 객체의 키 순서를 바꿀 때
- 통째 객체의 내부를 해석하거나 정규화하도록 경계를 넓힐 때

### Never do

- branch와 terminal을 별개 종류로 나누지 않습니다. 같은 객체 종류의 계산과 보조가 갈라집니다.
- 투영에서 자식을 생성하거나 부모 원본을 승격·교정하지 않습니다. 쓰기와 채움은 정착의 책임입니다.
