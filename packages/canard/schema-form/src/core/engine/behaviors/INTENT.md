# behaviors — 종류별 계산 행 경계

## Purpose

종류별 계산 행의 조합과 여러 종류가 재사용하는 계산 보조를 소유합니다. 상태 확정과 배달 순서는 호출자가 소유합니다.

## Conventions

- 독립 경계는 종류이며, 한 종류의 branch·terminal은 그 안의 전략입니다.
- 변환 정책은 [unionBehavior 계약](unionBehavior/DETAIL.md)을 정본으로 삼습니다. 입력 경로마다 해석을 복제하지 않기 위한 경계입니다.

## Boundaries

### Always do

- 같은 뜻의 칸은 함수 객체 하나를 공유하고, 행의 칸 순서를 일치시킵니다. 호출자에 종류별 예외가 퍼지지 않아야 합니다.
- 보조는 실제 소비자의 가장 낮은 공통 소유자에 둡니다. 종류 하나의 구현을 공용 계약으로 넓히지 않습니다.

### Ask first

- 종류·전략 조합이나 행의 칸을 늘려 소비자의 호출 계약을 바꿀 때
- 노드별 실행 객체나 새로운 변환 설정을 도입해 공유 비용·입력 의미를 바꿀 때

### Never do

- 행에서 원본 쓰기·자식 생성과 폐기 확정·되돌림·통지를 하지 않습니다. 정착과 배달의 순서를 우회하게 됩니다.
- 종류 모듈이 상위 동작 표·settle·write·validation·surface를 타입으로도 가져오게 하지 않습니다. 계산에서 호출자로 향하는 역의존을 막습니다.
