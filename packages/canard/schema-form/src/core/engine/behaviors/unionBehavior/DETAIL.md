# unionBehavior 계약

## Requirements

union은 여러 종류의 값을 한 터미널에서 받기 위한 계약입니다. 선언 순서로 형을 선택하거나 통째 객체·배열의 내부를 실행하는 장치가 아닙니다. 단일 종류도 같은 제한 해석의 특수한 경우로 취급하여 유입 경로와 type 배열 순서가 값을 결정하지 않게 합니다.

## API Contracts

해석 구현은 부모의 공유 parse에 두고 이 문서가 변환 정책을 소유합니다. 허용 집합과 종류의 결정은 [blueprint 계약](../../blueprint/DETAIL.md), 정적·유효 목록의 선택과 재해석 시점·misfit 계산은 [settle 계약](../../settle/DETAIL.md)이 소유합니다. 행은 주어진 spec만 해석하며 원본이나 경고등을 쓰지 않습니다.

문자열 입력 완료는 [stringBehavior 계약](../stringBehavior/DETAIL.md)을 공유합니다. 초안의 표시·보류·비우기와 DOM 표현은 [FieldInputUnion 계약](../../../../fieldInputs/fieldInputDefinitions/FieldInputUnion/DETAIL.md)에 둡니다. 순수 해석 함수를 공개 입력 API로 넓히는 결정과 혼동하지 않습니다.

## Acceptance Criteria

### WRITE-052 — 형 정규화는 값 교정의 제한된 예외입니다

뜻을 보존하는 명시적 변환만 수행합니다. 문자 제거, 정수 자르기, 빈 값 치환, truthy/falsy 강제 변환으로 검증 통과를 만들지 않습니다. 바꿀 수 없는 입력을 삭제·대체·거부하면 작성자가 입력 오류를 관찰하고 수정할 기회를 잃습니다.

### WRITE-075 — 변환 범위를 닫아 둡니다

| 대상 | 허용하는 변환 | 제한의 이유 |
| --- | --- | --- |
| number | 앞뒤 공백을 뺀 전체가 JSON 수 표기인 문자열을 유한수로 변환 | 일부 문자만 읽거나 비유한 값을 만들지 않습니다. 소수부·지수부 없는 정수 표기는 안전 정수여야 반올림으로 다른 정수가 되지 않습니다. |
| integer | number 변환이 가능하고 결과가 안전 정수인 문자열 | 소수를 자르거나 정수 변환에서 정밀도를 잃지 않습니다. 이미 수인 값의 멤버십과는 별개입니다. |
| string | 유한수·불리언의 문자열 표현 | 객체·배열·null을 문자열화해 데이터 구조를 잃지 않습니다. |
| boolean | 정확한 문자열 true·false와 수 1·0·-0 | JavaScript 진릿값 규칙으로 임의 문자열이나 수를 참으로 만들지 않습니다. |
| object·array·null | 변환하지 않음 | JSON 파싱이나 컨테이너 생성으로 입력에 없던 구조를 만들지 않습니다. |

이는 검증기 플러그인을 호출하는 변환이 아닙니다. 플러그인의 coerce 설정이 편집 원본을 바꾸는 통로가 되지 않게 합니다.

### WRITE-076 — 해석은 선택적으로 건너뛰지 않습니다

형 정규화는 행의 기본 해석이며 끄는 옵션이 없습니다. 별도 쓰기 옵션이나 스키마 키를 암묵적인 변환 스위치로 사용하면 같은 노드가 호출 경로마다 다른 값을 받습니다. 변환을 끄는 기능이 필요하면 Form 단위 정책으로 설계하고 먼저 경계를 합의합니다.

### WRITE-084 — 해석 실패도 정상 반환입니다

interpret는 순수하고 모든 입력에 결과를 돌려주며 던지지 않고 멱등입니다. undefined와 null은 그대로 유지하고, 허용 멤버이면 원본 참조를 유지합니다. nullable이 아닌 null도 여기서 비우지 않습니다. 해석 불가·모호성은 검증 실패나 실행 예외로 바꾸지 않고 원본을 남겨 정착이 정합 상태를 계산하게 합니다.

### WRITE-093 — 유일한 변환 결과만 채택합니다

이미 멤버인 값을 먼저 보존하고, 그 밖의 입력만 각 종류로 변환하여 성공한 결과를 === 기준으로 구별합니다. 종류가 여럿 받아도 결과가 하나면 채택하고, 결과가 없거나 서로 다르면 원본을 보존합니다. 후보 컨테이너를 할당하지 않아 쓰기마다 목록 크기에 비례하는 임시 객체가 생기지 않습니다. 수치 문자열을 number와 integer가 같은 수로 받는 경우를 모호성으로 잘못 거부하지 않습니다.

string·boolean을 포함하고 number·integer를 제외하는 목록에서 수 0·-0·1은 문자열과 불리언이라는 서로 다른 결과를 냅니다. object·array의 포함 여부를 조합한 동점 12건은 선언 순서로 승자를 고르지 않습니다. 그 외 변환은 문자열의 수 표기와 true·false 표기가 겹치지 않고, 불리언은 string만 받으므로 같은 충돌을 만들지 않습니다.

### union-rule-a — 목록 순서와 반복은 결과를 바꾸지 않습니다

스칼라 kind와 원소 하나인 목록의 결과를 일치시키고, 목록 순열·반복 해석·동점에서 WRITE-093을 유지합니다. 순서를 바꾸거나 한 진입의 해석을 반복했을 때 값이 달라지면 게이트와 쓰기 이력에 의존하는 상태가 됩니다.

### VALUE-037 — 통째 값은 불투명한 잎입니다

방출 정책이 생략하지 않는 객체·배열 원본은 같은 참조로 방출하고 내부를 정규화하지 않습니다. omitEmpty는 값 전체를 보며, union의 {}·[]가 생략되면 배열 아이템의 방출 자리는 [arrayBehavior의 VALUE-034](../arrayBehavior/DETAIL.md)를 따릅니다. 내부 JSON 부정합의 진단과 직렬화 뒤 검증 한계는 settle·[validation 계약](../../validation/DETAIL.md)이 소유합니다.

### union-source — 해석할 목록과 해석 시점을 구별합니다

게이트로 유효 목록이 바뀌어도 쓰이지 않은 값은 이 행이 소급 변환하지 않습니다. 문자열 `"2"`를 유지한 채 number 목록에 맞지 않게 된 트리와, 그 방출을 새로 로드해 수 `2`로 해석한 트리는 값과 검증 결과가 다를 수 있습니다. 이 차이를 없애려고 게이트 변화만으로 interpret를 호출하면 사용자 입력을 자동 교정합니다. 두 단계 해석·전이 예산·저장 왕복의 정책은 settle 계약에 둡니다.

### TEST-078 — 종류 수와 문자열 길이를 비용에서 구별합니다

해석은 허용 종류를 순회하므로 종류 수에 비례하며, 수 문자열 판정은 입력 길이의 비용도 가집니다. 후보 배열을 만들지 않는 WRITE-093의 선택은 쓰기마다 임시 컨테이너가 생기는 일을 막지만, 해석 전체가 비트 연산 한 번이나 무할당이라는 보장은 아닙니다. 통째 객체·배열은 멤버십을 위해 내부를 순회하거나 복사하지 않아 크기에 비례하는 비용이 검증·표시 경로와 섞이지 않습니다.

## Last Updated

멤버십·변환 허용 범위·모호성 판정·통째 값의 투영 또는 해석과 효과의 경계가 바뀔 때 갱신합니다.
