# Validation scheduling contract

## Requirements

engine의 독립 자식 fractal로, 검증·레코드·정착·쓰기에서 어느 것도 가져오지 않습니다. 마운트 바인딩과 쓰기 검증이 같은 화면 뒤 예약 책임을 소비하므로 두 정책을 이곳에 모읍니다. winglet 실행 수단만 소비하고 clock은 호출자가 넘깁니다.

## API Contracts

- V1 배치: 주기 구현은 utils/cadence, 그 보조는 cadence/utils, 형은 types, 일회성 슬롯은 utils/slot에 두어 함수 이름 폴더·파일/폴더 혼합을 없앤다. 하나의 frame loop가 callback wiring을 소유하고 순수 결정 함수가 phase·요청 여부·마지막 실제 시작 이후 경과로 다음 행동을 고르므로 helper import 순환이 없다.
- 모든 시작 실행 뒤에는 watch로 돌아가 cap이 마지막 요청을 포함했으면 다음 quiet 프레임에서 추가 실행하지 않는다. watch→carry 첫 프레임도100ms 상한을 검사하며, 실제 시작한 run만 cap clock을 갱신한다. 디바운스는 FieldInput이 소유하고 엔진은100ms 지각 문턱 아래의 실시간감을 지킨다.

- scheduleValidationSlot(run)은 기존 일회성 화면 뒤 슬롯입니다. 호출 시 프레임 요청 또는 취소 API가 없거나 문서가 숨겨져 있으면 매크로태스크로 실행합니다. 그 밖에는 프레임 뒤 매크로태스크와100ms 타이머를 경주시켜 정확히 한 번 실행하고 남은 핸들을 취소합니다. 마운트 경로는 이 정책을 유지합니다.
- createValidationCadence(run, now)는 request와 cancel을 반환합니다. run은 실제 검증 시작 여부를 boolean으로 반환하며 비동기 판정 완료를 기다리지 않습니다. false는 마지막 시작 시각을 옮기지 않습니다. now는 밀리초 단조 시간 입력이며 내부에서 전역 시계를 읽지 않습니다. 100ms 상한은 이름 붙은 상수이며 옵션이 아닙니다.
- idle의 요청은 다음 프레임 뒤 매크로태스크에서 선행 실행합니다. 실행 직전에 도착한 요청도 최신 실행에 포함되며 연속 입력으로 세지 않습니다.
- 실행 시작 이후 다음 프레임을 관찰합니다. 그 시작 이후 요청이 없었으면 idle로 돌아갑니다. 요청이 있었으면 carry로 들어가고 매 프레임 이전 프레임 이후 요청이 있으면 실행하지 않고 이월합니다.
- carry의 첫 무요청 프레임 뒤에 후행 실행하고 다시 watch합니다. 마지막 입력으로부터 약1~2프레임 뒤이며 한 키·한 작업 안 여러 쓰기는 한 번 실행합니다. 최소 두 프레임 떨어진 키는 키마다 실행합니다.
- carry 중 마지막 자동 실행 시작으로부터100ms가 지났으면 입력이 계속되어도 그 프레임 뒤 실행하고 watch로 돌아갑니다. 첫 입력 시각을 기준으로 삼지 않습니다.
- 요청 시 프레임 API가 없거나 문서가 숨겨져 있으면 매크로태스크 한 번으로 합치며 carry를 하지 않습니다. 예약 뒤 프레임이 오지 않으면100ms 타이머로 남은 요청을 한 번 실행하고 idle로 돌아갑니다. 이미 실행한 watch에 새 요청이 없다면 중복 실행 없이 idle로 끝납니다.
- cancel은 영구 취소이며 남은 프레임·타이머·매크로태스크와 늦은 콜백을 모두 무효화합니다. 프레임 관찰은 스트림의 종료를 판정한 뒤 남지 않습니다.
- 호스트가 소유한 프레임·가시성 API는 예약 함수에서 호출 시점에 읽는 경계 효과입니다. setImmediate와 MessageChannel이 모두 없는 호스트는 winglet 모듈 로드 제약으로 지원하지 않습니다.

## Acceptance Criteria

### scheduling-slot — 일회성 화면 뒤 실행

- 프레임 전 실행0, 프레임 뒤 실행1,100ms 경주 단일 실행, 전역 취소 함수 정리 뒤에도 예약한 호스트의 취소 함수를 사용합니다.

### scheduling-cadence — 연속 입력 주기

- 격리·연속·실행 전 추가 요청·100ms 상한·숨김/API부재·정지 프레임·취소를 제어 프레임과 주입 시계로 검증합니다. 마지막 실행 기준 상한과 후행 실행을 구별합니다.
