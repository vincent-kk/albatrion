# evaluateDeriveRound 계약

## Requirements

한 라운드가 돌려주는 후보는 적용 명령이 아니라 판정 결과입니다. 기준과 선언 결합은 [derive](../DETAIL.md), 원본 적용·자동 쓰기 억제·비수렴 처분은 [settle](../../settle/DETAIL.md)이 소유합니다. 결과를 결정하는 동안 노드 원본을 변경하지 않습니다.

## API Contracts

동적 대상의 실패와 식 실패는 판정 자료로 돌려주며 분류·공개 코드는 [errors](../../../../errors/DETAIL.md), 정착 후 보고 시점은 [write](../../write/DETAIL.md)를 따릅니다. 런타임 대상 해석을 청사진의 정적 오류로 옮기면 실행하기 전에는 알 수 없는 반환 경로를 잘못 거부합니다.

## Acceptance Criteria

### derive-rank — SETTLE-004: 순위는 라운드를 넘어 유지합니다

종류 순위는 unsetValue > derived > injectTo > 채움입니다. 같은 종류는 원천의 트리 전위 문서 순서에서 뒤쪽, 같은 원천은 조각 controls < 부모 fields 항목 < 노드 자신, 같은 층은 뒤 선언·뒤 반환 항목이 이깁니다. 충돌 자체는 경고하지 않습니다. 이전 라운드에서 더 높은 종류가 적용된 대상에는 낮은 후보를 버리고, 현재 승자와 진 후보 모두 에지를 소비합니다. 그렇지 않으면 진 규칙이 다음 라운드에 발화하여 선언 순위가 무의미해집니다. 정착 상한의 계산·적용은 settle이 담당합니다.

### derive-edge — SETTLE-028: 매번 덮는 규칙을 만들지 않습니다

derived는 의존 튜플의 에지에서만 후보를 만드므로 대상의 사용자 편집은 다음 의존 변화까지 남습니다. 매 입력마다 덮는 레벨 규칙은 타이핑한 입력을 다시 마운트시키며, 쓴 주체별 예외는 같은 개념에 다른 방아쇠를 만듭니다. 따라서 둘 다 사용하지 않습니다. unsetValue는 거짓→참에서 undefined 쓰기를 만들고 참→거짓에서는 복구하지 않습니다. 로드·새 발생의 참도 발화하며 형상 밖 원천은 평가하지 않습니다. 일반 쓰기와 로드의 기준은 [derive](../DETAIL.md)의 SETTLE-048을 따릅니다.

### CONTROLS-084 — 로드의 주입은 작성자의 규칙을 적용합니다

injectTo는 원천 방출의 에지에서 발화하고 로드 범위의 원천은 새 에지로 평가하므로 서버가 준 대상값도 덮을 수 있습니다. 로드에서 건너뛰면 초기 복사·기본 시딩이 원천의 다음 편집까지 비며, reset 전 이력과 비교하면 같은 로드가 과거에 따라 달라집니다. 일반 전체 교체를 로드로 간주하지 않아 같은 값을 쓰는 호출의 멱등성을 유지합니다. 대상만 켜지는 것은 원천 변화가 아니므로 다시 발화하지 않습니다.

### derive-inject-to — CONTROLS-079: 반환이 다른 노드에 쓰는 주소입니다

함수는 원천 emit과 이번 라운드의 맥락을 읽고 반환 경로를 원천 기준으로 풉니다. 반환 객체의 키 삽입 순서·튜플 배열의 차례를 유지하며 같은 대상의 뒤 항목이 이깁니다. undefined 항목과 null·undefined 반환은 쓰지 않되 에지는 소비합니다. @는 대상이 아니며 선언된 비활성 대상은 잠복 쓰기 후보가 될 수 있지만 형상 밖 원천의 함수는 부르지 않습니다. 반환은 대상 전체 교체이므로 부분 병합으로 바꾸지 않습니다. null 조상의 보존과 실제 잠복 분배는 settle의 계약입니다. 함수 안의 공개 쓰기는 write의 동기 진입 경계를 사용하며 이 판정의 반환 후보로 가장하지 않습니다.

### derive-inject-failure — 동적 실패는 그 규칙의 후보를 제외합니다

함수 throw·대상 부재·잘못된 가상 쓰기 모양은 그 주입 규칙의 후보 전체를 제외하고 에지를 소비합니다. 앞 항목만 적용하면 반환 순서에 따라 부분 성공한 데이터가 남습니다. 다른 규칙은 계속 판정하여 모든 실패를 돌려주며 원천 경로와 대상 경로를 구별합니다. undefined를 돌려준 derived도 후보 없이 에지를 소비하여 같은 변화로 계속 재시도하지 않습니다.

### derive-array-items — CONTROLS-073: 경로와 fold를 현재 발생에서 풉니다

아이템의 상대 경로는 현재 자리의 형제를 읽고, 동적 배열 대상은 살아 있는 아이템의 청사진을 우선합니다. 부재 자리에서는 작성 순서의 첫 후보와 형제 후보 목록을 판정 자료에 남겨 최종 선택을 settle에 맡깁니다. 객체의 리터럴 별표 이름을 반복 아이템으로 확장하지 않으며 union fold를 포함한 원천·대상 키로 같은 경로의 다른 후보를 구별합니다. 잘못된 후보의 기준점이나 문서 순서를 물려받는 것을 막습니다.

### derive-fragment-array-derived — CONTROLS-077: 호스트 식의 결과를 대상별로 적용합니다

반복 아이템·추가 아이템·tuple·prefixItems와 중첩 배열에서 조각이 직접 선언하고 현재 선택된 대상마다 derived 후보를 돌려줍니다. 호스트 식 평가의 공유는 부모 계약을 따르며 대상의 생김·사라짐은 각자의 에지 수명에 반영합니다. 새 아이템의 발화가 기존 아이템의 편집을 다시 덮는 이유가 되어서는 안 됩니다.

### derive-fragment-array-unset — CONTROLS-028: 참 에지를 대상마다 소비합니다

같은 조각의 unsetValue라도 참이 새로 성립한 아이템만 비웁니다. push·remove와 조각 선택 뒤에도 대상별 기준을 유지하여 이미 소비한 참을 기존 아이템에 반복 적용하지 않습니다. 생긴 대상의 참인 unsetValue는 채움보다 우선하며 채움 실행 자체는 settle에 둡니다.
