# FieldInputNumber 계약

## Requirements

브라우저가 아직 수로 해석하지 못한 표시와 노드에 저장할 수를 구별합니다. 입력 도중의 실패를 값 삭제로 처리하지 않습니다.

## API Contracts

- 빈 값과 진단의 공통 정책은 [상위 계약](../../DETAIL.md)에 둡니다.
- 비유한 수는 기본 표시와 흐림 복귀에서 빈 칸으로 보이지만 노드 값은 바꾸지 않습니다. 네이티브 수 입력으로 표현할 수 없다는 이유만으로 데이터를 버리지 않습니다.

## Acceptance Criteria

### REACT-027 — badInput과 의도적인 빈 칸을 구별합니다

- `badInput` 확인이 빈 칸 처리보다 먼저입니다. 브라우저가 미완성 수를 빈 문자열로 보여도 삭제를 발행하지 않으며, 빈 입력의 `valueAsNumber`인 `NaN`도 노드로 보내지 않습니다.
- 흐림 때 `badInput`이 남으면 현재 props의 노드 값으로 DOM 표시만 돌립니다. 이 복귀는 새 값 쓰기가 아니므로 입력 이력이나 검증 상태를 별도로 만들지 않습니다.

### number-drafts — 브라우저 초안의 한계

- `badInput`은 브라우저가 제공하는 판정이며 일반적인 숫자 문자열 파서를 추가하지 않습니다. 숫자로 해석된 값의 스키마 제약 판정은 검증기에 남겨 둡니다.

## Last Updated

브라우저 초안 판정·흐림 복귀 또는 표현 불가능한 수의 표시 정책이 바뀔 때 갱신합니다.
