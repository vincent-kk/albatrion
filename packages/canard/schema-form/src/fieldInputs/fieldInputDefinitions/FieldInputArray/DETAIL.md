# FieldInputArray 계약

## Requirements

값 없는 배열 위치를 편집할 수 있게 하되, UI를 그리는 것만으로 항목이나 값을 채우지 않습니다.

## API Contracts

- 목록은 자식의 독립 구독을 유지하는 memo 경계입니다. 값만 바뀌면 목록을 재생성하지 않아 잎 갱신의 목록 작업을 O(N)에서 O(1) props 비교로 줄이며, 그 대가로 배열 입력마다 memo fiber와 직전 props를 보유합니다.
- 구조·자식 정체성·잠금·유효 스키마·스타일·쓰기 처리기 변경은 목록에 반영합니다. 값 갱신 최적화가 편집할 수 있는 행이나 잠금 상태를 고정하지 않아야 합니다.
- 행의 DOM 순서는 배열 색인입니다. 삭제 처리기는 직접 자식 행의 현재 위치를 읽으므로, 행 사이에 보조 DOM을 넣으면 다른 항목을 지울 수 있습니다. 추가 버튼은 행 뒤에 둡니다.
- 빈 슬롯은 UI이며 렌더로 새 노드나 값을 추가하지 않고 `data-path`도 주지 않습니다. 기존 항목과 구별해야 가상화·필드 탐색이 편집 전 슬롯을 실제 데이터로 세지 않습니다.
- 추가·삭제·채움 버튼은 `type="button"`인 네이티브 버튼입니다. 기본값인 submit 버튼이면 폼 안에서 항목을 추가하거나 지울 때마다 네이티브 제출이 일어나 검증과 `onSubmit`이 실행됩니다.
- 기본 입력은 원시 컨트롤을 그대로 쓰는 것이 원칙이지만, 배열은 행과 버튼을 배치해야 하므로 목록·행 배치에 필요한 최소 인라인 스타일만 둡니다. 버튼 모양은 브라우저 기본값을 따릅니다.
- 행은 항목과 삭제 버튼을 기준선(`baseline`)으로 맞춥니다. 위쪽 맞춤은 fieldset 테두리와 legend 선에 버튼을 붙이고, 가운데 맞춤은 긴 항목에서 버튼을 이웃 항목 쪽으로 밀어 어느 항목의 버튼인지 흐립니다. 기준선이 없는 항목(아무것도 그리지 않는 항목)은 상자 아래쪽에 맞춰집니다.
- 버튼은 보이는 문구(`Add item`, `Remove`, `Fill item`)가 접근 가능한 이름입니다. 기호(`+`, `×`)는 스타일이 없는 기본 글꼴 크기에서 주변 글자보다 작게 보이고 글자 버튼인 추가 버튼과 짝이 맞지 않으므로 쓰지 않습니다. 렌더 하네스(`src/__tests__/renderForm.tsx`)와 스토리 스타일은 버튼을 `title`(`add item`, `remove item`, `fill item`)로 찾으므로 문구를 바꿔도 `title`은 유지합니다.

## Acceptance Criteria

### array-memo — 목록과 버튼의 비용을 분리합니다

- 안정된 삭제 처리기를 행 전체가 공유하고 버튼은 현재 색인을 함께 받습니다. 이동한 행의 삭제 대상은 갱신하되, push 때문에 기존 버튼 본문을 다시 실행하지 않습니다. 행별 전달 컴포넌트·훅·클로저를 추가하지 않습니다.
- 목록 생성과 props 비교의 합, 삭제 클릭의 위치 조회는 O(N)입니다. 버튼 본문의 재실행 감소를 배열 전체 연산의 상수 시간 보장으로 확대하지 않습니다.

### array-min-slots — 최소 항목 수가 자동 채움이 되지 않습니다

- minItems와 maxItems로 제한한 최소 위치까지 빈 슬롯을 그리되, 사용자 조작 때만 그 자리까지 배열을 한 번 씁니다. 기존 항목을 유지하고 앞 빈 위치는 undefined로 남기며, 새 행이 커밋되면 첫 조작 요소로 초점을 옮깁니다.
- 빈 슬롯 종류는 선택된 후보의 유효 아이템 스키마를 우선합니다. enum·format 등 단순 입력으로 표현하지 못하는 자리는 채움 버튼을 사용하여, 게이트나 prefixItems 전환 뒤에도 다른 종류의 값을 미리 만들지 않습니다.
- readOnly·disabled에서도 빈 슬롯은 보이지만 쓰지 않습니다. 최소 개수의 안내와 입력 허용 여부를 같은 결정으로 묶지 않습니다.

### array-buttons — 배열 버튼은 폼을 제출하지 않습니다

- 폼 안에서 추가·삭제 버튼을 눌러도 `onSubmit`이 호출되지 않고, 목록의 모든 버튼은 `type="button"`입니다.
## Last Updated

빈 슬롯의 값 생성 시점·후보 스키마 선택·DOM 위치 규약, 목록과 버튼의 비용 경계, 또는 버튼의 종류·문구·`title` 규약이 바뀔 때 갱신합니다.
