# FieldInputUnion 계약

## Requirements

기본 union 입력은 최소한의 글 편집 폴백입니다. 임의의 객체 편집기나 enum 선택기를 겸하지 않아, 입력이 사용자의 형 선택 의도를 추측하지 않게 합니다.

## API Contracts

- 빈 값·진단·플러그인 폴백의 공통 정책은 [상위 계약](../../DETAIL.md)에 둡니다.
- 글 표시는 형제 문자열 입력을 재사용하되 초안과 이벤트는 이 입력이 소유합니다. core의 순수 초안 해석을 쓰며 변환 규칙은 [unionBehavior 계약](../../../core/engine/behaviors/unionBehavior/DETAIL.md)에 둡니다.

## Acceptance Criteria

### REACT-033 — 현재 유효 목록으로 초안을 판정합니다

- 정적 schemaType과 유효 jsonSchema.type의 교집합을 사용하며, 유효 스키마에 type이 없으면 정적 목록을 사용합니다. 게이트가 좁힌 목록을 무시하면 현재 받을 수 없는 형을 기본 입력이 발행하게 됩니다.
- 입력·흐림·유효 목록 변경 때 보유 초안을 다시 해석하고, 목록의 멤버인 결과만 보냅니다. 조합 중에는 발행하지 않으며, 흐림에도 해석할 수 없는 초안은 버리고 현재 노드 값의 표시로 돌립니다. 미완성 글이 게이트나 파생 규칙의 데이터가 되는 일을 막습니다.
- string이 허용되면 친 글은 이미 유효한 멤버입니다. number와 string을 함께 허용하는 칸의 `"42"`는 문자열이며, 목록이 number로 좁혀진 동안에는 수가 됩니다. 선언 순서를 사용자 형 선택으로 해석하지 않습니다.
- 기본 입력은 편집 모드에서 null·객체·배열을 만들지 않으며, 문자열 표기가 겹치는 enum 리터럴도 구별하지 않습니다. enum·const나 일반 format의 의미를 구현하지 않으므로, number와 string의 enum에 수 1만 있어도 친 `"1"`을 그 수로 선택하지 않습니다. 이런 편집은 사용자 입력이 맡습니다.
- 객체·배열 값은 읽기 전용으로 표시하고 문자열화를 값 참조와 nullable에 따라 메모합니다. 원시 형이 유효 목록에 없으면 값이 없어도 읽기 전용입니다. 표시할 수 있다는 사실을 구조화된 값의 생성·삭제 지원으로 확대하지 않습니다.
- 문자열화 실패는 빈 읽기 전용 표시와 무효 속성으로 알리고 값을 바꾸지 않습니다. 무효 속성은 props의 misfit 또는 문자열화 실패로 계산하며, 해석에 실패한 로컬 초안만으로 별도 무효 속성을 만들지는 않습니다.

### union-interpret — 초안과 저장값의 관찰 범위

- undefined와 nullable null은 빈 표시이며, 다른 원시 값은 문자열로 보입니다. 표시의 같음은 저장값의 같음을 뜻하지 않으므로, 표시를 읽어 원래 값을 복원하려고 하지 않습니다.
- 유효 목록 변경에 따른 재판정은 남아 있는 초안에 적용합니다. 초안이 없는 저장값을 입력이 임의로 재발행하여 수리하지 않습니다.

### TEST-078 — 표시 비용은 값 참조에 붙습니다

구조화된 값의 문자열화는 값 크기에 비례하므로 value·nullable이 같은 동안 표시 메모를 재사용합니다. 유효 목록은 schemaType·jsonSchema 참조에 따라 교차하며, 입력 때의 초안 해석과는 별도 비용입니다. 흐림에서 실패한 초안을 원래 값으로 되돌릴 때는 현재 노드 값을 다시 표시하므로, 값 참조가 같으면 모든 경로에서 문자열화가 한 번뿐이라고 보장하지 않습니다. 이 구분을 유지해야 큰 통째 값의 표시 비용을 키 입력 비용이나 core 해석 비용으로 잘못 돌리지 않습니다.

## Last Updated
