# transformErrors

## Requirements

라이브러리가 스키마에 넣은 내부 강화 필드의 검증 오류만 사용자 오류 결과에서 제외합니다. 사용자가 쓴 스키마에서 나온 오류는 어느 조합 분기의 것이든 손대지 않습니다.

## API Contracts

- 배열이 아닌 입력은 빈 배열을 반환하며, 남은 오류를 새 결과 배열에 담습니다.
- 유지되는 오류 객체는 원본 참조를 그대로 사용하며, key 옵션이 켜지면 모듈 수준의 순차 key를 쓰고 꺼지면 기존 key를 undefined로 지웁니다.

## Acceptance Criteria

### transform-errors-contract — 관찰 가능한 동작

- 강화 키를 포함한 dataPath 오류는 반환 배열에 남지 않습니다.
- 그 밖의 오류는 모두 남습니다. `oneOf`/`anyOf`의 `type: 'null'` 분기가 null이 아닌 값을 거부한 `type` 오류도 다른 분기의 오류와 똑같이 남습니다.
- key 부여를 요청하지 않아도 유지되는 원래 오류 객체의 key는 undefined로 설정됩니다.

## History

- 2026-09-20 — `type: 'null'` 분기의 거부 오류를 걸러내던 규칙을 넣었다가 같은 날 뺐습니다. 그 규칙은 `schemaPath`만 보고 걸렀기 때문에 `&if`로 고른 분기가 없는 폼, `anyOf`, 터미널 필드에서도 적용되어 "null도 허용된다"는 사실을 지웠고, 선택되지 않은 객체 분기의 오류는 그대로 나가는 기존 동작과도 어긋났습니다. 이 모듈이 개입하는 대상은 라이브러리가 직접 넣은 강화 키뿐입니다.
