# jsonSchema Helpers — 현재 스키마 해석 경계

## Purpose

스키마 정보 추출·참조 해석·타입 분류·확장 필드 제거의 현재 헬퍼 계약을 소유합니다. 옛 엔진의 전처리와 allOf 병합은 레거시 경계에 남기며 여기서 재수출하지 않습니다.

## Conventions

- 독립 기능은 소유 하위 모듈에 둡니다. 단, 루트 `filter.ts`의 두 타입 분류 가드는 하나의 상호 배타적인 `JSONSchemaType` 판정이므로 함께 유지합니다.
- 참조 해석은 해석기를 만들어 호출자가 필요한 스키마에 적용하게 합니다. 스키마 입력을 미리 변형하지 않습니다.
- 확장 필드 제거는 복제본을 스캔해 호출자 스키마를 보존하고, 제거할 필드가 없으면 원래 참조를 돌려줍니다.
- 모든 헬퍼는 입력으로 결과를 결정하고 전역 상태를 읽거나 쓰지 않습니다.

## Boundaries

### Always do

- 새 독립 헬퍼는 소유 경계를 정한 뒤 공개 진입점에 명명해 연결합니다. 타입 분류 가드 쌍은 기존 루트 예외로 유지합니다.
- 함수는 입력만으로 결과를 결정하고 호출자 스키마를 변경하지 않습니다.

### Ask first

- 기존 공개 함수 시그니처 변경
- `filter.ts`의 `virtual` 포함 여부 등 타입 분류 기준 변경

### Never do

- 독립 계약이 없는 `helpers` organ을 별도 fractal로 취급하지 않습니다.
- 여기서 React 컴포넌트나 노드 인스턴스를 생성하지 않습니다.
- 공개 진입점을 우회해 하위 모듈 내부 파일을 직접 가져오지 않습니다.
