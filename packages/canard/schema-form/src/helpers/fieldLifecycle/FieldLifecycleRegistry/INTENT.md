# FieldLifecycleRegistry

## Purpose

노드와 라이프사이클 시점마다 일회성 FIFO를 소유합니다. 한 처리기의 재예약이나 실패가 현재 큐의 순서와 나머지 실행을 바꾸지 않게 합니다.

## Conventions

- pending은 예약 변경 때 갱신하는 비트마스크입니다. 예약이 없는 렌더 경로는 Map을 탐색하지 않습니다.
- 실행 전에 큐를 분리하고 실행마다 동결한 사건 하나를 공유합니다.
- 생성자가 받는 오류 보고기는 절대 던지지 않아야 합니다. 호스트 보고 실패의 격리는 생성자가 아닌 소비자가 보장합니다.

## Boundaries

### Always do

- 취소는 멱등하며 분리된 큐에서 아직 실행하지 않은 항목도 건너뜁니다.
- 실패한 처리기를 None으로 보고 나머지 처리기를 순서대로 실행합니다.

### Ask first

- 지속 예약이나 오류 보고 계약을 바꿀 때

### Never do

- 처리기 실행 중 같은 큐에 재예약된 항목을 즉시 실행하지 않습니다.
- DOM 행동, React 상태 또는 노드 마운트 상태를 보관하지 않습니다.
