# fieldInputDefinition

## Requirements

입력 정의와 경로 맵을 정규화하고, 해석된 입력의 정체성과 오류 격리를 소유합니다. 공개 Hint 형은 [types 계약](../../types/DETAIL.md)에 둡니다.

## API Contracts

실제 입력 안에서 useFieldErrors가 부른 포맷터의 예외는 이 입력 경계가 잡습니다. 포맷터 참조 교체만으로 실패한 입력을 복구하지 않으며, 틀의 예외와 복구는 바깥 필드 렌더러 경계가 소유합니다. 틀 선택 변경은 새 선택 토큰으로 옛 입력 콜백을 무효화합니다.

원본 컴포넌트를 약한 키로 보관하는 어댑터 캐시는 맵·정의·인라인·preferred 경로를 공유합니다. 같은 컴포넌트는 하나의 경계를 사용하여 공급 경로 변경만으로 재마운트되지 않습니다. 정규화는 설정 크기에 비례하고 캐시는 살아 있는 컴포넌트만 보유합니다.

- 정의 객체를 캐시 정체성으로 사용하므로 등록한 정의는 불변으로 취급하고 변경할 때 새 객체를 제공합니다. 같은 객체의 재정규화는 시험과 감싸개를 재사용하여 입력의 불필요한 재마운트와 반복 경고를 막습니다.
- 정의의 `controlled`는 불리언일 때만 정규화 결과에 싣습니다. 경로 맵에는 정의 선언이 없습니다. 선언의 뜻과 스키마 선언과의 결합은 [FieldInputBridge 계약](../../components/FieldProxy/components/FieldInputBridge/DETAIL.md)에 둡니다.
- wildcard는 파싱된 연산자 한 개가 세그먼트 하나를 소비합니다. `%2A`는 별표 이름이며 wildcard가 아닙니다. 문자열 치환으로 처리하면 이름이 같은 일반 속성을 다른 필드에 연결하게 됩니다.
- 맵의 `#`·빈 문자열은 루트, `/`·`#/`는 빈 이름 자식입니다. `^`로 시작한 키만 정규식이며, 그 밖의 키는 기존 단일 세그먼트 wildcard 또는 정확 경로입니다. 정확 경로가 자손까지 선택하면 객체 입력이 자식 입력을 뜻밖에 교체하므로 정규식은 명시적으로 선택합니다.
- 정규식은 escaped 노드 경로를 검사하며 작성자가 지정한 anchor를 유지합니다. 맵은 `Object.keys` 순서의 첫 일치가 우선이고, 구체적인 경로라는 이유로 순서를 바꾸지 않습니다.
- 정확 키는 절대 포인터일 때만 포인터 헬퍼로 한 번 표준화하여 같은 이름의 wildcard 비교와 일치시킵니다. 상대 키를 조립하면 작성하지 않은 선행 `/`가 생기므로 상대 텍스트는 그대로 비교합니다. 해석 시에는 문자열 비교 하나만 하며 정규식을 생성하거나 실행하지 않습니다.
- `**`와 정규식처럼 보이는 비패턴 키는 리터럴입니다. 일치하지 않는 키는 조용히 무시하며 개발 경고나 별도 오류를 만들지 않습니다. 키의 의도를 추측해 진단하면 합법적인 속성 이름까지 잘못된 설정으로 취급하기 때문입니다.
- `^` 맵 패턴 컴파일이 실패하면 `FormErrorCode.FormTypeInputMap`을 던집니다. 이를 유효하지 않은 입력 정의처럼 건너뛰면 잘못된 맵을 정상 폴백으로 오인하므로, 구성 오류의 보관과 확정 로드 보고는 [FieldInputsContext 계약](../../providers/FieldInputsContext/DETAIL.md)에 맡깁니다.

## Acceptance Criteria

### input-map-key-kinds — 키가 선택 범위를 명시합니다

- 정확 경로는 해당 노드만 선택합니다. 객체를 정확 경로로 매핑해도 자식 입력은 각자의 선택 규칙을 따릅니다.
- `^` 패턴은 정규식으로, 기존 `*` wildcard는 한 세그먼트 비교로 해석합니다. 정규식 분류가 wildcard 분류보다 먼저이므로 패턴의 별표는 정규식 문법입니다.

### input-map-patterns — 패턴의 anchor와 경로 표현을 보존합니다

- 패턴은 escaped 경로에 `RegExp.test`를 적용합니다. 시작·끝 anchor, 대안 그룹, 중간 경로 매칭의 범위는 작성한 표현식이 결정하며, 컴파일 실패는 구성 오류입니다.

### input-map-literals — 리터럴과 비매칭 키를 조용히 보존합니다

- `**`를 비롯한 이름은 정확 키와 wildcard의 리터럴 세그먼트에서 텍스트입니다. 존재하지 않는 경로나 지원하지 않는 포인터 표기를 추측하여 경고하거나 오류로 만들지 않습니다.
- 마지막 빈 세그먼트가 있는 키는 wildcard 문법이 아니며, 숫자처럼 보이는 키도 `Object.keys` 순서를 유지합니다.

### live-configuration — 설정 교체 수명

- 같은 원본 컴포넌트를 서로 다른 설정 경로로 정규화해도 동일 어댑터를 얻습니다.

### REACT-032 — 시험 배열을 union 목록 비교로 읽지 않습니다

- 객체 시험은 허용된 자기 키를 모두 만족해야 하며, 스칼라는 엄격한 같음, 배열은 후보 중 하나와의 같음입니다. 생략과 명시적 `undefined`는 달라, 후자는 Hint 값이 없는 경우만 고릅니다.
- `{ schemaType: ['string', 'number'] }`는 배열인 union schemaType의 원소를 검사하지 않습니다. union 전체는 `{ type: 'union' }`, 목록의 내용은 함수 시험으로 고릅니다. 이 구분이 없으면 union 입력이 조용히 폴백으로 빠집니다.
- `type`은 정수와 실수를 `number`로 합친 노드 종류를, `schemaType`은 정수 구분을 보존한 허용 형을 가릅니다. 정수 전용 시험을 `type: 'integer'`로 쓰면 어떤 정상 노드도 선택하지 못합니다.

### REACT-033 — 잘못된 시험을 진단하되 자유 키로 넓히지 않습니다

- 객체 시험의 모르는 키는 비교에서 빼고 `type: 'integer'`와 함께 개발 모드 `FormTypeTestInvalid` 경고로 알립니다. 허용 키에는 `inputType`이 있고 `misfit`은 없으므로, 값의 무효 상태를 객체 시험의 선택 축으로 삼지 않습니다.
- 경고는 정의 객체마다 한 번이며 프로덕션에서는 내지 않습니다. 모르는 키만 있으면 비교 조건이 비어 모든 Hint에 맞으므로, 경고를 정의 제외나 안전한 비매칭으로 해석하지 않습니다.

### form-type-input-definition-contract — 입력 해석 지점에서 한 번 격리합니다

- 유효하지 않은 컴포넌트·시험은 건너뛰고, 정규화 중에 컴포넌트를 렌더하거나 훅을 실행하지 않습니다. 선택 준비가 사용자 렌더의 부수 효과를 실행하지 않게 합니다.
- 인라인·preferred·맵·정의 입력은 같은 사설 어댑터를 사용합니다. 입력 경계는 적용 세대 key 바깥에 두고, 원본 입력만 key를 바꾸어 Refresh가 실패한 경계를 우회 복구하지 않게 합니다. 경계의 재마운트 범위는 [FieldInputBridge 계약](../../components/FieldProxy/components/FieldInputBridge/DETAIL.md)에 둡니다.
- 감싸개가 현재 입력 path로 폼 보고기를 읽고 비공개 적용 세대와 선택 수명 토큰을 소비합니다. 선택 토큰의 insertion effect는 이 감싸개가 소유하여, 삭제 시 원본 입력의 layout cleanup보다 먼저 토큰을 폐기합니다. 원본 입력에는 두 사설 prop을 전달하지 않으며 별도의 전달 전용 fiber를 만들지 않습니다.

## Last Updated

시험의 비교·진단·캐시 정체성, 맵 경로 의미 또는 입력 경계와 적용 세대의 관계가 바뀔 때 갱신합니다.
