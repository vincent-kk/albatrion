# 118라운드 닫기 — React 갱신 행의 증가분 대부분은 측정기의 타이머 대기 안에 옛 판의 일이 숨어 생긴 겹침이므로, 판정 열을 타이머 하한 없는 대기의 wall과 CPU 활성 시간으로 바꾸고 기존 wall은 기록 열로 남긴다; 실제로 늘어난 것은 필드당 fiber 계층 다섯이며 경계 계층을 줄이는 고침을 위해 `@winglet/react-utils`에 ErrorBoundary를 더해 내보낸다(안전한 확장, ERROR-115의 선례)

2026-10-07. 07 작업자(전환, `2f8c11fd3`, `verification/07-switch/react-layer-diagnosis-118.md`)의 읽기 전용 진단. 기제: 측정 루프는 `flushSync(apply)` 뒤 `setTimeout(0)` 두 번을 기다리는데, 옛 엔진은 이벤트를 microtask로 모으고 Refresh를 setState로 처리해 쓰기 하나가 커밋 둘로 갈라지고 그중 하나 또는 둘이 flushSync 뒤 타이머의 최소 대기 안에 숨어 돈다; 새 엔진은 쓰기 안에서 동기로 정착하고 REACT-024대로 uSES로 읽어 커밋 1회가 flushSync 안에서 끝나 wall에 그대로 잡힌다 — "렌더 16% 증가, 커밋 반감"도 이것이다. 근거(쓰기당 ms, 새−옛; G26 React 층 Δ / 타이머 하한 없는 wall Δ / CPU 활성 시간 Δ): array-push-100 +1.40/+0.23/+0.40, push-remove-100 +1.18/+0.10/+0.64, flat-50·100·500 +0.19·+0.21·+0.65 / +0.06·−0.03·−0.30 / 0.00·−0.03·−0.36, nested-d3·d5 +0.23·+0.22 / +0.09·+0.05 / 0.00·+0.35, computed +0.35/+0.11/−0.12, replace-200 +6.2/+9.5/+11.2; 이미 있는 항목의 재렌더 수·DOM 연산 수·memo를 깨는 props 변화는 두 판 같다. 실제로 늘어난 일: 마운트 때 필드마다 fiber 계층 +5(SchemaNodeProxy의 Provider·withErrorBoundary 래퍼·경계, SchemaNodeField 분리, 입력 경계의 세 층, 입력당 노드 이중 구독, 자식마다 layout effect) — replace-200 잔여의 약 75%와 array-push의 쓰기당 0.1–0.25 ms가 여기서 난다. 07이 둘을 물었다(Q118). 편집자 결정으로 닫는다. 소유자에게 물을 것은 없으나 판정 열의 변경은 소유자에게 알린다.

### 118C-01 (1) React 갱신 행의 판정 열은 타이머 하한 없는 대기(`setImmediate` 네 번)의 wall과 CPU 활성 시간 둘로 하고, 기존 wall은 기록 열로 남기며, 관측 digest와 커밋 수(옛 2, 새 1)의 단언을 붙인다 — 94C-01이 옛 판의 계측 치우침을 걷어낸 것과 같은 자리의 정정이며, 116라운드 소유자의 절대 기준("메인 스레드 CPU 버스트")에는 CPU 활성 시간이 맞는다; 제품 커밋을 비동기로 미뤄 지표를 맞추는 고침은 REACT-024와 어긋나므로 쓰지 않는다; (2) 경계 계층을 줄이는 고침(F2a 입력 경계 한 층, F2b 필드 경계 직접 렌더)을 위해 `@winglet/react-utils`에 ErrorBoundary 클래스를 더해 내보낸다 — 기존 동작을 바꾸지 않는 공개 확장이고 ERROR-115가 같은 패키지의 API를 더한 선례다; 패키지 CLAUDE.md의 "`withErrorBoundary`로 감싼다"는 "경계는 해석·소유 지점에서 한 번"의 뜻을 그대로 두고 수단만 넓히되 소유자의 확인을 받아 고친다; EVENT-039·040, 112C-01, REACT-019·024는 그대로다

- 닫는 항목: TEST-026(보충), ERROR-115(보충)
- 결정:
  - 【추론】 (1) 측정은 두 판이 같은 일을 재야 한다. 지금의 wall은 옛 판이 타이머 대기 안으로 미룬 커밋을 세지 않고 새 판이 동기로 끝낸 커밋은 세므로, 94C-01이 걷어낸 계측 치우침과 같은 종류의 치우침이다 — 옛 판에 유리한 쪽으로. 타이머 하한 없는 대기는 두 판의 모든 커밋이 끝날 때까지 기다리되 타이머의 최소 대기를 빼고, CPU 활성 시간은 대기 자체를 빼므로 둘을 판정 열로 둔다; 기존 wall은 비교의 연속을 위해 기록 열로 남긴다. 그 결과 flat·nested·computed의 React 층 증가는 사라지거나 음수가 되고, 실제로 남는 것은 array-push·push-remove(쓰기당 +0.23~+0.64 ms)와 replace-200(+9.5~+11.2 ms)이다. 커밋 수 단언(옛 2, 새 1)은 이 기제가 측정의 전제임을 고정한다. 제품의 커밋을 미뤄 지표를 맞추는 것은 REACT-024(동기 정착·uSES 읽기)를 뒤집는 것이고 사용자에게는 더 늦은 화면이므로 쓰지 않는다. 판정 열의 변경은 소유자가 정한 React 층 목표(27라운드, 85C-01)의 측정 방법을 바꾸는 것이므로 소유자에게 알리고, 소유자가 다르게 보면 바로잡는다. (2) 실제로 늘어난 일은 필드당 fiber 계층 다섯이고, 이 가운데 경계 계층(입력 경계의 세 층, 프록시의 래퍼와 경계)을 줄이는 고침은 결과를 바꾸지 않는 코드 수준이다. 두 고침 모두 ErrorBoundary 클래스를 직접 써야 하는데 `@winglet/react-utils`는 `withErrorBoundary`만 내보낸다; 클래스를 더해 내보내는 것은 기존 소비자의 동작을 바꾸지 않는 추가이고, ERROR-115가 같은 패키지의 감싸개에 선택 인자를 더한 선례와 같은 "안전한 확장"이다(reuse-first). schema-form 안에 내부 경계 클래스를 두면 winglet의 것과 중복된다. 패키지 CLAUDE.md의 문장은 112C-01이 정한 "경계는 해석·소유 지점에서 한 번 만들어 고정"의 뜻을 그대로 두고 수단(`withErrorBoundary` 또는 ErrorBoundary 직접)만 넓히며, CLAUDE.md의 변경은 07 세션의 규칙대로 소유자 확인을 받는다. 기대 효과(필드당 fiber 2개, replace-200 약 −3 ms, push 쓰기당 약 −0.03 ms)는 추정이므로 변경 하나에 105C-01 판정 하나로 확인한다; 공개 API와 EVENT-039·040, REACT-019·024, 112C-01의 단언 시험은 그대로 초록이어야 한다. 입력당 노드 이중 구독과 자식마다의 layout effect는 다음 코드 수준 후보로 두되 바인딩 계약(REACT-024의 늦은 쓰기 차단, 112C-01의 경계 고정)에 닿는지 명세에 적는다.
