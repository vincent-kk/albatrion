## §2 procedure (determinism)
- **S1.** Distinguish `τ = ∅` from `τ = {null}` everywhere. A null-only result (all static declarations null-only, or a slot whose gate-less branches are all null-only, or an intersection equal to `{null}`) is the **null kind with `nullable: true`** — never an error. `ALL_OF_TYPE_REDEFINITION`/kind conflict only when the intersection is truly empty. (codex D1, D2; antigravity §1)
- **S2.** Branch collection computes one allowed set per branch (`type` array elements, `nullable: true` with a `type`, null-only branch = `{null}`), unions them, and only then splits `null` off into `nullable`. `oneOf` + `anyOf` together: intersect the two allowed sets (null included) before splitting. Both `{oneOf:[{type:'null'}], anyOf:[{type:'null'}]}` and `{anyOf:[{type:'null'}]}` are null kind, nullable. (codex D3, C3)
- **S3.** Static-declaration rule, restated exactly: a static declaration whose allowed set (null included) is a **subset** of the anchor's set narrows: kind and list become the intersection, nullable = AND. A static set that is neither a subset nor disjoint (overlap, e.g. `['string','number']` + `allOf:[{type:['string','boolean']}]`) or disjoint is a kind conflict. Rationale line: a static conjunction always applies, so the intersection is what the validator enforces and what the author expects; a union node here would store `"42"` as a string and never validate. This supersedes the earlier "then/allOf narrowing is validation-only" for the **static** case; the gated case is O7. Put this change in §7 as **O8** (recommended: intersection; alternative: validation-only as originally accepted) — codex C1 says an editor cannot overturn an accepted decision, so the owner confirms.
- **S4.** Add O7 (gated narrowing) to §7: (ㄴ) node, `schemaType`, input selection and rule A all stay on the union list; narrowing is validation-only; document that authors who want the input to change must declare the field only inside `then`/`else`.
