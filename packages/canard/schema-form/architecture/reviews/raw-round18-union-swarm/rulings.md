# Editor rulings on the V1/V2 findings (binding for the compile step)

Each ruling names the finding (V1-n / V2-n), the decision, and the reason. "Owner" marks items that go to the owner instead of being closed here.

## Field and list
- **R1 (V1-1, V2-12).** No stamping of a computed `type` into the effective `node.jsonSchema`. The blueprint computes the list once per slot, freezes it, and every node of that slot shares the reference as `schemaType`. `node.jsonSchema.type` stays whatever the effective (merged) schema says. Inputs and rule A read `schemaType`, never `jsonSchema.type`. Consequence: the owner-answer sentence "목록은 `node.jsonSchema.type`에서 읽는다" (BLUEPRINT-033) changes to `node.schemaType` — **Owner: confirm wording change O5**.
- **R2 (A/B/C/D convergence).** `schemaType` is widened, not replaced: a single `JSONSchemaType` string for every non-union node (unchanged from today, including `'null'` for the null kind — V1-11 → A), and a frozen readonly array only for union nodes. Invariant `Array.isArray(node.schemaType) === (node.type === 'union')`. The array: author order of the anchor declaration, duplicates are an error (R6), `'null'` excluded (nullable carries it), `'integer'` kept unless `'number'` is also present (then absorbed into `'number'`). **Owner: O1** — this differs from the literal wish "스키마에 쓴 배열 타입을 그대로" in one point: `'null'` is not in the array. Reason: `['integer','null']` must keep `schemaType === 'integer'` so today's plugin tests and the mui integer check keep working, and so the three null spellings (`'null'` in the array, `nullable: true`, a null branch) give one node one value. Alternative (as-written including `'null'`, as a *new* field beside `schemaType`) is offered in the doc.
- **R3 (V1-10).** Rule A's list = `schemaType` (as an array; a scalar is the one-element case) plus `nullable`. D's `UnionSpec.kinds` is the internal precomputed form of the same list; the `expected` payload of `VALUE_TYPE_MISMATCH` lists `schemaType` and `nullable` separately, never a merged list with `'null'`.

## Declarations across fragments
- **R4 (V1-2, V1-3, V2-5, V2-13).** Static conjunction (body, gate-less `allOf` items, `$ref` targets) **intersects**: kinds intersect; `number ∩ integer = integer`; nullable is AND across static declarations (a declaration without any null spelling removes nullability). This is today's behavior (`processSchemaType.ts:65,73`). A non-empty intersection that is a *subset* of the anchor's set is not a conflict: the node is the intersection kind (a static `allOf: [{type:'string'}]` on `['string','number']` yields a string node). A null branch on a slot that has its own `type` does not add nullability (today). Disjoint sets → kind conflict (`ALL_OF_TYPE_REDEFINITION` today / `SHARED_NODE_KIND_CONFLICT` in the new design, per ERROR-164 — compile step checks which applies where).
- **R5 (owner exception, scoped).** Only **gated** declarations (`then`/`else`, `controls.active` fragments, gated branches) that narrow to a subset are validation-only: they change neither kind, list, nor nullable. A gated declaration that widens or is disjoint is a kind conflict when its gate is on (existing rule). Record as an explicit exception to BLUEPRINT-011/012.
- **R6 (V1-6).** Duplicate elements and unknown type names in a `type` array are `UNKNOWN_JSON_SCHEMA` (today's behavior; nothing is silently dropped).
- **R7 (V2-4).** A slot with both `oneOf` and `anyOf` (no own type): the list is the intersection of the two unions (they are conjoined); empty intersection → `UNKNOWN_JSON_SCHEMA`.
- **R8 (V2-1).** Typeless slots whose gate-less branches are all objects (or all arrays) stay `UNKNOWN_JSON_SCHEMA` as today. Out of scope; note it as a candidate for the pending mixed-`oneOf` decision.
- **R9 (V1-5).** `InferSchemaNode`/`InferValueType` mirror the runtime procedure: typeless branch → the schema is invalid at the type level (resolve to `never`/`unknown`, not `NullNode`); mixed object+primitive `oneOf` → same; `type` array → `UnionNode` when the folded set has ≥2 kinds, else the single kind.

## Hint, props, tests
- **R10 (V1-4, V2-9).** `hint.type = node.type` (kind, `'integer'` never appears), `hint.schemaType = node.schemaType`, `hint.nullable = node.nullable`; `FormTypeInputProps` mirrors the same three names. Migration: integer nodes' `hint.type` changes `'integer'` → `'number'`; tests `{type:['number','integer']}` become `{type:'number'}`; integer-only intent uses `{schemaType:'integer'}`; mui `FormTypeInputNumber` reads `schemaType`. **Owner: O6 confirm** (breaking for plugins, surfaced by TS2367).
- **R11 (V2-8).** Test-object `schemaType` accepts scalars (or an array meaning "one of these scalars"), never matches a union's array. Unions are matched by `{type:'union'}` or a function test. Matching rule for all keys unchanged (`===` / "one of").
- **R12 (V1-8, B-2).** No public "rule A preview" function now. Inputs observe the outcome via `valueTypeMismatch`; adding a function later is additive.
- **R13 (V2-10).** Default fallback keeps the owner's sentence: the string input, with the draft rule, `undefined` on empty, `null` on clear when nullable, read-only `JSON.stringify` + clear when the value is object/array. `enum`/`const` on a union slot: still the string input (no enum/radio definition is opened to unions). Note in the doc the usability gap for numeric enum members and that UI plugins cover it.

## Values
- **R14 (V1-9, V2-6).** Membership for `object` stays the owner's rule: `typeof v === 'object' && v !== null && !Array.isArray(v)`; no prototype check (cost; `Date`/`File` would light the warning).
- **R15 (V2-3).** VALUE-034 unchanged: a union is a leaf; when it emits nothing, root → `undefined`, array-item placeholder → the leaf rule. D 19 is dropped.
- **R16 (V1-12, V2-14).** `Merge` on a terminal node is a whole replacement (WRITE-079). Cite it.
- **R17 (V1-7).** No warning for `trim` on a union (it applies when the value is a string, else no-op). A discriminator branch whose `const`/`enum` literal type is outside the key's list is unreachable → dev-mode warning using the existing unreachable-branch warning family (today `warnIfNullUnreachable`; compile step names the new-design code from the ERROR ledger, no new code if one fits).
- **R18 (V2-7).** Validator mutation: contract "validators do not mutate value or schema"; at `bind`, the plugin reads `ajv.opts` and, when `coerceTypes`/`useDefaults`/`removeAdditional` is on, validates **a copy for that instance only** (dev-mode warning once); default path unchanged; schema deep-copied once per (instance, root) at compile. Listed as a change to VALIDATE-002/003 with a migration row. **Owner: O4 confirm** (they marked it pending).
