# Prior-art source verification (A–D)

Read-only source survey, HEAD of default branch on each repo, gathered 2026-09-21. All claims cite `path:line`; unconfirmed items are under "Could not verify".

## A. rjsf-team/react-jsonschema-form

**A1 (if/then/else, allOf, dependencies, merge).** `resolveCondition` calls `validator.isValid(if, formData||{}, rootSchema)` synchronously per schema node holding `if` (`packages/utils/src/schema/retrieveSchema.ts:111`). Not memoized in this file; `Form.tsx` stores the result in `state.retrievedSchema`, recomputed by `getStateFromProps` on prop/state changes (`packages/core/src/components/Form.tsx:316-317,748`), not on every render. `allOf` with multiple `if/then`: each `allOf` element is resolved independently (its own `isValid` call) via recursive `retrieveSchemaInternal` inside `resolveSchema`'s `ALL_OF_KEY` branch, then permuted and shallow-merged via `@x0k/json-schema-merge` (`retrieveSchema.ts:296-315,632-648`). Only draft-07 `dependencies` is resolved (`resolveDependencies`/`processDependencies`/`withDependentSchema`, `retrieveSchema.ts:779-961`); no `dependentSchemas`/`dependentRequired` constant exists (`DEPENDENT_SCHEMAS_KEY` search: 0 hits; `schemaHasNestedConditional.ts:73` checks only `DEPENDENCIES_KEY`/`IF_KEY`). `mergeSchemas` deep-merges same-named object properties recursively; other arrays are overwritten by the right operand except object-schema `required`, unioned+deduped (`mergeSchemas.ts:16-35`).

**A2 (oneOf/anyOf).** `getFirstMatchingOption`: discriminator shortcut first, else loops options calling `isValid` once per option until a match (worst case N calls) (`getFirstMatchingOption.ts:30-97`). Discriminator reads OpenAPI-style `discriminator.propertyName` (`getDiscriminatorFieldFromSchema.ts:15-16`); `getOptionMatchingSimpleDiscriminator` compares its `const`/`enum` directly against candidates — **no validator call** (`getOptionMatchingSimpleDiscriminator.ts:20-38`). `getClosestMatchingOption` (initial/ongoing selection, and defaults) tries the discriminator shortcut first, else runs `getFirstMatchingOption` once per option to build a valid-index set, then scores each via `calculateIndexScore` (recurses into nested oneOf/anyOf, more `isValid` calls) (`getClosestMatchingOption.ts:169-225`). `AnyOfField`/`MultiSchemaField` renders a select widget + `SchemaField` for the chosen option; initial selection from `getClosestMatchingOption` at mount, re-derived in a no-deps `useEffect` comparing `deepEquals(formData, prevFormData)` after every render (`MultiSchemaField.tsx:58-96`).

**A3 (sanitizeDataForNewSchema).** Old-schema keys default to removal; kept only if old/new resolved types match (or old had none); object/array-of-object keys recurse; scalar keys whose new `default` differs get overwritten to it (or cleared if the new schema is `readOnly`); `const` mismatches replace with the new const only if the old const matched, else clear; invalid enum values replaced via `replacementForInvalidEnumValue`. Arrays recurse per item when object-typed, filtered by `maxItems`/new enum values otherwise; an items type mismatch drops the whole array (`sanitizeDataForNewSchema.ts:107-171,232-290`).

**A4 (ValidatorType).** Interface: `validateFormData`, `isValid(schema, formData, rootSchema): boolean` (sync, not `Promise`), `rawValidation`, optional `reset` (`types.ts:1288-1327`). `FormProps.validator: ValidatorType<T,S,F>` is required (non-optional), documented "needed for form validation to work" — mandatory for rendering.

**A5 (defaults vs. inactive branches).** `computeDefaults` for `oneOf`/`anyOf` merges only the `getClosestMatchingOption`-selected branch (index 0 absent formData); other options' defaults are never applied (`getDefaultFormState.ts:380-427`). For `if` (when `emptyObjectFields !== 'skipEmptyDefaults'`), `computeDefaults` first calls `retrieveSchema` (runs `isValid` on the `if`) before deriving property defaults — only the winning branch contributes (`getDefaultFormState.ts:592-597`).

## B. eclipsesource/jsonforms

**B1.** `mapStateToCombinatorRendererProps` is a `connect()` selector, re-run on every store update. It loops subschemas, calling `ajv.compile(_schema)` — **a fresh compile every call, not cached** — then `valFn(data)`, accepting the first subschema whose errors are empty or omit the "structural" keywords `required/additionalProperties/type/enum/const` (`renderer.ts:1181-1202`). `MaterialOneOfRenderer` seeds local `selectedIndex` once from `indexOfFittingSchema||0` and never re-syncs it — tab selection is sticky after mount (`MaterialOneOfRenderer.tsx:64`).

**B2.** On tab switch: if `data===undefined`, switches immediately; else opens `TabSwitchConfirmDialog`; confirming calls `handleChange(path, createDefaultValue(newSchema, rootSchema))` — data is **replaced** with freshly generated defaults, not merged or sanitized (`MaterialOneOfRenderer.tsx:83-113`).

**B3.** Schema-based `rule.condition` runs `ajv.validate(condition.schema, value)` inside `evaluateCondition`'s `isSchemaCondition` branch, `value = resolveData(data, getConditionScope(condition, path))` (scope relative to the control's own path) (`runtime.ts:50-52,79-83`). Reached via `isVisible`/`isEnabled`/`isReadonly`, plain functions re-invoked whenever the connected renderer re-derives props from the store — no internal memoization.

**B4.** Confirmed: data-schema `if/then/else` does not affect rendering shape. `isCombinator()` checks only `oneOf/anyOf/allOf` (`uischema.ts:97-104`); `generateUISchema` never inspects `.if`; combinator mapping only accepts `keyword: 'anyOf'|'oneOf'|'allOf'` (`combinators.ts:37`). `if/then/else` exist on `JsonSchema7` solely as Ajv pass-through fields (`jsonSchema7.ts:151-153`); no rendering-path usage of `schema.if` found by code search.

## C. json-editor/json-editor

`MultipleEditor` is reused for `if/then/else`: `preBuild()` builds a synthetic 2-option switcher (`types=[thenSchema, elseSchema]`, deep-merged from `then`/`else`) (`multiple.js:170-186`). `getIfType` runs `jsoneditor.validator._validateSchema(ifSchema, value)` → 0 (then) if no errors else 1 (else); `switchIf()` is wired to `jsoneditor.on('change', …)`, re-evaluating **on every change anywhere in the form** (`multiple.js:277-296,251`). For `oneOf`/`anyOf`, `setValue` builds one `Validator` per option: `oneOf` picks the first option with zero `validate()` errors; `anyOf` also runs a custom, non-Ajv `fitTest(val)` per option (structural key-presence scoring, `validator.js:651-688`), preferring the better fit-test match over the strictly-valid pick when its score is higher (`multiple.js:307-345`). `keep_oneof_values` (default `true`) controls whether `switchEditor()` seeds the newly active editor with the previous value via `setValue(currentValue, true)`; `keep_only_existing_values` further trims that value to keys the new editor's own `getValue()` already produces (`multiple.js:66-92,145-151`).

## D. ajv / hyperjump

Ajv's `oneOf` emits `params.passingSchemas: [number, number] | null` **only on failure** (two branches both passed) — naming the conflicting indices, not a positive annotation of the single matching branch (`oneOf.ts:13-16,57-64`). When `opts.discriminator && parentSchema.discriminator`, Ajv's own discriminator vocabulary replaces the generic oneOf codegen entirely (`oneOf.ts:33`); Ajv separately tracks per-subschema "evaluated" properties (`cxt.mergeEvaluated`) for `unevaluatedProperties`. hyperjump/json-schema exposes `annotate()` backed by an `AnnotationsPlugin` collecting `{keyword, instanceLocation, annotation}` per evaluation, attached as `node.annotations[keyword]`, with an explicit `BASIC` output-format constant (`annotations/index.js:11-38`).

## Patterns shared by ≥2 implementations

1. All three renderer libraries re-run the validator against every candidate branch on every relevant data/state change, with no cross-change cache inside the resolution function — JSON Forms is the most extreme, re-`ajv.compile`ing every subschema on every store update.
2. RJSF and json-editor both have a fast/override path that picks a branch without a normal per-option validate on the common case (RJSF's discriminator const/enum compare; json-editor's dedicated `_validateSchema`-based `if` path).
3. RJSF (`AnyOfField`) and JSON Forms (`MaterialOneOfRenderer`) both cache the selected branch index as local state, but diverge on re-sync: RJSF re-derives via `deepEquals` on formData change; JSON Forms never re-syncs after mount.
4. RJSF (`sanitizeDataForNewSchema`) and json-editor (`keep_oneof_values`) both treat branch-switch cleanup as distinct, tunable logic rather than an accident of validation.

## Where they disagree

Branch-switch data: JSON Forms replaces with fresh defaults; json-editor keeps old data by default; RJSF prunes+patches (partial keep) — three strategies, matching `prior-art-survey.md`'s "no universal convention" conclusion. `if/then/else` and shape: RJSF merges the active branch transparently into the rendered schema; JSON Forms never lets it affect rendering; json-editor renders it as a visible switcher UI. Discriminator: RJSF is a hand-rolled OpenAPI fast path; Ajv is a compile-time opt-in vocabulary replacing oneOf codegen; JSON Forms has none — `indexOfFittingSchema` always runs a full compile+run loop over every branch.
