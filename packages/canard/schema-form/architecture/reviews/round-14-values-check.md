**전체.** 원리 다섯과 소유자의 축은 흔들리지 않았다. 여덟 검토 가운데 원리를 뒤집자는 것은 없다. 발견은 셋으로 갈린다. (가) 편집자 문장의 어긋남과 빈틈 — 원칙으로 닫는다(§3의 수정 명세, 스물넷 묶음). (나) 소유자의 판단이 필요한 것 열하나(§4) — 대부분 표면과 이름이며 축을 바꾸지 않는다. (다) 슬라이스 착수 때 짧은 설계로 닫을 항목(원장 §6에 더한다).

antigravity의 "무너질 지점 다섯"은 원장·ADR로 대조했다. 순수 `oneOf`의 같은 이름·다른 종류(ADR 0005 §3: 앞선 종류를 살리고 경고), `null` 호스트 아래 사용자 입력(ADR 0007:87: 자식의 투영된 방출이 생길 때만 호스트의 `null`을 비운다 — 08 §8에 보탠다), 자기 게이트를 끄는 파생(07 4.15: 예산 초과), `&children`의 깊은 경로(대상은 직계 자식 이름뿐), `extras`의 순서(구현 주의: 순서 보존 구조)로 모두 이미 답이 있거나 성립하지 않는다. 독립 PR 분할에 대한 견해(개발은 분할, 배포는 일괄)는 편집자 판단과 같다(08 §17).

## 3. 수정 명세 — 원칙으로 닫는 것 (worker 적용, verifier 게이트)

파일은 모두 `architecture/` 아래. "찾기"는 현재 문장(일부 인용), "바꾸기/더하기"는 적용할 문장이다. 같은 뜻의 문장이 여러 문서에 있으면 모두 고친다.

**F-1 접두 없는 키의 사실 정정.** `03-mental-model.md` §1.4 예약 층 행의 "표현 키로 렌더 계층만 읽으며 `&`를 붙이지 않는다" 뒤에 더한다: "접두 없는 키 가운데 코어가 읽는 것이 있다. `terminal`과 `FormTypeInput`의 유무는 청사진이 노드 종류(터미널인가)를 정할 때, `virtual`은 형상을 만들 때, `propertyKeys`는 방출 키 순서를 정할 때, `options.omitEmpty`·`omitTrailing`은 방출 투영이 읽는다. 어느 것도 정착 루프의 제어(게이트·잠금·값 규칙)가 읽지 않으므로 `&`를 붙이지 않는다(닫힌 목록은 14라운드 소유자 확인)." `02-target-overview.md:59`(표현 키 문단)와 `adr/0003` §1·§3(26행·55행 "없음 — 작업 루프 밖")에 같은 뜻을 한 문장으로. `adr/0011:56`의 "ADR 0003의 미결과 함께 정한다"를 "오늘도 `terminal: true`와 `terminal: false`가 양방향으로 있다(`getNodeGroup.ts:20-21`). 유지한다"로.

**F-2 07 4.27 표.** `07-conclusions.md:178` "값의 출처(`&derived`) | 주석 키워드와 같은 규칙 | 같음 | 같음 | 같음" 행과 179행 "동작(…)" 행을 한 행으로: "값·동작 키(`&derived`, `&injectTo`, `&unsetValue`, `&resetInteraction`) | 병합하지 않는다. 선언마다 규칙 하나, 같은 대상은 4.23 | 같음 | 같음 | 같음".

**F-3 같은 종류 동점.** `03:121` "같은 순위끼리(원천 둘의 `&injectTo`, 두 조각의 `control.derived`)는 원천(선언) 노드의 문서 순서에서 나중이 이긴다" → "같은 순위끼리는 원천(선언) 노드의 문서 순서에서 나중이 이기고, 같은 노드에 걸린 선언끼리는 층(`&children` 항목 < 조각의 `control` < 노드 자신)에서 세부가 이기며, 같은 층이면 조각의 전순서에서 나중이 이긴다(소유자 답 7·16·17 '뒤가 앞을 덮는다')". `adr/0003:80`, `adr/0007:35`, `02:165`의 같은 문장도.

**F-4 `&discriminator` throw 조건.** `03:178` "`&discriminator`가 가리키는 키가 호스트에 없음" → "`&discriminator`가 가리키는 키의 `const`·`enum`이 어느 분기에도 없음(분기 일부에만 없으면 그 분기는 게이트 없음, §6)". 02·ADR 0005에 같은 문장이 있으면 같게.

**F-5 잠금의 효과 범위.** `03:129` "리프가 아닌 노드의 잠금은 입력이 없으므로 효과가 없고(표준 독자의 기대와 다르므로 ADR 0010에 적는다)" → "터미널이 아닌 객체 노드의 잠금은 입력이 없으므로 효과가 없고(표준 `readOnly`는 청사진 경고, 표준 독자의 기대와 다르므로 ADR 0010에 적는다), 배열 노드의 잠금은 렌더 계층이 아이템 추가·삭제·이동 입력에 적용하며, 터미널 객체·배열은 입력이 있으므로 리프와 같다". `03:179`의 경고 항목 "리프가 아닌 노드의 표준 `readOnly`" → "터미널이 아닌 객체 노드의 표준 `readOnly`". `02:234·295`, `adr/0003:76`, `adr/0005:98`, `adr/0010` 약속 6도 같게.

**F-6 키 표와 `&children` 목록.** `adr/0003` §3 키 표에 행 추가: "`&unsetOnInactive` | 형용사(불리언) | 전이 | 켠 노드가 나갈 때 원본을 한 번 비운다. 기본 꺼짐. 네 층(노드 > `&children` 항목의 `control` > 조각의 `control` > Form 속성), 같은 층은 하나라도 유지면 유지". `&children`의 `control` 키 목록을 `03:53`, `adr/0003:53`, `07:314`, `02:296`에서 모두 "`readOnly`, `disabled`, `visible`, `active`, `default`, `derived`, `unsetValue`, `resetInteraction`, `unsetOnInactive`"로.

## 6. 답을 받은 뒤 (같은 날)

- 소유자가 열하나에 모두 답했다(`round-14-owner-answers.md`). O-1·2·3·6·7·9·11은 권고대로 또는 되물음의 답으로 확정해 원장·02·07·ADR·08에 반영했다(O-3은 출처 필드를 더하지 않음, O-7은 `validatorFactory`를 없애지 않고 넓힘, O-11은 `merge`에 배열 전략 옵션).

- O-2·4·5·10은 소유자 지시로 오류 처리 기법을 확장 조사했다(antigravity 선행 사례·원리, scout의 오늘 코드 사실. 원문 `raw-round14-error-policy-antigravity.md`, `raw-round14-error-facts.md`). 결과를 ADR 0014 "오류는 삼키지 않는다: 오류·경고·검증 결과의 세 층"으로 묶었고, 검증자 두 번(실패 → 조건부 통과, `raw-round14-error-policy-check.md`, `raw-round14-error-policy-check-2.md`)을 거쳐 3판이 소유자 확인 대기다.
- 문서 게이트 네 번(실패 → 실패 → 실패 → 조건부 통과 → 잔여 수정)으로 §3의 스물넷 묶음과 뒤따른 발견 마흔 남짓을 모두 닫았다. 08이 소유자 최종 검토용이다.
