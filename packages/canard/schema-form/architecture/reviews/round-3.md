## 3. 판정

"출처" 약어: RL=작업 루프 레드팀, RC=계약 레드팀, C=codex, A=antigravity, SP=스파이크.

### 3.1 작업 루프 (A)

| # | 명세 | 판정 | 근거 | 처방 (§6) |
| - | ---- | ---- | ---- | --------- |
| T1 ★ | A3-1 emit은 (스키마, raw)의 함수 | **반례** | (a) 조각 둘이 x를 다른 default로 선언하면 같은 raw가 활성 순서에 따라 x:1 / x:2 (RL 실행). "처음 활성"이 정착 단위인지 수명 단위인지 미정의 — 정착 단위면 사용자가 지운 값을 매 정착 되살린다. | T5 ★ | A3 4항 옵션 A(단조) | **반례** | 부정 가드 + 다른 조각의 활성(포함 키 변화)에서 `then`과 `else`가 동시에 켜진다. AJV는 `additionalProperties`/`unevaluatedProperties`가 없으면 통과시키고 있으면 기각(C 실행: A `{seed,a:'A',x:1}` vs B `{seed,x:1}`). 옵션 B는 3바퀴에 검증기가 받는 고정점. **그러나 B에도 고정점이 없는 스키마가 있다** — `if not required x then x default` (C 실행: cap 2면 `{}` invalid, cap 3면 `{x:1}` valid, 진동). 4항의 "어긋남은 검증기의 에러로 드러난다"는 거짓 (SP D4) | E6 |

### 3.2 판별식 식별 (B)

| # | 판정 | 근거 (RC 전부 실행) | 처방 |
| - | ---- | ------------------- | ---- |
| B1 `allOf`/`$ref` | **반례** | 2단 상속(Persian→Cat→Pet, 태그가 Cat의 `allOf` 안)에서 한 단계 평탄화가 태그에 닿지 못해 값 집합이 `[]`, 4단계가 공허히 "서로소" → 가드 `{enum: []}`는 AJV가 스키마로도 거부. 얕은 병합은 `type:integer ∧ const:'1'`에서 어떤 값도 안 받는 분기를 만든다. 자기 참조 `$ref`는 미정의 | E14 |
| B2 null | **반례** | `type:['object','null']` 분기와 `nullable:true`(strict에서도 컴파일)는 벗겨지지 않아 nullable=false인데 AJV는 `{pet:null}`을 통과시킨다. pydantic `Optional[discriminated]` = `anyOf:[{oneOf:[…]}, null]`은 바깥이 단일 분기가 되어 안쪽 재귀가 미정의 | E14 |
| B3 후보 | **반례** | typescript-json-schema 출력 `{apiVersion: const 1, kind: const 'circle'}`: 첫 분기의 키 순서로 `apiVersion`을 고른 뒤 겹침을 보고 `select` — `kind`가 유효한 판별식인데 버린다. 키를 정렬하는 생성기면 항상 `select`. 다원소 `enum`(zod `z.enum` 태그, pydantic 다중 `Literal`)도 허용하면 가드가 AJV와 3/3 일치 | E14 |
| B4 겹침 | 통과(G1) / 반례(왕복) | `select`로 떨어져 필드를 숨겨도 로드·방출 판정은 같다. 통과 이유가 분기 1 → 0으로 바뀌고 키를 잃는다 — S6 | S6으로 기록 |
| B5 mapping | **반례 — 명세의 사실 오류** | "표준 검증기는 어떤 값도 통과시키지 않는다"는 거짓. swagger petstore에서 표본 3/4가 `oneOf` 통과(분기의 `required`가 다르다). `{petType:'Cat', packSize:3}`은 Dog로 통과(태그 무시). Ajv `discriminator:true`는 mapping에 throw하고, mapping을 지워도 `allOf` 상속형에 throw하며, **pydantic 2.9 출력(const + mapping)에도 throw** — 플러그인이 켤 수 없다. B는 pydantic 출력을 `propertyName` + `const`로 올바르게 식별한다 | E14 |
| B6 `unevaluatedProperties` | 통과 | 5표본 모두 폼 판정 = 검증기(방출). 항상 방출되는 태그는 충돌 없음. 단 `{kind:'cat', meow, bark}`처럼 **로드는 invalid인데 비활성 분기의 키가 숨겨져 방출은 valid**가 되는 행이 있다 — 설계상 예외이며 S6 패턴으로 문서화한다 | 문서화 (§7) |

### 3.3 책임 경계 (C)

| # | 판정 | 근거 | 처방 |
| - | ---- | ---- | ---- |
| C1 세 종류의 쓰기 | 통과 + **미정의** | 잠복한 SECRET은 `setValue`로 사라진다 (RL·C 실행). 어느 쓰기가 어느 종류인지 **추론으로 정할 수 없다** — JSON 에디터가 객체를 통째로 돌려주며 `port`를 지웠을 때, 부분 쓰기면 삭제가 무시되고 전체 교체면 비활성 조각의 `clusterSecret`까지 사라진다 (A 시나리오). `injectTo`·`push`·`remove`·`reset`의 소속 미기재 (RL). "필드를 비우는 입력"이 `''`인지 없음인지 미정의 (RL) — E1이 정한다 | E15 |
| C2 로드 계약 | **모순 + 반례** | extra를 "호스트 raw"에 둔다는 문장이 A1의 "raw는 잘못된 종류일 때만"과 충돌 (RL·C 실행). 꺼진 조각이 선언한 키는 자식에 분배되면 저장에서 잃고(S6), extra로 두면 조각이 켜질 때 소유자가 둘 (RL). sparse 레코드 로드에서 default 주입만으로 dirty가 되므로 "옵션 불필요"는 반례 (A). 호스트 `required`/`dependentRequired`가 비활성 조각의 키를 가리키면 로드 valid, 방출 invalid, omit과 무관 (RC 7 실행). `getValue()`의 에러 목록 ≠ 로드 값의 에러 목록 — 비활성 분기의 키가 있으면 "required meow"가 추가된다 (RC 8). 태그 불일치 시 검증기는 `enum`이 아니라 분기별 `const` × N + `oneOf`를 내고 라우팅 규칙이 없다 (RC 8) | E16, E17 |
| C3 비객체 값 | 통과 + **모순** | 17 → type 에러 → 부분 쓰기로 복구 (RL·C 실행. SP는 구현만 하고 시나리오로 돌리지 않았다). 그러나 raw=17인 호스트 아래 자식 `node.value`가 'Alice'를 돌려준다 — ADR 0006 "부모·자식 값 불일치 불가"와 모순 (A). 형제가 원본 'B'가 아니라 default 'BD'로 돌아온다 — 17이 C1의 전체 교체로 자식 raw를 지웠기 때문 (RL) | E9, E18 |
| C4 문구 | **모순** | "원본을 바꾸는 예외는 없다"는 거짓 — 첫 활성의 default 주입(A3 3항이 raw 쓰기라고 명시), `injectTo`, C1의 부재 자식 삭제, C3의 호스트 raw 소거가 모두 raw를 바꾼다 (A·RL·C) | E19 |

## 5. Q5 — `virtual`의 사실과 선택지

현재 코드에서 확인한 것(scout, `file:line`은 `open-questions.md` Q5에 옮김):

- 문법: object 스키마의 `properties` 옆 `virtual: { period: { fields: ['startDate','endDate'], FormTypeInput } }`. 다른 위치는 없다.
- 전처리가 `required`·`then.required`·`else.required`의 가상 이름을 구성 필드로 펼친다(`processVirtualSchema.ts:13-29`, `transformCondition.ts:31-49`). **ADR 0001과의 충돌은 이 한 곳이다.**
- `VirtualNode`는 값을 소유하지 않는다 — 참조 노드의 값을 튜플로 비추고(`VirtualNode.ts:112-139`), 쓰기는 참조 노드로 부채질한다(`:39-96`).
- 이중 소유는 사실이다(`getChildren.ts:56-75`) — 그러나 렌더에서 구성 필드에 `virtual` 플래그를 달아 중복을 없앤다(`getChildNodeMap.ts:63-64`, `useChildNodeComponents.tsx:61`).
- object의 자식 전파·`resetToBlank`·계산 속성 처리 루프가 virtual 노드를 건너뛴다(`BranchStrategy.ts:279,353,703`) — 값 계산 자체가 아니라 virtual이 값에 관여하지 않는다는 뜻이다. 표현 전용이다.
- 보존해야 할 테스트는 `virtual.render.test.tsx` 12개와 `VirtualNode.test.ts`의 refresh 동작 4개다. virtual 전용 테스트 전체는 4파일 47개(교차검증 claude).

선택지:

| | 내용 | 결과 |
| - | ---- | ---- |
| (a) `&` 계열로 이동, 표현 전용 노드 종류 | `&virtual`(이름은 ADR 0003과 함께). 표준 `required`는 실제 필드만 적는다. core에 "참조 그룹" 노드 종류를 둔다 — ADR 0011의 표에 셋째 행: 자식의 출처 = **형제 참조**, identity = 이름, raw·local·emit 없음. 방출·가드·검증에 나타나지 않는다. 쓰기 부채질과 `RequestRefresh`는 유지 | ADR 0001 충돌 소멸. R16 해소. 테스트 16개 중 `processVirtualSchema`의 required 펼치기만 사라진다 |
| (b) 렌더 계층으로 완전히 이동 | core는 모른다. React 바인딩이 형제 노드를 묶는 컴포넌트를 제공 | `node.find('/period')`·`setValue` 부채질·`RequestRefresh`가 사라진다. C3(다른 렌더러 이식)에는 유리하나 기존 계약이 깨진다 |
| (c) 현행 유지 | `required`에 가상 이름 허용 | ADR 0001 위반이 남는다 |

권고: (a). 이유는 "값 없는 노드 종류"가 이미 필요하다는 것 — 터미널 전략과 A5의 union 호스트 처리에서 노드 종류의 목록이 어차피 다시 정해진다.

| E19 | C4 | "core는 **호출자가 쓴 값**을 고치지 않는다. core가 raw에 쓰는 자동 쓰기는 다음 다섯뿐이다: 로드와 OFF → ON 전이의 `default`(E1), 작성자가 선언한 `injectTo`(`derived`는 raw를 쓰지 않는다), 호출자가 선언한 전체 교체(E15), 배열의 구조 연산, 비객체 호스트 아래로 내려가는 부분 쓰기가 그 호스트의 raw를 비우는 것(C3·E18). 방출 제외(비활성 조각, omit, 금지 조각 — D-3)는 원본을 바꾸지 않는 정책이다" |
