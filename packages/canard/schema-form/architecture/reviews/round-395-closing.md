## 편집자 결정

- **395C-01 (후보 원천 보존의 규칙 셋 — NODE-043·NODE-051·WRITE-015·WRITE-034·WRITE-036의 적용, 35C-10의 좁힘).**
  - 【추론】 R1(a·b·c): 구조 이동이나 보존하는 호스트 이탈이 남기는 모든 자리는 파괴적 주소·저장 변경 전에 모든 깊이의 살아 있는·이미 잠복인 후보 원천을 포착하고, 같은 정착의 이후 모든 단계에서 (경로, 토큰) 정체와 메타데이터를 보존하며, 합성 입력보다 정확한 원천을 먼저 재생한다(NODE-051, 41C-01). 보호 여부는 직계 후보 수가 아니라 후보를 포함한 하위 트리로 정하고, 템플릿 없는 도착 예외는 후보가 있는 이동의 원본 포착에만 적용해 후보 없는·단일 종류 자리는 base의 조기 종료와 목적지 등록을 그대로 둔다. R2(d): 후보 이탈은 자동 쓰기 억제와 무관하게 상속 소유 범위 안의 공유되지 않은 도달 불가 낡은 열쇠를 지우되 억제된 정책 쓰기는 켜지 않는다(WRITE-015·034). 이 정리는 후보 소유 범위 안의 이탈에만 하고 같은 포착이 돌려준 소유 판정을 같은 이탈 결정 안에서 인자로만 넘겨 재사용한다 — 모듈·런타임·노드 어디에도 저장하지 않으므로 370라운드의 캐시 금지에 해당하지 않는다. 자연 경로는 찾지 못해 합성 재현이다. R3(e): 종류가 둘 이상인 배열 경로의 형상 밖 쓰기는 쓰는 순간 선언된 원천을 재귀적으로 청사진 전순서의 첫 종류에 묶고 그 주소의 다른 종류 원천을 지우며 길이와 미선언 꼬리는 보존하고 재진입 때 주인을 다시 바꾸지 않는다 — 객체의 형상 밖 쓰기 규칙(26C-13·14, WRITE-087)과 같아진다. 35C-10("비활성 배열 호스트의 잠복 원본은 배열 전체를 호스트 자신의 얼린 raw 하나로 보관")은 뒤집지 않고 좁힌다: 후보가 있는 배열 경로의 새 형상 밖 쓰기만 제외하고, 이탈 포착과 후보 없는·단일 종류 배열은 그대로다. 결정 62는 이 수정으로 (가) "현행 규칙 유지, 배열을 객체와 같게"로 잠정 닫으며 소유자 확정을 기다린다.
- **395C-02 (DETAIL 문장 수정의 기준과 codex 검증 과정의 관찰 — PROCESS-060의 보충).**
  - 【추론】 "기존 문장은 언어·내용을 바꾸지 않고 변경에 필요한 문장만 더하거나 고친다"는 지시의 뜻은, 변경으로 틀려지는 기존 문장은 같은 언어로 고치고 그렇지 않은 문장은 손대지 않는다는 것이다. 틀린 문장을 두고 옆에 새 문장을 더하면 코드와 어긋나는 사양 문장이 남으므로, 검증 3의 문서 FAIL("기존 한국어 문단을 다시 썼다")은 받아들이지 않는다. 같은 문단에 같은 인용 꾸러미를 문장마다 반복하지 않고 문단 끝 하나에 결정 코드를 더한다. 과정 관찰 셋: 검증자가 첫 실행에서 원본 작업 폴더의 node_modules 아래에 임시 설정 파일을 만들었다 지웠다고 스스로 보고했고(이후 쓰기 차단 뒤 전부 재실행, 추적 파일 깨끗) 검증자 지시서에 "원본 작업 폴더에 쓰지 않는다"를 명시한다; 검증자 보관 사본에서 unit 넷(ajv8 참조 경로 귀속, 시나리오 spec 셋)이 base·HEAD·R3 제거 사본 모두 똑같이 실패해 사본 환경 문제로 보며 실제 작업 폴더 게이트가 판정의 기준이다; fairy08이 짚은 대로 "재사용"처럼 관측값이 같은 설계 선택은 비용 시험(선택 호출 수 단언)으로만 고정되고, 정확한 호출 수 단언은 변경과 무관한 흔들림을 만들므로 base 이하 상한으로 적는다.
