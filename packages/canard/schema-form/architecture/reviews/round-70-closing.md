# 70라운드 닫기 — `nodeFromJSONSchema`의 새 서명을 07의 안대로 확정한다: 코어 전용 진입(소비자 겉면이 아님)이라 이주 행은 두지 않고, 직접 부르는 경로와 `<Form>` 경로가 같은 생성 통로를 지난다

2026-10-02. 07 작업자(전환, `feat/schema-form-switch` `94aeaa468`)가 `nodeFromJSONSchema`의 새 서명(`plan/07-switch/execution-adr.md` D3)을 보내 SURFACE 보충과 이주 행을 청했다. 원장은 "새 엔진 위에 다시 짓는다"(LANDING-067), "직접 부르는 경로와 `<Form>` 경로가 같은 계약"(VALIDATE-010), "core만 쓰는 호스트는 검증기를 선택 인자로"(CONTROLS-075), "렌더 계층이 터미널·원자 판정 함수를 청사진에 넘긴다"(REACT-003)만 정했고 서명은 열어 두었다. 오늘 이 함수는 `src/core/index.ts`가 이름으로 내보내고 `src/index.ts`는 내보내지 않으므로(`src/core/index.ts:1`) 소비자 겉면(SURFACE-058의 약 54)에 들지 않는다. 편집자 결정으로 닫는다. 소유자에게 물을 것은 없다.

### 70C-01 `nodeFromJSONSchema`의 새 서명은 07의 안대로다 — 선택 인자 `validator`(객체)·`validationMode`·`context`·`onChange`·`onStateChange`·`errorReporter`·`unsetOnInactive`·`disableAutomaticWrites`·`isTerminal`·`isAtomic`·`deferMountValidation`(기본 꺼짐)을 받아 마운트가 끝난 루트를 돌려주며, 안에서 바인딩 전용 통로의 트리 생성과 마운트를 차례로 부른다; `<Form>`의 첫 마운트와 재생성 reset도 같은 생성 통로를 지나므로 VALIDATE-010이 선다; 소비자 겉면이 아니므로 이주 행은 두지 않고 `core/index.ts`는 이름으로 내보내며 `src/index.ts`는 내보내지 않는다

- 닫는 항목: LANDING-067(보충), VALIDATE-010(보충), CONTROLS-075(보충), REACT-003(보충)
- 결정:
  - 【추론】 서명은 `nodeFromJSONSchema<Schema extends JSONSchema>(props: { jsonSchema: Schema; defaultValue?: InferValueType<Schema>; validator?: Validator; validationMode?: ValidationMode; context?: Dictionary; onChange?: (value: InferValueType<Schema> | undefined) => void; onStateChange?: () => void; errorReporter?: FormErrorReporter; unsetOnInactive?: boolean; disableAutomaticWrites?: boolean; isTerminal?: (schema: JSONSchema) => boolean | undefined; isAtomic?: (value: unknown) => boolean; deferMountValidation?: boolean }): InferSchemaNode<Schema>`이고 돌려주는 것은 마운트가 끝난 루트다. 칸마다 근거가 있다: `validator`는 함수 `validatorFactory`가 `{ compile, compileGuard, … }` 객체로 바뀌는 32C-01과 같은 방향이며 형은 새 엔진 쪽 `core/validation/type.ts`의 `Validator`다(공개 index가 아닌 모듈에서 내보냄, 32C-01); `context`는 옛 `contextNode`(`contextNodeFactory`의 노드)를 값으로 바꾼 것으로 `SchemaNode/`의 `setContext`가 받는 값이다; `errorReporter`는 05가 core 인자로 둔 보고기(`report`·`hasConsumer`, LANDING-064 PR-4 행)이고 `isTerminal`·`isAtomic`은 REACT-003이 렌더 계층이 넘긴다고 한 판정 둘이며 core만 쓰는 호스트가 주지 않으면 판정이 없다; `deferMountValidation`은 69C-05의 미룸 선택으로 기본은 꺼짐이라 켜지 않은 호출은 오늘대로 사슬 끝에서 검증을 요청한다. 안에서는 69C-01의 바인딩 전용 통로 가운데 "트리 생성(마운트 없음)"과 "마운트"를 차례로 부르고, `<Form>`은 첫 마운트에서 이 함수를(`deferMountValidation: true`, 버퍼형 보고기) 부르며 재생성 reset은 같은 트리 생성 통로 → 인계 → 마운트를 부르므로 두 경로가 같은 생성 함수를 지난다 — VALIDATE-010 "직접 부르는 경로와 `<Form>` 경로가 같은 계약"의 구현이다.
  - 【추론】 이주 행은 두지 않는다. 이주 표(LANDING-004–050과 그 뒤의 이주 행)는 소비자 겉면(`src/index.ts`가 내보내는 것)의 오늘 동작과 새 동작을 적는 표이고, `nodeFromJSONSchema`는 오늘도 `src/core/index.ts`만 이름으로 내보내며 `src/index.ts`는 내보내지 않으므로(`src/core/index.ts:1`) SURFACE-058의 약 54에 들지 않고 SURFACE-059의 대조 목록에도 들지 않는다. 대신 07은 이주 점검표(68C-02)의 끝에 "코어 전용 진입의 서명 변경"으로 한 줄 적고(옛 `{ jsonSchema, defaultValue, onChange, validationMode, validatorFactory, contextNode }` → 새 서명), 옛 `contextNodeFactory` 내보내기는 옛 엔진과 함께 `src/__legacy__/`로 가며 `core/index.ts`에서 빠진다. `core/index.ts`는 새 `nodeFromJSONSchema`를 이름으로 내보내고(와일드카드 금지), `src/index.ts`는 오늘처럼 내보내지 않는다. 문서 주석은 "core만 쓰는 호스트의 진입; `<Form>`은 같은 생성 통로를 바인딩 전용 함수로 부른다"를 적는다.
