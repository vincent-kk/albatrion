# 9라운드 도출 검토 보고서 (제3 검토자)

## Q1. 예약 층의 단계와 순서
(1) 질문: 작업 루프(표시 -> 계산 -> 파생 -> 전이 -> 커밋 -> 통지 -> 검증)에서 각 `&` 키의 배치 단계, 파생 단계 내 `&derived`·`&injectTo`·`&clearValue`의 순서, 복수 쓰기 경합 규칙, `&default` 채움 순서, 예산 초과 시 원본 B 커밋의 존속 여부.

(2) 축에서 따라오는 것:
- 단계 배치:
  - 계산 단계: `&active`, `&visible`, `&readOnly`, `&disabled`, `&children`. 형상 결정과 UI 상태 합성을 담당합니다 (`round-9-spec.md:112-124`, `03-mental-model.md:55-58`). [도출]
  - 파생 단계: `&clearValue`, `&derived`, `&injectTo`. 값 조작을 전담합니다 (`round-9-spec.md:24` 축 6항, `round-9-spec.md:26` 축 8항, `03-mental-model.md:59`). [도출]
  - 전이 단계: `&default` > `default`. 노드가 생길 때 1회 채웁니다 (`round-9-spec.md:56` 읽기 2, `round-9-spec.md:74-76` §3.1). [도출]
  - 커밋 단계: `&pristine`에 의한 `dirty`·`touched` 상태 초기화 (`round-9-spec.md:66-68`, `round-9-spec.md:118`). [도출]
  - 보조: `&watch`는 평가 단계가 아니라 정적 의존 경로 등록 메커니즘입니다 (`round-9-spec.md:117`). [도출]
- 파생 단계 내부 순서: 제거 -> 자기 변경 -> 타 노드 전파 인과율에 따라 (1) `&clearValue`(거짓에서 참 전이 시 값 제거), (2) `&derived`(의존 값 변경 노드의 자기 값 재계산), (3) `&injectTo`(값 변경 노드가 대상에 값 주입) 순서로 실행됩니다 (`round-9-spec.md:24` 축 6항, `round-9-spec.md:118-121`, `adr/0007-settle-cycle.md:32`). [확신 중]
- `&default` 채움과 다른 쓰기의 순서: 노드가 생길 때(로드 또는 조각 켜짐) 없음인 키에 1회만 채워지며, 이후 런타임에 `&clearValue`로 지워진 값은 다시 채워지지 않습니다 (`round-9-spec.md:74-76` §3.1). [도출]
- 예산과 원본 B 커밋: 상한(파생 라운드 25) 초과 시 중간 불완전 상태 대신 자동 쓰기 전체를 뺀 원본 B를 커밋하는 규칙은 새 목록에서도 그대로 유지됩니다 (`round-9-spec.md:32` 요약 발언, `06-conclusions.md:194`). [도출]
- 경합 규칙: 동일 노드에 복수의 `&injectTo` 또는 `&derived` 쓰기가 맞설 때의 승자 규칙은 축 문서에 명시되지 않았습니다.

(3) 실행 증거: 해당 없음 (실행하지 않았습니다).

(4) 소유자에게 남는 정책:
"동일한 대상 노드에 대해 복수의 `&injectTo` 또는 `&derived` 쓰기가 경합할 때, 스키마의 선언 전순서에서 나중에 선언된 쓰기가 이전 쓰기를 덮어씁니까?" [정책]

## Q2. 값 조작 표
(1) 질문: 조작 셋(채움·변경·제거) × 시점(로드·노드 생성·런타임) × 주체(호출자·사용자·예약 층)의 표.

(2) 축에서 따라오는 것:
축 4항(`round-9-spec.md:22`), 축 6항(`round-9-spec.md:24`), 읽기 2(`round-9-spec.md:48-56`), §3.1(`round-9-spec.md:74-76`), §3.4(`round-9-spec.md:112-125`)에서 아래 표가 도출됩니다. [도출]

| 조작 구분과 시점 | 로드 (마운트, 전체 교체, reset) | 노드 생성 (조각 켜짐) | 런타임 (정착 진행 중) |
| --- | --- | --- | --- |
| **채움 (호출자)** | `setValue(V)` 미선언 키 없음화, `defaultValue` | 해당 없음 (내부 사건) | `setValue(V, Merge)`의 새 키 주입 |
| **채움 (사용자)** | 해당 없음 | 간접 유발 (입력으로 조각 활성화) | 빈 입력란에 최초 값 입력 |
| **채움 (예약 층)** | `&default` > `default` (없음 키에 1회 채움) | `&default` > `default` (전이 주입, 1회 채움) | 없음 (채우기 규칙 A: 런타임 재채움 금지) |
| **변경 (호출자)** | `setValue(V, Overwrite)`로 전체 교체 | 해당 없음 | `setValue(V, Merge)`로 기존 키 수정 |
| **변경 (사용자)** | 해당 없음 | 해당 없음 | 기존 입력란 편집 |
| **변경 (예약 층)** | `&derived` / `&injectTo` (5.1 fire 채택 시 발화) | 의존 노드 변경에 따른 `&derived` / `&injectTo` | `&derived` (자기 값 재계산), `&injectTo` (타 노드 덮어쓰기) |
| **제거 (호출자)** | `setValue(null)`로 전체 자식 없음화 | 해당 없음 | `setValue({ k: undefined }, Merge)`로 키 제거 |
| **제거 (사용자)** | 해당 없음 | 해당 없음 | 입력란 텍스트 삭제 (빈 문자열 입력) |
| **제거 (예약 층)** | `&clearValue` (전이 참 시), `&active: false` 방출 제외 | `&clearValue` (전이 참 시), `&active: false` 방출 제외 | `&clearValue` (거짓에서 참 전이 시 값 제거), `&active: false` 방출 제외 |

(3) 실행 증거: 해당 없음.

(4) 소유자에게 남는 정책:

## Q3. root·local·inherit 위계와 자식 집합 제어의 결합 규칙
(1) 질문: 루트 스키마의 `readOnly`·`disabled`, Form 속성, 조상의 조각 범위 제어, `&children`, 노드 로컬 키의 위계 및 결합 규칙, `&children`의 값 형태 후보 둘의 비교.

(2) 축에서 따라오는 것:
- 결합 규칙:
  - 표시 계열(`active`, `visible`): 상위가 가리면 하위도 가려지므로 AND 결합(모두 참이어야 켜짐)을 적용합니다 (`round-9-spec.md:114-115`, `03-mental-model.md:12`). [도출]
  - 잠금 계열(`readOnly`, `disabled`): 어느 하나라도 잠그면 잠겨야 하므로 OR 결합(하나라도 참이면 잠김)을 적용합니다 (`round-9-spec.md:60` 읽기 3, `raw-round9-code-facts.md:37`, `SchemaNodeInput.tsx:111-112`). [도출]
- 위계:
  - 잠금 계열: `Form prop || rootSchema || inherit(&children) || local(node)`의 누적 OR 합성입니다 (`round-9-spec.md:28` 축 10항, `round-9-spec.md:60` 읽기 3). [도출]
  - 동일 노드 내 로컬 키 경합: `control.키`가 `&키`보다 우선합니다 (`round-9-spec.md:101`, `checkComputedOptionFactory.ts:25-26`). [도출]
- `&children` 형태 후보 비교:
  - 후보 1 (제어 종류별 대상 정의, 예시: `{ readOnly: { all: true } }`): 하위 전체에 동일 제어를 일괄 적용하기 편리하나, 대상 노드 관점에서 여러 제어가 파편화됩니다.
  - 후보 2 (대상 필드별 제어 묶음, 예시: `{ properties: { a: { readOnly: true } } }`): JSON Schema의 객체 구조와 일치하여 직관적이고 대상 노드별로 응집되나, 전체 일괄 제어 시 표현이 중복될 수 있습니다 (`round-9-spec.md:108`). [확신 중]

(3) 실행 증거: `SchemaNodeInput.tsx:111-112` 코드 사실 확인 완료 (`raw-round9-code-facts.md:37`).

(4) 소유자에게 남는 정책:
"`&children`의 선언 문법으로 제어 종류별 대상 정의(후보 1) 대신 JSON Schema 구조와 친화적인 대상 필드별 제어 묶음(후보 2)을 채택합니까?" [정책]

## Q4. 노드의 유효 스키마 병합표(5항)
(1) 질문: 검증 키워드, 주석 키워드, 폼 전용 키의 병합 우선순위(본체, `allOf`, 켜진 `then`, 켜진 분기) 및 유효 스키마 변경 시 통지 배달.

(2) 축에서 따라오는 것:
- 축 5항(`round-9-spec.md:23`)은 폼이 노드의 현재 제약조건(JSON Schema 조건)을 최신화하여 제공할 의무가 있음을 명시합니다.
- 검증 키워드(`minimum`, `maximum`, `enum`, `required` 등): 연언 문맥(`allOf`, 켜진 `then`)에서는 교차(교집합, 최소 범위, 합집합)하고, 분기(`oneOf`/`anyOf`)에서는 켜진 단일 분기의 제약이 overlay됩니다 (`adr/0005-blueprint-analysis-and-node-sharing.md:45, 62`). [도출]
- 폼 전용 키(`&FormTypeInput`, `&options`, `&*`, `control.*`): 전순서(본체 < `allOf` < `then`/`else` < 활성 분기)에 따라 나중에 활성화된 조각의 선언이 이전 선언을 덮어씁니다 (`constants.ts:34-88`, `round-9-spec.md:101`). [도출]
- 주석 키워드(`title`, `description`, `readOnly`, `format`, `default`): 축 5항의 최신화 의무 및 UI 힌트 제공 목적에 비추어, 조건부 조각이 켜지면 해당 조각이 선언한 주석 키워드가 본체를 덮어쓰는 C안이 도출됩니다 (`06-conclusions.md:291`). [확신 중]
- 유효 스키마 변경 통지: 유효 스키마가 변경된 노드는 해당 커밋의 통지 배달 집합에 포함되어 렌더러에 즉시 전달됩니다 (`06-conclusions.md:180` 4.9). [도출]

| 키워드 부류 | 본체 | `allOf` 항목 | 켜진 `then`/`else` | 켜진 분기 (`oneOf`/`anyOf`) | 병합 규칙 |
| --- | --- | --- | --- | --- | --- |
| 검증 키워드 | 기본 제약 | 교차 축소 | 교차 축소 | 제약 교체 또는 축소 | 연언 교차, 선언 단일 반영 [도출] |
| 주석 키워드 | 기본 주석 | 앞선 항목 우선 | 본체 덮어씀 (C안) | 본체 덮어씀 (C안) | 조건부 조각 활성 시 덮어씀 [확신 중] |
| 폼 전용 키 | 기본 설정 | 나중 항목 덮어씀 | 나중 선언 덮어씀 | 활성 분기 덮어씀 | 전순서 나중 선언 승리 [도출] |

(3) 실행 증거: RJSF 6.6.1 실행 결과 조건부 조각이 본체 주석을 덮어씀을 확인한 기록 참조 (`06-conclusions.md:139`, `06-conclusions.md:291`).

(4) 소유자에게 남는 정책:

## Q5. 분기와 조각의 규칙 재서술
(1) 질문: §3.2 컨벤션을 ADR 0002 조각 표로 재서술, 판별식 식별·값 가드·호스트 소유·선택 칸·추론·점수·동점의 삭제 확인, 상태 칸 축소, 축 2항 강제 방식 검토.

(2) 축에서 따라오는 것:
- 조각 표 재서술: 축 1항(`round-9-spec.md:19`)과 §3.2(`round-9-spec.md:80-93`)에 따라 폼은 분기 문법을 자체 해석하지 않으며, 모든 조건부 조각은 `if` 게이트(검증기 동기 판정) 또는 `&active` 게이트(예약 층 평가식)로 통합됩니다. [도출]

| 구문 | 게이트 (가드) | 조각 | 문맥 |
| --- | --- | --- | --- |
| `if`/`then`/`else` (최상위, `allOf`, `oneOf`/`anyOf` 분기 내부) | `if` (검증기 판정) | `then` / `else` (`else: false` 필수) | 연언 / 선언 |
| 무조건 블록 (`properties`, `allOf` 무조건 항목) | 항상 참 | 블록 전체 | 연언 |
| 예약 층 조각 제어 | `&active` (표현식 판정) | 선언된 노드 집합 | 연언 / 선언 |

- 삭제 항목 전수 확인:
  - 판별식 식별 (ADR 0005 §4 E14): 지워짐 (축 1항 "const/enum 등을 사용하는 특수 문법은 쓰지 않는다"). [도출]
  - 값 가드 (판별식 + required): 지워짐. [도출]
  - 판별 프로퍼티의 union 호스트 소유 (E8): 지워짐 (축 2항에 의해 조건 필드는 `properties`에 선언). [도출]
  - 상태 칸 `selection`: 지워짐 (폼이 분기 선택 상태를 소유하지 않음). [도출]
  - `setSelectedBranch` API (N2): 지워짐. [도출]
  - 초기 분기 추론 및 키 수 점수 (4.4 D-14): 지워짐. [도출]
  - 비판별 union 동점 처리 (5.5 D-14′): 지워짐. [도출]
- 상태 칸 축소: 노드의 상태 칸은 원본(`raw`)과 `extras` 둘만 남습니다 (`03-mental-model.md:21-34`의 `selection` 삭제). [도출]
- 축 2항 강제 방식: 코어가 `if` 내부를 직접 파싱하여 검사하는 것은 축 1항("if 블록은 해석하지 않는다") 및 P1′와 정면으로 충돌하므로, 런타임 파싱 대신 작성 규칙 컨벤션으로 둡니다. [확신 중]

(3) 실행 증거: ajv 8.17.1 실측에서 `oneOf`/`anyOf` 분기 내 `if` 사용 시 `else: false`가 없을 경우 다중 통과로 기각됨을 확인 완료 (`round-9-spec.md:82-93`, `spikes/round9/REPORT.txt:47-51`).

(4) 소유자에게 남는 정책:
"조건 프로퍼티가 `properties`에 선언되었는지를 코어가 `if` 스키마를 파싱하여 검사하지 않고, 스키마 작성자 컨벤션으로만 유지합니까?" [정책]
