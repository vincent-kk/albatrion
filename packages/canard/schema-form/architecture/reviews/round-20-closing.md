# 20라운드 닫기 — 새 설계문서와 ADR의 근거 표기

2026-09-28. 설계문서 PR(01)의 형식 명세를 원장과 대조하던 검증자가 지적했다: PROCESS-023은 08 문서의 근거 표기를 "원장 §n", "ADR 00nn", "07 n.n"으로 정했는데, 원장에서 만드는 새 설계문서와 ADR은 근거를 원장 ID로 단다. 표기의 대상이 바뀌는 것은 가리킴 바꿈이 아니라 규칙의 내용이므로, 문서가 원장을 앞서지 않도록 원장에 먼저 적는다. 소유자 물음 없이 편집자가 닫는다: 원장이 정본이고 개발은 새 설계문서를 중심으로 하며(PROCESS-050), ADR과 설계문서는 원장에서 만들고 옛 문서는 백업 디렉토리로 가며(PROCESS-061), 절 단위 통과는 새 설계문서에서만 하므로(PROCESS-062), 새 문서의 근거가 가리킬 수 있는 것은 원장 항목뿐이다.

### 20C-01 새 설계문서와 ADR의 근거 표기 — 문장 끝 괄호 안에 원장 ID

- 닫는 항목: PROCESS-023(보충·충돌), PROCESS-068(새 항목)
- 결정:
  - 【추론】 원장에서 만드는 설계문서와 ADR은 근거를 문장 끝 괄호 안에 원장 ID로 적는다(`…한다(NODE-002).`, 여럿이면 `(NODE-002, WRITE-090)`).
  - 【추론】 "원장 §n", "ADR 00nn", "07 n.n" 표기는 옛 문서(00–09, 옛 ADR)의 근거 표기이며 새 설계문서와 ADR에서는 쓰지 않는다.
  - 【추론】 약어를 쓰지 않고 원리·목표·소유자의 축 항목을 처음 나올 때 풀어 쓰는 규칙(PROCESS-023의 앞 두 문장)은 새 설계문서와 ADR에 그대로 적용된다.
- 근거: PROCESS-050(원장이 정본, 설계문서 중심의 개발), PROCESS-061(원장에서 ADR과 설계문서를 쓰고 옛 문서를 백업 디렉토리로), PROCESS-062(절 단위 통과는 새 설계문서에서만). 옛 표기가 가리키던 문서(08의 "원장" = `03-mental-model.md`, 옛 ADR, 07)가 모두 백업으로 가므로 새 문서의 근거는 원장 항목만 가리킬 수 있다. 소유자 물음이 아닌 까닭: 원리·현행 항목으로 유도되는 것은 편집자가 【추론】으로 닫는다(PROCESS-066).
- 게이트: `ledger/checks/doc-coverage.mjs`(설계문서 PR이 만든다)의 문장 ID 검사가 이 표기를 기계로 확인한다.
