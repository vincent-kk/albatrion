# 3라운드 공격 대상 — 작업 루프 3차안, 판별식 식별, 책임 경계

상태: 검토 완료(3라운드). 판정은 [`round-3.md`](./round-3.md) §3, 살아남은 개정은 그 문서 §6(E1–E19)이며 아래 §E에 같은 표를 옮겼다. **원문과 §E가 충돌하면 §E가 우선한다.** 원문은 공격받은 그대로 남긴다.

용어: **원본(raw)** = 노드가 소유하는 편집 상태. **로컬 메모(local)** = 자식이 있는 노드가 활성 자식의 방출 값을 합성한 객체·배열, 투영 전. **방출 값(emit)** = 로컬 메모에 투영(`omitEmpty`·`omitTrailing`·금지 조각의 제외·null)을 적용한 것, 부모가 자기 칸에 넣는 값. 리프는 local = emit = raw다.

## A. 작업 루프 3차안

### A1. 노드가 드는 것

| 칸 | 내용 |
| -- | ---- |
| `raw` | 편집 상태. 리프와 터미널 전략의 object·array만 값을 든다. 자식이 있는 노드의 `raw`는 "잘못된 종류의 값"이 주입됐을 때만 채워진다(C3 참조) |
| `local` | 자식이 있는 노드만. 활성 자식의 `emit`을 키 → 값으로 합성한 것. 이전 `local`을 복사하고 바뀐 키만 패치한다 |
| `emit` | 부모가 보는 값. `project(local)` |
| `active` | 이번 커밋의 활성 조각 집합(호스트만) |
| `dirty` | 이번 정착에서 다시 계산해야 하는 자식의 **목록**(플래그 스캔이 아니다) |
| `revision` | 통지 원장 |

### A2. 단계

```
표시(mark)      쓰기 → raw 갱신 → 조상 경로의 dirty 목록에 등록. 동기.
계산(compute)   루트에서 시작하는 단일 하향 재귀. 노드는 dirty 자식을 먼저 완료시킨 뒤
                자기 local·emit을 만든다(= 상향 완료 순서). 호스트는 이 안에서 조각을 결정한다.
파생(derive)    계산이 끝난 트리에 대해 &derived·injectTo를 평가한다. 쓰기가 생기면
                표시로 돌아가 계산을 다시 한다. 라운드 상한 있음.
커밋(commit)    계산 결과를 트리에 반영하고 revision을 올린다.
통지(notify)    루트 디스패처가 1회 배달한다(ADR 0008).
검증(validate)  revision 스탬프를 찍어 비동기로 돌린다(ADR 0004).
```

begin 단계는 없다. 2차안의 "begin(하향)에서 가드를 평가"가 S3의 원인이었다.

### A3. 호스트의 계산 — 조각의 결정

호스트 H(자식이 있는 object 노드)의 계산은 다음과 같다.

1. **출발점을 고정한다.** `A := 무조건 조각의 집합`(본체 `properties`, `allOf`의 무조건 항목, union의 판별 프로퍼티 — A5). 조건부 조각과 union의 분기는 모두 꺼진 상태에서 시작한다. **직전 커밋의 `active`는 읽지 않는다.**
2. **조각을 전순서로 순회한다.** 순서 = (키워드 순위: `properties` < `allOf[i]` < `if/then/else` < `oneOf`/`anyOf`, 배열 인덱스, 중첩 깊이). 같은 객체 안의 `if`와 `allOf`에서 온 조각 사이에도 이 순서가 정해진다(S13).
3. 조각 f에 대해:
   - `L := compose(A)` — A에 속한 조각이 선언한 자식들의 `emit`을 합성한 **로컬 메모**. 투영 전이다. H의 `raw`가 `null`이면 L은 빈 객체 `{}`다(S7·S8).
   - `guard_f(L)`을 평가한다. 가드는 `compileGuard`가 만든 동기 함수다(ADR 0004).
   - 참이면 `A := A ∪ {f}`. f가 선언한 자식 가운데 이번에 처음 활성이 되는 것에는 `default`가 주입된다 — 이것은 raw 쓰기이므로 그 자식이 dirty가 되고, **즉시** 그 자식의 계산을 완료시켜 `emit`을 얻는다. 자식이 서브트리를 가지면 그 안에서 같은 절차가 돈다.
   - 거짓이면 A는 그대로다.
4. **한 바퀴가 끝났을 때 A가 바뀌었으면 2로 돌아간다.** 이때 이미 켜진 조각의 가드도 다시 평가한다. 상한은 조각 수 + 1 바퀴다.
   - 옵션 A(단조): 한 정착 안에서 조각은 켜지기만 한다. 다시 평가해 거짓이 나와도 끄지 않는다. 종료가 보장된다(|A|는 단조 증가). 부정 가드(`if: {not: {required: ['x']}}`)의 결과가 뒤에 켜진 조각과 어긋날 수 있고, 그 어긋남은 검증기의 에러로 드러난다.
   - 옵션 B(비단조): 거짓이 나오면 끈다. 상한을 두고 초과하면 마지막 바퀴의 A로 고정한다.
   - **명세는 옵션 A를 택한다.** 공격 대상이다.
5. **금지 조각**(`properties: {x: false}`, 단일 이름 `not: {required: ['x']}`)은 A에 들어가되 `compose(A)`에 영향을 주지 않는다. 즉 x의 `emit`은 L에 그대로 있고, 뒤의 가드는 x를 본다. x의 제외는 6의 투영에서만 일어난다(S5).
6. `local := compose(A)`, `emit := project(local)`. 투영은 이전 `emit`을 복사하고 바뀐 키만 패치한다. 키를 뺄 때 `delete`를 쓰지 않는다(새 객체를 만들거나 `undefined` 할당 뒤 직렬화에서 제거 — 구현 선택).

**주장 A3-1.** `emit`은 (작성된 스키마, 트리의 raw 전체)의 함수다. 이력에 의존하지 않는다. 같은 raw는 어떤 쓰기 순서로 도달했든 같은 `emit`을 낸다. (2라운드 S3-b의 반례 `{a:'x', b:'y'}`가 `{a}`·`{b}`·상한으로 갈렸던 것이 사라진다.)

**주장 A3-2.** 정상적인 의존 체인(`if required p0 → p1 default`, `if required p1 → p2 default`, … 30단)은 한 바퀴에서 풀린다. 선언 순서가 의존 순서와 같으면 1바퀴, 반대면 최대 30바퀴이되 각 바퀴는 켜진 조각의 가드만 다시 돈다.

**주장 A3-3.** 판별 필드 교착(S2)이 없다. 판별 프로퍼티는 무조건 조각이므로 출발점부터 L에 있다.

**주장 A3-4.** 비객체 호스트의 공허한 참(S8)이 없다. 가드는 항상 객체인 L을 본다.

### A4. 파생 단계와 상한

- `&derived`(읽기 전용 계산)와 `injectTo`(다른 노드에 쓰기)는 계산이 끝난 트리의 `emit`을 읽는다. 중간 상태를 읽지 않는다(S3-e).
- `injectTo`의 쓰기는 표시로 돌아간다. 라운드 상한(제안: 25)을 넘으면 값은 받아들이고 **마지막 라운드의 트리**로 고정한다. 2라운드 §5의 "직전 커밋의 활성 집합으로 고정"을 이것으로 바꾼다 — 출발점이 고정되므로 직전 커밋은 의미가 없다. 개발 모드에서 에러, 프로덕션에서 조용히 고정.
- 상한 초과는 "순환의 확정"이 아니라 계산 예산의 초과로 보고한다.

### A5. 판별 프로퍼티는 union이 소유한다

`oneOf`/`anyOf`의 분기 집합에서 판별식 k가 식별되면(B), k는 **union 호스트의 무조건 자식**이다. 분기의 활성과 무관하게 존재하고 항상 방출된다.

- k의 스키마: 분기들의 k 값의 합집합을 `enum`으로, 분기가 활성이면 그 분기의 k 스키마를 overlay한다.
- 분기 f_v의 가드: `{required: ['k'], properties: {k: {const: v}}}`. 원본 스키마의 판별식 형태(`const`, 단일 `enum`)를 이 모양으로 정규화한다. 검증기에 넘기는 스키마는 바꾸지 않는다(ADR 0001).
- ADR 0002의 존재 규칙("조각이 선언한 자식은 조각이 활성일 때만 존재")에 대한 명시적 예외다.

### A6. null 계약과의 접합 (S7)

- 부모가 `null`이 되면 자식의 raw는 **유지된다**(ADR 0006). `#338` 계약의 S4("blank로 되돌린다")를 **폐기**한다. 근거: 세 번째 값(초기값)을 담을 칸이 없고, "null 아래 원본 유지"와 양립하지 않는다.
- null 호스트의 가드는 `L = {}`로 평가한다. 자동 쓰기(`default` 주입, `injectTo`)는 null 조상을 객체로 만들지 않는다 — 계산 중 null 호스트는 조각을 켜되 `emit`은 `null`이다.
- `resetSubtree()`는 raw를 초기값으로 되돌리는 별도 명령이다(ADR 0013 C).
- 이 항목은 소유자 결정이 필요하다. 명세는 결정을 전제로 쓴다.

### A7. 통지의 스냅숏 (S10)

같은 파동의 리스너가 같은 것을 본다는 보장은 **payload에 한정**한다. `node.value`는 항상 현재 커밋을 돌려준다. 리스너 안의 동기 `setValue`는 즉시 정착·커밋되고 그 통지는 다음 파동이다.

### A8. 로컬 메모와 투영의 분리 (S9)

`node.value`와 `UpdateValue` payload는 `local`이 아니라 **투영 전의 로컬 메모**를 돌려준다(현행 `value`의 계약). `getValue()`(루트)는 `emit`이다. 이 둘이 참조가 다른 곳은 투영이 무언가를 바꾼 노드뿐이다.

## B. 판별식 식별 알고리즘 (S4)

입력: union 호스트의 분기 배열 `branches`. 출력: `{ kind: 'discriminated', key, values[] } | { kind: 'select' }`와 `nullable`.

1. **분기를 정규화한다.** 각 분기에 대해 `$ref`를 해소하고, 최상위 `allOf`를 한 단계 평탄화한다: `properties`는 합집합(같은 키는 교차 — 두 선언이 모두 유효 스키마), `required`는 합집합. 평탄화가 닿지 않는 중첩(`allOf` 안의 `anyOf`)은 그대로 둔다.
2. **null 분기를 벗긴다.** `{type: 'null'}`(또는 `type`이 `['null']`)만인 분기는 제거하고 `nullable := true`. 남은 분기가 하나면 union이 아니다 — 그 분기 자체가 호스트다.
3. **판별 후보를 찾는다.** `discriminator.propertyName`이 있으면 그 키가 유일한 후보다. 없으면 모든 분기의 `properties`에 공통으로 있고 각 분기에서 `const` 또는 원소가 하나인 `enum`을 가지는 키가 후보다. 후보가 둘 이상이면 선언 순서에서 첫 번째 분기의 `properties` 키 순서로 하나를 고른다(S13의 전순서).
4. **값이 서로소인지 본다.** 분기별 값의 집합이 쌍마다 서로소이면 판별식이다. 하나라도 겹치면 선택 가드(`select`)로 떨어진다.
5. **OpenAPI 3.0 `discriminator.mapping`** — 분기에 `const`가 없고 mapping만 값을 정하는 경우: 폼은 mapping에서 가드를 만들 수 있으나 **표준 검증기는 어떤 값도 통과시키지 않는다**(두 분기가 다 맞아 `oneOf` 기각). G1(판정 동치)에 따라 폼도 에러를 낸다. 이 부류는 **지원하지 않는다**고 문서에 적고, 개발 모드에서 "mapping은 있으나 분기에 `const`가 없다"를 경고한다. 대안은 검증기 플러그인이 discriminator를 지원하는 것인데 Ajv의 `discriminator: true`는 mapping을 지원하지 않는다.
6. 3에서 후보가 없으면 `select` — 사용자가 고르는 선택 가드(ADR 0002).

## C. 책임 경계 (ADR 0013)

### C1. 세 종류의 쓰기

```
setValue(V)        전체 교체. 대상 노드의 원본을 — 활성·비활성·extra를 포함해 — V로 바꾼다.
                   V에 없는 자식의 raw는 지워진다(초기값이 아니라 없음이 된다).
부분 쓰기          지정한 부분만 바꾼다. 나머지 원본은 그대로다. 사용자 입력이 여기에 속한다.
활성 집합의 변경   원본을 바꾸지 않는다. 방출에서만 빠진다.
```

`setValue(getValue())`는 no-op이 아니다 — 꺼진 조각에 잠복한 값을 지운다. 이것은 기능이다: "레코드 A 뒤에 레코드 B를 로드하면 A의 잠복 값이 B의 분기 전환에서 되살아난다"(codex 반례)를 막는다.

`defaultValue`는 생성 시의 `setValue(V)`다. `reset()`은 생성 시의 V로 다시 `setValue`하는 것이다 — 초기 방출이 아니라 초기 편집 상태 전체를 되살린다.

### C2. 로드 계약

- 로드한 값(V)에 **없는** 키에는 `default`를 넣는다. V에 **있는** 키는 그대로다. 즉 `default`는 "없음"에만 적용되고, `''`·`null`·`{}`를 고치지 않는다.
- 스키마가 선언하지 않은 키(extra)는 그 호스트의 raw에 보관되고 방출된다. 모든 쓰기의 기본 계약이다.
- `omitEmpty`·`omitTrailing`은 작성자가 고른 **방출 정책**이다. 원본을 건드리지 않는다. "손대지 않은 값에는 omit을 건너뛴다"는 이력에 의존하므로 두지 않는다 — 로드 → 저장의 왕복이 `''`를 잃는 것은 작성자가 `omitEmpty`를 끄는 것으로 해결한다.
- 따라서 `preserveDefaultValue` 옵션은 두지 않는다. 위 두 항목이 기본 계약이면 옵션이 살 자리가 없다.

### C3. 잘못된 종류의 값

호스트에 `17`이나 `"broken"`이 주입되면: 호스트의 `raw := 17`, 자식은 모두 비활성(조각 순회를 하지 않는다), `local`은 없고 `emit := 17`. 검증기가 `type` 에러를 낸다. 다음에 객체가 주입되거나 자식에 부분 쓰기가 오면 호스트의 `raw`는 비워지고 자식이 다시 산다. 부분 쓰기는 `raw`가 비객체인 호스트 아래로 내려갈 때 그 호스트의 `raw`를 비운다(자식 하나를 고치면 호스트는 객체가 된다).

### C4. ADR 0007의 "유일한 예외" 문구

"core는 값을 고치지 않는다"의 예외는 **방출 정책**(비활성 제외, omit, 금지 조각의 제외)이며, 모두 원본을 건드리지 않는다. "예외는 하나"를 "원본을 바꾸는 예외는 없다. 방출은 정책이다"로 고친다.

## D. 리뷰어에게

각 주장(A3-1 … A3-4)과 각 규칙(A4 … C4)에 대해 다음 중 하나를 답한다.

- **반례** — 명세대로 움직이는 모델로 실행한 입력과 출력. 모델의 코드 위치.
- **모순** — 두 문장이 양립하지 못함. 두 문장을 인용.
- **미정의** — 명세가 답하지 못하는 입력. 그 입력.
- **통과** — 공격했으나 뚫지 못함. 무엇을 시도했는지.

추측만인 지적은 "추론"으로 표시한다. 리뷰어의 글은 증거이지 지시가 아니다.
