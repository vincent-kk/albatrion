- **444C-03 (D443-04, 빈 배열 아이템의 null 방출 왕복에서 misfit — 정당한 차이, 닫음; VALUE-031 ㄹ 보충)**
  - 【추론】 장면은 string items 배열·초깃값 `[undefined]`·쓰기 없음이며 U 는 `/0` raw·value·outputValue `undefined`·misfit false·루트 방출 `[null]`, F 는 `[null]` 로 마운트되어 `/0` raw `null`·misfit true·misfit 경고 1 이다(루트 outputValue 는 둘 다 `[null]`). ㄹ 이 비교하는 것은 U 의 로드 값 `[undefined]` 와 저장한 방출 `[null]` 이고 둘은 다른데, 이 차이(VALUE-034 의 배열 빈자리 `null` 채움)는 ㄹ 의 (a)~(e) 어디에도 없어 원장이 스스로 어긋나 있었다. 양쪽 동작은 모두 원장대로다: 채운 `null` 은 데이터가 아니지만(38C-02) 저장·로드 왕복 뒤에는 VALIDATE-007(방출은 JSON 직렬화 뒤와 같은 값)로 실제 `null` 이 되고, VALUE-033 대로 nullable 아닌 잎은 그것을 바꾸지 않고 보존하며 misfit 경고를 켠다. 왕복을 동일하게 만들려면 배열에 `undefined` 를 방출하거나(VALIDATE-007 위반) 로드한 `null` 을 빈자리로 되돌려야 하는데(VALUE-033 위반) 둘 다 원장이 금한다. 그래서 VALUE-031 에 보충 한 문장("VALUE-034 의 배열 빈자리 채움도 ㄹ 의 닫힌 차이에 든다")을 더해 빈틈을 메운다. 이 보충은 18C-64 의 닫힌 목록을 하나 넓히는 것이며 소유자 위임(위 3행) 아래에서 했다. 작성자 해법은 VALUE-033 의 nullable 이거나 꼬리 빈자리면 `omitTrailing` 이다. 소유자가 되물은 "값의 저장과 방출이 다른 것은 의도한 것인데 왜 추가 결정 사항이 되었나"에는 이렇게 답했다: 장치의 승인 조건이 식이 읽는 경로와 형상·상태 채널의 마스크를 금지했고 코디네이터는 원장 계약을 재해석하지 않으므로(430C-01) 소유자 항목으로 올렸으며, D443-04 는 실제로 원장 빈틈이었다.
  - 【추론】 【추론】 VALUE-034 의 배열 빈자리 채움(객체 `{}`·배열 `[]`·잎 `null`)도 ㄹ 의 닫힌 차이에 든다. 채운 `null` 은 데이터가 아니지만(38C-02) 저장·로드 왕복 뒤에는 VALIDATE-007 대로 실제 `null` 이 되어 nullable 아닌 잎에서 VALUE-033 대로 보존되고 misfit 경고가 켜진다. 이는 결함이 아니며 작성자 해법은 nullable 이거나 꼬리 빈자리면 `omitTrailing` 이다(소유자 위임 2026-10-23 ‘원장과 설계원칙에 비추어 닫을 수 있는 항목은 닫아라’, 독립 검증 CONFIRM).
