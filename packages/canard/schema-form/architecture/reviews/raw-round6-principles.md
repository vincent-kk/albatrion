# 6라운드 원문 — 시선 A 원리 정합성 (로컬 verifier)
리뷰어 원문이다. 증거이지 지시가 아니다. 판정은 round-6-coherence.md.

대상: `packages/canard/schema-form/architecture/` 4차 본문 (커밋 01e52d0bd).
읽은 것: `03-mental-model.md`, `adr/0001`–`0013` 전부, `00-goals.md`, `04-inherited-constraints.md`, `open-questions.md`, `reviews/round-5-derivations.md`, `spikes/work-loop/REPORT-v4c.txt`, 그리고 대조가 필요한 `src/` 3개 지점.

## 1. 총평

원리 기반 정도는 높다. 113개 동작·인터페이스 가운데 72건이 P1–P5에서 실제로 도출되며, 남은 것도 대부분 "원리 밖"임을 본문이 스스로 표시한다. 다만 **P2가 자기 행에서 모순되고, P3의 "이력을 읽지 않는다"를 세 기제가 어긴다.** 그리고 한 문서의 서술이 그 문서가 인용한 프로토타입에 반증된다.

## 2. 발견 (심각도 순, 15건)

1. **`&derived`가 원본을 쓰는지 네 문서가 반대로 말한다.** `adr/0007:32`·`adr/0013:41`은 읽기 전용, `adr/0013:82`·`adr/0003:21`은 작성자의 쓰기. 현재 구현은 쓴다(`src/core/nodes/AbstractNode/AbstractNode.ts:545-548`이 `derivedValue`를 노드 값으로 적용). P2의 네 주체 목록(`03-mental-model.md:10`)에도 없다. C-10의 처방 "파생 값은 `derived`/`injectTo`/스토어 리스너로 쓴다"(`adr/0008:113`, `03-mental-model.md:91`)가 이 답에 걸린다 — 읽기 전용이면 그 처방은 성립하지 않는다. 판정: 어긋남(확정). 제안: P2 목록에 다섯째 주체로 넣거나, 파생 단계의 `&derived`가 쓰기가 아님을 한 줄로 확정하고 C-10 처방을 고친다.

2. **`adr/0008:74`(F18)가 인용한 프로토타입에 반증된다.** 본문은 "리스너 안의 `batch`는 바깥 배치가 이미 끝난 뒤이므로 자기 배치다(진입 깊이는 통지 중 0이다)"라 한다. 그러나 `spikes/work-loop/REPORT-v4c.txt` §1은 "A listener write during a wave runs at depth >= 2 (setValue inside dispatch inside the outer write): it settles and commits immediately but fires NO onChange"라 적는다. 깊이 0인 것은 `root.onChange` 안의 쓰기뿐이다("A write made INSIDE root.onChange finds depth 0 -> NEW ENTRY"). 같은 문서의 `:62`(리스너 쓰기는 즉시 정착, 통지는 다음 파동)와 `:101`(리스너 되먹임 → onChange 1)과도 어긋난다. 판정: 어긋남(실행으로 확정). 제안: 리스너(`subscribe`)와 `onChange` 콜백을 분리해 다시 쓴다 — 전자는 깊이 2 이상, 후자만 깊이 0.

3. **P2 행이 자기모순이다.** `03-mental-model.md:10`은 "core가 스스로 원본을 '고치는' 일은 없다", 같은 문서 `:45`의 쓰기 표는 `default` 주입의 '누가' 칸이 `core (P2의 유일한 자동 쓰기)`. 판정: 어긋남(확정). 제안: "core의 자동 쓰기는 로드 계약 하나뿐이다"로 문구를 통일한다.

4. **null 계약(D-1)에 주입 트리거가 없다.** `adr/0013:42`와 `adr/0006:58`은 "다시 객체가 될 때 로드 계약의 `default`가 빈 상태를 만든다"고 한다. 그러나 주입 시점은 (i) 전체 교체 직후, (ii) 조각이 꺼짐→켜짐 둘뿐이다(`adr/0007:66`, `adr/0013:38`). `setValue(null)` 시점에는 F10(`adr/0007:78`, T-12)이 비객체 호스트로의 자동 쓰기를 막고, 사용자의 부분 쓰기로 호스트가 다시 객체가 되는 경로(F1, `adr/0007:78`)에는 주입 트리거가 없다. 결과: `setValue(null)` 뒤 사용자가 한 필드를 채우면 형제의 `default`는 영영 들어가지 않는 반면, `setValue({})`로 같은 상태에 도달하면 들어간다. #338이 겨냥한 바로 그 경로다. 판정: 공백(문서 추적으로 확정, 실행 미확인 — 구현이 없다). 제안: 쓰기 표에 셋째 시점("호스트가 비객체에서 객체가 될 때")을 넣거나, D-1의 그 문장을 삭제하고 빈 상태의 출처를 다시 정한다.

5. **P1′ 위반: 폼이 `required`를 읽어 형상을 정한다.** `adr/0002:127`(E17) 규칙 3은 "호스트의 `required`/`dependentRequired`가 비활성 조각의 키를 가리키면 그 키를 선언한 조각에 가중한다"고 한다. P1′(`adr/0002:26`, `03-mental-model.md:15`)는 `required`를 명시적으로 "검증기의 것"으로 분류한다. 초기 분기 선택은 형상이다. 판정: 어긋남(확정). 제안: 규칙 3을 철회하거나, P1′의 예외로 `const`/`enum`과 같은 자리에 명시한다(`adr/0005:90`이 `const`/`enum`에 대해 한 방식).

6. **`injectTo`의 발화 조건이 이력이다.** `adr/0007:79`(F11)는 "원천의 emit이 직전 커밋과 다를 때만" 발화한다. 그래서 같은 (raw, selection, extras)가 도달 경로에 따라 다른 정착 결과를 낸다 — 원천이 방금 바뀌어 도달한 상태에서는 대상이 덮이고, 사용자가 대상을 직접 고쳐 도달한 상태에서는 덮이지 않는다. `adr/0007:40`의 "커밋된 트리는 (스키마, 트리 전체의 `raw`·`selection`·`extras`)의 순수 함수다(F9)"와 충돌한다. 같은 이유("이력 의존")로 기각된 항목이 바로 옆에 있다(`adr/0013:71`의 "손대지 않은 값에는 `omitEmpty`를 건너뛴다"). 어느 원리에서도 도출되지 않는다. 판정: 편의(확정). 제안: F11을 P6(아래 §5)의 사례로 승격하고 F9의 문장을 "형상과 emit은 순수 함수, 전이와 파생의 방아쇠는 직전 커밋을 읽는다"로 좁힌다.

7. **`select`가 두 뜻이다.** `adr/0008:91`의 공개 쓰기 API 목록은 `setValue`·`write`·`select`·`removeKey`·`push`·`remove`·`batch`이고, 여기서 `select`는 union 분기 선택이다(`spikes/work-loop/REPORT-v4c.txt` §1의 목록과 동일). `adr/0008:121`의 `FormHandle.select`는 입력 텍스트 선택 명령이며 오늘 실제로 존재한다(`src/components/Form/type.ts:114`, `select: Fn<[path: SchemaNode['path']]>`). 같은 핸들 표면에서 한 이름이 쓰기와 명령을 동시에 가리킨다. 판정: 어긋남(실측 확정). 제안: 분기 선택을 `selectBranch` 또는 `setSelection`으로 바꾼다.

8. **`settle.status`의 값 집합이 문서마다 다르다.** `adr/0006:34`는 `{status: 'stable' | 'budget-exceeded', sweeps}`, `adr/0008:93`은 `onchange-cap-exceeded`를 쓴다, `03-mental-model.md:28`은 "정상 / budget-exceeded". 파동 상한 초과(`adr/0008:62`, "프로덕션은 무시 + `settle` 기록")는 이름이 없고, 전이 라운드 초과(`adr/0007:33`)는 처리 자체가 미정의다. 예산 다섯 중 이름 있는 것이 둘이다. 판정: 어긋남(확정). 제안: `settle.status`의 전체 값 집합을 ADR 0006에 한 번 적고 나머지 문서가 그것을 가리킨다.

9. **`adr/0001:32`이 구식이다.** "판정은 값의 revision에 묶인다 … `isValid`는 판정의 revision이 현재와 같을 때만 참"이라 하나, F28이 검증 스탬프를 별도의 단조 **커밋 번호**로 대체했다(`adr/0007:34`, `adr/0008:84`). 같은 revision으로 찍힌 서로 다른 커밋을 식별하지 못하던 반례(V13)가 그 이유였다. ADR 0001은 개정되지 않아 원래 문장을 그대로 들고 있고, 이것이 재설계 전체의 전제 문서다. 판정: 어긋남(확정). 제안: `adr/0001:32`을 커밋 번호로 고치고 변경 이력에 적는다.

10. **G4 목표와 ADR 0011이 충돌한다.** `00-goals.md:59`는 G4의 항목으로 "트리의 형태가 렌더링 선택에 좌우되지 않는다(현재는 좌우된다 — `01-current-structure.md` §6)"를 든다. `adr/0011:49-53`은 그 성질을 **유지**한다("암묵 규칙 유지", 인라인 `FormTypeInput`이 자식 노드를 없앤다). 사라지는 것은 React 감지뿐이며 의존 자체는 남는다. 그 귀결이 미결 S11이다(`adr/0011:88` — `React.lazy` 결과나 설정 객체도 서브트리를 접는다). 판정: 어긋남(확정, 다만 소유자가 "의도된 기능"으로 명시한 곳이다 — `00-goals.md:114`). 제안: G4의 그 항목을 "트리의 형태는 렌더링 **런타임**에 좌우되지 않는다"로 좁히거나, 터미널 판정을 `terminal` 키 하나로 옮긴다.

11. **`selection`과 `extras`에 쓰기 규칙이 없다.** 상태는 셋인데(`03-mental-model.md:34`, `adr/0006:38`) 쓰기 표(`03-mental-model.md:38-45`, `adr/0013:33-38`, `adr/0007:61-66`)는 `raw`만 규율한다. `selection`의 규칙은 흩어져 있다: `Overwrite`가 다시 정하고 `reset()`이 초기 선택으로 되돌린다(`adr/0002:128`), 사용자가 선택기로 고른다(`adr/0002:152`), `select`가 공개 쓰기 API다(`adr/0008:91`). `extras`는 누가 언제 쓰는지 어디에도 없다. 판정: 공백(확정). 제안: 쓰기 표에 `selection`·`extras` 열 또는 행을 더한다.

12. **`disableDefaultInjection`이 이름보다 좁게 작동한다.** 억제는 "호출자의 전체 교체가 일으킨 정착 — 그 안의 전이 주입을 포함 — 에서만 듣는다"(`adr/0013:54`, F25). 사용자 입력이 조각을 켜서 일어나는 전이 주입은 끄지 못한다. 이름은 "default 주입을 끈다"로 읽힌다. D-5의 뜻은 "로드 계약을 끈다"이다. 판정: 편의/이름 불일치(확정). 제안: 이름에 "로드"를 넣는다(예: `disableLoadDefaults`). 소유자가 확정한 것은 뜻("초기값 조작 비활성화")과 `disable…` 형태뿐이므로(`adr/0007:68`) 이름은 아직 열려 있다.

13. **`node.value`의 정의가 충돌한다.** `adr/0006:48`은 "`node.value`는 `local`, `getValue()`는 `emit`"이라 한다. `open-questions.md:25`는 "현재는 `value`(원본)와 `normalizedValue`(방출)로 나뉘어 있고 그 구분을 유지하는 것이 자연스럽다"고 한다. 호스트에서 `local`(활성 자식 emit의 합성)과 `raw`(비객체 값이 왔을 때만 존재)는 다른 것이므로 둘은 양립하지 않는다. `normalizedValue`는 4차 본문 어디에도 새 정의가 없고, `enhancedValue`는 **한 번도 등장하지 않는다**(`01-current-structure.md`의 현상 관찰이 유일). D-6로 참조 그룹이 emit을 갖지 않게 되면 `enhancedValue`(가상 필드 포함 읽기, 패키지 `CLAUDE.md` Key APIs)의 정의가 사라진다. 판정: 어긋남 + 공백(확정). 제안: 상태 칸 셋과 공개 읽기 이름의 사상표를 ADR 0006에 한 장으로 넣고 `enhancedValue`의 거취를 적는다.

14. **에러 라우팅 규칙이 셋이고 지정된 자리가 비어 있다.** `adr/0001:41`은 "`schemaPath`가 활성 조각 아래인 에러만 그 노드에", `adr/0005:92`는 "`instancePath`가 union 호스트이고 `schemaPath`가 union 키워드를 지나는 에러를 판별 노드에", `adr/0002:90`은 "`rejectedKey`가 있는 호스트 에러만 모은다". 셋은 서로 다른 축이다. Q12(`open-questions.md:80`)와 `adr/0005:92`·`:114`는 "규칙은 ADR 0004에 적는다"고 하나 ADR 0004에 그 절이 없다. 더해 `adr/0001:42`의 "주인 없는 에러를 모으는 폼 수준 sink"는 이후 어느 문서도 모양·이름·소유자를 정하지 않는다. 판정: 공백(확정). 제안: 라우팅 규칙 한 곳을 정하고 나머지 둘이 가리키게 한다.

15. **설계와 프로토타입이 반대다.** `adr/0002:125` 규칙 1은 여분 키만 있는 값(`{zzz:1}`)을 "분기 키 없음"으로 본다. `loop-v4b`는 첫 분기를 고른다(`spikes/work-loop/REPORT-v4b.txt` §5 U-1, `initialSelection`의 `bestCount = -1`). 본문이 이 불일치를 명시하고 소유자 확정 대기로 표시하므로 위험은 낮다. 판정: 교차(명시됨). 제안: 소유자 확정 뒤 프로토타입을 맞춘다는 현 계획대로.

### 심각도 밖의 소소한 교차 (수정 비용이 낮은 것)

- `03-mental-model.md:56`의 출발점은 "무조건 조각만"이나 `adr/0002:68`·`adr/0007:47`은 세 항(무조건 조각 ∪ 판별 프로퍼티 ∪ 상속 overlay)이다.
- `03-mental-model.md:57`의 상한은 "조각 수 + 1", `adr/0002:70`·`adr/0007:51`은 "**조건부** 조각 수 + 1".
- 배열 API 어휘가 셋이다: `push`/`remove`/`update`(`adr/0013:37`, `adr/0007:65`), `push`/`remove`/`pop`/`clear`(`04-inherited-constraints.md:15`, T-7), `push`/`remove`(`adr/0008:91`).
- `write`·`removeKey`는 `adr/0008:91`의 진입 정의 한 곳에만 등장하고 다른 어느 문서에도 없다.
- 파생 라운드 상한 초과(`adr/0007:41`)에 개발 모드 throw 언급이 없다. T-4(`04-inherited-constraints.md:12`)는 세 예산을 한 throw로 묶어 읽는다.
- `adr/0008:60`의 배달 집합 2항 "활성 여부가 바뀐 노드"에서 "노드의 활성"은 조각 집합에서 유도되는데 그 사상이 어디에도 없다.
- `adr/0002:61`·`adr/0007:50`의 "호스트 raw가 비객체이면 `G = {}`"는 "가드는 검증기가 볼 값을 본다"의 예외다. 검증기는 `null`을 그대로 본다. S8 대응의 편의이며 원리에서 도출되지 않는다.
- `adr/0002:114`는 판별식 가드에 `required`를 더하고 `adr/0002:119`는 `if` 가드에 더하지 않는다. 같은 문제(공허한 참)에 반대 처방이며 근거는 "`if`는 서버와 똑같이 평가한다"이다. 일관되나 한 문서 안에서 이유를 한 번 더 적어 둘 만하다.

| 주석성 키워드 병합 | `default`·`title`은 먼저 정의된 쪽이 이긴다 | 명시, 근거 없음 (`adr/0005:109`) |
| 초기 선택 규칙 2 | "통과 분기" 판정이 검증기 설정에 의존 | 미명시 |
| 유효 스키마 변경 | `node.jsonSchema`가 통지 없이 바뀐다 | 명시, 이벤트 없음 (`adr/0007:138`) |

## 4. 인터페이스 비대칭

| 항목 | 비대칭 |
|---|---|
| 옵션 객체 | `reset(options)`에서 `mode`가 no-op(reset은 항상 전체 교체), `Merge` + 억제도 no-op. 두 필드짜리 객체에 무효 조합이 둘 |
| 마운트 스위치 | Form 속성의 이름이 없다 (`adr/0013:51`, "Form 속성이 그 자리다"까지만) |
| 명령 어휘 | `focus`/`select`는 오늘 존재(`Form/type.ts:113-114`, `Fn<[path]>`), `refresh`/`remount`는 신설. `select` 이름 충돌 |
| 명령의 정의 | 무엇을 버리는지가 React 기제로 서술된다 — "입력의 `key`를 바꿔", "래퍼의 `key=version`" (`adr/0008:125-126`). 렌더러 중립 어휘가 아니다 |
| 공개 쓰기 목록 | `write`·`removeKey`가 한 곳에만 존재 |
| 배열 API | 세 문서가 세 목록 |
| 상태 칸 대 공개 읽기 | `raw`/`local`/`emit` 대 `value`/`getValue()`/`normalizedValue`/`enhancedValue`. 사상이 `adr/0006:48` 한 줄뿐이고 그 한 줄이 `open-questions.md:25`와 충돌. `enhancedValue`는 사상 자체가 없다 |
| FE 전용 키 문법 | `&`(0003이 선언한 규칙)와 `options.*`와 `computed.*`와 비접두 `injectTo`·`terminal`이 4차 본문에서 공존. `adr/0003:30`이 미결로 남긴 자리 |
| `settle` | 공개 읽기 API 없이 이벤트(`UpdateSettle`, 가칭)로만 관측 |
| 가칭 이름 | `latent(path)`, `onListenerError`, `UpdateSettle`, `&virtual`, `terminal` — 다섯이 미정 |

## 5. 제안하는 추가 원리

- **P6. 이력은 전이의 방아쇠로만 읽고, 형상에는 쓰지 않는다.** 전이(직전 `active`), `injectTo`(F11, 직전 원천 emit), `Refresh`(쓰기의 출처), `payload.previous`(마지막 통지값), extras의 삽입 순서가 이미 이 규칙 위에서 돈다. 이름이 없어 매번 P3의 예외로 변명되고, 그 결과 같은 종류의 이력 의존이 어떤 곳에서는 채택되고(F11) 어떤 곳에서는 기각된다(`adr/0013:71`). 원리로 세우면 어느 이력이 허용되는지 판단 기준이 생긴다: **방아쇠에는 허용, 결과 상태의 정의에는 금지.**

- **P7. 예산은 하나의 칸에 같은 모양으로 관측된다.** 상한이 다섯인데(호스트 바퀴, 파생 라운드, 전이 라운드, 틱당 파동, `onChange` 중첩) 관측 방식은 이름 둘, 무명 하나, 미정의 둘이다. "예산 초과는 언제나 `settle.status`에 이름 있는 값으로 남고 조상으로 전파된다"를 원리로 두면 `adr/0006:34`의 타입이 그 목록을 소유하게 되고, 새 예산이 생길 때 관측을 빠뜨릴 수 없다.

- **P8. core의 공개 어휘는 렌더러 중립 의미로 정의된다.** P5("core는 렌더러를 모른다")의 능동형이다. 지금 P5는 "core가 React를 import하지 않는다"로만 작동하고, 공개 명령의 **의미**는 React 재조정으로 서술된다(`adr/0008:125-126`). 통지 시점이 React의 `restoreStateOfTarget`에서 도출된 것(`adr/0008:47`)도 같은 자리다. 중립 의미로 다시 쓰면 "`refresh`는 그 노드의 입력이 들고 있던 표현 상태를 버리고 커밋된 값을 다시 읽게 한다", "`remount`는 서브트리의 표현 상태 전부를 버린다"가 되고, React `key`는 바인딩 계층의 구현으로 내려간다.

- **P9. 상태 칸 하나에 공개 이름 하나.** `raw`/`local`/`emit` 셋에 공개 이름이 넷 붙어 있고 그중 하나(`enhancedValue`)는 새 모델에 자리가 없다. 칸과 이름을 1:1로 묶으면 §4의 마지막 세 행이 한 번에 닫힌다.
