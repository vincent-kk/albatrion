## 217C-01 운영 규칙 (원장 관리자의 반영)

- **개발(소스·시험 변경)은 codex가 한다.** 각 Claude 세션은 seiri 계획을 쓰고(설계·판단은 Claude 세션 몫), 승인된 계획과 브리프(워크트리 경로, 바꿀 파일, 고치기 전 실패 시험, 검증 명령, 금지 사항)를 `/cennad:codex`로 보내 codex가 그 세션의 워크트리에서 구현한다. 커밋은 Claude 세션이 검증 뒤에 한다(커밋 규칙 — 세션 ID·co-author 금지, 근거·이유 — 를 지키기 위해).
- **검증은 Claude 세션이 주로 한다.** codex 결과를 받은 세션은 직접 읽기·시험 실행·typecheck·lint로 확인하고, 문서·원장 대조와 큰 문맥 리뷰는 agy(`/cennad:antigravity`)로, 코드 수준 독립 검증이 더 필요하면 Claude verifier로 한다(10월 1일 지시: agy로 될 것 같으면 agy, Claude 검증기는 꼭 필요할 때).
- **품질 게이트는 그대로다.** 문서 선행(DETAIL 먼저), 고치기 전 실패하는 회귀 시험, 전체 시험·typecheck·lint, verifier 통과, 측정이 걸린 변경은 측정. codex 결과가 게이트를 못 넘으면 같은 codex 세션(--continue)에 되돌려 고치게 하고, 두 번 뒤에도 못 넘으면 Claude 세션이 직접 고치고 원장 관리자에게 알린다.
- **codex의 범위.** 계획이 정한 파일과 워크트리 밖은 손대지 않게 브리프에 적고, 끝나면 바뀐 파일 목록·실행한 명령·결과를 보고받는다. `.claude/`, 설정, 원장(architecture/ledger)은 codex가 건드리지 않는다.
- **적용 시점.** 지금부터의 새 작업: fixy07의 ④ 검증 파동 고침과 ⑤ browser-mode guard, reviewer의 ajv 플러그인 createValidator 구현, fairy07의 내장 입력 일곱 이주. 이미 구현 중인 ③-②는 그 세션이 마무리한다.
