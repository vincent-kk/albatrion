  - 【추론】 가설 0의 첫 구현은 같은 정착 안에서 호스트가 다시 조립될 때마다 직전 커밋과 전체 폭을 깊게 견주어 정착당 폭 순회가 두 번에서 네 번으로 늘었다(TEST-071 전체 객체 큰 행 Node 22386→33352 µs, P-09 8천 39.4→45.6 ms). 편집자 힌트였던 "정착 끝에서 한 번 비교"는 형제가 실제로 바뀐 경우 부모의 local은 새 객체이고 자식의 emit은 되살린 옛 객체가 되는 조상 불일치를 만들어 채택하지 않는다(스크래치 테스트로 확인). 채택한 수정은 SETTLE-043 (나)의 정의 — 같은 키 목록과 키마다 같은 자식 emit 참조 — 를 얕은 필요조건으로 깊은 비교 앞에 두는 것이며, 단계 순서(SETTLE-001)·배달·저장 필드는 바꾸지 않는다. 알려진 차이 하나: 같은 정착에서 자식 노드 인스턴스 자체가 바뀌면 부모 되살림을 하지 않아 배달이 한 번 더 가되 값은 같다(가설 0 이전 동작). 수정 뒤 TEST-071·P-09는 가설 0 이전 수준으로 돌아왔다(교차 A/B, 같은 구간 3회 중앙값, 번들 no-H0 9ca9ea95 / H0 09d17765 / 수정 36ac0af9: Node 전체 객체 큰 행 22568 / 33776 / 22413 µs, 전체 배열 큰 행 16393 / 24714 / 16405 µs, 원소 객체 작은 행 5988 / 8824 / 6041 µs; Bun 전체 객체 큰 행 11414 / 17377 / 11264 µs, 전체 배열 큰 행 7879 / 11839 / 7805 µs; 16행 전부 수정/no-H0 비 0.929~1.013.
