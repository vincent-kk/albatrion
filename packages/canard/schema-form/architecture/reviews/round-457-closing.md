## 편집자 결정

- **457C-01 (판정의 간소화 — 2부 검토 생략, 결과 문서는 표와 판정 한 줄, B2의 남은 항목은 묶음 둘)**
  - 【추론】 소유자가 결과는 짧게 추세만 보고 시간을 많이 쓰지 말고 판정만 하라고 했다(위 1행). 이에 따라 B2의 남은 가설은 독립 코드 검토 한 번과 측정 판정으로 처리하고 측정 보고에 대한 2부 검토는 생략하며, 결과 문서는 표(단계 A/B, 행 A/B/A′·폭·품질, TEST-073, 힙)와 판정 한 줄로 줄인다. 남은 B2 항목은 설계의 묶음 둘로 합쳐 각각 PR 하나·창 하나로 잰다: B2-P2 호스트 수명 준비물(바퀴 계획·나감 정책과 제어 계층·정적 자식 준비물·잠복 순서의 청사진 색인), B2-P3 변화량 적용(노드가 드는 잠복 키·활성 자식만 걷는 조립·Δ 집합을 쓰는 등록·배달 표식). "가설 하나에 PR 하나"는 묶음 단위로 완화한 편집자 결정이며 소유자가 반대하면 되돌린다. 소유자가 요청한 1차 확인 요약(위 2행)은 B2-P2 창 뒤에 올렸다.
- **457C-02 (B2-P1b 지연 materialization의 미채택 — 비활성 값 메모는 이 구조에서 손대지 않고 설계 Ⅱ의 몫)**
  - 【추론】 B2-P1b(1ff87c4b3, 창 14:15 UTC, 0.16.1 레인 품질 1.0007 유효)는 증분 경로가 실행됐는데도 메모 단계가 oneOf-80에서 22.83→26.14 µs(압축 6/300), payload-12에서 44.16→64.48 µs(27/300)로 늘었고 총합 두 행 모두 폭 밖 개선이 없었다(oneOf A 0.503/B 0.467/A′ 0.423 ms·폭 0.190, payload A 0.811/B 0.884/A′ 0.878·폭 0.331). TEST-073 주판정 회귀 0, Node 힙 통과(B 중앙 1443.22 ≤ A 최대 1890.78), Bun 2234.26→2232.35. 즉시 유지(B2-P1)도 지연(B2-P1b)도 전체 재구성(약 19~23 µs)보다 비쌌으므로, 비활성 값 메모는 "나간 노드의 상태를 노드 밖으로 옮긴다"는 지금 구조에서는 더 손대지 않고 설계 Ⅱ(슬롯에서 읽음)의 몫으로 넘긴다. 제품 코드와 DETAIL은 되돌리고 공개 계약 시험 둘(읽기·수명)과 결과 문서, 교대 장치의 `--only` payload-12 확장만 #477로 남겨 짧은 검토 PASS 뒤 병합했다(8d9d885bf).
- **457C-03 (B2 묶음의 채택 기준 — 같은 창 단계 장부의 감소 + 주판정 TEST-073 회귀 0 + Node 힙, 총합 행은 B3 누적 판정; B2-P2 채택, 정적 준비물의 동명 후보 공백은 형제 선형항의 단서)**
  - 【추론】 B2-P2(e8c122986, 창 15:07~15:16 UTC, 품질 0.996 유효)에서 겨냥한 단계는 같은 창의 A/B 단계 장부로 크게 줄었다: 바퀴 준비 self 8.938→2.834 µs(목표 ≤1 미달), getControlLayers 합 15.770→1.790 µs(목표 ≤2 통과), `getLatentOrder`의 엔트리 선형 탐색 제거. 그러나 총합 행 switch-oneOf-80은 왕복 A 507.3/B 441.1/A′ 373.6 µs로 창 안의 흐름(A 대 A′ 26 %)이 개선 폭(약 20 µs/쓰기, 8 %)보다 커서 "폭 밖 개선"은 증명할 수 없는 구조였다(TEST-073 주판정 회귀 0, 뒷반 single-nested −18.45 % 1건, Node 힙 통과, Bun +4.374 B/노드 보고). B2의 묶음은 개선 폭이 5~15 µs라 총합 행으로는 어느 것도 증명되지 않으므로, 채택 기준을 "겨냥한 단계가 같은 창의 A/B 장부에서 상한 아래 또는 절반 이하로 줄고 어느 단계도 나빠지지 않으며 주판정 TEST-073 회귀 0, Node 힙 B 중앙 ≤ A 최대"로 두고 총합 행은 B3에서 단계 시작 판·0.16.1 대비로 누적 판정한다. 측정 뒤의 기준 변경이므로 재검증 목록에 올린다(TEST-081과의 경계). 이 기준으로 B2-P2를 채택한다(#478, 독립 코드 검토 PASS). 정적 자식 준비물은 동명 후보(x/y)가 있는 호스트(형제 픽스처)에서는 `HostStaticPartition`이 정적 목록을 비워 적용되지 않았고 고유 이름 호스트(oneOf-80)에서는 적용됐으므로, 측정된 묶음 전체를 그대로 채택하되(측정되지 않은 변형을 만들지 않음) 형제 1,000개당 약 2.0 ms의 선형항이 정적 선택이 아니라 다른 곳(조립·등록으로 추정, B2-P3 범위)에 있음을 단서로 기록한다.
- **457C-04 (설계 Ⅱ 착수 — 소유자 선택지 A, 떼어진 인스턴스의 보유와 복제 재진입, B4-1 롱턴 위임, 관문 1.5배 유지)**
  - 【추론】 1차 확인에서 oneOf-80 쓰기당이 261→252→약 220 µs로 관문 66 µs에 멀고, 남는 비용이 선택·계산 self 약 70 µs와 나감·들어옴 노드당 약 12 µs(설계 Ⅰ~Ⅲ로 건드릴 수 없는 항)임을 보고했으며, 소유자가 A(설계 Ⅱ 지금 착수, 설계를 먼저 고정하고 롱턴 위임)를 택했다(위 3행). 설계는 `plan/branch-switch/design-ii.md`에 고정했다: 나간 노드의 공개 인스턴스는 지금처럼 떼어진 채로 남고(NODE-044 그대로 — 읽기 고정·재진입은 새 인스턴스·옛 구독 비발화), 호스트가 그 인스턴스를 청사진 엔트리별 비활성 슬롯으로 보유하며, 재진입은 청사진과 잠복 저장소가 아니라 슬롯 인스턴스에서 복제해 새 인스턴스를 만든다(raw·extras·선언 외 값·자식 슬롯 복제, 부모·경로·레지스트리·색인은 새로, 상호작용 상태·오류는 복제하지 않고 itemKey는 새로). 비활성 동안의 쓰기는 떼어진 인스턴스를 고치지 않고 호스트의 슬롯별 overlay에 두며, `inactiveValues`는 슬롯에서 읽어 공개 결과를 그대로 내고 떼어진 호스트는 자기 슬롯에서 계산하므로 캡처가 없다. 비용 모델은 나감 O(1)·들어옴 O(복제 서브트리)·커밋의 메모 재구성 0·호스트당 슬롯 ≤ M이고, 예상 효과는 oneOf-80 쓰기당 약 50~55 µs다. B4-1은 기능 플래그 `engineModes.slots`(기본 on, off는 기준 경로이자 그림자 오라클) 아래 슬롯 경로와 잠복 경로를 공존시키고 여섯 의미 시험을 두며, B4-2가 잠복 경로를 지운다. 채택 규칙은 단계 장부(잠복 저장 0·메모 0·들어옴 생성 절반 이하)와 주판정 TEST-073·Node 힙·슬롯 보유량 기록이고 총합은 B3 누적이다. 소유자가 관문 수치를 따로 바꾸지 않았으므로 446C-06(1.5배·1 ms)은 그대로이며, 설계 Ⅱ 뒤에도 약 100~120 µs가 예상되어 선택·계산 self의 세부 장부가 B3 전에 필요하다는 전망을 보고했다. 워커는 codex(Orca, 가지 `perf/schema-form-b4-1-slots`, 기준 64185f8fd)다.
- **457C-05 (PR 본문·결과 문서·커밋 메시지에 기계 로컬 경로 금지 — 측정 요약과 검토 판정은 저장소에)**
  - 【추론】 소유자가 PR 본문의 `/private/tmp/...` 경로를 지적했다(위 4행): GitHub의 독자가 열 수 없으므로 PR의 의미가 없다. 규칙: PR 본문·결과 문서·커밋 메시지는 그 자체로 읽혀야 하며 기계 로컬 경로를 인용하지 않는다. 판정이 기대는 측정 요약(장치의 `judgement.json`, 행별 요약, 품질·창 CPU 기록, 단계 장부 요약 — 표본 전체 덤프는 제외)은 `verification/branch-switch/raw/<가설>/`에 커밋하고, 독립 검토의 판정 파일은 `verification/branch-switch/reviews/pr-NNN-<가설>-antigravity.md`에 커밋해 저장소 경로로 인용한다. 전체 표본 원자료는 측정 기계에 남고 존재만 한 줄로 적는다. #478의 본문과 결과 문서를 이 규칙으로 고쳤고(원자료 요약 `raw/b2-p2/`), #474~#478의 검토 판정 파일을 저장소에 넣었다. 이미 병합된 #474~#477의 스쿼시 커밋 메시지와 결과 문서에 남은 기계 로컬 경로는 바꾸지 않고(이력 불변) 이 결정으로 대체 경로를 밝힌다. 이 규칙은 `AGENT-POLICY.md`와 모든 워커 브리프에 넣는다.
- **457C-06 (B2-P3의 경계 — 존재 차분 재사용은 보류, JSON 키 관문은 잠복 저장 경로로 한정)**
  - 【추론】 B2-P3(가지 `perf/schema-form-b2-p3-delta-application`)의 두 항목이 B2-P2 소유 파일에 닿았다. `registerPresenceChanges`의 두 번째 차분 제거는 computeNode·childSelection이 라운드별 변경 이름을 넘겨야 가능하므로 이번 묶음에서 빼고 "B2-P2 병합 뒤 SettlementContext로 받으면 가능"으로 보류한다. "잠복 키 JSON 왕복 0회" 관문은 잠복 저장·메타데이터·색인 경로로 한정하고, 선택부(selectChildren·selectEntryStep·primeHost)의 pendingExits 키 생성은 두 묶음 병합 뒤 공통 helper로 바꾸는 정리로 따로 둔다(선택부 키 JSON 횟수는 결과에 계수로 적음). B2-P3의 채택 기준은 457C-03과 같다(겨냥한 단계 넷 중 셋 이상 상한 아래 또는 절반 이하, 어느 것도 나빠지지 않음, 주판정 TEST-073 0, Node 힙).
