## 편집자 결정

- **371C-01 (배열 동사의 계약 해석과 계약 레인의 합격 기준).**
  - 【추론】 GOAL-011 아래에서 push·pop은 꼬리 연산이라 자리 하나의 비용이 목표이고, remove·insert는 항목 정체성이 위치(NODE-051)이므로 지운·끼운 자리 뒤 꼬리 T개의 이름·경로 재매김이 필수이며 T에 비례하는 것은 준수다(355C-01을 옮긴 추론, 365라운드 소유자 결정). 항목 정체성을 안정 키로 바꾸는 일은 공개 경로가 JSON Pointer라 원칙 변경이므로 하지 않는다. 지름길의 틀은 동사마다 같다: 상수 시간 자격(청사진 전체에 게이트·식·derive·watch·상태·가상·터미널·비리터럴 기본값·injectTo 없음, batch·visit 아님, 템플릿 있음, 튜플 자리 밖), 호출 단위 증명 기록, 증명이 깨지면 같은 정착 문맥에서 일반 경로로 이어 감(재실행·이중 노드 없음), 정착 단계 순서·배달·revision·공개 API 불변. 계약 레인은 "마운트 배달을 비운 뒤 시간 밖에서 1개짜리 다른 트리에 push 한 번으로 엔진 작업 집합을 데운 정상 상태"이고, 합격은 엔진이 하는 일의 양으로 판정한다: 영구 게이트는 비용 계수 시험(접두 작업 호출 수가 N과 무관), 측정 기록은 JIT를 끈 단계 계측의 복사 제외 배율이 N 8배에서 1.25배 이하(push 1.13배), 시간 배율은 참고 열이다. 시간 배율이 1.0배에 닿지 않는 것은 직전 마운트가 CPU 캐시를 밀어내는 효과(64 MB 훑기로 재현, 2 MB 미재현, GC 겹침 0/160)이지 엔진의 일이 아니다. 전후 표의 형식은 옛 판 0.16.1(npm 공개 tarball)·수정 전·수정 후의 절대값 ms와 ±%(느려짐 +, 빨라짐 −)이고, 옛 판은 비동기라 루트 onChange가 기대 값으로 불리고 루트·바뀐 자식의 값·경로가 맞은 시점까지 잰다(369라운드). M0의 옛 판 열 0.16.0은 M3 종합 재측정에서 0.16.1로 다시 잰다(0.16.0→0.16.1 차이는 nullable null 계약 하나, 측정 장면에 닿지 않음).
- **371C-02 (SURFACE-005 보강: 배열 동사 여섯 — insert 추가와 그 규칙; insert 구현의 발견 넷).**
  - 【추론】 공개 배열 동사는 push·pop·update·remove·clear에 insert(index, value?)를 더해 여섯이며 새 길이를 돌려준다(365라운드 소유자 결정, 겉면 이름 수 94 그대로, 멤버 55). WRITE-099 결정은 이미 삽입을 push와 같은 구조 연산으로 적어 두었다. 규칙은 기존 동사의 규칙을 옮긴다: 유효 범위는 [0, N]이고 N은 push와 같은 결과·같은 지름길(WRITE-088·099), 범위 밖·음수·정수 아님은 오류 없는 무동작에 현재 길이(35C-06의 확장), 배열이 아닌 호스트는 insert(0)만 push처럼 [x]를 만들고 misfit 경고등을 끄며 그 밖은 무동작(47C-02의 추론: 있는 아이템을 전제하는 동사만 무효), batch 안은 62C-01대로 호출 자리에서 끼우고 끝에서 통째 쓰기, minItems·maxItems는 막지 않는다(SURFACE-005 보충·WRITE-022). 구현의 발견 넷: insert의 defaultValue는 통째 쓰기와 같을 수 없다(통째는 스냅숏 유지 WRITE-085, insert는 생성 값을 끼움 WRITE-099); 끼운 자리 뒤 아이템은 값 갱신 대신 경로 갱신 revision 하나를 받는다(NODE-051); 아이템 기본값이 있는 스키마는 차등에서 뺀다(새 아이템은 채움 WRITE-088, 통째의 기존 자리는 아님 WRITE-090); 겉면 DETAIL의 멤버 시험 수는 이미 54였던 것을 55로 바로잡았다. 06-conclusions.md:386의 "배열 다섯"은 이 결정과 충돌이다.
- **371C-03 (수용 복사 셋과 되살림 자리, 선택 재사용 계약의 변경).**
  - 【추론】 push 한 번에 남는 길이 비례 일은 복사 셋뿐이고 셋 다 필수다: 값 배열의 얕은 복사는 React 제어 상태의 불변성 때문(63C-03), 자식 노드 배열의 새 참조는 커밋 배달 판정(captureFieldNodeChange·markCommitDeliveries)과 자식 필드·자식 오류 hook의 의존성이 보는 신호라 제자리 변경이면 push한 항목이 그려지지 않고(실험: 직전 children 비교가 무너져 힙 고갈), 로드 스냅숏은 defaultValue 게터와 렌더 프롭이 참조를 그대로 주므로 제자리 변경은 WRITE-013·WRITE-085의 불변 약속에 어긋난다(실험: 34건 실패). 둘을 없애려면 배달 판정을 참조 아닌 신호로, 호출자 입력을 처음 한 번 복사해 소유하는 설계 변경이 필요해 하지 않는다. 기본값 채움으로 같은 정착에서 호스트가 두 번 조립되어 값 복사가 두 번 생기는 경우는 소유자가 수용했다(362라운드: 첫 정착 파동에 값이 완성되지 않을 수 있음). 되살림 자리는 조립이며 커밋이 아니다(360C-01). 선택 재사용의 시험 계약(settle-array-selection-reuse)은 "경로 이동이 있으면 거절"에서 "arraySplice 증명이 유효한 정적 호스트는 예외로 꼬리만 재공표"로 바꾼다 — 이것은 원장 항목이 아니라 settle DETAIL의 안전 조건이고 정적 자격이면 재매김된 꼬리의 선택은 경로와 무관한 구조 사실뿐이므로 절차적 개선이다(364라운드). 비정적 폼의 거절은 시험으로 그대로 둔다.
