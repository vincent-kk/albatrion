### 2. 코드로 옮길 때 가장 먼저 무너질 지점 다섯 개 (심각도 순)

| :--- | :--- | :--- | :--- |

| **2. 치명적**(비객체 호스트 자식 유령 상태) | `adr/0006-single-value-ownership.md:75` "비객체 호스트의 자식은 **존재하고 렌더되며** 빈 상태를 보인다. 로드는 새 수명이므로 그 자식들은 생긴 노드로서 채움을 받고" | **스키마**: `{"type": "object", "properties": {"user": {"type": "object", "properties": {"name": {"type": "string", "default": "Guest"}}}}}` **조작**: `setValue({ user: null })` 실행 후 사용자가 화면의 `name`에 `"Alice"` 입력 **결과**: 자식이 채움을 받아 렌더되나 호스트가 `null`이라 방출에서 제외되어 사용자 입력이 방출 값에 영구 미반영 | **원장의 원칙만으로 해결 가능**(원장 제3절 "null은 전체 교체, 자식 원본은 없음" 원칙을 엄격 적용하여 비객체 호스트 하위 채움 억제) |
| **3. 높음**(중간 라운드 채움 철회의 비단조 진동) | `03-mental-model.md:152` "중간 라운드의 채움은 최종 형상에 없으면 버린다" | **스키마**: `flag`(불리언), `extra`(`&active: "../flag === true"`, `default: "A"`), `watcher`(`&derived: "../extra === 'A' ? false : true"`) **조작**: `setValue({ flag: true })` **결과**: 1라운드 `extra` 생성 채움 → 2라운드 `watcher`가 `flag`를 거짓으로 역전 → 채움 철회가 역방향 쓰기를 유발해 전이 상한 초과 루프 촉발 | **소유자의 판단 필요**(원장 161행 미결 지적: 채움 시점을 최종 형상 확정 후로 지연하는 2단계 커밋 설계 요구) |
| **4. 높음**(자식 일괄 제어의 상대 경로 기준점 붕괴) | `03-mental-model.md:119` "조각 수준 식의 기준점. 조각 객체의 `&active`, `&children` 항목의 `control`, `&discriminator`가 만드는 식의 경로 기준은 그 조각이 선언한 노드의 자리, 곧 호스트의 직계 자식 자리다." | **스키마**: 루트 아래 `parent` 노드가 `&children: { targets: ["child.leaf"], control: { readOnly: "../locked" } }` 선언, 루트에 `locked` 선언 **조작**: `locked` 값 변경 **결과**: 식의 기준점이 호스트의 직계 자식으로 고정되어 `..`가 루트가 아닌 `parent`를 가리켜 대상 참조 실패 및 제어 불능 | **소유자의 판단 필요**(원장 제6절 미결 설계 항목: 깊은 자손 대상 상대 포인터 해석 기준점 규칙 확정 필요) |

### 3. 핵심 가치 간 충돌 시 설계의 선택과 원장 명시 여부

| 충돌 지점 | 설계의 선택 | 원장 명시 여부 및 근거 |
| :--- | :--- | :--- |
| **표현자유도 대 예측가능성** | **표현자유도 우선**(동적 제어를 온전히 허용하고 비멱등성·순서 의존 수용) | **명시됨** (`03-mental-model.md:80, 115, 157`) `setValue(getValue())`의 기본값 재채움(비멱등)을 공인함. 배치와 순차 실행 간 값 차이를 정착 주기의 정상 귀결로 수용함. 순환 가능성을 억지로 제한하지 않고 상한 초과 알림 방식을 채택함. |
| **고속성 대 투명성** | **고속성 우선**(루프 조기 수렴과 경량 상태를 위해 런타임 추적성 희생) | **명시됨** (`03-mental-model.md:70, 115, 121`) 파생 경합에서 패배한 규칙의 에지를 경고 없이 즉시 소비하여 폐기함. 상태 칸을 `raw`와 `extras` 둘로만 제한하여 과거 이력 추적을 배제함. 운영 환경 예산 초과 시 상세 원인 추적 대신 원본 B로 무음 복구함. |
| **고속성 대 일관성** | **고속성 우선**(변경 비례 연산량 보장을 위해 비단말 노드 잠금 배제) | **명시됨** (`03-mental-model.md:129`, `adr/0009-performance-budget-and-benchmarks.md`) 비단말 노드의 표준 읽기 전용 상속 검사를 생략하여 트리 순회 비용을 제거함. |

### 4. 독립 풀 리퀘스트 분할 구현 가능성에 대한 견해

| 구분 | 판정 및 분석 내용 |
| :--- | :--- |
| **판정** | **메인 코드 저장소 반영은 일괄 전환 필수, 개발 작업은 기능 브랜치 내 5단계 격리 풀 리퀘스트로 분할 가능** |
| **핵심 요소 간 결합 분석** | 1. **값 소유 단일화 ↔ 정착 주기**: 새 7단계 정착 주기는 단일 원본(`raw`)·미선언 키(`extras`) 구조 위에서만 동작하며 기존 다중 상태 모델과 공존할 수 없습니다. 2. **청사진 분석 ↔ 게이트/정착**: 정착 주기의 계산 단계는 청사진 분석이 생성한 조각 표와 노드 공유 위계에 전적으로 의존합니다. 3. **`&` 이름 공간 ↔ 파생/나감**: 검증기 격리 정제 및 파생 규칙은 `&` 제어 예약 층이 해석되지 않으면 동작 자체가 불가능합니다. 4. **정착 주기 ↔ 나감의 비움**: 나감 비움은 정착 주기의 전이 단계에서 최종 형상 변화를 감지하여 원본을 비우므로 루프 엔진과 한 몸입니다. |
| **통합 전략** | 기존의 비동기 이벤트 연쇄 구조와 새 동기 정착 구조는 상태 소유 방식이 달라 점진적 공존이 불가능하므로, 메인 배포는 **단일 우산 풀 리퀘스트를 통한 일괄 교체**로 진행해야 합니다(목표 문서 C7 원칙). 다만 개발 과정에서는 작업 브랜치 내부에서 **(1) 청사진 분석기 → (2) 노드 트리와 정착 루프 하네스 → (3) 파생·채움·나감 엔진 → (4) 검증기 플러그인과 통지 디스패처 → (5) 리액트 바인딩 계층** 순으로 독립 풀 리퀘스트를 작성하여 점진적으로 통합·검증할 수 있습니다. |
