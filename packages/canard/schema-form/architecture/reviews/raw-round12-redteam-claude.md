2026-09-24. 소유자의 요청("레드팀 공격")으로 돌린 두 제안(A: 루트 스키마의 글로벌 `readOnly`·`disabled` 제거, B: 조각이 꺼질 때 원본 제거를 기본으로)에 대한 검증자(opus)의 공격 원문이다. 오늘 `src`를 임시 디렉터리의 vitest 설정으로 직접 돌린 탐침 결과가 들어 있다(저장소에는 쓰지 않았다). 편집자는 고치지 않았다. 판정은 `round-12-derivation.md`에 있다.

- [확인] 루트 스키마 덮기는 `readOnly`·`disabled`뿐 아니라 `active`·`visible`·`pristine` 다섯 키에 모두 걸립니다(`checkComputedOptionFactory.ts:23`, `needsRealComputedManager.ts:42`). 루트 `active: true`는 모든 노드의 `&active: false`를 무력화합니다(탐침). README "Priority System"(README.md 1616행 부근)이 루트 키를 네 상태 키의 1순위로 공개 문서화합니다.
- [확인] 루트 키가 문자열 식이면 노드마다 그 노드 기준 상대 경로로 컴파일됩니다. 루트 `readOnly: "../x === 1"`, x=1이면 `/x`·`/o`는 잠기고 `/o/y`는 풀립니다. 오늘의 루트 키는 불리언일 때만 "글로벌"입니다.
- [확인] "정의되면 false여도 덮는다"는 2025-09-04 커밋 6e4892380(#265)부터입니다. 그 전에는 루트 키도 잠그는 값(`readOnly: true`, `disabled: true`, `visible: false`)일 때만 걸렸습니다. 곧 OR였습니다.
- [확인] 저장소의 스토리·렌더 테스트·README 예제 어디에도 루트 스키마 `readOnly`로 폼 전체를 잠그는 쓰임이 없습니다. 쓰임은 팩토리 단위 테스트 둘뿐입니다(`checkComputedOptionFactory.test.ts`, `sharedComputedSentinel.test.ts:72`). 외부 사용자는 알 수 없습니다.
- [확인] 오늘 객체 노드의 `readOnly: true`는 자식을 잠그지 않습니다(`addr` 참, `addr/city` 거짓). 루트만 예외입니다.
- [확인] 오늘 로컬 층은 OR가 아니라 순위 사슬입니다. 노드의 `readOnly: false`가 `&readOnly: 'true'`를 이깁니다. 원장 §4의 "로컬 층 안 OR"는 오늘과 다르며 이주 항목입니다.
- [확인] `disabled`·`visible`·`active`는 JSON Schema 키워드가 아닙니다. ajv 플러그인이 `strictSchema: false`라 통과할 뿐입니다.
- [확인] 오늘 `computed.active`가 거짓이 되면 `__reset__`이 원본에 `undefined`를 씁니다(`AbstractNode.ts:569-572`, `1085-1089`). `oneOf` 전환은 이전 분기 노드를 초기화합니다(`BranchStrategy.ts:480-512`). 다시 켜질 때는 사용자 입력이 아니라 로드 값, 그것이 없으면 `default`가 돌아옵니다. 탐침 값은 다음과 같습니다: 입력 TYPED가 꺼졌다 켜지면 D(기본값) 또는 L(로드 값)이 됩니다. 두 분기가 함께 선언한 `holder`도 입력 H2가 로드 값 H로 돌아갑니다. 렌더 테스트 `composition.oneOf.switch.render.test.tsx:105-122`가 통과합니다.
- 그러므로 원장 §6과 12라운드 §3의 "오늘은 꺼진 `oneOf` 분기의 값을 방출에서 뺀다"는 불완전합니다. [확인] 오늘은 원본까지 지우고, 다시 켜질 때 로드 스냅숏으로 되돌립니다. ADR 0013 87행 "분기 전환·active 전이의 reset: 폐기"가 이 동작을 의도적으로 버린 것입니다.
- [확인] `omitEmpty`는 문자열·숫자에서 기본으로 켜져 있습니다(`options.omitEmpty !== false`, `StringNode.ts:114`).

(b) 권고: 대안′. 모든 잠금(`readOnly`·`disabled`)은 철자와 노드를 가리지 않고 하위 트리로 OR됩니다. 철자는 표준 키, `&` 키, `control.*`, `&children`, Form 속성을 모두 포함합니다. `false`는 어디서도 아무것도 풀지 않습니다. 루트 스키마 키에는 특수 규칙이 없습니다. 루트의 잠금이 곧 하위 전체의 잠금이기 때문입니다. `visible`·`active`·`pristine`은 글로벌이 아닙니다.

이유는 다섯입니다.
- 표준 `readOnly`의 뜻(인스턴스 값 전체를 쓸 수 없음)과 맞습니다. 객체의 값은 자식의 합성이므로 객체 잠금은 곧 하위 잠금입니다. 이것은 "상속 장치"가 아니라 P1의 귀결입니다.
- 답 12 "루트 스키마 키는 Form 속성과 동치"가 글자대로 성립합니다. 오늘 코드도 제안 A도 이것을 만족하지 못합니다.
- 답 1 "false는 로컬 보장"이 특별 동작이 아니라 일반 규칙이 됩니다. 12라운드 §1의 "글로벌 안의 충돌" 질문도 사라집니다.
- 축 7항과 G4를 지킵니다. 두 철자의 뜻이 같습니다.
- E-13 "중간 상속 없음"이 막으려던 것은 조상의 값이 자손의 값을 덮는 우선순위 상속입니다. 단조 OR에는 덮기가 없습니다. 비용은 위에서 아래로 한 번 전파하는 것(노드 수에 비례)이고, 조상 잠금이 뒤집히면 하위 트리 전체가 배달 집합에 듭니다.

"제거"(제안 A 원안)는 A-1·A-5가 신호 없이 남고, A-6 없이는 고지 의무를 못 지킵니다. "유지"는 A-2·A-3·A-4를 떠안습니다. 덧붙여, 제안 A가 겨냥한 "스키마 위의 `disabled`"는 표준 키가 아닙니다. 투명한 JSON Schema(답 8)를 따르면 정리 대상은 맨 키 `disabled`·`visible`·`active`를 `&` 전용으로 옮기는 것이고, 표준 `readOnly`를 빼는 것이 아닙니다. 이것은 소유자 결정 사항입니다.

공격 항목별 답
- (1) 단위는 "노드가 형상에서 나감"이어야 합니다. 직전 커밋 형상에 있었고 이번 최종 형상에 없는 노드이며, 하위 트리를 포함합니다. 선언이 하나라도 켜져 있으면 나가지 않습니다. 채움의 "생김"과 대칭입니다.
- (2) 로드에서는 발화하지 않습니다. 직전 형상이 없으므로 나감도 없습니다. 이는 "생긴 노드" 정의와 같은 기준입니다. B-4의 잠복 부활은 알려진 귀결로 문서화합니다.
- (3) 최종 형상 기준이며 전이 단계에서 적용합니다.
- (4) 예. 이것은 다섯째 자동 쓰기이므로 억제 비트와 원본 B의 대상입니다.
- (5) 같은 부류가 아닙니다. `omitEmpty`는 투영이라 되돌릴 수 있고 이력이 없습니다. 이 지움은 원본 쓰기라 되돌릴 수 없고 에지(이력)에 의존합니다. 억제 비트, 원본 B, `getInactiveValues` 모두에서 다르게 동작합니다. 같은 것은 "기본 켜짐, 끌 수 있음"이라는 사용자 경험 기본값뿐입니다. 원장에서는 P4가 아니라 §3(쓰기)에 둡니다.
- (6) 예. 조각과 한 장치이므로(G4, 원장 §2) `&active: false`와 `&children` `control.active`로 나갈 때도 지웁니다. 그 결과 `&active`는 지우고 `&visible`은 보존합니다. 이는 오늘의 구분(README "Inactive … values are removed", 탐침 B3·B4)을 되살리는 것이지 새 혼동이 아닙니다.
- (7) 오늘 대비 회귀는 B-3 하나입니다. 오늘은 로드 스냅숏으로 돌아오고, 제안 B는 `default`로 돌아오고, P4 유지안은 마지막 입력으로 돌아옵니다. 셋 다 다릅니다.
- (8) 두 종류를 나눠야 합니다. 식 규칙(`&clearValue` 식, `derived`)은 원장 병합표대로 "선언마다 규칙 하나"입니다. 둘 다 발화하고 같은 대상 규칙이 풉니다. 지움끼리는 멱등이라 OR와 결과가 같고, `derived`끼리는 문서 순서에서 나중이 이기며 순환은 예산(개발 모드 throw)이 잡습니다. 반면 나감 정책(지움/유지)은 불리언 정책이므로 덮어쓰기로 풉니다. OR로 묶으면 유지를 끌 수 없습니다(B-7). 잠금의 OR와 같은 방향인 것은 식 규칙 쪽입니다.
- (9) 정책 키는 `&clearValue`와 다른 이름이어야 합니다(B-8). 자리는 네 층이고 세부가 포괄을 덮습니다: 노드 자신의 선언 > `&children` 항목의 `control` > 조각 객체의 `control`(그 조각이 선언한 모든 노드에 거는 설탕) > Form 속성(기본 참).

(b) 권고하는 안전한 형태
- 단위: 노드의 나감(하위 트리 포함). 공유 노드는 선언이 하나라도 켜져 있으면 제외합니다.
- 시점: 전이 단계, 최종 형상 대 직전 커밋. 로드에서는 발화하지 않습니다.
- 종류: 자동 쓰기 다섯째. 억제 비트와 원본 B의 대상이며 순위는 `&clearValue`와 같은 "지움"입니다. G4를 지키려면 "없음으로 만드는 장치 하나"를 "`&clearValue` 장치 하나, 발화원 둘(식의 거짓→참, 노드의 나감)"로 다시 적습니다.
- 옵션: 별도 정책 키, 가칭 `&clearOnInactive`, 기본 참, `false`로 유지. 이름은 소유자가 정합니다. 자리는 위 (9)의 네 층입니다. 같은 층에 여럿이 있으면(공유 노드의 두 조각) 하나라도 유지면 유지합니다. 되돌릴 수 없는 쓰기는 만장일치로만 합니다.
- 재진입: 생긴 노드이므로 채움과 상호작용 초기화를 받습니다.
- 소유자 선언이 필요한 것: 축 4항과 P1′ 끝 문장의 개정(B-2), B-3 회귀의 수용. 편집 화면은 Form 속성 한 줄로 유지를 켜게 안내합니다.

(c) 받으면 바뀌는 원장 문장
1. P1′ 끝 "값을 빼거나 지우는 것은 작성자의 `&` 명령뿐이다" → "… `&` 명령과, 형상에서 나간 노드의 비움 정책(기본 켜짐)뿐".
2. §1.2 4항의 읽기 "조각의 켜짐·꺼짐은 있는 값을 바꾸거나 지우지 않는다". 축 개정입니다.
3. §1.1 P2 행과 본문의 쓰기 주체 목록에 "나감의 비움"을 더합니다. "core가 스스로 원본을 고치는 일은 없다"에는 기본 정책이라는 단서를 답니다.
4. §1.4 JSON Schema 층 "값을 채우지도 바꾸지도 지우지도 않는다".
5. §2 "원본은 남아 `getInactiveValues`로 읽을 수 있으며" → 유지 정책 노드와 로드 때부터 형상 밖이던 노드만.
6. §3 표에 "나감" 행을 추가합니다. "비활성화는 쓰기가 아니다 — 조각이 꺼져도 원본은 그대로다"를 고칩니다. "로드는 새 수명" 문단에 "로드에는 나감이 없다"를 더합니다. "없음으로 만드는 장치는 `&clearValue` 하나다"를 발화원 둘로 고칩니다. 억제 범위 목록에 나감의 비움을 더합니다.
7. §4 전이 줄, 예산의 원본 B 목록, 같은 대상 순위 목록.
8. §5 행 "비활성화는 방출 제외, 원본 유지. 노드 게이트도 같다". `&children` 행. 채움 행 옆에 대칭 행 "비움은 노드가 나갈 때 한 번, 노드 단위, 최종 형상 기준"을 더합니다.
9. §6 "꺼질 때의 값 정책" 항목을 닫고, "오늘은 꺼진 `oneOf` 분기의 값을 방출에서 뺀다"를 사실대로 고칩니다(오늘은 원본을 지우고 로드 스냅숏으로 복원).
