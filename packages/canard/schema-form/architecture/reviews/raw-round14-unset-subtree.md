# 14라운드 — `unsetOnInactive` 하위 트리 규칙의 정합성 검증 원문 (로컬 verifier, opus)

2026-09-24. 소유자 답 O-8("논리적 정합성을 따져보세요. 권고가 맞는 거 같긴 한데 확신을 못하겠군요")에 따른 적대적 검증 원문이다. 편집자는 고치지 않았다. 반영은 `08-design-a-to-z.md` §8.4.

판정: 수정 채택입니다. 권고의 순서(자손 자신 > &children > 자손의 조각 > 나가는 조상 > Form 속성)는 문면 그대로면 두 곳에서 결과가 하나로 정해지지 않습니다. 조각 범위와 "조상의 정책"이라는 말뜻을 못박으면 정합합니다. 공유 노드의 경우(c)와 잠복 자손의 경우(h)는 소유자 결정이 남습니다.

3. 상속 금지 | 13라운드 답 1 "모든 control 필드는 자체 노드만 지원", 03:46·03:167 "조상의 상속도 없다" | 권고는 control 필드의 조상→자손 전달입니다 | "이는 상속이 아니다. 객체의 값은 리프에 있으므로(ADR 0006 §3) 나가는 객체를 비우는 것은 곧 그 리프를 비우는 것이다. 그래서 나가는 조상에서만 내려가고, 나가지 않는 조상(루트 포함)은 내려가지 않는다." 이 문장으로 루트 키가 전역 기본값이 되는 길(G4 중복)도 막습니다. 예외로 명시하려면 소유자 확인이 필요합니다
4. 문구 | 03:14, 03:72, 03:94, 08:105, ADR 0003:54, 0006:50·91, 0007:36·61의 "정책 키를 켠 노드" | 전달을 채택하면 자기 키 없이 비워지는 리프가 생깁니다 | "정책이 참으로 정해진 노드"로 바꿉니다
5. 동기 과장 | O-8 "내려가지 않으면 답 15를 이룰 수 없다" | 대안 ㄱ에서도 리프마다 키를 걸거나 층마다 &children을 걸면 표현할 수 있습니다. 불가능한 것이 아니라 선언 수가 중첩 깊이에 비례하는 것이 문제입니다. 대안 ㄱ에서는 비터미널 객체의 키가 효과 없는 이름 함정이 됩니다 | 문제 문장을 "선언이 리프 수만큼 늘고, 객체의 키가 효과 없는 함정이 된다"로 고칩니다
6. 비용 | 03:118 "재계산 목록과 자동 쓰기 기록만 순회" | 나간 하위 트리를 열거하는 일은 두 목록 어디에도 없습니다. 이는 권고 이전의 "하위 트리 포함" 때부터 있던 충돌입니다 | "나감의 비움은 나간 하위 트리를 위에서 아래로 한 번 순회하며, 조상 정책을 인자로 내려보낸다(노드당 상수 비용, 위로 거슬러 오르지 않는다). 청사진이 '하위 트리에 정책 선언 없음'을 미리 표시하면, Form 속성이 꺼져 있을 때 순회를 건너뛴다."

[대안 비교] 공통 스키마: oneOf[0] = { '&active': "../kind === 'a'", properties: { addr: { type: 'object', properties: { zip, street } } }, control: { unsetOnInactive: true } }
- ㄱ(내려가지 않음): control은 addr에만 걸리고 효과가 없습니다. addr: { '&children': [{ targets: ['zip','street'], control: { unsetOnInactive: true } }] }를 층마다 적어야 합니다. 조각에서만 선언된 자식을 targets로 가리킬 수 있는지는 03 §6에서 아직 미결이라, 소유자가 원래 상정한 &children 경로도 막힐 수 있습니다.
- ㄴ(권고): 위 선언 하나면 됩니다. 예외는 zip: { '&unsetOnInactive': false }입니다. 빈틈 1·2를 고치면 모든 시나리오가 글의 중첩 순서와 일치합니다.
- ㄷ(조상이 조각보다 세부): addr이 자기 키 true이고 addr.oneOf[0]이 control false로 zip을 선언한 경우를 보겠습니다. 바깥 addr이 안쪽 조각을 덮어 zip이 비워지므로 세부 원리를 거스릅니다. 반례만 있고 이득은 없습니다.
- 세 대안 모두 표현하지 못하는 요구: 답 15의 "변경"과 "입력 초기화"를 나감 때 거는 일입니다. 조각 control의 식 규칙이 나감 에지에서 발화하는 세부는 03:196에 따라 슬라이스 3의 미결입니다. (c)와 (h)도 세 대안 모두 비우지 못합니다.

[권고 문장] "나가는 노드의 비움 여부는 그 노드와 그 위의 나가는 조상들을 가까운 순서로 보아, 직전 커밋에서 세 층(노드 자신 > 그 노드를 가리키는 &children 항목의 control > 그 노드를 직접 선언한 조각의 control) 가운데 하나라도 명시된 첫 노드가 정하고(한 노드의 같은 층에 여럿이면 하나라도 유지면 유지), 끝까지 없으면 Form 속성이 정한다 — 객체의 값은 리프에 있으므로 이는 상속이 아니라 나가는 객체를 비우는 일의 정의이며, 나가지 않는 조상의 정책은 내려가지 않는다."

[브리프 밖 결정, 추측하지 않고 보고합니다]
- (c): 공유 노드가 남고 꺼진 조각 쪽에만 선언된 자손이 나갈 때, 그 조각의 control이 닿는가. 후보는 "노드의 나감"에 더해 "선언의 나감"을 조상 사슬에 세는 것입니다.
- (h): 나감 때 이미 잠복한 자손까지 비우는가. 비우면 비용 상한에 잠복 노드 순회가 더해집니다.
