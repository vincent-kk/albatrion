# 108라운드 — Vincent의 답 (코어 마운트의 남은 미달 다섯 행은 수용한다 — 원인은 청사진 분석의 첫 비용이고 React 층 마운트는 모두 목표 안이다; 청사진의 폼 간 공유 계약은 7단계 뒤로 미루되, 공유가 문제의 온상일 수 있다는 우려를 함께 적는다)

2026-10-07. 코드 수준의 큰 상한이 소진된 시점의 공식 판정표(106라운드)를 놓고 원장 관리자가 결정할 것 둘을 정리해 올렸다: 코어 마운트의 남은 미달 다섯 행(sample-2 2.13배, sample-3 1.69배, nested-d3 1.63배, nested-d5 1.90배, computed-visible-derived 3.36배; 원인은 모두 청사진 분석의 첫 비용이고 절대 차이는 nested-d5 약 2.8 ms 외에는 0.1–0.3 ms; React 층 마운트는 24행 모두 1.2배 목표 안)을 받아들일지, 그리고 청사진의 폼 간 공유 계약(S01: 같은 내용의 스키마 사이에 콜드 분석을 재사용; 둘째 폼부터 nested-d5 마운트가 옛 판보다 빨라지나 첫 마운트와 판정표는 바뀌지 않고, 키·수명·메모리·옵션 범위의 새 계약이 필요)을 7단계 안에서 열지, 뒤로 미룰지, 열지 않을지. 원장 관리자는 수용과 미룸을 권고했다.

| 코어 마운트 미달 다섯 행의 수용 | 남은 미달 다섯 행(원인: 청사진 분석의 첫 비용)을 받아들일지 | "첫번째는 수용하고," (2026-10-07, 원장 세션) | 확정. 코어 분기 없는 폼의 마운트 행 가운데 sample-2·sample-3·nested-d3·nested-d5·computed-visible-derived의 1.5배 미달은 소유자가 받아들였다(TEST-027). 이유: 폼 생성 때 스키마 전체를 한 번 분석해 두는 청사진 단계(BLUEPRINT-001)가 옛 판에는 없는 첫 비용이며, 코드 수준의 큰 상한은 소진되었고(열세 개의 채택으로 nested-d5 13.5 → 5.9 ms), React 층 마운트는 24행 모두 목표 안이다. 85C-01의 마운트 목표는 이 다섯 행에서 소유자 수용으로 닫힌다. 이로써 코어의 공식 표에서 수용되지 않은 미달은 flat-100 첫 갱신(1.73배, 손질 대상)뿐이다. |
| 청사진 공유 계약의 시기 | S01을 7단계 안에서 열지, 뒤로 미룰지, 열지 않을지 | "두번째는 미루는게 맞는거같다. 다만, 두번째 청사진 공유가 괜찮은건지도 모르겠군. 공유가 좋게 보면 좋은데 문제의 온상일수가 있어서 말이야" (2026-10-07, 원장 세션) | 확정(미룸). S01은 7단계에서 열지 않고 뒤의 항목으로 적어 두되, 열지 여부 자체는 그때 다시 소유자가 판단한다 — 소유자의 우려(공유는 문제의 온상일 수 있다)를 그 항목의 전제로 적는다. 원장 관리자의 메모: 지금도 같은 스키마 객체의 청사진은 폼 사이에 재사용되고 있어(100C-01이 그대로 둔 것) 공유의 위험은 좁은 형태로 이미 있으며, 동결 작업(102–103라운드)에서 폼 사이로 새는 길이 여럿 걸러졌다(힌트 병합의 중첩 객체, 공개 유효 스키마, 기본값 참조). 뒤에 S01을 판단할 때는 넓히는 쪽만이 아니라 지금의 같은 객체 재사용을 좁히는 쪽도 선택지에 둔다. |
