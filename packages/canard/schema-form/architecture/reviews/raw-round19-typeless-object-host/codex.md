### §5 축별 판정

**A1 결함 — 재귀 종료.** pydantic `Optional[discriminated]`의 바깥 `anyOf`는 형 없는 `oneOf` 분기와 null 분기를 가지며, 참조 대상 Cat·Dog는 명시적 object 형입니다. 따라서 D9가 같은 칸 안의 중첩 분기와 `$ref`를 따라가면 object+null로 끝납니다. 반면 재귀 트리의 `Node.children.items.anyOf → Node`는 *자식 아이템을 거치는* 참조입니다. D10의 "유한 참조 그래프의 순환"을 그대로 적용하면 이 정상적인 절단점까지 ⊤ 오류로 만들 수 있습니다. 현재 `inferAllowedTypes`의 재귀 호출에는 탐색 경로가 전달되지 않습니다. D9·D10은 **같은 칸의 형 추론 경로에서 형을 확정하지 못한 채 재진입할 때만** ⊤로 끝내고, 자식 참조의 형상 순환은 별도 형상 검사에 맡기도록 고쳐야 합니다(`architecture/spikes/guard-cost/redteam3/corpus.mjs:12-16,31-36,202-214`, `architecture/ledger/blueprint.md:469-484`, `src/core/blueprint/utils/types/inferAllowedTypes.ts:18-24,40-50`, `src/core/blueprint/utils/analyze/collectStaticSchemas.ts:13-27`, `src/core/blueprint/utils/analyze/validateShape.ts:11-40`). `RECURSIVE_SHAPE_UNBOUNDED`는 배열·게이트·터미널로 끊기지 않은 객체 프로퍼티 형상 순환에 남겨야 합니다(`architecture/ledger/blueprint.md:479-485`, `architecture/reviews/round-18-closing.md:16-27`).

**A2 결함 — 게이트 가진 분기의 셈.** 소유자 답 30행은 서두에서 원시 사례를 논하지만, 실제 절차 문장은 "정적 연언에 `type`을 가진 선언이 없는 칸"에서 **게이트 없는** 분기를 보도록 정하고, 끝에서 게이트 가진 분기를 합치기에서 제외합니다. 원장도 그대로 기록하며, U4는 게이트 선언이 종류·`schemaType`·nullable을 바꾸지 못하게 합니다. 그러므로 D1의 전 분기 셈과 D7의 게이트 제외는 한 절차에서 양립하지 않습니다. D1·D8·D9의 대상은 게이트 없는 분기로 통일해야 합니다(`architecture/reviews/round-18-owner-answers.md:30,37`, `architecture/ledger/blueprint.md:645-655,715-724`, `architecture/reviews/raw-round18-union-swarm/merged-v3.md:143-153`). 코퍼스의 표준 `discriminator` 필드와 명시적 `controls.discriminator`는 구별해야 합니다. 현재 변환 함수는 후자만 읽습니다(`architecture/spikes/guard-cost/redteam3/corpus.mjs:16,35-36`, `src/core/blueprint/utils/analyze/readDiscriminatorBranches.ts:27-38`, `src/core/blueprint/utils/analyze/collectDeclarations.ts:129-155`).

**A3 소유자 물음 — 배열만인 경우.** BLUEPRINT-035는 variant라는 이름을 정의하지만, BLUEPRINT-039가 보존한다고 명시한 것은 **object** variant 호스트입니다. NODE-042의 array 전략 순서는 서로 다른 배열 분기의 `items`·`prefixItems`를 합치는 규칙이 아닙니다. 현재 구현은 모인 아이템 입력의 `build` 결과에서 첫 노드를 택하므로 D4를 그대로 허용하면 아이템 종류가 다른 분기의 처리 계약이 비어 있습니다(`architecture/ledger/blueprint.md:598-603,677-683`, `architecture/ledger/node.md:621-633`, `src/core/blueprint/utils/analyze/populateNodeChildren.ts:100-136,172-181`).

- **선택지 1 — 객체만 허용:** F=`{array}`는 계속 `UNKNOWN_JSON_SCHEMA`입니다. 원장의 미정인 배열 결합 규칙을 요구하지 않으며, 코퍼스 재귀 트리의 `children`은 이미 명시적 `type:'array'`이므로 이 축소안의 대상이 아닙니다(`architecture/ledger/blueprint.md:679-683`, `architecture/spikes/guard-cost/redteam3/corpus.mjs:209-212`).
- **선택지 2 — 배열도 허용:** array variant 호스트가 되지만, `items`·`prefixItems`의 같은 종류 공유, 다른 종류 충돌 또는 분리, 튜플 위치별 처리부터 원장에 결정해야 합니다. 현재 첫 노드 선택을 통과 근거로 쓸 수 없습니다(`src/core/blueprint/utils/analyze/populateNodeChildren.ts:111-136,172-181`, `architecture/ledger/blueprint.md:821,830`).

**A4 결함 — 판정 절차의 자리.** S3에서 종류를 정한 뒤 S4의 variant 규칙과 S6의 object·array 전략으로 가는 자리는 맞습니다. 그러나 D1·D2는 null을 교집합 전에 떼고 D3·D4는 "어느 분기든 null"이면 nullable로 삼아, 원문의 *null 포함 합집합 → 키워드 간 교집합 → null 분리* 순서를 어깁니다. 예컨대 `oneOf:[object,null]`과 `anyOf:[object]`는 nullable이 false여야 합니다. null만 남는 E32·E33과 F=`{object,array}`도 현 D1–D8에는 단일 결과가 없습니다. D1–D3·D6·D7을 U 중심으로 다시 써야 합니다(`architecture/ledger/blueprint.md:645-655,802-811,818-835,883-884`, `architecture/reviews/round-18-closing.md:2390-2400,2409,2447-2449`; 초안 `architecture/reviews/raw-round19-typeless-object-host/brief.md:20-27`). 종류가 정해진 object의 전략 순서는 NODE-028·042와 맞습니다(`architecture/ledger/node.md:421-436,621-633`).

**A5 결함 — 형 수준.** 현 정본은 형 없는 객체 분기 전부를 `InferSchemaNode=never`, `InferValueType=unknown`으로 적고, `$ref`·게이트·두 키워드 병존·`allOf`는 넓은 형으로 남깁니다. 현재 `InferSchemaNode`는 형 없는 분기에서 넓은 `SchemaNode`로 떨어지고, `InferValueType`은 기본 형의 `type` 부재 경로를 따라 `any`가 됩니다. **A6 결함 — 뒤집히는 범위.** D11·D12·D14에는 대체 대상이 빠져 있습니다. 현행 오류 문장은 BLUEPRINT-039와 소유자 O3, merged-v3 §2.15·O3, 18C-90의 S3 참조·E16·ERROR-164 보충에 있습니다. **A7 통과 — 값 의미에 관한 설계 대조.** 명시적 게이트가 없으면 분기를 고르지 않고 모두 형상 선언으로 읽으며, 같은 이름·같은 종류는 노드 하나를 공유한다는 원장과 맞습니다. 현재 수집·자식 구성 경로도 게이트 없는 분기를 선언 문맥으로 두고 같은 이름의 자식을 모으므로, object 형 추론이 추가되면 명시적 object 호스트와 같은 경로로 이어질 근거가 있습니다. `kind`의 재선언이 자동 선택 게이트가 되지는 않습니다. **이는 설계상 통과이며, 형 없는 호스트는 현재 오류이므로 실행 동등성은 미검증**입니다(`architecture/ledger/goal.md:455-458`, `architecture/ledger/blueprint.md:197-204`, `architecture/spikes/guard-cost/redteam3/corpus.mjs:22-28,55-69`, `src/core/blueprint/utils/analyze/collectDeclarations.ts:150-174`, `src/core/blueprint/utils/analyze/populateNodeChildren.ts:66-87`, `src/core/blueprint/utils/types/inferAllowedTypes.ts:47-60`).

**A8 통과 — 구현 위치와 거리의 식별.** 필수 판정 변경 지점은 `inferAllowedTypes`의 게이트 제외·중첩 S3·순환 경로·object 허용입니다. `collectDeclarations`와 `readDiscriminatorBranches`의 게이트 표식을 연결해 확인하고, `resolveNodeTypes`→`buildNodes`→`populateNodeChildren`의 공유 자식 결과 및 `resolveNodeStrategy`의 전략을 회귀 검증해야 합니다. `readAllowedTypes`·`unionAllowedTypes`·`intersectAllowedTypes`·`foldAllowedTypes`는 현재 필요한 집합 연산을 이미 제공하므로 이 검토만으로 변경 필수라고 판정하지 않습니다. 시험은 `blueprint.type-inference`, `blueprint.recursion`, `blueprint.type-gated-declarations`, `blueprint.discriminator`와 공개 형 시험에 필요합니다. 객체만의 축소안에는 새 fractal이나 큰 구조 변경의 근거가 없습니다. 배열 허용을 택하면 `populateNodeChildren`의 아이템 결합을 별도로 설계해야 합니다(`src/core/blueprint/utils/types/inferAllowedTypes.ts:18-78`, `src/core/blueprint/utils/types/readAllowedTypes.ts:17-43`, `src/core/blueprint/utils/types/unionAllowedTypes.ts:8-21`, `src/core/blueprint/utils/types/intersectAllowedTypes.ts:9-26`, `src/core/blueprint/utils/types/foldAllowedTypes.ts:8-22`, `src/core/blueprint/utils/types/resolveNodeTypes.ts:24-78`, `src/core/blueprint/utils/analyze/buildNodes.ts:34-54,84-89`, `src/core/blueprint/utils/analyze/populateNodeChildren.ts:139-181`, `src/core/blueprint/utils/types/resolveNodeStrategy.ts:19-41`, `src/core/blueprint/DETAIL.md:34-56,70-72`).

### 고친 결정문

아래는 **A3에서 객체만 허용하는 축소안을 임시로 둔 문안**입니다. 배열 허용 여부는 소유자 물음으로 남습니다(`architecture/ledger/blueprint.md:677-683`, `src/core/blueprint/utils/analyze/populateNodeChildren.ts:172-181`).

- D1. S3(정적 연언 C에 `type`이 없는 칸)에서는 게이트 없는 `oneOf`·`anyOf` 분기만 세고, 각 키워드의 분기 A(b)를 `'null'`을 포함한 채 합쳐 키워드별 허용 집합 U를 만든다.
- D2. 게이트 없는 분기가 있는 키워드가 둘이면 두 U를 `'null'`을 포함한 채 교집합하고, 하나면 그 U를 쓰며, 그 결과가 빈 집합이면 `UNKNOWN_JSON_SCHEMA`다.
- D3. 최종 U에서 `'null'`을 뗀 형을 접은 F가 `{object}`이면 칸은 object 종류이고 `schemaType`은 `'object'`이며, nullable은 최종 U에 `'null'`이 있을 때만 true다.
- D4. F가 `{array}`이면 array variant 호스트의 `items`·`prefixItems` 결합 규칙을 소유자가 정하기 전까지 `UNKNOWN_JSON_SCHEMA`다.
- D5. D3으로 object 종류가 정해진 칸은 그 뒤 S4의 variant 규칙과 S6의 순서(`options.terminal` → 판정 → `type`)를 자기 `type`을 명시한 object 칸과 똑같이 따른다.
- D6. F에 `object` 또는 `array`와 다른 null 아닌 종류가 함께 있으면(`object`와 `array`가 함께인 경우 포함) `UNKNOWN_JSON_SCHEMA`다.
- D7. 최종 U가 `{null}`이면 null 종류·`schemaType:'null'`·`nullable:true`이고, F에 `object`·`array`가 없으면 소유자 답 30행의 원시 접기를 적용하며, 게이트 없는 분기가 전혀 없으면 `UNKNOWN_JSON_SCHEMA`다.

- D11. 소유자 답 33행의 "객체만인 경우도 `UNKNOWN_JSON_SCHEMA`"만 이 결정으로 대체하고, 배열만인 경우의 오류·객체 또는 배열과 다른 종류의 혼합 금지·기존 object variant 호스트의 분기 의미는 유지한다.
