2026-10-11. 135라운드의 "넷 구현 → 판정 하나"에 따라 136a(array-500·flat-50·oneOf-20 등)와 136b(flat-500·array-100·array-push-100·array-replace-200·array-push-remove-100)는 ADOPT였으나, 136c(array-1000)에서 갱신 wall·active 두 행이 회귀로 표시되었고(−140 µs, 기준 대비 약 8%), 확인 측정 136c2에서 같은 방향으로 다시 나왔다(−71 µs). gc 없는 짝 열은 [−3, +28] µs로 0을 품지만 124C-01의 크기 조건(2% 이하, 5 µs 이하)에서 벗어나 면제는 없다. 07의 진단(`verification/07-switch/fbx-a1000-diagnosis.md`)은 재현(17쌍 ABBA, −39.8 µs), 기전(창 안 GC 정지를 빼도 −41 µs가 남고 후보의 React 일은 오히려 적음), 사용자 비용(마운트 직후 첫 갱신에 한정, 살아 있는 마운트의 반복 입력 135회는 차이 없음), 지연 초기화 가설 기각(마운트 이득 약 +10,200 µs 대 첫 갱신 손실 −71~−140 µs이고 네 변경 어디에도 마운트의 일을 미루는 코드가 없음), 하나씩 뺀 조합(F-E 제외 −3.6 µs [−34.2, +24.5]로 해소, F-F 제외 −38.7 µs로 잔존, F-B·F-C 제외는 점 추정이 합본의 약 73%로 미해결)을 보였다. 남은 유력 기전은 힙 위상이다 — F-E의 보유량 감소(합본 15.7 MB 중 13.7 MB)가 마운트 뒤 GC 단계를 바꿔 첫 쓰기가 incremental marking 중(후보 59회 대 기준 16회)에 돌며 쓰기 장벽 비용을 낸다. 편집자 결정으로 닫는다. 소유자에게는 알렸다.

### 136C-01 (1) 넷 번들은 128C-01의 확인된 회귀이고 124C-01 면제가 없으므로 지금 규칙으로 채택하지 않는다(136c REJECT); (2) 134C-01 (1)의 "회귀가 나오면 갈라 잰다"대로 하나씩 뺀 조합 비교를 근거로 F-B·F-C·F-F 셋 번들(`r136-no-fe`)을 후보로 삼아 기준 `r133-base`, 기존 A/A 132b·132c·132d, 같은 행 파일 넷으로 네 부분 판정을 다시 받는다(약 268분; 1부·2부의 감시 설정 넷을 그대로 덮으며, array-500 갱신 이득이 셋 번들에서 남는지는 1부에서 자연히 드러나므로 따로 재지 않는다) — 모두 채택되면 fb·fc·ff 패치만 적용해 전체 검사 뒤 커밋한다; (3) F-E는 진단과 함께 보류한다 — 최종 표의 보류 행에 "gc 없는 짝 열은 0 포함, 판정 열(gc-on)에서만 회귀, 기전은 힙 위상 추정"을 그대로 적고, 소유자 질의 목록 3항(판정 열의 gc 조건을 개선 단계에서 다시 볼지)의 근거 사례로 붙인다; 판정 열의 조건을 바꾸는 것은 소유자 결정이므로 원장 관리자가 앞당기지 않는다; (4) 셋 번들을 빼도 손실이 남으면 넷 모두 보류하고 화면 main A/A와 최종 표로 넘어간다
