# 134라운드 닫기 — 남은 7단계 측정의 세션 수를 줄인다: 작은 화면 고침 셋(F-C·F-F·F-E)은 고침마다 계수와 시험을 두되 시간 판정은 묶어 하나로 받고 회귀가 나오면 갈라 잰다; 화면 A/A는 남은 고침 사이에 재사용하고 마지막 코드 변경 뒤 한 번으로 재사용을 확인한다; 분기 축 최종 재측정은 최종 표 세션과 합치고, 구조 검증과 base 정리는 측정과 겹쳐 준비한다

2026-10-10. 소유자가 남은 시간(이틀 안팎)이 너무 많다며 병렬화할 것이 없는지 물었다("엥? 이틀?? 진짜? 그렇게 많이남았어? 병렬화 할 수 있는건 없나? 너무 많이남았는데"). 측정은 한 기계에서 CPU 간섭을 피하려 직렬이므로 병렬이 아니라 세션 수를 줄이는 것이 답이다. 편집자 결정으로 닫는다. 소유자에게는 알렸다.

### 134C-01 (1) F-C(onSubmit useCallback)·F-F(useTerminalChildren의 의존성과 terminal 한정)·F-E(트래커 셋을 마스크 합친 하나로)는 효과가 작고 서로 독립이므로 고침마다 계수 시험과 단언(119라운드의 렌더 격리, 쓰기당 할당, 마운트 보유 바이트)을 따로 두되 시간 판정은 셋을 합친 번들 하나로 받는다 — 확인된 회귀가 나오면 그때 고침 단위로 갈라 잰다; (2) 화면 A/A는 F-B 판정과 번들 판정 사이에 다시 재지 않고 지금의 A/A(132b·132c·132d)를 소음 항으로 재사용하며, 마지막 코드 변경 뒤 A/A 한 번(코어·화면)으로 재사용이 옳았음을 확인한다 — 그 A/A가 범위를 넘으면 그 사이의 판정을 새 A/A로 다시 계산한다(원자료 재계산, 새 측정 없음); (3) 분기 축 최종 재측정(기울기 보고, 기준 ① 판정, if-then 행 확인)은 최종 표 세션에 합친다; (4) G27(seiri:verify, 새 문맥)은 마지막 코드 변경 직후 최종 측정과 겹쳐 시작하되 측정 중에는 시험을 돌리지 않는 읽기 전용으로 하고, base 정리 스크립트는 원장 관리자가 미리 만들어 G33 시점에 실행한다; 목표한 확인은 하나도 빠지지 않는다

- 닫는 항목: TEST-026(보충), GOAL-011(보충)
- 결정:
  - 【추론】 변경 하나에 판정 하나(88C-01·105C-01)의 뜻은 이득과 회귀를 변경에 귀속시키는 것이다. 효과가 작고 독립인 고침 셋을 묶어 판정해도 회귀가 없으면 귀속은 문제가 없고, 회귀가 나오면 갈라 재어 귀속한다 — 묶음은 귀속의 지연이지 포기가 아니다. A/A는 같은 코드를 두 번들로 잰 소음이고 그 크기는 측정기의 조건(프로세스, gc, 블록)이 정하므로 코드의 작은 변경에 거의 무관하다; 그래서 채택마다 다시 재는 것은 확인이지 필요가 아니며, 끝에 한 번으로 확인하고 넘으면 재계산하는 쪽이 같은 보증을 더 싼 값에 준다(129라운드의 "효율은 원장 관리자의 역할"). 분기 축 재측정은 어차피 최종 표의 행이다. G27은 코드가 바뀌면 다시 해야 하므로 마지막 코드 변경 뒤에 두되 측정과 겹칠 수 있고, base 정리는 미리 준비할 수 있다. 줄인 뒤 남는 세션은 F-B 판정 셋, 번들 판정 셋, 최종 A/A와 최종 표 넷이며 기계 시간 열다섯 시간 안팎이다.
