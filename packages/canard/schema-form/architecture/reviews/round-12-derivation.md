## 3. 레드팀 판정

### 3.1 제안 A — 루트 스키마의 글로벌 `readOnly`·`disabled` 제거

두 검증이 모두 원안(제거)에 반대했다. 검증자가 오늘 코드를 돌려 확인한 사실이 판단을 바꾼다.

- 오늘 루트 스키마 키는 `readOnly`·`disabled`뿐 아니라 `active`·`visible`·`pristine` 다섯을 덮고, 루트 `active: true`는 모든 노드의 `&active: false`를 무력화한다. 소유자의 "글로벌은 `readOnly`·`disabled`뿐"과 다르다.
- 루트 키가 문자열 식이면 노드마다 상대 경로로 컴파일되어 깊이에 따라 일부만 잠긴다. 오늘의 "글로벌"은 불리언일 때만이다.
- "정의되면 `false`여도 덮는다"는 2025-09-04 커밋부터이고, 그 전에는 OR였다. 저장소 안에 루트 `readOnly`로 폼 전체를 잠그는 쓰임은 없다(단위 테스트 둘뿐).
- 오늘 객체 노드의 `readOnly: true`는 자식을 잠그지 않는다. 오늘 로컬 층은 OR가 아니라 순위 사슬이다(노드 `readOnly: false`가 `&readOnly`를 이김).
- `disabled`·`visible`·`active`는 JSON Schema 키워드가 아니며 ajv가 `strictSchema: false`라 통과할 뿐이다.

편집자 판정. 소유자가 성가시다고 느낀 것은 "정의되면 `false`여도 덮는" 비대칭이다. 이를 없애는 길은 둘이고 둘 다 제거보다 낫다.

| 안 | 내용 | 얻는 것 | 잃는 것 |
| --- | --- | --- | --- |
| 가 (검증자 권고) | 잠금(`readOnly`·`disabled`)은 철자를 가리지 않고(표준 키, `&`, `control`, `&children`, Form 속성) **하위 트리로 OR**. `false`는 어디서도 풀지 않음. 루트 특수 규칙 없음(루트 잠금 = 전체 잠금이 자연히 나옴). `visible`·`active`·`pristine`은 글로벌 아님 | 표준 `readOnly`의 뜻(인스턴스 전체)과 일치. "루트 = Form 속성" 동치가 글자대로 성립. 규칙 하나(G4). 생성기 스키마의 `audit: {readOnly: true}`가 뜻대로 잠김 | 답 13 "중간 조상 상속 없음"의 개정(단조 OR는 값을 덮는 상속이 아니다). 위→아래 전파 비용(노드 수 비례). 오늘 동작 둘 사라짐(루트 `false`가 푸는 것, 노드 `readOnly: false`가 `&readOnly`를 이기는 것) |
| 나 (antigravity 권고) | 루트 스키마 키는 Form 속성과 똑같이 **참일 때만** 덮는 OR. 중간 객체의 `readOnly`는 오늘대로 자식을 잠그지 않음 | 답 13 유지. 변화 최소 | 중간 객체의 표준 `readOnly`가 계속 무효(생성기 스키마와 불일치). 루트만 특수라는 예외가 남음 |
| 다 (원안) | 루트 스키마 키를 글로벌에서 뺌 | 규칙 단순 | 스키마만으로 폼 전체를 잠글 길이 사라짐(P5: 코어만 쓰는 호스트). 루트 `readOnly: true`가 신호 없이 무효 |

편집자 권고는 **가**다. 이유: 표준의 뜻을 따르고, 소유자가 이번에 받은 "`false`는 로컬 보장"이 특별 동작이 아니라 일반 규칙이 되며, 루트·중간·리프에 같은 규칙 하나가 걸린다. 답 13이 막으려던 것은 조상의 값이 자손의 `&` 식을 덮는 우선순위 상속이고, 단조 OR에는 덮기가 없다. 소유자가 정한다(13라운드 1). 어느 안이든 루트 키의 `active`·`visible`·`pristine` 특수 처리는 사라진다(이주).

### 3.2 제안 B — 조각이 꺼질 때 원본 제거를 기본으로

두 검증이 갈렸다. antigravity는 강하게 반대(P4·P2 파괴, 공유 노드, 로드 시 증발, 잠깐 전환 시 입력 소실). 검증자는 조건부 통과이며 안전한 형태를 제시했다. 검증자의 탐침이 밝힌 사실: **오늘 코드가 이미 비운다.** `active`가 거짓이 되면 원본에 `undefined`를 쓰고, `oneOf` 전환은 이전 분기 노드를 초기화하며, 다시 켜지면 마지막 입력이 아니라 로드 값(없으면 `default`)으로 되돌린다. 원장 §6의 "오늘은 방출에서만 뺀다"는 틀렸고 고쳤다. ADR 0013이 이 reset을 의도적으로 버렸던 것이다.

antigravity의 공격 가운데 검증자의 안전한 형태가 막는 것: 공유 노드(단위를 조각이 아니라 "노드의 나감"으로), 로드 시 증발(로드에는 나감이 없음), 정착 안의 흔들림(최종 형상 기준, 전이 단계), 원본 B·억제(다섯째 자동 쓰기), OR 결합의 불능(정책은 덮어쓰기, 같은 층은 만장일치로만 비움). 막지 못하는 것 하나: **잠깐 전환했다 돌아오면 입력이 사라진다**(B-3). 오늘은 로드 값으로 돌아오고, P4 유지안은 마지막 입력으로 돌아오고, 비움안은 `default`로 돌아온다.

편집자 판정. 장치의 모양은 검증자의 안전한 형태로 정한다(어느 기본값이든 같다).

- 단위: 노드의 나감(직전 커밋 형상에 있었고 최종 형상에 없음, 하위 트리 포함). 선언이 하나라도 켜져 있으면 나가지 않는다. 채움의 "생김"과 대칭.
- 시점: 전이 단계, 최종 형상 기준. 로드에는 나감이 없다.
- 종류: 다섯째 자동 쓰기. 억제 비트·원본 B의 대상. `&unsetValue`와 같은 "없음으로" 장치이며 발화원이 둘(식의 거짓→참, 노드의 나감).
- 정책 키: `&unsetValue`와 다른 이름(가칭 `&unsetOnExit`, 소유자가 정함). 자리는 네 층, 세부가 포괄을 덮음: 노드 자신 > `&children` 항목의 `control` > 조각 객체의 `control` > Form 속성. 같은 층에 여럿이면 하나라도 유지면 유지(되돌릴 수 없는 쓰기는 만장일치).
- 노드 게이트 `&active: false`도 같은 장치(G4). 그 결과 `&active`는 비우고 `&visible`은 보존한다 — 오늘의 구분과 같다.
- 식 규칙(`unsetValue` 식, `derived`)은 정책이 아니라 규칙이므로 "선언마다 규칙 하나"로 둘 다 발화하고 같은 대상 규칙이 푼다(OR 아님, 체인 아님).

남은 것은 **기본값** 하나다. 소유자는 비움(참)을 원했고, antigravity는 유지를, 검증자는 비움을 조건부로 받았다. 편집자 권고는 **유지(P4 그대로)**다. 이유: (1) 순수 JSON Schema(`if/then`)만 쓴 스키마에서 `&` 없이 폼이 값을 지우는 것은 축 4항("조각의 켜짐·꺼짐은 값을 지우지 않는다")과 축 6항("값 변경은 전량 `&`로")을 소유자가 스스로 뒤집는 것이다. (2) 잠깐 전환의 입력 소실은 오늘 대비 회귀다. (3) 방출에서 빼는 것은 이미 기본이라 "빼는 게 기본"은 방출 층에서 이미 참이다. 비움을 기본으로 하려면 축 4항과 P1′ 끝 문장을 개정한다고 선언해야 한다. 소유자가 정한다(13라운드 2).

## 4. 13라운드로 올린 판단 넷

1. 잠금 규칙: 가(하위 트리 OR, `false`는 풀지 않음) / 나(루트 키만 참일 때 OR) / 다(루트 글로벌 제거).
2. 나감 비움의 기본값: 유지(P4) / 비움(축 4항·P1′ 개정 선언).
3. 폼 전용 키의 접두: `&options`·`&FormTypeInput`처럼 전부 `&` / 표현 키는 접두 없이(제거 목록 열거). 검증자 사실 하나가 여기 얹힌다: 맨 키 `disabled`·`visible`·`active`는 표준이 아니므로 투명한 JSON Schema를 따르면 `&` 전용으로 옮겨야 한다.
4. 같은 대상에 종류가 다른 규칙: 답 9의 종류 순위(`unsetValue` > `derived` > `injectTo`, 같은 종류 안은 문서 순서) / 12라운드 답의 문서 순서(종류 무관, 나중 선언 승).

## 5. 이주 항목으로 새로 확인된 것(오늘 코드와 다른 곳)

- 루트 키 다섯(`readOnly`·`disabled`·`active`·`visible`·`pristine`)의 특수 처리와 README "Priority System".
- 로컬 층의 순위 사슬(노드 `readOnly: false`가 `&readOnly`를 이김) → OR.
- 꺼질 때 원본 비움과 로드 스냅숏 복원(기본값 결정에 따라).
- `required`의 가상 이름 재작성.
- `const`·`enum` 자동 감지.
- `&clearValue`·`&pristine`의 이름.
