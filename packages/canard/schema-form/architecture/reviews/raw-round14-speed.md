# 14라운드 — 고속성 축 검증 원문 (로컬 verifier, opus)

2026-09-24. 편집자는 고치지 않았다. 판정과 반영은 `round-14-values-check.md`.

고속성 축 검증 결과는 조건부 통과입니다. 키 입력 한 번(토글 없음)의 비용은 조상 경로의 게이트 수에 묶입니다. 그러나 한 정착의 비용 상한을 정하는 문장 넷이 비어 있어 "스키마 크기에 비례 이상으로 커지지 않는다"를 문서만으로 보장하지 못합니다. 발견 1–3을 닫지 않고 슬라이스 2(코어 루프)에 들어가면 실패로 봅니다.

변수: N 형상 노드 수, D 쓰기 노드의 조상 수, I_h·A_h 호스트 h의 `if`·`&active` 게이트 수, C_h 자식 수, S_h 호스트 바퀴(≤ I_h+A_h+1), T 바퀴 안 토글 수, K 값 규칙 수, R_d 파생 라운드(≤25), R_t 전이 라운드.

질문 3의 어림. 필드 200, 루트 호스트에 `if` 조각 20과 노드 게이트 10을 가정하면 S 상한은 31입니다. 게이트 1회 비용은 AJV 약 40 ns, 인터프리터형 약 2.9 µs입니다(adr/0009:48-49의 200개 측정을 나눈 값).
- 토글 없는 키 입력: 검증기 호출 20회. AJV 0.8 µs, 인터프리터형 58 µs.
- 토글 있는 키 입력(2–3라운드 × 2바퀴): 80–120회. AJV 5 µs, 인터프리터형 350 µs. 여기에 토글당 200자식 재구성이 더해집니다.
- 예산 끝까지, 계산 한 번: 31바퀴 × 30게이트 = 930 평가, 그중 검증기 호출 620회.
- 라운드를 더하는 경우(25+31=56): 34,720회. AJV 1.4 ms, 인터프리터형 100 ms.
- 라운드를 곱하는 경우(25×31=775): 480,500회. AJV 19 ms, 인터프리터형 1.4 s.
- 둘 중 무엇인지 문서가 정하지 않았습니다(03:196). 원본 B 재계산 1회와 깊이 방향 곱은 따로 더해집니다.

질문 4(형상 전환). 조각은 정적으로 열거되고 모든 조각의 노드를 미리 만듭니다(adr/0005:45). 그래서 전환은 객체 재생성이 아니라 다음 넷입니다. 활성 표시 전환, 생긴 노드의 채움, 호스트 합성 C_h, 유효 스키마 병합(덧씌움 집합별 메모, adr/0005:106)과 배달. 노드 공유는 오늘의 "나가는 노드 reset → fallback 복원 → 타입 검사"(adr/0005:119)를 없앱니다. 공유되지 않는 경우는 셋입니다. 같은 이름·다른 종류(종류별 노드), 다른 이름, 통째로 교체한 배열 아이템(R13 미정, 03:190). 메모리와 마운트 비용은 켜진 조각이 아니라 모든 조각의 선언 수에 비례합니다.

질문 5(현행 대비). 현행 키 입력 비용을 (상호작용 − 렌더)/10으로 계산하면 flat-50 0.26 ms, flat-500 2.72 ms, nested-d5 6.74 ms입니다. React를 포함한 값이며 필드 수에 선형입니다. 현행도 G6을 지키지 못합니다. 새 설계가 더 느려질 수 있는 곳은 다섯입니다. 발견 1(전체 순회), 발견 2(구독 기반 의존 추적의 상실), 발견 5(디바운스 상실), 발견 7(조건부 폼 생성 1.7배), 게이트 없는 oneOf의 전 분기 렌더입니다. ADR 0009에는 예산 수치가 없습니다. ADR 0007:120-128의 비용 표는 노드 환경의 작업 루프 하니스 측정이라 `benchmark-form` 기준선과 이어지지 않습니다.

질문 6(렌더 층). 구독 단위는 노드의 `revision(mask)`이고, 커밋 뒤 동기 1파동, 배달 집합, `batch(fn)`가 적혀 있습니다(02:178, adr/0008:27-35,54-71). 10,000노드 동기 통지는 128 ms입니다(adr/0008:52). 유효 스키마 변경 통지의 이벤트 타입과 구독 표면은 미정입니다(02:316). React 바인딩은 ADR 0011의 제안 단계입니다.
