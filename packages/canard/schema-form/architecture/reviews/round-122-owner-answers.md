# 122라운드 — Vincent의 답 (폼 전체 단위의 변화에 폼 전체가 렌더되는 것은 자명하다 — 전체가 바뀌는 것이므로; Q121은 할 일이 아니며, 119라운드의 "전역 문맥 변화에 자식 필드가 렌더되지 않음" 단언은 "필드당 한 번, 리마운트 없음"으로 좁힌다)

2026-10-08. 121라운드가 소유자에게 올린 Q121(showError·context·readOnly 같은 전역 문맥 변화에 모든 필드가 렌더되는 것을 7단계에서 고칠지 개선 단계로 미룰지)에 소유자가 답했다.

Q121은 고칠 일도 미룰 일도 아니다 — 폼 전체 단위의 변화(readOnly 전환은 모든 입력의 화면이 바뀜, context 교체는 어느 입력이 어느 값을 읽는지 폼이 모름, showError는 오류 유무가 필드마다의 상태라 필드마다 판단함)에 폼 전체가 한 번 렌더되는 것은 두 판이 공유하는 정상 동작이고, 쓰기 경로가 아닌 드문 사건이라 성능 목표의 대상이 아니다. 119라운드의 단언 "전역 문맥 변화에 자식 필드가 렌더되지 않음"은 원장 관리자가 너무 넓게 잡은 것이므로 "전역 문맥 변화의 렌더는 필드당 한 번이며 리마운트는 없음"으로 좁힌다 — 감사의 계수(새 판 필드당 10·10·5회)는 컴포넌트 계층을 합친 수이므로 F2 뒤 필드당 컴포넌트 수로 나누어 한 번임을 확인한다. 필드마다 selector 스냅샷을 두거나 문맥을 노드 이벤트로 넘기는 설계는 열지 않는다. |
