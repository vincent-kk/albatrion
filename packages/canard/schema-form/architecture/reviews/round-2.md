## 2. 측정 — 작업 루프 프로토타입 대 현재 구현

환경: Node v24.20.0, darwin arm64(Apple M1 Max), ajv 8.17.1. 경우마다 새 프로세스. **같은 날 오후에 두 드라이버를 그대로 재실행해 15% 안에서 재현됐다**(`../spikes/work-loop/REPORT.txt` 끝의 RE-RUN 절. 예외는 매크로태스크 바닥에 묶인 현재 구현의 unbatched 1,352 ms, +21%). 첫 측정 뒤 스파이크의 정정 셋: 현재 구현의 지연 합성은 **한 단계 위**까지만 옛 값을 돌려준다(아래 표의 "두 단계 이상"은 과장이다), 배칭의 이득은 재설계의 성과가 아니라 현재 구현의 매크로태스크 바닥 때문이다, Node 24와 26은 3% 안에서 일치한다. **프로토타입에는 검증·이벤트·React·null 계약·파싱·배열 identity가 없으므로 모든 수치는 하한이다.** 전문은 `../spikes/work-loop/REPORT.txt`.

| dirty의 추적 | 노드별 dirty 자식 **목록** — 3.23 µs | 자식의 dirty **플래그** 스캔 — 55.5 µs (17배, 아이템 10,000개) |
| 가드 건너뛰기 | 역색인 — 2.42 µs | 없음 — 11.98 µs |

그 밖에 드러난 것:

- **V8의 속성 수 절벽.** 한 객체의 자기 속성이 1,020개면 복사·패치가 1.02 µs, 1,021개면 141 µs(138배). 필드 1,100개의 평면 폼은 키 입력당 153 µs다. 폼의 크기가 아니라 **한 객체의 키 수**에 대한 한계이고 현재 구현에도 같게 걸린다. JSC·SpiderMonkey는 재지 않았다.
- **`omitEmpty`로 키를 빼는 것이 비싸다.** `delete`가 객체를 사전 모드로 떨어뜨린다. 필드를 비우거나 채우는 키 입력이 비싼 키 입력이다.
- 패스 수는 가드 입력이 안 움직이면 1, 움직이면 2, 조각이 뒤집히면 3이었다.

## 4. 새 지적

"출처"의 약어: C=codex, L=claude, A=antigravity, RC=계약 레드팀, RL=작업 루프 레드팀, SP=스파이크. 둘 이상이 독립적으로 도달한 것에 ★.

### 수용 — 고쳐 쓴 설계가 틀렸거나 비어 있다

| # | 지적 | 출처 | 검증 |
| - | ---- | ---- | ---- |
| S1 | **스키마를 변형 없이 검증기에 넘기면 기존의 보호가 사라진다.** FE 키의 값에 순환하거나 깊은 객체가 있으면(`FormTypeInputProps`에 자기 참조, 개발 빌드의 React 엘리먼트 — `_owner` 순환) `ajv.compile`이 `RangeError: Maximum call stack size exceeded`로 죽는다. `validateSchema: false`에서도 같다. 현재는 `ValidationManager.ts:200`이 컴파일 전에 그 키들을 지운다. "기본은 제거하지 않는다"(ADR 0001·0003의 1라운드 개정)는 이 보호를 없앤다. 평범한 `&` 문자열과 함수·클래스인 `FormTypeInput`은 문제없이 컴파일된다 | RC | 실행 |
| S2 ★ | **판별 필드가 자기 존재를 스스로 정한다 — 교착.** 판별 프로퍼티 `k`가 분기에서만 선언되면(pydantic·OpenAPI가 내는 흔한 모양) 분기는 `k`가 방출 값에 있어야 켜지고, `k`의 노드는 분기가 켜져야 활성이다. 빈 폼에는 판별식을 고를 필드가 없고, 로드한 `{kind:'cat', …}`은 첫 방출을 무엇으로 두느냐에 따라 통째로 빠진다. `anyOf` 예에서는 `{}`가 검증을 통과하므로 폼이 필드 0개를 그리고 valid를 보고한다 | C, L, RC | C·L·RC 모두 실행 |
| S3 ★ | **작업 루프의 패스 구조가 방출 값을 상태의 함수로 만들지 못한다.** begin(위 → 아래)에서 가드를 평가하면 호스트의 방출 값은 아직 complete(아래 → 위) 전이다 — 첫 패스의 가드는 직전 커밋을 본다. (a) 값을 바꾸는 쓰기는 모두 최소 2패스, 조각이 뒤집히면 3패스. (b) 한 패스의 모든 가드가 같은 옛 값을 보고 동시에 갱신되므로 결과가 "직전 커밋에서 출발한 반복이 처음 닿는 곳"이 된다. 같은 원본 `{a:'x', b:'y'}`가 이력에 따라 `{a}`, `{b}`, 상한 초과로 갈린다(L 실행). (c) `if required p0 → p1 default`, `if required p1 → p2 default` 같은 **정상적인** 의존 체인은 단계마다 한 패스를 먹는다 — 30단이면 32패스, 순환이 아닌데 상한에 걸린다(C 모델 실행). (d) 위쪽의 가드가 멀리 있는 서브트리를 켜면 그 서브트리는 dirty 표시가 없어 건너뛰어진다 — dirty 집합이 패스 도중에 자라야 한다(RL). (e) `&` 식과 `injectTo`가 버려질 중간 방출에 대해 실행된다(RL) | C, L, A, RL | L·C 실행, SP가 패스 수 실측 |
| S4 ★ | **판별식의 식별이 BE의 흔한 모양을 놓친다.** (a) 분기가 `allOf: [{$ref: Base}, {properties: {kind: {const}}}]`면 분기 최상위에 `properties`가 없어 수동 선택으로 떨어진다. (b) `anyOf: [{$ref: A}, {$ref: B}, {type: 'null'}]`는 null 분기가 어떤 프로퍼티도 제약하지 않아 판별식을 잃는다 — null 분기를 먼저 벗기고 안쪽을 다시 식별해야 한다. (c) OpenAPI 3.0 상속형은 분기에 `const`가 없고 값이 `discriminator.mapping`에만 있다. 표준 검증기로는 **어떤 값도 통과하지 못한다**(두 분기가 다 맞아 `oneOf`가 기각). Ajv의 `discriminator: true`는 mapping을 지원하지 않아 컴파일이 throw한다. G2("BE 스키마를 그대로")가 이 부류에서 조용히 깨진다 | L, RC, C, A | L·RC 실행 |
| S5 ★ | **금지하는 조각이 순환을 만든다.** `if: {required: ['a']}, then: {properties: {a: false}}`는 "a가 있으면 안 된다"는 의미 있는 스키마인데, 가드가 방출 값을 보므로 a 있음 → 가드 참 → a 제외 → 가드 거짓 → a 있음 … 고정점이 없다. 기본값 없이도, 입력하는 순간. 옳은 동작은 a를 보이고 검증기의 에러를 붙이는 것이다 | RC, C, A, L | RC·C 실행 |
| S6 ★ | **로드한 뒤 손대지 않고 저장하면 값이 바뀐다.** 다섯 곳이 동시에 움직인다(L): 미선언 키가 빠진다, `''`가 `omitEmpty`로 빠져 `required` 위반, `{}`도 같다, 꺼진 조각의 키가 빠진다, 첫 활성의 기본값이 추가된다. 가장 작은 예(RC): 스키마 `{"type":"object"}`에 값 `{"a":1}` → `{}`를 방출하고 둘 다 검증을 통과해 아무것도 드러나지 않는다. 더 나쁜 예: 어느 분기도 통과하지 않는 **무효한** 서버 레코드가, 동점 폴백으로 분기 0이 골라지면서 데이터를 잃고 **유효해진다** — 사용자 행위도 알림도 없이. `additionalProperties: <스키마>`와 `patternProperties`는 노드 트리가 표현하지 못하는 열린 확장점이다 | L, RC, C, A | L·RC 실행 |
| S7 ★ | **null 계약과 "null 아래도 원본 유지"가 정면으로 어긋난다.** 현재 계약의 S4는 부모가 null이 되면 자식을 blank로 **되돌린다** — `{note:'typed', keep:'K1'}`에서 `setValue(null)` 뒤에 `note`는 스키마 기본값 `'D'`, `keep`은 `undefined`이고, 뒤의 쓰기는 `{note:'Z'}`만 방출한다. `K1`은 돌아오지 않는다(RL 실행). ADR 0006대로면 돌아온다. `resetSubtree()`는 세 번째 값(초기값)을 낸다 — 원본 칸 하나로는 셋을 담지 못한다. null 노드의 가드는 방출 값 `null`이 아니라 blank 객체를 봐야 S4의 "같은 상태"가 성립한다 | RL, C, L, A | RL 실행 |
| S8 ★ | **호스트가 객체가 아니면 판별식 가드가 전부 참이다.** `properties`와 `required`는 객체에만 걸리는 단언이어서 `null`과 `undefined`에서 통과한다 — `required: [k]` 보강은 `{}`만 고친다(L 실행). 빈 중첩 객체는 `omitEmpty`로 생략돼 `undefined`이므로, 빈 중첩 union에서 모든 분기가 동시에 켜진다. 같은 이름에 종류가 다르면 ADR 0005의 "런타임 충돌"이 **빈 폼마다** 뜬다 | L | 실행 |
| S9 ★ | **"노드의 메모는 스냅숏의 해당 부분과 같은 참조"는 정제가 있는 곳에서 거짓이다.** `omitTrailing`: 배열 노드는 `["a", null, null]`인데 부모는 `["a"]`를 든다. `omitEmpty`: 객체 노드는 `{}`인데 스냅숏에는 그 키가 없다. `node.value`와 `UpdateValue`의 payload는 계약상 원본이다(`AbstractNode/DETAIL.md:8`). 자식이 있는 노드에는 **투영 전의 로컬 메모**가 따로 필요하고, 부모가 자기 칸을 투영한다. 가드의 입력도 그 로컬 메모다(S8과 같은 해법) | RL, L, C | RL 실행 |
| S10 ★ | 루트 디스패처: "같은 파동의 리스너는 같은 스냅숏을 본다"와 "배달 도중의 쓰기는 즉시 정착"이 양립하지 않는다. 뒤쪽 리스너가 `node.value`를 읽으면 새 커밋을 본다. 읽힌 값이 `1 → 2 → 2`였다(C 모델 실행). 동기 `setValue`를 유지하려면 같은 스냅숏의 보장을 **payload에 한정**해야 한다 | C, L, RL | C 모델 실행 |

## 6. 책임 경계 교차검증 (ADR 0013) — codex

claude의 답은 아직 오지 않았다. 아래는 codex 하나의 의견이고 아직 다른 리뷰어와 맞춰 보지 않았다.

**핵심 권고: 비활성화와 전체 교체를 구분하라.**

> 비활성화는 원본을 보존하고 방출에서만 뺀다. 반면 **전체 값 교체, 명시적 삭제, reset은 원본에도 적용되는 명령이다.**

1차 제안("절대 제거하지 않는다")의 허점을 짚었다: 같은 Form 인스턴스에 레코드 A를 로드해 꺼진 분기에 `b: 'SECRET'`이 잠복한 뒤, **다른 레코드** `{kind:'a', a:'NEW'}`를 `setValue`하고 분기를 `b`로 바꾸면 `SECRET`이 나온다. 새 전체 값에 없는 `b`는 지워져야 한다 — 그것은 비활성화에 따른 삭제가 아니라 소비자가 요청한 전체 교체다. 소유자의 직관("보이지 않는 필드는 제거")과 1차 제안 사이의 제3의 입장이다:

```
setValue(V)      전체 교체 — 활성·비활성·extra를 포함해 대상의 원본을 V로 대체
(부분 쓰기)      지정한 부분만 바꾸고 나머지 원본은 유지
활성 집합의 변경  원본을 바꾸지 않는다
```

그 밖의 요점:

- `getValue(setValue(V)) = V`는 어느 정책에서도 성립하지 않는다(꺼진 분기의 값은 방출에서 빠진다). 성립하는 계약은 "`getValue()` = 현재 원본과 활성 집합의 투영"이다. `setValue(getValue())`는 잠복한 필드를 지우므로 no-op이 아니다.
- `reset()`은 초기 방출이 아니라 **초기 편집 상태 전체**를 되살린다. 민감한 값의 폐기 수단이 아니다 — 그것은 별도의 수명주기다.
- 판별식이 어느 분기와도 맞지 않는 값을 주입하면 임의로 첫 분기를 고르거나 판별식을 고치지 말고, 원본을 보존하고 기본 필드만 방출하며 `enum`·`oneOf` 에러를 보인다.
- **자식으로만 값을 합성하는 object 노드는 주입된 `"broken"`이나 `17`을 어디에 두는가.** "그대로 받아 에러를 보인다"를 구현하려면 노드가 잘못된 종류의 값을 들 수 있어야 한다 — 예컨대 그 노드가 일시적으로 터미널처럼 값을 들고 자식은 잠복한다. ADR 0006에 이 상태가 적혀야 한다.
- `preserveDefaultValue`: (a) "첫 의도된 쓰기까지 원본 그대로"는 권하지 않는다 — 비활성 제외와 바로 충돌하고, `a`만 고쳤는데 무관한 `b`가 방출에서 사라지며, 무엇이 "첫 의도된 쓰기"인지에 결과가 달렸다. (b)는 세 부분으로 나눠 봐야 한다 — 로드한 값에 없는 키에 기본값을 넣지 않는 것은 **일반 로드 계약**으로, extra의 보존은 **모든 쓰기의 기본 계약**으로 삼고, "손대지 않은 값에는 omit을 건너뛴다"만이 이력에 의존하는 별도의 정책이다. 앞의 둘을 기본으로 하면 옵션의 대부분이 필요 없어진다.
- ADR 0007의 "첫 활성에 기본값을 넣는다, complete에서 omit을 적용한다"와 ADR 0013의 "예외는 하나"를 함께 확정할 수 없다. omit을 남기려면 "원본을 건드리지 않는, 작성자가 고른 방출 정책"으로 규정하고 "유일한 예외"라는 문구를 고쳐야 한다.

**현재 core가 값을 바꾸는 곳의 전수 조사**(전부 `file:line`으로 확인됨, 원문은 세션 `169eccef…`)와 새 원칙에서의 분류:

| 분류 | 항목 |
| ---- | ---- |
| 입력 컴포넌트로 옮긴다 | 숫자·불리언·문자열 파서의 강제 변환(`parseNumber`는 `"1e3"` → 13, `"12kg"` → 12, integer에서 `1.9` → 1), blur의 `trim`, 빈 배열을 `minItems`까지 채우기, `maxItems`를 넘는 `push`의 차단, 아이템 생성 시의 기본값 주입 |
| 버린다 | 비객체 → `{}`·비배열 → `[]`, nullable이 아닌 객체·배열의 `null` → `{}`·`[]`(S7 — `type` 에러가 사라진다), `Normalize`의 미선언 키 제거, reset 때의 `minItems` 재충전, 아이템 스키마가 없을 때의 `push` 거부, 터미널 `push(input ?? default)`의 `null` 치환, 로드 경로의 기본값 주입, 루트 callback의 `undefined` → `{}`, 검증 전용 마커 |
| 방출에서만 적용한다 | 조건부 필드의 필터, `oneOf`/`anyOf`의 허용 키 필터, `active` 전이의 reset, 분기 전환의 reset과 복원, `omitEmpty`·`omitTrailing` |
| 남긴다 (작성자·소비자가 명시한 쓰기) | `derived`, `injectTo`, 명시적 overwrite/merge, 배열의 `update`/`remove`/`pop`/`clear`, `resetSubtree`, virtual의 길이 검사 |

## 7. 작업 루프의 고쳐 쓸 방향 (제안, 미반영)

S3·S5·S8·S9를 함께 푸는 방향으로 claude와 codex의 처방이 겹친다.

1. **가드를 begin이 아니라 호스트의 complete에서 평가한다.** 자식들의 방출 값이 먼저 나온 뒤에, 그 호스트의 조각을 **선언 순서로 하나씩 평가하고 결과를 즉시 반영한다.** 첫 패스의 헛평가가 사라지고, 정상적인 의존 체인(`p0 → p1 → p2`)이 한 번에 풀린다.
2. **출발점을 고정한다 — 조건부 조각이 전부 꺼진 상태.** 직전 커밋의 활성 집합에서 출발하지 않는다. 그러면 방출 값이 (스키마, 노드의 원본)의 **함수**가 되고, 같은 원본은 어떤 이력에서도 같은 결과를 낸다. ADR 0007의 "선언 순서에 대해 결정적"이 비로소 참이 된다.
3. **가드의 입력은 호스트의 로컬 메모다** — null·생략 투영을 거치기 **전**의 객체 방출. 부모가 자기 칸을 투영한다. null 노드는 blank 로컬 메모로 평가한다.
4. **금지하는 조각은 되먹임에 넣지 않는다.** 금지의 판정은 제외하기 전의 투영에 대해 한다.
5. **판별 프로퍼티는 union이 소유한다.** 분기의 활성과 무관하게 존재하고, 선택지는 분기 값의 합집합이다. ADR 0002의 존재 규칙에 대한 명시적 예외다.
6. 구현의 전제(스파이크): 이전 메모를 복사하고 바뀐 키만 패치한다, 노드별 dirty 자식 목록을 둔다, 키를 뺄 때 `delete`를 쓰지 않는다, dirty 집합은 패스 도중에 자란다.
7. 상한은 "순환의 확정"이 아니라 **계산 예산의 초과**로 보고한다.

소유자의 확인이 필요한 부분: 2번은 상한에 걸렸을 때 "직전 커밋의 활성 집합으로 고정한다"(§5)와 맞물린다 — 출발점이 고정이면 상한 뒤에 둘 활성 집합을 다시 정해야 한다.
