# 14라운드 — 투명성 축 검증 원문 (로컬 verifier, opus)

2026-09-24. 편집자는 고치지 않았다. 판정과 반영은 `round-14-values-check.md`.

투명성 축 검증 결과는 "실패"입니다. 문서만 읽고 결과를 예측할 수는 대체로 있으나, 자동 쓰기 다섯의 출처가 런타임에 전혀 드러나지 않습니다. 또 유일한 런타임 신호인 `diagnostics`는 예산 초과로 잃은 자동 쓰기가 트리에 남아 있는데도 다음 정착에서 `stable`로 돌아갑니다.

질문별 요약
- 질문 1(자동 쓰기가 일어났음을 아는 법): 이벤트·로그·경고 어느 것도 약속되어 있지 않습니다. 간접 관측은 둘뿐입니다. 하나는 값 변화의 `UpdateValue`(출처 없음)이고, 다른 하나는 나감에 대한 활성 변화 배달입니다.
- 질문 3(분류표의 덮음): 본문에는 있으나 분류표에 없는 것은 발견 3·4·5입니다. 분류표에는 있으나 발생 지점이 없는 것은 발견 8입니다. 누구 잘못의 오표기는 발견 6, 표면 누락은 발견 7입니다.
- 질문 4(정착 한 번의 재구성): 현재 설계로는 재구성할 수 없습니다. 최소로 필요한 것은 개발 모드 정착 기록 하나입니다. 담을 것은 진입(공개 API, 옵션 비트), 라운드별 {단계(파생/전이), 규칙 종류, 원천 경로, 대상 경로, 이전 값, 이후 값, 결과(적용 / 누구에게 짐 / `undefined`라 후보 아님 / 억제 / 최종 형상 밖이라 철회)}, 그리고 예산 초과 시 마지막 라운드에 쓴 규칙 목록입니다.
- 질문 5(프로덕션에서 사라지는 청사진 경고): 사용자 데이터 손실로 직접 이어지는 것은 찾지 못했습니다. 선언되지 않은 키는 `extras`로 보존되고, 기본 정책이 원본을 남기기 때문입니다. 간접 경로는 둘입니다. 리프가 아닌 노드의 표준 `readOnly`가 무효이면 작성자가 잠갔다고 믿는 값을 사용자가 고칠 수 있습니다(무결성 문제). 노드 공유 충돌과 `unsetOnInactive`가 겹치면 진 종류의 노드가 나감으로 비워질 수 있습니다(추정). 손실로 이어지는 침묵은 정착 쪽에 있습니다(발견 1·3·5, 로드 때의 `&unsetValue`).

확인한 것
- 원장, ADR 0005·0006·0007·0008·0010·0013 전문과 소유자 답 10·12·13라운드 원문 전문을 읽었습니다.
- 02는 개발 모드 경고 절과 공개 표면 절을, 07은 경고·예산·진단 관련 행을 검색으로 읽었습니다.
- 현행 `src`의 throw·`console.error`·`warnDevelopmentIssue` 발생 지점을 전수 검색했고, 경고 코드가 다섯임을 확인했습니다.
- `throwOnBudgetExceeded`가 ADR 0008과 02에 없음을 검색으로 확인했습니다.
- "터미널의 빈 자식"의 정의가 문서와 코드 어디에도 없음을 검색으로 확인했습니다.
- 확인하지 못한 것: 발견 1은 문서 규칙의 추적으로 판정했고 프로토타입으로 재현하지 않았습니다. 07은 전문을 정독하지 않았고, 다른 라운드의 도출 문서는 열지 않았습니다.
- 브리프 밖의 결정: 발견 1의 표면, 발견 2의 공개 payload, 발견 5의 처리 방식은 소유자 판단이 필요해 추측하지 않았습니다.
