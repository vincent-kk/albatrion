# 11라운드 — 착수 전 건전성·견고성 평가 (편집자 판정)

2026-09-23. 소유자의 물음: "다 정리되었나? 전체 설계의 건전성과 견고성을 다시 평가하라. 이제 곧 코드 개발 단계로 들어가려고 한다." 평가는 둘을 독립으로 돌리고 편집자가 합쳤다.

- 검증자(claude) — `raw-round11-readiness-claude.md`. 기록 전체(원장·02·07·ADR 전부·README·HANDOFF)를 대조하고 시나리오 여섯을 손으로 전개했으며 검증기 판정 둘은 ajv 8로 실행했다.
- antigravity — `raw-round11-readiness-antigravity.md`. 바깥 시선의 위험 평가. 코드는 보지 않았다.

## 1. 판정

| 물음 | 답 |
| --- | --- |
| 건전성(원리와 규칙이 서로 맞는가) | **좋다.** 원장·02·5차 ADR 일곱은 큰 줄기에서 하나다. 남은 어긋남은 문장 단위이며 원리에서 답이 나온다 |
| 견고성(규칙만으로 결과가 하나로 정해지는가) | **대체로 그렇다.** 시나리오 여섯 가운데 넷은 정해진다. 둘은 원장의 빈틈(로드 시 `&derived` 발화, 게이트 없는 분기 안 `then`의 교차)에 걸렸고, 그 빈틈은 도출로 닫힌다. 검증자가 새로 찾은 빈틈 다섯(같은 순위끼리의 순서, 형상에 없는 노드의 규칙, 조각 식의 경로 기준, `$ref` 재귀 종료, 에지의 값 동등)도 모두 편집자 도출로 닫을 수 있다 |
| 정리 여부 | **아직 아니다.** 5차로 고치지 않은 ADR 0001·0004·0009·0011·0012와 README·HANDOFF에 사라진 개념(`selection`, 참조 그룹·`&virtual`, 역색인, begin/complete, 분기 선택기, `if`의 `required` 경고)이 스무 곳 넘게 남았다. 02와 ADR 0003은 미정인 규칙 둘(Form 속성의 `false`, `virtual` 제거)을 확정처럼 적었다 |
| 착수 | **조건부.** 슬라이스 1(청사진 분석)은 소유자 확인 셋과 원장 보강 넷이 끝나면 들어간다. 슬라이스 2는 원장 §6의 `&active` 평가 순서와 생성 에지 규칙이 더 필요하다 |

## 2. antigravity 시나리오의 손 전개 (편집자)

antigravity의 위험 1·3·5 시나리오를 원장 규칙으로 다시 전개했다.

- **시나리오 2(핑퐁 `a = b+1`, `b = a+1`).** 보고대로 25라운드까지 진동해 원본 B를 커밋한다. 이것은 결함이 아니라 소유자 답 4가 정한 동작이다("루프 가능성을 막지 않고 상한에서 오류"). 원본 B를 커밋한 뒤에는 `a`·`b`가 바뀌지 않는 한 에지가 없으므로 "다른 입력란을 건드릴 때마다 재발"은 성립하지 않는다.
- **시나리오 3(경합 패배의 조용한 정지).** 성립하지 않는다. 보고는 `result`의 `&derived`가 에지 없이 매 라운드 평가된다고 가정했다. 원장에서 `&derived`는 원천(`isOverride`)의 에지에서만 후보가 되므로, `sourceInput` 변화 라운드에는 `&injectTo`만 후보이고 이긴다. 다만 이 전개에서 빈틈 하나가 드러났다: `&derived`가 `undefined`를 돌려줄 때의 뜻이 원장에 없었다. "쓰지 않는다(없음으로 만드는 장치는 `&clearValue` 하나, G4)"로 원장 §3에 넣었다.
- **시나리오 1(꺼질 때 지움 + `&default` + `&injectTo`).** 진동하지 않는다. 다시 켜질 때 채움이 `cardNumber`를 `'0000-0000'`으로 쓰고 그 `&injectTo`가 `paymentType`에 `'card'`를 쓰지만 이미 `'card'`라 변화가 없다. "호스트 바퀴와 전이 예산이 교대로 소진"은 추정이며 재현되지 않는다. 다만 "꺼질 때 지움"의 장치 자체가 미정이라는 지적은 맞다(11라운드 §4의 3).
- **P4 위반 주장.** 기각한다(`round-11-owner-answers-check.md` §3). 작성자가 예약 층에 적은 규칙의 쓰기는 P2의 쓰기다.
- **위험 7(`onChange` 중첩 초과 시 래퍼가 최종 값을 놓침).** 설계가 받아들인 대가다. 26번째 `onChange`를 부르면 중첩이 끝나지 않고, 쓰기를 거부하면 P2에 걸린다. 개발 모드가 throw하므로 작성자가 고친다.

## 3. 검증자 발견에 대한 편집자 판정

| 검증자 번호 | 판정 | 처리 |
| --- | --- | --- |
| 1 같은 순위끼리 | 도출. 같은 순위면 원천 노드의 문서 순서(통지 순서와 같은 위→아래)에서 나중이 이긴다("뒤가 앞을 덮는다"와 한 방향). 같은 종류 충돌도 개발 모드 경고 | 원장 §4에 넣는다 |
| 2 형상에 없는 노드의 규칙 | 도출(P4). 형상에 없는 노드의 규칙은 평가하지 않고 그동안의 원천 변화는 에지가 아니다. 다시 생기면 거짓→참으로 본다 | 원장 §3에 넣는다 |
| 3 `virtual`과 검증기 입력 | **소유자 확인.** 오늘 코드는 `required`의 가상 이름을 실제 자식 이름으로 펼쳐 검증기에 넘긴다. 이는 "판정은 작성된 스키마로"(P1, ADR 0001)와 부딪히고, 답 4의 전제("유효성 검증에 영향 없다")와도 다르다 | 11라운드 확인 목록에 11번으로 올린다 |
| 4 게이트 없는 분기 안 `then`의 교차 | 도출. 게이트 없는 분기는 선언 문맥이므로 안의 `then`도 교차하지 않는다 | ADR 0005:68을 좁힌다 |
| 5 Form 속성 `true` 대 루트 `false` | 확인 목록 1번에 함께 묻는다. 권고: Form 속성은 참일 때만 덮으므로 `true`가 이긴다 | 02·ADR 0003의 확정 서술을 단서로 고친다 |
| 6 경고 목록의 경계 | 도출. 원장 §5를 전체 열거로 닫는다(넷 + 공집합 `enum`, 터미널 빈 자식, 검증기 미등록) | 원장 §5, 02, ADR 0001 |
| 7 조각 식의 경로 기준 | 도출. 조각 수준 식의 기준은 그 조각이 선언한 노드의 자리(호스트의 직계 자식) | 원장 §4에 한 문장 |
| 8 `$ref` 재귀 종료, 값 union, `dependentSchemas` | 설계 항목. 슬라이스 1 전에 정한다 | 원장 §6에 올린다 |
| 9 로드 시 `&derived` 발화 | 도출(로드는 새 수명, 답 6과 같은 읽기). 발화한다 | 원장 §3에 넣는다 |
| 10 에지의 값 동등 | 설계 항목. 슬라이스 3 전 | 원장 §6 |
| 11 `&children` 값 키 목록 | 문서 통일 | ADR 0002:199, 07, 02 |
| 12–18 | 낮음. 12는 "분기에 `else: false`인 `if`가 있으면"으로 고친다. 13·14·15·17은 §6에 올린다. 16·18은 문장 수정 | 원장·07·ADR |
| 시나리오 1·5의 검증기 기각 | 설계대로다. `&active`만 있는 분기는 검증기에게 보이지 않으므로, 작성자는 검증기도 가를 수 있게 분기에 `const`+`required`를 두어야 한다(생성기 스키마는 그렇게 나온다). 컨벤션으로 ADR 0010에 적는다. 폼은 검사하지 않는다(답 23) | ADR 0010 |

## 4. 착수 전에 남은 일

**소유자 확인(슬라이스 1을 막는 것).**
1. `round-11-owner-answers-check.md` §4의 2 — `&discriminator` 명시 필수, 자동 감지 삭제(OpenAPI `discriminator.propertyName`을 인정할지 포함).
2. 같은 문서 §4에 새로 올리는 11 — `virtual`: 오늘의 `required` 재작성을 버리고 검증기에는 작성된 스키마를 그대로 넘기는가(P1). `virtualRequired`의 처리.
3. 07 §3–4의 통과(슬라이스 0의 조건, 이전부터 남은 것).
4. ADR 0005 §3 — 같은 이름·다른 종류 충돌은 에러가 아니라 경고(결정 다).

나머지 확인 항목(§4의 1·3–10)은 슬라이스 3·6의 몫이며 착수를 막지 않는다. 3(꺼질 때 값 정책)은 슬라이스 3(파생 단계) 전에 답이 있어야 한다.
