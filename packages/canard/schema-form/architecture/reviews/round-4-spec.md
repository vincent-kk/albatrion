# 4라운드 공격 대상 — 작업 루프 3.1판, 이벤트 시스템, 계승 제약

상태: 검토 완료(4라운드). 판정은 [`round-4.md`](./round-4.md) §3, 살아남은 개정은 그 문서 §5(F1–F28)이며 아래 §E에 같은 표를 옮겼다. **원문과 §E가 충돌하면 §E가 우선한다.** 원문은 공격받은 그대로 남긴다.

용어: **원본(raw)**, **로컬(local)** = 활성 자식의 emit 합성(투영 전), **방출(emit)** = local의 투영, **호스트** = 자식이 있는 object 노드, **조각** = 가드가 켜고 끄는 선언 묶음, **정착** = 표시부터 커밋까지 한 번.

## A. 작업 루프 3.1판

### A1. 상태와 계산 결과

| 칸 | 종류 | 내용 |
| -- | ---- | ---- |
| `raw` | 상태 | 리프·터미널 노드의 값. 호스트는 비객체 값(`null`, `17`)이 왔을 때만 든다 |
| `selection` | 상태 | 판별식이 없는 union 호스트의 수동 선택. 판별식이 있으면 칸이 없다 |
| `extras` | 상태 | 호스트가 받은, 어떤 조각에도 선언되지 않은 키와 값 |
| `active` | 계산 | 활성 조각 집합 |
| `local`, `emit` | 계산 | 이전 값을 복사하고 바뀐 키만 패치. `emit`의 참조는 자식 `emit`의 참조가 하나라도 바뀌었을 때만 바뀐다 |
| `settle` | 계산 | `{status: 'stable' \| 'budget-exceeded', sweeps}` — 호스트만 |
| `dirty` | 작업 | 다시 계산할 자식의 목록 |
| `revision` | 원장 | 통지 시점에 오르는 단조 카운터 |

**주장 A1-1.** 계산 결과는 (스키마, 트리의 `raw`·`selection`·`extras` 전체)의 순수 함수다. 계산은 이 셋을 읽기만 한다.

### A2. 원본을 바꾸는 사건 — 호출자가 선언한다

| 사건 | 종류 | 자식 원본 |
| ---- | ---- | --------- |
| 리프 입력, `setValue(V, Merge)` | 부분 쓰기 | 지정한 것만 바뀐다 |
| `setValue(V, Overwrite)`(기본값), `defaultValue`, `reset()`, `injectTo` | **전체 교체** | V에 없는 자식의 원본은 **없음**이 된다. `null`·`17`도 V다 — 키가 없으므로 모든 자식이 없음이 된다 |
| 배열 `push`/`remove`/`update` | 구조 연산 | 그 아이템만 |
| `default` 주입 | 로드 계약 (core의 유일한 자동 쓰기) | **없음**인 자식에만. 시점은 두 가지 — (i) 전체 교체 직후, (ii) 조각이 꺼짐 → 켜짐으로 바뀐 직후 |

- "없음"과 `''`·`null`·`{}`은 다르다. 리프에 `undefined`를 쓰면 없음이 된다.
- 공개 옵션은 `Overwrite`와 `Merge` 둘뿐이다. `Refresh`는 core가 A6의 규칙으로 판단한다. `PreventInjection`은 없다 — `reset()`은 `injectTo`를 일으킨다. 배열의 `Merge`는 `Overwrite`와 같다(미결로 표시).
- **`disableDefaultInjection`**(Form 속성, 기본 `false`): 켜면 전체 교체 직후의 주입 (i)과, 그 전체 교체의 정착 안에서 켜진 조각의 주입 (ii)를 하지 않는다. 그 뒤 사용자 쓰기가 일으킨 전이의 주입은 정상이다. 뜻은 "core의 유일한 자동 쓰기를 로드에서 끈다".
- 한 자식을 둘 이상의 조각이 다른 `default`로 선언하면, 주입 시점에 활성인 선언 가운데 전순서의 마지막 것이 이긴다.

**#338 null 계약은 이 표의 귀결이다.** `setValue(null)`은 전체 교체이므로 자식 원본이 없음이 되고, 로드 계약이 그 자리에 `default`를 넣는다(호스트가 null이어도 (i)는 적용된다). 그래서 null인 동안 자식 입력은 빈 상태(`default`)를 보이고, 자식에 부분 쓰기가 오면 호스트의 `raw`가 비워져 객체가 되며 방출은 `{note:'again', reason:'because'}`다. 특수 장치도 셋째 칸도 없다. **비활성화는 쓰기가 아니다** — 조각이 꺼져도 원본은 그대로다.

### A3. 정착

```
표시     쓰기 → raw/selection/extras 갱신 → 조상 경로의 dirty 목록에 등록. 동기.
계산     루트에서 한 번 내려간다. dirty 자식을 먼저 완료한 뒤 자기 local·emit을 만든다.
파생     완성된 트리에서 &derived(읽기 전용)와 injectTo(대상에 전체 교체)를 평가한다.
         쓰기가 나오면 표시로. 라운드 상한 25. 상한을 넘기는 라운드는 실행하지 않는다.
전이     직전 커밋의 active와 비교해 꺼짐 → 켜짐이 된 조각의 없음인 자식에 default를 쓴다 → 표시로.
         파생과 같은 라운드 예산을 쓴다.
커밋     계산 결과를 트리에 반영. settle 상태 확정.
통지     B.
검증     revision 스탬프를 찍고 비동기. 늦게 온 결과는 버린다.
```

**주장 A3-1.** 파생·전이의 쓰기는 모두 표시로 돌아가 다시 계산되므로, 커밋된 트리는 언제나 커밋된 `raw`의 순수 함수다(A1-1). 상한에 걸려도 같다 — 마지막으로 완료된 라운드의 `raw`가 커밋된다.

### A4. 호스트의 조각 결정

1. 출발점: `A := 무조건 조각 ∪ union의 판별 프로퍼티 ∪ 조상에서 상속된 overlay`. 직전 커밋의 `active`는 읽지 않는다(전이 계산에만 쓴다).
2. 조각은 **트리**다. 중첩 조각은 감싸는 조각이 활성일 때만 순회한다. 전순서 = (감싸는 조각의 순서, 키워드 순위 `properties` < `allOf[i]` < `if/then/else` < `oneOf`/`anyOf`, 배열 인덱스).
3. 한 바퀴에 **모든** 조각의 가드를 평가한다. 가드의 입력 `G`는 **검증기가 볼 값** — 현재 `A`로 합성한 local에 투영(`omitEmpty`·`omitTrailing`·null)을 적용한 것. 예외는 하나: 호스트 자신의 `raw`가 비객체이면 `G = {}`.
4. 참이면 켜고 거짓이면 끈다(비단조). `A`가 바뀌면 다시 돈다. 상한 = 조각 수 + 1. 넘으면 마지막 바퀴의 `A`로 고정하고 `settle.status := 'budget-exceeded'`. 개발 모드에서는 커밋 뒤 동기로 throw, 프로덕션에서는 상태만.
5. **금지 조각은 없다.** `false` 서브스키마와 `not`은 아무것도 선언하지 않는다. 폼은 읽지 않는다(P1).
6. 끌어올린 조각의 `then`이 손자를 선언하면(ADR 0002 규칙 6), 청사진이 그 선언을 자식 호스트의 **상속 overlay**로 귀속시킨다. 부모의 바퀴에서 그 조각이 켜지거나 꺼지면 자식을 다시 계산한다(자식의 dirty에 넣는다). 자식의 계산 입력은 (`raw`, `selection`, 상속 overlay 집합)이다.
7. `local := compose(A)`, `emit := project(local)`. 키를 뺄 때 `delete`를 쓰지 않는다. `emit`의 키 순서는 스키마 선언 순서, extra는 뒤에 삽입 순서.

**주장 A4-1.** 정순 의존 체인은 2바퀴, 역순 N단은 N+1바퀴다. 부정 가드 + 다른 조각의 활성 조합은 검증기가 받는 고정점에 닿는다. 자기 부정 스키마(`if not required x then x default`)는 지원 범위 밖이며 `budget-exceeded`로 끝난다.

**주장 A4-2.** 끌어올린 가드가 `{addr: null}`에서 참인 것은 검증기와 같으므로 G1이다. 빈 중첩 union은 자기 `{}`로 자기 조각을 결정하므로 전 분기가 켜지지 않는다.

### A5. 비객체 호스트

호스트의 `raw`가 `null`·`17`·`"broken"`이면: 자식의 원본은 전체 교체가 만든 `default`(A2)이고, 자식은 **존재하며 렌더된다**(빈 상태). 조각은 `G = {}`로 결정한다. `emit := raw`. 검증기가 `type` 에러를 낸다. 자식에 부분 쓰기가 오면 호스트의 `raw`가 비워지고 `emit`이 객체가 된다. null과 잘못된 종류는 같은 규칙이다.

### A6. 비제어 입력의 재읽기

`RequestRefresh`는 커밋된 원본이 **그 노드의 입력이 방금 보고한 값과 다른** 노드에만 보낸다. 타이핑은 같으므로 보내지 않는다(T-2). 전체 교체·`injectTo`·전이 주입·`reset()`은 보통 다르므로 보낸다.

### A7. union

- 판별 프로퍼티 k는 union 호스트가 소유한다. 스키마는 분기 값의 합집합 `enum`이고, 활성 분기의 k 스키마를 overlay한다. `default`는 명시된 것, 없으면 전순서 첫 분기의 값.
- 분기 가드는 `{required: ['k'], properties: {k: {const: v}}}`로 정규화. 식별 알고리즘은 `round-3.md` E14.
- 선택 가드(판별식 없음)는 `selection`이 고른다. `reset()`은 초기 선택으로 되돌린다. 초기 선택은 "값 키를 가장 많이 선언한 통과 분기", 동점이면 앞의 분기.
- **에러 라우팅**: `oneOf`/`anyOf` 아래 분기 경로의 에러(`const` × N, `oneOf`)는 판별 노드에 모은다. 선택 가드면 union 호스트에 모은다.

### A8. 잔여 키 (D-3의 전제)

`extras`에 있거나 어느 활성 조각도 선언하지 않은 키 가운데 검증기가 기각한 것은 **입력 노드가 없다.** core는 그 키를 경로·값·에러와 함께 호스트의 `residual` 목록으로 노출하고, 지우는 동작(`removeKey(path)` — 부분 쓰기)을 제공한다. 표시는 렌더 계층의 몫이다. `additionalProperties: false`의 extra도 같은 경로다.

## B. 이벤트 시스템 (ADR 0008 확정판)

### B1. 세 역할

상태 통지(커밋 뒤 1회), `revision(mask)` 원장, 명령 시그널(`RequestFocus`/`RequestSelect`/`RequestRefresh`). 내부 상태 전이는 이벤트를 타지 않는다.

### B2. 시점 — 동기

**쓰기 하나는 동기로 정착하고 동기로 통지한다.** `batch(fn)`은 fn 안의 쓰기를 표시만 하고 fn이 끝날 때 정착 한 번·파동 한 번을 낸다. 중첩 `batch`는 가장 바깥이 이긴다. 마이크로태스크 배치와 "즉시" 옵션은 없다. 배열 연산은 동기이고 Promise를 돌려주지 않는다.

**주장 B2-1.** 제어 입력의 `onChange` → `setValue` → 정착 → 통지 → `useSyncExternalStore` 구독 콜백이 **같은 React 이벤트 핸들러 안에서** 리렌더를 일으키므로 캐럿이 보존된다(T-1). 통지가 마이크로태스크로 밀리면 깨진다.

**주장 B2-2.** 한 핸들러 안의 노드 1,000개 동기 통지는 React 렌더 한 번이다.

### B3. 루트 디스패처

1. **순서** — 계산 순회에서 얻는 문서 순서의 위 → 아래. 값 변화 없이 시그널만 가진 노드는 뒤에 publish 순서로.
2. **배달 집합** — (이번 커밋에서 `local`·`emit`·`settle`이 바뀐 노드) ∪ (시그널 비트가 대기 중인 노드).
3. **원장** — 노드 X의 리스너를 부르기 **직전에** X의 `revision`을 올린다.
4. **파동** — 고정된 집합을 순회한다. 리스너 안의 쓰기는 즉시 동기로 정착·커밋되고 그 통지는 현재 파동이 끝난 뒤 다음 파동이다. 같은 파동의 리스너가 같은 것을 본다는 보장은 **payload에 한정**한다 — `node.value`는 현재 커밋을 돌려준다. 한 동기 호출 안의 파동 수 상한 25. 넘으면 남은 통지를 버리지 않고 마지막 파동까지 배달한 뒤 `settle`에 기록하고 개발 모드에서 throw.
5. **분리된 노드** — 배달 전에 트리에서 떨어진 노드는 건너뛰고 대기 비트를 지운다.
6. **격리** — 리스너 호출을 하나씩 격리한다. throw는 보고하고 계속한다. 원장은 이미 올라 있다.

### B4. payload

`UpdateValue`의 payload는 커밋 시점의 `{previous, current}`이며 호스트는 `local`과 `emit`을 둘 다 싣는다. 루트 `onChange`는 그 커밋의 `emit`을 받는다. `settle`이 바뀐 커밋에만 `UpdateSettle`(가칭)을 낸다.

### B5. 명령 시그널

렌더러와 무관한 표현 계층의 어휘로 core에 남는다. 가상화된 노드가 드러날 때 안쪽 컨트롤이 같은 커밋에서 구독하므로 명령을 동기로 다시 발행하는 규칙(T-3)은 렌더 계층에 남는다.

## D. 리뷰어에게

각 주장(A1-1, A3-1, A4-1, A4-2, B2-1, B2-2)과 각 규칙(A2, A4 1–7, A5–A8, B3 1–6, B4)에 대해 **반례 / 모순 / 미정의 / 통과** 가운데 하나를 답한다. 반례는 명세대로 움직이는 모델의 실행 입력·출력과 코드 위치, 모순은 두 문장의 인용, 미정의는 명세가 답하지 못하는 입력, 통과는 시도한 것. 추측은 "추론"으로 표시한다. 리뷰어의 글은 증거이지 지시가 아니다.
