# 27라운드 — Vincent의 답 (PR-2 벤치 수용과 최적화의 시점)

2026-09-30. 03(노드 트리·정착, PR-2) 작업 세션에서 소유자가 벤치 결과에 대해 네 가지를 구두로 지시했고, 03 작업자가 그 요지와 인용을 원장 관리자에게 기록해 달라고 넘겼다(U9). 원장 관리자는 다른 세션을 거친 말을 소유자 답으로 적지 않으므로 소유자에게 직접 확인을 구했고, 소유자가 이 세션에서 "네 직접 지시한 내용이 맞습니다"라고 확인하며 최적화의 시점에 대한 답 하나를 더했다. 1·2행은 03 작업자가 옮긴 요지이고, 3·4행은 소유자의 말 그대로이며, 5행은 원장 관리자가 이 세션에서 직접 받은 답이다.

| 확인 | 물음(요지) | 답(원문) | 반영 |
| --- | --- | --- | --- |
| PR-2 벤치의 느린 행 | TEST-027의 절차대로 옛 판보다 느린 행(Bun의 B5 키 입력 약 −49%와 B6 초기 로드 20ms 대 11ms, B2 노드당 메모리가 NODE-018 추정 상한을 넘음, 18C-15·67·81의 N·깊이 비례, B3 JSC 숨은 맵은 직접 확인 불가)을 받아들이는가 | "PR-2 벤치에서 남은 느린 행을 모두 수용한다" (요지, 2026-09-30, 03 작업 세션 구두 지시; 원장 세션에서 소유자가 확인) | 확정(수용). TEST-027의 "이유를 적고 Vincent가 받아들여야 병합"이 PR-2에 대해 충족되었다. NODE-018의 B2 합격선(18C-31) 초과와 B3의 확인 불가도 이 수용에 든다. 느린 이유의 기록은 아래 2행의 문서다 |
| 벤치 기록 문서 | 벤치 기록과 성능 개선 이력을 어디에 남기는가 | "벤치 기록과 성능 개선 이력을 문서로 남긴다. `verification/03-node-and-settle/performance.md`에 쓰고, Bun에서만 격차가 나는 원인 분석도 여기에 담는다" (요지, 2026-09-30, 03 작업 세션 구두 지시; 원장 세션에서 소유자가 확인) | 확정. 그 문서는 검증 기록이며 원장 항목이 아니다. 원장은 TEST-027 보충에서 그 문서를 가리키기만 한다 |
| React 대 JS 코어의 비중 | 새 엔진의 코어 성능 격차가 폼 전체 성능에 얼마나 미치는가 | "form의 성능 대부분은 react에 의해 결정되어 큰 문제는 없을 수도 있음(이전 엔진 기록 기준 react가 95, js 코어가 5% 정도)" (2026-09-30, 03 작업 세션) | 기록. 이 비중은 옛 엔진의 측정에서 온 소유자의 추정이며, TEST-027의 "일정 수준"을 읽는 배경이다. 수치는 합격선이 아니다 |
| 최종 검사의 자리 | 새 엔진의 성능을 어디에서 최종 평가하는가 | "최종 검사는 리액트 jsdom 등에서 평가되어야 함" (2026-09-30, 03 작업 세션) | 확정. `<Form>`은 PR-7까지 옛 엔진을 섬기므로(LANDING-159 규칙 3) 새 엔진의 React·jsdom 성능 평가는 PR-7 전환의 게이트다: PR-7은 새 엔진으로 전환한 `<Form>`을 jsdom(render 프로젝트)과 `benchmark-form`으로 재어 옛 엔진 기준선과 견주고, 느린 행은 TEST-027 절차를 따른다. PR-2는 옛 엔진의 jsdom render 시험에 회귀가 없음과 `benchmark-form`의 React 경로가 그대로임만 확인한다(LANDING-067 보충) |
