2026-10-16. 389C-03이 별도 PR로 둔 F1을 닫는다. 코드의 `kind` 문자열 `union`이 원장의 "종류"(union이면 접은 집합까지)보다 거칠어, 선택 루프의 자식 재사용·비활성 간선 삭제와 이탈 대기·잠복 원본·게이트 레지스트리·커밋 선언·나감 정책·파생 규칙 열쇠·채움 집합이 서로 다른 union fold를 뭉쳤다(뒤 간선만 켠 값으로 마운트하면 호스트 바퀴 예산 초과, 뒤 간선 생존 중 앞 간선이 켜지면 앞선 종류가 아닌 노드 생존). codex가 먼저 kind 비교·열쇠 자리 전부를 분류했고(정체 용도 25곳 여섯 묶음, 범주 용도는 유지), fairy08이 분류표를 대조해 틀린 자리 없음을 확인했으며, 구현(codex, 커밋 fixy08)은 묶음마다 커밋 하나로 했다. fairy08의 커밋 대조가 빠진 자리 하나(이탈 대기 쓰기 열쇠)를 잡아 고쳤고 그 경로는 자연 입력 시험으로 고정됐다. codex 검증자(agy 한도) PASS, 전체 게이트(unit 2,744, render·react18 725, production 20, storybook 251, 시나리오 45, 플러그인 645, 겉면 94, filid 26) 뒤 원장 관리자가 diff를 읽고 squash 병합했다(319a1109b). 바뀐 기존 기대는 2건이며 둘 다 결함으로 판정된 옛 열쇠(범주만의 `union`)를 단언하던 시험이다.

## 편집자 결정

- **390C-01 (노드 정체 토큰 — union이면 접은 집합의 마스크를 붙인 하나의 토큰, 다른 종류는 기존 kind — BLUEPRINT-043·NODE-043·FRAGMENT-049의 적용).**
  - 【추론】 "(경로, 종류)" 열쇠와 "어느 종류의 노드를 살릴지"의 종류는 토큰 보조 하나가 정한다: union이 아니면 기존 kind 문자열이고(같은 이름 형제 사이에서 fold가 단일 타입이라 kind가 곧 정체), union이면 `union:<fold mask>`다. 마스크는 청사진 노드가 이미 보관한 정규화 `schemaType` 목록에서 청사진과 같은 fold 보조로 호출마다 계산하며(number/integer 같은 비트, null은 비트 없음), 저장 필드와 캐시를 더하지 않는다. 그래서 `[string,number]`와 `[number,string]`은 같은 토큰이고 `[string,boolean]`은 다르다. 이탈 대기·잠복 원본과 순서·게이트 경로 등록·커밋 선언·나감 정책·파생 규칙 열쇠·채움 집합은 모두 이 토큰으로 구별하고, 선택의 재사용·비활성 삭제·문서 순서 검색은 청사진 노드 객체 동일성으로 판정하므로 뒤 종류가 살아 있어도 첫 활성 종류가 생존하며 다른 fold의 잠복 값은 넘겨받지 않는다. 행 선택·전략·게이트 방식·구멍 값·공개 `type` 가드 같은 범주 판정은 기존 kind를 그대로 쓴다. 두 보조는 blueprint·settle·derive의 가장 낮은 공통 소유자인 engine의 organ에 두고 자식 모듈이 위로 직접 가져온다.
- **390C-02 (원장 보충 둘 — NODE-006 386C-01 문장의 반례, NODE-043 열쇠의 경로 단위 경계 — NODE-006·NODE-043의 보충).**
  - 【추론】 (1) 386C-01의 "`primeHost`의 조회는 지연된 SharedNodeConflict 정착에서만 자연 적중한다"는 틀렸다: 같은 정착 안에서 한 쓰기가 union 게이트를 닫았다가(기본값 채움으로) 다시 열면 그 노드는 이탈 대기에서 같은 인스턴스로 되살아나며, 이것이 자연 입력 시험으로 고정됐다. 조회를 남긴 결정은 그대로이고 "유일 경로" 문장만 거둔다. (2) 열쇠는 경로 단위이므로, 부모가 게이트로 객체 속성 `0`과 배열 `items`를 배타 전환하면 `/p/0`의 string 토큰이 두 노드에서 같아 나간 속성의 잠복 원본이 배열 아이템 0으로 들어갈 수 있다. NODE-043의 "(절대 경로, 종류)" 정의가 허용하는 모양이라 결함이 아니며 설계를 유지한다(토큰을 청사진 ID로 바꾸면 기존 열쇠 기대 112쌍이 바뀜). 시험은 두지 않고 경계로만 적는다.
