# 전체 구조의 멘탈 모델 — 질서와 원리

상태: 소유자와 맞추는 중. 이 문서는 결정의 목록이 아니라 결정을 **낳는** 원리를 적는다. 새 결정이 여기의 원리에서 도출되지 않으면 원리가 틀렸거나 결정이 틀린 것이다. 2026-09-23에 소유자가 P1을 원칙으로 다시 말했고(P1′, §1), 그 원칙에서 남은 결정이 도출됐다(`reviews/round-5-derivations.md`). ADR 본문(4차)은 이 문서와 그 도출을 따른다.

## 1. 다섯 원리

| # | 원리 | 한 문장 | 근원 |
| - | ---- | ------- | ---- |
| P1 | **판정은 검증기의 것이다** | 폼은 스키마의 뜻을 해석하지 않는다. 폼의 판정 = `validator(작성된 스키마, 방출 값)`. 폼이 스키마에서 읽는 것은 **형상**(어떤 필드가 있는가)을 만드는 데 필요한 최소한이다 | G1, G3, ADR 0001·0004 |
| P2 | **원본은 호출자와 작성자만 쓴다** | 노드의 원본(raw)에 쓰는 주체는 넷뿐이다 — 사용자 입력, 호출자의 `setValue`/`reset`, 작성자가 스키마에 선언한 `injectTo`, 로드 계약의 `default`. core가 스스로 원본을 "고치는" 일은 없다 | ADR 0013, C1·C2, E19 |
| P3 | **형상은 상태의 순수 함수다** | 어떤 조각이 켜져 있고 어떤 자식이 존재하는지는 (스키마, 원본 전체, 선택 상태)에서 매번 같은 절차로 계산된다. 이력을 읽지 않는다. 계산은 원본을 읽기만 한다 | ADR 0007, E1, E4–E6 |
| P4 | **방출은 정책이다** | 방출 값은 원본과 형상의 투영이다. 비활성 조각의 제외, `omitEmpty`·`omitTrailing`은 원본을 건드리지 않는 투영 규칙이며, 작성자가 고른다 | ADR 0006·0013, C4 |
| P5 | **core는 렌더러를 모른다** | core는 노드 트리·작업 루프·통지만 안다. React도, 컴포넌트도, 화면의 명령도 모른다. 렌더 계층이 core를 구독한다 | C3, ADR 0008·0011 |

**P1′ (소유자, 2026-09-23).** 폼이 스키마에서 읽는 것은 **노드 트리의 모양을 정하는 문법뿐**이다 — 타입(`type`, 다중 타입, 튜플), 자식의 존재(`properties`, `items`, `prefixItems`), 조건부 존재(`if/then/else`, `allOf`, `oneOf`/`anyOf`의 분기). 값의 유효성을 정하는 문법(`required`, `false`, `not`, `additionalProperties`, 범위·패턴 …)은 검증기의 것이고, 폼은 그 판정을 **보여 줄 뿐** 값을 고치지 않는다. 값을 빼거나 지우는 것은 작성자의 `&` 명령뿐이다. 소유자의 말(원문은 `reviews/round-5-derivations.md` §0): "그걸 바랐다면 ajv autofix 같은 걸 쓰지 않았을까. … 값 수정은 안 하고 에러만 보여주는 걸 기본 동작으로 하려고 했다."

P1이 가장 위에 있다. P2–P4는 "폼이 값을 어떻게 다루는가"를 셋으로 나눈 것이다 — **쓰기(P2)**, **계산(P3)**, **읽기(P4)**. 한 사건이 두 칸에 걸치면 설계가 잘못된 것이다.

## 2. 상태 — 노드가 드는 것

```
raw        원본. 리프와 터미널 노드만 값을 든다. 자식이 있는 노드는 "잘못된 종류의 값"이 왔을 때만
selection  union 호스트의 수동 선택(판별식이 없을 때만 존재)
extras     호스트가 받은, 어디에도 선언되지 않은 키
active     이번 커밋의 활성 조각 집합 — 계산 결과, 상태가 아니다 (P3)
local      활성 자식의 방출 값을 합성한 것, 투영 전 — 계산 결과
emit       local의 투영 — 계산 결과
settle     이번 정착의 결과 상태(정상 / budget-exceeded) — 계산 결과, 루트 통지로 관측
dirty      이번 정착에서 다시 계산할 자식 목록 — 작업 기록
revision   통지 원장 — 커밋 시 일괄 갱신
커밋 번호  검증 결과의 스탬프 — 오래된 결과를 버린다(F28)
```

**상태**는 `raw`·`selection`·`extras` 셋뿐이다. 나머지는 상태에서 계산되거나(P3) 작업의 기록이다. "노드 트리가 곧 상태"(ADR 0006)는 이 셋을 노드가 소유한다는 뜻이다.

## 3. 쓰기 — 원본을 바꾸는 사건 (P2)

| 사건 | 종류 | 누가 | 자식 원본에 미치는 것 |
| ---- | ---- | ---- | -------------------- |
| 사용자 입력 | 부분 쓰기 | 렌더 계층 | 그 리프만 |
| `setValue(V, { mode: 'Merge' })` | 부분 쓰기 | 호출자 | V에 있는 키만. 로드가 아니므로 `default`가 들어가지 않는다 |
| `setValue(V)`(기본 `Overwrite`), `defaultValue`, `reset()` | **전체 교체** | 호출자 | V에 없는 자식 원본은 **없음**이 된다. `null`·`17`도 V다 — 키가 없으므로 모든 자식이 없음이 된다. `setValue(getValue())`도 전체 교체다(D-7) |
| `injectTo` | 전체 교체(대상에) | 작성자 | 위와 같다 |
| 배열 `push`/`remove`/`update` | 구조 연산 | 호출자·렌더 계층 | 그 아이템만 |
| `default` 주입 | 로드 계약 | core (P2의 유일한 자동 쓰기) | **없음**인 키에만, 전체 교체 직후와 조각이 꺼짐 → 켜짐으로 바뀐 직후. 끄는 스위치는 이 하나만 끈다 — Form 속성이 기본값, 호출의 `{ disableDefaultInjection }`(이름 후보)이 양방향으로 이기며 `reset(options)`·마운트에도 있다(D-5·D-7). 배치 안에 억제가 섞이면 억제가 이긴다 |

쓰기의 종류는 호출자가 **선언**한다 — 옵션 객체 `{ mode?: 'Overwrite' | 'Merge'; disableDefaultInjection?: boolean }`. core는 추론하지 않는다(D-4). 유일한 예외는 `Refresh`(비제어 입력의 재읽기)로, 이것은 쓰기의 종류가 아니라 출처로 core가 판단한다(F7). "없음"과 `''`·`null`은 다르다 — 없음에만 `default`가 들어간다.

이 표에서 #338의 null 계약이 저절로 나온다: `setValue(null)`은 전체 교체이므로 자식 원본이 없음이 되고, 다시 객체가 될 때 로드 계약이 `default`로 빈 상태를 만든다. 특수 장치가 필요 없다(D-1). 반대로 **비활성화는 쓰기가 아니다** — 조각이 꺼져도 원본은 그대로다(P4).

## 4. 계산 — 정착 한 번 (P3)

```
표시     쓰기 → raw 갱신 → 조상의 dirty 목록에 등록                         동기
계산     루트에서 한 번 내려간다. dirty 자식을 먼저 완료하고 자기 local·emit을 만든다.
         호스트는 조각을 결정한다: 무조건 조각만 켠 채 출발 → 전순서로 가드 평가
         → 켜지고 꺼짐 → 집합이 안 바뀔 때까지 반복(상한 = 조각 수 + 1)
         가드는 검증기가 볼 값을 본다. 호스트 자신이 객체가 아니면 {}                (P1)
파생     &derived·injectTo를 완성된 트리에서 평가. 쓰기가 나오면 표시로. 라운드 상한
전이     꺼짐 → 켜짐이 된 조각의 없음인 자식에 default → 표시로                    (P2)
커밋     revision 갱신
통지     루트 디스패처가 위 → 아래 순서로 1회                                       (P5)
검증     커밋 번호 스탬프를 찍고 비동기                                              (P1)
```

계산은 원본을 쓰지 않는다. 원본을 쓰는 것은 파생과 전이뿐이고, 그것은 표시로 돌아가 다시 계산된다. 그래서 같은 (스키마, 원본, 선택)은 언제나 같은 형상이다.

## 5. 원리에서 결정으로 — 도출표

| 결정 | 도출 | 원리 |
| ---- | ---- | ---- |
| 검증기 입력 불변, `&` 네임스페이스 | 폼이 스키마를 고치면 판정이 달라진다 | P1 |
| 가드는 검증기 플러그인이 컴파일 | 폼이 `if`의 뜻을 해석하지 않는다 | P1 |
| 가드는 투영 후 값을 본다 (E5) | 검증기가 보는 값과 같아야 형상과 판정이 어긋나지 않는다 | P1 |
| 금지 조각을 읽지 않는다 (D-3, (iii)) | `x: false`·`not: {required}`는 값 유효성 문법이지 모양을 정하는 문법이 아니다(P1′). 폼이 읽어 값을 지우면 P2 위반. 본체에 선언된 자식은 보통 필드로 보이고 검증기 에러가 붙는다 | P1′, P2 |
| 잔여 키의 표시는 검증기 플러그인의 계약 | 어떤 에러가 "키 하나를 기각한다"인지 해석하는 것은 판정의 일부다. 정규화된 에러의 선택 필드 `rejectedKey?: string`을 플러그인이 채우고 core는 그것만 모은다(C-4) | P1 |
| 판별 프로퍼티는 union이 소유 (A5·E8) | 판별식은 형상을 만드는 최소한의 읽기다 | P1 |
| 판별 프로퍼티에 암묵 default 없음, 빈 값은 분기 없음 (D-8, C-1·C-7) | 폼은 값을 만들지 않는다. 선택 가드 union도 분기가 선언한 키를 가진 값에만 초기 선택을 적용한다 | P2 |
| core는 값을 고치지 않는다 (ADR 0013) | 파서 강제 변환·`minItems` 채우기·`trim`은 입력 컴포넌트로 | P2 |
| 쓰기 종류는 호출자 선언 (D-4) | core가 추론하면 P2의 "누가"가 흐려진다 | P2 |
| null 계약 유지 (D-1) | null은 전체 교체다. 자식 원본을 남기면 "없다"고 말한 데이터를 숨겨 두는 것 | P2 |
| 로드 시 default는 없음인 키에만 (D-5) | 있는 값을 고치지 않는다. 끄는 스위치는 유일한 자동 쓰기를 끄는 것 | P2 |
| `setValue(getValue())`에도 로드 계약 (D-7 (a)) | 전체 교체는 전체 교체다. 이력을 읽어 "방금 있던 키"를 구별하면 P3 위반. 예외는 호출 단위 억제 옵션 | P2, P3 |
| null 복귀·`setValue(getValue())`·억제 스위치는 한 규칙 (C-2·C-3) | 셋 다 "전체 교체 뒤 로드 계약"의 사례다 | P2 |
| 출발점 고정, 비단조 반복 (E1·E6, D-2) | 형상이 이력을 읽으면 같은 원본이 다른 형상이 된다 | P3 |
| default 주입은 계산 밖의 전이 (E1) | 계산이 원본을 쓰면 순수 함수가 아니다 | P3, P2 |
| 선택 상태는 노드의 칸 (E2) | 함수 입력에 없는 것이 형상을 바꾸면 P3 위반 | P3 |
| 비활성화는 방출 제외, 원본 유지 | 형상 변화는 쓰기가 아니다 | P4 |
| `omitEmpty`는 방출 정책 | 원본의 `''`는 그대로, 방출에서만 뺀다 | P4 |
| 통지는 커밋 뒤 1회, 루트 디스패처, 동기 | 렌더 계층은 정착된 상태만 본다. 동기여야 React의 controlled restore보다 먼저 커밋돼 캐럿이 남는다(T-1) | P5 |
| 루트 `onChange`는 최외곽 동기 진입당 1회 (D-10) | 한 수정에 한 통지. 리스너의 되먹임은 같은 진입 안이다(진입 깊이 카운터). React 이펙트의 쓰기는 새 진입이므로 키 입력당 2회이며 core가 합칠 수 없다(C-10) — 파생 값은 `derived`/`injectTo`/리스너로 | P5 |
| 명령(`focus`·`select`·`refresh`·`remount`)은 공개 API (D-9, C-11) | 명령은 렌더러와 무관한 표현 계층의 어휘다. `Refresh`는 입력의 `key`를 바꾸는 좁은 리마운트이므로 무엇을 버리는지 표로 적는다 | P5 |
| `virtual`은 참조 그룹 노드 (D-6) | 값을 소유하지 않으므로 P2–P4 밖. 형제의 값에서 파생되는 읽기 전용 뷰 | P5, P4 |
| 터미널 전략 유지, React 감지 제거 | 컴포넌트를 감지하는 것은 렌더러를 아는 것 | P5 |

## 6. 원리가 아직 답하지 않은 것

- **잔여 키의 UI**. 해석은 플러그인 계약 `rejectedKey`로 답했다(§5). 남은 것은 렌더 계층이다 — 기본 렌더러가 잔여 데이터 영역과 삭제 동작을 제공하는가, `not.required` 에러를 호스트에서 자식으로 옮기는 표시 규칙과 문구.
- **`setValue(undefined)`의 정의**와 배열 `Merge`의 뜻, `push()`로 만든 아이템이 로드인가(D-4·D-5의 세부).
- **배열** — 아이템 identity(R13), `contains`·`prefixItems`(Q13)는 P3 안에서 아직 자리가 없다.
- **선택 상태의 reset과 분기 전환의 확인** (ADR 0010).

## 7. 소유자와 맞출 질문

이해를 맞추는 순서로 적었다. 하나씩 답한다.

1. P1–P5가 맞는가. 빠진 원리가 있는가. 순서(P1이 위)에 동의하는가. — P1은 소유자가 P1′로 답했다(2026-09-23). P2–P5는 명시적 답 대기.
2. §2의 "상태는 셋뿐"에 동의하는가 — 특히 `active`가 상태가 아니라 계산 결과라는 것. — 대기.
3. §3의 표에서 `null`을 전체 교체로 보는 것(D-1)과 `default` 주입이 유일한 자동 쓰기라는 것. — D-7·D-8 결정과 원칙 답변이 같은 방향이나 D-1 자체는 확정 대기.
4. D-3(금지 조각을 읽지 않는다). — **답함.** 2라운드 발언은 `&active`로 값을 빼는 것만 뜻했고, 원칙 답변에서 (iii)이 도출됐다(`reviews/round-5-derivations.md` §2).
5. D-5의 스위치 이름. — 방향은 답함("초기값 조작 비활성화", `disable…` 형태). 후보 `disableDefaultInjection`, 확정 대기.
6. (새로) D-2의 상한 초과를 제출 차단으로 볼 것인가, D-6의 (a)/(b) 비용 비교를 어느 시점에 할 것인가.
