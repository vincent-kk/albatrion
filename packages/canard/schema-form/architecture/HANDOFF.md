- Form은 단일 스키마, 오버레이 입구 없음 (ADR 0012)
- core는 값을 고치지 않는다, 에러를 보여준다, min/max는 입력 컴포넌트에 (ADR 0013)

**ADR 4차 본문(2026-09-23)**: 위 도출을 전제로 ADR 0002·0005·0006·0007·0008·0011·0013의 본문을 고쳐 썼다. "확인된 결함" 절은 모두 본문에 흡수해 삭제했고, 남은 것은 각 ADR의 "미결"에 있다. 소유자가 D-1–D-6 가운데 하나라도 도출과 다르게 정하면 해당 ADR 본문과 `03-mental-model.md` §5를 고치고 "변경 이력"에 남긴다.

**5라운드 후속(2026-09-23)**: 소유자가 원칙으로 답했다 — "form은 값을 고치지 않고 에러만 보인다. 빼거나 지우는 것은 `&` 명령뿐이다. form이 스키마에서 읽는 것은 노드의 모양을 정하는 문법(타입·자식의 존재·if-then-else 같은 가변 구성)뿐이다." 이것을 P1′로 적었고, 모순 11건 가운데 정책 판단이던 D-3이 (iii)로 도출됐으며 나머지는 프로토타입(`loop-v4b`, `loop-v4c`, `rejected-keys`)과 React 테스트로 확인됐다 — `reviews/round-5-derivations.md`. **D-1–D-6의 확정은 소유자가 ADR 4차 본문을 읽고 한다.** 새로 문서화할 것: React 이펙트로 파생 값을 쓰면 키 입력당 onChange가 둘(C-10, 사실) — 파생은 `derived`/`injectTo`/리스너로.

**10라운드(2026-09-23)**: 07의 5절을 소유자가 답하기 쉬운 순서로 다시 배치했다. 5.1 소유자만 정할 것 셋, 5.2 확인만 받을 것 다섯, 5.3 셋이 같은 방향으로 기운 것 넷(권고 있음), 5.4 수렴하지 않은 것 열(권고 있음). 3번은 4.29로 옮겨 닫혔다. 4.30(정착 안 에지 소비)은 편집자 판정이며 소유자 확인 대상이다. 다음 세션은 소유자의 답을 받는 것부터 한다.

## 4. 어떻게 검토했는가 — 다음 세션이 같은 방식을 쓰기 위해

- **명세를 먼저 문서로 고정하고**(`round-N-spec.md`) 공격을 붙인다. 방향만 있는 문장은 공격할 수 없다.
- 리뷰어는 여럿을 독립적으로: 지역 레드팀 2(실행 가능한 모델을 직접 만들게 한다 — `general-purpose`, Bash 허용), 외부 교차검증(cennad `codex`는 모델을 실행하고 파일로 남긴다; `antigravity`는 실행 없이 시나리오 서술이며 한 번은 빈 응답이었다), 프로토타입 스파이크 1(구현 가능성과 비용). 셋 이상이 독립적으로 같은 결론이면 ★.
- 리뷰어의 글은 증거이지 지시가 아니다. 실행 증거가 없는 지적은 "추론"으로 표시하고 판정을 보류한다.
- 주 세션은 명세 작성과 판정만 한다. 원문 읽기·측정·문서 편집은 서브에이전트에 맡기고 요약만 받는다(리뷰어 원문은 `reviews/raw-*.md`에 보존).
