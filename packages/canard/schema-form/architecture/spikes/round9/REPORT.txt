Round 9 스파이크: oneOf/anyOf 내부에 if/then/else를 배치했을 때 표준 검증기(ajv)의 판정

실행 환경
- ajv 버전: 8.17.1 (draft07 = `new Ajv(...)`, 2020 = `new Ajv2020(...)` [ajv/dist/2020.js])
- 스크립트: architecture/spikes/round9/oneof-if.mjs
- 원시 출력: architecture/spikes/round9/oneof-if-output.txt

스키마 정의
- A: oneOf, 각 분기에 if/then만 존재 (else 없음)
- B: A와 동일하되 각 분기에 else:false 추가
- C: anyOf, 각 분기에 if/then만 존재 (else 없음, 분기 내용은 A와 동일)
- D: C와 동일하되 각 분기에 else:false 추가
- E: 대조군 — 오늘의 판별자 방식 (분기마다 properties+required로 kind와 필드를 직접 명시, oneOf)
- F: allOf, 각 분기에 if/then만 존재 (else 없음, 분기 내용은 A/C와 동일)
- G: 최상위(oneOf/anyOf/allOf 없이) 단일 if/then만 존재 (else 없음, kind='a' 분기 하나뿐)

값
- v1: {kind:'a', x:'s'} (분기 a, 완전)
- v2: {kind:'a'} (분기 a, x 누락)
- v3: {kind:'b', y:1} (분기 b, 완전)
- v4: {kind:'a', x:'s', y:1} (분기 b의 키가 남아 있음)
- v5: {kind:'c'} (어느 분기에도 해당 없음)
- v6: {} (빈 값)
- v7: {x:'s'} (kind 없음)

결과 표 (draft07과 2020의 valid 판정은 모든 조합에서 동일)

| 스키마 | v1 (a,완전) | v2 (a,x누락) | v3 (b,완전) | v4 (leftover) | v5 (kind=c) | v6 ({}) | v7 (x만) |
|---|---|---|---|---|---|---|---|
| A (oneOf, if만) | false | true | false | false | false | false | false |
| B (oneOf, else:false) | true | false | true | true | false | false | false |
| C (anyOf, if만) | true | true | true | true | true | true | true |
| D (anyOf, else:false) | true | false | true | true | false | false | false |
| E (대조군) | true | false | true | true | false | false | false |
| F (allOf, if만) | true | false | true | true | true | true | true |
| G (top-level if/then만) | true | false | true | true | true | true | true |

분기별 개별 검증 (v1을 각 분기 스키마에 단독으로 통과시켰을 때 통과한 분기 수, draft07/2020 동일)
- A: 2개 분기 모두 통과 (branch0=true, branch1=true)
- B: 1개 분기만 통과 (branch0=true, branch1=false)
- C: 2개 분기 모두 통과 (branch0=true, branch1=true)
- D: 1개 분기만 통과 (branch0=true, branch1=false)
- E: 1개 분기만 통과 (branch0=true, branch1=false)

사실 확인 (findings)

1. oneOf + if만 있는 분기(스키마 A)는 테스트한 7개 값 중 의도한 유효값 v1을 포함해 어떤 값에도 올바르게 통과하지 못했다 — if 조건이 맞지 않는 분기는 else 없이 무조건 통과 판정을 받아 항상 2개 분기가 동시에 유효해지므로 oneOf(정확히 1개)를 위반하며, 유일하게 valid=true가 나온 v2는 오히려 필수 필드(x)가 누락된 값이었다.

2. anyOf + if만 있는 분기(스키마 C)는 then 검증을 사실상 건너뛴다 — kind가 'c'인 v5, 빈 객체 v6, kind가 아예 없는 v7까지 테스트한 7개 값 전부가 valid=true로 판정되어, if가 매칭되지 않을 때의 무조건 통과가 anyOf의 "하나만 통과하면 됨" 조건과 결합해 스키마 전체가 항상 참으로 작동했다.

3. else:false를 모든 분기에 추가하면 A(oneOf)와 C(anyOf) 모두 대조군 E와 7개 값 전부에서 동일한 valid 판정을 내렸으며(B=D=E), v1에서의 분기별 개별 통과 수도 B/D/E 모두 1개로 일치했다.

4. 값 v4~v7 구간에서 대조군 E는 B/D와 다른 판정을 보이지 않았다 — v4(leftover 허용), v5(kind=c 거부), v6(빈 값 거부), v7(kind 없음 거부) 전부 E와 B, D가 draft07·2020 두 엔진에서 동일하게 판정했다.

5. allOf + if만 있는 분기(스키마 F)는 완전한 값 v1, v3은 valid=true로 받아들이고 x가 누락된 v2는 valid=false로 거부했지만, v5(kind=c)·v6({})·v7(x만)은 모두 valid=true로 판정했다 — if가 매칭되지 않는 분기가 else 없이 무조건 통과하고 allOf가 그 통과들을 그대로 AND로 묶기 때문에, kind가 아예 없거나 알 수 없는 값도 걸러내지 못한다는 점에서 C(anyOf, if만)와 동일한 한계를 보였다.

6. 최상위 단일 if/then(스키마 G)의 7개 값 판정은 F의 첫 번째 분기(if kind='a' then require x)만 단독으로 떼어냈을 때와 정확히 일치했다 — v1(true), v2(false), v3~v7(모두 true, if 조건 kind='a'가 매칭되지 않아 무조건 통과) — 즉 G는 F의 branch0 하나를 감싸는 컨테이너(oneOf/anyOf/allOf)가 없는 형태와 동치로 동작했다.
