# Round 18 Settle Prototype Contract

## Requirements

프로토타입은 LANDING-060의 v7 실행 모형입니다. v5·v6에서 확인한 회귀를 유지하면서 정적 extras 분류, 정착 단위 쓰기 순위, 나감 에지, 전이 상한, 재계산 목록 순회를 관측 가능하게 합니다. 제품 노드 엔진·React 바인딩을 구현하거나 제품 구현을 시험 대역으로 가져오지 않습니다.

규칙 A와 U7은 WRITE-093·098·099를 함께 따릅니다. WRITE-093의 첫 해석 목록 및 두 번째 해석 대상에 관한 옛 문장은 WRITE-098이 대체합니다. 루트 출력은 VALUE-034와 단계 검증 문서의 빈 그릇 규칙을 따릅니다.

## API Contracts

### Model boundary

실행 모듈은 명시적인 노드·조각·규칙 입력으로 생성, 쓰기, 정착, 값 조회와 계측을 제공합니다. 회귀 어댑터는 v6의 호출 형태를 보존하여 기존 사례를 재실행할 수 있게 하며, 형상 조건의 참·거짓은 주입된 게이트 함수가 판정합니다. 모형의 가변 상태는 모형 인스턴스에 귀속합니다.

`loop-v7.mjs`는 버전이 정해진 회귀 진입점입니다. 기존 회귀가 특정 버전 파일을 직접 불러오는 관례 때문에 이 이름을 유지하며, 구현은 그 진입점 아래 내부 단위로 분리합니다. v6의 생성 결과를 편집하지 않고 v7의 정본 소스만 변경합니다.

역사적 정책 행의 `EXPERIMENT=true`는 v6의 버리기·재시도·에지 소비 조합을 관측하기 위한 회귀 전용 모드입니다. v7 현행 규범의 증거로 세지 않습니다. 일반 실행은 `WRITE_CONFLICT`의 옛 `first`·`last` 선택과 무관하게 정착 전체의 고정순위를 따릅니다. 과거 레벨/진입 기준 스위치의 결과도 역사적 변형 관측으로 구분하며, 현행 규범 프로브는 실험 모드를 켜지 않고 정착 기준 기본값으로 실행합니다.

### Interpretation and projection

`isMember`는 유한 number, `Number.isInteger` integer, JSON 종류 멤버십을 판정합니다. `convert`는 WRITE-093의 변환표를 따르며 객체·배열 파싱이나 문자열화를 하지 않습니다. `interpret`는 멤버인 값을 그대로 반환하고, 변환에 성공한 서로 다른 결과가 정확히 하나일 때만 바꿉니다. 없음과 null은 보존합니다. 후보 배열을 만들지 않으며 순서 무관·멱등·무할당을 유지합니다.

진입의 쓰기 경계는 게이트와 무관한 정적 목록으로 해석하고 호출자가 준 값을 보관합니다. 전이에서는 이번 진입에 쓰였고 유효 목록이 좁혀진 노드만 원래 쓰인 값으로 다시 해석합니다. 게이트만 바뀐 노드는 소급 변환하지 않습니다. 재해석은 라운드당 노드별 한 번인 전이 쓰기이며 게이트가 바뀌면 다음 라운드를 부릅니다. 상한에 도달하면 원본 B에는 쓰기 경계의 정적 해석만 남기고 경고등·degraded 결과를 관측합니다.

객체·배열의 빈 local은 각각 `{}`·`[]`입니다. omitEmpty는 빈 local의 방출을 생략하지만 루트 출력의 빈 그릇은 객체 `{}`, 배열 `[]`, 나머지 `undefined`입니다. 배열 중간의 방출 없는 자리는 객체 `{}`, 배열 `[]`, 잎 `null`로 표현하고 omitTrailing은 꼬리만 자릅니다.

### Settling and work ownership

extras는 현재 활성 집합이 아니라 모든 정적 선언을 기준으로 구분합니다. if 안에서 조건으로만 언급된 키는 선언이 아니므로 extras이며 게이트 입력에 남습니다. 꺼진 조각에서 선언된 키는 잠복 원본이고 게이트 입력에서 제외합니다(VALUE-002).

같은 대상의 쓰기는 unsetValue > derived > injectTo > 채움 순위입니다. 동순위는 원천 노드 문서 순서, 같은 노드이면 선언 층의 구체성, 같은 층이면 조각 전순서로 정합니다. 정착 앞 라운드의 높은 순위는 뒤 라운드의 낮은 순위에도 이깁니다. 진 쓰기와 그 에지는 소비하지만 새 원천 값 변화는 새 에지입니다(SETTLE-004).

조각의 에지 규칙은 켜진 동안만 후보입니다. 나가는 조각의 규칙은 발화하지 않으며 나감 쓰기는 unsetOnInactive만 맡습니다. 새로 생긴 노드와 이미 남아 있던 공유 노드의 에지 기준점을 구별합니다(FRAGMENT-050).

전이 상한은 게이트 가진 조각 수 + 노드 게이트 수 + 1이며 파생 상한과 분리합니다. 중간 채움은 최종 형상에서 빠진 노드에 남기지 않습니다. 계산은 재계산 목록의 자식만 내려가고 영향 없는 형제를 방문하지 않음을 계측으로 확인합니다(SETTLE-002·003·005).

## Acceptance Criteria

### PROTO-REGRESSION — 이전 프로브 회귀

- TEST-060의 v5 회귀·Q8·경계·수정 뒤 탐침과 v6의 기존 프로브를 빠짐없이 대응시킵니다.
- 바뀐 기대에는 현행 원장 ID와 기존/새 결과를 보고하며 기존 사례를 무단 삭제하지 않습니다.

### PROTO-RULE-A — 규칙 A 변환표

- 변환표 모든 칸, integer 멤버십과 안전한 변환의 차이, 정확한 동점 12건을 확인합니다.
- 목록 순열의 결과 동일성, 멱등성, 멤버 값의 참조 보존 및 후보 수집의 무할당을 확인합니다.

### PROTO-ENTRY — 쓰기 경계 재해석

- 직전 게이트 상태와 무관하게 `{kind:'num', a:'42'}`가 `a = 42`, `{kind:'flag', a:0}`가 `a = false`가 됩니다.
- 쓰이지 않은 노드는 게이트 전환으로 값이 바뀌지 않고 경고등만 바뀝니다.
- WRITE-099의 수렴 반례는 `a = "0"`, 비수렴 반례는 B의 `a = 0`과 degraded를 남깁니다.

### PROTO-SETTLE — 전이와 정착

- extras·잠복 원본의 게이트 입력, 동순위와 정착 단위 순위, 나감 에지, 채움 철회와 전이 상한을 각각 관측합니다.
- 독립 형제 중 하나를 쓸 때 재계산 방문량이 영향 경로에 한정됩니다.

### PROTO-OUTPUT — 빈 루트 방출

- 빈 객체·배열 루트, 빈 중첩 호스트, omitEmpty 해제, 배열 중간 빈자리와 omitTrailing을 VALUE-034대로 확인합니다.

### PROTO-EVIDENCE — 실행 증거

- 프로브 보고서는 실행 명령, 실행 환경, 회귀 대응, 실패 후 통과 증거, 단언 결과, 비용 관측과 미해결 발견을 담습니다.
- 현재 구현의 통과를 문서 작성만으로 주장하지 않으며, 보고된 실행 결과로 완료 여부를 판정합니다.
