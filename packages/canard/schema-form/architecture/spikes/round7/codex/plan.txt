2. E1/E2/E3/E9의 기대값을 assert로 고정하고, 동일 엔진에서 old/P6 및 batch/sequential을 비교합니다.
3. 가드를 바꾸는 default, injectTo chain, batch 내부 사용자 입력, mount/reset 기준,
   같은 settle의 target 활성화, default 충돌을 실행합니다. 유한 default 영역을 전수 검사해 고정점 유무를 독립 확인합니다.
4. node model.mjs > results.txt를 지정 디렉터리에서 실행합니다. 종료 코드 0과 PASS를 확인합니다.
5. review.txt에 스키마, 쓰기, old/P6 결과, 결함/모호성 구분, 모델 한계와 재현 명령을 기록합니다.
6. 변경 경로와 round6 파일 불변 여부를 확인합니다.

계획 검토: grounded-only
현재 파일 경로와 명세의 원문을 확인했습니다. 배치 동치는 P6의 결론으로 가정하지 않고 검증 대상으로 둡니다.
독립 red-team 실험이며 제품 API나 모듈 경계를 변경하지 않으므로 별도 설계 결정이나 위임은 하지 않습니다.
사용자의 쓰기 범위/.md 금지에 따라 .seiri 계획/게이트 파일을 만들지 않고 이 파일로 기록을 대체합니다.
단일 실행 파일을 요청하셨으므로 모델 내부 함수를 같은 model.mjs에 둡니다.
제품 기능/버그 수정이 아닌 탐색 모델이므로 구현 전 제품 회귀 테스트 대신 old/P6 대조 단언을 사용합니다.
사용자 지정 Node 실행이 검증 명령입니다. 제품 빌드/렌더 테스트는 이 모델을 실행하지 않으므로 수행하지 않습니다.
