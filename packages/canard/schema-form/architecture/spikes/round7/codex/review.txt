Round 7 — P6 독립 red-team 검토

판정

P6는 E1의 중간 기본값 누출을 제거할 수 있고, F13 제한은 E9의 이력 힌트 의존성을 제거합니다.
그러나 D-13(a)의 기준 변경만으로 배치와 순차의 결과가 같아진다는 주장은 성립하지 않습니다.
E2와 E3가 그대로 재현됩니다. 자동 쓰기가 가드를 바꾸면 “최종 활성 집합”도 독립 입력이 아니라
자동 쓰기와 함께 풀어야 하는 고정점입니다. 이 고정점은 없을 수도, 여러 개일 수도 있습니다.
유일한 고정점이 존재해도 자연스러운 후보 반복이 그 해에 도달한다는 보장은 없습니다.

아래에서 “P6 결함”은 확정된 제품 버그를 뜻하지 않습니다. 제안의 보장 문구에 대한 반례인지,
아직 정하지 않은 의미론인지, 이 모델의 선택에 따른 결과인지 구분합니다.

2. 모델의 계약과 명시적인 선택

스키마 표기:
  base=[k,...]는 무조건 선언된 자식이며 default 존재를 뜻하지 않습니다.
  F: guard => declares, defaults는 조건부 조각입니다.
  a->b:f는 원천 emit이 기준 상태와 달라질 때 b를 f(a)로 전체 교체하는 리프 injectTo입니다.
  {}에서 키가 없는 것은 missing입니다. null, 빈 문자열, 숫자 0은 missing이 아닙니다.

형상 계산은 매번 조건부 active=[]에서 시작하고, 가드를 투영된 현재 값으로 평가합니다.
조각의 켜짐/꺼짐은 같은 sweep의 뒤 가드에 즉시 반영합니다. 형상 예산은 조건부 조각 수+1입니다.
선언되지 않은 raw는 latent로 남습니다. 예제는 평면 객체와 원시 리프만 사용합니다.

old:
  사용자 쓰기를 표시한 뒤 형상을 계산하고, 완성된 후보 트리에서 injectTo를 읽습니다.
  injectTo 변화가 있으면 다시 계산하고, 그 다음 전이 default를 채워 다시 계산합니다.
  중간 자동 쓰기는 원본에 누적됩니다. injectTo는 직전 커밋 emit을 기준으로 합니다.
  파생 25회, 전이 조각 수(무조건 기본값 조각 포함) 예산을 별도로 둡니다.
  테스트된 정상 사례는 이 예산에 닿지 않습니다.

P6:
  S0 = 최외곽 진입 직전 상태, B = 모든 명시적 쓰기를 표시한 뒤의 원본입니다.
  Rn 후보의 형상 An과 emit En을 계산한 뒤 다음 후보를 만듭니다.
  R(n+1) = B에 [En과 E0를 비교한 injectTo]를 적용하고,
           [An과 시작 active를 비교해 허용한 default]를 missing 키에 채운 값입니다.
  이전 후보의 자동 쓰기를 누적하지 않고 B에서 다시 만듭니다.
  R(n+1)=Rn이고 형상이 안정되었을 때만 커밋합니다.
  load/reset은 F4에 따라 전이 active 기준을 비우되, 원천 emit 기준은 별도로 처리합니다.

이는 D-12의 default 폐기를 injectTo 후보에도 적용한 강한 P6 구현입니다. D-12만 바꾸고
injectTo 후보를 누적하는 약한 해석과의 차이는 N8에서 드러납니다. P6 문구 자체가 이 알고리즘을
유일하게 지정한 것은 아닙니다. 안정 후보에서 자동 쓰기 출처와 최종 형상을 일치시키는 구현을 택했습니다.

명세가 정하지 않은 부분은 다음과 같이 분리했습니다.
- default winner 기본값은 최종 활성 선언 전체의 선언 순서 last-wins입니다. first-wins도 실행합니다.
  전이한 조각은 주입 자격을 정하고, 어떤 default가 이기는지는 최종 활성 선언 전체에서 정합니다.
  guard 평가 순서를 default 우선순위로 쓰지 않습니다.
- injectTo는 default보다 먼저 쓰므로 같은 target에서 injectTo가 default를 이깁니다.
- 비활성 target은 기본 실험에서 쓰지 않습니다(active-only). latent 쓰기 허용도 N6에서 실행합니다.
- mount의 기본 원천 기준은 빈 상태입니다. loaded 상태와 비교하는 선택도 N5에서 실행합니다.
- 후보 순환이면 candidate-cycle, committed:null로 반환합니다. 이는 진단용 모델 정책입니다.
  P6가 이 status 이름이나 커밋 거부를 이미 규정했다는 뜻은 아닙니다.
- P6는 형상 유일성을 보증하지 않은 힌트를 사용하지 않습니다. N7에서만 무조건 자식에만 의존하는
  가드임을 근거로 uniqueShape 인증을 전달하고, 해당 raw의 형상 고정점 개수도 검사합니다.
  일반 스키마의 유일성을 자동으로 증명하는 기능은 구현하지 않았습니다.

“동일한 입력”도 구분해야 합니다. 같은 S0/B/에지 기준/승자 규칙/선언 순서에서의 결정성과,
같은 사용자 쓰기 목록을 여러 settle로 나누어도 같은 결과라는 성질은 다릅니다.
이 모델은 규칙을 고정한 정상 사례에서 결정적입니다. 그 사실이 배치 분할 동치를 뜻하지 않습니다.

3. 기존 반례 E1, E2, E3, E9

E1a — required 없는 조건과 중간 then 기본값
스키마: base kind(default b); then guard=(kind 없음 또는 a), x default T;
        else는 해당 guard의 보수이며 x default E입니다.
쓰기: 경로 A는 load {}; 경로 B는 load {kind:b}입니다.
old: A={kind:b,x:T}, B={kind:b,x:E}. 최종 active는 둘 다 else입니다.
P6: A=B={kind:b,x:E}. 최종 집합에서 나온 E만 커밋합니다.
판정: 해결되었습니다. 유한 default oracle의 결합 고정점은 하나입니다.

E1b — required 있는 권장 조건
스키마: base kind(default a); then guard=(kind=a), x default T; else x default E입니다.
쓰기: A=load {}, B=load {kind:a}입니다.
old: A={kind:a,x:E}, B={kind:a,x:T}.
P6: A=B={kind:a,x:T}. 결합 고정점은 하나입니다.
판정: 해결되었습니다. required 사용만으로 old의 문제를 회피할 수는 없습니다.

E2 — 공유 자식에 먼저 커밋된 default
스키마: base kind; A:(kind=a)=>x default A; B:(kind=b)=>x default B.
시작: raw={}. 쓰기: kind=a; kind=b.
old: 순차={kind:b,x:A}, 배치={kind:b,x:B}.
P6: 순차={kind:b,x:A}, 배치={kind:b,x:B}.
최종 active는 모두 B이며 유일합니다. 순차의 첫 settle에서 A는 실제 최종 조각입니다.
그 x=A는 두 번째 settle의 B 원본에 이미 들어 있으므로 폐기할 “중간 후보”가 아닙니다.
판정: P6의 배치 동치 주장은 반증됩니다. missing-only와 이전 커밋 보존을 유지한다면 이 차이는 필연적입니다.

E3 — 사용자 target 수정 뒤 source 왕복
스키마: base src,tgt; src->tgt: f(v)='f('+v+')'.
준비: load {src:x,tgt:custom}; 기본 mount 정책에서는 {src:x,tgt:f(x)}가 됩니다.
      사용자 tgt=mine으로 수정합니다.
비교 쓰기: src=y; src=x.
old: 순차={src:x,tgt:f(x)}, 배치={src:x,tgt:mine}.
P6: 순차={src:x,tgt:f(x)}, 배치={src:x,tgt:mine}.
순차의 두 기준은 x와 y이고, 배치의 단일 기준은 x입니다. 배치의 최종 src=x는 기준 x와 같습니다.
판정: D-13(a)만으로는 해결되지 않습니다. 정상 동기 진입에서 “직전 커밋”과 “진입 직전 상태”는 같습니다.
만약 시작을 표시 이후로 잡으면 직접 source를 바꾸는 쓰기도 에지가 사라집니다. 그것은 또 다른 규칙입니다.

E9 — 짝수 부정 순환과 이력 힌트
스키마: base 없음; A: !has(b)=>a, B: !has(a)=>b. default는 없습니다.
쓰기: load {a:1,b:2}; 스키마 선언 순서는 A,B로 고정하고 평가 힌트만 바꿉니다.
old: 힌트 A,B이면 emit={a:1}; B,A이면 emit={b:2}. 둘 다 stable입니다.
P6: 두 힌트 모두 emit={a:1}. 유일성을 보증하지 못하므로 고정 선언 순서로 평가합니다.
raw={a:1,b:2}는 모두 보존되고, 형상 고정점은 A와 B 두 개입니다.
판정: 이력 힌트에 의한 차이는 해결됩니다. 스키마 선언 순서 자체를 뒤집는 것은 별개 입력이며,
다중 고정점이라는 모호성까지 없어진 것은 아닙니다.

4. 추가 실험

N1 — default가 자신의 guard를 끕니다: 해가 없습니다
스키마: base x; F:(x != 1)=>x default 1.
쓰기: load {}.
old: raw=emit={x:1}, active=[], stable. F가 꺼져도 주입된 x는 남습니다.
P6: {} / active F → {x:1} / active 없음 → {}로 순환합니다. 커밋하지 않습니다.
독립 oracle: 가능한 원본 {}와 {x:1}을 모두 검사했으며 결합 고정점은 0개입니다.
판정: 실제로 서로 다른 정상 커밋을 얻은 반례가 아니라, P6의 “최종 집합”이 존재하지 않는 사례입니다.
기존의 형상-only 순환 금지로 충분하지 않습니다. 두 raw 각각의 형상은 즉시 안정됩니다.
자동 쓰기까지 포함한 지원 범위와 실패 시 유지/거부/진단 규칙이 필요합니다.

N2 — default가 자신의 guard를 켭니다: 해가 둘입니다
스키마: base x; F:(x=1)=>x default 1.
쓰기: load {}.
old: raw=emit={}, active=[], stable.
P6 기본 출발점 B={}: 동일하게 {}로 안정됩니다.
P6 진단용 후보 seed={x:1}: raw=emit={x:1}, active=F로 안정됩니다.
독립 oracle: 정확히 [{},active 없음]과 [{x:1},active F] 두 해입니다.
판정: 해 선택의 본질적 모호성입니다. 대체 seed를 사용자 쓰기나 허용된 이력 힌트라고 주장하지 않습니다.
“최종 형상의 함수”라는 제약만으로는 두 해를 구별하지 못합니다. 초기 후보/최소 해/자기 지지 해 금지
중 어떤 규칙을 택할지 정해야 합니다. raw별 형상 유일성과 결합 시스템 유일성은 다릅니다.

N3 — injectTo 체인 a→b→c
스키마: base a,b,c; a->b:10*a, b->c:b+1.
시작: {a:0,b:0,c:99}. 이는 a=0으로 초기화한 뒤 사용자가 c를 99로 바꾼 상태와 같습니다.
쓰기: a=1; a=0.
old: 순차={a:0,b:0,c:1}, 배치={a:0,b:0,c:99}.
P6: 순차={a:0,b:0,c:1}, 배치={a:0,b:0,c:99}.
대조군: a=1 한 번은 old/P6 모두 {a:1,b:10,c:11}로 전파됩니다.
판정: 체인이 에지 손실을 복원하지 않습니다. 새로운 독립 원인이라기보다 E3가 체인 전체로 확장된 사례입니다.
각 settle 안에서 최종 값으로 재평가해도 배치 경계 밖에서 발생한 에지를 되살릴 수 없습니다.

N4 — fragment 전환과 batch 내부 사용자 입력
스키마: base on,src; F:(on=true)=>tgt default D; src->tgt:f(src).
시작: {on:false,src:0}. 쓰기: on=true; src=1; tgt=mine.
old: 순차={on:true,src:1,tgt:mine}, 배치={on:true,src:1,tgt:f(1)}.
P6: 순차={on:true,src:1,tgt:mine}, 배치={on:true,src:1,tgt:f(1)}.
순차에서는 src=1의 settle이 끝난 뒤 사용자가 tgt를 수정합니다. 배치에서는 모든 표시 뒤 injectTo가 실행됩니다.
대조군: E2 스키마에서 kind=a; x=mine; kind=b는 old/P6·순차/배치 모두 x=mine입니다.
판정: default의 missing-only 보장은 동작합니다. injectTo 전체 교체와 사용자 쓰기의 우선순위는 별개입니다.
P6의 일반적인 배치 동치 보장에는 반례이며, 사용자 우선/자동 우선/시간 순서를 보존하는 별도 규칙이 필요합니다.

N5 — mount/reset에 원천 기준이 없거나 초기화될 때
스키마: E3의 src->tgt:f(src).
쓰기: load {src:x,tgt:custom}. reset 직전 상태는 {src:x,tgt:mine}입니다.
old/P6 각각 동일한 결과:
  mount + 빈 원천 기준       -> {src:x,tgt:f(x)}
  mount + loaded 원천 기준   -> {src:x,tgt:custom}
  reset + 직전 원천 기준 유지 -> {src:x,tgt:custom}
  reset + 원천 기준 비움     -> {src:x,tgt:f(x)}
판정: 기준 상태 초기화 규칙이 필요합니다. old의 mount 정책도 확정 명세로 간주하지 않았습니다.
F4의 “전이 기준 비움”은 default active 기준에 관한 규칙입니다. 이것을 injectTo의 emit 기준 초기화와
동일시하면 reset이 사용자 값을 덮는 시점이 달라집니다. history를 trigger로 허용하는 한 mount/reset
차이는 그 자체로 P6 위반이라고 단정할 수 없습니다.

N6 — target이 같은 settle에서 켜집니다
스키마: N4와 같습니다. 시작: {on:false,src:0}. 쓰기: src=1; on=true.
active-only target 정책:
  old: 순차={on:true,src:1,tgt:D}, 배치={on:true,src:1,tgt:f(1)}.
  P6: 순차={on:true,src:1,tgt:D}, 배치={on:true,src:1,tgt:f(1)}.
  순차에서 source 에지가 발생할 때 target이 비활성입니다. 이후 target이 켜져도 source는 변하지 않았습니다.
latent target 쓰기 허용 정책:
  old/P6·순차/배치 모두 {on:true,src:1,tgt:f(1)}입니다.
쓰기 순서를 on=true; src=1로 바꾸면 active-only 순차에서도 tgt=f(1)입니다.
판정: 비활성 노드에 injectTo가 쓰는지, target 활성화가 재발화 trigger인지 규칙이 필요합니다.
active-only가 확정 규칙이라고 가정한 제품 결함 주장은 아닙니다. 이 선택 아래서는 P6도 경로 차이를 유지합니다.

N7 — 최종 집합에 두 default 선언이 함께 남습니다
스키마: base a,b; A:(a=true)=>x default A; B:(b=true)=>x default B. 선언 순서 A,B.
시작: {a:false,b:false}. 쓰기: a=true; b=true.
last-wins일 때:
  old: 순차={a:true,b:true,x:A}, 배치={a:true,b:true,x:B}.
  P6: 순차={a:true,b:true,x:A}, 배치={a:true,b:true,x:B}.
first-wins일 때 old/P6 배치는 {a:true,b:true,x:A}입니다.
P6의 guard 평가 힌트를 B,A로 바꾸어도 last-wins 배치는 x=B입니다.
추가 대조: 시작 {a:false,b:true}, x missing에서 a=true이면 P6 last-wins는 x=B입니다.
새로 켜진 A가 trigger이지만 winner는 이미 활성인 B까지 포함한 최종 집합에서 정했습니다.
판정: default-winner는 final-set만으로 정해지지 않습니다. 순서를 확정해야 합니다.
그 뒤에도 먼저 커밋된 x=A는 missing이 아니므로 배치 동치는 성립하지 않습니다.
기본값 출처를 추적해 다시 쓰려면 P2와 사용자 수정 보존에 관한 새 규칙이 필요합니다.

N8 — 체인에서 사라진 중간 에지 출력
스키마: base a,b,c; a->b:항상 0, b->c:f(b).
시작: {a:0,b:0,c:mine}. 쓰기: batch(a=1; b=1).
old: {a:1,b:0,c:f(1)}. 첫 완성 트리의 b=1이 c를 바꾼 뒤, b가 0으로 돌아와도 c는 남습니다.
P6: {a:1,b:0,c:mine}. 최종 b=0은 시작 b=0과 같으므로 c에 대한 자동 쓰기 후보를 폐기합니다.
판정: 강한 P6에서 해결되는 대조 사례입니다. 전이 default만 폐기하면 충분하다는 해석에는 반례입니다.
“자동 쓰기 전체의 최종 상태 의존”과 “default만 rollback”은 같은 구현이 아닙니다.

N9 — 유일한 해가 있는데 반복은 도달하지 못합니다
스키마: base x;
  zero:(x=1)=>x default 0;
  one:(x missing 또는 x=0)=>x default 1;
  two:(x=2)=>x default 2.
쓰기: load {}.
old: raw=emit={x:1}, active=zero, stable. 중간 one이 쓴 1이 유지됩니다.
P6 기본 출발점: {}→{x:1}→{x:0}→{x:1}로 순환하여 커밋하지 않습니다.
독립 oracle: {}, {x:0}, {x:1}, {x:2}의 전체 영역에서 유일한 해는 {x:2}, active=two입니다.
그 해를 진단용 seed로 주면 P6가 안정됨도 확인했습니다.
판정: 후보 반복 알고리즘의 불완전성을 보여줍니다. P6를 충족하는 모든 solver의 실패를 뜻하지 않습니다.
F13의 유일성 제한만으로는 수렴을 보장할 수 없습니다. 도달 가능한 해만 허용할지, 자기 지지 해를
배제할지, 단조성/층화로 허용 스키마를 제한할지 정해야 합니다. 순환 검출만으로 “해 없음”이라 부르면 틀립니다.

5. 추가 단언과 검증의 신뢰도

C1: 기존 x='mine', x='', x=null을 전이 기본값으로 덮지 않는지 확인했습니다.
    이미 켜진 F에서 x가 missing일 때 같은 부분 쓰기는 default를 재주입하지 않지만,
    같은 값을 reset으로 로드하면 F4에 따라 x=D가 들어갑니다.
C2: 시작 {src:x,tgt:mine}, 원천 알파벳 x/y/z, 길이 1–3인 총 39개 경로를 전수 실행했습니다.
    old/P6 모두 순차는 중간에 x를 떠났으면 마지막 f(src)를 커밋하고,
    배치는 마지막 src가 x이면 mine을 유지합니다. 차이를 보이는 경로는 정확히 10개입니다.

유한 default oracle은 가능한 각 missing 키에 대해 missing 및 스키마의 모든 default 상수를 열거하고,
각 raw에서 모든 active 부분집합을 검사합니다. 주입만 있는 평면 예제에서는 가능한 값의 전체 영역입니다.
따라서 N1의 해 0개, N2의 해 2개, N9의 해 1개는 반복 알고리즘과 독립적으로 확인한 결과입니다.
shapePoints와 defaultPoints는 지수 비용의 실험용 oracle입니다. 제품 성능이나 일반 JSON Schema에 대한
결정 가능성을 주장하지 않습니다. 64회 후보 예산 역시 모델의 보호장치이며 새 ADR 예산 제안이 아닙니다.

디스크 파일을 바꾸지 않는 두 mutation probe도 수행했습니다.
- P6가 B 대신 이전 후보 emit을 보존하도록 바꾸면 E1a가 실패합니다:
  actual={kind:b,x:T}, expected={kind:b,x:E}, AssertionError, 종료 코드 1.
- 유일성 인증 없이 P6 힌트를 허용하도록 바꾸면 E9가 실패합니다:
  actual={b:2}, expected={a:1}, AssertionError, 종료 코드 1.
따라서 해당 단언은 주장한 의미 변화에 실제로 민감합니다. 정상 파일 실행은 종료 코드 0입니다.

한계:
- 제품 런타임, React 렌더링, 검증기, 중첩 overlay, union selection, 배열과 listener 파동은 검증하지 않았습니다.
- 자동 쓰기가 객체를 전체 교체하는 중첩 경우와 source가 사라지는 injectTo는 모델 범위 밖입니다.
- 가드의 문자열/null 투영 옵션은 구현하지 않았습니다. 핵심 반례는 존재 여부 또는 원시 상수 비교로 충분합니다.
- old도 명세의 독립 모델입니다. 미정인 default 우선순위, mount 기준, 비활성 target 정책은 확정 동작으로 주장하지 않습니다.
- N2의 후보 선택 차이와 N9의 비수렴을 두 개의 정상 사용자 경로 커밋 차이라고 부르지 않았습니다.
- N3는 E3의 확장이고 N7의 커밋 보존 문제는 E2와 같은 원인입니다. 독립 근본 원인 수로 부풀리지 않았습니다.

6. 권고할 규칙

가장 먼저 D-13(a)의 “배치·순차 동일”이라는 결론을 삭제하거나, 동치가 보장되는 범위를 좁혀야 합니다.
다음 세 성질은 E2에서 동시에 유지될 수 없습니다.
  (1) 순차 settle마다 새 fragment의 missing default를 실제로 커밋합니다.
  (2) 이미 커밋된 값은 이후 fragment 전환에서 default로 덮지 않습니다.
  (3) 중간 settle을 없애는 batch와 순차의 결과가 언제나 같습니다.

권고 방향은 “주어진 진입 시작 상태와 표시 후 원본에 대해 settle 내부 후보 경로에 의존하지 않는다”를
P6의 범위로 삼고, batch는 중간 에지를 제거하는 트랜잭션이라고 명시하는 것입니다.
정말 분할 동치가 필요하면 표시 과정에서 논리적 자동 쓰기/에지를 재생하거나, 에지 트리거를 레벨 파생으로
바꾸거나, 기본값의 출처를 추적해 재평가해야 합니다. 어느 선택도 D-13의 기준 이름만 바꾸는 수정은 아닙니다.

그 다음 다음 항목을 계약에 명시해야 합니다.
- 최종 상태는 raw/active/자동 쓰기 후보의 결합 고정점인지, default 층화를 따르는 다른 계산인지.
- 고정점 없음, 다중 고정점, 존재하지만 반복 비수렴을 어떻게 구분하고 관측할지.
- 초기 후보와 해 선택 규칙, 특히 자기 지지 default를 허용할지.
- default뿐 아니라 철회된 injectTo의 중간 쓰기도 폐기할지.
- mount/reset의 source 기준, 비활성 target 처리와 target 활성화 재발화 여부.
- 최종 활성 선언들의 default 우선순위와 사용자/자동 쓰기의 충돌 규칙.

본 작업은 독립 검토 자료를 제출하는 범위이며 제품 수정·커밋·병합이나 별도 리뷰 위임은 하지 않았습니다.
다음 검토자는 model.mjs와 results.txt를 함께 보고, 특히 위 명시적 선택들이 채택될 계약과 같은지 확인하시면 됩니다.
