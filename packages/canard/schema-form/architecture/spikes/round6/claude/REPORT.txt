1. 실행 결과 요약
----------------------------------------------------------------------------------------------------
E1  전이 주입이 정착 안의 과도 형상에 대해 일어난다. x를 then(default T)과 else(default E)가 공유.
    (a) if에 required 없음, kind default b:  load {} → {kind:b, x:T}   load {kind:b} → {kind:b, x:E}
    (b) if에 required 있음(권장 패턴), kind default a: load {} → {kind:a, x:E}   load {kind:a} → {kind:a, x:T}
    → {}의 로드 결과가 "default를 채운 값"의 로드 결과와 다르다. 최종 활성 조각의 default가 아니다.
E2  같은 두 쓰기(kind a → b), 공유 노드 x(A:'A', B:'B'): 순차 → x='A', batch → x='B'.
E3  injectTo F11(EMULATED): 로드 {src:x, tgt:custom} 직후 tgt='f(x)'(로드한 값 덮음).
    사용자가 tgt=mine 후 src y→x: 순차 → tgt=f(x), batch → tgt=mine.
E4  순 변화 0: 리스너가 bad→orig 되돌림 → onChange 1·검증 1(previous와 current가 같은 값),
    batch(bad, orig) → onChange 0·검증 0.
E5  예산 초과 스키마에서 키 입력 1회: dev → onChange 0·검증 0(throw 2), prod → onChange 1·검증 1.
    커밋된 값은 같다({y:'1'}, status budget-exceeded).
E6  한 틱 안의 배치 없는 쓰기 30회: 리스너 없음 → 파동 30(26번째 호출에서 25 초과),
    권장 스토어 리스너(a→b 파생) → 파동 60(13번째 호출에서 25 초과).
E7  setValue({obj:{y:1}, items:[{y:1}]}, Merge): obj.x는 없음 유지, items[0].x='D' 주입.
E8  양의 순환: if required x then properties x(x는 본체에 없음), load {x:'v'} → 방출 undefined, raw는 x:'v',
    status stable. 상호 순환 {a:1,b:2} → 방출 undefined, stable.
E9  짝수 부정 순환 F1(if not b then a), F2(if not a then b), load {a:1,b:2}:
    선언 F1,F2 → {a:1}, F2,F1 → {b:2}. 둘 다 stable, sweeps 2. budget-exceeded 아님.
E10 판별식 없는 anyOf, 두 분기 모두 통과하는 {a:1,b:2} → 방출 {a:1}. 편집 없이 저장해도 b 소실.
E11 스토어 리스너가 같은 필드를 대문자로 → 두 번째 배달에 refresh:true(입력 key 교체 = 리마운트).
E12 선택 가드 union, load {zzz:1} → 분기 A 켜짐, default 'A' 주입(ADR 0002 규칙 1의 도출과 반대, 기록된 U-1 재현).
E13 루트 {a}, 사용자가 a를 '' 로 지움 → getValue() undefined(루트 자체가 방출에서 빠짐).
E14 판별 필드를 '' 로 지움 → 방출 undefined, meow는 잠복.

2. 발견 (심각도 순)
----------------------------------------------------------------------------------------------------
F-1 [높음, 실행 E1] 전이 주입이 최종 형상이 아니라 라운드 중간의 과도 형상에 대해 일어난다.
    어디: MM:45, MM:60, 0007:33, R4S:36("주입 시점에 활성인 선언 가운데 마지막"), F4(R4S:137).
    원리: P3(형상은 상태의 순수 함수)는 형상만 보장하고 주입된 원본은 라운드 순서의 함수가 된다. P2의
    "없음인 키에만"은 지켜지지만 어느 default가 들어가는지가 예측 불가. 권장 패턴(if에 required)에서도 난다.
    같이 걸리는 것: 어느 default가 이기는가 — R4S:36은 "마지막 승", 0005:109는 현재 "먼저 승"이며 소유자 결정
    대기, 4차 ADR 본문에는 규칙이 없다.
    제안: (a) 같은 정착 안에서 꺼진 조각이 한 주입은 커밋 전에 버린다(아직 커밋되지 않은 쓰기이므로 "core가
    값을 고친다"가 아니다), 또는 (b) 층화 — 무조건 default → 재계산 → 최종 활성 조각의 default. default 우선순위를
    ADR 본문에 적는다.

F-2 [높음, 실행 E8·E9] 양의 순환·짝수 부정 순환에서 로드한 유효 값이 조용히 방출에서 빠지고 신호가 없다.
    어디: 0013:63 "형상은 그 값으로 수렴한다", 0007:57·0002:71 "budget-exceeded로 표시된다", 0002:60 가드 입력.
    원리: P1("가드는 검증기가 볼 값을 본다") — 검증기는 로드 값 {x:'v'}에서 if를 참으로 보지만 폼의 G는
    출발점 고정(E6) 때문에 x를 합성하지 않는다. 결과는 최소 고정점이며 문서는 이를 말하지 않는다.
    F13(0007:47, 0002:72)의 "직전 active를 평가 순서 힌트로"는 E9 부류에서 결과를 이력에 묶는다
    — "결정적이되 임의적"(0007:57)과 충돌.
    제안: "최소 고정점"을 명시, 로드 시 원본에 값이 있는데 방출되지 않는 조건부 자식을 dev 경고·latent()로 알림,
    F13 힌트는 부정 순환이 없음을 청사진이 증명한 호스트에만.

F-3 [높음, 실행 E2·E3] 자동 쓰기(전이 주입, injectTo)는 직전 커밋 대비 에지 발화라 batch 여부에 따라 결과가 다르다.
    어디: 0008:72(batch 정의), 0007:33, 0013:41(F11), 00-goals G5(같은 쓰기 순서 → 같은 상태).
    설계는 batch를 "표시 N·정착 1"로만 적고 결과 동치 여부를 말하지 않는다. F11은 마운트에서 발화하는지도
    미정의(E3: 발화하면 로드한 tgt를 덮는다).
    제안: "batch는 중간 커밋을 없애므로 중간 에지도 없다"를 규칙으로 적거나, injectTo를 레벨 트리거로 바꾸는 안을 비교.

F-4 [높음, 문서] &derived의 정의가 둘이다.
    어디: 0007:32 "읽기 전용", 0013:41 "원본을 쓰지 않는다" ↔ 0013:82 "작성자가 명시한 쓰기", 0001:39 "값을 쓰든",
    현재 구현은 쓴다(src/core/nodes/AbstractNode/AbstractNode.ts:545-550, Overwrite|Automatic).
    원리: 쓰면 P2의 쓰는 주체 넷(MM:10)에 빠진 다섯째, 안 쓰면 P4 투영 목록(MM:12)에 없는 투영.
    제안: 하나로 정하고 MM §3 쓰기 표 또는 P4 목록에 넣는다.

F-5 [높음, 실행 E6 + 추론] 틱당 파동 상한 25가 권장 패턴과 만나면 같은 쓰기의 결과가 같은 틱의 앞선 쓰기 수에 달린다.
    어디: 0008:62, 04-inherited:12(T-4), 권장 0008:113.
    스토어 리스너 파생이면 배치 없는 쓰기 13번째부터 리스너 쓰기가 거부된다(prod 무시 → 파생 필드 stale,
    dev throw). 첫 파동도 센다면 리스너 없이도 26번째 setValue에서 닿는다. 문구가 어느 쪽인지 정하지 않았다.
    제안: 상한을 "되먹임 파동"만, 진입 사슬 단위로 센다(onChange 중첩 상한과 같은 모양).

F-6 [중상, 문서] P1′의 문언과 달리 폼이 값 유효성 문법을 형상 결정에 읽는다. 우선순위 미기재.
    어디: P1′(MM:15, 0002:26)은 required를 "읽지 않는다"로 분류 ↔ 0002:127(E17: required/dependentRequired로
    초기 분기 가중), 0005:81(판별식 선택에 required 포함 여부). 유효 스키마의 범위·enum·pattern 교차(0005:109),
    OpenAPI nullable·discriminator(0005:58·79)도 읽는다.
    제안: P1′를 세 층으로 — (i) 형상 문법, (ii) 표시 힌트로만 읽는 것, (iii) 읽지 않는 것 — 과 예외 목록.
    E17은 (i)에 넣을지 뺄지 결정 필요.

F-7 [중, 실행 E5] 예산 초과에서 dev와 prod의 수명주기가 다르다.
    어디: 0007:52(dev는 커밋 뒤 throw), REPORT-v4c §5 A5(진입 onChange·검증 생략). ADR 0008 §5에는 없다.
    D-10의 이유가 "dev와 prod 라이프사이클 어긋남"(0008:89)이었는데 다시 생긴다.
    제안: 커밋이 섰으므로 onChange·검증 요청을 먼저 내고 throw하거나, 차이를 명시.

F-8 [중, 실행 E7] "Merge는 로드가 아니다"가 배열에서 거짓이다.
    어디: MM:41, 0013:55("Merge + 억제는 무해한 no-op"), 배열 Merge = Overwrite(0013:91, 0007:132).
    Merge 안의 배열 아이템은 전체 교체라 default가 들어가고, 따라서 억제도 no-op가 아니다.
    제안: 배열 Merge를 정의할 때까지 이 두 문장을 "객체에 한해"로 좁힌다.

F-9 [중, 문서] 억제 옵션의 범위 규칙이 서로 어긋난다.
    어디: 0013:54 "리스너가 일으킨 정착은 로드가 아니다" ↔ MM:42 setValue(V)는 누가 부르든 전체 교체 → 로드.
    리스너·onChange 안의 setValue(V)는 어느 쪽인가. 0013:53 배치 안에서는 억제가 이긴다 → 관계없는 쓰기의
    로드 계약까지 꺼진다(batch 의존). 0013:51-52 마운트에는 호출 옵션이 없어 Form 속성이 기본값과 마운트 옵션을 겸한다.
    제안: 억제를 쓰기(대상 호스트) 단위로 기록하고 배치 합산을 없앤다. 마운트 전용 값을 분리할지 결정.

F-10 [중, 문서] 인터페이스 이름 충돌·불일치.
    select: 진입 목록의 쓰기 API(분기 선택, 0008:91) ↔ 명령 RequestSelect(텍스트 선택, 0008:121,
    현재 FormHandle src/components/Form/type.ts:114).
    검증 스탬프: 0001:32 "revision" ↔ 0008:84 "커밋 번호" ↔ 04-inherited:28 "revision 스탬프".
    previous: 노드 payload는 "마지막으로 통지한 값"(0008:83), onChange는 진입 시작의 emit(REPORT-v4c §1).
    node.value = local, getValue() = emit(0006:47) — 같은 "값"이 다르다.
    mode의 'Overwrite'|'Merge'(PascalCase 문자열)와 disableDefaultInjection(camelCase 불리언) 혼용(0007:71).
    진입 목록에 write·removeKey(프로토타입 이름), update·pop·clear 누락(0007:65, 04:15).

F-11 [중, 실행 E4] "같은 값이면 onChange 없음"은 참조 비교라 경로에 따라 다르다.
    어디: 0008:91, 표 0008:103("같은 값 다시 쓰기 +0").
    리스너 되돌림은 같은 값으로 onChange 1·검증 1, batch는 0.
    제안: 진입 끝 비교를 dirty 경로의 값 비교로, 또는 "참조 기준"을 명시.

F-12 [중, 문서] P5 문언과 명령·터미널 규칙의 충돌, G4와 ADR 0011의 우선순위 미기재.
    어디: MM:13 "화면의 명령도 모른다" ↔ MM:92, 0008:28·121(명령은 core 공개 API, remount는 렌더러 개념).

    터미널은 안의 if/oneOf로 형상을 만들지 않으므로(0011:27) 같은 스키마·같은 값의 방출이 입력 컴포넌트 유무로 달라진다.
    제안: P5를 "명령을 전달하되 해석하지 않는다"로, G4에 예외(소유자 선택)를 적는다.

F-13 [중하, 실행 E11] 권장된 스토어 리스너로 같은 필드를 정규화하면 키 입력마다 Refresh(=입력 리마운트).
    어디: 0008:113 ↔ 0007:77(F7 출처 규칙), T-2(04-inherited:10).
    제안: "같은 필드 변환은 입력 컴포넌트에서"를 C-10 문서에 함께 적거나, 그 입력의 진입 안에서 같은 노드에 온
    쓰기를 입력 출처로 본다.

F-14 [중하, 실행 E13 + 문서] P1′ "빼는 것은 & 명령뿐"과 & 없는 방출 정책 키.
    어디: MM:15 ↔ options.omitEmpty 기본 true(src/types/jsonSchema.ts:265-266), omitTrailing, injectTo(& 없음).

    type 에러를 낼 것(추론). 빈 호스트의 방출 규칙이 ADR에 없다.
    제안: 방출 정책 키의 이름공간과 빈 호스트 방출({} 또는 없음)을 정한다.

F-15 [중하, 문서] 쓰기 표가 상태 셋 중 raw만 다룬다.
    어디: MM:34(상태 = raw·selection·extras) ↔ MM:38-45(쓰기 표에 select·removeKey·초기 선택 없음).

    제안: 쓰기 표를 상태 셋으로 넓히고 초기 선택을 "로드 계약의 일부"로 적는다.
