# 06단계 배열 성능 기록

## 환경과 재현

2026-10-01에 커밋 `103433634`의 worktree에서 MacBookPro18,2(M1 Max, 64 GB), Darwin 25.6.0/arm64, Node.js 26.10.0/V8과 `/opt/homebrew/bin/bun` 1.4.2/JSC를 순차 실행했습니다. 스크립트 실행은 서로 겹치지 않았습니다. 패키지 루트에서 실행한 명령은 다음과 같습니다.

```sh
node --expose-gc --import tsx bench/array.bench.ts
/opt/homebrew/bin/bun bench/array.bench.ts
node --import tsx bench/node-and-settle.bench.ts
/opt/homebrew/bin/bun bench/node-and-settle.bench.ts
node --import tsx bench/derive-and-controls.bench.ts
/opt/homebrew/bin/bun bench/derive-and-controls.bench.ts
```

`TEST-032`의 배열 잎 입력은 같은 10,000개 객체 아이템 중 `/5000/key`에 `setValue`를 120회(준비 20, 측정 100) 호출합니다. 입력 시간에는 트리 생성·청사진 분석을 넣지 않습니다. 두 엔진 모두 잎의 값을 매번 확인합니다. 레거시 루트 `value`의 해당 자리 값은 동기 시점에 마지막 잎 입력과 일치하지 않아 루트 확정까지 같은 시점에 기다린 비교는 아닙니다. 루트 통째 쓰기는 1000개 객체 아이템 배열 두 개를 번갈아 `setValue`하고 루트의 500번 아이템을 매번 관찰합니다.

시간은 준비 20회 뒤 각 엔진 100표본의 중앙값입니다. 대괄호는 10–90백분위이고 단위는 µs/입력 또는 µs/쓰기입니다. 메모리는 `--expose-gc`/`Bun.gc(true)`로 GC한 별도 자식 프로세스 7개의 중앙값과 10–90백분위입니다. 입력 배열·스키마와 새 엔진의 청사진은 GC 전 준비해 차분에서 빼고, 루트 1 + 객체 아이템 10,000 + 숫자 잎 10,000 = 20,001개 노드로 나눴습니다. 잔존 트리·출력·런타임 부속 객체가 포함된 전체 트리 B/노드이며 노드 인스턴스 단독 크기는 아닙니다.

첫 기록 커밋 `648b8a124`(당시 측정 worktree `f293efe18`)의 새/레거시 중앙값은 키 입력 Node 639.96/0.959·Bun 753.62/1.042 µs, 통째 쓰기 Node 14,045.33/3,421.13·Bun 18,333.83/1,337.25 µs였습니다. 44C-01에 따라 잎 입력의 전체 슬롯 재합성과 통째 쓰기의 `dirtyChildren` 이차 순회를 고친 뒤 새 엔진 시간이 줄었습니다. 이번 계측만으로 남은 단계별 CPU 비용이나 크기에 따른 차수를 따로 증명하지는 않습니다.

각 표본의 µs를 회/s로 바꿔 평균 낸 처리량의 레거시 대비 하락은 키 입력 Node **96.57%**·Bun **95.89%**, 통째 쓰기 Node **25.36%**·Bun **74.80%**입니다. 시간 행 네 쌍 모두 Welch |t| ≥ 7.50(자유도 99–111)으로 p<0.05이며 `TEST-072`의 처리량 −15% 선도 넘습니다. 스크립트의 `meanHz`는 평균 µs의 역수여서 이 표본별 처리량 평균과 다릅니다. 메모리는 두 런타임 모두 레거시보다 작습니다. 비례하지 않는 비용의 수정은 44C-01로 닫고, 남은 느린 두 시간 행은 [속도 문제 대장](../performance-issues.md)에 기록했습니다. `TEST-027`·실행 계획 I18에 따라 **NODE-053은 소유자 수용 대기**입니다.

잎 입력에는 새 엔진의 호출별 동기 정착·배열 출력 갱신 비용이 남습니다. 레거시의 잎 값 관찰은 루트 확정까지 기다리지 않으므로 배율만으로 동등한 커밋 비용을 단정할 수 없습니다. 루트 통째 쓰기에는 1000개 아이템 노드의 위치별 값 쓰기와 정착 비용이 남습니다. 두 경우 모두 이번 계측은 단계별 CPU 시간을 분리하지 않았습니다.
