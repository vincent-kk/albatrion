## Why (diagnosis `/Users/Vincent/Workspace/albatrion/.seiri/tasks/bulk-setvalue-441/diagnosis.md`, read it first)

A root `setValue` with every leaf changed on nested-d6 costs 15.6 ms (0.16.1: 3.0–4.6 ms). Confirmed root cause: in a gate-less settlement the `DirtyPathSet` is still in its general index mode while `markWrite` adds the written paths (`src/core/engine/settle/utils/scratch/DirtyPathSet.ts:61-84`), so every path registers an entry under every ancestor prefix (two slices and a Map update per level); the very next `registerRecalculation` calls `beginPostOrder()` (`registerRecalculation.ts:17-18`), which clears that index and rebuilds the direct-edge index, and no code reads the general index in between. The wasted work is O(depth) per written path: `DirtyPathSet.add` 3.26 ms of the 15.6 ms; `add`+`beginPostOrder`+`delete` together 35 %. Counterfactual on a bundle copy: nested-d6 15.41 → 11.93 ms (−23 %), flat-2000 −10 %, nested-d3 −12 %; delivery order, payloads and final values of 11 writes on three forms identical (319-line record, same hash). Call counts of every phase equal the changed-node count (5,461), so no tree-proportional phase exists; the remaining ~11 ms is spread over per-node bookkeeping with no dominant function (later hypotheses).
