## Why (diagnosis `/Users/Vincent/Workspace/albatrion/.seiri/tasks/bulk-setvalue-441/diagnosis.md`, read in full; fix 1 is already merged, fix 3 is out of scope)

A root bulk `setValue` on nested-d6-f4 (4,096 leaves) costs 11.86 ms against 0.16.1's 2.98 ms (round-442 three-tables window). The diagnosis attributes about 0.85 ms (−7 %) to `src/core/engine/settle/utils/compute/utils/computeStableNode.ts:28`: after a stable node is recalculated it removes its own path from the dirty set by slicing the parent map per path (`context.dirtyPaths.delete(node.path)` walking `dirtyChildrenByParent`). Since the children were already consumed in post-order and the `recalculated` list is fixed before the loop, the node can remove its own entry from the set and drop its own `dirtyChildrenByParent` entry in one call. This belongs on `DirtyPathSet` as a `consume(path)` method (see the diagnosis, "수정 2"). Post-PR-3 the dirty set also carries split anchors and representative counts (`settle/utils/dirty/DirtyPathSet.ts`, `DirtyPathSet.split-anchors.test.ts`, `settle/DETAIL.md` 3.3); `consume` must keep those exactly as `delete` would for a path whose children are already consumed (anchor representative decrement rules unchanged, `releaseSplitMember` only when the path is a split member).

Observable behaviour must be identical: the dirty set after each `computeStableNode`, every `dirtyChildren` result (members and order), deliveries and warnings.
