## Hypothesis (from the round-439 nested-mount diagnosis, verifier-confirmed)

`validateChildTargets` (`src/core/engine/blueprint/validateChildTargets/validateChildTargets.ts`, called at `blueprint.ts:79`) iterates every node and every declaration on every mount, but it can only throw when some declaration's `controls.discriminator` or `controls.fields` is defined. Declarations are created at exactly one place, `src/core/engine/blueprint/buildNodes/utils/declarations/collectDeclarations.ts:91-106`, and that site is reached for fragments, `$ref` overlays and virtual declarations (`populateVirtualNodes.ts:83` reuses existing declarations). Non-array `fields` are rejected earlier by `validateControlGroups.ts:68-69`. Therefore recording a monotonic flag "some declaration has discriminator or fields" at the creation site and calling `validateChildTargets` only when the flag is set yields byte-identical behavior: the same errors in the same order when the flag is set, and no error possible when it is not. Expected saving at nested d6 mount ≈0.33 ms (≈1 % of the mount; the function's d6 self time), i.e. small; the PR is about removing a named inefficiency with no slowdown, like #425/#426.
