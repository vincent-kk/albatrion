# 자식 있음 변경을 읽는 게이트와 상태 키의 재평가 결과

raw 쓰기 없이 자식이 방출 형상에 들어오거나 나가면 그 경로를 읽는 다른 게이트·상태 키가 낡은 형상을 유지하던 결함을 수정했습니다. 호스트 바퀴 안에서 이름별 노드 정체의 변화를 등록하는 설계 C와 브리프 수정 A~C를 적용했습니다. 첫 창 후보는 `d4bde8625`, 기준은 `d9b30dec7`이며, 검증자 지적을 반영한 4.5절 보완 후보는 `b03f0fbfa`입니다. 게이트 배열 1,000개 마운트에는 측정상 비용 증가가 있으며, 성능 수용과 병합은 Vincent의 결정으로 남깁니다.

## 결함과 설계

기존 재계산 등록은 changedRaw만 보았습니다. 잠복 raw가 유지되는 게이트 퇴장·재진입과 setContext는 raw 쓰기 없이 방출상 있음을 바꾸므로 읽는 쪽이 다시 평가되지 않았습니다. 새 동작 시험은 같은 최종 원본·맥락의 새 마운트와 emit, 있음, active, visible, readOnly, disabled, diagnostics.status, 살아 있는 노드의 committedDeclarationIds를 비교합니다.

자식 선택 직후, 남은 dirty 자식을 계산하기 전에 이전 라운드 끝의 lastStructure와 현재 구조를 비교합니다. 첫 변화 뒤에는 `|| registered`로 바퀴 끝까지 비교를 유지합니다. 변경 경로와 접두는 정착 문맥에 누적하고 새 경로의 접두만 더합니다. 게이트 없는 문맥은 등록에서 즉시 돌아옵니다. load 범위 안 조상은 이미 형상 dirty이므로 집합 조회로 질의를 끝내며, 범위 위 조상은 필요한 경우 질의합니다.

진행 중 호스트나 그 조상을 읽는 하위 소유자와 바뀐 하위 트리 안의 소유자는 설계의 두 제외 규칙을 따릅니다. 앞 규칙에서 빠진 상태 키 소유자만 최종 공표 때 평가합니다. 형상 dirty가 아니던 조상은 등록 계수가 달라질 때만 직접 자식을 다시 고르고, 이미 계산한 자식이 다시 필요하면 기존 예산의 바퀴로 넘깁니다. 반복은 새 직접 자식을 계산하거나 바퀴로 넘기거나 계수가 그대로여서 끝나며, 빈 배치에서는 반드시 끝납니다. 배열 append·pop·splice 재사용의 있음 변화는 기존 raw 쓰기 등록이 맡고, 다음 라운드의 새 자식은 첫 표시 자리에서 잡습니다.

## 기존 정정과 열린 항목

코디네이터 분류 J-38에 따라 기존 relocated 시험의 `added`만 두 경우 모두 true로 정정하고 마운트·갱신 뒤 p.child가 P임을 단언했습니다. 이는 SETTLE-020·045의 늦은 사촌 재평가 정정입니다. 다른 기존 기대값은 바꾸지 않았습니다.

overlay가 omitEmpty·omitTrailing·type을 바꿔 있음은 그대로이고 방출만 바꾸는 읽기 누락은 알려진 남은 결함입니다. 처음 locate한 옮긴 게이트에서 선언 호스트까지의 경로 재계산도 있음 변화 없이 값만 바뀌는 경우 별도 확인이 필요합니다. 가상 노드의 새 읽기 전용 장면은 추가하지 않았으며 기존 전체 시험의 통과를 그 부류의 전수 증명으로 확대하지 않습니다.

설계자가 지적한 조상 dirty 반복의 틈도 열린 항목입니다. 조상의 dirty 자식 반복에서 이미 지나간 자식이 다시 dirty가 되고 해당 라운드의 출력이 바뀌지 않으면 그 자식이 남을 수 있으며, 즉시 표시하던 PR에도 존재하는 경로입니다. 아직 재현하지 못했으므로 해결되었다고 주장하지 않습니다.

## 보완 — 원래 감시 경로와 호스트별 대기

검증자의 CONDITIONAL PASS 조건 C1~C5와 설계 4.5절을 적용했습니다. 지적 1의 제곱 비용은 접힌 소유자의 원래 감시 경로를 보존하는 필터와 정적 호스트별 템플릿 대기의 조합으로 제한했습니다. raw affected의 접기는 그대로입니다. 제외 규칙은 등록 경로의 가장 깊은 사슬로 재현하며, 제외된 배열 전체 읽기 상태 키는 최종 트리에서 평가합니다. 루트 계산 직후 undefined-host flush가 모든 잔여 대기를 펼칩니다(C1). owesTemplates만의 효과를 독립적으로 검출하는 장면을 확보하지 못했으므로 C2의 명시적 대안에 따라 skip/stop 조건은 전혀 바꾸지 않았습니다. 대기 등록은 boolean을 반환하며 계수는 record 모드의 형식화된 presenceMetrics.ownerInsertions에만 둡니다(C4).
