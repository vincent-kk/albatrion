# nextExtras own key 추적 결과

가설 N은 이미 복사한 결과 객체에 `Object.keys(result)`를 다시 적용하여 빈 결과인지 확인하던 열거를 제거하는 것입니다. 복사 중 실제 own key가 생성됐는지를 호출별 boolean으로 기록하고, own key가 없으면 기존처럼 `undefined`를 반환합니다. 네 게이트와 Node·Bun 관측 동등성은 통과했습니다. 측정의 바퀴별 방향 불일치와 0 교차는 아래 표에 그대로 남깁니다.

## 비효율과 호출 경로

기존 구현은 결과를 복사한 다음 결과 키 배열을 만들어 길이만 확인했습니다. 변경 후에는 Merge의 기존 키 복사와 입력 키 복사 양쪽에서 쓰기 직후 `hasOwnProperty(result, name)`을 확인하며 첫 own key 이후에는 `||=`의 우변을 평가하지 않습니다. 보조 함수는 패키지 지침에 따라 `@winglet/common-utils/lib`의 기존 함수를 사용합니다. `Object.hasOwn`을 직접 사용한 첫 타입 검사는 현재 라이브러리 설정 때문에 실패하여 이 동등한 보조 함수로 수정했습니다.

속도 비용은 첫 own key가 생길 때까지 쓰기별 O(1) 확인이며, 결과 키 배열의 O(K) 재열거를 없앱니다. 전체 복사·같은 값 비교는 기존대로 남습니다. 메모리는 호출별 boolean 하나이고 보유 캐시·노드 필드·별칭은 추가하지 않습니다. `__proto__`의 own data property 쓰기와 같은 값의 이전 참조 되살림을 유지합니다. 동결된 own data를 상속 setter가 흡수하는 경우에도 실제 own key가 없으므로 `undefined`입니다.

호출자인 `markWrite`, `loadStaticFirstTree`, `distributeLatentValue`, `distributeMovedLatentInput`과 배열 대응 함수 `arrayExtras`는 변경하지 않았습니다. `assembleObject`와 pristine-input 계약도 그대로입니다.
