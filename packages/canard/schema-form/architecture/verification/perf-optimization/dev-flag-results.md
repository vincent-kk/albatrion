# Node 조건 산출물의 개발 플래그 검증 결과

결정 61의 후보 5를 HEAD `0645705c1` 기반으로 구현하였습니다. 소스의 호출 자리 비교와 기본 ESM은 그대로 두고, Node가 고르는 ESM과 CJS에 빌드 시점 단일 플래그를 넣었습니다. 기본 ESM은 변경 전 이 작업 트리의 빌드와 바이트가 같습니다.

## 선택한 형태와 PR430의 문제

esbuild 0.25.9 기준 관찰에서 import 문이 있는 ESM 파일의 최상위 상수는 인라인되지 않았습니다. PR430처럼 호출 자리의 비교를 소스 모듈 상수로 옮기면 esbuild production minify 뒤에도 개발 코드가 남습니다. 소스의 bare 비교와 lint 규칙을 유지해야 하는 이유입니다.

`node` export 조건은 import에 `index.node.mjs`, require에 `index.cjs`를 선택합니다. 기본 import는 `index.mjs`입니다. Node ESM 첫 줄과 CJS의 `"use strict";` 다음 줄에 `const __SCHEMA_FORM_DEV__ = process.env.NODE_ENV !== "production";`을 놓고, 해당 두 빌드에서만 비교를 플래그로 치환합니다. 공용 번들러는 바꾸지 않았고 세 출력 모두 `minify: false`입니다.

| 파일 | bytes | NODE_ENV 토큰 | 플래그 토큰 | PURE 주석 |
| --- | ---: | ---: | ---: | ---: |
| index.mjs | 684129 | 43 | 0 | 456 |
| index.node.mjs | 683423 | 1 | 44 | 456 |
| index.cjs | 701414 | 1 | 44 | 456 |

Node ESM의 선언을 지우고 치환을 역변환하면 기본 ESM과 바이트가 같습니다. 세 개발 표식도 모두 남습니다. 빌드 검증은 이 형태, 주석, 표식, directive 부재와 Node import/require 해석을 확인하며, 번들러 접힘은 아래 별도 실험으로 확인합니다. 설계 문서의 실험과 이번 HEAD는 절대 번들 크기와 PURE 수가 다르므로 이번 빌드의 수치를 사용합니다.

## 소비자별 파일과 의미

| 소비자 | 기본 선택 | 환경 판정 시점 |
| --- | --- | --- |
| Node import, tsx, 외부화된 Vite SSR | index.node.mjs | 적재 때 1회 |
| Node require, CJS 소비자 | index.cjs | 적재 때 1회 |
| esbuild·rolldown browser, Vite client, webpack web의 ESM | index.mjs | 호출 자리 비교를 소비자 define으로 접음 |
| esbuild·rolldown node, webpack node의 ESM | index.node.mjs | 적재 시점 값 또는 소비자 define |
| source 조건을 명시한 소비자 | src/index.ts | 소스의 호출 자리 비교 |

Node/CJS 소비자는 적재 뒤 NODE_ENV를 바꾸어도 진단 여부가 바뀌지 않습니다. import 이후의 vitest `vi.stubEnv`, Jest, tsx, Vite SSR에서 이 차이를 고려해야 합니다. define도 process도 없는 호스트는 CJS와 Node 산출물에서 적재 때 실패하며, 기존에는 첫 호출 자리에서 실패했습니다.

CI workflow의 benchmark-form은 이제 index.node.mjs를 적재하므로 병합 뒤 첫 CI 벤치마크가 새 기준선입니다. 플러그인 일곱 개의 vitest jsdom 시험은 이 적재 경로의 smoke 시험으로 기록하며, ESM 사본 두 개의 동일성이나 중복 적재 부재를 증명하는 시험으로 해석하지 않습니다.

## 검증과 한계

- build와 build:verify, 선언 생성, 패키지 typecheck가 통과하였습니다. 새 buildOutputs 회귀 시험은 변경 전 빌드에서 Node 산출물 부재로 실패하고 새 빌드에서 통과하였습니다.
- 일반 시험은 785파일·5050시험 통과, todo 1개이며 production 시험은 9파일·20시험 통과입니다. 첫 일반 실행의 EVENT-065 IME 15초 timeout은 425C-02에 따라 따뜻한 단독 재실행 1회에서 통과한 뒤, 조용한 전체 재실행도 통과하였습니다. 시험 코드와 timeout은 바꾸지 않았습니다.
- ajv6·ajv7·ajv8·antd5·antd6·antd-mobile·mui smoke 시험은 79파일·645시험이 통과하였습니다. 새 작업 트리의 자체 dist 부재 때문에 ajv6 첫 실행이 실패한 뒤, 허가받아 일곱 플러그인을 빌드하고 재실행하였습니다.
- 루트에는 lint 스크립트가 없어 첫 명령이 실패하였습니다. 코디네이터가 대체로 허가한 `yarn workspace @canard/schema-form lint`는 통과하였습니다.
- 측정 동안 다른 벤치마크·빌드·시험은 없었으나 메인 트리 원장 문서 워커의 파일 편집과 짧은 Node 검사, CPU 작업 중지를 지시받은 읽기 전용 Claude 검증자, OS·IDE·MCP 상주 프로세스가 남아 있었습니다. 간섭량은 별도로 계측하지 않았습니다.
- 한 기기·한 production 창의 엔진 마운트 시간입니다. React·DOM 렌더링, 실제 검증기 비용, 다른 런타임과 시스템 부하를 대표하지 않습니다. A′ 폭은 신뢰구간이 아닙니다.
