# 결정 62 PR-1 — 자식 선택 단계 추출과 기준 특성화

후속 값→분기 표 고리가 현재 선택기와 같은 엔트리 처리를 재사용하도록 `selectEntryStep`을 추출했습니다. 게이트 평가 순서와 자식 선택·되살림·잠복 분배·배달 계약을 유지합니다. 추출 전 제품 소스 `394c284a7`에서 초기 38개 스냅숏을 고정했고, 아래 보완에서 같은 추출 전 소스를 가진 `e73d162db`에 두 장면을 더해 40개 기준을 재캡처했습니다.

## 선택 단계

구현은 `src/core/engine/settle/utils/compute/childSelection/selectEntryStep.ts`입니다. 기존 보조 파일들과 같은 구획에 배치했습니다.

```ts
selectEntryStep<Self extends FieldNodeRecord<Self>>(
  entry: BlueprintChildEntry,
  step: DirectChildSelection | undefined,
  frame: ChildSelectionFrame<Self>,
): void
```

`entry`는 후보 간선, `step`은 준비된 게이트와 선언 ID입니다. 호출당 한 번 만든 `frame`으로 호스트·정착 문맥·직전 형상·계산 콜백·즉시 계산 및 읽기 공표 플래그·현재 구조·이름별 수용 기록·비활성 엔트리·누적 변경 여부를 넘깁니다. 함수의 JSDoc에 각 입력과 효과를 기록했습니다. 기존 `DirectChildSelection` 형은 정의한 파일에서 type-only 소비가 가능하게 export했습니다.

루프는 엔트리와 준비된 단계를 정한 뒤 이 함수를 부릅니다. 문맥의 효과는 원래 위치에서 실행하고, 지역 변경 플래그는 `frame.changed`에 누적하며, 바깥 고리의 `continue`는 보조 함수의 `return`으로 대응합니다. 이 두 치환을 정규화한 TypeScript AST leaf-token 순서가 같습니다. 검사 문맥을 포함한 토큰 수는 1,709개입니다. 공표·비활성 입력 분배·퇴장 대기 등록·자식 목록 조립의 후처리는 원래 고리에 있습니다.

추가 할당은 일반 선택 호출당 frame 객체 하나이며 엔트리별 추가 frame은 0개입니다. 기존 배열 재사용·정적 형상·가상 호스트의 조기 반환 경로를 유지합니다. 전체 엔트리 순회와 게이트 평가 수의 복잡도는 그대로입니다. 파일명으로 호출 지점을 찾는 기존 두 계수 시험의 필터에는 새 보조 파일을 포함했습니다.
