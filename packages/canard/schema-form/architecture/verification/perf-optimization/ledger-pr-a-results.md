# Ledger bundle A — 후보 Set 복사 없는 커밋 방문 결과

2026-10-22 기준으로 C1을 채택했습니다. 현행 기울기 폭 (가)에서 bulk-flat과 bulk-nested가 모두 감소 입증이며 어느 가족·행에도 입증(느림)이 없습니다. 완전한 라운드만 쓰는 폭 (다)에서도 두 가족이 빠름입니다. 부분 라운드를 혼합한 폭 (나)는 두 가족 모두 미입증이며 이를 채택 근거로 쓰지 않습니다.

## 최종 범위와 메커니즘

- C1만 구현했습니다. C2는 제외했고 C5는 보류했습니다. EVENT 계약, 청사진, markWrite, DirtyPathSet, updateOutput, finishSettlement, 게이트 계산, 공개 수출을 바꾸지 않았습니다.
- 기존 global-state 합집합 대신 departing → entered → changedNodes → stateDirtyNodes → load 원본을 직접 순회합니다. 앞선 원본의 기존 membership에 있으면 건너뛰고 빈 Set에는 has를 호출하지 않습니다. required 자식·루트·경로 변경·감시자·사전 표시의 추가 후보만 별도 Set에 남겨 마지막에 순회합니다.
- 원래 global-state 후보 집합은 이 다섯 원본의 첫 등장 순서입니다. 배달 후보의 changed·entered·stateDirty는 모두 그 집합에 포함되므로 추가 후보에서 세 원본을 복사하지 않아도 최종 추가 방문 순서는 같습니다. departing·load 출신만 추가 후보와 세 원본으로 배달 membership을 확인합니다. 추가 단계의 global-state 방문은 원래 무동작이므로 생략합니다.
- global-state 증감·출입·load 처리는 모두 유지합니다. 방문 도중 원본 집합을 바꾸거나 사용자 코드를 부르지 않는 현재 커밋 경로에서 이 순회가 성립합니다. 사건 표시·비트 개정·payload·문서 순서 배달을 유지합니다(EVENT-006·007·024·071, SETTLE-017, settle DETAIL 184·457·523).
- 노드 도장·고정 필드·상주 캐시·재사용 후보 배열을 추가하지 않았습니다. 노드당 추가 슬롯은 0이며 커밋마다 남는 상수 할당은 참조 6개의 임시 원본 목록과 비어 있지 않은 원본마다 하나씩의 Set iterator(최대 6개, 기준은 2개)입니다. departing 집합과 load의 방문 집합은 유지합니다. 시간은 O(G+C), 추가 후보 이외의 합집합 보관은 제거했습니다. heap 바이트 절감 실측을 주장하지 않습니다.

## C5 보류

deliveries는 파동마다 교체되고 채택 때 이전되지만 revisionNodes는 커밋 끝에 비워집니다. 정상 제품 흐름의 방문 전 required 표시는 이미 후보에 같은 순서로 들어가므로 단순 삽입 순서 예시만으로 제품 반례를 주장하지 않습니다. 별도 membership이 필요한 경우는 커밋 밖 직접 표시와 예외 잔여물입니다.

deliveries를 pendingRevision으로 걸러 커밋마다 순회하면 한 파동에 누적된 과거 커밋 노드를 반복 방문하여 이번 정착 범위만 순회하는 SETTLE-017을 어깁니다. 파동이 deliveries를 비워도 revisionNodes 잔여물이 남을 수 있습니다. 공유 표시 구간 등 새 작업 수명은 추가하지 않고 두 장부를 유지했습니다.

## 제품 변경 전 특성화와 비용 검증

DETAIL 문서 커밋을 먼저 만들고, 기존 코드에서 특성화 9건이 통과하는 것을 확인한 뒤 제품을 변경했습니다. 추가 장면은 bulk 순서, gated 임의 state key, 기존 트리 load, required만 바뀐 자식, changedNodes 밖 root diagnostics, 경로·맥락·영향 감시 중복과 detach, 앞 리스너가 시작한 다음 정착, 예외 뒤 다음 커밋, departing 정리입니다. Node/Bun 비교와 기존 dirty-postorder fixture도 그대로 유지했습니다.

4노드 bulk 장면의 Set.add 호출은 17→1회, 단일 detach 장면은 4→3회입니다. 두 비용 시험은 변경 전에 각각 그 차이로 실패했습니다. 후보 복사를 한 부분씩 복구하자 추가 후보 복구는 9 대 목표 1로, global 복구는 9 대 1 및 detach 4 대 3으로 다시 실패했습니다. 변이를 제거한 뒤 비용·dirty-postorder 7건이 통과했습니다. 실행 도구를 위한 시험 import는 write 내부에서 기존 진입점의 dispatchBatch로 수정했습니다.
