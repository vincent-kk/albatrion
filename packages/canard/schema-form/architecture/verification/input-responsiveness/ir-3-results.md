# IR-3 — AJV8 동기 우선 컴파일 사전 측정

2026-10-31. 결과는 **not adopted(미채택)**입니다. flat-2000의 오류 검증·이슈 변환 중앙값은 55.73% 감소했지만 정상 비용이 7.50% 증가하여 사전 등록된 정상 +5% 상한을 넘었습니다. Step 0에서 중단했으며 제품 변경과 Step 1·2는 수행하지 않았습니다.

## 입력과 방법

- 기준은 `e01cfcd7bb93b977603c3bbd837ef1f9646fe114`이며 Node v24.20.0, arm64, 플러그인 로컬 AJV **8.17.1**을 사용했습니다.
- IR-2의 `getHeavyValidationFixture`와 실제 플러그인의 `transformErrors`를 직접 불러왔습니다. AJV 옵션은 현재 기본값인 `allErrors: true`, `strictSchema: false`, `validateFormats: false`, `allowUnionTypes: true`입니다.
- 동일 스키마 복제본을 현재 방식인 `$async: true`와 동기로 각각 컴파일했습니다. 비동기 경로는 `await validate`의 오류를 잡고 동기 경로는 `validate.errors`를 읽습니다. 컴파일·데이터 생성 시간은 측정하지 않았습니다. 각 경로의 검증만 수행한 값과 실제 이슈 변환까지 포함한 값을 별도로 기록했습니다.
- 정상 입력은 스키마 기본값으로 채우고 편집 잎을 `ab`로 설정했습니다. 배열은 같은 잎 스키마가 모든 항목에 적용되므로 기존 이름 중 홀수 길이에 `x`를 붙여 전체를 정상으로 만들었습니다. 오류 입력은 대상 잎 하나만 `a`로 변경했습니다. 동기 검증으로 정상 true, 오류 false 및 오류 한 개를 확인했습니다. 따라서 이 배열 입력은 IR-2의 원래 기본값 전체를 그대로 둔 브라우저 타이핑 입력과 같지 않습니다.
- 셀별 1,000회 예열 후 250호출 × 21라운드, **5,250호출**을 보존했습니다. 세 스키마 × 두 모드 × 정상/오류 × 변환 포함/미포함의 24셀, 총 **126,000호출**입니다. 모드 순서는 라운드마다 정순/역순으로 교대했습니다. 단위는 µs이며 각 호출의 벽시계를 측정하고 전체 보존 호출에서 nearest-rank 중앙값·p95를 계산했습니다. 비동기 수치에는 await·catch 비용이 포함됩니다.
- 정식 측정은 UTC 18:40:24.874–18:40:39.710에 단독 실행했습니다. 측정 중 빌드·시험·lint·다른 명령을 실행하지 않았습니다. 시작 전 UTC 18:39:54.718–18:40:24.874의 30.152초 누적 CPU 관찰은 첫 시도에 통과했습니다. 제외 조상을 뺀 PID 중 평균 30% 초과가 없었으며 최상위 외부 PID는 mds 25.77%였습니다. OS·상주 프로세스의 무부하를 보증하는 관찰은 아니며 창 내부 CPU 별도 샘플러는 두지 않았습니다.

### 사전 등록 결정

진행 조건은 flat-2000의 **오류 변환 포함 비용 30% 이상 감소**와 **정상 비용 증가 5% 이하**를 함께 만족하는 것입니다. 비교 통계는 위 호출 중앙값입니다.

| 조건 | async → sync | sync/async | 결과 |
| --- | ---: | ---: | --- |
| 오류 변환 포함 30% 이상 감소 | 85.084 → 37.667µs | 0.442704 (−55.73%) | pass |
| 정상 비용 증가 5% 이하 | 35.000 → 37.625µs | 1.075000 (+7.50%) | fail |

두 번째 조건 실패로 **not adopted**입니다. 통과할 때까지 반복 측정하지 않았습니다. 변환 포함 flat-2000의 라운드 중앙값 범위는 sync 정상 37.250–40.125µs, async 정상 24.375–40.250µs, sync 오류 37.334–39.542µs, async 오류 79.959–87.333µs입니다. 끝의 5라운드 정상 중앙값은 sync 37.250/37.375/37.292/37.375/38.083µs, async 34.833/34.917/34.875/35.084/35.083µs였습니다. 라운드별 변동과 중첩의 긴 꼬리는 원시에 그대로 보존했습니다. 이 결과는 이 Node 창의 채택 기준에 대한 결과이며 Chromium 성능이나 회귀 기전의 인과 증명이 아닙니다.
