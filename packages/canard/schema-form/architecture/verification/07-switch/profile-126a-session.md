## 측정 절차와 입력의 고정

각 설정은 아홉 회차이며, 회차마다 두 비교 블록을 ABBA 또는 BAAB 순서로 실행했습니다. 한쪽당 두 개, 회차당 네 개의 새 측정 프로세스를 순차 실행했고, 측정 프로세스마다 번들 하나만 올렸습니다. 따라서 각 행은 18개 비교 블록의 1,818개 대응 표본입니다. 공식 행 92개와 고정 분기 축 12개를 합친 104개 판정 행을 측정했습니다.

각 프로세스의 예열은 20회, 본 표본은 101개였습니다. 강제 GC는 시계 밖에서 실행했고 GC 뒤 첫 빈 호출 쌍을 버렸으며, 같은 큐의 paired sentinel tail을 유지했습니다. ON 경로의 두 차례 sentinel과 프로세스별 (ga) 검사를 유지했습니다. 값 digest는 설정 내 모든 회차와 양쪽 프로세스 사이에서 일치했습니다.

두 쪽에 동일한 검증 경로별 pooled 빈 호출 종단 중앙값을 호출 수에 맞춰 빼고 음수 clipping은 하지 않았습니다. A/A의 OFF·ON 보정값은 15.083µs·29.625µs였습니다. 1c의 보정값은 [1c JSON](profile-126a-session/core-head-1c.json)의 calibration에 기록했습니다. 대응 차이에서는 동일한 보정 상수가 상쇄됩니다.

모든 구간은 원본 report-verdict-121.mjs의 pairRows121을 통해 seed 101, xorshift, 1,999회 재표집, nearest-rank 99% pooled 대응 중앙값 bootstrap으로 계산했습니다. 차이는 기준−변경이며, 음수는 1c가 느려졌음을 뜻합니다.

제공된 c-head.cjs·c-headx.cjs·c-1c.cjs는 S/bundles와 S/bundles-126에서 각각 바이트가 일치했습니다. 원본 매니페스트의 빌드 리비전은 `439fda3219ec6b42efbef4d7fa0f02a40111453f`이며 작업 트리 HEAD와 다릅니다. 세션 전용 메모리 로더가 이 원본 리비전과 매니페스트 SHA-256을 검증하도록 연결했고, 제공된 번들의 바이트를 그대로 측정했습니다. c-headx는 c-head에 끝 주석 한 줄을 붙인 사본입니다.

같은 로더가 no-gc 기록 선택기만 확장해 if-then OFF/ON의 mount·update·update-later를 추가 기록했습니다. 공식 강제 GC 열의 시계·GC 위치·작업 순서는 원본 그대로입니다. 첫 쓰기 27개 행과 if-then의 여섯 추가 행을 합쳐 본 측정에서 no-gc 33개 열을 수집했습니다. no-gc는 강제 GC가 없는 두 번째 전체 순서이며, 자동 GC가 발생하지 않는다고 주장하는 열이 아닙니다.

번들에 @winglet/common-utils/scheduler 외부 import가 없으므로 (ga)의 경계 계수는 구조적으로 0입니다. 실제 시간 대조는 paired sentinel과 microtask 종단의 차이에 기반한다는 하네스 126의 한계를 유지합니다.
