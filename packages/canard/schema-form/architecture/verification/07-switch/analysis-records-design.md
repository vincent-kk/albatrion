### 분모와 계수의 뜻

`N`은 청사진 노드 수, `E`는 이름을 가진 자식 entry 수, `F`는 선언 기여 및 조각 수, `B`는 자식을 만드는 object 호스트 수입니다. 이 세 폼에는 배열·가상·union 노드와 `$ref` 재사용이 없으므로 작성 위치마다 노드가 하나 생깁니다. nested는 깊이 5, 폭 4이므로 `N=1+4+16+64+256+1024=1365`, `B=341`, `E=1364`, `F=1365`입니다. flat은 `N=501`, `B=1`, `E=500`, `F=501`입니다. 실제 생성기는 `packages/aileron/benchmark-form/src/fixtures/scale-schemas.ts:18`, `packages/aileron/benchmark-form/src/fixtures/scale-schemas.ts:36`, fixture 연결은 `packages/aileron/benchmark-form/fixtures/equivalent/mounts.ts:64`에 있습니다.

여기서 oneOf-20은 일반 scale-schema의 oneOf 생성기가 아니라 측정 driver의 폼입니다. root, common, kind 및 20×3 payload로 `N=63`, `E=62`, `B=1`입니다. root의 기본 기여와 20개 gated overlay를 포함해 `F=83`이고, 활성 게이트와 컴파일된 active 식은 각각 20개입니다. 조각의 자식 목록이 비어 있지 않은 호스트는 root와 분기 조각 20개로 21개입니다. 입력 정의는 `packages/canard/schema-form/architecture/verification/07-switch/tools/profile-99c01.mjs:137`, 게이트 생성은 `packages/canard/schema-form/src/core/blueprint/utils/analyze/collectDeclarations.ts:47`, 식 생성은 `packages/canard/schema-form/src/core/blueprint/utils/analyze/compileBlueprintExpressions.ts:77`입니다.

표의 셀은 `mount당 생성 수 / N`입니다. 예를 들어 `1364/1365`는 0.9993개/node입니다. 기록·배열은 각각 하나로 세고, 배열 원소와 작성된 스키마 자체는 새 분석 객체로 세지 않습니다. 문자열·함수·iterator·V8 backing store는 뒤의 소스 family 표본 표에 남깁니다. 따라서 이 표의 합을 173.4에서 직접 빼면 안 됩니다. 101 자료도 함수 안의 record·array·iterator별 표본 분해를 제공하지 않습니다. 근거는 `packages/canard/schema-form/architecture/verification/07-switch/profile-101-alloc.md:11`입니다.

## 변경 후의 권위 기록과 공개 view

권위 기록은 작성 위치의 기여를 나타내는 기존 PropertyDeclaration입니다. 별도의 metadata 객체를 하나 더 붙이지 않습니다. schema, schemaPath, context, role, scope, inherited, 원본 hostPath, declaration ID, fragment ID 및 완성된 order/gates를 여기에서 한 번 결정합니다. 조각 view는 이 결정된 값과 자기 소유 membership 목록을 읽어 한 번 만드는 평범한 객체입니다. node view는 기존 노드 ID·종류·전략과 선언 참조 목록을 한 번 갖습니다. 물리적으로 공개 node/fragment 객체를 없애거나 서로 같은 객체로 합치는 설계는 아닙니다. 기존 칸의 차이는 `packages/canard/schema-form/src/core/blueprint/type.ts:45`, `packages/canard/schema-form/src/core/blueprint/type.ts:77`, `packages/canard/schema-form/src/core/blueprint/type.ts:103`에 명시되어 있습니다.

구성 순서는 기존 ID 및 진단 방문 순서를 유지합니다. 먼저 입력의 gate/order를 완성하고 기여·조각 ID를 기존 순서로 예약한 뒤 원본 선언과 조각 view를 만듭니다. 선언을 종류별로 배정할 때 validationOnly가 달라지는 경우는 기존처럼 별도 공개 view를 유지합니다. 자식 입력은 eager Object.entries snapshot과 부모 declaration ID를 분석별 slot 벡터에 저장하고, name별 Map에는 객체 목록 대신 숫자 slot 연결을 넣습니다. 현재의 그룹 삽입 순서를 따라 slot을 읽어 깊이별 cursor를 설정한 후 key 조회를 먼저 하며, cache miss 때만 새 기여를 생성합니다. cursor를 자식 재귀에 맞춰 덮어쓸 때 부모 상태는 부모 frame에 남기고, mutable slot 벡터와 frame은 청사진에 출판하지 않습니다. 기존 ID 생성과 cache-hit 생략 근거는 `packages/canard/schema-form/src/core/blueprint/utils/analyze/collectDeclarations.ts:62`, `packages/canard/schema-form/src/core/blueprint/utils/analyze/collectDeclarations.ts:77`, `packages/canard/schema-form/src/core/blueprint/utils/analyze/buildNodes.ts:44`, 이름별 입력 순서는 `packages/canard/schema-form/src/core/blueprint/utils/analyze/populateNodeChildren.ts:87`, `packages/canard/schema-form/src/core/blueprint/utils/analyze/populateNodeChildren.ts:160`입니다.

새 cursor frame은 각각 H개이고, slot의 parent ID·source 위치·next 연결을 담는 작업 벡터 세 개와 static policy 기록 한 개는 분석당 한 번만 만듭니다. static policy는 분석 시작 시 `Object.freeze`한 뒤 여러 병합 호출에 전달하며, callback 참조는 기존 입력 참조를 유지합니다. mutable cursor와 세 작업 벡터는 해당 분석 호출만 소유하며 view나 결과에 노출하지 않습니다. 이 세 종류만의 추가 생성 예산은 `(H+4)/N`, 즉 nested 10/1365, flat 6/501, oneOf 6/63개/node입니다. 앞 표의 방문 벡터 1개와 깊이별 반환 벡터 H개까지 더한 기본 scratch의 합은 `(2H+5)/N`, 즉 17/1365, 9/501, 9/63개/node입니다. 이 세 폼에는 가상 그룹이 없습니다. 일반 폼의 가상 그룹에는 새 반환 배열이나 즉시 만든 복사본을 주며, node.declarations로 보존되는 배열은 공개 목록의 생성량에 계수하고 scratch 한도로 흡수하지 않습니다. 보관·추가·동결 경로는 `packages/canard/schema-form/src/core/blueprint/utils/analyze/populateVirtualNodes.ts:75`, `packages/canard/schema-form/src/core/blueprint/utils/analyze/populateVirtualNodes.ts:94`, `packages/canard/schema-form/src/core/blueprint/utils/analyze/populateVirtualNodes.ts:96`, `packages/canard/schema-form/src/core/blueprint/utils/analyze/populateVirtualNodes.ts:108`입니다. 일반 grouping Map·eager snapshot·병합 state 등은 이 합에 넣지 않고 해당 행에서 따로 계수하며, 공개 결과 생성 총량과도 구분합니다. slot의 실제 원소 수·backing bytes는 줄지 않을 수 있으므로 재측정에서 bytes도 확인합니다. 기여와 조각의 의미를 한 cursor에 덮어써서 공개 객체까지 재사용하는 설계가 아닙니다. 현재 분석별 상태의 소유 경계는 `packages/canard/schema-form/src/core/blueprint/utils/analyze/type.ts:39`입니다.

자식 entry는 기존처럼 이름·호스트·node 참조를 가진 독립 객체입니다. 바인딩 후 name/path/hostPath/schemaPath와 gate 원소 참조가 모두 원본과 같고, 기존 바인더가 새 gate를 만들지 않는 경우에만 원본 declaration과 동결 declarations 배열을 그대로 빌립니다. 하나라도 다르면 그 entry 전용 바인딩 view와 배열을 분석 중 한 번 만듭니다. `$ref`의 두 번째 host나 같은 이름의 다른 종류를 name만으로 합치지 않습니다. 기존 재바인딩 규칙과 gate 복사 조건은 `packages/canard/schema-form/src/core/blueprint/utils/analyze/populateNodeChildren.ts:163`, `packages/canard/schema-form/src/core/blueprint/utils/analyze/populateNodeChildren.ts:170`, `packages/canard/schema-form/src/core/blueprint/utils/analyze/populateNodeChildren.ts:175`입니다.

접미 공유는 내부 전달에서만 사용합니다. order는 동결된 부모 prefix와 rank/index 숫자를 인자로 전달하고 공개 평탄 배열을 한 번만 만듭니다. gates는 변화가 없으면 부모의 동결 배열을 빌리고, 실제 조건을 추가할 때에만 새 동결 배열을 만듭니다. 새 chain cell이나 읽을 때 flatten하는 view를 만들지 않습니다. 공개 order의 index/length 비교와 gates의 index 순회가 그대로 작동해야 합니다. 근거는 `packages/canard/schema-form/src/core/blueprint/utils/effectiveSchema/utils/selectEffectiveDeclarations.ts:50`, `packages/canard/schema-form/src/core/settle/utils/compute/computeNode.ts:81`입니다.

## 조건 1: 새로 공유하는 값의 동결 지점
