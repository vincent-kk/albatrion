# 108라운드 현재 core 배율 재측정

HEAD `0f690b0fa489c84cd2266f86928be27a8d0abe52`의 새 엔진과 `@canard/schema-form@0.16.0`를 같은 세션에서 재측정했습니다. mount는 **8/14 충족, 6/14 미달**이며 sample-1·flat-50·flat-100이 107의 미달에서 충족으로 바뀌었습니다. 107과 비교할 수 있는 update 42행에서는 새 1.5× 미달이 없습니다. 공식 표 전체 update 69행의 수치 판정은 12행 충족·57행 미달입니다. **update 3행은 검증 (가)를 통과하지 않아 공식 판정을 보류합니다.** 수치 배율과 보류 여부를 별도로 적었습니다.

## 절차와 비교 기준

`profile-107-remaining.md`의 ‘현재 공식 core mount 열’과 `tools/measure-verdict-95c01.mjs`를 그대로 재사용하고 메모리에서 HEAD·warmup 20·data-module 위치만 바꿨습니다. development 빌드 모드, fresh process, old→new / new→old / old→new의 세 회차, 매 회차 warmup 20·101개 표본, clock 밖 schema clone·강제 GC·GC 뒤 check anchor를 유지했습니다. 강제 GC 위치와 update의 fresh/retained-root 준비는 공식 harness와 같습니다. validation OFF/ON별로 외부 구독자 0·onChange noop을 유지했습니다.

공식 clock은 operation부터 64 Promise checkpoints 및 FIFO sentinel 안의 clock까지입니다. OFF는 sentinel 1회, ON은 2회입니다. 공식 표본 뒤에만 scheduler callback을 감쌌습니다. 모든 행의 sentinel pending=0, 추가 128 checkpoints/다음 sentinel의 추가 예약·실행=0, 새 엔진 예약=0을 단언했습니다. 엔진 코드 계측·음수 clipping은 없습니다. 세 회차의 303개 표본을 pooled하여 보정 median 비율을 구하며, 94C-02의 경계 양쪽 회차는 동률·충족으로 판정했습니다.

구 값은 선택을 고정하지 않았습니다. (나)의 pooled 또는 어느 회차라도 잡음 밖이면 그 행의 세 회차 모두 보정 microtask와 별도 callback의 순번별 합을 사용했습니다. 잡음은 공식 reporter와 같은 seeded 1,000회 bootstrap 99% median 오차 및 empty wait residual p95로 계산했습니다. BF 갱신은 실제 interaction 수만큼 C/M과 empty 잡음을 적용했습니다.

전체 작업의 자체 종료 조건에는 예외가 있습니다. **성능 측정 전의 넓은 `rg --files` 준비 조회 1회가 기본 출력 버퍼 초과로 SIGTERM 종료되었습니다.** 성능 표본에 포함하지 않았습니다. 후처리의 첫 전체 tracked-diff 단언도 exit 1·signal=null로 자체 종료했습니다. 원인은 제가 편집하지 않은 `analysis-records-design.md`의 2줄 추가·1줄 변경이며 수정 시각 `2026-10-06T21:12:42.693Z`은 첫 측정 약 3분 28초 전입니다. 해당 변경을 되돌리지 않았습니다. 제품 src와 나머지 tracked 경로가 변경되지 않았음을 확인한 뒤, 후처리 검사를 제품 src 및 알려진 문서 경로로 한정하고 문서 변경을 감사에 남겼습니다.
