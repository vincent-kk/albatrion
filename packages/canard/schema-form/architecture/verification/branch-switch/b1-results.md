# B1 게이트 판정 통일 검증 결과

## 후보 1 — 기능 통과, 성능 미달

최종 판정은 **기능 통과, 성능 수용 기준 미달**입니다. if·discriminator는 단계 시작 대비 폭 밖으로 개선됐지만 if 상대 목표선을 6.159 µs/쓰기 초과했고, TEST-073에서 canonical 2행이 회귀로 판정됐습니다. 재측정 없이 후보와 원자료를 보존했으며 채택·병합을 요청하지 않습니다.

### 기준과 고정한 판정

- 단계 시작 제품 기준은 `0eb03ff3bb54bf06af95271d157aefece1b9bf32`입니다. B0의 기준 번들 `index.node.mjs` SHA-256은 `59932cf4b9b12e52ce2610d3c4c1ad212705c1a714265234fbf24c753c55841b`입니다. 최종 A/B/A′ 원자료와 실제 사용 해시는 측정 뒤 기록합니다.
- 정식 시간은 Node 26·production, 행마다 20예열·100표본·독립 3프로세스, 실행 최소값의 중앙값입니다. 폭 (다)는 `max(|A−A′|, rangeA, rangeA′)`입니다. 분기 왕복 행은 쓰기 2회이며 형제 0은 기존대로 쓰기 1회입니다. 표에는 합계와 쓰기당 환산을 모두 기록합니다.
- 측정 전에 고정한 B1 선은 쓰기당 `if80 ≤ active80 × 1.1 + 40 µs`, `discriminator80 ≤ active80 × 1.05`입니다. 두 행 모두 같은 창의 단계 시작 A 대비 폭 밖 개선이어야 합니다. oneOf-80의 폭 밖 악화는 허용하지 않고 canonical·구독 행은 TEST-073 선을 지켜야 합니다. Node의 B2 잔존 힙은 7표본 B 중앙값≤A 최댓값이며 Bun도 7표본을 보고합니다.
- 쓰기당 `evaluateGate` 호출은 if·discriminator 각각 80 이하, 좁힌 if의 호스트 바퀴는 1회입니다. B 판의 단계 장부를 별도로 한 번 수집해 실제 호출 수를 확인합니다. 재측정은 하지 않습니다.

### 설계와 비용

등록 occurrence가 `reads`와 `evaluate(inputs)`를 가진 술어를 지연 바인딩합니다. `active`는 컴파일된 식, discriminator는 strict 태그 membership, if는 기존 guard compiler를 소비합니다. 마지막 읽기가 모두 `Object.is`로 같을 때만 성공 결과를 재사용하고 던짐은 저장하지 않습니다. `@` callback과 완전한 읽기 증거가 없는 식은 기존 실행을 유지합니다. 경로 문자열별 메모나 개별 게이트 역색인은 추가하지 않았습니다.

if의 화이트리스트는 객체 `type`·`properties`·`required`·`dependentRequired`와 논리 조합입니다. 값 제약은 DETAIL에 명시한 type·const·enum·숫자/문자열 제약만 인정하며, 중첩 `$ref`·패턴 키·추가 프로퍼티·알 수 없는 키워드는 전체 호스트 읽기로 후퇴합니다. 전체 view를 guard에 넘기는 계약은 그대로입니다.

공유 view는 **투영 객체와 extras identity가 이어지는 구간**마다 하나입니다. 라운드 최초 객체를 고정하지 않습니다. 앞선 `a` 진입을 뒤의 불투명 `$ref` guard가 같은 선택 중 읽어 `b`를 들이는 반례를 시험으로 고정했습니다. B0가 확인한 불일치 키는 루트 포인터 `""`의 `value`이며, payload 진입으로 투영 객체의 내용과 identity가 바뀌는 것이 원인입니다. 복사본 공유만으로 이 증인을 일관되게 만들 수 없으므로, 좁힌 순수 읽기만 property 값·존재 증인을 사용하고 일반 if의 추가 라운드는 보존합니다.

직접 선택은 기존 고유 이름·단일 선언·잎 자격을 유지하며 여러 oneOf/anyOf 및 여러 if/then의 allOf에 적용합니다. if 묶음은 첫 선언 자리에서 판정하고 연속한 활성 구간을 복사 없이 방문합니다. 던진 묶음은 나머지 엔트리의 원래 평가로 후퇴합니다. 판별 키는 태그→선언 인덱스와 공유 baseline을 만들고, 실제로 만난 칸의 ID·유효 스키마만 준비합니다. 알려지지 않은 입력은 공유 빈 칸을 사용합니다.

평가는 라운드당 O(전체 읽기 수 + 실제 guard 비용), 적격 표의 payload 적용은 O(A+Δ)입니다. view 복사는 투영 변경 구간별 O(A)입니다. 판별 키의 준비된 칸은 재방문 O(1)이며 정적 표는 O(D+태그 소속 수), 만난 K개 칸의 ID·스키마 보유는 최악 O(K·D)입니다. occurrence마다 마지막 입력·성공 결과·지연 guard를 보유하며 공개 node 필드는 늘리지 않습니다. 바퀴 준비·나감 정책·잠복 장부·등록·조립은 B2 범위로 남습니다.

#### TEST-073: 처리량 평균과 Welch

정본 `packages/aileron/benchmark-form/src/utils/stat-regression.ts`에 각 행의 300개 표본을 `1000/ms` 처리량으로 변환해 입력했습니다. 게이트는 A 대비 평균 처리량 15% 초과 하락과 양측 Welch p<0.05가 동시에 성립하는 경우입니다. A′ 비교도 별도로 보존했습니다. 두 실행 모두 exit 2이며 이 실패를 성공으로 처리하지 않았습니다.

### 증거와 인계

기능 로그·red/green·초기 OOM·계획·게이트 기록은 정식 루트의 `evidence/`에 보존합니다. 전후 배달 원자료는 `/private/tmp/claude-501/perf-runs/b1-delivery-4cjs_a8c`입니다. 각 시간 가족의 raw 결과는 정식 루트와 같은 접두사의 `-A/-B/-Aprime-{canonical,branch,probes}/pair`에 있고, 루트의 `judgement.json`이 전체 21행·힙·호출 수를 연결합니다. 구독은 `subscribed/`, 단계는 `stages/`, 통계 실패는 `test073-primary.log`·`test073-aprime.log`, CPU 표본은 `quiet-window.json`·`window-end.json`입니다.

속도/메모리 비용은 **if와 discriminator 개선을 얻었으나 if 상대선과 canonical 처리량 회귀를 남기고, Node flat 잔존 힙 중앙은 같으며 Bun 중앙은 약 9.748 B/노드 늘었다**는 것입니다. 원인 분리 실험이나 재측정은 하지 않았으므로 이 회귀를 특정 할당이나 잡음 탓으로 단정하지 않습니다. 후보는 별도 브랜치에 보존하며 수용·병합을 요청하지 않습니다. 독립 검토와 PR 처리 여부는 수용선 미달 escalation에 대한 코디네이터 결정으로 남깁니다.
