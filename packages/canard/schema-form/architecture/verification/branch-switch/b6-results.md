# B6 — 경로 문법 통합과 별표 호환 장치 제거

## 판정 범위

비교 기준은 단계 커밋 `0b9337cd9b7372211883a727fead7f76c8220b4f`입니다. 이 문서는 코드·시험·문서의 증거와 단일 A/B 창의 판정을 구분합니다. 후보 1의 고정 판정은 **채택 조건 미충족**이며 채택하지 않습니다. 후보 2는 쓰기 경로 파싱과 wrapper 할당을 제거하도록 준비합니다. 제품 관측·검증은 통과했지만 형제 0 단계 장부 합계가 A 자체 폭을 넘어 성능 관문이 미달했습니다.

## 출하하는 세 줄 규칙

1. 세그먼트가 정확히 `*`, `..`, `.`, `@`이면 각각 와일드카드·부모·현재·컨텍스트의 고유 심볼 연산자입니다.
2. 정확히 `%2A`, `%2E%2E`, `%2E`, `%40`이면 각각 `*`, `..`, `.`, `@`라는 리터럴 이름입니다.
3. 그 밖의 이름은 `~1`→`/`, `~0`→`~`만 풀며 보통 이름의 `%`는 보존합니다.

`#`는 맨 앞에서만 fragment 접두사입니다. 정확히 `%2A`, `%2E`, `%2E%2E`, `%40`라는 이름 자체는 문자열 경로로 주소화할 수 없습니다. 영한 SPECIFICATION의 JSONPointer 절에 같은 규칙과 한계를 적었습니다.

## 소유 경계와 내부 API

`helpers/jsonPointer`가 해석·이스케이프·조립을 소유합니다. 패키지 공개 진입점과 `JSONPointer` 상수는 유지합니다.

| 역할 | 최종 이름 |
| --- | --- |
| 확장·표준 입력 | `parsePointer`, `parsePointerSegment`, `parseStandardPointer` |
| 리터럴 이름과 연산자 | `formatSegment`, `PointerOperator`, `PointerSegment` |
| 조립 | `appendSegment`, `appendFormattedSegment`, `joinPointer` |
| 경로 관계와 해석 | `isDescendantPath`, `resolvePointer`, `stripFragment`, `isAbsolutePath` |
| 기존 할당 수를 지키는 부분 읽기·바인딩 | `readPointerSegment`, `readFormattedPointerSegment`, `getChildPointer`, `rebasePointer`, `hasPointerOperator`, `bindPointerTemplate` |
| 검증 경계의 기존 루트 별칭 | `normalizeValidationDataPath` |

네 escape 정규식과 쓰이지 않는 `JSONPointerPrefix`의 외부 수출을 제거했습니다. tilde escaping은 winglet pointer-escape 구현을 재사용합니다. 내부에서 만든 스키마 경로는 확장 파서로 읽고, 외부 `$ref`와 AJV 경로만 표준 fragment 디코딩을 사용합니다. 검증기 이슈는 필요한 경우에만 새 경로 표기의 사본으로 바꾸며 일반 이슈 배열과 항목 참조는 유지합니다.

## 장치 제거

두 전용 디렉터리의 제품 20파일·1,275줄과 공유 47파일의 장치 분기 168곳을 제거했습니다. 추가로 장치 전용·고아 helper까지 합하면 제품 전체 파일 삭제는 27파일·1,564줄입니다. 이 줄 수는 삭제된 전체 파일만 세며 공유 파일의 부분 삭제 줄 수는 포함하지 않습니다. 세부 수치는 `raw/b6/device-removal.json`에 있습니다.

`containsLiteralStar`와 전파 분기, 런타임·정착의 장치 필드, 전역 잠복 저장소·메모와 호환 전용 호출이 없습니다. 별표 이름도 보통 슬롯·overlay 경로를 사용합니다. B7 소유 네 제품 파일에는 제거할 장치 표식이 없어 변경하지 않았습니다.

장치 자체를 고정하던 16개 시험을 제거하고 공개 값·복원·사건 단언은 유지하거나 알맞은 위치로 옮겼습니다. 변경 전 `*x` 사본은 5파일/19건 중 계약대로 11건의 차이와 8건의 동일 결과를 보였습니다. soft 단언으로 첫 실패 뒤의 참조와 복원 값도 관측했습니다.

## 공개 기대값 11건

아래 새 값은 변경 전 `*x` 사본의 관측을 원래 별표 이름과 퍼센트 주소로 되돌린 값입니다. 한 실행 케이스 안의 여러 단언을 별도 케이스로 세지 않습니다.

| 시험 케이스 | 기존 → 새 기대값 |
| --- | --- |

| publication — 다른 wildcard 매치 진입 | `star.inactiveValues=[]` → `[{path:'/%2A/x',value:'held'}]` |

| lifetimes — read=true | 외부 매치 시 숨김·재공표 때 새 항목 → 계속 공표·같은 항목 |

## 후보 1 — 고정 판정: 채택 조건 미충족

### 회귀와 실행 관문

- 새 oneOf 시험은 살아 있는 형제와 별표 속성을 함께 두고 `find('/branch/%2A')`, wildcard 조회, AJV minLength 오류의 정확한 배정과 퇴장 공표를 확인합니다. 같은 최종 시험은 기준 소스에서 리터럴 경로 조회 단언으로 실패했습니다.
- 객체 별표 속성의 derive·inject·watch 세 시험은 배열 템플릿 메타데이터와 리터럴 이름이 섞이지 않는 것을 확인합니다.
- 내부 스키마 경로의 보통 퍼센트 이름을 표준 fragment로 재해석하던 회귀는 `rate%20`을 공백으로 바꾸는 실패를 재현한 뒤 확장 파서로 고쳤습니다.
- 이름 한 번 이스케이프 시험, 빈 이름·해시 마디, 상대 루트/fragment, 표준 파서, 예약 이름 왕복과 템플릿 바인딩을 검증합니다.

최종 typecheck·lint·build는 통과했고 공개 진입점 차분 0 및 기준 빌드의 공개 선언 바이트 동일성을 확인했습니다. 파서·격리 검사는 7파일/137시험, Storybook은 100파일/251시험이 통과했습니다. Node 네 프로젝트도 831파일/5,356시험 통과·기존 TODO 1건으로 완료했습니다. 다섯 프로젝트 합계는 931파일/5,607시험 통과·기존 TODO 1건입니다. `test:verify`는 698파일/4,619시험 통과·기존 TODO 1건으로 완료했습니다.

### 비용

문자열 파싱은 split 배열 하나를 제자리 디코드하며 보통 문자열은 재사용합니다. 보통 이름만 가진 상대 배열 입력도 기존 배열을 재사용합니다. 이름의 기존 형식화 결과, 단일 마디·부모 조회와 템플릿 바인딩을 재사용하여 핫패스에 split/map 배열을 추가하지 않습니다. 모든 폼에서 장치 분기 168곳과 전용 원본·메모가 사라집니다. 실측에서는 TEST-073 회귀 0과 Node 힙 관문은 통과했지만 형제 0 장부 총합이 +6.744%로 A 자체 폭을 넘어 악화 없음 관문을 충족하지 못했습니다.

### 할당 검토의 한계

navigation의 비어 있지 않은 문자열 입력은 기존도 결과 객체 1개·split 배열 1개였고 현재도 같습니다. 보통 상대 배열 입력은 기존 배열을 재사용하며 디코드가 필요한 배열은 호출자 불변을 위해 사본 하나를 만듭니다.

전체 핫패스의 할당 수 동일성은 입증하지 못했습니다. GateRegistry의 세그먼트 캐시 miss와 DependencyIndex에서 기존에 split 배열만 만들던 일부 통로는 배열 1개에 parsePointer 결과 wrapper 객체 1개를 더 만듭니다. 기존 split+filter 또는 split+slice의 두 배열은 배열 1개·wrapper 1개로, 슬롯 쓰기의 split+slice+map 세 배열은 배열 1개·wrapper 1개로 바뀝니다. V8의 wrapper 제거 여부나 실제 힙 할당 횟수를 별도로 측정하지 않았으므로 단순한 소스 객체 수와 런타임 할당을 같은 수치로 단정하지 않습니다. 이 제한을 코디네이터에게 알렸으며 판정 뒤 임의로 코드를 바꾸거나 창을 다시 열지 않았습니다.
