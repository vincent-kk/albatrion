# B6 — 경로 문법 통합과 별표 호환 장치 제거

## 판정 범위

비교 기준은 단계 커밋 `0b9337cd9b7372211883a727fead7f76c8220b4f`입니다. 이 문서는 코드·시험·문서의 증거와 단일 A/B 창의 판정을 구분합니다. 후보 1의 고정 판정은 **채택 조건 미충족**이며 채택하지 않습니다. 후보 1은 제품 관측·검증을 통과했지만 형제 0 단계 장부 합계가 A 자체 폭을 넘었습니다. 후보 2는 쓰기 경로 파싱과 wrapper를 제거한 구현·검증·불변 입력 준비를 마쳤고, 아래 정식 창에서 고정 관문 다섯이 모두 PASS입니다. 채택 문장은 코디네이터가 정합니다.

## 출하하는 세 줄 규칙

1. 세그먼트가 정확히 `*`, `..`, `.`, `@`이면 각각 와일드카드·부모·현재·컨텍스트의 고유 심볼 연산자입니다.
2. 정확히 `%2A`, `%2E%2E`, `%2E`, `%40`이면 각각 `*`, `..`, `.`, `@`라는 리터럴 이름입니다.
3. 그 밖의 이름은 `~1`→`/`, `~0`→`~`만 풀며 보통 이름의 `%`는 보존합니다.

`#`는 맨 앞에서만 fragment 접두사입니다. 정확히 `%2A`, `%2E`, `%2E%2E`, `%40`라는 이름 자체는 문자열 경로로 주소화할 수 없습니다. 영한 SPECIFICATION의 JSONPointer 절에 같은 규칙과 한계를 적었습니다.

## 소유 경계와 내부 API

`helpers/jsonPointer`가 해석·이스케이프·조립을 소유합니다. 패키지 공개 진입점과 `JSONPointer` 상수는 유지합니다.

| 역할 | 최종 이름 |
| --- | --- |
| 확장·표준 입력 | `parsePointer`, `parsePointerSegment`, `parseStandardPointer` |
| 리터럴 이름과 연산자 | `formatSegment`, `PointerOperator`, `PointerSegment` |
| 조립 | `appendSegment`, `appendFormattedSegment`, `joinPointer` |
| 경로 관계와 해석 | `isDescendantPath`, `resolvePointer`, `stripFragment`, `isAbsolutePath` |
| 부분 읽기·바인딩 | `readPointerSegment`, `readFormattedPointerSegment`, `readFormattedNameSegment`, `getChildPointer`, `rebasePointer`, `hasPointerOperator`, `bindPointerTemplate` |
| wrapper 없는 세그먼트·절대 여부 | `parsePointerSegments`, `isAbsolutePointer` |

네 escape 정규식과 쓰이지 않는 `JSONPointerPrefix`의 외부 수출을 제거했습니다. tilde escaping은 winglet pointer-escape 구현을 재사용합니다. 내부에서 만든 스키마 경로는 확장 파서로 읽고, 외부 `$ref`와 AJV 경로만 표준 fragment 디코딩을 사용합니다. 검증기 이슈는 필요한 경우에만 새 경로 표기의 사본으로 바꾸며 일반 이슈 배열과 항목 참조는 유지합니다. 후보 2는 검증 전용 slash 루트 별칭을 제거합니다.

## 장치 제거

두 전용 디렉터리의 제품 20파일·1,275줄과 공유 47파일의 장치 분기 168곳을 제거했습니다. 추가로 장치 전용·고아 helper까지 합하면 제품 전체 파일 삭제는 27파일·1,564줄입니다. 이 줄 수는 삭제된 전체 파일만 세며 공유 파일의 부분 삭제 줄 수는 포함하지 않습니다. 세부 수치는 `raw/b6/device-removal.json`에 있습니다.

`containsLiteralStar`와 전파 분기, 런타임·정착의 장치 필드, 전역 잠복 저장소·메모와 호환 전용 호출이 없습니다. 별표 이름도 보통 슬롯·overlay 경로를 사용합니다. B7 소유 네 제품 파일에는 제거할 장치 표식이 없어 변경하지 않았습니다.

장치 자체를 고정하던 16개 시험을 제거하고 공개 값·복원·사건 단언은 유지하거나 알맞은 위치로 옮겼습니다. 변경 전 `*x` 사본은 5파일/19건 중 계약대로 11건의 차이와 8건의 동일 결과를 보였습니다. soft 단언으로 첫 실패 뒤의 참조와 복원 값도 관측했습니다.

## 공개 기대값 11건

아래 새 값은 변경 전 `*x` 사본의 관측을 원래 별표 이름과 퍼센트 주소로 되돌린 값입니다. 한 실행 케이스 안의 여러 단언을 별도 케이스로 세지 않습니다.

| 시험 케이스 | 기존 → 새 기대값 |
| --- | --- |
| publication — 비활성 별표 잎 | 빈 목록·빈 배열 참조 유지 → `[{path:'/%2A',value:'retained'}]`·새 배열 |
| publication — 다른 wildcard 매치 진입 | `star.inactiveValues=[]` → `[{path:'/%2A/x',value:'held'}]` |
| publication — 떼어진 호스트 뒤 외부 매치 이탈 | `held.inactiveValues=[]` → `[{path:'/%2A/x',value:'held'}]` |
| lifetimes — read=true | 외부 매치 시 숨김·재공표 때 새 항목 → 계속 공표·같은 항목 |
| lifetimes — read=false | 재공표 때 새 항목 → 같은 항목 |
| lifetimes — 떼어진 호스트 overlay | 숨김·호스트와 조상 항목이 같은 참조 → 공표 유지·값은 같고 항목 참조는 다름 |
| lifetimes — ancestor-star 후손 | 호스트와 조상 항목이 같은 참조 → 값은 같고 항목 참조는 다름 |
| lifetimes — 외부 매치 수명 | 숨김·다음 항목이 새 참조 → 공표 유지·다음 항목이 같은 참조 |

### 회귀와 실행 관문

- 새 oneOf 시험은 살아 있는 형제와 별표 속성을 함께 두고 `find('/branch/%2A')`, wildcard 조회, AJV minLength 오류의 정확한 배정과 퇴장 공표를 확인합니다. 같은 최종 시험은 기준 소스에서 리터럴 경로 조회 단언으로 실패했습니다.

### 구현한 비용 경계

- `parsePointerSegments`는 문자열의 split 배열을 제자리 디코드하고, 변환 없는 상대 배열은 그대로 돌려줍니다. `parsePointer` 결과 객체는 absolute와 segments가 모두 필요한 차가운 경계에 남깁니다.
- DependencyIndex는 작성된 node·declaration·watch·split host 경로를 구성 시 준비합니다. query의 미등록 주소는 청사진에 추가하지 않습니다. 현재 owner·structure·배열 길이·rank 순서는 조회마다 읽습니다.
- 구체 주소 캐시는 기존 HostDerived의 root.runtime 슬롯에 있고 256개 FIFO 상한을 가집니다. 새 주소와 퇴출 주소는 최초 채움에서만 디코드하며, 모드 변경은 기존 파생 레코드 세대를 함께 교체합니다.
- GateRegistry는 기존 주소 캐시와 DependencyIndex의 정적 배열을 연결합니다. 게이트 발생 등록은 레지스트리별 callback 하나로 syntax를 읽습니다. 선행 출력 검사에서 첫 마디만 필요한 곳은 단일 마디 API를 사용합니다.
- watch/state 계획은 실제 host identity·현재 hostPath·작성 dependency별 path와 segments만 보유합니다. 현재 또는 명시한 이전 snapshot의 스키마·emit·context는 매 호출 읽습니다. 멤버십 제거는 등록 시 보유한 segments를 사용합니다. context가 없을 때 기존 노드/커밋 값 메모의 빈 객체 identity를 보존합니다.
- 슬롯은 주소 문법만 공유합니다. 같은 경로의 다른 blueprint·lineage·source·overlay는 조회마다 선택하고, 배열 재키 뒤에는 이전 참조의 이동된 쓰기 주소를 사용합니다. DirtyPathSet은 이미 형식화된 이름을 다시 디코드/형식화하지 않고 canonical 이름 마디를 직접 읽습니다.

호출 계층상 markWrite는 DirtyPathSet의 이름 읽기, registerRecalculation은 의존 색인 조회, computeNode는 presence/dependency 조회와 게이트 선행 출력, selectChildren은 발생 등록과 슬롯 조회 경로를 소비합니다. watch/state 변경은 주로 커밋 영역입니다. 이것은 변경된 호출 위치의 설명이며, 실행 전에는 self 시간의 개선 원인이나 실제 V8 할당 수를 주장하지 않습니다.

준비·보유 비용은 정적 색인의 작성 경로와 전체 마디 수, 실제 host의 방문한 dependency 수, 현재 watch 에지 수에 비례합니다. runtime의 역사 주소는 256개로 제한됩니다. 값·현재 형상·선택된 노드·슬롯 원본을 syntax 캐시에 저장하지 않습니다.

8. **사소한 정합성** — `resolvePointer`는 연산자 바로 뒤의 빈 이름만 버립니다. `getDeriveSourceNodes`는 연산자가 든 경로만 건너뜁니다. `readPointerSegment.ts`를 함수당 파일로 나누고 `parseSegment`를 `parsePointerSegment`로 바꿨으며 `resolveReference`의 중복 import, `encoded` 변수명, 이력 어휘를 고쳤습니다. 후보 1 절의 창 시작 시각 1밀리초 차이는 후보 1 절이라 고치지 않았습니다.
