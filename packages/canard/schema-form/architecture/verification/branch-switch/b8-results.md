## 3. 전용 오류 코드와 공개 선언

이름이 정확히 `%2A`, `%2E`, `%2E%2E`, `%40`인 속성은 `FormErrorCode.ReservedPropertyName` (`JSON_SCHEMA_ERROR.RESERVED_PROPERTY_NAME`)으로 거부합니다. 메시지·`details.property`·작성 위치는 유지합니다. 평면 객체 네 건과 게이트 분기 한 건이 기존 코드에서 실패하고 수정 뒤 통과했습니다. 영문·한글 명세와 오류 계약을 함께 갱신했습니다. 진단 발생 경로의 시간·메모리 비용은 같습니다.

소유자가 승인한 공개 확장은 아래 멤버 **하나**입니다.

```diff
 FormErrorCode: {
   readonly SchemaValidationFailed: "VALIDATION_ERROR.SCHEMA_VALIDATION_FAILED";
+  readonly ReservedPropertyName: "JSON_SCHEMA_ERROR.RESERVED_PROPERTY_NAME";
 }
```

이 저장소의 빌드는 분산 선언을 생성하므로 직접 `dist/index.d.ts`는 재수출 목록이고 바이트 차이가 0입니다. 실제 멤버 정의는 `dist/errors/constants/FormErrorCode.d.ts`에 추가되며, 내부 그룹 파생 표에도 같은 멤버가 반영됩니다. 이를 단순 진입 파일 해시 비교로 놓치지 않도록, 두 빌드의 진입점에서 재수출을 따라 **94개 공개 이름의 kind와 완전한 타입**을 비교했습니다. 새 멤버만 제거하면 전후가 동일하고 다른 공개 변화는 0입니다. 공개 오류 멤버는 41→42이며 top-level 이름 수는 그대로입니다. [선언 관문](raw/b8/declarations.json), [전](raw/b8/declarations-before.txt), [후](raw/b8/declarations-after.txt).

## 4. 생존 아이템 0개인 지움 배열

keep 선언이 없는 빠른 경로와 keep 선언은 있으나 값이 남지 않는 경로 모두 버려진 아이템의 보유 서브트리를 폐기 표시합니다. owned children과 inactive slots를 재귀하므로 해당 아이템·자손의 옛 참조 쓰기는 잠재 쓰기 장치에 도달하지 않습니다. 배열 호스트 자체의 쓰기와 보유 그래프 밖의 두 기존 한계는 유지합니다. settle DETAIL을 코드보다 먼저 변경하고 zero-survivor 한계 문장만 제거했습니다.

양성 대조의 정상 keep 잠재 쓰기는 writer 1회입니다. 동일 spy에서 zero-survivor 아이템과 자손 쓰기는 수정 전 각 사례 합계 2회, 수정 후 0회입니다. 선언 유무 두 사례 모두 실패 우선으로 확인했고, 공개 값·재진입을 보는 네 사례 및 기존 압축 keep 시험 11건도 통과했습니다. 추가 비용은 버려진 보유 서브트리 크기에 비례하는 순회와 발생마다 최대 한 WeakMap 항목입니다. keep 없는 아이템의 정책 평가를 생략하는 경로는 유지합니다.

독립 검토 뒤 공개 시험 두 건을 추가했습니다: keep 생존 행 안의 keep 없는 inner 지움 배열, 이미 비활성인 undefined keep 후보를 가진 zero-survivor 배열입니다. **두 시험 모두 새 폐기 호출 두 곳을 지운 상태에서도 통과했습니다.** 따라서 이 둘은 실패 우선 회귀 증거가 아니라 공개 값의 특성 시험입니다. 길이 0 배열의 잠재 patch가 공개 값에서 숨겨지므로, 실제 쓰기 폐기는 앞의 내부 writer 호출 2→0 시험으로 구별합니다. 코디네이터 요청에 따라 두 장면의 내부 spy 변형도 추가했습니다. 두 폐기 호출을 지우면 각각 writer **1회**로 실패하고 현재 제품에서는 **0회**로 통과하며, 각 변형의 정상 keep 양성 대조는 **1회**입니다. 기존 두 회귀는 삭제 대조에서 각 **2회**로 실패했습니다. 제품 소스는 대조 뒤 원본 바이트로 복원했습니다. 공개 차이가 없어도 보유 상태의 일관성을 위한 폐기라는 점을 settle DETAIL에 명시했습니다. `discardClearedArrayItems`의 배열 자체 inactive-slot 순회는 fixture로 실행하지 못해 코드 읽기로만 확인합니다. [삭제 대조](raw/b8/review-zero-survivor-mutation.json).

## 5. mount 원인과 중복 복구

이전 보고의 2.04→2.16→2.34 ms는 서로 다른 창의 프로세스 최소값 중앙입니다. 약 +0.12/+0.18 ms를 정확한 동시 실험의 차이로 취급하지 않고, 세 과거 head와 최종 후보를 동일한 장치·창에서 다시 비교합니다. S=`0eb03ff3b`, B4=`95853ae5f`, B7=`ad0be79ba`, E=`57becc34f`입니다.

확인한 무의미한 중복은 gate 예산 색인이 같은 active gate의 schema 경로를 선언·자식 템플릿·binding마다 다시 파싱하던 부분입니다. oneOf-80에서 80개 gate를 **560회→80회**로 줄였습니다. gate별 fields-active 분류만 임시 Map에 메모하고 선언별 decision 추가는 유지하므로 transition cap **81**은 같습니다. 재조회 decoder는 0회입니다. 관련 예산·첫 쓰기 시험 21건이 통과했습니다. 임시 Map은 준비 뒤 해제되며 기존 보유 색인과 예산 값은 유지합니다.

schemaPath 선준비는 fragment 소유·슬롯 조회와 첫 쓰기 decoder=0 계약의 비용이므로 유지합니다. keep 표식은 한 번의 청사진 순회로 지움 배열의 나감 때 keep 없는 아이템의 정책 방문을 생략하게 하는 비용입니다. 예약명 진단은 보통 이름에서 첫 문자 검사로 반환하며 전체 디코드를 하지 않습니다. 상세 계측의 호출자별 구문 장부로 중복과 이 선준비 비용을 구분합니다.
