직전 공식 표의 B5 새 엔진은 Node 41,959/s·Bun 63,549/s, B6는 Node 50.76 ms·Bun 48.33 ms였다. 이번 결과는 각각 66,390/136,987/s와 24.86/20.27 ms이다. B1은 30,158/31,942→33,344/30,743/s, B2는 1,224/1,950→413/1,732 B였다. 표의 처리량은 스크립트의 `1000/meanMs`이며 Welch 검사는 각 표본의 `1000/sampleMs`에 `benchmark-form/src/utils/stats.ts`의 `welchTTest`를 적용했다. UI `bench:baseline`이 기록하는 `results/baseline.json`의 하니스는 입력·완료점이 달라 코어 수치와 직접 나누지 않았다. 02의 `55ed75504` 수치는 #347·#349 이전이므로 최종 비교 기준이 아니다(LANDING-159).

프로파일: Node는 `--cpu-prof --import tsx`로 전체 B6와 B5 단독 경로를 채집했다. 전체 CPU 프로파일 10,196표본(레거시·GC·자식 프로세스 대기 포함)의 큰 자기 표본은 `selectChildren` 794, 게이트 등록 553, `commitSettlement` 390, `markWrite` 376, 유효 선언 선택 299, `transitionSettlement` 290, `assembleObject` 160, 노드 팩터리 108이었다. B5 단독 10,000쓰기 프로파일의 `assembleObject` 자기 표본은 26이었다. 단계 시간은 별도 임시 타이머/카운터로 Node·Bun 각각 B5 10,000쓰기와 B6 10로드를 순차 측정했다. 생성·병합은 계산에 포함되므로 합산하지 않는다.

B5 준비 뒤 한 번의 변경된 숫자 입력에 대한 코드 경로의 할당 지점 수(엔진 내부·JIT 최적화 제외): 객체 6→3, 배열 27→4, Map 6→0, Set 13→0, 클로저 9→0, `JSON.stringify` 키 0→0. 남은 객체는 정착 문맥·새 루트 값·커밋 번호 기록이고, 배열은 더러운 자식 목록 하나와 키 순서 확인 하나·값 비교 둘이다. 경로 접두/부분 문자열은 최대 두 개다. 이는 소스의 실행 경로를 센 값이며 엔진의 실제 할당 바이트를 뜻하지 않는다.

최적화: 게이트 없는 분석의 레지스트리·호스트 바퀴 우회(`settle/utils/write/writeSchemaNode.ts:49`, `settle/utils/compute/computeNode.ts:24`), 청사진별 유효 스키마와 선언 ID 재사용(`blueprint/utils/effectiveSchema/mergeEffectiveSchema.ts:14`, `settle/utils/compute/selectChildren.ts:18`), 선언 이름·정적 해석 캐시(`settle/utils/write/markWrite.ts:6`, `staticSpec.ts:5`), 안정된 객체 키 순서의 얕은 패치(`behaviors/objectBehavior/branch/utils/assembleObject.ts:17`), 빈 의존·잠복·경고 경로의 할당 생략(`settle/utils/write/getDependencyIndex.ts:50`, `settle/utils/commit/commitSettlement.ts:76`), 호출 뒤 작업 집합 해제(`settle/utils/write/releaseSettlementScratch.ts:8`). DETAIL 변경은 없으며 NODE-004·010과 SETTLE-047 계약을 유지했다.

남은 차이: B5 Bun은 레거시가 직접 입력→부모 값을 갱신하는 데 비해 새 엔진이 더러운 경로 계산, 루트 키 순서 보존 패치, revision·typeMismatch·Refresh 커밋을 수행한다(SETTLE-002·047, VALUE-037, EVENT-071). B6 Bun은 레거시의 직접 자식 생성과 달리 자식별 활성 선언 선택·유효 스키마 조회, 생김 노드의 기본값/유효형 전이 확인, 잠복 원본·경고등·revision 커밋을 수행한다(SETTLE-003·005·047, WRITE-087, VALUE-037). B2가 NODE-018 추정 상한을 넘는 이유는 노드 인스턴스만이 아닌 유효 스키마·출력·런타임과 경로 메모를 함께 재기 때문이다. 18C-15는 N개 활성 조각의 작성 순서 평가(SETTLE-044), 18C-67은 깊이에 따른 전체 루트 교체와 잠복 원본 갱신(WRITE-087, SETTLE-047), 18C-81은 L로 옮긴 N개 게이트의 평가·호스트 무효화(SETTLE-045)가 N=0/깊이 0 쌍에 없는 추가 작업이다. 모두 소유자 수용 대기다.
