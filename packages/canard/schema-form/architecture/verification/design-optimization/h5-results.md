# H5 — 배달 후보 큐: 폐기 결과

**폐기했습니다.** 미구독 정식 다섯 행 중 mount·bulk 네 행은 개선이 입증됐으나 switch는 미입증이었고, 추가한 구독 두 행은 모두 폭 (다) 밖으로 악화됐습니다. 조정자의 확정 지시에 따라 제품·새 시험·DETAIL·freeze 상한 정정을 `bc0fb3d0a`로 복원했습니다. 최종 diff는 이 결과 문서 하나이며 PR은 열지 않습니다.

## 가설과 보존한 실험

여섯 출처 합집합 대신 변경 지점의 ranked 후보 큐를 순회하고, 관측 없는 공개 최외곽 커밋에서 payload를 생략하며, 동일 이전 원장+mask의 다음 불변 원장을 한 커밋/파동 안에서 공유했습니다. 기존 출처 우선순위·각 출처 삽입 순서와 pending previous 병합, detached 정리, 리스너와 무관한 revision 비트 계수를 유지했습니다. 큐는 정착 끝에 비우고 중첩 정착은 이전 활성 큐를 복원했습니다.

DETAIL `0ca9f9cb9` → 원본 실패 시험 `0f0edce61` → 구현 `5a8be3dcb` → 부분 증거 `a86610415` → 빈 배달 Set 계약·freeze 상한 문서 `a32f68686` → 최종 시험 대상 `759439ece` 순서입니다. 이 커밋들은 지우지 않고 이력에 남겼습니다. 후속 H5b는 별도 가설로 맡기며 이 가지에서 진행하지 않습니다.

원장 전이는 옛 snapshot을 바꾸지 않으며 마운트의 같은 EMPTY+mask를 공유합니다. 메모를 커밋/파동 끝에 버려 EMPTY 키가 강한 다음 원장 사슬을 계속 붙잡지 않게 했습니다. payload 생략은 entryDepth=1·트리 전체 리스너 없음·revision 읽은 적 없음·기존 pendingDelivery 없음에만 적용했고, revision을 한 번 읽은 트리는 이후 계속 payload를 유지했습니다. 개발·출하의 결정 경로는 같았습니다.

## 측정 전에 고정한 판정

2026-10-26 21:24:45 UTC에 최초 빌드를 시작했습니다. 단일 Set 호환성 수정 후 최종 빌드는 21:32:25 UTC에 시작했고 그 실제 UTC를 최종 명령의 `--quiet-since`로 사용했습니다. 다른 워커의 무거운 명령이 없는 같은 창에서 순차 실행했습니다. 마지막 추가 구독 측정은 2026-10-26T21:41:14.686Z–2026-10-26T21:41:23.637Z이며 작업 계수 진단까지 끝난 뒤 조정자에게 `창 종료`를 먼저 보냈습니다.

A와 A′는 동일 기준 번들, B는 최종 후보입니다. Node v26.12.1 production에서 각 프로세스 20회 예열·100표본, 독립 프로세스 3개의 최소값 중앙값을 사용했습니다. 정본의 1ms 미만 switch 행은 추가 12프로세스 자료의 최소값 중앙값을 사용했습니다. 구독 추가 두 행은 후속 지시의 3프로세스를 그대로 사용했습니다. **폭 (다) = max(|median(A)−median(A′)|, range(A), range(A′))**이며, B−A와 B−A′가 같은 부호이고 둘 다 폭을 엄격히 넘어야 입증입니다. 값을 본 뒤 판정식을 바꾸지 않았습니다.

초기 규칙은 mount 또는 bulk 한 쌍 모두 개선이고 어떤 정본 행도 입증 악화가 없는 것이었습니다. 조정자는 진단 wave의 느림을 확인한 뒤 PR 전에 구독 두 행에도 같은 악화 금지를 적용하도록 지시했습니다. 추가 두 행의 입증 악화로 이 조건을 충족하지 못했습니다.
