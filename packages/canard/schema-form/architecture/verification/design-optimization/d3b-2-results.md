## 원인 점검과 비용

수치 재측정 없이 정본과 같은 `flat(5000)`을 청사진→factory→load 순서로 Node·Bun에서 각각 한 번 구성하고 후보 저장소를 직접 읽었다. 관찰을 위해 새 슬롯을 만들지 않았다.

| 관찰                     | Node/Bun 공통 결과                                                          |
| ------------------------ | --------------------------------------------------------------------------- |
| 청사진 직후 host 레코드  | 5,001개, 모두 `defaultEffectiveSchema` 하나만 보유                          |
| load 뒤 추가된 슬롯      | root에만 `declaredNames`, `effectiveSchemaMemo`, `staticShape`, `staticIds` |
| `staticIds`              | 선언 부모 host 한 개의 Map, 5,000 entry                                     |
| 나머지 5,000 host 레코드 | `defaultEffectiveSchema`만 유지                                             |
| live node own-key 추가   | 0                                                                           |

기존 전역 `STATIC_IDS` WeakMap을 host-owned Map으로 옮긴 저장 비용이 주요 후보다. 빈 슬롯을 선할당하거나 자식마다 edge Map을 만드는 결함은 관찰되지 않았다. Map과 기존 WeakMap의 할당 차이가 시간·힙 차이 전부를 설명하는지는 분리 입증하지 않았다. 계획의 슬롯·저장 모양을 임의로 바꾸지 않고 후속 실험과 창을 ask로 요청했다.

기존 파생 WeakMap 32개를 두 전역 WeakMap 레코드로 모았다. 외부 슬롯은 blueprint 14개·host 17개이며 `staticShape.byEntry`가 별도 지연 하위 색인이다. 각 슬롯 builder는 원 소유자에 남고 공통 모듈은 자식 타입을 import하지 않는다. 실제 읽은 blueprint/host마다 레코드 한 개와 채운 슬롯, edge entry Map 및 필요한 하위 색인이 비용이다. 모드 변경 때 두 저장소를 새로 만들며 생성 사실·값 메모·트리 저장소는 유지한다. 노드 고정 칸은 늘리지 않았다.

생성 사실 두 개는 freeze 전 비열거·읽기 전용 속성으로 정의한다. 처음에는 `completeReads`의 열거 속성이 기존 BF 관측 fixture에 드러나 full unit 한 사례가 실패했다. 새 열거 관측 시험이 수정 전에 실패함을 확인한 뒤 속성 descriptor로 고쳤고 기존 BF 단언을 그대로 통과했다.
