# H5b — 미구독 커밋의 payload 생략과 불변 원장 공유

**채택 조건과 필수 관문을 통과했습니다.** mount 두 행은 A/A′ 대비 모두 폭 (다) 밖으로 개선됐고 구독 두 행을 포함한 일곱 행에서 악화가 입증된 행은 없습니다. 후보 큐를 넣었던 H5는 구독 회귀로 폐기했으며, H5b는 큐 없이 미구독 bit-only 커밋에만 두 최적화를 적용합니다.

## 가설·구현·비용

여섯 출처 후보 방문·mark/capture 기록·정착 scratch/context·정착 밖 원장 constructor·배달 파동 알고리즘은 기존 그대로입니다. 후보 큐는 만들지 않았습니다. 미구독 마운트의 노드별 payload 봉투와 원장 할당을 줄이면 마운트 두 행이 개선되면서 H5의 구독 비용을 피할 것으로 예측했습니다(EVENT-006·GOAL-011·NODE-060·TEST-080 D1-H5b).

- bit-only 자격은 공개 dispatch 최외곽 entryDepth=1·트리 전체 리스너 없음·revision 읽은 적 없음·노드 기존 pendingDelivery 없음입니다. 최초 revision() 읽기 이후 그 트리는 계속 관측 모드이며 payload 생략을 재개하지 않습니다. raw·중첩·기존 pending의 최초 previous 병합은 기존 경로입니다. 일반 로드와 정적 첫 적재는 같은 predicate를 씁니다.
- 불변 원장 공유도 같은 bit-only 자격에서만 사용합니다. 같은 이전 원장+mask는 한 불변 다음 원장을 공유하고 옛 snapshot은 변하지 않습니다. 조정자가 이 범위를 명시 승인했습니다. 구독·revision 관측·기존 pending·raw·중첩·정착 밖에서는 기존 constructor 경로와 횟수를 유지합니다.
- 최초 커밋은 빈 deliveries Set을 보장합니다. 일반 커밋과 정적 첫 적재 모두 정상·예외 종료에 전이 메모를 해제하며 중첩 프레임의 이전 메모 참조를 복원합니다. 노드 고정 필드는 늘리지 않았습니다.
- 추가 보유 비용은 트리당 관측 플래그와 커밋 중 서로 다른 이전 원장/mask 수 K에 비례하는 약한 메모 O(K)입니다. 메모는 종료 시 버려 EMPTY를 뿌리로 한 역사 사슬을 남기지 않습니다. 같은 전이가 적은 미구독 커밋에는 인덱스 비용이 남으며 모든 할당이 공유되는 것은 아닙니다. 구독 경로에는 원장용 Map 작업을 추가하지 않습니다.

기준은 feat/schema-form-design-optimization의 `34ca96333`이며 제품 코드는 `bc0fb3d0a`/`8d5c5dba1`과 같습니다. DETAIL `171e3ed3a` → 원본 실패 시험 `9fd9384f3` → 구현 `3b4466150` 순서입니다. H5의 필요한 부분만 손으로 옮겼으며 큐·그 scratch/context와 Set 재사용 변경은 옮기지 않았습니다.

## 측정 전에 고정한 판정

조정자가 H4 종료 뒤 창을 승인했습니다. 실제 빌드 시작인 **2026-10-26T22:06:40Z**를 --quiet-since로 사용했습니다. Node v26.12.1 production, 각 프로세스 20회 예열·100표본·독립 3프로세스의 최소값 중앙값입니다. A와 A′는 같은 보존 기준(a396cf65…), B는 최종 후보(6159ffe4…)입니다. 일곱 행 모두 세 프로세스를 사용했고 작은 행을 추가 재측정하지 않았습니다.
