# H3 — 파동 문서 순서: 개선 없음, 폐기

**H3는 채택하지 않았으며 PR을 열지 않았습니다.** 세 구현 모두 비교 중 조상 배열 생성을 없앴지만, 같은 조용한 창의 wave와 bulk 측정에서 변동 폭을 벗어나는 개선을 확인하지 못했습니다. 코디네이터가 마지막 시도 승인 때 정한 442C-03 판정에 따라 제품 코드·이번에 추가한 시험·DETAIL을 기준 `bc0fb3d0a`로 되돌리고 이 결과만 남깁니다. 기준판의 기존 시험과 단언은 바꾸지 않았습니다.

## 가설과 범위

TEST-080 D1-H3, EVENT-006·011, ADR 0008의 한 파동·문서 순서·리스너 고정 보장을 유지하며 비교마다 조상 배열 둘을 만드는 비용을 없애려 했습니다. 대상은 write의 deliverWave와 compareDocumentOrder였고, runDeliveryWaves의 기존 파동 경계는 그대로 사용했습니다. 리스너 복사·즉시 구독 해제 확인·detached skip은 모든 시도에서 유지했습니다. 영구 노드 필드와 전역 색인은 추가하지 않았습니다.

1. 관찰 노드와 필요한 조상마다 숫자 경로 배열을 한 번 준비한 뒤 비교했습니다. 비교의 조상 읽기와 reverse는 0이 되었지만 준비 비용이 상쇄했습니다.
2. 관찰 대상·조상을 색인하고 필요한 부모의 children 순서로 일시적인 전위 rank를 만든 뒤 정렬했습니다. 임시 배열 수는 줄었지만 전체 시간의 개선을 확인하지 못했습니다.
3. 전위 순회 결과를 배달 벡터로 직접 사용하여 정렬과 비교 자체를 없앴습니다. 필요한 조상이 아닌 형제의 하위 트리는 내려가지 않지만, 필요한 부모의 직접 children 목록은 검사합니다. 이 추가 보관·색인·순회 비용 역시 전체 시간에서 이득을 확인할 수 없었습니다.

새 시험은 1,000자식 구독 루트 setValue의 문서 순서, 배달 중 구독 추가·즉시 제거, 다음 파동의 현재 children 순서를 확인했습니다. 기준 구현에서는 비교 구간 parent 읽기 4,005회와 reverse 2,004회로 0 기대값에 실패했습니다. 최종 시도에서는 비교 0, 준비 1회, 준비 parent 읽기 ≤1,001을 단언했습니다. 최종 단언 보완은 이번 PR에서 만든 새 파일에 한정해 코디네이터가 승인했습니다. 각 구현의 새 시험 3건과 기존 dispatch.waves 7건은 통과했습니다.

## 비용·관문·처분

가설의 추가 비용은 파동 수명의 노드/조상 색인과 경로 배열 또는 rank/배달 벡터, 필요한 부모의 직접 children 검사였습니다. 리스너 사본 비용은 유지했습니다. 비교자 안의 할당을 줄이는 국소 변화가 전체 wave 속도 향상을 보장하지 않았으므로 최종 제품에 이 비용을 추가하지 않습니다. 잔존 힙 개선은 측정하지 않았고 주장하지 않습니다.
