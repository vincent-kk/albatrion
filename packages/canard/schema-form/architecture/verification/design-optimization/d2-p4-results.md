각 행은 20 예열·100 표본·독립 3 프로세스입니다. 각 프로세스 안에서 현재/0.16.1 순서를 교대하고, 프로세스별 최솟값 세 개의 중앙값을 ms로 사용합니다. 표의 괄호는 그 세 최솟값의 최대−최소 폭이며 신뢰구간이 아닙니다. 판별자 행은 왕복 두 쓰기 시간입니다.

## 후보가 줄인 일과 보존한 계약

- 기존 HostStaticPartition의 약한 청사진 키 안에 독립 지연 슬롯을 두었습니다. 소유 색인 조회가 정적 분할이나 parent childEntries 읽기를 유발하지 않으며, 자기 선언은 정적 ID→선언·작성 순서 색인으로 골랐습니다. 선택된 ID 조합이나 런타임 노드를 캐시하지 않았습니다.
- 고정 객체 호스트의 정적 게이트 목록에 등식 성질을 한 번 증명하고, 실제 relocation이 생길 때만 목록을 복사했습니다. 불변 벡터의 budget cap은 같은 identity를 이용해 반복 every 순회를 없앴습니다. 배열의 기존 동적 전략과 실제 게이트 재평가는 유지했습니다.
- 부모 조각을 정확한 작성 경로로, fields를 디코딩된 이름으로 색인했습니다. 자식이 선택한 선언의 소유자만 찾은 뒤 부모 작성 순서를 유지했습니다.
- 정착 문맥 안에서 inherited 입력까지 포함해 나감 정책을 공유했습니다. 정착 사이에는 공유하지 않았고 false 정책, overlay, 잠복, inactive, 배달 계약을 유지했습니다.

## 청사진 보유량과 B2

B2는 기존 node-and-settle 벤치의 flat 5,000 fields(5,001 nodes), 두 번 GC, 일곱 표본을 그대로 사용했습니다. 외부 복사본에서 runtime loader·typeguard import·Bun 자식 경로만 고정 번들에 맞췄고 fixture·GC·통계는 바꾸지 않았습니다. 청사진은 heap 측정 전에 준비하는 기존 B2 정의이므로 위 정적 색인 크기를 B2 bytes/node가 직접 측정하지는 않습니다. 판정은 런타임별 **B 중앙값 ≤ A 최대값**입니다.

다른 실패는 `settle.exit-direct-ownership.test.ts`의 기존 작업량 하한 `>64`에 후보의 63회가 걸린 것입니다. 이를 그대로 목록으로 ask했고 코디네이터가 400C-02·447C-03의 비공허성 의도에 맞춰 **필요한 정책 읽기 수 15개 이상**으로 한 건 정정하도록 명시 승인했습니다. 상한 `<=84`와 `root.emit` 동작 단언은 유지했습니다. 나가는 15노드마다 정책 읽기 정확히 한 번을 확인하는 새 인접 사례를 더했으며, 기존 두 호출처로 되돌린 ablation에서는 두 번으로 실패했습니다(`required-policy-red-ablation.log`). 이후 전체 unit을 한 번 다시 실행해 위 최종 결과를 얻었습니다. 후보 이력에서는 기존 작업량 하한 한 건만 승인 변경했으며, 폐기로 이 변경도 복원되어 최종 결과 커밋에는 기존 단언 변경이 0건입니다.

측정 도구의 첫 정식 시도는 `--current-sha256` 인자 이름에 숫자를 허용하지 않는 파서 오류로 표본 수집 전에 실패했습니다. tools 파서만 고친 뒤 실제 A/B/A′를 한 번 실행했습니다. `measure-preflight-failure.log`와 `config-red.log`를 보존했습니다.
