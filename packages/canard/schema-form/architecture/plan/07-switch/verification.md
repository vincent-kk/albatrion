사용자 관점의 동작이 처음 검증되는 PR이다(LANDING-071). 02–06이 쌓은 엔진 수준 시나리오는 그대로 초록이어야 하고, 여기서 렌더 수준·브라우저·React 18/19·벤치 비교가 더해진다. 기본 입력으로 검증한다(UI 플러그인은 08).

## 게이트 — 이 PR이 단독으로 통과해야 하는 것

- 렌더 시나리오 전체와 살린 17파일 초록. 옛 시험 가운데 `<Form>`을 시험하던 것은 처분표대로.
- **이주 점검**(LANDING-198): 오늘과 다른 곳마다 이주 행이 있고 시험 목록의 모든 줄이 통과. 이주 표의 행마다 대조 시험. union 이주 행 LANDING-181–186, 채움 시점 이주 행 셋(18C-99), 공개 표면 잔여의 거취(18C-87, SURFACE-059).
- **브라우저 게이트**(TEST-024): IME 조합의 동기 통지(EVENT-065, 18C-63), 입력 계약의 브라우저 사실(REACT-027, 18C-40), 입력 판정의 구현 확인(REACT-028, 18C-62), 빈 `ChildNodeComponents` 감지 비용(18C-73), 스키마 타입의 컴포넌트 자리(18C-76).
- **React 18·19 실행**(REACT-017, EVENT-070, 18C-85): 이펙트를 거친 진입 간 순환이 React 한도에 막힌다.
- **공개 형**: `tsc --strict`로 `UnionNode`·`InferSchemaNode`·`InferValueType`·가드(NODE-058), 공개 표면 잔여(SURFACE-059).
- **바인딩 계약 다섯**(LANDING-095)과 `reset` 로드 전환(같은 스키마 판정·커밋 재대조·재생성·Refresh 번호·상호작용 초기화 번호), 로드가 아닌 쓰기의 Refresh 범위(EVENT-071, 18C-94).
- **벤치 비교**(TEST-026·027): 옛 판 기준선 대 새 판, 코어와 렌더, 벤치 일곱. 느린 항목은 이유를 적고 소유자가 받아들여야 병합. 모바일 안전 임계는 잰 사실만 적는다(TEST-074).
- **레거시**: 새 코드에서 `__legacy__`를 가리키는 import 0(린트 + 검색), 레거시 시험은 글롭에서 제외, `yarn lint`·`typecheck`·`test` 저장소 전체 초록.
