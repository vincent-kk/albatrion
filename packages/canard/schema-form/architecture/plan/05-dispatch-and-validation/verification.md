# 05 통지와 검증 — 검증 구성요건

## 검증 원칙

이 PR이 차등 테스트의 출발점이다(LANDING-071, TEST-001): 폼의 판정이 독립 검증기의 판정과 같아야 한다. `<Form>`에는 아직 닿지 않으므로 옛 시험 전체가 회귀 신호이고, React 바인딩은 훅 수준에서만 시험한다.

## 시험 구성

| 프로젝트 | 무엇을 더하는가 |
| --- | --- |
| `unit` | 새로 있어야 하는 시험(TEST-017): 디스패처, 사슬 끝 throw와 `onError` 계약의 core 쪽, 검증기 없음·컴파일 실패, `degraded`, 가드, 훅 수준 바인딩 시험 |
| 시나리오 패키지 | 차등 테스트 스위트(독립 검증기와 판정 동치, 다른 구현·직렬화한 값), 검증·오류 상황 |
| 플러그인 패키지 ajv6·7·8 | 플러그인 계약 게이트 넷과 `bind` 거부 시험 |
| `render` | 옛 렌더 시험 그대로 |

## 게이트 — 이 PR이 단독으로 통과해야 하는 것

- **차등 테스트**(TEST-001): 독립 검증기와 판정 동치. union의 검증기 줄(TEST-077): `integer` 멤버십과 `type` 배열의 판정이 검증기와 같다.
- **플러그인 계약 게이트 넷**(VALIDATE-046·047, 18C-58): 따로 컴파일한 가드가 전체 검증의 `if`와 같은 boolean(`$id`·동적 범위 포함), 같은 `$id`의 두 살아 있는 루트가 저마다 판정. ajv7·8 전부, ajv6은 (i)만. 사본 루트 등록의 해제 계약과 최근 해제 목록 크기(18C-56), 살아 있는 두 트리의 같은 `$id`(18C-57).
- **`bind` 거부**: 세 옵션 각각과 조합에서 거부, 꺼진 검증기는 붙음, 스키마 깊은 복사로 원본 불변(VALIDATE-050·051).
- **`onError`**: 사슬 끝 기록마다 전달, 핸들러 예외 묶음, 전달 중 쓰기 거부(`WRITE_IN_OBSERVER`), 구조 키 중복 억제, 폼 수준 로드에서만 초기화(ERROR-204): `resetSubtree()`는 `VALIDATOR_COMPILE_FAILED`를 다시 내지 않고 초기화하지도 않는다(WRITE-099).
- **에러 라우팅**(18C-53): union 호스트 수준 에러와 잔여 키.
- **명령**: 메서드 하나가 종류마다 요청 사건만 내고 원본을 쓰지 않음, `FormHandle` 대칭이 `find(path)`로 위임하고 노드가 없으면 아무것도 하지 않음(EVENT-063·073).
- **훅 수준 바인딩**: 동기 통지와 `useSyncExternalStore`, StrictMode 이중 호출, 구독 뒤 따라잡기(LANDING-064).
- 컴파일 예산(TEST-076): 마운트 벤치에서 폼 몫과 검증기 몫을 나눠 보고, 가드 200개 조건부 폼 생성은 수용 필요 항목.
