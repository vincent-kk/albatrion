# 01 설계문서 PR — ADR과 핵심 축

> ADR 본문은 권위가 아니다. 수렴의 축은 원리·수락된 결정·목표이며 각 소스가 먼저 도출한다(PROCESS-034). 이 PR이 바로 그 ADR을 원장에서 다시 쓰는 PR이다.

## 이 PR이 지켜야 하는 축

| 축 | 원장 | 이 PR에서의 뜻 |
| --- | --- | --- |
| 설계 문서는 단일 원장으로 증류하고, 설계 완료 뒤 원장에서 ADR과 설계문서를 만든다 | PROCESS-050 | 문서는 원장의 표면이다. 원장에 없는 문장을 문서가 만들지 않는다 |
| 증류 절차 — 파일럿, 행의 칸, 누락과 해상도를 막는 검사 세 겹 | PROCESS-051 | 역방향(원장 → 문서)에도 같은 세 겹: 원문 보존, 기계 검사(`doc-coverage`), 해상도 대조 |
| 결론 문서는 새 결정을 만들지 않고 이미 나온 결론을 약어와 생략 없이 풀어 쓴다 | PROCESS-007 | 설계문서도 같다. 요약 금지, 약어 금지(PROCESS-023) |
| 결정은 소유자의 것 — 도출 기록은 "원리를 받아들이면 이렇게 된다"를 적는다 | PROCESS-054 | 문서의 귀속 표기(소유자 답·원리·편집자 결정)는 원장의 닫은 사람 칸을 그대로 옮긴다 |
| 원리 원장의 지위 — 결정을 낳는 원리, 도출되지 않는 결정은 원리나 결정이 틀림 | PROCESS-004 | `design/00`은 원리를 먼저 놓고, 뒤의 문서는 그 원리에서 도출된 순서로 적는다 |

| 설계 완료 확정 — 원장에서 ADR과 설계문서를 쓰고 검사를 다시 거친 뒤 옛 문서를 백업 디렉토리로 | PROCESS-061 | 이 PR의 순서 그 자체 |
| 소유자의 절 단위 통과는 새 설계문서에서만 | PROCESS-062 | 통과 절차의 대상은 `design/` 8편 |

## ADR

- 옛 ADR 0001…0014는 백업으로 간다. 새 ADR은 옛 주제 단위를 유지하되 본문을 원장의 현행 결정으로 바꾸고, 채택 여부와 라운드를 원장의 닫은 사람 칸에서 옮긴다. 각 ADR을 인용하는 현행 항목은 원장에서 기계로 뽑는다(0001 → VALIDATE-001…011·034·036, 0002 → FRAGMENT 영역 다수와 SETTLE-018·020·022·023·026, 0003 → CONTROLS 영역 55건, 0004 → VALIDATE 26건, 0005 → BLUEPRINT·SCHEMA 30건, 0006 → VALUE 23건, 0007 → SETTLE 38건, 0008 → EVENT 51건, 0009 → TEST 17건, 0010 → FRAGMENT 11건, 0011 → NODE 24건, 0012 → SCHEMA-015…018, 0013 → WRITE 28건, 0014 → ERROR 147건).
- 새 번호: 0015 union 잎(BLUEPRINT-036…047, NODE-057·058, WRITE-093·098·099, VALUE-037, SURFACE-061, REACT-032·033), 0016 채움 시점과 전체 교체 쓰기(WRITE-090·094…097, EVENT-071·072, ERROR-204), 0017 좁힘의 교집합 원리(BLUEPRINT-041·044, WRITE-098·099).
- ADR 0010(분기 관행)은 PR-8이 최종화한다(LANDING-068). 이 PR에서는 현행 결정까지만 옮긴다.

## 설계 가치와 문서의 관계

패키지의 설계 가치(일관되고 예측 가능한 동작, 속도 우선과 같은 값의 같은 참조; `CLAUDE.md` Design Values, GOAL-049·050)는 `design/00`이 목표 G1–G8·원리 P1–P5와 함께 첫 절로 놓는다. 가치끼리 부딪히는 자리에서 설계가 고른 쪽(GOAL-086)은 표 그대로 옮긴다.

## 이 PR에서 부딪히는 자리

- 읽기 쉬움 대 원문 보존: 산문으로 잇되 요약하지 않는다. 문장이 길어지면 문장을 나누되 뜻을 빼지 않는다(PROCESS-007).
- 새 문서에서 발견한 원장의 결함: 문서에서 고치지 않고 원장에 새 라운드 항목으로 먼저 적는다(PROCESS-052).
