# 01 설계문서 PR — 검증 구성요건

## 검증 원칙

정본은 원장이다. 문서는 원장을 옮긴 것이므로 검증은 "문서가 원장을 빠짐없이, 바꾸지 않고 옮겼는가"의 세 겹이다(PROCESS-061·062): (가) 원문 보존, (나) 기계 검사, (다) 해상도 대조.

## 기계 검사 — 모두 문제 0

| 검사 | 명령(ARCH에서) | 무엇 |
| --- | --- | --- |
| 기존 원장 검사 8종 | HANDOFF §4의 명령 | 백업 이동 뒤에도 `verbatim`·`sup`가 옛 경로를 읽는다 |
| 문서 덮개 | `node ledger/checks/doc-coverage.mjs design/*.md adr/*.md -- ledger/*.md` | 현행 항목마다 인용 문서 1개 이상, 문서의 ID는 모두 현행, 결정문 토큰이 문서에 그대로 |
| 계획 링크 | `node ledger/checks/plan-links.mjs plan/*.md plan/*/*.md -- ledger/*.md` | 계획서의 ID가 현행 |

## 해상도 대조 (세 겹 검사 (다))

- codex와 antigravity에 같은 지시서로 "원장 대 문서"를 한 번 돌린다: 문서 문장 가운데 원장에 없는 주장, 원장의 현행 결정 가운데 문서가 뒤집은 것, 요약으로 뜻이 바뀐 것. 양식은 `F<n> <높음|중간|낮음>`, 두 위치, 원문 인용, 왜, 제안.
- 검증자가 원문과 대조해 거른 뒤 고침. 원문·판정·고침은 `reviews/raw-design-docs-check.md`(선례 `reviews/raw-round18-final-check.md`).

## 소유자 통과

- 문서마다 절 단위 통과. 통과한 절은 문서 머리의 표에 날짜와 함께 적는다.
- 통과 중 나온 새 결정은 원장에 새 라운드 항목으로 먼저 들어가고 문서가 따라간다(문서가 원장을 앞서지 않는다).
