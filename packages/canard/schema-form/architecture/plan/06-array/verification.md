# 06 배열 — 검증 구성요건

## 검증 원칙

03의 정착 위에서 배열 행만 더한다(TEST-069). `<Form>`에 닿지 않으므로 옛 시험 전체가 회귀 신호다.

## 시험 구성

| 프로젝트 | 무엇을 더하는가 |
| --- | --- |
| `unit` | 배열 행·구조 연산·스냅숏 자리·필터 단위 시험(TEST-018) |
| 코어 시나리오 시험 | `src/core/__tests__/scenarios/<부류>.spec.ts`(TEST-023; 데이터 모듈은 시나리오 패키지에): 배열·터미널 배열·아이템 채움·통째 교체 상황(02 §9의 해당 부분), 채움 시점 이주 행의 배열 장면(LANDING-203) |
| `render` | 옛 렌더 시험 그대로 |

## 게이트 — 이 PR이 단독으로 통과해야 하는 것

- 배열 시나리오(TEST-018): 구조 연산마다 identity와 스냅숏 자리, 통째 교체 뒤 아이템 노드 참조, `items`·`prefixItems`, 터미널 배열 행의 구조 연산(원본 사본 위의 `push`·`pop`·`update`·`remove`·`clear`), `omitTrailing`, 원본 B의 배열 아이템 구조 기록, 위치 재조정(키 유지와, 위치를 따라가는 `dirty`·`touched`·바깥 오류·가상화 기록·노드 참조), 청사진 없는 자리의 `extras` 보존, 구조 연산에서 값이 노드와 `extras` 사이를 옮기는 것(TEST-018과 그 보충).
- 스냅숏 자리 맞춤(WRITE-095·099): `push(v)`는 `v`, 비구조 쓰기는 `undefined`, O(배열 길이).
- 채움 시점의 이주 행(18C-99, LANDING-203): 배열 통째 `setValue` 뒤 아이템 채움이 새로 생긴 아이템에만 든다.
- 빈 배열 호스트·루트의 방출 규칙(VALUE-034), `reset` 로드의 아이템 identity(WRITE-048).

## 벤치 (18C-59 ㅁ, NODE-053)

- TEST-032의 "긴 배열(아이템 10,000개) 안의 키 입력", "array 1000 루트 통째 쓰기", "노드당 메모리"를 TEST-027 게이트로 옛 판과 견준다. 통과: 옛 판보다 느리지 않거나, 느린 항목을 Vincent가 받아들인다.
- 실패: 지연 실체화를 넣되, 관찰 결과(`value`·`outputValue`·`inactiveValues`·채움·에지 발화·검증 결과 라우팅·통지·`revision`, 그리고 `find`에 관찰 가능한 부수효과가 없음)가 실체화 판과 같음을 PR-5 시험을 두 모드로 돌려 보인 경우에만 넣고, 같게 만들 수 없으면 소유자에게 올린다(NODE-053).
