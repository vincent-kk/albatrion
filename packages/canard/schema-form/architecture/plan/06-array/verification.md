# 06 배열 — 검증 구성요건

## 검증 원칙

03의 정착 위에서 배열 행만 더한다(TEST-069). `<Form>`에 닿지 않으므로 옛 시험 전체가 회귀 신호다.

## 시험 구성

| 프로젝트 | 무엇을 더하는가 |
| --- | --- |
| `unit` | 배열 행·구조 연산·스냅숏 자리·필터 단위 시험(TEST-018) |
| 시나리오 패키지 | 배열·터미널 배열·아이템 채움·통째 교체 상황(02 §9의 해당 부분), 채움 시점 이주 행의 배열 장면(LANDING-203) |
| `render` | 옛 렌더 시험 그대로 |

## 게이트 — 이 PR이 단독으로 통과해야 하는 것

- 배열 시나리오(TEST-018): 구조 연산마다 identity와 스냅숏 자리, 통째 교체 뒤 아이템 노드 참조, `items`·`prefixItems`, 터미널 배열의 통째 값, `omitTrailing`.
- 스냅숏 자리 맞춤(WRITE-095·099): `push(v)`는 `v`, 비구조 쓰기는 `undefined`, O(배열 길이).
- 채움 시점의 이주 행(18C-99, LANDING-203): 배열 통째 `setValue` 뒤 아이템 채움이 새로 생긴 아이템에만 든다.
- 빈 배열 호스트·루트의 방출 규칙(VALUE-034), `reset` 로드의 아이템 identity(WRITE-048).

## 벤치 (18C-59 ㅁ, NODE-053)

- 지연 실체화는 벤치 게이트: 관찰 결과가 실체화 판과 같음을 두 모드로 돌려 보인 경우에만 넣는다. 그렇지 않으면 전부 실체화.
