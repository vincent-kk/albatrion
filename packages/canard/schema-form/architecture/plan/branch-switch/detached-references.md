# 떼어진 참조의 단일 규칙 (B11, 462라운드)

## 자리

461라운드 뒤 소유자가 B7의 알려진 한계(쓰기 주소의 모서리 둘)를 물었고, 그 답에서 "떼어진 참조는 읽기는 마지막 커밋에서 멈추는데 쓰기는 현재 노드로 넘어간다"는 비대칭이 드러났다. 소유자는 "node 자체가 불변하지 않는다면 괜히 일부 핸들러만 캐싱하는게 더 이상할거같다. set 은 되는데 get 은 안되는건 이상한 일이잖아"라 했고, 비활성 노드를 `find`로 닿게 하는 모델(선택지 다)과 그 확장인 그림자 트리를 함께 검토한 뒤 접었다: 비활성 호스트 안의 중첩 분기까지 다시 계산해야 하므로 "이 모든 작업이 find 로 비활성 노드를 찾게 하기 위한 작업인데, 얻는 것에 비해 잃는 것이 너무 많다". 소유자의 결정은 "find 가 비활성 노드를 찾지 못하도록 하면서 (단, 못찾음과 활성 아님은 구분했으면 함) 지금까지 논의에서 나온 장점들을 취할 수 있는 것만 취하는 방향"이었다가, 개발 개시 뒤 "비활성 노드라는게 항상 생성되어 있는게 아니니까 undefined 랑 null을 구분하면 안될거같아. 그냥 동일하게 처리하자"로 `find`의 구분을 거두었고, 개발 개시와 함께 "아직 우리 신규 버전은 한번도 릴리즈가 나가지 않았으니, 공개표면은 없다"고 밝혔다(`../../reviews/round-462-owner-answers.md`). 이 문서는 설계 Ⅱ(`design-ii.md`)의 보강이며 B7(`defect-fixes.md`)의 쓰기 주소 규칙을 대체한다. 설계 Ⅲ(B9)은 이 PR의 병합 머리 위에서 재개한다.

## 문제

- **비대칭.** NODE-044는 떼어진 참조의 읽기를 마지막 커밋으로 고정하고 구독을 침묵시키지만, 쓰기는 역사적으로(0.16.1의 "비활성 노드도 쓰기를 받는다"를 잠복 저장소로 이어 온 것) 현재 노드나 overlay로 흘러갔다. 설계 Ⅱ가 잠복 저장소를 슬롯으로 바꾸면서 이 흐름을 떠받치는 장치가 커졌다: `settle/utils/detached/DetachedWriteAddress`(칸·retain·discard·read), `slots/rekeySlotWriteAddresses`, `slots/discardClearedArrayItems`, `slots/readSourceTree`의 버려진 노드 읽기, `cloneSlotSubtree`의 재키, `write/writeFieldNode`의 떼어진 분기. B7은 이 장치의 경로를 독립 검토 여섯 번으로 닫았고 그래도 모서리 둘이 남았다(보유 그래프가 닿지 않는 칸, 재진입 전에 잡은 지워진 채 먼저 나간 후보의 옛 참조).
- **보유.** 재진입이 슬롯을 복제한 뒤에도 옛 인스턴스가 다음 나감까지 슬롯에 남아, 소비자가 참조를 놓아도 엔진이 그것을 든다.

## 명제

**떼어진 참조는 한 상태(무효)뿐이고, 비활성 값에 닿는 길은 경로를 담은 JSON 쓰기뿐이며, `find`는 지금처럼 활성 노드가 없으면 `null`이다(비활성과 미선언을 가르지 않는다).** 재진입은 지금처럼 새 인스턴스를 만들고(NODE-044) 그때 슬롯을 비운다. 쓰기 주소 장치는 없앤다.

## 규칙

1. **떼어진 참조는 무효다.** 읽기 멤버는 마지막 커밋의 값으로 고정(그대로), 구독은 남되 발화 없음(그대로), 명령과 상태 진입은 무동작(그대로). **쓰기(`setValue`, 배열 동사 `push`·`insert`·`remove`·`move`·`clear`·`update` 등)는 아무것도 하지 않고 개발 모드에서 경고한다**(`FormWarningCode`에 전용 멤버 하나; 운영 번들은 무동작만). 쓴 값은 어디에도 적히지 않는다: overlay에도, 현재 노드에도. 이것이 "읽기는 옛값인데 쓰기는 간다"를 없애는 한 줄이다.
2. **비활성 값의 쓰기는 경로 JSON 쓰기뿐이다.** 루트·호스트의 `setValue(V)`와 로드가 비활성 경로를 담으면 overlay에 적히고(VALUE-031 ㅁ 그대로: 노드 생성 없음, 규칙 평가 없음, 방출 없음), `inactiveValues`로 읽히며, 재진입 복제에 적용된다. `controls.injectTo`의 분배도 같다.
3. **`find`는 그대로다.** 활성 노드가 없으면 `null` 하나이며 비활성 영역과 미선언을 가르지 않는다. 비활성 노드는 항상 만들어져 있는 것이 아니므로(값이 없는 분기에는 아무것도 없다) "비활성이라 없음"을 "선언이 없어 없음"과 믿을 만하게 가를 수 없고, 가르려면 청사진 조회가 붙는다. 반환 형과 호출자는 바꾸지 않는다.
4. **재진입은 슬롯을 비운다.** 복제가 끝나면 그 엔트리의 슬롯과 overlay를 지운다. 보유 상한은 "호스트당 지금 비활성인 엔트리"가 되고, 소멸 인스턴스는 소비자의 참조로만 살아 있다가 회수된다.
5. **없애는 것.** `DetachedWriteAddress`와 그 사용처 전부(retain·discard·rekey·버려진 노드 읽기·떼어진 쓰기 분기), settle DETAIL의 쓰기 주소 문단과 알려진 한계 둘, B7의 "옛 참조 쓰기가 압축을 따른다"는 공개 기대값. **남는 것.** B7의 kept 아이템 압축 복원(나갈 때 keep 원본을 가진 아이템만 앞에서부터), `hasKeepDescendants` 플래그, 생존 0개 배열의 공개 결과(길이 0), `inactiveValues`의 공표, overlay 규칙.

## 하지 않는 것

- 비활성 노드를 `find`로 돌려주는 것과 그림자 트리: 비활성 호스트 안의 미결 게이트 아래에 새 이름을 쓸 때 어느 템플릿인지 정할 수 없어 두 번째 정착 엔진이 필요해진다(소유자가 접음).
- 떼어진 참조의 읽기·구독을 현재 노드로 넘기는 것(느리고 복잡; 소유자가 접음), 떼어진 인스턴스를 되살리는 것(NODE-044 기각 그대로).
- 수명별 핸들: `find`가 주소 기반이라 필요가 없고, 필요해지면 노드 밖 포장으로 따로 한다.

## 비용

- 나감: `retainExitedSlot`의 retain과 misfit 색인 가운데 칸을 위한 부분, 버림 표시 순회가 빠진다(B5 finalizeExits self 18.4 µs의 일부, B9-0 하위 타이머가 정확히 잰다). 복제: `cloneSlotSubtree`의 재키가 빠진다. 활성 경로의 쓰기와 읽기는 변화 없음. 떼어진 쓰기는 플래그 검사 하나로 끝난다.
- 메모리: 슬롯 소비로 호스트당 보유가 "지금 비활성인 엔트리"로 줄어든다. 힙 관문의 보유량 행에 열고 닫기 반복의 도달 노드 수를 적는다.
- 공개 선언: 경고 코드 한 멤버. 소유자가 "공개표면은 없다"(릴리스 전)고 했으므로 선언 차분 0 관문은 이 PR에 적용하지 않되 차분은 기록한다.

## 지키는 것

- NODE-044의 나머지(떼어짐, 새 인스턴스, 읽기 고정, 구독 비발화, 명령 무동작), VALUE-031 ㅁ(비활성 경로 쓰기는 거부도 오류도 아니고 방출되지 않음 — JSON 쓰기에 한함), SETTLE-044·GOAL-029, BLUEPRINT-007, 같은 값은 같은 참조, 배달 비교(떼어진 참조 쓰기 단계를 뺀 관측점에서 차이 0), 460C-07의 검증 스케줄과 무결함, 461C-04의 창 규칙.

## 검증(PR 관문)

- 수정 전에 실패하는 시험: (a) 떼어진 참조의 `setValue`와 배열 동사가 값·overlay·`inactiveValues`를 바꾸지 않고 개발 모드에서 경고 코드를 낸다(운영 번들 무동작은 production 프로젝트), 재진입 뒤에도 같다; (b) `find`가 비활성 경로에서 지금처럼 `null`을 돌려줌을 그대로 두는 회귀 시험(바뀌지 않음을 못 박음); (c) 재진입 뒤 슬롯이 비워져 열고 닫기 반복에서 도달 노드 수가 고정(기존 `surface.slots-memory-bound` 확장); (d) B7의 옛 참조 쓰기 시험들은 기대값을 "효과 없음"으로 바꾸고, 생존 0개·압축 복원의 공개 결과 시험은 그대로.
- 배달 코퍼스: 떼어진 참조 쓰기 단계는 이 규칙으로 의미가 바뀌므로 그 단계를 코퍼스에서 지우고(관측점 수 변화를 기록) 나머지 관측점에서 단계 머리 대비 차이 0.
- 최종 머리에서 한 번: build·typecheck·lint·다섯 프로젝트·verify, 선언 차분 기록, 격리 시험, 첫 쓰기 파서 0.
- 창 하나(A = 병합 전 단계 머리, B = 최종 머리): 악화 없음(TEST-073 0, `switch-oneOf-80`·`switch-siblings-0` 장부 총합 A 폭 안, Node 힙 B 중앙값 ≤ A 최대)과 보유량 행; finalizeExits·cloneFromSlot self의 감소는 기록하되 요구하지 않는다(결함·일관성 PR이지 성능 가설이 아님).
- 문서: 바뀐 fractal의 DETAIL이 코드보다 먼저, `docs/en/SPECIFICATION.md`·`docs/ko/SPECIFICATION.md`에 "떼어진 참조의 규칙", 마이그레이션 한 줄("비활성을 건너는 노드 참조는 재진입 뒤 `find`로 다시 얻는다; 비활성 값은 호스트의 `setValue` JSON으로 쓴다"). 독립 검토는 claude 검증 에이전트, 판정 파일을 PR 전에 가지에.
