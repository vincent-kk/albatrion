## 457라운드의 간소화와 규칙(소유자 지시)

결과는 추세만, 판정만: 남은 B2 가설은 코드 검토 한 번과 측정 판정만 하고 2부 검토는 생략하며, 결과 문서는 표와 판정 한 줄이다. B2 묶음의 채택은 같은 창의 A/B 단계 장부에서 겨냥한 단계가 상한 아래 또는 절반 이하로 줄고 어느 단계도 나빠지지 않으며 주판정 TEST-073 회귀 0, Node 힙 B 중앙 ≤ A 최대이면 채택이고 총합 행은 B3에서 누적 판정한다(457C-03, 재검증). PR 본문·결과 문서·커밋 메시지는 기계 로컬 경로를 인용하지 않고, 측정 요약은 `../../verification/branch-switch/raw/<가설>/`, 검토 판정은 `../../verification/branch-switch/reviews/`에 커밋한다(457C-05). 설계 Ⅱ(B4)는 `design-ii.md`의 규칙으로 판정한다.

## 458라운드의 처리 규칙과 B4-2의 채택 규칙

준비물 누락(플러그인 dist)이나 외부 고부하(XProtect)로 중단된 창은 측정의 흐트러짐이 아니라 환경 실패이므로 판정 불가·중단 창으로 한 줄 기록하고, 플러그인 dist 빌드와 A/B 사본의 22행 44동작 무계측 적재 점검을 통과시킨 뒤 같은 고정 구성으로 새 창을 한 번만 연다(정식 표본이 0인 보류는 재시도가 아니다, 458C-03). 힙 스냅샷의 노드 ID 추적은 판정에 쓰지 않고 호스트당 슬롯 수·바이트와 reset 뒤 슬롯 호스트 수만 적는다. B4-1 후보 2는 고정 장치의 원판정(채택 조건 미충족)을 고치지 않은 채 편집자 결정으로 채택했고 제안 규칙(겨냥한 단계의 감소 합 대비 기존 단계의 악화 합이 1/10 이하, 주판정 TEST-073 회귀 0, Node 힙 통과면 악화를 기록한 채 채택)은 소유자 재검증 대상이다(458C-04). B4-2의 채택: 전후 배달 비교 0, `switch-siblings-0`의 장부 합·unwrapped 지연과 `markCommitDeliveries`가 A(병합된 B4-1, 슬롯 on)의 자기 폭 안이거나 더 좋음, 어느 단계도 A의 폭 밖으로 나빠지지 않음, 주판정 TEST-073 회귀 0, Node 힙 B 중앙 ≤ A 최대, Bun 보고; 지워지는 구현(잠복 저장소, `slots` off/verify)을 직접 단언하던 시험은 같은 시나리오·같은 공개 기대값으로 공개 관측 또는 슬롯 계약 단언으로 옮기고, 장치 자체가 목적인 단언은 지우며, 바뀐 단언과 지운 케이스는 PR 본문에 파일별로 열거한다(458C-06).

## 459라운드의 형제 관문 상한과 B3 장치, 마감 판정

형제 관문의 "작은 상수 배"는 창 전에 3배로 고정했다(siblings-1000 ≤ 3 × siblings-0; 0.16.1 레인의 같은 비와 1,000개당 선형항을 함께 보고). B3는 기존 교대 장치를 타이밍 경로 수정 없이 재사용해 세 레인을 한 창에서 재고(0.16.1 레인은 A 쪽 10프로세스만 주표·품질), 단계 장부는 4행 × A/B × 3회이며 단계 시작 판은 저장소 밖 호환 실행기에서 같은 함수 타이머를 재사용해 B0 장부와 대조한다(매핑 불일치 단계는 비교 제외); 관문 판정은 총합 행으로만 한다. Node 노드당 힙의 단계 관문은 중앙값 ≤ 중앙값이고 PR마다의 규칙(B 중앙 ≤ A 최대)도 함께 적는다. B3 결과: oneOf-80·discriminator-80·if-80·형제·Node 힙 중앙 미달, TEST-073·제거 단계 호출 0 통과(`../../verification/branch-switch/b3-results.md`). 계획서대로 단계를 B3에서 멈추고 수치와 선택지 셋(관문 수정 뒤 B5 마감 / 선택·계산 self와 형제 선형항의 설계 Ⅲ / 9단계)을 소유자에게 올린다(459C-05).

## 460라운드의 결함 수정 관문과 검증 스케줄

결함 수정 PR(B6·B7)은 성능 가설이 아니므로 "겨냥한 행의 폭 밖 개선"을 요구하지 않고 악화 없음만 본다: 한 창의 A/B에서 TEST-073 주판정 0, `switch-oneOf-80`·`switch-siblings-0`의 단계 장부 총합이 A의 폭 안, Node 노드당 힙 B 중앙값 ≤ A 최대(`plan/branch-switch/defect-fixes.md` 관문 절). 검증은 단계로 나눈다: 수정 반복 중에는 표적 시험과 typecheck·lint만, 독립 검토는 지난 검토 이후의 delta만, 창은 한 측정 담당이 후보들을 연달아 돌리며, 다섯 프로젝트 전체·verify·배달 비교·선언 차분은 검토를 통과한 최종 머리에서 PR당 한 번 한 worktree씩 돌린다. 동작 무결함은 양보하지 않는다: 최종 머리의 전체 시험이 하나라도 빨간 상태로는 PR을 열지도 병합하지도 않으며, 검토가 최종 머리 뒤에 제품 수정을 요구하면 그 머리에서 전체 관문을 다시 한 번 돌린다. 측정 창의 실행은 구현 워커가 적은 인계 파일(번들 경로와 해시, 사전 점검·창·요약 명령, 결과 문서의 미기입 절)을 받은 측정 담당이 맡고, 사전 점검은 프로세스 하나가 30 %를 넘으면 거절한다(합계는 기록만). 독립 검토는 코디네이터가 수행하고 판정 파일을 PR 전에 가지에 넣는다. B5는 B3와 같은 세 레인과 여섯 관문으로 설계 Ⅱ의 이정표를 적는다.

## 461라운드의 보강 PR 관문과 설계 Ⅲ 제안

보강 PR(B8)은 결함 수정 PR과 같은 "악화 없음" 관문(위 460라운드 절)에 겨냥 행 하나를 더한다: `mount-oneOf-80`(단계 시작 2.04 → 이정표 2.34 ms)을 단계별 마운트 장부로 세 머리(`0eb03ff3b`·`95853ae5f`·`ad0be79ba`)에서 재어 늘어난 몫을 단계에 귀속하고, 단계마다 "이유 있는 느려짐(문서화된 동작을 사는 비용, 수치와 함께 수용)"과 "무의미한 느려짐(중복 순회·쓰지 않는 파싱·건너뛸 수 있는 진단, 수정과 호출 수 시험으로 복원)"을 판정해 결과 문서에 적는다(소유자 규칙: 느려짐의 사유를 어느 쪽이든 특정한다). 전용 오류 코드로 `dist/index.d.ts`가 이름 하나만큼 넓어지는 것은 소유자가 허용한 예외이며 선언 차분을 결과 문서에 적는다. 설계 Ⅲ은 `plan/branch-switch/design-iii.md`에 PR 단계(B9-0 측정, B9-1~3 가설, B10 이정표)와 PR별 판정을 두었고, 461라운드에 소유자가 착수를 정했다("좋아 설계3 진행. 그 다음 다시 측정하고 설계4를 검토해보자."); B10 뒤 설계 Ⅳ를 검토한다. B9-0은 제품 변경이 없으므로 A/B 없이 기준 머리 한 레인의 창 하나와 결과 문서로 닫고, 그 뒤의 PR 관문은 아래 "게이트 — PR마다"와 460라운드의 검증 스케줄을 그대로 쓰며, 독립 검토는 claude 검증 에이전트가 맡는다(460C-05).

**창 스케줄 규칙(461라운드, 소유자 지시 "앞으로는 이런 실수가 반복되지 않도록 잘 좀 스케줄링 하도록 하렴").** 460~461라운드에 창이 네 번 중단되어(B6 플러그인 dist 누락, B5 번들 444 권한과 러너 자신의 프로세스 미제외, B8 시스템 데몬 `mds_stores`·`duetexpertd`의 수 초 부하 두 번) 그때마다 검토·구현이 멈췄다. 앞으로의 창은 다음을 지킨다. (1) **정식 시작 전 무시간 스모크 한 번**: 번들·dist·플러그인·권한·적재를 프로세스 하나로 통과시킨 뒤에만 정식 시작 마커를 찍는다(준비물 실패는 스모크에서 잡힌다). (2) **사전 점검은 프로세스별 30 %를 3초 평균으로 재고, 넘으면 중단이 아니라 5초 간격 최대 120초 시작 지연**(B8 장치); 러너 자신의 에이전트 프로세스는 제외하며, 120초 안에 조용해지지 않을 때만 환경 실패다. 이 장치는 PR마다 복사하지 않고 `tools/window/`(공용)에 두어 모든 창이 같은 장치를 쓴다. (3) **창은 임계 경로를 막지 않는다**: 제품 관문이 초록이면 독립 검토와 PR 본문 준비를 창과 동시에 진행하고(검토는 읽기 전용), 창 결과는 병합 전에만 붙이면 된다. 창 중에 금지되는 것은 시험·빌드·다른 창뿐이다. (4) **창은 모아서 한 번**: 한 PR의 후보가 여럿이면 한 러너가 연달아 돌리고, 제품 바이트가 바뀌지 않은 후속 커밋(시험·문서)은 창을 다시 요구하지 않는다. (5) 환경 실패는 458C-03대로 기록하되 같은 원인으로 두 번째 중단이 나면 세 번째 시도 전에 장치를 고친다(원인을 고치지 않은 재시도 금지).

## 462라운드의 결함·일관성 PR 관문(B11)과 보강 계약(B12), 창 재개 규칙

B11(떼어진 참조의 단일 규칙, #487)은 결함·일관성 PR이라 성능 가설이 없고 "악화 없음" 관문만 건다: 수정 전에 실패하는 시험 네 묶음(떼어진 쓰기의 무효와 개발 경고·운영 침묵, `find` 불변 회귀, 64회 재진입의 도달 노드 고정, B7 옛 참조 쓰기 시험의 기대값 "효과 없음"), 배달 코퍼스에서 의미가 바뀐 떼어진 쓰기 관측점을 빼고 나머지 차이 0(491 → 429), 최종 머리의 다섯 프로젝트·verify·격리·첫 쓰기 파서, 선언 차분은 기록만(릴리스 전, 소유자 "공개표면은 없다"), 창 하나(TEST-073 0, `switch-oneOf-80`·`switch-siblings-0` 장부 총합 A 폭 안, Node 힙 B 중앙값 ≤ A 최대, 보유량 행; finalizeExits·cloneFromSlot self는 기록만). 독립 검토가 제품 바이트를 바꾸는 수정을 요구하면 수정 전 창은 "대체됨"으로 보존하고 최종 관문과 창을 새 머리에서 한 번 더 연다(B11: 창 1 → 창 2). 바이트 중립의 판정은 재빌드 뒤 런타임 번들 셋과 공개 `index.d.ts`의 해시다: 내부 선언 TSDoc과 해시 매니페스트만 다르면 창 없이 닫는다(462C-05). B12(`exit-value.md`)는 같은 관문에 두 길의 배달 장면과 공개 선언 기록(멤버 하나·형 셋·키 하나·경고 멤버 둘)을 더한다.

**표본 사이의 양보(463라운드, B9-0 진단).** 러너가 표본 사이에 매크로태스크 경계를 둘 때는 `setImmediate()`(`node:timers/promises`)를 쓰고 `setTimeout(0)`은 쓰지 않는다: 잠드는 루프는 코어의 성능 상태를 낮춰 같은 번들의 중앙값을 잠든 횟수에 비례해 1.3~5.2배 늘렸다(B9-0). 새 러너나 양보 방식이 바뀐 러너는 창 전에 행당 프로세스 하나의 파일럿으로 중앙값/최솟값 비 1.2~1.4를 확인한다. 잠드는 루프로 잰 표(B5의 alternate 표)와의 절대 비교는 하지 않고, 관문은 같은 창 안의 A/B 상대값으로 판정한다.

## 463라운드의 창 동시성·장치·병합 순서 규칙과 설계 Ⅳ의 관문

창 아홉(B9-0 하나, B12 넷, B9-1 넷) 가운데 여섯이 중단된 라운드 뒤의 규칙(463C-05): 같은 기계의 두 워커는 코디네이터 허가로 창을 하나씩 열고 다른 워커는 창 시작 status부터 창 종료 디스패치까지 편집만 한다(파일럿 같은 짧은 측정도 같다); 새 장치나 바뀐 장치는 검증·적재 스모크로 끝내지 말고 실제 CLI를 1행·1프로세스·예열 1/표본 1로 정식 마커 없이 예행한다; 준비 루트와 원시 폴더는 이름이 `.noindex`로 끝나고 Spotlight 계열(`mds`·`mds_stores`·`mdworker`)만 시작 지연 허용이 600초이며 그 밖의 외부 부하는 120초 그대로다; 창 원시의 CPU 관측은 상위 10개 프로세스의 이름과 비율만 남긴다; 두 제품 PR을 병행할 때 뒤에 병합되는 PR은 앞 PR을 병합한 머리 위에서 최종 관문과 창을 다시 잰다(창 순서는 "먼저 끝나는 쪽 병합 → 나머지 rebase → 창"); 독립 검토의 P2가 제품 바이트를 바꾸면 수정 전 창은 "대체됨"으로 보존하고 새 머리에서 관문과 창을 한 번 더 연다; 자원 경합의 시간 상한 실패는 단독 재현 뒤 조용한 시간에 한 번만 재실행한다.
