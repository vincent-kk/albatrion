# 최적화 — 성능 최적화 — 검증 구성요건

## 검증 원칙

첫째 게이트는 **동작 불변**이다. 이 작업의 어떤 PR도 새 동작을 더하지 않으므로 02–08이 쌓은 시험 전체가 그대로 오라클이고, 시험 파일의 변경은 추가만 허용한다. 둘째 게이트는 **측정**이다. 개선은 같은 기계·같은 명령의 전후 비교로만 주장하고(TEST-029), 선은 TEST-072·073의 `guard:check` 규칙이며 새 수치를 지어내지 않는다. 셋째는 **원장 불변**이다. 최적화가 원장 결정 문장과 닿으면 코드가 아니라 라운드가 먼저다.

## 게이트 — 묶음 PR마다 단독으로 통과해야 하는 것

- 전체 시험 초록. `git diff --stat`에서 시험 파일은 추가 줄만(기존 단언 변경 0). 바꿔야 통과한다면 그 PR은 머지하지 않는다.
- PR 본문 머리의 예측(함수·크기)이 측정으로 확인됨: 대상 행이 예측한 방향으로 측정 오차(10–90백분위 퍼짐) 밖으로 개선. 오차 안이면 "개선 없음"으로 적고 코드는 되돌린다.
- 다른 어떤 벤치 행도 TEST-073의 선을 넘어 나빠지지 않음. 넘으면 머지하지 않고 원인을 같은 PR에서 분리한다.
- `B2` 노드당 힙이 최적화 전 판보다 크지 않음.
- 공개 겉면 변경 0(`tsc --strict`의 공개 형 선언 diff 0, TEST-070의 설정 그대로).
- 속도·메모리 비용 문장이 PR 본문에 있음(패키지 `CLAUDE.md`).
- 대장(`verification/performance-issues.md`) 행 갱신이 같은 PR에 있음.
- 원장 접촉이 있으면 라운드 항목이 먼저 머지되어 있음.
- filid 스캔(organ 외부 소비 0, 순환 0), seiri 게이트.

- 계약 위반 행 0: M1이 "위반"으로 분류한 모든 행이 "해결"에 있고 차수 탐침이 선형 이하를 보인다(GOAL-011, SETTLE-017).
