# 최적화 — 성능 최적화 — 검증 구성요건

## 검증 원칙

첫째 게이트는 **동작 불변**이다. 이 작업의 어떤 PR도 새 동작을 더하지 않으므로 02–08이 쌓은 시험 전체가 그대로 오라클이고, 시험 파일의 변경은 추가만 허용한다. 둘째 게이트는 **측정**이다. 개선은 같은 기계·같은 명령의 전후 비교로만 주장하고(TEST-029), 선은 TEST-072·073의 `guard:check` 규칙이며 새 수치를 지어내지 않는다. 셋째는 **원장 불변**이다. 최적화가 원장 결정 문장과 닿으면 코드가 아니라 라운드가 먼저다.

## 게이트 — PR마다 단독으로 통과해야 하는 것

PR 하나는 수용한 가설 3~4개를 담고, 가설마다 커밋 하나다. 아래 게이트는 PR마다 한 번 돈다(결정 대기열 56(344라운드 편집자 가결정, 소유자가 뒤집을 수 있음, `reviews/owner-queue-07.md`)).

- 전체 시험 초록. `git diff --stat`에서 시험 파일은 추가 줄만(기존 단언 변경 0). 바꿔야 통과한다면 그 PR은 머지하지 않는다.
- PR 본문 머리의 예측(함수·크기)이 측정으로 확인됨: 대상 행이 예측한 방향으로 측정 오차(10–90백분위 퍼짐) 밖으로 개선. 오차 안이면 "개선 없음"으로 적고 코드는 되돌린다.
- `--equivalent`(옛 판 대비, TEST-073의 선)의 어떤 행도 선을 넘어 나빠지지 않음. 넘으면 TEST-027의 절차(이유를 적고 소유자 수용)를 밟되, 원인을 같은 PR에서 분리한다.
- 패키지 벤치의 다른 행이 최적화 전 판보다 측정 오차(10–90백분위 퍼짐) 밖으로 나빠지지 않음. 이 기준은 이 계획의 규칙이며 원장 항목이 아니다.
- `B2` 노드당 힙이 최적화 전 판보다 크지 않음.
- 공개 겉면 변경 0(배포 형 선언 `dist/index.d.ts`의 diff 0).
- 속도·메모리 비용 문장이 PR 본문에 있음(패키지 `CLAUDE.md`).
- 대장(`verification/performance-issues.md`) 행 갱신이 같은 PR에 있음.
- 원장 접촉이 있으면 라운드 항목이 먼저 머지되어 있음.
- PR 직전의 전체 게이트 한 번(309라운드: 빌드·표면 열거·unit·render·react18·production·storybook·플러그인 일곱·documents·filid validate, 그리고 verifier 한 번), seiri 게이트.

## 게이트 — 작업 전체(M3)가 통과해야 하는 것

- 계약 위반 행 0: M1이 "위반"으로 분류한 모든 행이 "해결"에 있고 차수 탐침이 선형 이하를 보인다(GOAL-011, SETTLE-017).
- 세 판 대조표(옛 판·최적화 전·최적화 뒤)가 같은 기계·같은 세션에서 M0와 같은 명령으로 재어져 `verification/perf-optimization/`에 있다.
- 남은 느린 행마다 이유와 수치, 그리고 **소유자 수용**이 소유자 답 파일에 있다(TEST-027). 수용은 다른 세션을 거친 말이 아니라 소유자의 직접 답이어야 한다.
- 대장의 열림은 "해결" 또는 "소유자 수용"만(미확인·미측정·측정 과제 0).
- NODE-055의 B1–B6 합격선 재판정(B1·B5·B6은 TEST-073의 선 안(NODE-055 원문의 "`guard:check`의 선"; 독립 스크립트의 같은 프로세스 레거시 열 대비), B2는 추정의 1.5배 이내이며 오늘보다 크지 않음, B3 같은 맵, B4 보고).

## 합격 판정과 실패 처리

- 묶음 PR: 위 게이트 전부 통과 + 측정 첨부. 개선이 오차 안이면 폐기, `--equivalent`의 회귀(TEST-073의 선)는 TEST-027 절차, 패키지 벤치 행의 회귀는 이 계획의 규칙대로 머지하지 않음, 원장과 부딪히면 멈추고 라운드.
- 작업 전체: M3 게이트 전부 통과 + 소유자 수용. 통과하지 못한 행은 09의 벤치 재실행(LANDING-096)으로 넘기지 않고 이 작업 안에서 닫는다 — 09는 "최적화 뒤" 판을 다시 재는 일만 한다.
