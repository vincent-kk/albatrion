# 최적화 — 성능 최적화 — ADR과 핵심 축

> ADR 본문은 권위가 아니다. 축은 원리·수락된 결정·목표다(PROCESS-034). 구현 중 현장 판단은 원리 원장으로 돌아와 한다(PROCESS-005). 이 작업은 결정을 더하지 않는다 — 결정을 바꿔야 빨라진다면 그것은 최적화가 아니라 설계 변경이고, 라운드가 먼저다.

## 이 작업이 지켜야 하는 축

| 축 | 원장 | 이 작업에서의 뜻 |
| --- | --- | --- |
| G6 비용은 변경에 비례 | GOAL-011, TEST-029 | 유일한 "반드시 고침" 기준. N(노드·형제·조각·규칙)에 비례하는 비용은 수용 대상이 아니라 결함이다. 상수 비용은 측정으로 고칠지 정한다 |
| 다섯 가치 — 고속성 | GOAL-050 | 최소 생성, 메모리 안정, 캐싱. "같은 값을 두 번 읽으면 같은 참조"는 최적화 뒤에도 그대로다 |
| 비용의 상한 | SETTLE-017 | 순회 범위(재계산 목록과 자동 쓰기 기록만, 트리 전체는 로드만), 되돌림 기록, 역의존 표, 라운드 합산, 컴파일 공유. 최적화는 이 상한 안에서 상수를 줄이는 일이며 상한 자체를 바꾸지 않는다 |
| P3 형상은 상태의 순수 함수, 출발점 고정 | GOAL-029, SETTLE-018, SETTLE-044 | 직전 커밋의 활성 집합에서 출발하는 최적화는 기각되어 있다. 이력을 캐시로 쓰는 어떤 지름길도 같은 까닭(양의 순환에서 결과가 달라짐)으로 후보가 아니다 |
| 게이트는 전부 다시 평가 | BLUEPRINT-007 | 게이트가 읽는 것을 뽑아 건너뛰지 않는다. 허용된 남는 최적화는 셋 — 루트 키만 읽는 게이트의 건너뛰기, `delete` 없는 키 제거, 조각이 선언한 키만 패치 — 이고 넣을지는 벤치가 정한다 |
| 노드 비용 모델 | NODE-018, NODE-055 | 노드마다 객체 하나·행 아홉·숨은 클래스. `B2` 상한(추정의 1.5배)은 재판정 대상이지 완화 대상이 아니다. 아이템 노드의 지연 실체화는 NODE-053이 06 벤치 게이트의 실패 처리로만 열어 둔 길이라, 06의 판정 없이 이 작업이 꺼내지 않는다 |
| 성능은 측정 | TEST-029, TEST-031, TEST-026 | 기준선은 고정 커밋의 옛 판과 같은 실행의 쌍. 주장만 있는 개선은 머지하지 않는다 |
| 선과 수용 | TEST-072, TEST-073, TEST-027 | 선은 `guard:check`(처리량 −15%·Welch p<0.05), 절대 수치·배율 상한은 두지 않는다. 선을 넘은 것은 이유를 적고 Vincent가 받아들인다 |
| G5 결정성 | GOAL-009 | 같은 입력에 같은 결과. 캐시·색인은 결과를 바꾸지 않아야 하며 그 증명은 기존 시험 전체의 초록이다 |
| 공개 계약 불변 | SURFACE 영역 | 겉면의 이름·형·반환형은 바뀌지 않는다. 바뀌면 이 작업의 범위 밖이다 |

## 축이 금하는 후보 (들어오면 멈춘다)

- 직전 커밋의 `active`에서 이어 출발하는 정착(SETTLE-044).
- 게이트의 읽기 경로를 뽑아 건너뛰는 역색인(BLUEPRINT-007, ADR 0005의 기각).
- 아이템 노드의 지연 실체화(NODE-053) — 06 벤치 게이트의 실패 처리로 열린 경우가 아니면.
- 정착 단계의 생략이나 순서 변경(SETTLE-017, ADR 0007).
- 공개 겉면의 축소·개명으로 얻는 속도.

이 가운데 하나가 유일한 길로 보이면 코드를 바꾸지 않고 새 라운드 항목으로 올린다. 소유자가 P3 대 속도의 맞바꿈을 정한다(SETTLE-044의 실패 처리 문장).
