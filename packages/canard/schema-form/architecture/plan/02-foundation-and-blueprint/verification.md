# 02 기반 + 청사진 — 검증 구성요건

## 검증 원칙

이 PR은 `<Form>`에 닿지 않는다. 옛 시험 전체가 회귀 신호이고, 새 코드는 순수 함수라 테이블 테스트로 닫힌다. 독립 장치 넷 가운데 1(옛 엔진 유지)·2(레거시 import 금지)를 이 PR이 세우고, 4(시나리오 하니스)의 뼈대를 만든다(README §3).

## 게이트 — 이 PR이 단독으로 통과해야 하는 것

### 기반
- 프로토타입 v7의 회귀 프로브 전부(v5·v6 회귀 목록, TEST-060) + 18라운드 프로브: 규칙 A 표 전체와 동점 12건, `integer` 멤버십, 게이트 전이에서 경고등만 바뀌고 값은 그대로, `setValue({kind:'num', a:'42'})`가 직전 상태와 무관하게 `a = 42`(U7), 되먹임 반례 `['string','boolean']`의 라운드 상한(WRITE-099), 빈 루트는 `undefined`(VALUE-034).
- `yarn test`가 세 프로젝트로 나뉘어 돌고 옛 시험 전부 초록.
- 벤치 기준선 결과 파일이 커밋에 고정(TEST-031).

### 청사진
- 청사진 판정 예 E1–E42(BLUEPRINT-045) 전부, union 시험 목록의 청사진 줄(TEST-077), 청사진 오류·경고 코드마다 한 사례(ERROR-164의 청사진 행).
- `$ref` 재귀 게이트(TEST-067): 스캐너 확인, 코퍼스 14종, 무한 형상 표본, 청사진 1회 비용. 표본 (c′)는 03.
- 잎 교차 함수 이동 뒤 옛 시험 전부 초록(예외: `const` 깊은 비교).
- 이주 점검의 청사진 줄(LANDING-198): `['object','null']`은 nullable object, `['null']`은 null 노드, `[]`·`['string','string']`은 오류, `integer`/`number` `allOf`의 `schemaType`은 오늘과 같다.
- 레거시 규칙 1 린트 통과, filid `max-depth` 통과.
