# 02 기반 + 청사진 — 검증 구성요건

## 검증 원칙

이 PR은 `<Form>`에 닿지 않는다. 옛 시험 전체가 회귀 신호이고, 새 코드는 순수 함수라 테이블 테스트로 닫힌다. 독립 장치 넷 가운데 1(옛 엔진 유지)·2(레거시 import 금지)를 이 PR이 세우고, 4(시나리오 하니스)의 뼈대를 만든다(README §3).

## 시험 구성

| 프로젝트 | 무엇을 더하는가 |
| --- | --- |
| `unit` | 청사진 테이블 테스트(`src/core/blueprint/__tests__/`), 잎 교차 함수 시험, `$ref` 코퍼스 시험, v7 프로브(spikes) |
| `render` | 옛 렌더 시험 그대로(회귀 신호) |
| `storybook` | 자리만(옛 스토리 그대로) |
| 시나리오 패키지 | 돌리는 것은 "없음"(TEST-023). 패키지는 "스키마·초기값·단계·기대(순수 데이터)"와 `FormScenario` 형·`playScenario`·시나리오 감싸개만 든다(TEST-023) |

## 게이트 — 이 PR이 단독으로 통과해야 하는 것

### 기반
- 프로토타입 v7의 회귀 프로브 전부(v5·v6 회귀 목록 63 + 108 + 26 + 52, TEST-003·TEST-060. 새 엔진으로의 이식은 TEST-069 (라)대로 03·04·05가 나눈다) + 18라운드 프로브: 규칙 A 표 전체와 동점 12건, `integer` 멤버십, 게이트 전이에서 경고등만 바뀌고 값은 그대로, `setValue({kind:'num', a:'42'})`가 직전 상태와 무관하게 `a = 42`(U7), 되먹임 반례 `['string','boolean']`의 라운드 상한(WRITE-099), 방출이 없는 루트는 루트 종류의 빈 그릇 — 객체 루트 `{}`, 배열 루트 `[]`, 그 밖의 루트 `undefined`(VALUE-034; v6은 빈 루트를 `undefined`로 내므로 v7이 고친다).
- `yarn test`가 세 프로젝트로 나뉘어 돌고 옛 시험 전부 초록.
- 벤치 기준선 결과 파일이 커밋에 고정(TEST-031).

### 청사진
- 청사진 판정 예 E1–E42(BLUEPRINT-045) 전부, union 시험 목록의 청사진 줄(TEST-077), 청사진 오류·경고 코드마다 한 사례(ERROR-164의 청사진 행).
- 청사진 시험(TEST-014): "청사진 테이블 시험(조각 열거, 전순서, 노드 공유, `controls.discriminator` 변환과 끌어올림, `extras` 정적 집합, 역의존 표, 청사진 오류·경고), 병합표 시험, 제거 규칙 시험(키워드 위치만), 식 컴파일러 시험(옮긴 9파일 + 기준점 호스트. `regex.test.ts`의 `SIMPLE_EQUALITY_REGEX` 묶음은 그 상수와 함께 옛 엔진에 남긴다)". 병합표 시험은 "런타임 교차의 공집합은 던지지 않고 표준 JSON Schema로 적는다"(SCHEMA-045)의 표현을 단언한다.
- 병합과 전략(TEST-014): "`options`·`presentation` 병합의 원자(React 요소, ref 모양)·한쪽 값의 참조 이동·양쪽 객체의 쓰기 시 복사(작성자 객체를 변이하지 않음, `@winglet/common-utils`의 `merge` 선택 인자 포함)", "선언 사이 `options.terminal`·렌더 계층 판정의 불일치(노드가 형상에 있는 경우마다 순서대로 정한 전략이 다르면 청사진 오류. 게이트 없는 선언끼리는 나중 승, 조각에만 선언된 노드는 조각이 모두 꺼진 경우를 비교하지 않음(조각 하나에만 선언된 노드의 인라인 `presentation.FormTypeInput`·`options.terminal`은 오류가 아님, 두 조각이 같은 노드에 서로 다른 전략을 주면 청사진 오류), 게이트 없는 선언의 `options.terminal`이 정한 노드에 조각이 인라인 입력을 더해도 오류가 아님, 판정의 없음은 앞 판정을 지우지 않음)".
- 경고 수집(TEST-014): "청사진 경고의 데이터 수집(수집기 인자, 코드·`schemaPath`·판별 칸, 소비자가 없으면 모으지 않음, 캐시 청사진의 늦은 수집이 작성 루트마다 한 번)". TEST-014의 마지막 항목(정적 `controls.injectTo` 대상 없음의 청사진 오류)은 시험하지 않는다(LANDING-061의 충돌 줄, CONTROLS-079).
- `$ref` 재귀 게이트(TEST-067): 스캐너 확인, 코퍼스 14종, 무한 형상 표본, 청사진 1회 비용. 표본 (c′)는 03.
- 잎 교차 함수 이동 뒤 옛 시험 전부 초록(예외: `const` 깊은 비교).
- 이주 점검의 청사진 줄(LANDING-198): `['object','null']`은 nullable object, `['null']`은 null 노드, `[]`·`['string','string']`은 오류, `integer`/`number` `allOf`의 `schemaType`은 오늘과 같다.
- 레거시 규칙 1 린트 통과, filid `max-depth` 통과.
