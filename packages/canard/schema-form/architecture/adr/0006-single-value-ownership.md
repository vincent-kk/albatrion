# ADR 0006 — 값의 소유: 노드 트리가 곧 상태다

상태: 일부 수락 (4차 본문). "노드 트리가 곧 상태"는 수락(2차안). 칸 목록과 `emit` 불변식, D-1(null 계약)은 원리에서 도출(`reviews/round-5-derivations.md` §3), 소유자 확정 대기.

## 변경 이력

- 2026-09-23 — 4차 본문. 3·4·5라운드 반영(E1–E19, F1–F32, D-1–D-10 도출). 이전 본문의 "확인된 결함" 절은 본문에 흡수하고 삭제.
- 2026-09-22 — 2라운드(`reviews/round-2.md`)의 S7·S9와 ADR 0013 교차검증의 지적을 "확인된 결함" 절에 적었다.
- 2026-09-22 — 1차안("루트가 불변 JSON 값 트리 하나를 소유하고 노드는 경로에 대한 뷰")을 대체했다. 이유: 적대적 검토 R12(`reviews/round-1.md`) — JSON 값만으로는 입력 중인 원본, null 아래의 자식 상태(#338), 꺼진 조각의 값을 둘 자리가 없다. 검토가 제안한 "편집 상태를 담는 별도의 셀 트리"에 대해 소유자는 중앙에 값을 두는 것은 허용하되 **데이터 모델을 따로 두는 것은 거부**하고, 노드가 React Fiber처럼 동작하는 방식을 택했다.

## 합의 근거

- 소유자: "중앙에 값을 두는 걸 허용. 단, 데이터모델을 따로 두는 건 안 돼. react 파이버처럼 node가 동작하도록 했으면 해. 최적화와 라이프사이클 관점에서의 단일화는 동의해."
- 소유자: "브랜치 노드에서 브랜치 전략이냐 터미널 전략이냐는 내부 동작은 다르지만 노출 표면(사용자 입장)은 같아야 해. 브랜치 노드가 항상 복사값만을 가지는 건 아니야. 경우에 따라서는 브랜치 노드인 객체나 배열이 터미널처럼 직접 값을 쓰기도 하니까."

## 맥락

현재는 값을 자식이 소유하고 모든 레벨이 사본을 든다(`01-current-structure.md` D4). 자식을 가진 노드는 `__value__`/`__draft__`/`__composed__`에 배열 슬롯의 `data`/`output`까지 최대 4벌을 유지하고, 상향 전파는 클로저 콜백이며, 역류를 막으려고 `__locked__` 같은 불린이 쌓였다. 캐시(`__composed__`, `__normalized__`)는 여러 경로에서 무효화되고 읽는 시점에 다시 계산된다.

## 결정

**1. 별도의 데이터 모델을 두지 않는다. 노드 트리가 곧 상태다.**

**2. 노드가 드는 칸은 아홉이고, 그 가운데 상태는 셋뿐이다.**

| 칸 | 종류 | 내용 |
| -- | ---- | ---- |
| `raw` | 상태 | 원본. 리프와 터미널 노드가 값을 든다. 호스트는 비객체 값(`null`, `17`)이 왔을 때만 든다 |
| `selection` | 상태 | 판별식이 없는 union 호스트의 수동 선택. 판별식이 있으면 칸이 없다 (E2) |
| `extras` | 상태 | 호스트가 받은, 어떤 조각에도 선언되지 않은 키와 값 (E16) |
| `active` | 계산 | 이번 커밋의 활성 조각 집합 |
| `local` | 계산 | 활성 자식 `emit`의 합성 — 투영 전 |
| `emit` | 계산 | `local`의 투영 |
| `settle` | 계산 | `{status: 'stable' \| 'budget-exceeded', sweeps}` — 호스트만 |
| `dirty` | 작업 | 이번 정착에서 다시 계산할 자식의 목록 |
| `revision`·커밋 번호 | 원장 | 통지 때 오르는 단조 카운터와, 커밋마다 오르는 단조 번호 (F16·F28) |

**상태는 `raw`·`selection`·`extras` 셋뿐이다**(P3). 나머지는 상태에서 계산되거나 작업의 기록이다. "노드 트리가 곧 상태"는 이 셋을 노드가 소유한다는 뜻이다.

**3. 저장되는 값은 자식 노드가 없는 노드에만 있다** — 터미널 타입(string·number·boolean·null)과 터미널 전략의 object·array. 자식 노드가 있는 노드의 값은 자식들로부터 계산되어 **그 노드에 메모된다.**

**4. 노출 표면은 전략과 무관하게 같다.** `value`, `setValue`, 구독, 이벤트는 자식 노드의 유무에 따라 달라지지 않는다.

**5. 비활성 노드는 원본을 유지한다. `null`을 포함한 전체 교체는 V에 없는 원본을 지운다.** 조각이 꺼지는 것은 **쓰기가 아니라 방출에서의 제외**이며(P4), `omitEmpty`·`omitTrailing`도 원본을 건드리지 않는 투영 규칙이다.

**6. 불변식은 `emit`에만 있다**(E9): 부모의 `emit` = 활성 자식 `emit`의 투영. `raw`에는 그런 불변식이 없다 — 비활성 노드와 비객체 호스트 아래 자식의 원본은 부모의 `emit`에 나타나지 않는다.

**7. 투영 전 로컬 메모를 따로 둔다**(S9). `node.value`는 `local`, `getValue()`는 `emit`이다. "노드의 메모는 루트 스냅숏의 해당 부분과 같은 참조"는 `omitEmpty`·`omitTrailing`이 투영을 바꾸는 노드에서 거짓이므로, 구조 공유는 `emit` 사이에서만 말한다.

**8. `emit`의 참조**는 (자식 `emit` 참조 ∪ `extras` ∪ 호스트 `raw` ∪ 활성 키 집합) 가운데 하나라도 바뀌면 새로 만들고, 아니면 이전 참조를 그대로 둔다(F9). "같은 값을 두 번 읽으면 같은 참조"가 이것으로 성립한다.

**9. 읽기는 계산하지 않는다.** 메모를 쓰는 곳은 작업 루프의 커밋 단계뿐이고(ADR 0007), 무효화 수단은 조상 방향의 dirty 표시 하나다.

### null 계약 — D-1

상태: **원리에서 도출(`reviews/round-5-derivations.md` §3), 소유자 확정 대기.**

`setValue(null)`은 키가 없는 전체 교체이므로 자식 원본이 없음이 되고, 다시 객체가 될 때 로드 계약의 `default`가 빈 상태를 만든다(ADR 0007 §3). 원본 칸 하나로 족하며 셋째 칸도 특수 장치도 없다 — 2라운드 S7(#338 S4와 "null 아래도 원본 유지"의 충돌)은 이렇게 닫힌다. 3라운드 E9의 "비객체 V는 자식 raw를 건드리지 않는다"와 E18("비객체 호스트의 자식은 비활성")은 **삭제**한다: 비객체 호스트의 자식은 **존재하고 렌더되며** 빈 상태를 보인다. 실수로 누른 null의 되돌리기는 입력 컴포넌트의 몫이다.

### 읽기가 쓰기보다 잦은 구조에서의 비용

| 동작 | 비용 |
| ---- | ---- |
| `node.value` 등 모든 읽기 | 필드 접근. 계산 없음 |
| 쓰기 1회 | 경로의 각 레벨에서 얕은 복사 한 번. 실측: 키 1,000개 객체 1.1 µs, 아이템 10,000개 배열 2.7 µs (`reviews/round-1.md` §2). 형제 서브트리는 참조를 재사용한다 |
| dirty 표시가 없는 서브트리 | 통째로 건너뛴다 |
| 쓰기 N회의 배치 | 표시 N번, 작업 루프 1번 |
| 가드와 `&` 식 | **변경 키 역색인은 쓰지 않는다**(E13) — 출발점 고정에서 무효다. 유효한 최적화는 (a) 무조건 루트 키만 읽는 가드의 건너뛰기, (b) 조각 끄기의 키 제거를 `delete` 없이 하는 것, (c) 조각이 선언한 키만 패치하는 합성(F13) |

## 결과

- 레벨마다의 사본, `__draft__`/`__composed__`의 지연 합성, 상향 콜백 그래프, 역류 방지 잠금이 필요 없어진다.
- 분기 복원, `active` 재활성화, null 계약이 "원본은 남고 방출에서만 빠진다" 하나로 설명된다. 나가는 노드를 reset하고 들어오는 노드에 값을 복원하며 타입 호환을 검사하는 절차가 없어진다(R8, T-23).
- 입력 도중 조각이 잠깐 꺼져도 데이터가 지워지지 않는다. 다시 켜지면 돌아온다.
- 상한에 걸린 계산을 고정해도 커밋된 트리는 그대로다(ADR 0007).

## 남는 것

- **배열 아이템의 identity.** 값 배열에는 키가 없고 통째 쓰기는 키를 싣지 않는다. 구조 연산이 갱신하는 identity 목록은 ArrayNode가 든다(R13, T-22). 통째 쓰기를 재조정으로 바꿀지는 ADR 0011.
- **꺼진 조각이 선언한 자식의 잠복 원본.** 방출되지 않으므로 검증기가 기각하지 않고 잔여 목록에도 없다 — 설계상 잠복이다(P4). core는 읽기 전용 `latent(path)`(가칭)로 열거만 하고(F26), 실제 파기 시점(reset·명시적 분기 전환·제출 후)은 `open-questions.md` Q1.
- **검증기가 기각한 잔여 키의 표시.** 입력 노드가 없는 키를 사용자가 고칠 수단이 필요하다. 어떤 에러가 "키 하나를 기각한다"인지의 해석은 **검증기 플러그인의 계약**이며(P1), 정규화된 에러의 선택 필드 `rejectedKey?: string`을 플러그인이 채우고 core는 그것을 가진 호스트 에러만 모은다(C-4, F8). 두 이름 이상의 `not: {required}`는 단일 키가 없어 호스트 에러로 남는다. 표시는 렌더 계층의 몫이고 Q12와 함께 정한다.
- **선택 상태의 reset과 분기 전환의 확인** (ADR 0010).

## 기각한 대안

- **1차안 — 루트가 소유하는 JSON 값 트리, 노드는 뷰.** R12로 기각.
- **루트가 소유하는 셀 테이블 + 필요할 때 만드는 손잡이 노드.** 소유자가 별도의 데이터 모델을 거부했다. 큰 배열에서 노드 생성을 늦추는 최적화는 이 결정 안에서도 가능하다 — 자식 노드가 실체화되기 전까지 array 노드가 터미널처럼 값을 직접 든다. 필요 여부는 벤치마크로 정한다(ADR 0009, 0011).
- **노드별 소유를 유지하고 사본 동기화를 고친다.** 복잡함의 원인이 남는다.
