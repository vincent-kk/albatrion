# ADR 0006 — 값의 소유: 노드 트리가 곧 상태다

상태: 수락 (2차안).

## 변경 이력

- 2026-09-22 — 1차안("루트가 불변 JSON 값 트리 하나를 소유하고 노드는 경로에 대한 뷰")을 대체했다. 이유: 적대적 검토 R12(`reviews/round-1.md`) — JSON 값만으로는 입력 중인 원본, null 아래의 자식 상태(#338), 꺼진 조각의 값을 둘 자리가 없다. 검토가 제안한 "편집 상태를 담는 별도의 셀 트리"에 대해 소유자는 중앙에 값을 두는 것은 허용하되 **데이터 모델을 따로 두는 것은 거부**하고, 노드가 React Fiber처럼 동작하는 방식을 택했다.

## 합의 근거

- 소유자: "중앙에 값을 두는 걸 허용. 단, 데이터모델을 따로 두는 건 안 돼. react 파이버처럼 node가 동작하도록 했으면 해. 최적화와 라이프사이클 관점에서의 단일화는 동의해."
- 소유자: "브랜치 노드에서 브랜치 전략이냐 터미널 전략이냐는 내부 동작은 다르지만 노출 표면(사용자 입장)은 같아야 해. 브랜치 노드가 항상 복사값만을 가지는 건 아니야. 경우에 따라서는 브랜치 노드인 객체나 배열이 터미널처럼 직접 값을 쓰기도 하니까."

## 맥락

현재는 값을 자식이 소유하고 모든 레벨이 사본을 든다(`01-current-structure.md` D4). 자식을 가진 노드는 `__value__`/`__draft__`/`__composed__`에 배열 슬롯의 `data`/`output`까지 최대 4벌을 유지하고, 상향 전파는 클로저 콜백이며, 역류를 막으려고 `__locked__` 같은 불린이 쌓였다. 캐시(`__composed__`, `__normalized__`)는 여러 경로에서 무효화되고 읽는 시점에 다시 계산된다.

## 결정

1. **별도의 데이터 모델을 두지 않는다. 노드 트리가 곧 상태다.**
2. **저장되는 값은 자식 노드가 없는 노드에만 있다** — 터미널 타입(string·number·boolean·null)과 터미널 전략의 object·array. 자식 노드가 있는 노드의 값은 자식들로부터 계산되어 **그 노드에 메모된다.**
3. **노출 표면은 전략과 무관하게 같다.** `value`, `setValue`, 구독, 이벤트는 자식 노드의 유무에 따라 달라지지 않는다.
4. **"중앙의 값"은 루트 노드에 메모된 방출 값이다.** 커밋된 스냅숏이며, 각 노드의 메모는 그 스냅숏의 해당 부분과 **같은 참조**다. 구조 공유이지 사본이 아니다. 부모와 자식의 값이 어긋날 수 없다.
5. **노드가 드는 것**: 원본(편집 상태 — `''`, 후행 빈 아이템, null 여부), 메모된 방출 값, 활성 여부, dirty 표시. 비활성 노드와 null 조상 아래의 노드도 원본을 유지한다. 방출 값에서 빠질 뿐이다.
6. **읽기는 계산하지 않는다.** 메모를 쓰는 곳은 작업 루프의 한 단계뿐이고(ADR 0007), 무효화 수단은 조상 방향의 dirty 표시 하나다.

### 읽기가 쓰기보다 잦은 구조에서의 비용

| 동작 | 비용 |
| ---- | ---- |
| `node.value` 등 모든 읽기 | 필드 접근. 계산 없음 |
| 쓰기 1회 | 경로의 각 레벨에서 얕은 복사 한 번. 실측: 키 1,000개 객체 1.1 µs, 아이템 10,000개 배열 2.7 µs (`reviews/round-1.md` §2). 형제 서브트리는 참조를 재사용한다 |
| dirty 표시가 없는 서브트리 | 통째로 건너뛴다 |
| 쓰기 N회의 배치 | 표시 N번, 작업 루프 1번 |
| 가드와 `&` 식 | 입력의 참조가 바뀐 것만 다시 계산한다. "어떤 경로가 바뀌면 누구를 다시 계산하는가"는 역색인으로 찾는다(가드 수와 무관하게 13 ns) |

"같은 값을 두 번 읽으면 같은 참조"(패키지의 설계 가치)는 바뀐 자식이 없으면 이전 메모의 참조를 그대로 두는 것으로 성립한다.

## 결과

- 레벨마다의 사본, `__draft__`/`__composed__`의 지연 합성, 상향 콜백 그래프, 역류 방지 잠금이 필요 없어진다.
- 분기 복원, `active` 재활성화, null 계약이 "노드의 원본은 남고 방출에서만 빠진다" 하나로 설명된다. 나가는 노드를 reset하고 들어오는 노드에 값을 복원하며 타입 호환을 검사하는 절차가 없어진다(R8).
- 입력 도중 조각이 잠깐 꺼져도 데이터가 지워지지 않는다. 다시 켜지면 돌아온다.
- 상한에 걸린 계산을 버려도 커밋된 트리는 그대로다(ADR 0007).

## 남는 것

- **쓰기 의도의 기록.** "같은 값을 다시 써도 null 조상이 풀린다"(`ObjectNode/DETAIL.md` S6)는 값만 봐서는 구분할 수 없다. `derived`와 `injectTo`는 같은 단계에서 돌지만 객체를 만드는 권한이 다르다. 출처를 단계만으로 구분할 수 있다는 가설은 기각됐다(R12). `open-questions.md` Q2.
- **스키마가 선언하지 않은 키.** 자식 노드가 있는 object에 선언되지 않은 키가 들어오면 그 값을 둘 자리가 필요하다. "로드 후 그대로 저장하면 값이 같은가"(`reviews/round-1.md` §7-3)와 묶인다.
- **배열 아이템의 identity.** 값 배열에는 키가 없고 통째 쓰기는 키를 싣지 않는다. 구조 연산이 갱신하는 identity 목록은 ArrayNode가 든다(R13). 통째 쓰기를 전량 재생성이 아니라 재조정으로 바꿀지는 ADR 0011.
- **꺼진 분기에 남는 값의 파기.** 민감한 값이 남을 수 있다. 언제 실제로 지울지(reset, 명시적 분기 전환, 제출 후)는 `open-questions.md` Q1.
- **`&derived`.** 지금은 derived가 노드에 값을 쓴다. 메모 단계의 계산으로 바꾸면 사용자가 derived 필드를 직접 고칠 수 있는지를 정해야 한다.

## 기각한 대안

- **1차안 — 루트가 소유하는 JSON 값 트리, 노드는 뷰.** R12로 기각.
- **루트가 소유하는 셀 테이블 + 필요할 때 만드는 손잡이 노드.** 소유자가 별도의 데이터 모델을 거부했다. 큰 배열에서 노드 생성을 늦추는 최적화는 이 결정 안에서도 가능하다 — 자식 노드가 실체화되기 전까지 array 노드가 터미널처럼 값을 직접 든다. 필요 여부는 벤치마크로 정한다(ADR 0009, 0011).
- **노드별 소유를 유지하고 사본 동기화를 고친다.** 복잡함의 원인이 남는다.
