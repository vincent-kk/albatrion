# ADR 0005 — 스키마 → 청사진 분석 단계와 노드 공유 규칙

상태: 일부 수락(4차 본문). "같은 이름 + 같은 타입이면 노드 하나를 공유한다"는 수락. 분석 단계의 분리와 청사진의 형태는 제안. §3의 "같은 종류"와 정적 throw의 폐지, §4의 판별식 식별(E14)은 수락된 규칙의 세부를 고친 것이어서 **소유자의 확인이 필요하다.** §4의 에러 라우팅은 제안이며 규칙은 ADR 0004에 적는다(Q12).

## 변경 이력

- 2026-09-22 — 적대적 검토 1라운드 R11(`reviews/round-1.md`)을 반영했다. (a) "같은 타입"을 타입 표기의 동일성이 아니라 **같은 노드 종류**로 다시 정의했다 — `number`와 `integer`, `['string','null']`과 `'string'`은 배타가 아니다. (b) "배타가 구조로 보장되지 않으면 분석 단계에서 throw"를 없앴다 — 이 규칙은 ADR 0002가 필수 지원이라 한 `allOf: [{ if k=a then v:string }, { if k=b then v:number }]`를 거부했고, "같은 `oneOf`의 분기끼리는 배타"라는 가정은 런타임에 성립하지 않았다. 종류가 다른 선언의 충돌은 런타임에 드러낸다. (c) 판별식을 "기본 프로퍼티의 재선언"이 아니라 **분기 집합으로부터** 식별한다. (d) 제약의 교차가 공집합이어도 throw하지 않는다. §2의 "호스트 참조가 그대로면 건너뛴다"는 같은 검토의 측정으로 고쳤다.
- 2026-09-22 — 2라운드(`reviews/round-2.md`)의 S4·S13을 "확인된 결함" 절에 적었다.
- 2026-09-23 — 4차 본문. 3·4·5라운드 반영(E1–E19, F1–F32, D-1–D-10 도출, 소유자 원칙 P1′). 이전 본문의 "확인된 결함"·"교차검증 중" 절은 본문에 흡수하고 삭제.

## 맥락

- 조각이 `properties` 밖에서 새 노드를 선언할 수 있으므로(ADR 0002) 노드 생성 전의 전처리가 지금보다 복잡해진다(소유자의 지적).
- `allOf` + `if`/`then`/`else`를 쓰면 같은 이름의 필드에 여러 스키마가 겹친다. 같은 타입이면 여러 조건이 병합되어야 한다(소유자의 지적). 이 때문에 계약 재설계와 노드 코어 재설계는 따로 갈 수 없다.
- 현재는 `$ref` 해석, `allOf` 병합, 노드 생성이 하나의 팩토리 클로저 안에서 얽혀 있고, 스키마를 제자리 변형한다(`01-current-structure.md` D1).
- 폼이 읽는 것은 형상 문법뿐이다(P1′, ADR 0002·0013). 이 문서의 모든 읽기는 그 안에 있어야 한다.

## 결정

### 1. 복잡도를 순수한 분석 단계로 옮긴다

```
작성된 스키마 ──(순수 함수, 폼 생성 시 1회)──▶ 청사진 ──▶ 노드 트리

ObjectBlueprint {
  base:      PropertyDecl[]        // properties
  fragments: Fragment[]            // 정적으로 열거된 모든 조각
}
Fragment {
  id          // 작성된 스키마 안의 위치 (schemaPath). 에러 라우팅의 키
  guard       // 값 가드(스키마) 또는 선택 가드
  context     // 연언 | 선언, 그리고 어느 oneOf/anyOf의 분기인가 (ADR 0002)
  declares    // 이 조각이 새로 선언하는 property
  constrains  // 기존 property에 얹는 overlay: name → 스키마
  inherited   // 조상에서 끌어올린 조각이 이 호스트에 귀속시킨 overlay (E12)
  children    // 중첩 조각 — 감싸는 조각이 활성일 때만 순회한다 (E3)
}
```

- 작성된 스키마는 변형하지 않는다(ADR 0001). 분석 결과는 별도 구조에 둔다.
- `forbids` 칸은 없다. 금지 구문은 폼이 읽지 않는다(ADR 0002, D-3).
- "`properties` 밖에도 노드가 있다"는 런타임의 특수 경로가 아니라 청사진의 `declares`를 읽는 일반 경로가 된다.
- 조각은 스키마에서 **정적으로 열거된다.** 그래서 "모든 분기 자식을 사전 생성하고 활성만 토글"하는 현재의 트리 모델(D2)을 유지할 수 있다.
- 끌어올린 조각의 `then`이 손자를 선언하면 청사진이 그 선언을 자식 호스트의 `inherited`로 귀속시킨다(E12). 가드는 조상의 것이므로 자식은 자기 바퀴에서 그것을 평가하지 않는다.
- `allOf`의 무조건 항목은 가드가 항상 참인 연언 조각이다. 기존 `intersectSchema`는 "활성인 연언 조각들을 교차하는 연산"으로 승격된다.
- 폼은 방언 스위치 없이 **두 철자를 모두 읽는다**: `items: [..]`와 `prefixItems`, `definitions`와 `$defs`(`00-goals.md` C5).

### 2. P1′와의 경계 — 구조는 읽고, 의미는 평가하지 않는다

폼은 서브스키마가 **어디에 있고 무엇을 선언하는지**(`properties`, `items`, `prefixItems`, `if`/`then`/`else`, `allOf`/`oneOf`/`anyOf`, `$ref`, `type`)를 읽는다. 값이 스키마를 **만족하는지**는 평가하지 않는다. 그것은 언제나 `compileGuard`가 답한다. 값의 유효성 문법은 읽지 않는다(ADR 0002 "금지 조각은 없다").

**가드가 무엇을 읽는지는 기본적으로 뽑지 않는다.** dirty가 닿은 노드에 걸린 가드를 전부 다시 평가한다. 측정에 따르면 AJV에서는 이것으로 충분하다 — 루트에 걸린 좁은 가드 200개를 키 입력마다 전부 돌려 7.9 µs다(`reviews/round-1.md` §2). "가드가 걸린 객체의 참조가 그대로면 건너뛴다"는 루트에 걸린 가드에 대해 효과가 없다(어떤 쓰기든 루트의 참조를 바꾼다).

건너뛰기가 실제로 필요한 경우는 둘이다: 인터프리터형 검증기(같은 작업이 약 70배), 컬렉션을 훑는 가드(`contains` 등 — 아이템 10,000개에 AJV 190 µs, 인터프리터 4.5 ms). 변경 경로 → 가드의 역색인은 출발점 고정(ADR 0002, D-2) 아래에서 듣지 않으므로 후보에서 뺐다(E13). 남는 최적화는 (a) 무조건 루트 키만 읽는 가드의 건너뛰기, (b) 조각이 꺼질 때 키 제거를 `delete` 없이 하는 것, (c) 조각 토글마다 전체 리빌드 대신 그 조각이 선언한 키만 패치하는 것(F13)이다. 넣을지는 ADR 0009의 벤치마크로 정한다.

### 3. 같은 이름 필드의 규칙

노드의 **종류**는 여섯이다: string, number(`integer` 포함), boolean, null, object, array. nullable(`type: ['string', 'null']`, `nullable: true`, null 분기와의 `anyOf`/`oneOf` — 현재 `helpers/jsonSchema/isNullBranch`가 알아본다)은 종류가 아니라 노드의 플래그다. `type`이 없는 overlay(`{ const }`, `{ enum }`, `{ minimum }`)는 어느 종류와도 맞는다.

| 상황 | 처리 |
| ---- | ---- |
| 같은 이름 + 같은 종류 (어느 조각이든) | **노드 하나를 공유한다.** 활성인 선언이 하나라도 있으면 존재한다. 유효 스키마의 제약은 ADR 0002의 합성 규칙으로 정한다 |
| 같은 이름 + 다른 종류 | 종류별로 노드를 둔다. 같은 시점에 활성인 선언의 종류가 하나면 그 노드가 산다 |
| 같은 이름 + 다른 종류가 **동시에** 활성 | 런타임 충돌이다. 앞서 선언된 종류의 노드를 살리고, 충돌을 작성자에게 드러낸다(`00-goals.md` C2) — 개발 모드에서는 에러, 그 밖에서는 폼 수준의 경고. 분석 단계에서 미리 throw하지 않는다 |

- "앞서"와 "나중"은 ADR 0002의 **전순서**(감싸는 조각의 순서, 키워드 순위, 배열 인덱스)로 정의한다. 2라운드 S13(순서가 JSON 키 순서에 기댄다)은 이것으로 닫힌다.
- 판별식 union의 `value: string` / `value: number`는 흔하고 정당한 선언이다. 판별식 가드는 서로소이고 `required`를 포함하므로(ADR 0002, 아래 §4) 통상 동시에 활성이 되지 않는다.
- `allOf: [{ if k=a then v:string }, { if k=b then v:number }]`도 같은 방식으로 동작한다. 가드가 동시에 참이 되는 스키마를 썼다면 그것은 작성자의 실수이고, 검증기도 그 값을 기각한다.
- **제약의 교차가 공집합이어도 throw하지 않는다.** 서로소인 `enum` 둘이 연언 문맥에서 동시에 활성이면 그 필드는 "지금 고를 수 있는 값이 없는" 상태가 되고 개발 모드에서 경고한다. 필드를 비우면 값이 유효해지는 경우가 있으므로 폼 전체를 멈춰서는 안 된다(R11-e).

### 4. 판별식의 식별 (E14)

`oneOf`/`anyOf`의 분기 **집합**을 보고 정한다. 2라운드 S4(분기 최상위에 `properties`가 없는 `allOf: [{$ref}, {properties}]`, null 분기, OpenAPI 3.0의 `mapping`을 놓친다)는 이 순서로 닫힌다.

| 단계 | 규칙 |
| ---- | ---- |
| 1 | 분기의 `$ref`를 풀고, `allOf` 항목의 `$ref`도 풀어 **`allOf`가 없어질 때까지 반복** 평탄화한다. 방문 집합으로 종료를 보장하고 자기 참조에서는 중단한다. 같은 키의 교차 결과 최상위에 `const`/`enum`이 남아야 한다 |
| 2 | null 분기를 벗긴다 — `type: 'null'`, `type`에 `'null'` 포함, `nullable: true`가 모두 nullable이며 분기 자체는 유지한다. 남은 분기가 다시 union이면 이 절차를 재귀하고 nullable을 전달한다 |
| 3 | 후보를 모은다 — 어떤 프로퍼티 이름 `k`를 **모든 분기**가 `const` 또는 `enum`으로 제약하면 후보다. 다원소 `enum`을 허용한다. OpenAPI의 `discriminator.propertyName`은 **힌트이지 무조건 채택이 아니다** — 모든 분기에 그 키의 `const`/`enum`이 있어야 후보로 남는다 |
| 4 | 후보 **전부**에 서로소 검사를 한다. 값 집합이 빈 분기가 있으면 판별식이 아니다 |
| 5 | 통과한 후보 가운데 (`discriminator.propertyName` > `required`에 포함 > 사전순)으로 하나를 고른다 |

- 가드는 ADR 0002대로 `{ properties: { k: <분기의 제약> }, required: ['k'] }`.
- 값이 겹치거나 일부 분기에만 있으면 판별식이 아니다. 그 union은 **선택 가드**가 되고 노드의 `selection` 칸이 분기를 고른다(E2). 초기 선택과 "빈 값이면 분기 없음"은 ADR 0002.
- `mapping` 전용(분기 스키마에 `const`가 없는 OpenAPI 3.0 모양)은 지원하지 않는다 — 표준 검증기는 그 스키마에서 태그로 분기를 고르지 않는다. 선택 가드로 보내고 개발 모드에서 경고한다: "태그로 형상을 정할 수 없다 — 검증기는 `required` 차이로 분기를 고른다".
- ajv의 `discriminator: true`는 pydantic 출력에도 throw하므로 플러그인이 켜지 못한다.
- 기본 `properties`에 `k`가 선언되어 있는지는 묻지 않는다. **판별 프로퍼티 k는 union 호스트가 소유한다**(E8) — k의 스키마는 분기 값의 합집합 `enum`이고, 활성 분기의 k 스키마를 overlay한다. 2라운드 S2(판별 필드 교착)는 이 소유 규칙으로 닫힌다. 암묵 default는 없다(D-8, 수락 2026-09-22, `reviews/round-4.md` §4). select의 선택지는 분기들의 `const`/`enum`의 합집합이다.
- 회귀 표본은 `spikes/guard-cost/redteam3/corpus.mjs`의 14종이다 — pydantic 2.9(판별·Optional·재귀), OpenAPI 3.0(mapping 전용·nullable 분기), OpenAPI 3.1(2단 `allOf` 상속·`type: [object, null]`), zod-to-json-schema 3.23(`const`·`enum` 태그), TypeBox 0.32, typescript-json-schema 0.64, 태그 값이 겹치는 손수 쓴 `anyOf`.

값이 겹치는지 보려고 `const`/`enum`의 **값**을 읽는 것은 형상을 만드는 최소한의 읽기이므로 P1′ 안에 있다. 소유자: "`oneOf`/`anyOf`에서 `enum`/`const`를 사용하는 폼 제어 같은 간단한 건 넣을 수도 있다." 값의 만족 여부는 여전히 검증기가 답한다.

**에러 라우팅(제안).** `instancePath`가 **union 호스트 자신**이고 `schemaPath`가 union 키워드를 지나는 에러(`const` × N, `required` × N, `oneOf`)를 판별 노드에 모은다. 활성 분기 **안** 필드의 에러는 그 필드에 남는다(F6). 판별식이 없는 union이면 호스트에 모은다. **이것은 아직 제안이고 규칙은 ADR 0004에 적는다**(Q12, E17).

이 규칙은 현재의 "`type`/`$ref`가 없는 `const`/`enum`이면 판별식"(`getCompositionKeyInfo.ts:33`, `getExpressionFromSchema.ts:43` — 두 파일이 서로를 언급하지 않은 채 같은 암묵 규칙에 기댄다)과 `COMPOSITION_PROPERTY_REDEFINITION` throw(`getCompositionNodeMapList.ts:95-105`)를 대체한다. `JSONSchema` 타입이 `kind: { const: 'a' }`를 받아들이게 하는 것은 `00-goals.md` C4.

## 합의 근거

- 같은 이름 + 같은 타입이면 노드 하나를 공유한다 — 소유자: "동의합니다."
- 타입이 다르면 오류 — 소유자: "타입이 달라버리면 우리로서는 답이 없지만(이 경우엔 오류가 throw 되겠지)." 개정분은 이 오류를 **분석 단계의 throw에서 런타임의 충돌 보고로** 옮긴다. 소유자가 순환에 대해 택한 방침("돌려보고 터지는 걸 개발 단계에서 알려준다", ADR 0007)과 같은 방향이지만 이 규칙에 대한 확인은 따로 받아야 한다.

## 결과

- 같은 종류의 필드는 분기가 바뀌어도 같은 노드이므로 값이 자연스럽게 남는다. 현재의 "나가는 노드 reset → 들어오는 노드에 `fallbackValue` 복원 → `validateSchemaType`으로 타입 호환 검사"(`ObjectNode/.../BranchStrategy.ts:479-511`) 절차가 필요 없어진다.
- `node.jsonSchema`가 정적 값에서 메모된 유효 스키마로 바뀐다(ADR 0006). `then`이 `enum`을 좁히면 select의 선택지가 바뀌어야 하기 때문이다. 유효 스키마가 바뀌면 입력 컴포넌트의 해석 결과도 바뀔 수 있다(`format`이 달라지는 경우 등). 이를 알리는 이벤트는 ADR 0007의 미결.
- 분석 단계는 노드 없이 테스트할 수 있다(`02-target-overview.md` §5-2).

## 미결

- **주석성 키워드의 병합 우선순위.** 현재 `intersectSchema`의 정책(관찰): 범위 키워드는 좁히는 교차, `enum`은 집합 교차(공집합이면 throw — §3에 따라 바꾼다), `pattern`은 lookahead AND, `required`는 합집합. `title`·`description`·`default`·`readOnly`·`format`·`additionalProperties` 등은 **먼저 정의된 쪽이 이긴다**(`processFirstWinFields.ts:16-27`). 그 밖의 모든 키(`FormTypeInput`, `options`, `computed`, `&` 키)는 **나중 것이 이긴다**(`processOverwriteFields.ts:15-25`). "먼저/나중"은 §3의 전순서로 정의하면 결정적이다. `default`가 선언 순서에 따라 달라지는 것은 표준에서 나온 결과가 아니라 폼의 쓰기 규칙이다(`reviews/round-1.md` R6의 둘째 반례). 정책을 그대로 둘지는 소유자가 정한다.
- **종류가 조건에 따라 바뀌는 슬롯.** `type: ['string', 'number']`, 원시 타입끼리의 `anyOf`. nullable 말고는 아직 다루지 않았다. 값 union(`oneOf: [string, object]`)도 청사진 모델 밖이다.
- **배열.** `items`/`prefixItems` 안의 조각, 아이템 단위의 가드 평가 — ADR 0011. `contains`와 튜플은 Q13.
- `$ref`의 재귀 스키마에서 조각의 정적 열거가 어디서 끝나는가. 현재 `$ref` 해석 깊이의 기본값은 1이다(`getResolveSchema.ts:18-28`).
- 따로 컴파일한 가드가 `$id` 기저 URI와 `$dynamicRef`의 동적 범위에서 문맥 안의 평가와 같은 답을 내는가(ADR 0004).
- 에러 라우팅 규칙을 ADR 0004에 기재하는 일(Q12).

## 되돌림 가능성

청사진의 구체적 형태는 내부 구조여서 바꾸기 쉽다. 노드 공유 규칙은 값 보존 동작을 정하므로 공개 후에는 바꾸기 어렵다.
