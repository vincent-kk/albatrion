# ADR 0013 — core는 값을 고치지 않는다

상태: 제안(4차 본문). 원칙은 소유자가 발의했고 2026-09-23에 재확인했다("합의 근거"). D-7(로드 계약을 그대로 두고 호출 단위로 억제한다)은 **수락**(2026-09-22, `reviews/round-4.md` §4). D-1(null은 키 없는 전체 교체)·D-4(쓰기 종류는 호출자 선언)·D-5(억제 스위치는 유일한 자동 쓰기를 끈다)는 **원리에서 도출**(`reviews/round-5-derivations.md` §3), 소유자 확정 대기. 옵션의 이름은 후보다.

## 변경 이력

- 2026-09-22 — codex 교차검증의 요지를 적었다. 규칙화는 `reviews/round-3-spec.md` C.
- 2026-09-23 — 4차 본문. 3·4·5라운드 반영(E1–E19, F1–F32, D-1–D-10 도출, 소유자 원칙 P1′). 이전 본문의 "확인된 결함"·"교차검증 중" 절은 본문에 흡수하고 삭제.

## 맥락

소유자: "현재 스펙은 form이 좀 적극적으로 값을 바꾸고 있다. 앞으로는 field가 가려지면서 node가 deactive 되면서 값을 빼내는 걸 제외하고는, 어지간하면 입력 등을 막지 않고 error를 보여주려고 한다. array 같은 경우 min/max length 같은 처리는 FormTypeInput에서 구현하도록 위임할까 한다. core가 값을 바꿔버리는 건 예외 상황이 너무 많다." 이어서: "문제가 되는 게 setValue로 값을 주입하는 경우일 텐데, 이때는 form의 노출과 형태를 특정 값으로 수렴시킨 다음에, 보이지 않는 필드는 제거(숨김 필드 및 extra field는 제외)하고 나머지는 값에 따라 에러 메시지 등을 보여줘야 하지 않나 싶다. 확신이 없다. 책임 경계를 어떻게 해야 할지." 그 확신 없던 자리를 소유자가 2026-09-23에 원칙으로 답했다.

## 합의 근거

소유자(2026-09-23, `reviews/round-5-derivations.md` §0):

> "schema form으로서 특정한 값을 주입했을 때 기대되는 값은 그 값을 '유효성 검사를 통과하는 것으로 교정'하는 건가? 그걸 바랐다면 ajv autofix 같은 걸 쓰지 않았을까. 나는 form이 값을 바꾸도록 이전에 설계했고, 이 방식이 사용자에게 혼란을 준다는 걸 느껴서, 값 수정은 안 하고 에러만 보여주는 걸 기본 동작으로 하려고 했다. 빼거나 지우는 건 모두 `&`로 시작하는 명령으로 조작해야 한다. 그러면 JSON Schema 문법을 form이 추적하며 구현할 필요는 없다. 노드 타입을 결정하는 일부 동작(튜플, `type: [number, string]`)과 가변 구성을 위한 `if-then-else` 같은 일부 문법만 차용한다."

이 발언이 이 ADR의 원칙을 재확인하고 동시에 P1′(폼이 읽는 것은 형상 문법뿐)을 낳았다. P1′는 ADR 0002의 D-3(금지 조각을 읽지 않는다)을 도출한다.

## 결정

1. **core는 받은 값을 고치지 않는다.** 유효하지 않은 값은 그대로 들어가고 에러로 보인다. 입력을 막지 않는다.
2. **예외는 하나다 — 비활성 노드의 값은 방출에서 빠진다.** 원본을 지우는 것이 아니라 방출을 계산할 때의 제외다(ADR 0006·0007, P4).
3. **제약을 입력 단계에서 강제하는 일은 입력 컴포넌트에 위임한다.** core는 제약을 유효 스키마로 노출하고(`node.jsonSchema`) 위반은 검증이 알린다.
4. 형상 계산이 수렴하지 않을 때도 값은 받아들인다(ADR 0007).

### 원본을 바꾸는 사건 (P2, E15·E19)

쓰기의 종류는 **호출자가 선언한다.** core는 추론하지 않는다(D-4).

| 사건 | 종류 | 자식 원본 |
| ---- | ---- | -------- |
| 리프 입력, `setValue(V, Merge)` | 부분 쓰기 | 지정한 것만 바뀐다 |
| `setValue(V, Overwrite)`(기본), `defaultValue`, `reset()`, `injectTo` | **전체 교체** | V에 없는 자식의 원본은 **없음**이 된다 |
| 배열 `push`/`remove`/`update` | 구조 연산 | 그 아이템만 |
| `default` 주입 | 로드 계약 (core의 유일한 자동 쓰기) | **없음**인 자식에만 |

- "없음"과 `''`·`null`·`{}`은 다르다. 리프에 `undefined`를 쓰면 없음이 된다.
- `&derived`는 원본을 쓰지 않는다. `injectTo`는 작성자가 선언한 전체 교체이고 **원천의 방출이 직전 커밋과 다를 때만** 발화한다(F11). 자동 쓰기는 비객체 호스트의 원본을 건드리지 않고(F10, T-12), core는 호출자가 넘긴 객체를 바꾸지 않는다(F24, T-19).
- **null은 키 없는 전체 교체다**(D-1). 키가 없으므로 모든 자식의 원본이 없음이 되고 로드 계약이 그 자리에 `default`를 넣어 빈 상태를 만든다 — #338의 계약이 특수 장치도 셋째 칸도 없이 이 표에서 나온다. "null 아래에 원본을 남긴다"는 호출자가 "없다"고 쓴 것을 숨겨 두는 것이므로 P2에 어긋난다. 상태: 원리에서 도출, 소유자 확정 대기.

### 쓰기 옵션 (D-4·D-5·D-7)

공개 옵션은 비트가 아니라 객체다 — `{ mode?: 'Overwrite' | 'Merge'; disableDefaultInjection?: boolean }`(이름은 후보).

| 규칙 | 내용 |
| ---- | ---- |
| 기본 | `mode`는 `Overwrite` — 오늘과 같다 |
| 자리 | `setValue(V, options)`뿐 아니라 **`reset(options)`와 마운트**에도 둔다. 마운트는 `defaultValue`가 로드이므로 Form 속성이 그 자리다 |
| 우선순위 | **호출 옵션 > Form 속성**, 양방향이다. 속성이 켜 둔 억제를 호출이 끌 수 있고 그 반대도 된다 |
| 배치 | 한 배치 안에 서로 다른 억제 값이 섞이면 **억제가 이긴다**(보수적) |
| 범위 | 억제는 호출자의 전체 교체가 일으킨 정착 — 그 안의 전이 주입을 포함 — 에서만 듣는다. 리스너·`injectTo`·사용자 입력이 일으킨 정착은 로드가 아니다(F25) |
| `Merge` + 억제 | 무해한 no-op이다(`Merge`는 로드가 아니다). 판별 유니온으로 막는 것은 실효가 없으므로(리터럴에만 걸림, tsc 실측) **문서로 적는다** |

**`default` 주입은 core의 유일한 자동 쓰기이고 스위치는 그 하나를 끈다**(D-5). 있는 값은 고치지 않는다 — 주입은 "없음"인 키에만 간다. 방향은 확정("초기값 조작 비활성화, `disable…` 형태")이고 이름은 후보다.

**`setValue(getValue())`에는 로드 계약이 그대로 적용된다**(D-7 (a), 수락). 사용자가 지운 키는 `getValue()`에 없으므로 재주입되어 멱등이 아니다. 소유자: "form에 값을 씌우는 경우와 기본값을 설정하는 경우가 다르다. props로는 함수 단위 제어가 안 된다." 호출 단위의 억제 옵션이 그 답이다(F30).

### 값을 통째로 주입할 때 — 결론

- 주입된 값은 꺼진 조각의 노드까지 포함해 모든 노드의 원본으로 분배되고, 형상은 그 값으로 수렴한다(ADR 0002).
- 꺼진 조각의 값은 **방출에서** 빠진다. 원본을 지우지는 않는다(P4). `&visible: false`로 숨긴 필드와 스키마가 선언하지 않은 키는 방출된다 — 숨김은 렌더링에만 닿는다.
- 나머지는 검증이 에러로 알린다.

2라운드의 "절대 제거하지 않는다"가 남긴 결함 — 레코드 A 뒤에 레코드 B를 로드하면 A의 잠복 값이 분기 전환에서 되살아난다 — 은 **전체 교체가 V에 없는 키를 없음으로 만들면서** 사라진다. 비활성화(원본 보존)와 전체 교체(원본에도 적용)를 구분한 것이 답이었다. 남는 잠복은 하나다: 비활성 조각이 선언한 자식의 원본은 방출되지 않으므로 검증기가 기각하지도 잔여 목록에 오르지도 않는다 — 설계상 잠복이다(P4). core는 이를 열거하는 읽기 전용 API를 두어 렌더 계층이 보여 주거나 지울 수 있게 한다(F26, 이름 후보 `latent(path)`).

### 초기값 보존 옵션 — 결론

(a)("첫 의도된 쓰기 전까지 `getValue()`가 주입된 값을 그대로 돌려준다")는 택하지 않는다 — 첫 편집에서 기본값이 나타나고 미선언 키가 빠지는 점프가 생긴다. (b)의 셋 가운데 둘은 **기본 계약이 되었다**: 로드한 값에 없는 키에만 `default`를 넣는 것과, 미선언 키를 호스트의 별도 칸(`extras`)에 보존하는 것(E16). 남은 하나("손대지 않은 값에는 `omitEmpty`·`omitTrailing`을 건너뛴다")는 이력 의존이므로 채택하지 않는다 — 방출은 상태의 투영이다(P4). `preserveDefaultValue`라는 이름은 사라지고 그 자리에 억제 스위치 하나가 남는다.

### core가 값을 바꾸던 곳의 분류

| 오늘의 동작 | 새 원칙에서 |
| ---------- | ---------- |
| 타입별 파서의 강제 변환, `options.trim` | **입력 컴포넌트로**(P2). 입력을 값으로 해석하는 일은 입력의 몫이다 |
| 배열을 `minItems`까지 채우기, `maxItems` 초과 `push` 차단 | **입력 컴포넌트로.** core는 제약을 유효 스키마로 노출하고 위반은 검증이 알린다 |
| nullable이 아닌 객체의 `null`을 `{}`로 바꾸기(S7), 비객체 값 버리기 | **폐기.** 보존·방출하고 type 에러를 낸다. 동작 변화로 기록한다(F27, `04-inherited-constraints.md`) |
| `Normalize`의 미선언 키 제거 | **폐기.** 미선언 키는 `extras` 칸에 보존하고 방출한다(E16) |
| 분기 전환·`active` 전이의 reset | **폐기.** 같은 종류의 노드를 공유하므로 값이 남는다(ADR 0005 §3) |
| `computed.derived`, `injectTo` | **남는다.** 작성자가 명시한 쓰기이며 이 원칙의 대상이 아니다 |

## 교차검증 결과 — codex

2라운드에서 codex 하나의 의견을 받았다(claude 무응답, antigravity 빈 응답). 요지 넷은 모두 본문에 반영됐다 — 비활성화와 전체 교체를 구분할 것, `getValue(setValue(V)) = V`는 어느 정책에서도 성립하지 않고 성립하는 계약은 "현재 원본과 활성 집합의 투영"이라는 것, `preserveDefaultValue` (a)의 기각, 자식으로만 값을 합성하는 object 노드가 주입된 `17`을 들 수 있어야 한다는 것. 전문과 현재 core가 값을 바꾸는 곳의 표는 `reviews/round-2.md` §6, 세 제공자의 원문은 `reviews/raw-crosscheck-decisions-codex.md`·`reviews/raw-crosscheck-decisions-claude.md`·`reviews/raw-crosscheck-decisions-antigravity.md`.

## 미결

- 억제 옵션과 `mode`의 이름, `Overwrite`/`Merge`와의 표기 — Q6.
- **배열의 `Merge`가 무엇을 뜻하는가.** 3.1판은 `Overwrite`와 같게 두고 미결로 표시했다.
- `setValue(undefined)`의 정의, `push()`로 만든 아이템이 로드인지, 입력의 객체 전체 쓰기가 로드인지(derivations §3 D-4·D-5).
- 실수로 누른 `null`의 되돌리기는 입력 컴포넌트의 몫이다(D-1). 표준 예제로 남긴다.
- 잠복 값 열거 API(F26)의 이름과 모양.
