# ADR 0007 — 작업 루프: 표시 → 계산 → 파생 → 전이 → 커밋, 그 뒤에 통지와 검증

상태: 일부 수락 (4차 본문 — 정착 루프 3.1판). 가드가 보는 값과 순환의 처리는 수락. D-7·D-8·D-9·D-10은 수락(2026-09-22, `reviews/round-4.md` §4). 단계의 구성과 D-1–D-6에서 나온 것은 원리에서 도출(`reviews/round-5-derivations.md` §3), 소유자 확정 대기.

## 맥락

현재 복잡함의 원인은 내부 로직이 이벤트를 구독해서 상태를 움직인다는 점이다(`01-current-structure.md` §5). BranchStrategy가 자기 host의 `UpdateComputedProperties`를 구독해 분기를 바꾸고, computed 의존성은 `UpdateValue`를 구독하며, `oneOf`와 `active`가 서로 다른 라이프사이클을 탄다. 이를 막으려고 불린 여섯 개가 쌓였고, 결과가 원인보다 먼저 배달되는 역전이 실측됐다.

## 결정

### 1. 정착 한 번 — 일곱 단계

쓰기(또는 쓰기의 묶음)마다 **한 곳에서, 고정된 순서로** 다음을 돈다.

| 단계 | 하는 일 | 예산 |
| ---- | ------- | ---- |
| 표시 | 쓰기를 받은 노드의 `raw`·`selection`·`extras`를 갱신하고 조상 경로의 dirty 목록에 등록한다 | — |
| 계산 | 루트에서 한 번 내려간다. dirty 자식을 먼저 완료한 뒤 자기 `local`·`emit`을 만든다. **원본을 읽기만 한다**(E1) | 호스트 바퀴 = 조건부 조각 수 + 1 |
| 파생 | 완성된 트리에서 `&derived`(읽기 전용)와 `injectTo`(대상에 대한 전체 교체)를 평가한다. 쓰기가 나오면 표시로 | 라운드 25 |
| 전이 | 직전 커밋의 `active`와 비교해 꺼짐 → 켜짐이 된 조각의 **없음**인 자식에 `default`를 쓴다 → 표시로 | 라운드 = 조각 수 (파생과 **별도**, F2) |
| 커밋 | 계산 결과를 트리에 반영하고 `settle`을 확정한다. 배달 집합 전체의 `revision`을 한 번에 올리고(F16) 단조 **커밋 번호**를 매긴다(F28) | — |
| 통지 | 루트 디스패처가 문서 순서 위 → 아래로 1회 배달한다(ADR 0008) | 틱당 파동 25 (F15), `onChange` 중첩 25 (ADR 0008 §5) |
| 검증 | `validator(작성된 스키마, 방출 값)`. **커밋 번호**를 스탬프하고 비동기로 요청하며, 늦게 온 결과는 버린다 | — |

- **표시부터 커밋까지는 동기·단방향이다.** 비동기는 경계(검증·React·`onChange`)에만 있고 이벤트는 출력 전용이다. 배치는 표시 N번에 계산·커밋 1번, 통지 1번이다.
- **`if`/`then`, `oneOf`/`anyOf`, `&active`는 같은 계산을 탄다.** 라이프사이클이 하나다.
- 원본을 쓰는 것은 파생과 전이뿐이고 둘 다 표시로 돌아간다. 그래서 커밋된 트리는 (스키마, 트리 전체의 `raw`·`selection`·`extras`)의 순수 함수다(F9) — `selection`이 emit을 바꾸므로 "raw의 순수 함수"라는 축약은 쓰지 않는다.
- 상한을 넘기는 파생 라운드는 **실행하지 않고** 마지막으로 완료된 라운드의 원본이 커밋된다(E7). 2라운드의 S3(begin/complete 두 패스)은 사라졌다 — 조각은 완료 단계에서 정해지고 출발점이 고정된다.

### 2. 호스트가 조각을 정하는 법

| 규칙 | 내용 | 근거 |
| ---- | ---- | ---- |
| 출발점 고정 | `A := 무조건 조각 ∪ union의 판별 프로퍼티 ∪ 상속 overlay`. 직전 커밋의 `active`는 **읽지 않는다** — 전이 계산과 평가 순서 힌트(F13)로만 쓴다 | E1·E6 |
| 조각은 트리 | 중첩 조각은 감싸는 조각이 활성일 때만 순회한다. 전순서 = (감싸는 조각의 순서, 키워드 순위 `properties` < `allOf[i]` < `if/then/else` < `oneOf`/`anyOf`, 배열 인덱스) | E3 |
| 매 바퀴 전부 | 한 바퀴에 **모든** 조각의 가드를 평가한다(켜진 것, 꺼진 것 모두). 한 바퀴 안의 켜짐·꺼짐은 뒤의 가드에 즉시 반영된다(가우스-자이델) | E4, F3 |
| 가드 입력 | 가드는 **검증기가 볼 값**을 본다 — `A`로 합성한 local에 투영(`omitEmpty`·`omitTrailing`·null)을 적용한 것. 예외는 하나: 호스트 자신의 `raw`가 비객체이면 `G = {}` | E5, P1 |
| 비단조 재평가 | 참이면 켜고 거짓이면 끈다. `A`가 바뀌면 다시 돈다. 상한 = **조건부** 조각 수 + 1 | E6, F3 |
| 상한 초과 | 마지막 바퀴의 `A`로 고정하고 `settle.status := 'budget-exceeded'`. 프로덕션에서도 관측 가능하고 자식의 초과는 조상으로 전파된다. 개발 모드는 커밋 뒤 **동기로** throw | E6, F12 |
| 금지 조각 없음 | `false` 서브스키마와 `not`은 아무것도 선언하지 않는다. 폼은 읽지 않는다 | P1′, D-3 |
| 상속 overlay | 끌어올린 조각의 `then`이 손자를 선언하면 청사진이 그 선언을 자식 호스트의 overlay로 귀속시킨다. 부모의 바퀴가 overlay 집합을 바꾸면 자식을 **바퀴 안에서** 재계산하되 (`raw`, `selection`, overlay 집합)으로 메모한다 | E12, F5 |
| 합성 | `local := compose(A)`, `emit := project(local)`. `delete` 없이 조각이 선언한 키만 패치한다(F13). `emit`의 키 순서는 스키마 선언 순서, extra는 뒤에 삽입 순서 | E10, F13 |

**고정점이 없는 스키마는 지원 범위 밖이다.** 가드 의존 관계에 부정을 포함한 순환이 있으면 결과는 상한에서 결정적이되 임의적이고 `budget-exceeded`로 표시된다(F3). 대표적인 진동은 `if: { not: { required: ['x'] } }, then: { properties: { x: { default: 1 } } }`다. 고정점이 둘 이상이면(R7) 선언 순서에 대해 결정적인 하나로 정착하며, 어느 경우에도 원본은 남는다.

### 3. 쓰기 — 호출자가 종류를 선언한다

| 사건 | 종류 | 자식 원본에 미치는 것 |
| ---- | ---- | -------------------- |
| 리프 입력, `setValue(V, { mode: 'Merge' })` | 부분 쓰기 | 지정한 것만 바뀐다 |
| `setValue(V)`(기본 `Overwrite`), `defaultValue`, `reset()`, `injectTo` | **전체 교체** | V에 없는 자식의 원본은 **없음**이 된다. `null`·`17`도 V다 — 키가 없으므로 모든 자식이 없음이 된다 |
| 배열 `push`/`remove`/`update` | 구조 연산 | 그 아이템만 |
| `default` 주입 | 로드 계약 (core의 유일한 자동 쓰기) | **없음**인 자식에만. (i) 전체 교체 직후, (ii) 조각이 꺼짐 → 켜짐으로 바뀐 직후 |

공개 옵션은 객체 하나다. 이름은 후보이며, 소유자 방향은 뜻 "초기값 조작 비활성화" + `disable…` 형태로 확정됐다(`reviews/round-3.md` §8).

```ts
setValue(value, options?: { mode?: 'Overwrite' | 'Merge'; disableDefaultInjection?: boolean })
```

- 같은 옵션이 `reset(options)`와 마운트(`defaultValue`)에도 있다. Form 속성이 기본값이고 **호출 옵션이 양방향으로 이긴다**. 한 배치에 서로 다른 억제 값이 섞이면 **억제가 이긴다**.
- `Merge` + 억제는 무해한 no-op이다(`Merge`는 로드가 아니다). 판별 유니온으로 막지 않는다 — 리터럴에만 걸려 실효가 없다.
- 억제의 범위는 호출자의 전체 교체가 일으킨 정착(전이 주입 포함)뿐이다. 리스너·`injectTo`·사용자 입력의 정착은 로드가 아니며, union 판별 프로퍼티의 `default`는 막힌다(F25).
- **`Refresh`는 공개 옵션이 아니다.** core가 **출처**로 판단한다 — 그 노드 자신의 입력에서 온 부분 쓰기는 내지 않고 그 밖의 쓰기가 원본을 바꾸면 낸다(F7, T-2). 타이핑은 리마운트되지 않는다.
- 호스트의 `raw`를 비우는 것은 사용자·호출자의 부분 쓰기뿐이고 **그 자식의 투영된 emit이 존재하게 될 때만** 비운다(F1). 자동 쓰기는 비객체 호스트의 원본을, core는 호출자가 넘긴 객체를 건드리지 않는다(F10·F24, T-12·T-19).
- 전체 교체는 **전이 기준을 비운다**(F4). `injectTo`는 **원천의 emit이 직전 커밋과 다를 때만** 발화하므로 사용자의 부분 쓰기를 되돌리지 않는다(F11).

"core는 값을 고치지 않는다"의 예외는 **방출 정책**(비활성 제외, `omitEmpty`·`omitTrailing`)뿐이고 원본을 건드리지 않는다(P4). core가 스스로 원본에 쓰는 것은 `default` 주입 하나다(E19를 P2로 좁힌 결과).

### 4. 소유자 결정 — D-7 ~ D-10

상태: **수락 (2026-09-22, `reviews/round-4.md` §4)**.

| # | 결정 |
| - | ---- |
| D-7 | `setValue(getValue())`는 (a) — 전체 교체 뒤 **로드 계약이 그대로 적용된다.** 사용자가 지운 키에 `default`가 재주입되므로 멱등이 아니며, 필요하면 호출 단위 억제 옵션으로 끈다 |
| D-8 | 판별 프로퍼티에 **암묵 default는 없다.** 빈 값과 분기 키가 없는 값은 분기 없음이고 판별 필드만 존재한다(현재의 `oneOfIndex = -1`과 같다). 3라운드 E8은 철회. 선택 가드 union에 같은 규칙을 적용하고 여분 키만 있는 값도 "분기 키 없음"으로 보는 확장(C-1·C-7)은 **수락이 아니라 도출**이며 §5와 ADR 0002 규칙 1을 따른다 — 프로토타입 `loop-v4b`는 여분 키만 있는 값에서 첫 분기를 고른다(`REPORT-v4b.txt` §5 U-1) |
| D-9 | `RequestRemount`는 공개 명령으로 남는다 — 사용자가 서브트리의 입력을 제어·비제어와 무관하게 최신화하는 도구(T-18) |
| D-10 | 루트 `onChange`는 **최외곽 동기 진입당 1회**, 그 진입의 마지막 파동 뒤 최종 emit으로. 디바운스 없음 |

- D-8의 실행 확인: `loop-v4b`에서 X2가 `{a:'A'}` → `undefined`로 바뀌었고 새 시나리오 14/14 통과, 기존 63 회귀 0(`spikes/work-loop/REPORT-v4b.txt`).
- D-10의 구현은 **진입 깊이 카운터**다(`spikes/work-loop/REPORT-v4c.txt`). 배치 없는 연속 `setValue` 3회는 통지 3회, `batch`로 묶으면 1회다(C-8·C-9).
- **React 이펙트의 쓰기는 새 진입이다.** 레이아웃·패시브 어느 쪽이든 키 입력당 진입 2·통지 2·검증 2이고(C-10, React 19 + jsdom 7/7, `spikes/events/entry.spike.test.tsx`) 스택 기반 정의로는 합칠 수 없다. core가 풀 문제가 아니라 **문서화 대상**이다 — 파생 값은 `derived`/`injectTo` 또는 스토어 리스너로 쓴다(그러면 1·1·1). 첫 통지의 stale 검증 결과는 커밋 번호 스탬프(F28)가 버린다.

### 5. 원리에서 도출된 것 — D-1 ~ D-6

상태: **원리에서 도출(`reviews/round-5-derivations.md` §3), 소유자 확정 대기.**

| # | 도출 |
| - | ---- |
| D-1 | `null`은 키 없는 전체 교체다(P2). 자식 원본이 없음이 되고 다시 객체가 될 때 로드 계약이 빈 상태를 만든다. #338의 null 계약은 §3 표의 귀결이다 |
| D-2 | 형상은 상태의 순수 함수(P3)이므로 출발점 고정 + 비단조 재평가. 고정점이 없는 스키마는 지원 범위 밖이고 `budget-exceeded`로 관측 가능하다 |
| D-3 | `false`와 `not`은 값의 유효성을 정하는 문법이므로 폼이 읽지 않는다(P1′). 숨기려는 작성자는 `&active`를 쓴다 |
| D-4 | 쓰기의 종류는 호출자가 선언한다(P2). 기본은 `Overwrite`이고 `Refresh`는 core가 출처로 판단한다(F7) |
| D-5 | `default` 주입은 core의 유일한 자동 쓰기이므로 끄는 스위치는 그 하나를 끈다. Form 속성 = 기본, 호출 옵션 = 양방향 재정의, `reset`·마운트 포함 |
| D-6 | 참조 그룹(`virtual`)은 값을 소유하지 않으므로 P2–P4 밖이고 표현 계층의 것이다(P5) |

## 결과

- 잠금용 불린들과 마이크로태스크 flush가 필요 없어지고, 두 단계 하네스는 단일 단계가 된다(T-5, F23).
- "한 번의 쓰기가 두 번 배달된다", "결과가 원인보다 먼저 배달된다"가 구조적으로 사라진다.
- 배열 구조 변경 API(`push`/`remove`/`clear`)가 동기가 된다. 파괴적 변경이다(T-7).
- 라이프사이클을 §1의 표 한 장으로 읽는다(G5). Q3(편집 중 상태와 가드가 보는 값)이 닫혔다.

## 미결

- **배열의 `Merge`가 무엇인가.** 지금은 `Overwrite`와 같다.
- **`setValue(undefined)`의 정의.**
- **`budget-exceeded`에서 제출을 막는가.** 청사진의 정적 검사와 함께 정한다.
- **`push()`로 만든 아이템이 로드인가.** 입력 컴포넌트의 객체 통째 쓰기도 같은 질문이다.
- **억제 옵션의 이름.** 후보는 `reviews/raw-round5-consumer.md`. JSDoc이 "로드"를 정의한다.
- **값이 아닌 입구 (R15).** `setState`(dirty/touched)와 명령 시그널은 쓰기가 아니다.
- **유효 스키마의 변경을 알리는 이벤트가 없다.**
- **검증을 입력 경로에서 떼어 내는 법 (R19).** 커밋 번호 스탬프는 경합만 막는다.
- Q13(`contains`·`prefixItems`), Q14(emit의 키 순서), Q15(직전 `active`를 출발 가설로).
