# getTrackableHandler contract

## Requirements

- 비동기 함수를 감싸 상태(`state`)·구독(`subscribe`)·실행 중 여부(`pending`)를 노출하는 핸들러로 변환한다.
- `preventConcurrent` 기본값 `true`로 동시 호출을 차단하고, `false`면 병렬 실행을 허용한다.
- `afterExecute`는 시작 통지 또는 원본 함수의 성공·실패와 무관하게 실행되며, 호출 종료 시 진행 중 호출 수를 줄입니다.
- 허용된 호출은 성공·원본 함수 실패·after 훅 실패에서 시작·완료 두 번 통지합니다. before 훅 실패는 한 번, 동시 실행 차단으로 거절된 호출은 통지하지 않습니다. 동일 리스너의 중복 구독은 횟수를 늘리지 않습니다.

구독자가 던져도 모든 구독자에게 순서대로 알립니다. 시작 통지의 첫 예외는 핸들러 거부로 전파하고, 추가 시작 오류와 완료 통지 오류는 reportError 또는 별도 throw 태스크로 호스트에 보고합니다. 완료 구독자 오류는 원본의 성공·실패 결과를 바꾸지 않습니다.

훅이 Promise 또는 thenable을 반환하면 그 정착을 기다리고 동기 반환은 같은 tick에서 진행합니다. before 훅의 거부는 원본 실행을 막고, after 훅의 거부는 pending 정리 후 전파합니다. 정착하지 않는 훅을 기다리는 동안에도 pending과 동시·재진입 차단은 유지됩니다. 훅이 있는지 생성 시 한 번 선택하여 훅이 없는 호출 경로에는 훅 반환값 검사를 넣지 않습니다.

두 `preventConcurrent` 값은 같은 실행·갱신·통지 모델을 사용합니다. 이 옵션은 진행 중 호출이 있을 때 새 호출을 허용하는지만 정합니다. 호출별 훅 진행 상태를 다른 호출의 갱신 통지 판단에 사용하지 않습니다. 상태 객체는 공유되며 갱신은 즉시 반영되므로 다른 호출의 알림에서도 그 값을 관찰할 수 있습니다. 훅별 상태 트랜잭션은 제공하지 않습니다.

### 실행 모델

핸들러는 현재 상태 `S`, 끝나지 않은 허용 호출의 집합 `A`, 삽입 순서의 중복 없는 구독자 집합 `L`을 소유합니다. 각 허용 호출 `c`는 자기 인자, 결과 또는 실패, 상태 관리자 `M(c)`, 단계 `before | origin | after | finished`를 소유합니다. `pending`은 `A`가 비어 있지 않다는 뜻입니다. 훅이 없는 단계는 즉시 다음 단계로 넘어가며 동기 훅은 같은 tick에서, thenable 훅은 정착 뒤에 넘어갑니다.

| 이벤트 | 상태 전이와 통지 |
|---|---|
| 호출합니다. | 차단 옵션이 켜져 있고 `A`가 비어 있지 않으면 `undefined`로 끝나며 훅·원본·통지를 실행하지 않습니다. 그 외에는 새 `c`를 `A`에 넣고 before 단계에 진입합니다. |
| before 훅이 성공합니다. | `c`를 origin 단계로 옮기고 시작 통지를 한 번 보낸 뒤 원본을 한 번 호출합니다. 시작 구독자가 던지면 원본을 부르지 않고 그 실패로 after 단계에 진입합니다. |
| before 훅이 던지거나 거부됩니다. | after와 원본을 부르지 않습니다. `c`를 finished로 옮기고 `A`에서 제거한 뒤 완료 통지를 한 번 보내고 같은 오류로 거부합니다. |
| 원본이 성공하거나 실패합니다. | 해당 결과를 `c`에 저장하고 after 단계에 진입합니다. 원본 실패도 after를 생략하지 않습니다. |
| after 훅이 성공하거나 실패합니다. | 실패하면 원본 결과 대신 after 오류를 채택합니다. `c`를 finished로 옮기고 `A`에서 제거한 뒤 완료 통지를 한 번 보내고 저장한 결과로 정착합니다. |
| `M(c).update(u)`를 호출합니다. | `S`를 현재 `S`와 `u`의 부분 갱신을 병합한 새 객체로 즉시 교체합니다. 오직 `c` 자신의 훅이 실행 중인 before 또는 after 단계일 때만 개별 통지를 접습니다. origin 또는 finished 단계이면 즉시 통지합니다. |
| 이전 호출에서 저장한 관리자로 갱신합니다. | 그 관리자의 소유 호출 단계로만 판단합니다. 소유 호출이 끝났으면 다른 호출의 훅이 기다리는 중이어도 즉시 통지합니다. |
| 구독하거나 해제합니다. | 구독은 `L`에 추가하고 통지하지 않습니다. 반환된 해제 함수는 그 구독자를 제거하며 반복 해제도 통지하지 않습니다. 같은 함수를 중복 구독해도 한 번만 알립니다. |

통지는 그 순간의 `S`와 `pending`을 구독자가 읽게 합니다. 자기 훅의 갱신을 접는 것은 개별 통지만 생략하며 다른 호출이 보내는 통지까지 막지 않습니다. 완료 통지는 호출의 진행 상태를 정리한 뒤 보내므로 그 구독자가 새 호출을 시작할 수 있습니다. 어떤 허용 호출도 다른 호출의 단계나 결과를 덮어쓰지 않습니다. 겹치지 않는 같은 호출·갱신·구독 이벤트 열은 두 옵션 값에서 같은 상태 통지 열과 훅·원본 호출 수를 만듭니다.

## API Contracts

- `getTrackableHandler(origin, options?)` → 상태·구독·`pending`이 결합된 핸들러. `options`: `preventConcurrent`(기본 `true`), `initialState`, `beforeExecute`, `afterExecute`.
- 반환된 핸들러: 호출 가능(`Promise<Result | undefined>`), `subscribe(listener)`(구독 해제 함수 반환), `pending`(읽기 전용), `state`(읽기 전용) — 세 속성 모두 non-enumerable이다.
- `StateManager<State>`: `{ state, update(updater) }` 형태로 두 훅 콜백에 전달된다. `updater`는 부분 객체이거나 이전 state를 받는 함수다.

## Acceptance Criteria

### lifecycle-publish — 실행 라이프사이클과 구독 통지

- `pending=true`로 호출을 예약 → `beforeExecute` 정착 → 시작 통지 → 원본 함수 실행 → `afterExecute`(항상) → `pending` 갱신 통지 순서로 진행되며, before 훅이 실패하지 않은 허용된 호출은 정확히 두 번 통지합니다. before 훅 실패는 완료 통지만 한 번 발생하고, 차단된 호출은 통지하지 않습니다.
- 동일 리스너를 두 번 구독해도 한 번만 등록되어 통지 횟수가 늘지 않는다.
- 자기 호출의 훅 실행 중 이뤄진 state 갱신만 훅 종료 통지로 접히며, 다른 호출의 훅 진행은 갱신 통지를 지연하지 않습니다.

### call-owned-hook-model — 호출별 상태 관리자 귀속

- 훅 없음·동기 훅·비동기 훅과 두 동시 실행 옵션에서 모델의 상태 통지 열 및 before·after·원본 호출 수가 일치합니다.
- before 정착 전, 원본 성공·실패, after 정착 전후에 자기 관리자와 이전 호출의 저장된 관리자를 교차 사용해도 통지 소유권은 관리자의 호출만 따릅니다.
- 겹치지 않는 호출 열은 두 옵션에서 같은 결과를 만들고, 겹치는 호출의 차이는 차단된 호출의 유무뿐입니다.

### concurrent-guard — 동시 실행 제어

- `preventConcurrent`가 `true`(기본값)면 첫 호출이 진행 중일 때 추가 호출은 원본 함수를 실행하지 않고 `undefined`를 반환한다.
- `preventConcurrent`가 `false`면 동시에 호출된 만큼 원본 함수가 모두 실행되고 마지막 호출이 종료될 때까지 `pending`이 true입니다.

### hook-error-recovery — 훅 에러 시 정리 보장

- `beforeExecute`가 던지면 원본 함수는 호출되지 않고 에러가 전파되며, 그 이전에 이뤄진 state 갱신은 통지된다.
- `afterExecute`가 던지면 에러가 전파되지만 `pending`은 남은 호출 수에 맞게 정리되고 완료 통지도 수행됩니다. 시작 통지에서 구독자가 던져도 같은 정리를 수행합니다.
