# Merge contract

## Requirements

- 객체 병합은 독립 계약이며 부모는 재수출만 맡습니다. 기본 재귀와 옵션 재귀를 분리하여 옵션이 없는 호출에 정책 검사 비용이 재귀 깊이만큼 붙지 않게 합니다.
- 배열 전략은 공개 래퍼에서 한 번 정하고 재귀에 전달합니다. 옵션의 접근자가 재귀마다 호출되어 정책과 비용이 달라지는 일을 막습니다.
- 형제 filter 진입점으로 판별 함수를 가져오며, 두 재귀 함수는 자기 로컬 함수 이름으로 재진입합니다. 성능 판단은 동일 도구로 만든 실제 배포 ESM·CJS 산출물을 기준으로 합니다. 벤치 전용 변환에서만 발생하는 재수출 getter를 피하려고 소스에 로컬 별칭을 추가하지 않습니다.
- 두 인자 호출의 기존 의미는 유지합니다. 원본 source는 바꾸지 않으며, 기본 모드는 target을 변이하고 배열을 인덱스별로 병합합니다.
- 선택 정책은 스키마에 한정되지 않는 병합 계약입니다. 스키마 그룹의 적용 순서·터미널 전략은 호출자가 소유하며, React 요소·ref의 표식도 이 모듈이 해석하지 않습니다.

## API Contracts

- `merge(target, source, options?)`는 병합 결과를 반환합니다. options가 없으면 기존 mutable 재귀, 객체가 제공되면 옵션 재귀로 분기합니다. 공개 이름과 패키지 import 경로는 유지합니다.
- `MergeOptions.arrayStrategy`의 기본값은 인덱스별 병합이며 replace는 뒤 배열 전체를 사용합니다.
- `MergeOptions.isAtomic`에 해당하는 값은 내부를 읽지 않고 뒤 값으로 대체합니다. 원자 여부는 호출자가 정의합니다.
- `MergeOptions.preserveReferences`가 참이면 한쪽에만 있는 컨테이너 참조를 유지합니다.
- `MergeOptions.immutable`이 참이면 겹치는 컨테이너를 새로 만들고 입력 객체를 변이하지 않습니다. preserveReferences도 참이면 한쪽에만 있는 객체를 복사하지 않고, 객체 병합의 재귀는 양쪽 plain object가 겹칠 때만 수행합니다. 배열은 별도의 arrayStrategy를 따르므로 기본 인덱스별 병합에서는 재귀합니다.
- 뒤의 undefined는 정의된 앞 값을 지우지 않습니다. 기본 모드는 기존 __proto__ 제외를 유지하고, 옵션 모드는 부모의 안전한 own 데이터 속성 프리미티브로 예약 키를 처리합니다.
- 비용은 방문한 키, 각 호출의 키 배열, 재귀 스택과 생성한 컨테이너에 따릅니다. immutable은 겹치는 컨테이너 복사 비용을 더하고 preserveReferences는 한쪽 컨테이너의 복사를 줄입니다. 어느 모드도 순환 입력에 대한 새 지원을 추가하지 않습니다.

## Acceptance Criteria

### default-compatibility — 기존 두 인자 의미

- 대상 동일성·source 불변·배열 인덱스 병합·undefined·예약 키 처리 의미를 유지합니다.
- 옵션 추가 전 베이스와 같은 빌드 도구로 만든 실제 배포 산출물에서 기본 경로 성능을 비교합니다. 측정 순서와 반복을 분리하고, 성능 저하를 단순한 허용 오차로 간주하지 않습니다. 소스 CJS 변환을 통한 진단은 배포 성능 게이트와 구분합니다.

### explicit-policies — 선택한 병합 정책

- 원자 값 내부를 읽지 않고, immutable 입력을 변이하지 않으며, 한쪽 값과 교체 배열의 참조를 보존합니다.
- 정책 조합은 동결한 양쪽 입력으로도 확인하여 하나의 옵션만 통과하고 조합에서 입력이 바뀌는 회귀를 막습니다.

### SCHEMA-039 — 원자와 공유 참조의 경계

- 원자 판정은 호출자가 제공합니다. 범용 유틸리티에 React 표식을 넣으면 비렌더 호스트에도 React의 객체 지식을 강제하므로 기본 원자 규칙을 두지 않습니다.
- 양쪽 중 하나가 원자이면 그 내부로 재귀하지 않습니다. 렌더 요소·ref 같은 불투명 객체의 내부 상태를 설정으로 취급하거나 접근자를 읽는 실패를 막습니다.
- 쓰기 시 복사·배열 교체·한쪽 참조 이동은 함께 선택할 수 있는 별도 정책입니다. immutable만 켜고 참조 이동과 교체까지 보장된다고 해석하지 않습니다.
- immutable과 preserveReferences를 함께 쓰면 겹친 plain object는 새 그릇으로 병합하고 한쪽에만 있는 값은 공유합니다. 공유한 값의 후속 변경까지 격리하는 deep clone 계약은 아닙니다.
- 배열 교체는 뒤 배열의 참조를 사용합니다. 교체 배열이나 원자 내부를 복사·재귀하지 않아 참조 정체성이 필요한 소비자를 보존합니다.
- 정의된 앞 값을 뒤의 undefined가 지우지 않는 규칙은 원자 내부의 병합 요청과 구별합니다. 원자 취급은 지우기 동작을 추가하는 장치가 아닙니다.

### module-boundary — 단일 분기와 재귀 소유

- 공개 래퍼는 두 구현의 선택, 배열 전략의 일회 판정과 호출만 합니다. 기본 재귀와 옵션 재귀는 wrapper를 가져오거나 호출하지 않습니다.
- 형제 fractal은 해당 진입점으로 가져오고, 부모의 안전한 속성 프리미티브는 부모 내부 파일을 직접 참조하여 재수출 순환을 피합니다.
