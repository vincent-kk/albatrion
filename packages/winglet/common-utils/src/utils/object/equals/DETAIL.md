# equals contract

## Requirements

두 비교 정책은 값을 재귀적으로 비교하되 속도와 관찰 범위가 다르다. 일반 비교는 순환 추적 없이 열거 가능한 문자열 키와 배열 값을 빠르게 순회하고, 안정 비교는 순환 쌍·희소 배열·심볼 키·내장 이진 값을 다룬다. 비교 키 생성이나 그래프 저장·복원은 이 계약에 속하지 않는다.

두 정책은 내장 객체의 실제 상태를 공통 규칙으로 비교한다. 키가 비어 있다는 이유만으로 서로 다른 내장 객체를 같다고 판단하지 않는다.

`equals`와 `stableEquals`는 다른 패키지에서도 가져다 쓰는 공개 비교 계약이다.

## API Contracts

`equals(left, right, omit?)`는 동일 참조와 양쪽 NaN을 같게 본다. 배열 길이와 인덱스 값을 비교하므로 hole과 명시적 undefined는 구분하지 않는다. 일반 객체는 own enumerable 문자열 키를 재귀 비교하고, 선택적 제외 키는 배열 또는 Set으로 받는다. 순환 입력은 지원하지 않는다.

`stableEquals(left, right, omit?)`는 방문한 객체 쌍을 기록해 순환을 종료한다. 배열에서는 각 인덱스의 존재 여부도 비교하고, 객체에서는 `Reflect.ownKeys`로 얻는 문자열·심볼 키를 검사한다. 선택적 제외 키는 읽기 전용 배열로 받는다. 매우 깊은 비순환 입력은 여전히 재귀 호출 스택의 한도를 따른다.

두 비교 정책은 Date의 시각, RegExp의 패턴과 플래그, Set의 구성원, Map의 키와 값을 각각 검사한다. Set 구성원과 Map 키는 SameValueZero 기준으로 찾으므로 객체 키·구성원은 참조 동일성이 필요하고, Map 값은 선택한 정책으로 재귀 비교한다. 안정 비교는 ArrayBuffer와 view의 바이트도 비교한다.

제외 키가 있으면 두 객체 모두 제외 후 남은 키의 수를 비교한다. 내장 객체 상태 비교에는 선택한 재귀 비교 함수를 전달하여 두 정책이 같은 상태 규칙을 공유하면서 각자의 순환·키 관찰 정책을 유지한다.

## Acceptance Criteria

### equals-fast — 일반 재귀 비교

- 동일 참조, 양쪽 NaN, 배열 길이와 인덱스 값을 비교한다.
- 일반 객체는 own enumerable 문자열 키를 비교하고 순환 추적을 추가하지 않는다.
- 배열의 hole과 명시적 undefined는 같은 인덱스 값으로 취급한다.

### equals-stable — 순환과 확장 키 관찰

- 방문 쌍을 사용해 순환 입력에서 종료한다.
- 희소 배열의 hole과 명시적 undefined를 구분한다.
- 문자열 키와 심볼 키를 포함한 own 키를 관찰하고 ArrayBuffer·view의 바이트를 비교한다.

### equals-builtins — 내장 상태 비교

- Date와 RegExp는 내부 값을, Set은 구성원을, Map은 키와 재귀 비교한 값을 사용한다.
- Set의 객체 구성원과 Map의 객체 키는 참조 동일성이 있어야 일치한다.

### equals-omit — 제외 키 정책

- 제외된 키는 두 피연산자 모두에서 비교와 남은 키 수 계산에서 빠진다.
- 일반 비교는 배열 또는 Set, 안정 비교는 읽기 전용 배열을 제외 키 입력으로 받는다.
