# withErrorBoundary — 오류 경계 HOC

## Purpose

하위 컴포넌트 트리의 렌더링 오류를 격리하는 HOC와 직접 합성하는 `ErrorBoundary`의 공개 계약을 소유합니다. 기본 fallback의 구현은 내부에 둡니다.

직접 합성은 HOC의 추가 감싸기 없이 경계를 배치하려는 소비자를 위한 표면입니다.
보고기의 문맥 읽기는 렌더에서 수행하여 HOC를 다시 만들지 않아도 현재 인스턴스를 사용합니다.

## Conventions

- 공개 클래스와 HOC는 같은 fallback·보고 계약을 공유합니다. 컴포넌트가 내부 디렉터리에 있다는 이유로 공개 클래스를 사설로 취급하지 않습니다.
- fallback 계약: `undefined`일 때만 기본 메시지로 대체한다 — `null`은 "아무것도 렌더하지 않음"으로 존중한다. 두 HOC의 fallback 의미론은 동일하다.

## Boundaries

### Always do

- 포착한 오류는 `console.error`로 로깅한다 — 로깅 옵션을 추가하더라도 기본 로깅은 유지
- fallback 의미론 변경은 DETAIL.md를 먼저 갱신
- 선택 보고기는 격리의 관찰자이며 기본 console 로깅을 대신하지 않습니다. 보고기의 유무에 따라 기본 진단이 사라지지 않게 합니다.
- 훅은 렌더마다 조건 없이 읽고, 보고기 생략 시에도 기본 훅을 호출하여 훅 순서를 보존합니다.
- 공개 클래스를 직접 합성할 때도 같은 보고·fallback 계약을 지켜 HOC와 다른 오류 정책을 만들지 않습니다.

### Ask first

- HOC 시그니처 확장(fallback 이외의 옵션 추가)
- 공개 경계·보고기 정보의 확대나 fallback의 복구 정책 변경

### Never do

- 원본 컴포넌트의 props/ref 전달을 변형하는 로직 추가
- 오류를 삼키고 fallback 없이 렌더를 계속하는 경로 추가
- 보고기 중복 억제·전달 중 표지 같은 호스트별 정책을 범용 경계에 결합
