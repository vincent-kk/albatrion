# json-schema — 스키마 순회와 변환의 공통 계약

## Purpose

스키마·값 타입과 순회·출력의 공통 규칙을 소유하고, 하위 모듈의 공개 계약을 연결합니다. 스키마 선언은 스캐너에 의존하지 않는 keyword 모듈이, 순회 엔진·방언 판별·어휘 컴파일·복제와 해소기는 스캐너 모듈이 소유합니다. 그래야 선언만 쓰는 소비자가 스캐너를 불러오지 않고, 동기·비동기 실행과 참조 사본이 한 구현을 공유합니다.

## Conventions

- 하위 모듈의 공개 이름을 그대로 노출하며 구현 책임과 공개 import 주소를 구분합니다.
- 데이터 인스턴스 검증은 외부 검증기의 책임으로 둡니다. 타입 판별자는 스키마의 타입 정보만 해석합니다.

## Boundaries

### Always do

- 입력과 해소기 대상의 소유권을 유지합니다. 출력 변환이 호출자의 객체를 바꾸지 않게 합니다.
- 방문 순서·자식 확정 시점·보존 이유를 공통 엔진에서 관리해 두 드라이버의 결과가 갈라지지 않게 합니다.
- 여러 하위 모듈이 쓰는 구현은 공통 소유자 아래에 두고, 공개 하위 경로에는 소비자가 필요한 계약만 노출합니다.

### Ask first

- 공개 심볼·타입을 제거하거나 반환값의 범위를 바꾸는 변경
- 지원 방언·이동 안전 조건 또는 출력의 객체 공유 정책을 바꾸는 변경

### Never do

- 하위 모듈의 주소 해석·대기 정책을 루트 진입점에서 재구현
- 참조를 모두 제거하기 위해 동적 범위나 기존 주소를 훼손하는 변환
