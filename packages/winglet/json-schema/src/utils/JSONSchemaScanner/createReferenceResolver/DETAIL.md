# createReferenceResolver contract

## Requirements

참조는 정규 위치의 유일한 대상으로 해석하거나 명시적인 이유를 남깁니다. 주소를 찾았다는 사실과 그 대상을 현재 호스트에 옮길 수 있다는 판단을 구분해 잘못된 인라인을 막습니다. 삭제·재배치가 기존의 유효한 참조 주소를 바꿀 수 있고 안전을 증명하지 못하면 원래 참조를 보존합니다.

## API Contracts

스캐너의 순회는 동기 스캐너 진입점으로, 방언과 기본 어휘 선언은 keyword 모듈 진입점으로 사용합니다. 오류·방언 판별·어휘 구성과 공통 복제는 상위 스캐너 모듈의 organ에서 가져와 내부 헬퍼를 공개 scanner API에 추가하지 않습니다.

문맥은 불투명하게 전달해 색인 구조의 변경이 공개 계약으로 번지지 않게 합니다.

루트 문서는 생성 때 색인하고 등록 문서는 최초 조회 때 색인합니다. 방언의 스키마 위치와 구방언 참조 옆의 정의 주소 컨테이너만 식별자를 등록합니다. 다른 inert 형제의 식별자는 등록하지 않습니다. 방언에서 inert인 위치와 그 후손을 가리키는 참조는 같은 자원의 식별자 없는 사본 최적화보다 먼저 relocation으로 보존합니다. 색인에서 스키마 위치로 확인되지 않은 포인터 대상과 inert 영역은 기준 URI·방언·식별자의 의미를 증명할 수 없으므로 같은 이동 불가 조건으로 다룹니다. 구방언 참조 옆의 식별자 자체는 무시합니다.

포인터 조각은 퍼센트 디코딩을 한 번 한 뒤 빈 값·포인터·앵커로 분류합니다. 포인터 토큰은 기존 JSON Pointer 해제를 재사용하며 상속 속성은 읽지 않습니다. 정규 위치가 같으면 앵커와 포인터 표기는 같은 순환 정체성을 가집니다. 동적 앵커로 향하는 동적 참조는 정적 인라인 대상이 아닙니다. [자원 검증](__tests__/createReferenceResolver.resources.test.ts)이 정적 대상과 동적 대상의 구분을 확인합니다. URI에 노출하는 포인터는 퍼센트와 조각 구분자를 인코딩해 재조회해도 같은 대상을 가리킵니다.

같은 대상과 호스트 쌍의 템플릿을 재사용합니다. 같은 자원의 식별자 없는 대상은 그대로 복제하고, 그 밖에는 방문·필터·깊이와 무관하게 전체 대상을 조사해 식별자를 제거하고 참조 URI를 원래 범위에서 재작성합니다. 방언이 바뀌거나 동적 범위를 지우거나 재작성할 수 없는 위치가 있으면 relocation입니다. [이동 검증](__tests__/createReferenceResolver.relocation.test.ts)과 [미인식 위치 검증](__tests__/createReferenceResolver.positions.test.ts)이 이 보존 경계를 확인합니다. 데이터 키워드의 값은 재작성하지 않습니다.

비동기 해소기는 사용자 load가 있을 때만 읽고 문서의 성공·미발견과 진행 중 요청을 절대 URI별로 공유합니다. 사용자 로드의 예외는 호출자에게 전파합니다. [비동기 공급 검증](__tests__/createReferenceResolver.async.test.ts)이 요청 합치기와 공급 결과를 확인합니다.

## Acceptance Criteria

### addresses — 자원과 조각의 정확한 조회

- 기준 URI·식별자·앵커·내장 자원·빈 포인터·퍼센트 조각을 정확한 위치로 해석합니다.
- 중복 식별자를 거절하고 같은 위치의 별칭을 허용합니다.

### relocation — 위치를 옮겨도 판정을 유지하는 사본

- 미방문 후손을 포함한 이동에서 참조 의미와 데이터 값을 보존합니다.
- 방언·동적 범위·미인식 위치가 안전하지 않으면 원래 참조를 남깁니다.

### async-loading — 명시적인 비동기 문서 공급

- 등록 문서를 먼저 사용하고, 같은 절대 문서 요청은 한 번만 호출합니다.
