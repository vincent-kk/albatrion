# ResolverStore — 두 해소기가 함께 쓰는 색인과 해석

## Purpose

동기 해소기와 비동기 해소기가 같은 결과를 내도록 문서 색인, 참조 해석, 이동 판정을 한곳에서 구현합니다. 저장소는 호출자가 넘긴 문서만 색인하며, 어떤 문서를 언제 읽을지는 생성 함수가 정합니다.

## Conventions

- 지켜야 할 동작과 그 이유는 부모 해소기 `DETAIL.md`가 정합니다. 저장소는 그 계약을 구현할 뿐 같은 규칙을 따로 적지 않습니다.

## Boundaries

### Always do

- 색인, 해석, 이동 판정의 규칙은 저장소 안에만 둡니다. 생성 함수 쪽에 두면 같은 스키마에서 동기와 비동기 해소기의 결과가 갈라집니다.

### Ask first

- 생성 함수가 부르는 공개 메서드를 더하거나 그 의미를 바꾸는 변경. 두 생성 함수를 함께 고쳐야 합니다.

### Never do

- 저장소를 비동기로 만드는 코드(`load` 호출, Promise를 돌려주는 메서드). 동기 해소기가 같은 저장소를 쓰므로 저장소는 동기로 남고, 비동기 읽기는 비동기 생성 함수가 맡습니다.
