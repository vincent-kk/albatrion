# compressCss contract

## Requirements

- `compressCss(css)`는 빈 문자열 입력에 빈 문자열을 반환한다.
- 연속된 공백·탭·개행은 하나의 공백 또는 무공백으로 축약되고, 단일·다중 라인 주석은 제거하되 토큰을 합치는 경계에서는 빈 주석을 유지한다.
- 중복되거나 블록 끝 직전에 오는 세미콜론은 제거된다.
- `@media`, `@keyframes` 등 중첩 규칙은 바깥 블록과 안쪽 블록 모두 압축되어 올바른 중첩 구조를 유지한다.
- 작은따옴표·큰따옴표 문자열은 여는 따옴표부터 닫는 따옴표까지(백슬래시 이스케이프 포함) 바이트 그대로 복사한다. 문자열 안의 `/*`는 주석을 열지 않는다 — 열면 뒤따르는 스타일시트 전체가 조용히 사라진다.
- 따옴표 없는 `url(…)`은 `(`부터 `)`까지(백슬래시 이스케이프 포함) 바이트 그대로 복사한다. `url(http://x.com/a/*b)`의 `/*`도 주석이 아니다. `url` 함수 이름은 단순·16진수 이스케이프 표기도 같은 토큰으로 읽습니다. `url`(대소문자 무관) 바로 앞이 식별자 문자(영문자·숫자·`-`·`_`·백슬래시·비ASCII 바이트)이면 `myurl(` 같은 다른 함수이므로 일반 텍스트로 압축한다 — 그 인자 안의 주석까지 남기면 안 된다.

- 백슬래시는 1~6자리 16진수와 선택적인 CSS 공백 한 개(CRLF는 한 개)를 포함한 전체 이스케이프를 소비합니다. 그 뒤의 실제 공백은 별도로 보존하므로 하위 결합자가 사라지지 않습니다. 문자열 안에서 16진수 종결자로 소비한 개행은 잘못된 문자열의 종료가 아닙니다. 문자열 밖의 단순 백슬래시는 다음 바이트를 소비하므로 이스케이프된 따옴표·구두점·공백은 문자열이나 구조를 시작하지 않는다.

- 문자열 안의 이스케이프되지 않은 LF·CR·FF는 잘못된 문자열을 끝내며 이후 규칙의 압축을 계속한다. 백슬래시 뒤 CRLF는 하나의 줄 연속이다.

문자열·주석·url 토큰·이스케이프·괄호와 대괄호의 경계는 cssTokens가 한 번 결정합니다. 압축은 그 밖의 위치에서만 공백·주석·세미콜론을 제거합니다. 주석 제거가 토큰을 합치거나 나누면 빈 주석을 유지합니다. 이 규칙은 식별자·함수명·숫자·dimension·퍼센트·부호·hash뿐 아니라 comment 시작, CDO/CDC, attribute match 연산자 등의 경계도 포함합니다. EOF의 홀수 개 후행 백슬래시는 CSS Syntax의 EOF escape로 읽으며, 압축 자체가 뒤에 닫는 문자를 붙여 escape의 대상을 바꾸지 않습니다.

## API Contracts

- `compressCss(css: string): string` — 공유 CSS Syntax Level 3 위치 모델로 코드 단위를 순회하며, 빠른 경로에도 같은 의미 보존 조건을 적용합니다. 구두점에 인접한다는 이유만으로 공백을 제거하지 않습니다. 선택자 prelude의 `.a [b]`, `[a] .b`, `:is(.a) .b`는 하위 결합자를 유지합니다. `(` 앞·`)` 뒤·`[` 앞·`]` 뒤의 공백도 문맥상 의미가 같다고 확인할 때만 제거합니다. 콜론 뒤 공백은 선언 구분자일 때만 제거할 수 있으며 `.a: hover`를 `.a:hover`로 고치지 않습니다.
- 플러스(`+`)와 마이너스(`-`) 양옆에 존재하는 공백은 선언 값과 at-rule prelude에서 괄호 안팎 모두 보존합니다. custom property의 값은 나중에 `calc()`로 치환될 수 있으므로 괄호 밖 부호도 토큰 경계를 유지해야 합니다. 선택자의 An+B(`:nth-child(2n + 1)`)도 숫자 토큰 경계를 유지합니다. 선택자 목록 함수인 `:is()`·`:not()` 내부의 결합자 및 `||`는 Selectors의 결합자 문맥에서만 의미가 같은 공백 제거를 허용합니다. 문맥을 확정하지 못하면 공백을 남깁니다.
- 선언 값의 `>`·`~` 등을 선택자 결합자로 취급하지 않습니다. custom property의 내부 토큰과 공백 및 공백만 있는 빈 값(`--x: ;`)은 치환 의미가 유지되어야 합니다. 선언 구분자·끝과 유효한 중복 세미콜론의 압축은 값 자체의 공백을 없애는 허가가 아닙니다.
- 콜론 앞 공백은 선언 이름 상태에서만 생략합니다. 중첩 style rule일 수 있는 프렐류드가 뒤의 블록으로 확정되면 저장한 원문 구간을 복원합니다. `.a :hover`(하위 요소)와 `.a:hover`(자기 자신)는 다른 선택자입니다. `@supports (--x: )`와 `style(--x: )` 같은 선언 쿼리의 공백뿐인 값도 보존합니다.
- 출력 끝의 이스케이프되지 않은 공백은 제거하고 백슬래시가 소비하는 공백은 보존한다.

최상위 CDO/CDC는 CSS Syntax의 stylesheet 규칙으로 읽으며 comment 제거가 이 토큰을 새로 만들거나 식별자로 합치지 않습니다. 문자열·url 내부의 원시 바이트는 그대로 유지합니다. 압축은 잘못된 입력을 유효하게 교정하는 기능이 아니며, 의미 보존과 별개로 불투명 토큰의 경계는 잘못된 입력에서도 다음 토큰에 넘기지 않습니다.

## Acceptance Criteria

### whitespace-comment-normalization — 공백·주석 정규화

- 빈 문자열은 빈 문자열로 압축된다.
- 규칙 안팎의 여러 공백·개행이 축약되어 최소 형태(`.class{color:red;background:blue}`)로 압축된다.
- 주석 내용은 제거하되 인접 토큰이 합쳐지는 경계에서는 빈 주석을 보존한다.
- 따옴표 문자열과 따옴표 없는 `url(…)` 안의 주석 표식과 공백은 그대로 남는다.

### syntax-punctuation-rules — 세미콜론·결합자·중첩 규칙 압축

- 중복 세미콜론과 블록 종료 직전의 세미콜론은 제거된다.
- 하위 결합자(공백)의 공백은 보존되고, 자식·인접 형제 결합자 주변 공백은 제거된다.
- 가상 클래스·가상 요소 앞의 하위 결합자 공백은 보존되고, 선언의 콜론 앞 공백은 제거된다.
- 선언 값의 `+`·`-` 주변 공백은 괄호 안팎에서 보존되며 `:nth-child(2n + 1)` 같은 함수형 선택자의 필요한 토큰 경계도 유지합니다.

### syntax-reader-equivalence — 유효 시트 의미 보존

- CSS Syntax Level 3 판독기로 읽은 유효 입력과 압축 출력의 규칙·선택자·선언 값 의미가 같습니다. 문자열·url 및 이스케이프 내부는 그대로이며, 공백 제거가 식별자·숫자·dimension·부호 토큰을 합치지 않습니다.
- 같은 생성 입력을 빠른 경로와 일반 경로에 적용해도 같은 의미를 보존합니다. nested·statement at-rule과 선택자·선언 값의 문맥을 섞어 검증합니다.
- `@media`, `@keyframes` 중첩 규칙이 중첩 구조를 유지한 채 압축되며, 조건식 앞에 필요한 공백은 보존된다.
