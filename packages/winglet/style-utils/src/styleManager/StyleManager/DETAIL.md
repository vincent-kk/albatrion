# StyleManager contract

## Requirements

- `StyleManager.get(scopeId, config?)`는 scopeId(및 Shadow DOM인 경우 `shadowRoot` 인스턴스)별로 유일한 인스턴스를 반환하는 정적 싱글톤 팩토리다.
- `add(id, css, compressed?)`는 빈 입력과 공백만 있는 입력을 무시하고 기존 식별자 값을 유지합니다. 그 외에는 `compressed`가 아니면 압축하고 문서 모드에서 스코핑한 뒤, 이전에 저장된 동일 id의 처리 결과와 다를 때만 DOM 갱신을 예약합니다. Shadow DOM은 스코핑을 생략합니다.
- `remove(id)`는 저장된 스타일을 제거하고, 실제로 제거되었을 때만 DOM 갱신을 예약한다.
- DOM 갱신은 `requestAnimationFrame` 콜백 하나로 배치된다 — 같은 프레임 안의 여러 `add`/`remove` 호출은 DOM에 한 번만 반영된다.
- `destroy()`는 예약된 애니메이션 프레임을 취소하고, 적용된 시트 또는 엘리먼트를 제거하고, 내부 캐시를 비우고, 인스턴스를 레지스트리에서 제거한다.

식별자는 서로 독립된 스타일시트 구문 입력입니다. 식별자 하나의 유효·미완성·잘못된 CSS가 다른 식별자의 규칙 해석을 바꾸지 않습니다. `C(f)`를 선택적인 압축과 식별자 시작의 U+FEFF 하나 제거를 거친 조각으로 정의합니다. ShadowRoot의 oracle 입력은 `C(f)`이고 문서 모드의 oracle 입력은 `scope(C(f))`입니다. 이 입력을 CSS Syntax Level 3 판독기에 단독으로 넘긴 규칙 열을 식별자 삽입 순서로 이어 붙인 결과가, 주입한 전체 텍스트의 규칙 열과 AST 구조까지 같습니다. CSSOM의 적용 순서는 아래 입력 한계와 구별합니다.

같은 식별자의 교체는 기존 위치를 유지합니다. 제거 후 다시 추가하면 마지막으로 이동합니다. 빈 입력은 제거가 아니며 기존 위치와 규칙을 유지합니다.

### 식별자 경계 모델

각 식별자의 판독 상태는 어휘 위치, 열린 component 블록의 스택, 각 규칙의 종류와 시작 위치입니다. 규칙 단계는 규칙 사이, qualified-rule prelude, at-rule prelude, block 중 하나입니다. 문자열·주석·url·이스케이프가 소비한 구두점은 구조 이벤트가 아닙니다. 토큰의 끝 위치는 공통 `cssTokens` 모델이 한 번 결정하며, 별도 문자 판독기로 같은 입력을 다시 분류하지 않습니다.

| 이벤트 | 판독 상태와 경계 처리 |
|---|---|
| 식별자를 추가하거나 교체합니다. | 그 식별자의 입력만 압축·스코핑하고 저장합니다. 동일 처리 결과이면 DOM 쓰기를 예약하지 않습니다. |
| 구조 밖 at-keyword를 만납니다. | 그 깊이의 at-rule prelude를 시작합니다. 구조 세미콜론은 해당 prelude를 끝내며 중괄호는 block으로 옮깁니다. |
| 중첩 statement at-rule 뒤에서 블록이 끝납니다. | 그 블록 안에서 EOF처럼 끝나는 statement도 함께 끝납니다. 이미 끝난 안쪽 prelude가 바깥 규칙이나 다음 식별자의 세미콜론을 만들지 않습니다. |
| 식별자 EOF에 도달합니다. | CSS Syntax EOF와 같은 규칙 열을 확정합니다. 주석·문자열·url 및 열린 component는 그 토큰의 EOF 의미로 끝나고, 끝나지 않은 at-rule은 해당 깊이에서 끝납니다. 블록 없는 qualified-rule prelude는 버리며 다음 식별자의 첫 규칙으로 완성하지 않습니다. |
| stray `}` 또는 `;`가 남습니다. | 같은 식별자 내부의 복구는 단독 판독과 같습니다. 끝에 남은 복구용 토큰이 다음 식별자의 선택자 앞에 붙지 않습니다. |
| 다음 식별자를 반영합니다. | 빈 판독 상태에서 시작합니다. 이전 식별자의 블록·문자열·프렐류드 상태를 물려받지 않습니다. |
| 식별자를 제거하거나 scope를 정리합니다. | 해당 저장값을 지우며, 다른 식별자의 처리 결과를 바꾸지 않습니다. |

경계 처리는 oracle 입력에서 새로운 유효 qualified rule을 만들거나 유효 규칙을 버리지 않습니다. 문자열 끝의 홀수 개 연속 백슬래시는 줄 연속으로 끝내고, url·이름 토큰 끝의 홀수 개 백슬래시는 replacement 문자로 EOF escape 의미를 유지합니다. 짝수 개 백슬래시에는 이 보충을 하지 않습니다. 뒤에 추가한 닫는 구두점이 escape에 먹혀 다음 식별자를 삼키지 않습니다. 토큰 안의 마지막 중괄호를 구조적 종료로 판단하지 않습니다.

최상위 CDO(`<!--`)·CDC(`-->`)는 독립 시트와 같은 stylesheet 구문으로 처리합니다. 뒤에 남은 qualified-rule prelude의 CDO/CDC는 다른 조각의 규칙을 완성하지 않습니다. 식별자 시작 U+FEFF는 BOM으로 정규화하며 내부 U+FEFF를 지우지 않습니다. 문서의 scoper는 끝나지 않은 마지막 블록 규칙을 버리고, ShadowRoot의 oracle은 CSS Syntax EOF가 닫는 규칙을 유지합니다. 모드마다 서로 다른 oracle 입력을 쓰므로 이 차이를 경계 처리가 뒤집지 않습니다.

식별자당 별도 시트는 채택하지 않습니다. 스코프당 한 시트·한 style 요소와 한 번의 배치 쓰기라는 문서화된 DOM 형상을 유지하기 위해서입니다. 정상 CSS 두 조각의 jsdom fallback 쓰기 사전 비교에서 단일 요소는 5,121 ns/flush, 두 요소는 7,399.5 ns/flush이며 비율은 1.445, 같은 빌드 대조는 1.002입니다. 이는 12회 교대 별도 프로세스의 CPU 중앙값이며 실제 브라우저나 전체 속도 관문을 대신하지 않습니다. 새 @media/@layer 그룹도 @import/@namespace의 최상위 의미를 보존하지 못하므로 사용하지 않습니다.

선언 목록으로 확정된 위치의 완전한 단순 선언은 한 위치로 묶을 수 있습니다. 불투명 토큰·이스케이프·중첩 component가 없고 공백이 이미 정규 형태일 때만 적용합니다. 같은 조건의 완전한 단순 선택자 규칙도 규칙 목록 위치 하나로 묶을 수 있으며, 그 내부가 닫힌 것이 확정된 경우에만 스택을 그대로 유지합니다. 끝 세미콜론과 닫는 중괄호는 일반 위치와 같은 상태 전이를 사용하며 EOF 정보도 같은 스택에서 도출합니다.

식별자에 저장한 처리 결과는 EOF 경계까지 완성한 텍스트입니다. 배치 반영은 저장값을 이어 한 번 쓰며 변경하지 않은 식별자를 다시 읽지 않습니다.

## API Contracts

- `StyleManager.get(scopeId: string, config?: StyleManagerConfig): StyleManager` — 문서는 scopeId별 Map을 사용하고, Shadow DOM은 ShadowRoot를 키로 하는 WeakMap 안의 scopeId별 Map을 사용한다. 레지스트리는 분리된 ShadowRoot와 호스트의 수거를 막지 않는다.
- DOM 반영은 `CSSStyleSheet.prototype.replaceSync`와 `adoptedStyleSheets`를 모두 지원하는 환경에서는 그 경로를 쓰고, 아니면 scope 클래스가 붙은 `<style>` 엘리먼트에 `textContent`를 대입하는 방식으로 폴백한다. `replaceSync` 호출이 실패하면 예외를 던지지 않고 `console.warn`으로 기록한다.
- CSS 스코핑은 텍스트를 앞에서부터 한 번 훑으며 규칙마다 프렐류드(선택자 또는 at-rule 조건)와 블록을 찾는다.
  - 중괄호·세미콜론·쉼표는 문자열(`"…"`, `'…'`), 주석(`/* … */`), 백슬래시 이스케이프 밖에 있을 때만 구조로 센다 — 안쪽 문자를 세면 `content: "{"` 하나가 시트의 나머지를 지우거나 다음 규칙을 블록 안으로 끌어들인다. 따옴표 없는 `url(…)`(대소문자 무관) 안의 `/*`는 주석을 열지 않고, 그 안의 `;`는 문장형 at-rule을 끝내지 않는다 — `url(http://x.com/a/*b)`가 주석으로 읽히면 뒤따르는 규칙이 사라지고, `@import url(http://x.com/a;b.css);`가 URL 안에서 끊기면 스코프가 URL에 들어가고 다음 규칙이 스코프를 잃는다. `url(`은 바로 앞이 식별자 문자(영문자·숫자·`-`·`_`·백슬래시·비ASCII)가 아닐 때만 URL로 본다 — `myurl(` 같은 다른 함수의 인자를 불투명하게 다루면 그 안의 주석과 괄호를 잘못 읽는다.
  - 블록 끝은 중괄호 깊이로 찾는다 — 첫 `}`에서 끊으면 `@media` 같은 중첩 블록의 닫는 중괄호가 사라진다.
  - 일반 규칙은 선택자 목록의 최상위 쉼표(괄호·문자열·주석·이스케이프 밖)마다 나눈 각 선택자에 `.<scopeId> ` 접두사를 붙인다. 식별자 이스케이프를 해석한 선택자가 ASCII 대소문자 구분 없이 `:root` 또는 `:host`이면 그대로 둔다. `:root` 뒤의 주석과 `:/*c*/root`처럼 콜론과 이름 사이에 끼운 주석을 같은 선택자로 고치지 않습니다. 식별자 중간의 주석은 서로 다른 토큰을 합치지 않는다. 빈 목록 항목은 빈 항목으로 남겨 무효 목록을 범위 컨테이너 규칙으로 바꾸지 않는다. 이스케이프된 후행 공백은 선택자 토큰에 속하므로 보존한다. 첫 선택자에만 붙이면 나머지 선택자가 문서 전체로 샌다.
  - 평평한 스타일 규칙(프렐류드의 `{`가 다음 `}`와 다음 불투명 토큰보다 앞서고, 블록의 `}`가 다음 `{`와 다음 불투명 토큰보다 앞서는 규칙)은 구조 탐색 없이 처리하고, 그중 선택자가 하나이며 비어 있지 않고 ASCII 비공백 문자로 시작하고 끝나며 `:`로 시작하지 않는 규칙은 접두사 뒤에 선택자부터 `}`까지의 원문 한 조각을 붙인다. 출력은 일반 경로와 바이트 단위로 같아야 한다 — 동등성 테스트가 고정된 기준 스코퍼와 비교해 이를 지킨다.
  - 규칙을 담는 그룹 at-rule(`@media`, `@supports`, `@container`, `@layer`, `@scope`, `@document`, `@starting-style`, 벤더 접두사 포함)은 조건부를 그대로 두고 블록 안 규칙을 같은 방식으로 재귀 스코핑한다. 안쪽 규칙이 스코프 밖으로 새지 않게 하기 위해서다.
  - 그 밖의 블록 at-rule(`@keyframes`, `@font-face`, `@page` 등)은 블록 전체를 그대로 복사한다 — `from`/`to` 같은 키프레임 선택자에 접두사가 붙으면 규칙이 무효가 된다.
  - 문장형 at-rule(`@import`, `@charset`, `@layer a, b;` 등)은 구조로 센 `;`까지, 여러 스타일 식별자를 DOM에 합칠 때 누락된 세미콜론을 보충해 다음 식별자와의 경계를 유지한다. 경계는 공유 위치 순회에서 확정하여 배치 반영 때 다시 읽지 않습니다. Shadow DOM에서도 같은 경계를 보충한다. 뒤에 스타일 규칙이 없어도 복사한다.
  - 규칙 사이의 주석은 버린다. 주석 뒤의 at-rule도 at-rule로 인식한다.
  - 블록 없이 `}`를 만난 프렐류드와 짝 없는 `}`는 버리고, 다음 프렐류드는 그 `}` 뒤에서 시작한다 — 남은 `}`가 다음 선택자 앞에 붙으면 그 규칙의 스코프가 깨진다.
  - 짝이 맞는 `}`가 없는 마지막 규칙은 버린다. 그 규칙이 그룹 at-rule이면 이미 만든 안쪽 결과도 함께 버린다.
- 이스케이프되지 않은 LF·CR·FF는 닫히지 않은 문자열을 끝내므로 다음 규칙 탐색이 계속된다. 백슬래시 뒤 CRLF는 하나의 줄 연속으로 처리한다. 16진수 이스케이프는 최대 여섯 자리와 선택적인 공백 종결자를 함께 소비하므로 그 안의 개행·구두점은 구조가 아니다. 이스케이프된 url 함수 이름도 같은 불투명 토큰으로 읽는다. 빠른 이스케이프 후보 분류는 보수적이며 후보에 포함된 단순 이스케이프도 전체 토큰 판독기와 같은 끝 위치를 반환한다.
- Shadow DOM 대상에는 스코핑을 적용하지 않는다.

압축의 의미 보존은 compressCss 계약이 소유합니다. 식별자 독립성은 입력이 잘못되었을 때도 적용하지만, 잘못된 입력을 유효한 스타일로 고쳐 주겠다는 보장은 아닙니다. scoper의 별도 입력 제한은 그대로 적용합니다.

### 입력과 CSSOM의 한계

- 식별자 독립성은 CSS Syntax 규칙 열의 보장입니다. 하나의 시트를 사용하는 CSSOM에서 `@charset`·`@import`·`@namespace`는 전역 위치 제약을 따릅니다. 앞 식별자의 style rule 뒤에 오는 import/namespace를 독립 시트처럼 적용한다고 보장하지 않으며, `replaceSync`의 import 제한도 유지합니다. `@layer`의 명명·순서 선언, keyframes와 font-face 이름은 스코프별로 격리하지 않고 시트·문서의 cascade 규칙을 따릅니다.
- 문서 모드의 scoper는 따옴표 없는 `url(a{b)`의 중괄호를 안전하게 처리하지 못합니다. 해당 입력은 URL을 따옴표로 감싸야 하며, ShadowRoot의 독립 구문 경계 보장과 혼동하지 않습니다.
- 256단계를 넘는 중첩은 기존 component 탐색 대체 경로의 한계이며 정확한 스코핑을 보장하지 않습니다. CSS Nesting의 중첩 style rule과 style block 내부 grouping rule도 재귀 스코핑 지원 범위가 아닙니다. 이 한계가 다른 식별자로 문맥을 넘기는 것은 허용하지 않습니다.
- scopeId는 접두사로 그대로 쓰므로 소비자가 유효한 CSS class 식별자를 제공합니다. 숫자로 시작하는 이름이나 escape가 필요한 이름을 자동 교정하지 않습니다.

주입 준비는 압축 여부와 관계없이 공유 위치 상태의 한 순회로 EOF 정보를 얻습니다. 압축을 켜면 같은 순회가 공백을 정리합니다. 문서 모드에서 열린 최상위 블록 규칙은 버리고 나머지 EOF 경계를 완성한 뒤 스코핑하며, 그림자 모드에서는 CSS Syntax의 EOF 복구를 구체화합니다. 연결 시 다시 판독하거나 별도 닫기 캐시를 유지하지 않습니다.

## Acceptance Criteria

### identifier-sheet-equivalence — 식별자별 단독 판독 동등성

- 유효 규칙, 모든 위치의 중첩·statement at-rule, 미완성 문자열·주석·블록·프렐류드와 stray `}`·`;`를 조합한 식별자 목록의 각 규칙 열이 식별자별 단독 CSS Syntax 판독과 같습니다.
- 문서·ShadowRoot 및 압축 적용·생략에 같은 모델을 적용하며, 실패한 생성 입력은 seed와 함께 재현합니다.

### singleton-registry — scopeId·ShadowRoot별 싱글톤 계약

- 동일 scopeId로 `get`을 반복 호출하면 같은 인스턴스를 반환한다.
- 서로 다른 `shadowRoot`로 같은 scopeId를 호출하면 서로 다른 인스턴스를 반환한다.

### batched-dom-update — rAF 배치와 폴백 계약

- 한 프레임 안에서 여러 번 `add`를 호출해도 DOM 반영 함수는 정확히 1회만 실행된다.
- 동일한 처리 결과의 CSS를 다시 `add`해도 DOM 반영 함수가 호출되지 않는다.
- `CSSStyleSheet`/`adoptedStyleSheets`를 지원하는 환경에서는 시트로, 아니면 scope 클래스가 붙은 `<style>` 엘리먼트로 반영된다.

### css-scoping — 선택자 스코핑 규칙

- 일반 선택자와 선택자 목록의 모든 선택자에 `.<scopeId>` 접두사가 붙고, `:root`·`:host`는 접두사 없이 유지된다.
- `@media` 블록은 닫는 중괄호를 유지하고 안쪽 규칙에도 접두사가 붙으며, 뒤따르는 규칙은 블록 밖에 남는다. `@keyframes` 블록은 그대로 유지된다.
- 문자열·주석 안의 중괄호·세미콜론·쉼표, 짝 없는 `}`, 앞선 주석은 규칙을 잃거나 스코프를 빠뜨리게 만들지 않는다.
- Shadow DOM 대상에서는 스코프 접두사가 붙지 않는다.

### destroy-cleanup — 정리 계약

- `destroy()` 이후 같은 scopeId로 `get`을 호출하면 이전과 다른 새 인스턴스를 반환한다.
- `destroy()` 이후 문서(또는 shadowRoot)의 `adoptedStyleSheets`/`<style>` 흔적이 모두 제거된다.
- Shadow DOM 대상에서도 동일하게 정리된다.
- 외부 참조가 없는 분리된 ShadowRoot와 호스트는 명시적 destroy 없이도 수거된다.
